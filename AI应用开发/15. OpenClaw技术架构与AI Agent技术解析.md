# OpenClaw 技术架构与 AI Agent 技术解析

> OpenClaw 是 2025 年底爆火的开源个人 AI Agent 运行时（GitHub 145k+ stars，MIT 协议，TypeScript），它不是给开发者构建 Agent 的框架，而是**Agent 本身**——本地运行的后台服务，连接 WhatsApp/Telegram/Discord/Slack 等 20+ 渠道，7×24 小时自动执行任务。
> 本文解析 OpenClaw 用到的 AI Agent 技术，并与本仓库 [AgentMate 项目](../简历/resume.md#L61-L81) 对比，提炼可复用的工程经验。

---

## 一、OpenClaw 是什么

### 1.1 定位

```
传统 AI 聊天机器人：
  浏览器打开网页 → 手动输入 → 获得回答 → 关闭页面 → 结束

OpenClaw：
  后台服务常驻运行 → 监听消息渠道 → 自动响应 → 自动执行工具 → 持久记忆 → 永不停止
```

**核心理念**：从「云端 AI 对话」向「本地 AI 行动」的范式转变。

| 维度 | 传统 AI 助手 | OpenClaw |
|:---|:---|:---|
| 运行方式 | 浏览器/SaaS | 本地后台服务 |
| 交互方式 | 主动打开网页 | 消息渠道自动推送 |
| 数据位置 | 云端 | 本地优先（Local-First） |
| 执行能力 | 仅文本生成 | 工具执行 + 自动化任务 |
| 记忆 | 单会话 | 跨会话持久记忆 |
| 定义方式 | 写代码/调 API | 写 Markdown 配置（SOUL.md） |

### 1.2 两个核心配置文件

OpenClaw 的 Agent 定义是**配置优先**的，不用写代码：

```markdown
# SOUL.md（Agent 的人格、规则、行为）
你是一个软件团队的项目经理。
你每天早上通过 Slack 检查团队状态。
你跟踪阻塞问题并向团队负责人汇报。
未经人工确认，你不会批准预算变更。

# AGENTS.md（多 Agent 定义，可选）
## Agent: research-bot
你负责市场调研，使用 search 工具收集竞品信息。
## Agent: code-bot
你负责代码审查，使用 git diff 工具分析变更。
```

> **设计哲学**：Agent 行为是配置，不是代码。改行为只需编辑 Markdown，重新对话即生效，无需重新编译部署。

### 2.2 完整消息流

```
入站消息处理：
  Channel SDK（Baileys/Grammy/Carbon 等）
    → Channel Monitor（渠道监控）
    → Inbound Debouncer（消息防抖，批量处理快速连续消息）
    → Allowlist Check（白名单检查）
    → Mention/Command Gating（@提及/命令门控）
    → Message Deduplication（LRU 去重）
    → Route Resolution（路由解析：哪个 Agent 处理）
    → Session Key Construction（会话键构建）

Agent 处理：
  Session Manager（加载/创建会话）
    → Pi Embedded Runner（Agent 执行器）
    → System Prompt Construction（SOUL.md → System Prompt）
    → Model Selection + Failover（选模型）
    → Tool Registration + Policy（注册工具）
    → LLM API 调用（anthropic/openai/google/deepseek）
    → Tool Execution Loop（工具执行循环 = Agentic Loop）
    → Response Streaming（流式响应）

出站投递：
  Block Stream Coalescer（流式块合并）
    → Message Chunking（消息分块，避免超长）
    → Markdown Formatting（格式化）
    → Outbound Delivery（投递）
    → Channel Send Adapter（渠道发送适配）
    → Gateway Broadcast（WebSocket 广播到所有客户端）
```

## 三、核心 AI Agent 技术

### 3.1 Agentic Loop（ReAct 工具调用循环）

OpenClaw 的核心是 **Agentic Loop**——LLM 自主决定调用工具、观察结果、继续推理的循环：

```
Agentic Loop（ReAct 模式）：

  ┌──────────┐
  │  用户消息 │
  └────┬─────┘
       ▼
  ┌─────────────────┐     否
  │ LLM 是否需要工具?│─────────→ 直接生成响应
  └────────┬────────┘
           │ 是
           ▼
  ┌─────────────────┐
  │ 选择工具 + 参数  │
  └────────┬────────┘
           ▼
  ┌─────────────────┐
  │ 工具执行 + 结果  │
  └────────┬────────┘
           ▼
  ┌─────────────────┐     否
  │ 结果是否满足需求?│─────────→ 回到 LLM 推理（带上工具结果）
  └────────┬────────┘
           │ 是
           ▼
  ┌─────────────────┐
  │ 生成最终响应     │
  └─────────────────┘
```

**关键技术点**：
- 工具调用采用 **JSON Schema** 定义（函数名 + 参数类型 + 描述）
- 支持**多工具并行调用**（一次 LLM 输出多个 tool_call）
- 工具结果注入回对话历史，LLM 基于结果继续推理
- 循环有**最大步数限制**（防止无限循环）+ **超时熔断**

**与 AgentMate 对比**：
- OpenClaw：对话入口保留 ReAct 循环（自由探索）
- AgentMate：对话入口保留 ReAct，执行链路（AutoDev）用过程式状态机（可控性优先）

### 3.2 LLM Provider 抽象层（模型无关）

OpenClaw 是**模型无关**的，通过统一接口抽象不同 LLM 提供商：

| 提供商 | 定位 | 特点 |
|:---|:---|:---|
| Anthropic Claude | 默认首选 | 优化 Agentic 任务，长上下文 |
| OpenAI GPT-4o+ | 全支持 | 生态成熟，工具调用稳定 |
| Google Gemini | 全支持 | 多模态能力强 |
| DeepSeek | 中国社区适配 | 性价比高，中文好 |
| Ollama | 本地部署 | 完全离线，隐私优先 |

```
统一抽象接口：
  interface LLMProvider {
    chat(messages: Message[], tools?: Tool[]): ChatResponse
    stream(messages: Message[], tools?: Tool[]): AsyncStream<Chunk>
    embed(text: string): number[]
  }

  实现：AnthropicProvider | OpenAIProvider | DeepSeekProvider | OllamaProvider
```

**Model Selection + Failover**：支持主备模型自动切换（如 Claude 限流时自动切到 GPT-4o）。

### 3.3 Skills 系统 + ClawHub 技能市场

OpenClaw 的 Skills 系统类似 AgentMate 的 Skill 体系：

```
Skills 架构：

┌─────────────────────────────────────────────────┐
│ ClawHub（技能市场，类似 npm registry）            │
│   ├─ 官方 Skills（搜索/计算/文件操作/网络请求）   │
│   ├─ 社区 Skills（第三方贡献）                    │
│   └─ 私有 Skills（企业内部）                     │
└────────────────────┬────────────────────────────┘
                     │ install
                     ▼
┌─────────────────────────────────────────────────┐
│ Local Skills（本地安装）                          │
│   ├─ skill.md（技能描述：name/description/tools） │
│   ├─ index.ts（技能实现：工具注册 + 执行逻辑）    │
│   └─ config.json（技能配置）                     │
└────────────────────┬────────────────────────────┘
                     │ register
                     ▼
┌─────────────────────────────────────────────────┐
│ Agent Runtime（运行时）                           │
│   └─ Tool Registry（工具注册表 + 安全策略）       │
└─────────────────────────────────────────────────┘
```

**Skill 定义示例**：

```markdown
# skill.md
name: weather-query
description: 查询实时天气
tools:
  - get_weather:
      description: 获取指定城市的天气
      parameters:
        city: { type: string, description: 城市名 }
```

```typescript
// index.ts
export default {
  name: 'weather-query',
  tools: {
    get_weather: async (params) => {
      // 调用天气 API
      return { temperature: 25, condition: '晴' };
    }
  }
};
```

**与 AgentMate 对比**：两者 Skill 设计理念一致——**Skill 是「给 Agent 用的可复用操作手册」**，包含描述 + 工具 + 约束。AgentMate 额外做了**双引擎回归测试守门**（LLM-as-Judge + 接口真查），OpenClaw 更偏向社区生态。

### 3.4 Session Manager（持久会话管理）

OpenClaw 的 Session Manager 管理跨会话的持久上下文：

```
Session 层级：

├─ Channel Session（渠道会话）
│   └─ 每个渠道（WhatsApp/Telegram）的消息历史
│
├─ Agent Session（Agent 会话）
│   └─ 每个 Agent 的对话上下文（可跨渠道）
│
├─ User Session（用户会话）
│   └─ 用户级偏好设置（长期记忆）
│
└─ Memory Store（记忆存储）
    ├─ 短期记忆（当前对话 context window）
    ├─ 中期记忆（会话历史，可摘要压缩）
    └─ 长期记忆（用户偏好、事实、知识）
```

**上下文管理策略**（与 [2.5 上下文工程](2.5%20上下文工程.md) 一致）：
- 超过 token 预算时**滚动摘要**（旧对话压缩成摘要）
- 关键事实提取到**结构化记忆**（不保留原文）
- 按相关性召回历史对话注入当前 context

### 3.5 Hooks System（生命周期钩子）

类似 AgentMate 的 pre/do/post 三态 Hook，OpenClaw 也有钩子系统：

```
Hook 类型：
  ├─ pre-message：消息到达时（可拦截/修改）
  ├─ pre-llm：LLM 调用前（可修改 prompt）
  ├─ post-llm：LLM 调用后（可校验输出）
  ├─ pre-tool：工具执行前（可鉴权/审计）
  ├─ post-tool：工具执行后（可过滤结果）
  └─ post-message：消息发送后（可记录/通知）
```

**安全策略**：工具执行前可以通过 Hook 做权限检查（如危险操作需要人工确认）。

### 3.6 多 Agent 协作（AGENTS.md）

OpenClaw 通过 AGENTS.md 支持多 Agent：

```markdown
# AGENTS.md
## Agent: researcher
角色：市场研究员
工具：search, web_fetch
## Agent: analyst
角色：数据分析师
工具：python_exec, chart_gen
## Agent: writer
角色：报告撰写
工具：markdown_render, email_send
```

**路由策略**：
- 关键词路由（包含"调研"→researcher）
- Mention 路由（@researcher → 直接指定）
- 默认路由（无法判断→默认 Agent）

**与 AgentMate 对比**：
- OpenClaw：多 Agent 是配置式的（Markdown 定义），路由是简单关键词匹配
- AgentMate：多 Agent 是过程式的（AutoDev 五阶段状态机），每个 Agent 有明确的输入输出契约

## 五、OpenClaw vs AgentMate 对比

| 维度 | OpenClaw | AgentMate（简历项目） |
|:---|:---|:---|
| **定位** | 个人 AI Agent 运行时 | 企业内部智能体平台 |
| **运行方式** | 本地后台服务 | 阿里云 MSE 平台服务 |
| **交互渠道** | 20+ 消息平台（WhatsApp/Telegram/Slack） | Web + 钉钉 Stream |
| **Agent 定义** | Markdown 配置（SOUL.md） | 代码 + Prompt 模板 |
| **多 Agent** | 配置式 AGENTS.md | 过程式状态机（AutoDev 五阶段） |
| **工具系统** | Skills + ClawHub 市场 | Skill 体系 + Aone 流水线集成 |
| **模型选择** | 多 Provider 抽象 + Failover | DashScope/Qwen 为主 |
| **安全** | Hooks + 本地优先 | pre/do/post Hook + PII 脱敏 + 越权拦截 |
| **评测** | 社区驱动 | 双引擎回归测试守门（LLM-as-Judge + 接口真查） |
| **记忆** | Local-First 持久存储 | Redis 短期 + MySQL 长期 + 向量库 |
| **开源** | MIT，145k stars | 内部项目 |

**AgentMate 的差异化优势**：
1. **过程式状态机**：AutoDev 五阶段比 OpenClaw 的自由 ReAct 更可控
2. **双引擎回归守门**：OpenClaw 没有系统的评测回归机制
3. **平台级安全**：pre/do/post 三态 Hook + PII 脱敏，企业级安全
4. **流水线集成**：Aone 自定义组件，Agent 行为漂移成为发布卡点

## 七、面试高频问答

### Q1：OpenClaw 是什么？

开源个人 AI Agent 运行时（TypeScript，MIT，145k stars），本地运行的后台服务，连接 20+ 消息渠道，7×24 小时自动响应消息、执行工具、持久记忆。核心理念是从「云端 AI 对话」到「本地 AI 行动」。

### Q2：OpenClaw 的核心架构是什么？

四层微内核架构：
1. **Gateway 控制平面**：WebSocket + HTTP API + 路由引擎 + 会话管理 + Hooks
2. **Agent Runtime**：Pi Embedded Runner（Agentic Loop + 模型选择 + 工具注册 + System Prompt 构建）
3. **Channel Adapters**：WhatsApp/Telegram/Discord/Slack 等渠道插件
4. **Persistent Memory**：Local-First 加密存储

### Q3：OpenClaw 怎么定义 Agent？

配置优先——两个 Markdown 文件：
- **SOUL.md**：Agent 的人格、规则、行为（自然语言描述）
- **AGENTS.md**：多 Agent 定义（可选）

改行为只需编辑 Markdown，重新对话即生效，无需重新编译部署。

### Q4：OpenClaw 的 Agentic Loop 怎么工作？

标准 ReAct 循环：
1. LLM 判断是否需要工具
2. 需要→选择工具+参数→执行→结果注入对话历史
3. LLM 基于结果继续推理，直到不需要工具
4. 生成最终响应

有最大步数限制 + 超时熔断防止无限循环。

### Q5：OpenClaw 的 Skills 系统和 MCP 有什么关系？

两者理念一致——**工具标准化接入**：
- OpenClaw Skills：本地插件 + ClawHub 市场，TypeScript 实现
- MCP 协议：跨语言的工具接入标准（见 [11. MCP协议](11.%20MCP协议.md)）

未来 OpenClaw 可能原生支持 MCP，让第三方 MCP Server 直接作为工具接入。

### Q6：OpenClaw 和你的 AgentMate 有什么区别？

定位不同：OpenClaw 是个人 Agent 运行时（配置优先、本地优先、消息优先），AgentMate 是企业平台（代码+Prompt、云端、Web+钉钉、过程式状态机、双引擎回归守门）。AgentMate 在**可控性**（过程式状态机 vs 自由 ReAct）和**质量保障**（双引擎回归 vs 无系统评测）上更有优势。

### Q7：从 OpenClaw 能学到什么工程经验？

1. **配置优先**：Agent 行为是配置不是代码，改 Markdown 即生效
2. **Local-First**：数据不离开本地，隐私安全
3. **模型无关**：Provider 抽象 + Failover，不绑定单一厂商
4. **微内核 + 插件**：小核心 + 大生态，渠道/工具都通过插件扩展
5. **Hooks 生命周期**：pre/post 钩子实现安全拦截和可观测性

## 九、一句话总结

> OpenClaw 是 2025 年底爆火的开源个人 AI Agent 运行时——**微内核网关 + 20+ 渠道适配器 + ReAct Agentic Loop + 模型无关 Provider 抽象 + SOUL.md 配置优先 + Skills/ClawHub 生态 + Local-First 持久记忆**，它证明了「Agent 即服务 + 配置优先 + 本地优先」的范式可行性；与 AgentMate 对比，OpenClaw 赢在生态和易用性，AgentMate 赢在可控性（过程式状态机）和质量保障（双引擎回归守门），两者的设计理念互相印证了 Agent 工程化的关键原则。
