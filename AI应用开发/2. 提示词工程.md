# 提示词工程（Prompt Engineering）面试题整理

> **P7 面试的分层考法**：P5 问「prompt 怎么写」，P7 问「prompt 怎么管」——版本化、评测集回归、A/B 灰度、成本（前缀缓存）、注入防御。能否说出「**提示词是上下文工程的子集，生产 prompt 是被测试和版本管理的代码**」，是区分「调参侠」和「工程化落地者」的分水岭。

## 二、逐题详解

### Q1：什么是提示词工程？和上下文工程什么关系？

**一句话**：提示词工程 = 用自然语言**确定性-ish 地控制模型行为**的技艺——约束任务、格式、角色、边界。

**关系（P7 答法）**：上下文工程是大盘——**放进模型窗口的一切**（system、检索片段、工具结果、历史消息、few-shot）都算上下文；提示词工程只管其中「指令性文本」这一层。RAG 拼装、工具 schema、记忆裁剪都是上下文工程，但不是提示词工程。**Prompt 是变量，上下文是环境。**

### Q2：结构良好的 Prompt 长什么样？

生产模板五段式（缺一段就是一个追问点）：

```text
【角色】你是 MSE 网关运维助手，只回答网关与流量治理问题。
【任务】根据提供的监控片段，定位 503 错误率突增的根因，给出处置建议。
【上下文】{检索到的监控片段}   ← 变量注入，与指令隔离
【约束】1. 仅依据给定片段，不知道就说"片段不足" 2. 不编造 IP/数值 3. 涉嫌操作必须 human-in-the-loop
【格式】JSON：{"root_cause": "", "evidence": [], "actions": []}
```

| 段 | 作用 | 缺失后果 |
|:---|:---|:---|
| 角色 | 划定知识域与语气 | 答非所问、越界回答 |
| 任务 | 一个 prompt 一个目标 | 多任务互相稀释 |
| 上下文（变量化） | 事实来源与指令**物理隔离** | 注入风险、无法缓存 |
| 约束 | 边界与幻觉防线 | 编造、越权 |
| 格式 | 下游可解析 | 解析失败重试风暴 |

### Q3：Zero-shot / Few-shot / CoT 怎么选？

| 技术 | 一句话 | 适用 | 代价 |
|:---|:---|:---|:---|
| Zero-shot | 直接下指令 | 任务常见、模型熟 | 最低 |
| **Few-shot** | 给 2~5 个输入输出示例 | **格式模仿**、口径统一、边界 case 对齐 | token 变长；示例错→模型照错（示例污染） |
| **CoT** | 「一步步思考」/ 给推理示例 | 多步推理、数学、诊断类 | token×N、延迟↑ |
| 自我一致性（Self-Consistency） | 同题采样 N 次取多数 | 高准确要求（成本换准度） | 成本×N |

**Few-shot 示例挑选原则**：覆盖边界 case > 数量多；示例格式必须 100% 正确——模型会忠实地模仿你的错误。

### Q4：CoT 为什么有效？什么时候反而有害？

**有效的原理（面试深度点）**：Transformer 每层计算量固定，**输出 token 是唯一的「额外计算时间」**——CoT 让模型把中间步骤写出来，相当于给了它草稿纸，把「一步到位的内隐计算」变成「可展开的外显计算」。所以 CoT 对**可分解的推理任务**有效，本质是「用生成时间换推理深度」。

**有害/无效的场景**（说不出这个就是背口诀）：
- **精密算术**：CoT 不改变模型「不会精确计算」的事实——正解是**调工具**（计算器/代码执行），见 [Agent智能体框架](7. Agent智能体框架.md) 工具调用。
- **简单分类任务**：无推理步骤可展开，纯浪费 token 和延迟。
- **知识缺失**：不会的题加 CoT 还是不会，只会「流畅地编」——知识问题走 RAG（Q7）。

### Q5：System / User 提示的权限层级？

```text
System（开发者写的宪法）  >  User（用户输入，不可信）
```

- **System Prompt 是信任边界**：角色、能力边界、安全红线、格式契约全放这里；用户输入**永远当数据**，不当指令。
- 这正是 Prompt Injection 防御挂在 System 层的原因（Q10）：注入的本质就是「让用户数据伪装成 System 指令」。
- **工程要点**：System 提示保持**稳定**——它是前缀缓存（Prompt Caching）的命中前提，改动 System 等于缓存全灭（成本口诀见 [AI高频面试题速查](14. AI高频面试题速查.md) T23：固定前缀命中价 1/10）。

### Q6：怎么保证 LLM 输出合法 JSON？（三层防线，T21 展开）

```text
① API 层：JSON Mode / Structured Output（Schema 约束解码）  ← 模型层硬保证
② Prompt 层：给 schema + few-shot 示例                      ← 引导
③ 代码层兜底：解析失败 → 带错误信息重试让模型自修复 + 关键字段校验 ← 兜底
```

**生产原则**：永远不要无条件信任输出格式，解析失败是常态，必须设计进链路。

### Q7：Prompt vs 微调 vs RAG 怎么选？（T2 骨架）

| 手段 | 解决 | 不解决 | 成本 |
|:---|:---|:---|:---|
| **Prompt 工程** | 行为约束、格式控制、任务编排 | 知识补充、能力跃迁 | 最低 |
| **RAG** | 知识实时性、私有知识 | 行为风格、格式纪律 | 中 |
| **微调** | 风格对齐、领域语感、稳定格式 | 时效知识（训练截止即定格） | 高 |

**标准决策链**：先用 Prompt（便宜快）；缺知识加 RAG；风格/格式要求苛刻到 prompt 稳不住、且数据量大且稳定，才上微调。**三者是叠加态不是单选**。

### Q8：生产上怎么管理提示词？（P7 核心：prompt 即代码）

| 工程实践 | 具体做法 |
|:---|:---|
| **模板化** | prompt = 模板 + 变量；指令与数据物理隔离（Q2），变量走注入框架不手拼 |
| **版本化** | 模板入库带版本号，改动走 MR/Code Review，prompt diff 和代码 diff 同级对待 |
| **评测集回归** | golden set（含边界 case），改 prompt 必跑回归——**没有评测集的 prompt 调优 = 没有单元测试的重构** |
| **A/B + 灰度** | 新版 prompt 灰度 5% 流量，对比成功率/成本/延迟再全量 |
| **LLM-as-Judge** | Judge prompt 固化版本、打分跑 3 次取中位数、误报样本人工复核后**追加进 Judge 的 few-shot**（口径同 [LLM安全与工程化](13. LLM安全与工程化.md)） |
| **成本观测** | token 用量按模板版本聚合；利用前缀缓存设计稳定前缀 |

**AgentMate 结合点**：Skill 描述、Spec 模板、周报生成模板全部版本化，改模板必跑线上回放集（可观测可回放，见 [Agent智能体框架](7. Agent智能体框架.md)）。

### Q9：提示词优化有什么方法论？

1. **先建基线**：跑通评测集拿到当前分数，没有基线就没有「改好了」。
2. **一次只改一处**：角色/示例/格式/约束分开调，改完即回归——多变量同改无法归因。
3. **从失败样本反推**：把 badcase 归类（格式错/幻觉/越界），每类对应一个针对性约束或示例，而不是凭感觉重写全文。
4. **负面清单比正面描述可靠**：「不要编造 IP」比「请准确」有效。
5. **收益递减即停**：prompt 只能逼近模型能力上限，到顶后换手段（工具/RAG/换模型）。

### Q10：Prompt Injection 和提示词工程什么关系？

提示词工程包括**防御性写作**，但注入防御**不能只靠提示词**：

- System 层强化（红线声明）只拦截约 60% 简单注入；DAN/编码注入/多轮分段注入可绕过。
- **最终防线是权限而不是模型自律**：就算模型被说服，代码层 RBAC 不放行危险操作（口径与 [LLM安全与工程化](13. LLM安全与工程化.md) 三层防线一致：System 强化 → 正则过滤 → 权限锁死）。
- 提示词侧的正确姿势：**指令与数据物理隔离**（Q2 的变量化）+ 工具输出当数据不当指令。

## 三、易错点

1. **「Prompt 万能论」**——prompt 不解决知识缺失（T2），缺知识加 RAG，别拿格式约束当知识注入。
2. **Prompt 越长越好**——长 prompt 稀释关键指令、烧钱烧延迟；目标是**最小充分**。
3. **Few-shot 示例随手写**——示例里的格式错误、口径错误会被忠实模仿（示例污染）。
4. **System Prompt 频繁改**——前缀缓存全灭，成本翻倍；改动要走版本化+灰度。
5. **没有评测集就调 prompt**——无法归因、无法回归、改好改坏全凭体感（P7 一票否决项）。
6. **把注入防御寄托在提示词上**——提示词是第一层不是最后一层，最终防线是权限（Q10）。

---

## 四、一句话总结

**提示词工程 = 把「自然语言接口」当代码管理：五段模板隔离指令与数据、CoT 用生成时间换推理深度、三层防线保证结构化输出、评测集回归驱动迭代；它是上下文工程的指令层子集，是选型链条里最便宜的第一步。**
