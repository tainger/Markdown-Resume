## 一、为什么这是 P7 差异化竞争力？

```

  Java → JVM → Spring → MySQL → Redis → MQ → 分布式事务 = 同质化严重，面试官面一天见 10 个

你（AI 应用落地 + 后端）复合知识栈：
  上面全套 + ✅ RAG 架构选型（混合检索/重排/切片策略）

              + ✅ LLM 安全工程（PII 脱敏/Hook 三态防护/越权拦截）
              + ✅ AI 输出非确定性质量卡点（LLM-as-Judge 语义评测 + 接口真实校验）
              + ✅ 大模型微调工程化经验（SDXL LoRA/相似度量化闭环）

```

## 四、面试「P7 级必背」速查清单（一句话版）

| # | 场景 | 回答要点 |
|:---:|:---|:---|
| 1 | 「你们的 RAG 怎么做的？」 | 不是纯向量，是 **Wiki 结构化 + 百炼向量 Dual 双混合检索**，两阶段召回：向量粗排 Top-20 → Cross-Encoder 重排 Top-3，**切片按 Markdown 标题优先并保证表格代码块不切断**，P0-P4 分级策略杜绝模型硬答。 |
| 2 | 「Agent 框架怎么选？」 | 对话入口保留 ReAct 循环增强自由性；**执行链路（AutoDev）必须用过程式状态机**，我踩过「主管 Agent + 执行 Agent 双层 ReAct 导致推理发散/链路超时/结果不可控」的坑，过程式线性流水线 + 幂等重跑，可控性大幅提升。 |
| 3 | 「多任务并发操作 Git 仓库冲突怎么解？」 | 自研 WorktreeManager：**每个任务分配独立 git worktree**，只对 worktree 元数据操作加仓库级锁，耗时的编码过程锁外保留并行度；并配开关 + 异常降级兜底共享目录策略。 |
| 4 | 「LLM 输出不稳定，怎么保证发布质量？」 | 双引擎回归：**LLM-as-Judge 做语义评判（比对答案语义而非字符）+ 接口真实校验（工具调用结果真查真验证）**；虚拟线程异步批量跑并实时回写进度；进一步封装成 Aone 流水线自定义组件，**让 Agent 行为漂移成为发布可阻断卡点**。 |
| 5 | 「LLM 安全怎么防？」 | 自研 **pre/do/post 三态 Hook 底座**：前置鉴权（谁能调哪些工具）+ 执行监控（执行时长/调用次数红线）+ 后置过滤（PII 正则脱敏 + 敏感词拦截）；PII 覆盖手机号/身份证/邮箱/银行卡/IP 5 类，把日志、SSE 流、LLM 上下文三条路径全部拦截。 |
| 6 | 「SSE 流式返回有坑吗？」 | 有！EventSource 不支持自定义鉴权 Header + 不支持 AbortController 中断，所以 **手写 fetch + ReadableStream 解析 SSE**；并对「粘包（一条消息被拆多个 chunk）/ 半包（chunk 在 data: 中间切开）」做容错跳过，遇到不完整帧缓存等下一包拼完整再解析。 |
| 7 | 「大模型微调有经验吗？」 | 做过 SDXL 人物 LoRA 完整工程化：消费级 T4 16GB 显存通过 fp16 混合精度 + AdamW8bit + gradient_checkpointing + network_dim=32 把显存压进 16GB；做了 **ArcFace embedding 余弦相似度量化闭环**，多 seed 重复评测报均值±标准差而非单张分数，选档不靠拍脑袋看拐点。 |

## 五、学习建议

1. **按 RAG → Agent → 安全工程 → 大模型基础**的顺序过：面试中 RAG 最常考（80% AI 岗都有 RAG 落地需求），Agent 框架次之，安全工程是「P7 深度加分项」，大模型基础是理论底线。
2. **每篇结合自己 AgentMate 经历讲**：不要只讲理论，要落到「我在 AgentMate 里踩了 X 坑，然后做了 Y 改造，最终指标 Z 提升了多少」（比如 AutoDev 从双层 ReAct 改过程式状态机后链路超时率从 30% 降到 < 5%）。
3. **CyberLoRA 个人项目也要能讲**：面试官喜欢看「**你下班之后还在主动探索 AI**」，证明你的 AI 知识不是项目逼出来的而是主动学习积累来的——相似度量化闭环、LoRA vs InstantID 选型对比、Colab 工程化三条线是亮点。
