# 大模型工程基础

> 面试中 AI 岗位 100% 会问：「你理解 Transformer 吗？LoRA 为什么能微调？」。不求手推 Attention 公式，但必须能讲清核心结构和工程化原理。本章结合 AgentMate（大模型调用/RAG Embedding）和 CyberLoRA（SDXL LoRA 微调个人项目）的双重视角，从 P7 工程落地维度讲。

## 一、Transformer 架构核心（面试口述 2 分钟版）

Transformer 是所有大模型（LLM + 文生图）的地基，2017 年 Google《Attention Is All You Need》提出。核心突破 = **抛弃 RNN 的「串行递归」**，全部用 **Self-Attention 自注意力** 做序列建模，天生可并行 + 长程依赖建模能力强。

### 1.1 整体结构 ASCII

```
            （编码器 Encoder 堆 × N）               （解码器 Decoder 堆 × N）
              ┌─────────────┐                    ┌─────────────────────┐
  输入（中文） │  + 位置编码  │  ┌───── 交叉注意力 ◀─┤  + 掩码自注意力+位置编码│ 输出（英文）
   "我爱你" ─▶│  多头自注意力│──│                  │  多头自注意力（掩码）│──▶ "I love you"
              │  + 残差+Norm │  │                  │  + 残差+Norm       │
              │  Feed Forward │  │                  │  Feed Forward（FFN）│
              │  + 残差+Norm │  │                  │  + 残差+Norm       │
              └─────────────┘  │                  └─────────────────────┘
                               │
            Encoder 输出 K V  ──┘   Decoder 上一步输出 Q
```

### 1.2 5 个核心组件（口述能讲 3 个就过）

| # | 组件 | 一句话作用 | 为什么这么设计 |
|:---:|:---|:---|:---|
| 1 | **Self-Attention 自注意力** | 序列里每个字都和「其他所有字」算注意力分数，知道「这个字和谁有关」 | 解决 RNN 长程依赖问题：第 1 个字和第 1000 个字直连，没有 N 步中间层衰减 |
| 2 | **Multi-Head 多头** | 把 Q/K/V 投影到 h 个不同子空间，分别算 Attention 结果再拼起来 | 一个头只能学一种「关系模式」；h 个头 = h 种不同视角（语法/指代/语义……并行学） |
| 3 | **位置编码 Positional Encoding** | Attention 本身不知道字的顺序（置换不变），硬给每个位置注入 sin/cos 的位置信息 | sin/cos 不同频率组合，天然支持「相对位置泛化」：训练到 512 长度，推理时 1024 长度的位置也能合理推断（虽然后来都用 RoPE/ALiBi 了）|
| 4 | **残差连接 + LayerNorm** | X + Sublayer(X)，再 Norm；每一层都包一套 | 残差解决深层网络梯度消失（N 堆 12 层起）；LayerNorm 让训练更稳定收敛（相比 BN，不依赖 batch size，适合 NLP 变长序列）|
| 5 | **Feed Forward（FFN/MLP）** | 两层 Linear + GELU 激活：Linear(512→2048) → GELU → Linear(2048→512) | Attention 负责「找和谁相关」，FFN 负责「对这个位置的向量做非线性变换」——可以理解为：Attention 是「信息收集」，FFN 是「信息加工写回」 |

### 1.3 Self-Attention 公式（面试说清楚三个矩阵就行）

```
Q = X × Wq    Query：我是这个字，我想找和我相关的
K = X × Wk    Key：  每个字的「身份卡」
V = X × Wv    Value：每个字的「内容」

          Q × K^T                        对每行 Softmax（归一化成概率和=1）
Attention(Q,K,V) = Softmax(────────────) × V
             √d_k
                ↑ 除以 √d_k 防止点积太大 Softmax 后梯度过小（Scaled Dot-Product）
```

> 面试不用写公式，能讲：「**Q 和 K 做点积算相关度，Softmax 变成权重，加权求和 V 就是这个位置融合了全局信息的新向量**」就行。P7 面试不会让你手推 Attention 反向传播。

### 1.4 为什么 BERT 只用 Encoder，GPT 只用 Decoder？

| 模型族 | 结构 | 原因 | 典型 |
|:---|:---|:---|:---|
| **BERT（理解型）** | Encoder only | 编码时能看到左右完整上下文（双向注意力），适合「理解任务」：分类/实体/提取/打分 | 早期 NLP 理解任务、Embedding 模型（向量检索用的就是 Encoder 类）|
| **GPT（生成型）⭐ 现在所有 LLM 都是这个族** | Decoder only | 解码时用「因果掩码（Causal Mask）」：每个位置只能看到自己左边的字（不能偷看右边答案），适合「自回归生成」：逐字吐字回答 | GPT-3.5/4、Llama/Qwen/ChatGLM、所有对话大模型 |
| **T5/翻译模型** | Encoder + Decoder | 编码读源语言（能看全），解码写目标语言（逐字生成）+ 交叉注意力（对齐两边）| 翻译、摘要、文生图里 Transformer 结构类似（UnCLIP 等）|

> 💡 为什么现在 LLM 都选 Decoder-only？工程上一套结构训练推理都简单；实验上大参数下效果和 Enc+Dec 持平甚至更好；而且 Scaling Law 明确——模型参数量 + 训练数据量上去，效果可预测地变好。

## 二、LoRA 微调原理（低秩适应 Low-Rank Adaptation）

为什么需要微调？**基础大模型是通用知识（学会了说话）**，但要让它变成「**你的专属写真模型/企业问答模型**」，就要注入你自己的数据。全量微调 = 改所有参数（7B 模型 70 亿参数都训练一遍）：**时间 1 周 + 显存 8×A100 + 成本几万** → 消费级显卡根本玩不起。

LoRA = **冻结基座模型所有参数，只训练极少数「低秩矩阵」来注入新信息**，把训练成本降 100 倍！

### 2.1 核心思想：低秩分解

Transformer 里的 Linear 层（比如 QKV 投影矩阵、FFN 层）都是大权重矩阵 `W₀ ∈ R^(d×k)`：
```
全量微调：W₀ 每一个元素都要算梯度 + 更新，7B 模型 ≈ 130 亿参数（主要就是这些大矩阵占的）

LoRA 思路：我不直接改 W₀，而是 W = W₀ + ΔW，把 ΔW 做「低秩分解」：
         ΔW = B × A，其中 A ∈ R^(r×k)，B ∈ R^(d×r)，r ≪ min(d,k)（秩很小，r=8/16/32）

         原来的前向传播：h = W₀ x
         LoRA 前向传播：h = W₀ x + B A x   （W₀ 冻结不训练，只训练 A 和 B）

         参数量对比（以 Q 投影矩阵 d=4096, k=4096 为例）：
           全量：W₀ = 4096×4096 ≈ 16,777,216 参数
           LoRA r=32：A=32×4096 + B=4096×32 = 262,144 参数
           → 只训练原来的 1.56% 参数！显存直接能塞进消费级 T4 16GB
```

ASCII 直观图：
```
全量微调的大矩阵 W₀：4096×4096（一大块，全要训）
       ┌────────────────────────────────┐
       │ ██████████████████████████████ │
       │ ██████████████████████████████ │
       │ ...  16,777,216 个参数 ...      │
       │ ██████████████████████████████ │
       └────────────────────────────────┘

LoRA：把要训练的增量 ΔW 拆成两个细条（低秩分解）
  A (r=32 × 4096) 细横条     B (4096 × r=32) 细竖条
  ┌────────────────────┐      ┌────┐
  │░░░░░░░░░░░░░░░░░░░░│ 131k │░░░░│
  └────────────────────┘      │░░░░│ 131k    合起来才 262k 参数！
 参数矩阵相乘：B × A = ΔW     │░░░░│   而且 r 越小，参数越少
 (近似模拟大矩阵的变化)       │░░░░│
  效果：ΔW 的秩 ≤ r，所以叫  └────┘
  「低秩适应」= Low-Rank Adaptation
```

### 2.2 LoRA 的 6 个关键超参（CyberLoRA 实测踩坑）

| # | 超参 | 作用 | 推荐值（SDXL LoRA） | 踩坑经验 |
|:---:|:---|:---|:---:|:---|
| 1 | **rank（秩 r）** | 低秩矩阵的秩 r；越大表达力越强但参数越多越容易过拟合 | **32**（人像通用）| r=8 人脸特征抓不住；r=64 开始过拟合油腻；32 是人像甜蜜点 |
| 2 | **alpha（缩放系数 α）** | 实际生效 = α/r × BA；保证改 rank 不用改学习率 | **16（r=32 时）** | 固定 α=r/2 就行，这样 LoRA 实际输出幅度恒定，调参不用重扫 lr |
| 3 | **要训哪些层（target_modules）** | 给哪些 Linear 层加 LoRA | **to_q,to_k,to_v,to_out + up,down（FFN）** | 只训 QV 层效果差，加上 FFN 层后相似度 +0.03（实测 0.762→0.792）|
| 4 | **学习率 lr** | LoRA A/B 的学习率（基座模型 lr 是 0，冻结） | **1e-4** | lr=5e-4 训 5 步就崩了（过拟合）；lr=5e-5 收敛太慢；1e-4 是 T4+SDXL 甜蜜点 |
| 5 | **optimizer（优化器）** | 优化器选型 | **AdamW 8bit** | 全精度 AdamW 多占 8GB 显存（存 fp32 动量）；bitsandbytes 的 8bit AdamW 把优化器状态压缩 8 倍，T4 16GB 才塞得下 |
| 6 | **训练精度** | 数据类型混合精度 | **fp16（T4 专属）** | T4 是 Turing 架构，**只有 fp16 有 Tensor Core 加速**；bf16 要 Ampere 以上（A10/A100）才支持；fp16 下 SDXL VAE 出 NaN 黑图 → 必须加 `--no_half_vae` 保留 VAE fp32 |

### 2.3 LoRA vs 其他微调方案对比

| 方案 | 训练参数量 | 显存占用 | 训练时间 | 效果 | 是否需要重新推理权重 |
|:---|:---:|:---:|:---:|:---:|:---:|
| 全量微调（Full FT） | 100%（7B 全部）| 80GB+（多 A100）| 几天 | ⭐⭐⭐⭐⭐ 最好 | 是：每个任务一份 14GB 权重 |
| **LoRA ⭐ 首选** | **0.1%~2%** | **16GB（T4 可跑）** | **几十分钟** | ⭐⭐⭐⭐ 接近全量 | **否**：推理时把 LoRA 权重「合并」回基座，或者动态加载切换 |
| QLoRA | 0.1%~2%（+ 基座 4bit 量化）| **8GB（3090 可跑 7B）** | ~几小时 | ⭐⭐⭐⭐ 几乎和 LoRA 持平 | 否：同 LoRA |
| P-Tuning v2 / Prefix Tuning | 0.01%（只训 Prompt 向量）| ~8GB | 快 | ⭐⭐ 一般（数据量一大效果差）| 是：要带额外 prefix 参数 |
| 全参数 + PEFT 混合 | 50% + LoRA | 40GB+ | 中等 | ⭐⭐⭐⭐⭐ 最好 | 是：存整套权重 |

> 💡 选型口诀：消费级显卡 → LoRA（CyberLoRA 就这方案）；13B+ 大模型消费级显卡真塞不下 → QLoRA 4bit 量化；只有大公司有 A100 集群 + 海量高质量数据 → 才考虑全量 FT。

### 2.4 CyberLoRA 项目：ArcFace 相似度量化闭环（⭐ 工程化深度亮点）

纯 LoRA 训练最常见的问题：**判断「人像不像本人」全靠肉眼**，A 同学觉得像 B 同学觉得不像，选权重档位全靠拍脑袋。

我们的解法：**用量化指标替代主观判断**——把人脸识别模型 ArcFace 的 Embedding 余弦相似度当「像不像」的可复现指标：

```
一张测试真实图 real.jpg，一组 LoRA 权重档位 0.5/0.6/0.7/0.8/0.9/1.0 → 每个档位用 10 个 seed 出 10 张 AI 图 →
  每张都算 ArcFace Embedding（512 维向量），和 real.jpg 的 Embedding 算余弦相似度 →
    10 张的 均值 ± 标准差（避免单 seed 撞大运），而不是单张分数！

实测 CyberLoRA 结果（InstantID 免训练方案对比）：
  LoRA：   权重 0.75   10 seed 均值 0.792 ± 0.018  ← 稳定、标准差小
  对照组： 身份注入的 AI 图 -0.019（近似随机，证明指标不会误报）
  InstantID：单张 0.792 ± 0.007（标准差更小，出图更稳定，但相似度上限略差）

选档逻辑：
  画「权重 vs 相似度」曲线 → 看拐点：权重 0.7 之前相似度上升快，0.8 之后上升变慢，
  0.9 之后开始下降（过拟合油腻塑料感） → 拐点 0.75~0.8 就是最优档位，不用人眼一张一张挑。
```

这个「**量化指标 + 多 seed 重复评测均值 ± 标准差**」的方法论，P7 面试讲出来 = 证明你「做 AI 项目不是瞎炼丹，而是数据驱动的工程化迭代」。

## 三、大模型推理优化（线上成本优化，P7 加分）

大模型推理成本极高（一个 token 就几十 ms + 几 GB 显存带宽 + 计算）。P7 做 AI 应用要知道哪些优化手段能在 80% 场景里砍一半成本。

### 3.1 推理优化手段对比表

| # | 优化 | 原理 | 加速比/显存省 | 副作用/限制 |
|:---:|:---|:---|:---:|:---|
| 1 | **KV Cache（几乎所有推理框架默认开）⭐** | 生成第 t+1 个字时，前 t 个字的 K V 已经算过了缓存下来，不用重算（自回归每生成一个字本来 O(t²)，开了 KV Cache 变 O(t)） | **延迟 -50%，吞吐 +100%** | 显存占用增加（缓存的 KV 要存），长对话显存爆；但可以配合 KV Cache 量化（4/8bit）省 |
| 2 | **量化（Quantization）⭐** | 权重用 INT4/INT8 存而不是 FP16（2字节→半/四分之一字节）| **显存省 50%~75%，同显存可并发用户数 ×2~4** | 精度损失（4bit 量化 Llama 效果几乎不掉，经验证）；量化越狠，生成质量越低（2bit 就糊了）|
| 3 | **投机解码（Speculative Decoding）⭐ 现在主流** | 先用一个小「草稿模型（Draft Model，小 10 倍）」快速猜 N 个字（几乎免费），再用大模型一次性并行验证哪些字对，对的都保留（不用逐字串行推） | 吞吐 2~3×，延迟 -60% | 需要一个和大模型 tokenizer 一致的草稿模型（Llama 70B + Llama 7B 草稿）|
| 4 | **Continuous Batching（连续批处理 / ORCA）** | 传统静态批：一批 N 个请求，最后一个最慢的吐完字才能发下一批 → GPU 空等；连续批：**字级别调度**，哪个请求生成完立刻插入新请求补上 | **吞吐 2~4×**（并发请求越多越明显） | 推理框架必须支持（vLLM/TGI 都支持，自己写很难）|
| 5 | **FlashAttention 2** | 重排 Attention 计算顺序，利用 SRAM 减少 HBM 显存读写带宽瓶颈 | 训练 2~4× 提速，推理 15%+ 加速 | 对短序列效果不明显（长序列 >4K 收益巨大）|
| 6 | **并行推理（Tensor / Pipeline 并行）** | 把一张大模型拆到多卡上：张量并行按矩阵切，流水线并行按层切 | 单卡装不下的大模型才能跑 | 多卡互联带宽要求高（NVLink 最佳），延迟反而可能上升（跨卡通信）|

### 3.2 KV Cache ASCII 直观理解

```
自回归生成「我爱中国」四个字：
  Prompt: "请用中文说一句爱国的话"
  step0: 把整段 Prompt 送入 Transformer → 计算所有 token 的 K V → Output: 下一个字是「我」  ✅ KV Cache 建立（这些 K V 存起来）
  step1: 只要输入「我」（不是整句+我重算！）→ 拿 step0 存好的 K V + 「我」的新 K V
         → Attention 计算 → 下一个字是「爱」                              ✅ 复用历史缓存！
  step2: 只要输入「爱」→ 历史 K V + 「我」「爱」KV → 输出「中」
  step3: 只要输入「中」→ 同理 → 输出「国」
  step4: 只要输入「国」→ 同理 → 输出 EOS 停止符

没有 KV Cache：每一步都重算「Prompt + 已生成」所有字的 K V = O(1+2+3+…+t) ≈ O(t²/2) Attention 计算
有了 KV Cache：每一步只算新字的 K V，历史直接读 = O(t) 线性！
```

## 五、常见大模型参数概念（面试别被这些名词问懵）

| 名词 | 含义 | 典型数值 |
|:---|:---|:---|
| **参数量（Params）** | 模型可训练权重总数（就是大矩阵元素个数） | 7B/13B/70B 常见；7B ≈ 70 亿参数 |
| **上下文长度（Context Length / Window）** | 模型一次能吃下去的最大 token 数（Prompt + 生成）| Llama1=2K → Llama2=4K → 现在大多 32K/128K |
| **Token** | 分词后的最小单元（不是字/词）| 中文 1 字 ≈ 1.5 token；英文 1 词 ≈ 1.3 token |
| **Temperature（采样温度）** | 生成多样性：0=最死板（argmax 概率最高的字），1=更随机有创造力 | 代码生成=0.1，创意写作=0.8，RAG问答=0.2（更可信） |
| **Top-p（Nucleus Sampling）** | 只从前 p% 累计概率的候选字里抽，屏蔽概率极低的垃圾选项 | 默认 0.9 |
| **Pre-train（预训练）** | 第一阶段：用全网海量文本（万亿 token）训基础模型（学会语言+常识） | 成本几亿~几十亿 |
| **SFT（有监督微调）** | 第二阶段：用几十万「高质量问答对」让模型学会「用对话格式回答人类问题」 | 几千到几十万条数据 |
| **RLHF / DPO** | 第三阶段对齐人类偏好：RLHF 用奖励模型强化学习；DPO 直接用偏好数据对优化，现在 DPO 更常用 | 几万条偏好对比数据 |

> 💡 记忆：基座大模型制作 3 阶段流水线：**Pre-train（学会说话） → SFT（学会对话格式） → RLHF/DPO（学会说人话、人类爱听的）**。

## 六、易错点 ⚠️

| # | 易错点 | 正确理解 |
|:---:|:---|:---|
| 1 | 「LoRA 秩 r 越大越好，学的东西多」 | ❌ 错！r 越大参数越多越容易过拟合（人像出现油腻塑料感/五官畸形）。r=32 通常是人像 LoRA 的甜蜜点，超过 r=64 效果不升反降，还浪费训练时间。 |
| 2 | 「KV Cache 开了就完全免费，没有代价」 | ❌ 错！KV Cache 要占显存：7B 模型 32K 上下文 + FP16 = ~30GB/用户并发 ×10 并发 = 300GB 显存直接炸。配合 KV Cache 4bit 量化 + 滑动窗口才能真正撑住并发。 |
| 3 | 「Embedding 模型越大向量维度越高，召回越好」 | ❌ 错！1536 维 vs 1024 维，召回差距不到 2%，但存储占用 +50%、检索速度 -30%。关键是**切片策略 + 混合检索**，不是盲目堆 Embedding 维度/大小。 |
| 4 | 「量化到 4bit 模型效果就没法用了」 | ❌ 错！GPTQ/AWQ 等 4bit 分组量化算法，70B 模型量化后效果和 FP16 差距不到 1%，人类根本感知不出来。现在主流推理框架默认 4bit/8bit 量化。 |
| 5 | 「训练 AI 模型就炼丹，没指标全靠感觉」 | ❌ 错！像相似度量化闭环（均值±标准差、多 seed 评测）、MTEB 召回基准测试、LLM-as-Judge 语义打分，都是成熟的量化指标体系。做 P7 必须建立「先量化再迭代」的工程化思维，不能拍脑袋调参。 |

---

## 七、一句话总结

> 大模型工程基础的本质是「**在有限显存、有限成本、有限时间的工程约束下，拿到最可用的模型效果**」。Transformer 是理论地基，LoRA 是微调成本下降 100 倍的钥匙，KV Cache/量化/投机解码是线上推理成本的「三板斧」，相似度量化闭环等方法论则是把 AI 从「玄学炼丹」拉回「可量化迭代的工程」的关键。P7 面试考察的不是手推 Attention 公式，而是**能讲清 LoRA 为什么能把全量微调的 80GB 显存压进 16GB T4、KV Cache 为什么能把 O(t²) 生成复杂度降到 O(t)、相似度量化闭环为什么要多 seed 报均值±标准差** 这类「原理→落地效果」的链路。
