# 工单与 Aone 闭环

⚠️ raw 缺失，待补充：以下为拟议业务流程；未提供内部工单、Aone API、状态枚举、Webhook 或权限模型，不能将公开云效接口视作内部 Aone 的已验证接口。见 [[AI项目/AgentMate/wiki/synthesis/AgentMate总体设计]]；[[AI项目/AgentMate/README]] 暂无实现说明。

## 工单状态机
RECEIVED → ENRICHING → INVESTIGATING → ANSWER_READY / NEED_INFO / ESCALATION_READY。
ANSWER_READY → 待验证 → RESOLVED；ESCALATION_READY → TRACKING_AONE → 待发布 → 待客户验证 → RESOLVED。
NEED_INFO 等待资料，支持超时提醒与恢复；任意阶段可取消或转人工；重开后建立新调查轮次，保留旧证据。
工单状态与 Aone 状态分别维护，通过事件关联，不能把“研发完成”自动等同于“客户问题解决”。

## 自动受理与诊断
- 输入规范化：症状、时间/时区、产品域、实例、环境、版本、客户影响、已执行操作、相关发布。
- 按工单字段和知识命中选择处理路径；严重故障可立即转值班，证据采集并行继续，避免模型调查延误响应。
- 简单问题：已审核知识足够时生成引用答案；实现细节问题：进入源码调查；运行异常：进入假设验证。
- 信息不足时只请求决定下一步的最少字段；工具不可用与“未查到”分别显示。
- 支持人员获得面向客户的答复草稿；研发获得内部技术诊断包。

## 研发诊断包
包含：问题摘要、影响范围、环境与精确版本、事件时间线、复现条件、预期/实际行为、已排除原因、候选根因、代码/日志证据、建议模块/负责人、下一步最小验证动作。
自动填充“待确认”而非编造复现步骤、优先级、负责人或承诺修复时间。

## 工单生成 Aone
1. 判断是产品缺陷、改进需求、文档缺口还是操作问题；不是所有工单都创建研发项。
2. 按产品域、版本范围、错误签名、关联实例和已有根因搜索重复项；语义相似只作候选，不直接合并。
3. 已有项则关联工单；新增项则先生成完整草稿，包含标题、描述、影响、证据、验收标准、建议类型及待确认字段。
4. 首期由有权限人员确认创建；成熟后允许管理员配置明确项目/类型/字段范围内自动创建。授权策略由服务端执行。
5. 提交使用稳定幂等键（来源系统、工单标识、调查轮次、动作类型），记录请求摘要与外部 ID。
6. 网络超时后先查询写入结果再重试；若接口不支持按幂等标识检索，进入待对账，禁止盲目重复创建。
7. 多工单关联一个 Aone 时分别维护客户可见信息；聚合统计不能泄漏其他客户资料。

## 定时同步进度
- 如内部接口支持事件通知，事件触发更新；定时增量拉取作补偿，默认周期可从 30 分钟试起，由限流和业务时效调整。
- 按项目保存 updatedAt 水位与分页位置，使用重叠时间窗防止边界遗漏；成功持久化后推进水位。
- 通过 eventId 或 workItemId + revision 去重；处理乱序，周期性校对未关闭关联项以弥补漏事件。
- 同步状态、负责人、阻塞、计划时间、关联变更、发布版本；缺字段保留未知，不从评论臆测状态。
- 仅状态变化、阻塞、逾期、需支持配合、修复待验证时通知相关人员；未变化保持安静。
- Aone 完成后检查合入/发布/实际部署/客户验证等独立证据；不能仅根据状态关闭工单。
- 外部删除、失去访问权限、限流、服务错误分别记录，不误标成完成。

## 知识回流
解决方案草稿 → 技术验证 → 可见性与脱敏检查 → 人工审核 → 发布为适用版本明确的知识 → 后续变更触发重验。
条目保留原工单、Aone、代码 commit、验证方法、审核人、适用版本、失效条件；模型答复本身不能成为“已验证事实”的唯一来源。

## 自动化分级
| 动作 | 首期执行策略 |
| :--- | :--- |
| 授权范围内读知识、源码、日志、Aone | 自动执行，记录访问与成本 |
| 生成答复、Aone、补丁、测试草稿 | 自动生成，展示证据 |
| 创建/更新 Aone、向客户发送答复 | 经过业务授权策略；初期人工确认 |
| 合并、发布、改生产配置 | 接入既有审批与发布流程，不能靠模型绕过 |

确认绑定到具体动作内容、对象和版本；内容变化或授权过期需重新检查，避免审批后实际写入不同内容。

## 故障与恢复验收
- 创建 Aone 超时后恢复不会创建两个工作项。
- 同一事件重复或乱序不会回退业务状态。
- 重启后恢复未完成任务，不重复执行已确认写入。
- 撤销仓库或日志权限后，缓存和历史会话也不能继续暴露原文。
- Aone 已完成但尚未发布时，客户工单仍保持待解决。
