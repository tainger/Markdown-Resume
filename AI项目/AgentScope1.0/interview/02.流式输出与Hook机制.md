# 流式输出与 Hook 机制

> 答题骨架：事件和内容 → 增量/累积 → 执行与观察 → Hook 的调度边界。返回 [[AI项目/AgentScope1.0/interview/README]]。

## Q09｜call 和 stream 有什么关系？

**口述答案**：call 返回完整结果的 Mono；stream 返回事件流 Flux。在 v1.0.12，`createEventStream` 临时加 StreamingHook，订阅内部 call，把推理/工具/总结事件送给外部 sink；call 结束按配置发 AGENT_RESULT，最后完成流。它们复用执行主链，不是两个不同的推理引擎。

**追问**：只想返回最终结果还要逐字展示吗？不必，可用 call，或者过滤 stream 的事件；但不要为同一需求分别订阅 call 和 stream，导致两次业务执行。

**边界**：流式 API 是框架事件流，不自动等于浏览器 SSE，需要应用层做协议转换和连接管理。

## Q10｜增量输出和累积输出怎么区分？isLast 是整个任务结束吗？

**口述答案**：增量模式给本次新增片段，UI 追加；累积模式给截至当前的完整内容，UI 替换。ReasoningContext 负责拼完整消息，StreamingHook 按 StreamOptions 选择发哪种。`isLast` 表示这次事件对应消息的完整版本，工具和推理都可能出现，不能仅凭它判定整个任务成功。

**追问**：什么时候知道流程结束？结合事件类型、最终消息原因与流完成信号；AGENT_RESULT 也受配置控制，不能假设任何配置都一定包含该事件。

**易错点**：把累积快照反复 append 会重复文本；同时展示 chunk 和完整消息也要按消息 ID 去重/替换。

## Q11｜结构化输出是不是简单在提示词里要求 JSON？

**口述答案**：框架通过 `generate_response` 工具表达目标结构，StructuredOutputHook 在模型未调用工具时加提醒重新推理，在需要时设置特定 tool_choice；工具成功后在 PostActing 请求停止，最后整理结构化输出相关 Memory。比只提示“返回 JSON”多了 Schema、受控工具和执行反馈。

**追问**：有 Schema 就能保证事实正确吗？不能，它约束结构，事实、业务范围和权限仍需服务端校验。模型/供应商对工具选择的支持也需验证。

**边界**：当前 Hook 对“没调用任何工具”的提醒默认最多 3 次，不是保证任意输入都生成合法业务对象。

**依据**：[[AI项目/AgentScope1.0/2.AgentScope Java特性：流式输出、结构化输出、超时与重试、执行控制]]；[StructuredOutputHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/StructuredOutputHook.java:68>)、[StructuredOutputHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/StructuredOutputHook.java:140>)、[StructuredOutputHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/StructuredOutputHook.java:161>)。

## Q12｜为什么流里工具执行结果和最终答案要分开处理？

**口述答案**：工具结果是给 Agent 下一轮推理的观察，可能含原始 JSON、错误和敏感数据；最终答案是 Agent 本轮输出。TOOL_RESULT 可用于进度和结构化卡片，AGENT_RESULT 用于展示最终响应，但还要检查 GenerateReason，挂起/中断并不是普通完成。

**追问**：直接把全部事件推给用户有什么问题？可能暴露工具参数、凭据和内部思考，也可能把中间失败当最终失败。建议建立明确事件白名单、脱敏和 UI 语义。

**边界**：事件过滤和脱敏属于应用职责，框架流式能力不自动提供产品级数据授权。

**依据**：[[AI项目/AgentScope1.0/2.AgentScope Java特性：流式输出、结构化输出、超时与重试、执行控制]]、[[AI项目/AgentScope1.0/9.AgentScope Java特性：工具集成]]；[StreamingHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/StreamingHook.java:84>)、[GenerateReason.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/message/GenerateReason.java:1>)。

## Q13｜Hook 的核心设计和生命周期是什么？

**口述答案**：Hook 统一通过 `onEvent` 接收事件，自行筛选类型。AgentBase 负责调用前后和错误，ReActAgent 负责推理、工具执行与总结相关事件。Pre 事件可改输入或参数，部分 Post 事件可改结果或请求停止；chunk 事件更多用于观察。

**追问**：和修改主循环相比有什么好处？日志、鉴权、压缩、记忆等横切逻辑能组合接入。代价是优先级和可变事件的相互影响需要明确契约。

**易错点**：不是声明关心哪类事件就由框架自动过滤所有其他事件；Hook 应对不处理的类型原样返回。

**依据**：[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]；[Hook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/hook/Hook.java:1>)、[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:565>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:905>)。

## Q14｜priority 越小越先执行，就保证所有 Hook 都串行吗？

**口述答案**：优先级升序，同优先级保持注册顺序；但还要看调度操作符。PreCall、PostCall 和普通 `notifyHooks` 使用 flatMap 串链，前一个完成再给下一个；ReasoningChunk 和 Error 通知用 Flux.flatMap，可能并发。排序列表并不保证所有异步处理按完成顺序执行。

**追问**：鉴权依赖上一个 Hook 修改完参数怎么办？应放在有顺序保证的执行事件链，避免把关键副作用放到并发 chunk 通知里。

**边界**：PendingToolRecovery 的 priority=10 不意味着一定第一个；AutoContextHook 在该标签实际 priority=0，自定义 Hook 也可更早。

**依据**：[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]、[[AI项目/AgentScope1.0/8.AgentScope Java中ReactAgent的实现原理]]；[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:601>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:938>)、[AutoContextHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-extensions/agentscope-extensions-autocontext-memory/src/main/java/io/agentscope/core/memory/autocontext/AutoContextHook.java:115>)。

## Q15｜修改 PostActingEvent 的 toolResult 后，Memory 一定会更新吗？

**口述答案**：要看实际写回字段。`notifyPostActingHook` 先构造工具结果消息并设到事件上，Hook 处理后写入 Memory 的是 `getToolResultMsg()`。因此若对结果做压缩或脱敏，仅 setToolResult 可能无法改变真正写入的消息；应同步维护 toolResultMsg，保留调用 ID、名称和关键元数据。

**追问**：适合用 Hook 做什么？可做结果格式归一、日志统计、凭据注入与策略检查，但应明确哪些是观察、哪些会改变执行内容，避免日志与执行事实不一致。

**易错点**：别只根据 setter 名称判断数据流，要沿最终消费者追踪字段。

**依据**：[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]、[[AI项目/AgentScope1.0/8.AgentScope Java中ReactAgent的实现原理]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:709>)、[PostActingEvent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/hook/PostActingEvent.java:1>)。

## Q16｜Hook 可以做单例吗？为什么 Reactor Context 也可能丢失？

**口述答案**：无状态 Hook 可以复用，有“首次注册”“当前结果”“计数器”等实例状态的 Hook 必须看隔离范围。AutoContextHook 用一个 registered 标记初始化工具，多个 Agent 共享同一 Hook 可能让后续 Agent 跳过初始化。另一方面，ReAct 的 chunk 通知使用独立 subscribe，不天然继承外层订阅的 Reactor Context。

**追问**：怎么改？建议每个 Agent 建立独立有状态 Hook；事件关联数据可显式绑定 Agent/运行 ID，或在同订阅链内传播。要验证清理、并发与取消，而不是仅换成 ThreadLocal。

**边界**：具体上下文是否能在某个回调读到值，要沿源码和测试确认，不能宣称响应式上下文在所有边界都自动传播。
