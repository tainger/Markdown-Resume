# 会话持久化与长期记忆

> 答题骨架：运行上下文 → 状态存储 → 恢复范围 → 长期语义记忆 → 一致性边界。返回 [[AI项目/AgentScope1.0/interview/README]]。

## Q25｜Memory 和 Session 为什么分成两层？

**口述答案**：Memory 是 Agent 当前运行时的对话上下文，决定模型看见哪些消息；Session 是可插拔状态存储接口，给组件保存和加载状态。Agent 状态还包括工具组激活、计划和压缩卸载数据，所以不应把“保存聊天文本”当作完整恢复。

**追问**：InMemoryMemory 线程安全就代表 Agent 并发安全吗？它使用 CopyOnWriteArrayList 管理消息，但一次 Agent 调用包含多步读改写，列表操作安全不等于整个执行流程隔离。

**边界**：Session 也不等于用户可见聊天记录数据库；展示消息与内部工具上下文可以有不同存储模型。

## Q26｜进程重启后怎样恢复多轮对话？需要重建哪些对象？

**口述答案**：先按相同定义重建模型、工具、Memory 和 Agent，再用同一 SessionKey 调用 loadIfExists/loadFrom，恢复受管理状态；执行新消息后在合适时机 saveTo。状态存储保存数据，不是把含网络连接、线程和函数引用的 Java 对象整体序列化。

**追问**：多个 Agent 共用一个 SessionKey 会怎样？它们写的状态字段可能相同，应给用户/会话/Agent 建立清晰命名空间，避免覆盖；共享数据库不自动隔离业务身份。

**边界**：工具实现、提示词与模型版本变化可能影响恢复后的行为，需要持久化版本和兼容策略，这属于应用设计。

**依据**：[[AI项目/AgentScope1.0/3.AgentScope Java特性：多轮会话&会话持久化]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:236>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:242>)、[SessionKey.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/state/SessionKey.java:1>)。

## Q27｜ReActAgent.saveTo 保存了什么？StatePersistence.all 就等于一切都保存吗？

**口述答案**：当前 saveTo 总是保存 Agent 元数据，按开关保存 Memory、Toolkit activeGroups 和 PlanNotebook；loadFrom 对应恢复后三者。StatePersistence 提供四个管理开关，但 v1.0.12 的 ReActAgent 保存/加载方法没有看到 statefulToolsManaged 对应的工具状态遍历。

**追问**：工具自己有临时状态怎么办？不要仅凭开关名称承诺已保存，应沿实际 saveTo/loadFrom 路径确认，必要时让工具实现独立 StateModule 并显式纳入保存。

**边界**：loadFrom 也没有把全部 agent_meta 字段直接恢复到新对象；应按相同配置重建，不能说保存了元数据就自动重建配置。

## Q28｜SessionManager 是自动事务管理器吗？

**口述答案**：不是。它提供 forSessionId、withSession、addComponent、loadIfExists、saveSession 等链式入口，内部依次调用每个组件的保存/加载。它简化手工组织组件，不能仅凭方法名保证多个组件跨文件/跨键一起原子提交。

**追问**：JsonSession 注释说 atomic file operations，就能抗掉电吗？当前单值 save 直接 Files.writeString，不能从注释推导临时文件替换、fsync 或跨字段事务。生产可靠性要结合后端实现逐项验证。

**边界**：如果业务需要一致快照，可设计版本化快照和提交标记；这属于建议，不能写成当前所有 Session 的保证。

**依据**：[[AI项目/AgentScope1.0/3.AgentScope Java特性：多轮会话&会话持久化]]；[SessionManager.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/session/SessionManager.java:163>)、[JsonSession.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/session/JsonSession.java:99>)。

## Q29｜每次 call 会自动加载、自动保存 Session 吗？

**口述答案**：通用 call 主链并没有无条件包上 Session 读写。应用需要显式调用保存/加载，使用 Hook 或其他集成层安排时机；GracefulShutdown 可在绑定 Session 后处理退出保存，是另一条生命周期路径。SessionManager 的存在也不代表每次自动调用它。

**追问**：中断后只靠 PostCall 保存安全吗？不安全，AgentBase 的中断错误处理直接走 handleInterrupt，绕过正常 PostCall 位置。应检查框架系统关机保存与应用用户中断保存的实际覆盖范围。

**边界**：自动化入口、保存时机和恢复键必须具体说明，不能笼统回答“框架都有持久化所以不会丢”。

## Q30｜长期记忆与聊天历史有什么区别？三种模式怎么选？

**口述答案**：长期记忆面向跨会话有用的信息，例如用户偏好与长期事实，接口提供 record/retrieve；聊天 Memory 面向当前推理历史。AGENT_CONTROL 注册记忆工具让模型选择何时记录/召回，STATIC_CONTROL 注册 Hook 自动处理，BOTH 同时启用。选择取决于召回频率、延迟、成本和信息治理要求。

**追问**：BOTH 一定最好吗？不一定，可能增加重复召回、记录和不必要上下文；应看任务集与后端延迟。接入百炼、Mem0 或 ReMe 也不自动解决身份隔离。

**边界**：服务可用性、删除、更正与隐私保留策略需要单独设计。

**依据**：[[AI项目/AgentScope1.0/4.AgentScope Java特性：长期记忆]]、[[AI项目/AgentScope1.0/6.实战：实现AgentScope的三层记忆体系]]；[LongTermMemory.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/memory/LongTermMemory.java:1>)、[LongTermMemoryMode.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/memory/LongTermMemoryMode.java:1>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1607>)。

## Q31｜STATIC_CONTROL 实际在哪个事件召回？注入什么角色？

**口述答案**：以 v1.0.12 为准，StaticLongTermMemoryHook 在 PreCall 找最后一条 USER 作查询，召回后构造名为 long_term_memory 的 USER 消息，追加到输入；PostCall 再按配置记录。不是每一轮 PreReasoning 召回，也不是直接注入 SYSTEM 消息，注释与部分原文存在旧口径。

**追问**：自动记录异步就不会丢吗？异步路径有调度、队列和退出窗口，需要观察失败与拥塞，不能把 fire-and-forget 等同于持久可靠投递。

**易错点**：记忆属于数据，用户身份和授权不能从召回文本中恢复成可信凭据。

**依据**：[[AI项目/AgentScope1.0/4.AgentScope Java特性：长期记忆]]、[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]；[StaticLongTermMemoryHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/memory/StaticLongTermMemoryHook.java:122>)、[StaticLongTermMemoryHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/memory/StaticLongTermMemoryHook.java:151>)。

## Q32｜三层记忆体系怎么落到工程？如何防止“记住错误事实”？

**口述答案**：工作记忆服务当前推理，Session 保存可恢复执行状态，长期记忆保存跨会话语义事实。先明确哪些信息应记录、归属于谁、多久有效；业务订单状态等应回权威系统查询，不靠模型记忆当数据库。长期记录应保留来源/时间，支持纠正与删除，再用独立问题验证召回。

**追问**：增加向量库就算完成长期记忆了吗？只完成存储/检索的一部分，还涉及提取、去重、冲突、权限、更新及评测。

**待补**：⚠️ raw 缺失，待补充：具体应用的记忆污染回归、用户隔离与删除验证报告。本题治理措施为建议，框架接口存在不等于应用已实现。
