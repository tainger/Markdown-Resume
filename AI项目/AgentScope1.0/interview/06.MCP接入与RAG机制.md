# MCP 接入与 RAG 机制

> 答题骨架：协议适配与知识抽象 → 调用/检索路径 → 控制权 → 失败、权限与评分边界。返回 [[AI项目/AgentScope1.0/interview/README]]。

## Q41｜MCP 工具怎么变成 AgentScope 工具？

**口述答案**：模型上下文协议 Model Context Protocol（MCP）接入通过 McpClientBuilder 建客户端，McpClientWrapper 抽象通信和工具列表；Toolkit 的 MCP 管理层查询工具描述，包装为实现 AgentTool 的 McpTool。模型照常看到工具 Schema，执行时远程 callTool，返回内容由 McpContentConverter 转成框架 ToolResultBlock。

**追问**：MCP 是 Agent 互相交接任务的协议吗？此处用于连接外部工具服务，不要与 SubAgentTool 的进程内委派或其他 Agent 协议混为一谈。

**边界**：协议统一不能保证工具描述可信、调用有业务授权或返回事实正确。

## Q42｜v1.0.12 支持哪些 MCP 传输？超时怎样分层？

**口述答案**：这个标签的 Builder 提供 stdioTransport、sseTransport 和 streamableHttpTransport，分别适配本地进程与不同 HTTP 传输。初始化超时控制握手，调用 timeout 控制请求等待，外层工具 ExecutionConfig 还可限制整个工具执行。具体部署要按服务端能力配置。

**追问**：连接失败时能透明重试到成功吗？不能这样保证。要区分握手失败、连接中断、业务失败、异常是否已转成错误结果，以及操作是否可重试。

**边界**：这里只描述该标签支持的 API，不把老示例里出现的传输方式当作未来协议推荐或当前服务商支持承诺。

## Q43｜同时配置 enableTools 和 disableTools，谁优先？

**口述答案**：以 McpClientManager.shouldRegisterTool 为准，先应用 disableTools，再在非空 enableTools 时覆盖结果，所以 enable 列表优先。没有非空筛选列表时默认全注册。尤其不能把空 enable 列表误解成“一个工具也不允许”。

**追问**：只注册少量工具有什么收益？减少 Schema 长度、模型选择干扰和暴露面；但服务端仍要核验用户和动作权限，工具可见性不是资源授权的替代。

**边界**：不能凭通常习惯回答“黑名单一定覆盖白名单”，必须按本版本代码解释。

**依据**：[[AI项目/AgentScope1.0/10.AgentScope Java特性：MCP接入]]；[McpClientManager.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/McpClientManager.java:273>)。

## Q44｜RAG 的几个核心抽象怎样分工？

**口述答案**：检索增强生成 Retrieval-Augmented Generation（RAG）中，Reader 读文档并切块，EmbeddingModel 把内容转成向量，VDBStoreBase 存储/搜索向量，Knowledge 对外提供 addDocuments/retrieve。SimpleKnowledge 将文档向量化后批量写库，查询时向量化 query、检索并按阈值过滤/排序；也可以接第三方 Knowledge 实现。

**追问**：Knowledge 是大模型吗？不是，它提供检索知识，生成回答仍由模型执行；检索结果也不是天然准确答案。

**边界**：分块、向量维度与后端评分需要匹配，框架抽象不会自动保证语料、权限和版本质量。

**依据**：[[AI项目/AgentScope1.0/11.AgentScope Java特性：RAG]]；[Knowledge.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/rag/Knowledge.java:1>)、[SimpleKnowledge.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-extensions/agentscope-extensions-rag-simple/src/main/java/io/agentscope/core/rag/knowledge/SimpleKnowledge.java:97>)、[SimpleKnowledge.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-extensions/agentscope-extensions-rag-simple/src/main/java/io/agentscope/core/rag/knowledge/SimpleKnowledge.java:135>)。

## Q45｜GENERIC 与 AGENTIC RAG 的控制权有什么区别？

**口述答案**：GENERIC 在调用前通过 GenericRAGHook 自动检索并把结果补到输入，流程可预测；AGENTIC 把 KnowledgeRetrievalTools 注册进 Toolkit，由模型决定何时检索、用什么查询，也可能不检索或多轮检索。前者适合每次都需要同类知识的任务，后者给模型更多探索空间。

**追问**：Generic 每轮 reasoning 都查一次吗？该标签实际监听 PreCall，不是每轮 PreReasoning。Agentic 是否反复查则由工具调用轨迹决定。

**边界**：Agentic 不必然更准确，可能漏检或增加轮次；Generic 也可能给不需要知识的简单请求增加延迟。

**依据**：[[AI项目/AgentScope1.0/11.AgentScope Java特性：RAG]]、[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1634>)、[GenericRAGHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/rag/GenericRAGHook.java:107>)、[KnowledgeRetrievalTools.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/rag/KnowledgeRetrievalTools.java:1>)。

## Q46｜检索没命中或调用失败，Generic RAG 会怎样？

**口述答案**：GenericRAGHook 从最后一条 USER 提取查询；输入空、无查询或结果为空时保留原事件，检索异常会记录警告并返回原事件，主调用可能继续。这样提高可用性，但也可能在无知识依据时让模型生成回答。

**追问**：企业政策问答允许继续凭常识答吗？要由应用定义：可返回缺资料、追问或人工处理，而不是默认把框架降级视为满足业务准确性要求。

**边界**：外部召回内容属于数据，不能因为注入上下文就升级为可信指令。来源引用与拒答策略需要额外设计和验证。

**依据**：[[AI项目/AgentScope1.0/11.AgentScope Java特性：RAG]]；[GenericRAGHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/rag/GenericRAGHook.java:128>)、[GenericRAGHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/rag/GenericRAGHook.java:173>)。

## Q47｜多个 Knowledge 接在一个 Agent 上，结果如何融合？

**口述答案**：Builder 生成聚合 Knowledge，并发调用各库 retrieve，按 Document ID 去重，重复项选择较高分，再按分数排序并截到配置 limit。它是直接基于返回分数的汇总，不是自动学习的重排模型，也不等同于倒数排名融合 RRF。

**追问**：不同库的 score 能直接比较吗？未必，不同后端可能有不同量纲、相似度或距离定义。需要统一评分、做归一化/排名融合或明确路由；还要避免跨库 Document ID 碰撞。

**边界**：这些是对当前聚合逻辑的限制分析，不能宣称该实现已解决所有多库排名问题。

**依据**：[[AI项目/AgentScope1.0/11.AgentScope Java特性：RAG]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1663>)。

## Q48｜chunkSize、overlap 和 scoreThreshold 怎么调，怎么评测？

**口述答案**：块太小可能丢语义，太大可能带噪声并增加上下文；overlap 保留边界信息也增加重复。阈值决定低相关结果是否进入候选，Top-K 决定候选规模。先保留文档/段落来源，使用独立问题与证据片段标注集，分别看召回、回答依据、拒答和延迟，再调参。

**追问**：阈值 0.8 是 80% 正确率吗？不是，它是后端检索分数门槛，先核对分数方向和定义。提高阈值可能降低噪声，也可能漏掉需要的证据。

**待补**：⚠️ raw 缺失，待补充：具体语料、查询集、召回/生成质量实测。本题是评测建议，不把示例参数当通用最优值。
