# HITL、中断恢复与生产追问

> 答题骨架：暂停点 → 保存的状态 → 恢复协议 → 故障窗口 → 验证办法。返回 [[AI项目/AgentScope1.0/interview/README]]。

## Q57｜敏感动作前确认和执行后确认分别在哪个 Hook 做？

**口述答案**：人机协同 Human-in-the-Loop（HITL）可以在 PostReasoning 检查模型提出的工具调用并 stopAgent，此时调用已入 Memory 但还没执行；PostActing 则用于工具执行后暂停继续推理。返回原因分别为 REASONING_STOP_REQUESTED 与 ACTING_STOP_REQUESTED，应用据此展示确认或审阅界面。

**追问**：执行后停止能阻止刚才的副作用吗？不能，工具已经运行。高风险动作应在执行前由应用策略校验和确认，不能靠事后停止补授权。

**边界**：同批多个工具结果的 acting 最后用 `.last()` 读取停止标志，早先结果事件的 stop 请求不能直接视为整批都生效，需单独验证。

## Q58｜ToolSuspendException 和 stopAgent 有什么不同？

**口述答案**：stopAgent 是在生命周期事件上请求停止后续流程；ToolSuspendException 是工具主动表示需要外部输入，ToolExecutor 将它转成 suspended 结果。ReAct 保存已完成工具的结果，不把挂起结果当完成写入 Memory，最终返回 TOOL_SUSPENDED，包含需要恢复的工具调用与挂起信息。

**追问**：一个工具挂起，其余工具都没执行吗？不一定，同批并行工具可能已经成功。恢复必须按 pending ID 处理，避免重跑已经完成的副作用。

**易错点**：挂起返回后本次调用结束，不是占着线程等待用户点按钮；保存运行状态和后续入口是应用需要接上的部分。

## Q59｜用户回复之后，如何把答案交回原工具调用？

**口述答案**：构造与 pending ToolUseBlock 相同 ID 的 ToolResultBlock，作为消息传给 call。`validateAndAddToolResults` 检查重复 ID、未知 ID，部分回填时禁止混入其他内容；通过后写入 Memory，未完成部分继续 acting，否则进入推理。对动作前暂停，也可空 call 继续执行未完成工具。

**追问**：这些 ID 校验能替代用户授权吗？不能。应用还要验证会话归属、pending 有效期、确认对象和一次消费，禁止任意客户端伪造别人的工具结果。

**边界**：框架校验的是 Memory 中的协议一致性，不天然提供跨节点数据库抢占锁。

**依据**：[[AI项目/AgentScope1.0/13.AgentScope Java进阶：Human-in-the-Loop]]、[[AI项目/AgentScope1.0/8.AgentScope Java中ReactAgent的实现原理]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:378>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:264>)。

## Q60｜PendingToolRecoveryHook 默认启用吗？它恢复的是执行结果吗？

**口述答案**：v1.0.12 的 Builder 字段 `enablePendingToolRecovery=false`，要显式开启或手动注册 Hook，不能沿用笔记和类注释的“默认开启”。启用后若发现 pending 且新输入不是空恢复或 ToolResult，它生成合成错误结果补洞，让后续模型调用不因悬空工具协议失败。

**追问**：生成错误结果能证明工具在外部没成功吗？不能，它只是恢复对话结构，不是查供应商实际结果或回滚副作用。恢复前后仍需要业务查单和幂等。

**易错点**：priority=10 也不代表在所有 Hook 中第一个；如果你在别的 Hook 才加载 Memory，还要明确排序，保证补洞看到的是正确状态。

**依据**：[[AI项目/AgentScope1.0/13.AgentScope Java进阶：Human-in-the-Loop]]、[[AI项目/AgentScope1.0/8.AgentScope Java中ReactAgent的实现原理]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1118>)、[PendingToolRecoveryHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/hook/PendingToolRecoveryHook.java:84>)。

## Q61｜interrupt() 怎样生效？能立即杀掉正在执行的外部操作吗？

**口述答案**：AgentBase 设置中断标志和来源，ReAct 在阶段切换、模型 chunk 消费等位置检查，抛出中断信号后走 handleInterrupt 返回恢复消息。它是协作式中断，不是对任意线程/第三方请求的强制回滚。长工具是否及时停止，要看其实现是否响应取消或中断。

**追问**：为什么中断后 PostCall 保存可能没发生？主链先安排 notifyPostCall，再在错误路径处理 InterruptedException；handleInterrupt 返回恢复消息不会重新经过前面的 PostCall 节点。

**边界**：应区分用户中断和系统关机策略，已经完成的下单、文件写入等副作用不因中断消失。

## Q62｜有 Session 和 pending，就能任意宕机后精确续跑吗？

**口述答案**：它们提供恢复所需的状态能力，但还要看保存时机、存储原子性和外部副作用。若工具已经成功而结果没存，下次可能误判为 pending 重跑；若只有压缩标记没保存 offload 数据，也无法补回细节。跨节点重建还需要相同工具定义和共享存储。

**追问**：如何更可靠？建议保存业务 requestId、动作状态和结果，未知状态先查事实；恢复入口原子消费确认凭据，状态版本与执行版本绑定。框架运行恢复和业务幂等分别实现。

## Q63｜优雅关机如何工作？kill -9 也能保存状态吗？

**口述答案**：GracefulShutdownManager 管理活跃请求、关机阶段和超时信号，新请求取得执行权时会检查是否还接受请求。已有请求按配置收敛或系统中断，绑定的 Session 可用于保存状态；部分推理结果可选 SAVE/DISCARD。默认 shutdownTimeout=null，表示没有指定有限等待上限。

**追问**：为什么生产应明确预算？容器的退出宽限时间、长工具和框架等待时间要对齐；否则还没保存完就可能被系统强杀。

**边界**：kill -9、掉电或进程崩溃不会保证执行 JVM 关机 Hook；优雅保存也不等于撤销所有第三方副作用。
