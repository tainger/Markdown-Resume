# 应用层RAG与旧接口迁移

> 新示例先检索再组装上下文，兼容接口只作为迁移背景。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 不照搬旧 RAG 配置

检索增强生成 Retrieval-Augmented Generation（RAG）仍有“固定先检索”和“模型通过工具按需检索”两种应用设计。v2.0.4 自带 ApplicationLayerRagExample 采用应用层 retrieve → prompt → ReActAgent 的明确链路。

旧 `knowledge` / `knowledges` / `ragMode` Builder 方法存在，且标为 `@Deprecated(forRemoval=true)`，适配器仍有功能；不能写成“已完全删除”，也不应将其包装为新版主线。

本地 integration 文档示例里的 `RAGMode.STATIC` 不在枚举中；实际旧枚举只有 GENERIC、AGENTIC、NONE。来源冲突详见核对页。

## 应用层链路

```text
用户问题
 → 应用按权限过滤后检索（关键词/向量/混合等由应用实现）
 → 保留文档 ID、片段和来源
 → 构造“检索资料 + 用户问题”的输入
 → 普通 Agent 生成答案
 → 应用检查引用、拒答和任务结果
```

仓库示例是内存关键词重合计分，不是已经实现了向量检索、混合召回或重排。替换检索器时要各自验证数据接入、过滤、召回与生成。

## 固定检索与工具检索

| 方式 | 适用 | 需要控制 |
|:---|:---|:---|
| 应用先检索 | 每次都应查固定业务知识 | 权限过滤、空召回、上下文预算 |
| 自建检索工具 | 多步骤任务，按需查库 | 工具权限、查询改写、调用次数、引用 |

这些是应用设计建议；本目录没有提供某个检索平台的生产接入成果。

## 与长期记忆的区别

知识库通常管理业务知识，工作区记忆管理用户/任务长期事实，AgentState.context 管理当前对话。三者可能互相引用，但索引、权限和更新周期不同，不能因为都能“补充上下文”就混为一个存储。

## 如何验收

分别看检索命中、引用可溯源、无答案时拒答和用户间资料隔离，再统计耗时与成本。⚠️ raw 缺失，待补充：领域测试集、索引规模、召回与答案质量报告。
