# Skill装配、作用域与自学习

> 技能是按需读取的能力包，执行仍通过工具和权限系统。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## Skill 是什么

技能 Skill 以 SKILL.md 描述用途与指令，可带 references、scripts 等资源。读取技能不会自动执行脚本；脚本运行需要 shell/文件系统工具以及相应权限。

旧 SkillBox 路线仍有兼容入口；新版主线通过 skillRepository 与 Harness 工作区动态合成。

## 四层优先级

| 从低到高 | 来源 | 同名处理 |
|:---|:---|:---|
| 1 | projectGlobalSkillsDir | 作为基础 |
| 2 | 市场/仓库 | 覆盖低层，同层按注册关系处理 |
| 3 | 工作区共享 skills | 覆盖前层 |
| 4 | 用户 skills | 用户命名空间中最高优先 |

动态装配从本次 RuntimeContext 获取用户与会话；不要缓存全局“当前已激活用户技能”。只让用户提供一个 skill 名字，不等于允许越过其作用域读取其他用户文件。

## 资源读取与执行

技能加载工具按 skillId/path 读取 SKILL.md 或声明的资源路径。文件系统决定这些资源物化在本机、远端还是沙箱；模型不能把任意绝对路径当作 skill 资源读取。

动态更新要同时检查版本、作用域、资源与工具能力。禁用动态技能意味着改变刷新时机，不代表脚本权限随之自动放宽。

## 自学习闭环

草稿提出 → 可见性与审批闸门 → 晋升正式技能 → 审计与维护。该能力需要相关配置；不应把所有生成的草稿自动当成可信正式技能。

本标签程序化晋升入口为 `promoteSkill(name, reviewerId, ctx)`，显式传上下文；本地文档残留的两参数示例应更新理解，不能照抄。

## 高频追问

- Skill 与 Tool：前者表达操作知识，后者执行动作并提供结果。
- Skill 与 RAG：前者多为能力流程，后者常提供任务事实；两者都可能含不可信内容。
- 用户级覆盖与权限：覆盖优先级只决定读取哪份说明，不构成业务授权。

⚠️ raw 缺失，待补充：用户技能隔离、审批晋升、脚本沙箱联调的运行报告。
