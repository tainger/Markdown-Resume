# Human-in-the-Loop与AgentRun执行控制

> 区分审批挂起、外部工具挂起、协作中断和立即取消。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 四类控制不能混用

| 情况 | 协议/入口 | 恢复重点 |
|:---|:---|:---|
| 工具权限需要人确认 | RequireUserConfirmEvent / PERMISSION_ASKING | 回填 ConfirmResult，校验工具 ID 与会话 |
| 工具由外部执行 | TOOL_SUSPENDED / 外部结果事件 | 调用方执行后提交相同 ID 的 ToolResult |
| 用户要求停止当前执行 | AgentRun.interrupt 或 session interrupt | 在检查点协作中断，形成恢复消息 |
| 立即取消本次执行 | AgentRun.cancel | 取消响应式执行，不承诺生成恢复回复或保存路径 |

人工参与 Human-in-the-Loop（HITL）只是其中的审批路径。外部执行和用户中断各有不同的状态与输入要求。

## 审批恢复协议

从确认事件保存待审批 ToolUseBlock，在应用完成身份与会话校验后收集决定。以下片段中的 pendingToolCall 应来自该次事件，ctx 必须标识原用户/会话：

```java
import io.agentscope.core.event.ConfirmResult;
import io.agentscope.core.message.Msg;
import io.agentscope.core.message.UserMessage;
import java.util.List;
import java.util.Map;

UserMessage confirmation = UserMessage.builder()
        .metadata(Map.of(Msg.METADATA_CONFIRM_RESULTS,
                List.of(new ConfirmResult(true, pendingToolCall))))
        .build();
agent.call(List.of(confirmation), ctx).block();
```

自然语言“同意”不是 ConfirmResult；ASKING 工具恢复前会校验非空结果、ID 唯一性及是否属于待审批集合；工具名、参数修改和新增规则的业务授权仍由应用核对。pending recovery 默认关闭，即使显式开启也不能跳过 ASKING。

## 单次执行句柄

`prepareRun` 或 `prepareCall` 返回惰性 AgentRun。先登记 runId 和调用者，再且仅订阅一次 `stream()`；订阅才开始执行。一个句柄重复订阅会报错，重试应创建新句柄。

运行状态为 CREATED、QUEUED、RUNNING、COMPLETED、FAILED、CANCELLED；termination 可以观察终态但不会启动执行。

取消排队中的 B 不应取消运行中的 A，也不让后续 C 越过 A；源码队列专门保持前驱依赖。按 session 的 interrupt 只选中当前运行者，需要选择某次排队请求时使用句柄。

## 应用仍需负责

runId 查询与鉴权、终态清理、审批归属、重复提交和外部幂等都由应用设计。工具已产生的外部副作用不会因 cancel 回滚，不响应取消的阻塞调用也不能保证立即停止。

⚠️ raw 缺失，待补充：审批重放、取消竞态、宕机窗口和精确一次业务操作验证。
