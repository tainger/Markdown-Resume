# Plan模式、子Agent与Harness部署

> 把只读规划、任务清单、子任务隔离和运行存储连起来。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## Plan Mode 不只是写一段计划

Harness 的 `.enablePlanMode()` 装配计划工具与拦截逻辑。plan_enter 进入规划、plan_write 写计划正文、plan_exit 通过 ASK 申请退出。非白名单写工具受拦截；todo_write 可维护任务清单，shell 需显式配置是否在计划阶段放开。

开启 Plan Mode 能力不应被理解为所有任务都自动完成严格的计划审批流程。计划文本也不是可执行工作流：模型仍需选择工具、处理失败并验证结果。

| 数据 | 所在位置 | 压缩影响 |
|:---|:---|:---|
| PlanModeContextState | AgentState 独立字段 | 不属于对话摘要输入 |
| 计划正文 | 工作区 plans 文件 | 文件按自身生命周期保存 |
| todo 清单 | AgentState.tasksContext | 独立于聊天消息 |
| 子任务记录 | TaskRepository / 工作区任务文件等 | 需要对应后端恢复 |

## 子 Agent 委派

Harness 支持工作区 subagents 声明与编程声明。主 Agent 调用 agent_spawn；同步返回结果或后台返回 task_id，任务完成信息可在后续推理前作为提醒注入。

同步超时默认可能晋升后台；若通过 RuntimeContext 强制同步，超时处理有所不同。不能把“调用超时”统一解释为“子任务已经终止”。

ISOLATED 与 SHARED 表达工作区关系，隔离上下文不等于共享文件没有并发写风险。依赖任务先等上游，互相独立的任务才适合并行；这是任务设计建议。

## 从本机学习到多副本

```text
Core AgentStateStore：保存会话状态与版本
工作区 filesystem：保存记忆、技能资源、日志与产物
TaskRepository / bus：跟踪后台任务与结果
沙箱与快照：约束工具执行环境并恢复文件
应用运行管理：鉴权、预算、审批、观测与幂等
```

Harness 默认本机状态文件不构成分布式方案。RemoteFilesystemSpec 与本地状态存储的组合在本标签 build 中会被拒绝；分布式部署需一起核对状态、文件、任务、消息与互斥后端。

不要根据“有 Redis”或“有沙箱”就承诺整条链具备跨节点精确恢复。⚠️ raw 缺失，待补充：多副本部署、故障注入、任务重领和外部幂等报告。
