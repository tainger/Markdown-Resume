# 流式输出、结构化输出与执行控制

> 围绕 AgentEvent 消费事件，把循环限制与调用预算分开。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## call 与事件流

`call` 交付最终 Msg；`streamEvents` 逐个交付 AgentEvent，适合在界面展示文本片段、工具执行及确认请求。它们驱动相同任务，不能为了同时拿最终答案和事件而各订阅执行一次。

```java
// 片段：agent 与 ctx 沿用第 1 篇；只订阅这一次事件流。
agent.streamEvents(List.of(new UserMessage("说明一次工具调用的步骤。")), ctx)
        .doOnNext(event -> {
            if (event instanceof io.agentscope.core.event.TextBlockDeltaEvent text) {
                System.out.print(text.getDelta());
            }
        })
        .blockLast();
```

Delta 是片段，应追加；最终消息与生命周期事件承担不同职责。不要把所有事件都当文本，确认事件需交给审批交互处理。

## 结构化输出的两条路

ReActAgent 的 `call(messages, TargetClass.class, ctx)` 或 JSON Schema 重载会按模型能力选择原生结构化输出或工具回退路径。原生路线不等于所有模型都支持相同 Schema；回退路线会使用 `generate_response` 工具。

应用拿到结构后仍应验证业务规则，例如日期先后、金额范围、资源归属。结构合法只说明形状可接受。

## 重试、回退与超时

| 控制 | 范围 | 需要注意 |
|:---|:---|:---|
| `maxIters` | ReAct 轮次，默认 10 | 不是整个任务的网络请求或 token 硬预算 |
| `ModelConfig.maxRetries` | 进入模型执行配置 | 本标签传给 `maxAttempts`，默认 3 表示总尝试最多 3 次 |
| `fallbackModel` | 主模型失败后的候选模型 | 接管条件需按模型流实现理解，不能保证任意已输出的流都无缝切换 |
| `ExecutionConfig.timeout` | 对应模型/工具执行 | 超时与重试叠加后总耗时可能更长 |
| `AgentRun` | 单次排队或运行中的执行 | 用句柄精确取消或协作中断，见第 13 篇 |

`maxRetries` 的名字容易被理解成“初次之外再试三次”，本系列按 `buildGenerateOptions → maxAttempts → Retry.backoff(maxAttempts - 1)` 解释。显式执行配置还有覆盖优先级。

## 复习与验收

- 口述一遍“订阅 → 事件 → 文本追加/工具/审批分发 → 最终结果”。
- 分开记录单次模型尝试数、ReAct 轮次、子 Agent 次数和任务总时长。
- ⚠️ raw 缺失，待补充：真实供应商的流中失败、结构化兼容性、重试成本测试。上述控制机制不能代替这些实测。
