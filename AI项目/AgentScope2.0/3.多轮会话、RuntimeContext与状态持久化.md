# 多轮会话、RuntimeContext与状态持久化

> 将调用元数据、可恢复状态和工作区文件分开管理。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 三类数据

| 对象 | 生命周期 | 内容 |
|:---|:---|:---|
| RuntimeContext | 当前一次调用 | userId/sessionId、请求 ID、类型化依赖、调用期 AgentState 引用 |
| AgentState | 会话状态 | 对话、摘要、权限、工具组/技能、任务清单、Plan Mode 等 |
| 工作区文件 | 文件自身生命周期 | 长期记忆、计划正文、日志、子任务记录；不等同于 AgentState |

用户与会话字段用于寻址，自由属性并不会全部序列化进状态。身份必须由应用鉴权后设置，不能信任模型提交的同名参数。

## 一次调用如何保存与恢复

```text
订阅 → 按 (userId, sessionId) 进入本实例会话队列
     → 有 store：加载 agent_state；无 store：使用该 slot 的内存缓存
     → 创建 CallExecution，ctx 绑定本次 AgentState
     → 推理/工具修改本次状态 → 保存状态 → 释放会话执行位置
```

Core 不配置 store 时仍可在实例存活期间保存同一 slot 的历史，但重启后不恢复。Harness 默认装配文件状态存储，不能把两种默认行为混讲。

## 两轮会话片段

```java
// 片段：builder 中明确配置 store，再创建 agent。
.stateStore(new io.agentscope.core.state.JsonFileAgentStateStore(
        java.nio.file.Path.of(".agentscope/learning-state")))
```

两次 `call` 各创建独立 RuntimeContext，填入相同 userId/sessionId；第二轮才能定位同一会话。不同会话应使用不同 sessionId。

## 并发与跨节点

同实例、同 slot 的执行由异步门串行；不同 slot 可以并发。门保存在 AgentBase 内存 map 中，不能据此推出多副本分布式互斥。

支持版本的 AgentStateStore 可做比较并交换 Compare-And-Swap（CAS）写入。冲突策略包括 FAIL、OVERWRITE、APPEND_MERGE；后者并非任意状态的语义合并，当前实现追加上下文增量并处理权限字段，不能假定工具/任务/计划均被正确合并。

工具与中间件应从 `ctx.getAgentState()` 或 `RuntimeContext.resolveAgentState(ctx, agent)` 取得本次状态。不要把调用上下文写进共享 middleware 字段。

## 故障边界

普通失败有保存已累积安全上下文的路径；中断另有协调处理。直接 cancel、进程崩溃、外部调用成功后本地未保存，都不能宣称精确一次。

⚠️ raw 缺失，待补充：跨节点争用、版本冲突和外部幂等的运行报告。
