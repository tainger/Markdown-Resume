# 长期记忆与工作区

> 以工作区记忆文件理解 Harness，不沿用旧长期记忆模式作为主线。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 从 1.0 三模式走向工作区

1.0 的 LongTermMemory/模式接口在本标签存在 deprecated 兼容入口；新主线是 Harness 工作区中的长期事实与维护能力。旧接口仍存在，不代表新项目应继续从旧 Builder 配置入手。

## 双层记忆

| 内容 | 用途 | 读取方式 |
|:---|:---|:---|
| `MEMORY.md` | 精炼、相对稳定的长期事实 | 工作区上下文注入，受预算约束 |
| `memory/*.md` | 增量事实与历史记录 | `memory_search` / `memory_get` 按需读取 |
| 会话 JSONL 日志 | 查询原始历史 | `session_search` / `session_history` |

长期记忆与日志不同：前者经提炼，后者承担历史检索。AgentState 的当前上下文也不是全部原始历史的永久档案。

## 写入链路

摘要压缩前可启用事实提取 Memory Flush；随后后台维护逻辑按节流条件整理、归档或合并。`flushBeforeCompact=true` 表示压缩前尝试提取，不表示每个请求都同步完成全部后台维护。

源码把普通 flush/offload 失败视为 best-effort，继续后续摘要；涉及中断则传播。因此不能承诺“摘要前长期记忆一定写成功”。

## 工作区与状态存储

Harness 默认状态根为 `~/.agentscope/state/<agentId>/`，与工作区解耦。备份 MEMORY.md 不等于备份可恢复状态；备份 AgentState 也不等于保存了全部文件和子任务产物。

多用户文件访问要结合 userId 与 filesystem 的隔离配置。工作区共用文件可以作基线，运行期文件按命名空间处理；不能只创建不同 sessionId 就认为任意物理文件都已经隔离。

## 复习与设计建议

- 回答“记住了什么”时，说明是上下文、长期事实还是原始日志。
- 对长期事实保留来源、更新时间和删除入口；这是应用设计建议，不是本库已完成的生产功能。
- ⚠️ raw 缺失，待补充：记忆准确率、错误事实纠正与用户数据删除的运行证据。
