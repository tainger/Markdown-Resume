# 智能上下文压缩与工具结果卸载

> 理解摘要、原文日志、结果卸载和溢出兜底的分工。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 先明确默认值

v2.0.4 Harness Builder 默认构造 CompactionConfig 与 ToolResultEvictionConfig，两个 disable 标志均为 false；文档中“默认全部不开”的说法与源码不一致。裸 ReActAgent 与 Harness 的装配不同。

CompactionConfig 默认 `triggerMessages=50`、`keepMessages=20`、`triggerTokens=0`、`keepTokens=-1`。其中 0 的 triggerTokens 表示动态阈值，-1 的 keepTokens 表示动态保留预算；不能一律当成禁用。若需要明确按条数保留，可设置 `keepTokens(0)`。

## 压缩链路

```text
推理前评估
 → 参数截断 / 工具结果 pruning 等轻量预处理
 → 判断触发条件与安全切分点
 → 尝试提取长期事实 → 尝试原消息卸载到 JSONL
 → 模型摘要前缀（包含已有摘要）
 → [摘要消息] + [保留的最近消息] 替换当前上下文
```

安全切分点可能让压缩跳过；不是超过阈值就必然得到更小的上下文。TokenCounter 是估算，仍需和实际模型 usage 比较。

## 四种手段

| 手段 | 保留什么 | 代价/边界 |
|:---|:---|:---|
| 摘要 | 前缀提炼 + 近期原文 | 额外模型调用，可能丢细节 |
| 参数截断/pruning | 减少重复大参数或旧工具内容 | 应结合工具语义判断信息损失 |
| 大结果 eviction | 全文在文件，消息只留预览和路径 | 文件必须可访问，状态快照不包含所有全文 |
| 溢出恢复 | 强制压缩后再调 delegate | 需具备 compactionHook，不保证任意超限都能恢复 |

大结果默认阈值为 80,000 字符；字符数不能当作模型精确 token 数。排除工具列表与预览长度以配置类为准。

## 与 1.0 的区别

1.0 笔记里的六级 CompressionController 链路不能直接套到 Harness；2.0 重点是工作区、CompactionMiddleware、ToolResultEvictionMiddleware 与状态保存的协同。

计划状态、权限、todo 等独立字段不由对话摘要直接改写；这只说明压缩范围，并非这些子系统天然不会丢失或不需要单独持久化。

## 需要实测的三件事

建议比较压缩前后关键事实问答、工具调用完整性、历史原文可检索性，并记录额外 token 与耗时。⚠️ raw 缺失，待补充：本项目相关实测，不能写“无损压缩”。
