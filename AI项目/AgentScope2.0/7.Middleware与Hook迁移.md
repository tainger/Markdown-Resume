# Middleware与Hook迁移

> 用五个拦截位置表达横切逻辑，显式传入调用上下文。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 五个位置

| 位置 | 包裹范围 | 典型用途 |
|:---|:---|:---|
| `onAgent` | 一次 agent 事件执行流程 | 总体观测、输入与终止控制 |
| `onReasoning` | 一轮推理 | 上下文组装、推理事件处理 |
| `onActing` | 框架内部工具调用 | 工具观测与控制 |
| `onModelCall` | 底层模型调用 | 模型观测、文本事件变换 |
| `onSystemPrompt` | system prompt 字符串变换 | 人格、工作区/技能上下文装配 |

前四类是洋葱 Onion 模型：`next.apply(input)` 驱动内层；最后一类串行转换字符串。MiddlewareBase 实际是 interface，可只覆盖关心的方法。

## 顺序与响应式时机

`order()` 默认 1，值大在外层；同值保留注册顺序。若 A 在 B 外，正常路径可理解成 A-before → B-before → core → B-after → A-after。

日志、统计等若需要在订阅时发生，应放在响应式回调/defer 中；在方法构造阶段打印一次不等于执行了一次调用。收尾也要区分 complete、error、cancel。

## 从旧 Hook 迁移

| 旧思路 | 新主线 | 注意 |
|:---|:---|:---|
| PreCall/PostCall | onAgent 外围控制 | onAgent 包裹共享事件入口；加载/保存仍由 Core 生命周期负责，需分别确认成功、异常和取消路径 |
| PreReasoning/PostReasoning | onReasoning | 读本次 ctx 中的 state |
| PreActing/PostActing | onActing | 外部执行工具不在内部执行包装内 |
| 系统提示词拼接 | onSystemPrompt | 不能把文档示意图当成每次触发的精确时序保证 |

旧 Hook 在 AgentBase 中仍有注册/通知路径。迁移应一次确认一个关注点，避免新旧同时修改同一数据导致重复注入。

## 不要共享本次请求数据

中间件实例可能服务多个会话，不要用 `this.currentUser`、`this.currentState` 保存正在处理的用户。通过方法参数 ctx 和局部变量传递；工具也应遵守相同规则。

工作区、Skill 与系统提示词的生命周期以实际实现为准，例如 `seedSystemMsg` 也会调用提示词转换链；细节见版本核对页。
