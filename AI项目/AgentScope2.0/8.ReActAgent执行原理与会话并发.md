# ReActAgent执行原理与会话并发

> 以 CallExecution 串起状态、推理、工具和恢复分支。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 调用主链

```text
call / streamEvents（订阅后开始）
 → 本实例 slot 队列 → beforeAgentExecution
 → 加载 AgentState → CallExecution / RuntimeContext 绑定
 → PreCall 等兼容生命周期 → doCallInner
 → reasoning：消息与工具视图 → 模型流 → 累积完整响应
 → acting：权限评估 → 内部执行 / 外部执行 / 等人工确认
 → 结果写入上下文 → 继续推理或返回
 → 状态保存与执行清理
```

Middleware、Hook 与事件系统在这些位置介入；流程图是阅读骨架，错误、中断、空结果和直接返回工具另有分支。

## doCallInner 的恢复顺序

1. 处理优雅停机恢复标记，避免把同次重试输入重复加进历史。
2. 没有 pending 工具：加入新输入，开始正常推理。
3. 有 ASKING 工具：必须先处理结构化 ConfirmResult。
4. 显式启用 pending recovery 时，按规则为孤立调用补错误结果。
5. pending + 空输入：续跑待执行工具；pending + 外部结果：校验 ID 并回填。
6. 仍缺必要结果又不能恢复：报错，不把普通聊天内容擅自当工具结果。

Pending recovery 在本标签 Builder 默认 false。它位于 ASKING 之后，不得用“自动补洞”跳过人工确认。

## 为什么能多会话并发

引擎复用配置，CallExecution 持有本次状态、权限引擎、工具请求视图与中断信号。RuntimeContext 绑定这个调用；共享 Toolkit 不靠请求内临时改写来实现工具隔离。

这里的“无状态引擎”是配置与会话状态解耦的设计描述；实例仍有缓存、队列和资源，不是没有任何可变字段。

## 终止原因与 returnDirect

应用应结合 GenerateReason 和内容块判断普通完成、挂起、审批、中断等。`returnDirect` 只有整批工具都声明直接返回且全部成功等条件满足才短路下一轮模型；混合批次不能假定直接返回。

`maxIters` 控制主循环，达到边界有总结路径；不能把它说成“全链路最多十次调用”。
