# 工具集成、权限治理与请求隔离

> 把 Schema、身份、并发安全和执行权限逐层说明。版本固定为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/README]]。

## 定义工具

注解方法通过 Toolkit 注册，生成 JSON Schema。`readOnly` 和 `concurrencySafe` 是开发者声明，框架不会证明业务代码真的只读或线程安全。

```java
import io.agentscope.core.agent.RuntimeContext;
import io.agentscope.core.tool.Tool;
import io.agentscope.core.tool.ToolParam;

class OrderReadTools {
    @Tool(name = "order_status", description = "查询当前用户订单状态",
          readOnly = true, concurrencySafe = true)
    public String status(@ToolParam(name = "orderId", description = "订单编号") String orderId,
                         RuntimeContext ctx) {
        // 接真实服务时还须校验订单归属；身份由应用鉴权后注入。
        return "示例用户=" + ctx.getUserId() + ", 订单=" + orderId;
    }
}
```

片段仅说明注入方式，返回的是演示文本，未实现真实订单查询。

## 默认值与调度

本标签 `@Tool.readOnly=false`，`@Tool.concurrencySafe=true`。Toolkit 支持批次并行；不安全工具要显式声明 false。这个标志不是数据库锁，也不能保证多个进程不会同时改同一业务资源。

工具超时、调度、重试在 ToolExecutor 层组合。只有沿异常通道传播的错误才会触发响应式 retry；业务返回错误对象或提前转错误结果不能等同于抛异常。

## 权限决策

源码顺序为 deny 规则 → ask 规则 → 工具自身检查 → allow 规则 → BYPASS/默认回退。工具检查的 ALLOW/DENY 和带 safety 原因的 ASK 有直接返回路径；不能只记“allow 一定覆盖其他检查”。

权限系统解决工具动作是否允许；业务服务仍应验证身份、租户、对象归属和数据版本。它不自动替代这些检查。

## 请求级工具视图

ToolRequestConfig 以不可变配置组合外部 schema 和共享 Toolkit：

| 模式 | 可见行为 |
|:---|:---|
| AGENT_ONLY | 后端工具，不允许配置非空外部工具表 |
| MERGE_EXTERNAL_PRIORITY | 外部同名 schema 优先 |
| EXTERNAL_ONLY | 隐藏后端，即使外部表为空 |

外部工具是 schema-only，执行交给调用方并回填；隐藏工具是本次视图行为，不是删除共享注册表。不要使用“修改共享 Toolkit → 执行 → 恢复”的方式为请求注入工具。
