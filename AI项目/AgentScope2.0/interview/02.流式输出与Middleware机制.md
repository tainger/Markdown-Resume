# 流式输出与Middleware机制

> 答题骨架：机制 → 调用链 → 场景 → 边界。源码为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/interview/README]]。

## Q09｜call 与 streamEvents 的关系是什么？

**口述答案**：二者驱动相同任务，分别交付最终 Msg 和 AgentEvent 流。应用需要文本增量、工具进度和审批提示时消费事件流，而不是额外再 call 一次。

**追问**：为什么会发生重复工具操作？可能把 call 和 streamEvents 当作同一次执行的两个观察者，分别订阅实际启动了两次。

**边界**：一次业务请求应有明确的执行入口与结果订阅策略。

## Q10｜文本 Delta 应怎样消费？

**口述答案**：TextBlockDeltaEvent 是增量片段，应追加到对应回复/内容块。工具事件、确认事件和最终结果走独立分支；不能把所有事件强行转字符串拼在一起。

**追问**：只保存屏幕上的文本可以恢复会话吗？不行，会丢工具 ID、状态和结果结构。

**边界**：事件展示与持久化是不同责任，不能用 UI 是否显示完成判断 store 保存成功。

**依据**：[[AI项目/AgentScope2.0/2.流式输出、结构化输出与执行控制]]、[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]；[AgentEventType.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/event/AgentEventType.java:53>)、[AgentState.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/state/AgentState.java:171>)。

## Q11｜Middleware 的五个拦截点是什么？

**口述答案**：onAgent 包裹整体执行，onReasoning 包裹一轮推理，onActing 包裹内部工具，onModelCall 包裹底层模型，onSystemPrompt 变换提示词。前四个是洋葱包装，最后一个串行变换。

**追问**：onActing 能覆盖前端自行执行的外部工具吗？不能按内部执行包装来假定，需要另外记录外部执行与结果回填。

**边界**：范围以具体调用点为准，不把架构示意图当作所有生命周期的精确嵌套图。

**依据**：[[AI项目/AgentScope2.0/7.Middleware与Hook迁移]]；[MiddlewareBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareBase.java:59>)。

## Q12｜Middleware 的顺序怎样决定？

**口述答案**：order 默认 1，值越大越靠外；相同 order 保留注册顺序。链从后往前构造，使列表首项成为外层。正常路径的前置与后置顺序相反。

**追问**：旧 Hook priority 与 order 可以当同一规则吗？不能，新旧系统分别核对排序和通知方式。

**边界**：异步回调发生时机还受响应式订阅影响，顺序配置不是任意副作用顺序的保证。

**依据**：[[AI项目/AgentScope2.0/7.Middleware与Hook迁移]]；[MiddlewareBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareBase.java:71>)、[MiddlewareChain.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareChain.java:56>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:5621>)。

## Q13｜如何从 Hook 迁移到 Middleware？

**口述答案**：先按关注点对应整体调用、推理、工具和提示词，再把状态读取改为显式 ctx。旧 Hook 仍有兼容路径，逐项迁移并检查重复注入、重复审计或相互覆盖。

**追问**：可以把 currentUser 存在中间件字段吗？共享实例会并发服务多会话，应使用 ctx 和局部变量。

**边界**：迁移不是简单改类名，特别要检查异常、取消和外部执行覆盖范围。

**依据**：[[AI项目/AgentScope2.0/7.Middleware与Hook迁移]]；[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:621>)、[MiddlewareBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/middleware/MiddlewareBase.java:50>)。

## Q14｜onSystemPrompt 只在每轮 reasoning 内触发吗？

**口述答案**：文档示意图把它画在推理内部，但源码 seedSystemMsg 也调用转换链。答题应讲“系统提示词装配入口会做变换”，再按具体版本定位，而不是断言只在一个位置触发。

**追问**：动态 Skill 为什么也接在这里？它需要依据本次 ctx 装配可见技能并影响提示词。

**边界**：触发次数不能只从示意图推算，本次未运行计数实验。

## Q15｜结构化输出有哪些路径？

**口述答案**：ReActAgent 有原生结构化输出和回退的 generate_response 工具路径，根据模型能力等条件选择。应用把结果映射为指定类型或 Schema 后仍需做业务校验。

**追问**：字段类型正确等于订单金额可信么？不等，Schema 不验证真实资源归属或业务规则。

**边界**：各模型的 Schema 子集、流式与拒答行为需要接入测试。

## Q16｜日志与追踪应该放在哪里？

**口述答案**：按任务、模型、工具分层观测，使用本次 ctx 中的用户/会话与请求关联信息。OtelTracingMiddleware 提供相应跨度；实际导出仍需应用配置 OpenTelemetry SDK。

**追问**：在方法入口打印日志算执行成功吗？方法可能仅构造响应式链，应在订阅/完成/错误/取消等回调中分别记录。

**边界**：没有导出配置或真实 trace 不能声称已经建立完整线上观测。
