# 工具调用、权限与执行治理

> 答题骨架：机制 → 调用链 → 场景 → 边界。源码为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/interview/README]]。

## Q17｜工具 Schema 与调用上下文怎样分开？

**口述答案**：模型决定的业务参数进入 Schema，RuntimeContext 等依赖由框架从调用端注入。鉴权后的 userId、服务依赖不应让模型伪造；工具实际执行时还要验证对象归属。

**追问**：声明 ctx 参数就完成权限校验了吗？没有，只是获得可信调用数据，业务验证仍需实现。

**边界**：教程订单工具仅返回演示文本，没有真实业务实现。

## Q18｜readOnly 与 concurrencySafe 默认值是什么？

**口述答案**：本标签 @Tool.readOnly 默认 false，concurrencySafe 默认 true。开发者应根据副作用与共享状态显式标注；文档中并发默认 false 的表格与注解不一致。

**追问**：框架会证明 readOnly 标记真实吗？不会，错误标记可能影响权限和计划阶段的放行判断。

**边界**：声明不是数据层约束，也不代替代码审查与实际并发验证。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]；[Tool.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/Tool.java:107>)、[Tool.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/Tool.java:117>)。

## Q19｜并行工具批次怎样治理？

**口述答案**：Toolkit 支持并行批次，对不安全工具按其声明实施调度。需要整体串行时通过 ToolkitConfig 控制，而共享业务对象、跨进程修改还需各自的锁、事务或幂等。

**追问**：把 concurrencySafe 设为 false 是否就实现全局分布式串行？不是，调度范围与业务资源锁范围不同。

**边界**：不能把同步等待结果说成所有工具必然串行。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]、[[AI项目/AgentScope2.0/14.Plan模式、子Agent与Harness部署]]；[ToolExecutor.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolExecutor.java:443>)、[subagent.md](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/docs/v2/zh/docs/harness/subagent.md:141>)。

## Q20｜权限引擎的判断顺序如何回答？

**口述答案**：先 deny 规则，再 ask 规则，再工具特定检查，然后 allow 规则与模式回退。工具检查可能直接 ALLOW、DENY，或因 safety ASK 返回；BYPASS 不是直接跳过前置规则。

**追问**：为什么不要只背一张模式表？具体工具检查与规则命中能改变结果，需要按执行路径解释。

**边界**：工具授权与业务身份校验是两层责任。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]；[PermissionEngine.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/permission/PermissionEngine.java:139>)、[PermissionEngine.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/permission/PermissionEngine.java:229>)。

## Q21｜为什么不能请求期间临时修改共享 Toolkit？

**口述答案**：多会话会同时使用注册表，临时增删后再恢复会让另一个请求看到错误工具。ToolRequestConfig 用不可变差异组合共享表，外部工具只带 schema，解析和执行使用同一视图规则。

**追问**：这是不是每次深拷贝 Toolkit？源码强调不复制也不变更共享表，通过 per-call 配置组合。

**边界**：用户工具对象仍要自行满足无状态或线程安全要求。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]；[ToolRequestConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolRequestConfig.java:41>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:762>)。

## Q22｜EXTERNAL_ONLY 配空列表是什么意思？

**口述答案**：隐藏全部后端工具；外部表为空意味着本次没有外部工具，不是回退到 agent 工具。同名外部 schema 优先；AGENT_ONLY 不允许非空外部表。

**追问**：隐藏工具会删除注册表吗？不会，只改变本次请求可见与解析行为。

**边界**：Schema-only 工具由调用方执行，不能以后台 Java 实现替代前端选择的同名工具。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]；[ToolRequestConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolRequestConfig.java:106>)、[ToolRequestConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolRequestConfig.java:89>)。

## Q23｜maxRetries=3 到底尝试几次？

**口述答案**：本标签 ModelConfig 的值传入 ExecutionConfig.maxAttempts，再由 ModelUtils 使用 Retry.backoff(maxAttempts-1)。在没有更高优先级配置覆盖时，3 表示初次加最多两次重试。

**追问**：为何不能照字段名理解成额外重试三次？需要沿使用位置看真实语义；工具与模型还可能各有不同预算。

**边界**：总任务成本还包含 ReAct、fallback、摘要与子任务，不能只统计这个字段。

**依据**：[[AI项目/AgentScope2.0/2.流式输出、结构化输出与执行控制]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:4247>)、[ModelUtils.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/model/ModelUtils.java:118>)。

## Q24｜工具失败为什么不一定触发重试？

**口述答案**：响应式 retry 依赖异常信号。ToolExecutor 组合调度、超时与重试，但如果内层已返回错误 ToolResult 或业务方法用正常对象表达失败，外层就不会把它当异常重试。

**追问**：超时取消等于外部操作未发生吗？不等，阻塞请求可能继续执行，写操作需幂等。

**边界**：本题解释错误通道边界，没有声称某个供应商失败已经运行复现。
