# 会话持久化与长期记忆

> 答题骨架：机制 → 调用链 → 场景 → 边界。源码为 **v2.0.4**；返回 [[AI项目/AgentScope2.0/interview/README]]。

## Q25｜RuntimeContext 与 AgentState 区别是什么？

**口述答案**：ctx 是本次元数据容器，userId/sessionId 决定状态槽位，自由/类型属性不会整体持久化。AgentState 承载对话、摘要、权限、工具、todo 与计划状态等会话数据。

**追问**：为什么 ctx 可以带 AgentState 引用但仍不叫持久化状态？这是调用期绑定，真正保存的是 store 序列化的状态对象。

**边界**：不要把连接、回调和凭证都塞进可恢复快照。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]；[AgentState.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/state/AgentState.java:171>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:754>)。

## Q26｜Core 与 Harness 默认都自动落盘吗？

**口述答案**：Core 未配置 store 时使用 slot 内存缓存，实例存活期间保留历史，重启不恢复。Harness 默认创建 JsonFileAgentStateStore，状态目录与工作区分开。

**追问**：换了工作区路径就一定换了状态吗？不能这样假定，应同时核对 agentId、状态根、userId 与 sessionId。

**边界**：只保存工作区文件不等于完整保存 AgentState。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]、[[AI项目/AgentScope2.0/4.长期记忆与工作区]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:670>)、[HarnessAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-harness/src/main/java/io/agentscope/harness/agent/HarnessAgent.java:2427>)。

## Q27｜同会话串行保证的范围是什么？

**口述答案**：AgentBase 的异步门按 key 排队，ReActAgent 的 key 为用户与会话槽位；同实例相同 key 串行，不同 key 并发。它是本实例内存中的队列。

**追问**：两个副本都收到同一 session 怎么办？还需分布式互斥或明确冲突策略；不能从这个门推导全局互斥。

**边界**：订阅顺序决定实际入队时机，创建两个 Mono 的先后不是已执行的证明。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]、[[AI项目/AgentScope2.0/8.ReActAgent执行原理与会话并发]]；[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:374>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:727>)。

## Q28｜配置 store 后每次会使用缓存里的旧状态吗？

**口述答案**：activateSlotForContext 在配置 store 时会按 slot 重新加载版本化状态，避免会话漂移到节点后只用本地旧缓存；无 store 才依赖内存 slot。

**追问**：多节点读到最新值就能消除写冲突吗？不能，两个调用仍可能从同一版本开始，需写入侧 CAS 等机制。

**边界**：读新状态与互斥执行是两个不同保证。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:659>)。

## Q29｜CAS 冲突策略能自动合并全部状态吗？

**口述答案**：支持版本的后端可比较版本保存；FAIL 报冲突，OVERWRITE 覆盖，APPEND_MERGE 尝试在最新状态上追加本次上下文增量并处理权限。它不是任意字段的语义合并。

**追问**：如果本地已压缩消息，简单追加能表达完整变化吗？不能笼统保证，应对消息切分、摘要、计划和任务状态分别验证。

**边界**：CAS 能检测覆盖竞争，不保证外部工具只执行一次。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:535>)。

## Q30｜为什么 middleware 不能依赖 agent.getAgentState？

**口述答案**：并发调用的权威状态保存在本次 CallExecution 并绑定到 ctx。使用 ctx.getAgentState 或 resolveAgentState 可以取得本次数据，而全局访问器不能作为多会话调用的可靠上下文。

**追问**：可以在共享工具对象保存 currentState 吗？同样不合适，应从调用参数获取。

**边界**：即使某个无并发示例正常，也不能据此声称共享访问器在生产安全。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]、[[AI项目/AgentScope2.0/7.Middleware与Hook迁移]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:740>)、[RuntimeContext.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/RuntimeContext.java:137>)。

## Q31｜2.0 的长期记忆与会话历史如何区别？

**口述答案**：AgentState.context 服务当前模型输入；MEMORY.md 与 memory 文件保存提炼事实；会话 JSONL 保存可查询历史。摘要改变当前上下文，不代表原始日志和长期事实也被同样修改。

**追问**：旧 LongTermMemory 三种模式还能用吗？有 deprecated 兼容入口，但新主线按 Harness 工作区记忆学习。

**边界**：没有真实提取与检索记录不能把配置成功当作记忆质量已验证。

**依据**：[[AI项目/AgentScope2.0/4.长期记忆与工作区]]、[[AI项目/AgentScope2.0/6.实战：三层记忆与会话恢复]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:5266>)、[ConversationCompactor.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-harness/src/main/java/io/agentscope/harness/agent/memory/compaction/ConversationCompactor.java:134>)。

## Q32｜普通失败、中断、cancel 的状态保存相同吗？

**口述答案**：普通失败有保存已累积安全上下文并保留原异常的路径；中断专门处理悬空工具后保存；立即 cancel 不承诺走相同恢复与保存流程。

**追问**：有 store 就能精确恢复外部支付吗？不能，业务成功和本地快照之间仍有故障窗口，需要幂等与对账。

**边界**：本次只有静态核对，没有宕机注入结论。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]、[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:510>)、[AgentRun.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentRun.java:38>)。
