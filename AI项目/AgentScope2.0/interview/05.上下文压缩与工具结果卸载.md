## Q33｜Harness 默认开启压缩吗？

**口述答案**：v2.0.4 Builder 默认构造 compactionConfig 和 toolResultEvictionConfig，两个 disable 标志为 false，构建时装配对应组件。文档“默认全部不开”与这份实现冲突。

**追问**：裸 ReActAgent 也能套用这个默认吗？不能，要区分 Core 和 Harness 装配。

**边界**：开启能力不表示每次调用都实际触发摘要。

## Q34｜triggerTokens=0、keepTokens=-1 分别是什么意思？

**口述答案**：本标签 0 的触发预算表示动态计算，-1 的保留预算表示动态计算；keepTokens=0 才退到按 keepMessages 保留。默认 triggerMessages=50、keepMessages=20。

**追问**：只设 keepMessages(4) 就保证保留四条吗？不应这样承诺，动态 token 保留可能优先生效，需要明确 keepTokens(0) 并考虑安全切分。

**边界**：数值语义按配置实现解释，0 和负数不是统一的“关闭”。

## Q35｜ConversationCompactor 的主步骤是什么？

**口述答案**：先进行参数截断与工具结果 pruning，计算估算 token，判断触发和安全切点；再尽力提取事实、卸载原文，模型摘要前缀，返回摘要加保留尾部。

**追问**：已存在的摘要怎么办？进入后续摘要输入，但从事实 flush 输入中过滤，避免反复抽取相同事实。

**边界**：安全切点可能为零而跳过，不能保证每次触发都成功缩小。

**依据**：[[AI项目/AgentScope2.0/5.智能上下文压缩与工具结果卸载]]；[ConversationCompactor.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-harness/src/main/java/io/agentscope/harness/agent/memory/compaction/ConversationCompactor.java:92>)。

## Q36｜压缩前 flush 失败会中止摘要吗？

**口述答案**：普通 flush 和原文 offload 失败有 best-effort 降级，记录后继续；涉及中断的异常另行传播。不能把 flushBeforeCompact=true 理解为写入成功的事务保证。

**追问**：怎样验证记忆没丢？要检查事实文件、原文日志与压缩后问答，不能只看摘要调用成功。

**边界**：不存在本项目“无损压缩”的实测证据。

## Q37｜大工具结果卸载与摘要有什么不同？

**口述答案**：卸载针对单条大结果，把全文放文件，当前消息保留预览与读取提示；摘要把旧消息前缀概括成新消息。默认卸载阈值按字符计，不能当成精确 token。

**追问**：重启只恢复 AgentState 就能读取卸载全文吗？还取决于文件后端与路径是否恢复。

**边界**：文件存在性、权限与保留期都应另外验证。

## Q38｜为什么不能把 1.0 六级压缩直接套到 2.0？

**口述答案**：本系列 2.0 主线是 Harness 的 CompactionMiddleware、ConversationCompactor、工具结果 eviction 与溢出恢复，和旧 CompressionController 的六级策略不是同一条实现。

**追问**：概念还能复用吗？预算、近期保护与原文回查等思想能复用，但配置、默认值、顺序与存储要重新核对。

**边界**：保留旧笔记作为版本资料，不静默把旧实现改写成新版。

## Q39｜溢出恢复能保证超限任务成功吗？

**口述答案**：Harness 检测匹配的上下文溢出错误且有 compactionHook 时，走强制压缩后重调 delegate 的路径；没有 hook 或压缩没有结果会失败。

**追问**：为什么还要保留预防式压缩？等报错再处理会增加请求和延迟，也不能保证任意模型错误都被正确识别。

**边界**：它不是无限重试，也不是模型精确预算控制器；重复输入和状态交互需运行验证。

## Q40｜摘要是否会删除计划、todo 和后台任务？

**口述答案**：摘要主要处理当前对话列表。计划状态、权限和 todo 是 AgentState 独立字段，计划正文与后台任务记录又有自己的文件/仓库；不由摘要直接处理。

**追问**：因此这些数据永远不会丢吗？不能，仍需各自持久化、后端可用性与恢复测试。

**边界**：压缩范围不等于整个系统的数据可靠性保证。
