## Q41｜MCP 接入有哪些步骤？

**口述答案**：先选择并配置传输与鉴权，初始化客户端，再注册到 Toolkit，最后让 Agent 在实际权限与请求视图下使用工具。连接、展示 Schema 和实际授权是三个检查点。

**边界**：本系列没有真实 MCP 联调结果。

## Q42｜MCP 工具可见性怎样与请求视图相互作用？

**口述答案**：MCP 注册提供后端工具；ToolRequestConfig 决定本次是否允许看到后端以及外部同名 schema 是否覆盖。隐藏后端与删除 MCP 注册不同。

**追问**：把工具从 UI 列表藏掉够不够？还要验证实际解析、权限和远端数据访问。

**边界**：注册成功不代表具备特定用户的业务数据权限。

**依据**：[[AI项目/AgentScope2.0/9.工具集成、权限治理与请求隔离]]、[[AI项目/AgentScope2.0/10.MCP接入与工具可见性]]；[ToolRequestConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolRequestConfig.java:89>)、[ToolRequestConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolRequestConfig.java:106>)。

## Q43｜MCP 元数据能当成自动鉴权吗？

**口述答案**：客户端提供元数据传播配置，但传播哪些字段、服务端如何验证都要明确。RuntimeContext 任意对象不会因此自动成为可信远端身份。

**追问**：请求头里传 userId 就够吗？应用应有可信身份建立与服务端校验，不能让模型随意选择身份。

**边界**：这是接入边界与设计建议，不是已完成的鉴权系统。

**依据**：[[AI项目/AgentScope2.0/10.MCP接入与工具可见性]]；[McpClientBuilder.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/mcp/McpClientBuilder.java:107>)、[RuntimeContext.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/RuntimeContext.java:34>)。

## Q44｜MCP 超时或连接关闭为什么要考虑所有权？

**口述答案**：初始化、请求和工具执行各有超时；复用连接不能被单次调用随意关闭，退出时又需释放真正由本应用拥有的资源。取消请求也不代表远端动作没发生。

**追问**：工具写操作超时后可直接重试吗？应先设计幂等或查询结果，避免重复副作用。

**边界**：未验证的供应商资源生命周期不应写成确定保证。

**依据**：[[AI项目/AgentScope2.0/10.MCP接入与工具可见性]]、[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[McpClientBuilder.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/mcp/McpClientBuilder.java:97>)、[ToolExecutor.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/ToolExecutor.java:500>)。

## Q46｜knowledge/ragMode 已删除吗？RAGMode.STATIC 可用吗？

**口述答案**：Builder 的旧接口仍有实现并标 forRemoval，适配器仍可工作。实际旧枚举是 GENERIC、AGENTIC、NONE，没有 STATIC；部分新版文档残留错误示例。

**追问**：为何不直接沿用能编译的旧接口？可用于迁移，但新学习主线应按应用层检索组织，避免继续依赖计划移除的接口。

**边界**：不夸大为所有旧接口都失效，也不把过时文档当新版保证。

## Q47｜固定检索与 Agentic 检索怎样选？

**口述答案**：固定检索让应用每次先查，适合强制使用业务知识；Agentic 可把检索包装成工具，由模型按需调用。两者都要处理权限、预算、空结果与来源。

**追问**：按需检索一定更省钱更准确吗？不一定，多轮搜索可能增加成本，需要领域评测。

**边界**：这是基于应用机制的设计比较，没有本项目指标证明优劣。

**依据**：[[AI项目/AgentScope2.0/11.应用层RAG与旧接口迁移]]；[ApplicationLayerRagExample.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-examples/documentation/src/main/java/io/agentscope/examples/documentation2/rag/ApplicationLayerRagExample.java:77>)、[Tool.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/tool/Tool.java:87>)。

## Q48｜怎样区分知识库、长期记忆和会话上下文？

**口述答案**：知识库保存业务资料，长期记忆沉淀用户/任务事实，会话上下文服务当前推理。它们可以互相引用，但访问权限、更新周期与保留策略不同。

**追问**：统一叫 Memory 有什么问题？会混淆状态恢复、知识检索与事实提炼，难以定位遗忘或越权发生在哪层。

**边界**：需要分别评测召回、记忆准确率和恢复完整性，当前没有这些运行报告。
