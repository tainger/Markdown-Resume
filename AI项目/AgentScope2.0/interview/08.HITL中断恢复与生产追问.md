## Q57｜权限 ASK 与外部执行挂起相同吗？

**口述答案**：ASK 等待人类对工具调用作决定，恢复携带 ConfirmResult；外部执行把实际动作交给调用方，恢复提交匹配 ID 的 ToolResult。两者的状态和输入协议不同。

**追问**：普通文本“同意”够吗？不够，ASKING 分支校验结构化结果。

**边界**：应用必须验证审批身份与会话归属。

## Q58｜ConfirmResult 恢复需校验什么？

**口述答案**：框架检查结果非空、ID 非空、重复 ID 以及 ID 是否属于 ASKING 集合，再应用批准、拒绝及可选规则；该校验方法没有逐项比较原工具名与参数。应用应审核修改范围、规则权限与原会话归属，不能直接信任回填内容。

**追问**：可否让用户修改工具参数？协议允许返回修改后的调用，但仍应按业务权限验证。

**边界**：结构匹配不是业务授权和重复提交处理的全部。

**依据**：[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1953>)、[ConfirmResult.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/event/ConfirmResult.java:35>)。

## Q59｜为什么运行控制需要 AgentRun 而不只传 sessionId？

**口述答案**：session interrupt 定位当前已运行者，不能精确选择排队中的某次请求。AgentRun 为单次执行分配 runId、状态与控制信号，可在订阅前登记并精确取消。

**追问**：句柄能重复订阅重跑吗？不能，第二次订阅拒绝，重试创建新句柄。

**边界**：应用负责 runId 注册、鉴权和终态回收。

**依据**：[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[AgentRun.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentRun.java:66>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1101>)。

## Q60｜cancel 和 interrupt 的差别是什么？

**口述答案**：cancel 取消响应式执行，可在订阅前和队列中生效；interrupt 请求运行者在检查点协作中断并生成恢复消息。排队阶段的 interrupt 只取消这次排队调用。

**追问**：cancel 是否保证保存状态并撤销工具操作？不保证，也不能撤销已发生的外部副作用。

**边界**：不响应取消的阻塞工具可能继续执行。

**依据**：[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[AgentRun.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentRun.java:38>)、[agent.md](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/docs/v2/zh/docs/building-blocks/agent.md:231>)。

## Q61｜队列中 B 被取消为什么不能让 C 提前执行？

**口述答案**：同 slot 队列保留前驱依赖；B 即使取消，C 仍需等 A 释放，避免同时修改会话状态。代码使用 previous.then(release) 维护等待关系。

**追问**：仅用一个 doFinally 释放自己够吗？若未保持前驱，取消中间节点就可能让后继误以为整条链已完成。

**边界**：本系列依据源码解释，未做取消竞态压力测试。

**依据**：[[AI项目/AgentScope2.0/3.多轮会话、RuntimeContext与状态持久化]]、[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:374>)。

## Q62｜优雅停机与崩溃恢复能等价吗？

**口述答案**：优雅停机会跟踪本次运行控制与解析后的状态，协作中断并设置恢复标记；崩溃可能来不及保存。重复输入消除只覆盖特定恢复分支，不是全局幂等。

**追问**：外部订单创建后进程崩溃怎么办？需业务请求幂等键、结果查询或对账机制。

**边界**：这类生产恢复方案是建议，当前没有故障注入证据。

**依据**：[[AI项目/AgentScope2.0/8.ReActAgent执行原理与会话并发]]、[[AI项目/AgentScope2.0/13.Human-in-the-Loop与AgentRun执行控制]]；[AgentBase.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/agent/AgentBase.java:334>)、[ReActAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope2.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:1821>)。

## Q63｜多副本部署要一起检查哪些后端？

**口述答案**：状态 store、工作区 filesystem、后台任务仓库、消息/协调、沙箱快照与运行管理都要核对。默认本机状态文件不构成分布式方案；RemoteFilesystemSpec 配本机状态在本标签 build 会拒绝。

**追问**：只换 Redis 状态存储就足够吗？不一定，文件、后台任务和外部副作用还可能留在其他节点。

**边界**：本目录没有集群压测、故障注入或任务重领验收报告。
