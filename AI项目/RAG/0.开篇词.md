# RAG 系列脑图

> 从"什么是 RAG"到"多模态实战"，本系列 38 篇完整覆盖 **基础原理 → 分片策略 → 向量检索 → 优化全家桶 → 框架对比 → 多模态 + Agentic**。用 **markmap** 渲染为 XMind 风格可交互脑图（缩放/拖拽/折叠、暗色自适应），按六条主线拆成 6 棵子树避免单图过大。

## 一、基础概念与原理（01-05）

```markmap
- RAG 是什么
  - 定义与核心（01）
    - Retrieval-Augmented Generation
    - 检索 + 生成，查完资料再说
    - 解决幻觉 / 知识过时 / 领域缺失
  - 使用场景（01）
    - 企业知识问答 / 智能客服
    - 安全分析与情报检索
    - 法律 / 医疗 / 金融专业问答
  - 整体流程（01）
    - 离线：索引构建（预处理 → 分片 → 向量化 → 建索引）
    - 在线：检索生成（查相似 chunk → 注入上下文 → LLM 回答）
    - GIGO 原则：垃圾进垃圾出
- 索引构建（02）
  - 文档预处理（清洗/去噪/结构化保留）
  - 文档分片（见第二节）
  - 向量化（Embedding）
  - 生成索引（向量库写入）
- 检索生成（03）
  - 用户提问 → Embedding
  - 向量相似度检索（Top-K）
  - 构造 Prompt（问题 + chunk）
  - LLM 生成答案（附引用来源）
- Naive RAG Demo（04）
  - LlamaIndex 快速上手
- 范式演进全景（05）
  - 三种经典
    - Naive RAG（基础版，检索 + 生成）
    - Advanced RAG（进阶版，混合检索/重排序/改写）
    - Modular RAG（模块化，组件解耦可插拔）
  - 业界其他范式
    - Agentic RAG（Agent 自主决策检索）
    - Graph RAG（知识图谱 + 社区摘要）
    - Self-RAG（自我反思校验）
    - CRAG（检索质量评估 + 纠错）
    - Adaptive RAG（按问题复杂度路由）
    - RAG-Fusion（多查询 + RRF 融合）
    - Long-Context（长窗口跳过检索）
  - LLM Wiki（知识编译一次、持续积累）
```

## 二、文档处理与分片策略（08-11.5, 17）

```markmap
- 为什么要分片
  - Embedding 模型有 token 上限（如 8192）
  - 全文检索信号稀释（相关性被淹没）
  - LLM 上下文窗口有限
- 分片策略
  - 固定长度切分
    - 硬切 chunkSize 字符/token
  - TokenTextSplitter（08）
    - 按 token 数切，支持 overlap
    - chunkSize / chunkMin / embeddingFilter
  - 按标题 / 段落切分（10/11）
    - Markdown 标题分片器（10）
    - Word 标题分片器（11）
    - 保留语义边界
  - 语义切分
    - 按语义相似度阈值分组
- Overlap（重叠）
  - 相邻 chunk 保留一段冗余
  - 解决语义断裂
  - 推荐 10%~20%
- 父子分片（09, 10, 11, 11.5）
  - 核心思想
    - 子块（小）入向量库 → 用于检索
    - 父块（大）入关系库 → 用于生成
  - 优点
    - 检索精度高 + 生成上下文完整
    - 绕过 Embedding token 限制
    - 解决表格/图片被切断
  - 缺点
    - 存储翻倍（~2x）
    - 检索多一跳（向量命中 → 查 MySQL）
    - 父块去重复杂
    - 框架不原生支持，需手写
  - 语义识别父子分片（11.5）
- ETL 总结（17）
  - ContentFormatTransformer 格式转换
  - KeywordMetadataEnricher 关键词富化
  - SummaryMetadataEnricher 摘要富化
```

## 三、向量模型与检索算法（12-16）

```markmap
- Embedding 模型（12, 13, 15）
  - 云端（DashScope）
    - DashScopeEmbeddingModel
    - OpenAiEmbeddingModel
  - 本地私有化（15）
    - BGE 向量模型（LangChain4j）
    - Ollama 本地推理
  - PostgresML Embedding（13，选学）
    - pgml 扩展 + 模型自托管
- 向量数据库选型（14）
  - PgVector
    - PostgreSQL 扩展，零新组件，快速 MVP
  - Milvus
    - 分布式，亿级规模，生产首选
  - Qdrant
    - 轻量单机/分布式，易部署
  - Chroma
    - 学习/原型阶段
  - Elasticsearch
    - 已有 ES 栈的企业，混合检索原生支持
  - 选型关注点
    - 部署复杂度 / 检索性能 / 可扩展性
    - 方便集成 / 高级特性 / 社区活跃度
- 相似度算法（16）
  - 衡量指标
    - 余弦相似度（方向匹配，最常用）
    - 欧式距离（空间距离）
    - 点积（方向 × 长度综合）
  - 搜索算法
    - KNN（暴力 O(ND)，100% 精确，小数据用）
    - IVF（聚类分桶，查局部，内存可压缩）
    - IVF_PQ（PQ 压缩，内存降几十倍）
    - HNSW（分层小世界图，综合最优）
      - 高层高速 → 底层街道
      - 速度 O(log N)，召回极高
    - LSH（概率哈希，O(1) 粗筛）
  - 选型
    - 综合最优 → HNSW
    - 内存吃紧 → IVF_PQ
    - 快速粗筛 → LSH
```

## 四、RAG 优化技术全家桶（19-28）

```markmap
- 基础增强（19）
  - 相似度检索 + 增强生成
  - QuestionAnswerAdvisor（Spring AI）
- 元数据过滤（20）
  - 多版本文档过滤（year = 2023）
  - 多租户权限隔离（user_id）
  - 提供参考源（file_name + page）
- 问题改写（21）
  - 分解（Sub-Query）：多跳问题拆成多个子问题
  - 富化（Enhancement）：模糊问题补全语义
  - 多样化（Perspective）：多视角重写 → RAG-Fusion
  - 回溯提示：结合对话上下文
- 查询路由（22）
  - 数据源路由（内部知识库 / 联网搜索 / API）
  - 领域路由（多知识库场景）
- 查询构造（23）
- 问题澄清（24）
  - 指代消解 / 关键参数缺失 / 歧义检测
- HyDE（25）
  - 先让 LLM 编造假设答案 → 用假设答案去检索
  - 解决词汇不匹配、问题太短
- ES 关键词检索（26）
  - IK 中文分词器
  - 与向量检索混合 → 混合检索
- 重排序（27）
  - 为什么需要
    - 召回和精度 trade-off
    - Bi-Encoder（Embedding）vs Cross-Encoder（Reranker）
  - RRF 融合
    - Σ 1/(k + rank_i)，k=60
    - 只看排名不看分数，不同检索器分数可比
- Graph RAG（28）
  - 文档 → LLM 抽实体关系 → 知识图谱
  - 用户问题 → 社区检测 → 社区摘要 → 答案
  - 擅长全局总结、关系推理
```

## 六、多模态 RAG 实战（33-36）

```markmap
- 多模态 RAG 原理（33）
  - 为什么要多模态
    - PDF 里的图片/表格/公式被纯文本 RAG 丢弃
  - 多模态处理
    - PDFBox 提取文本 + 图片 + 表格（按坐标排序保序）
    - 图片 → 多模态模型（qwen-vl-plus）→ 图片描述文本
    - 表格 → Markdown 或结构化数据
  - 统一文本流 → 分片 → Embedding → 检索
- 多模态问答系统实战（34）
  - 完整工程链路
- MinIO 对象存储（35）
  - 存原始 PDF 文档（长期存档）
  - 向量库 + MySQL + MinIO 三者关系
  - 原始文档是重新 ETL 的来源
- 多模态文档处理串联（36）
  - PdfMultimodalProcessor 完整实现
  - 图片描述不再 mock
  - 文本 + 图片描述 + 表格结构化 → 统一文本流
```
