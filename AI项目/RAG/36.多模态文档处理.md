到这里，已经实现了为图片生成了文字摘要。但问题是，这样做真的够吗？

  

其实还不够。理想的企业级多模态 RAG 系统应当能够在回答中**直接返回原文中的图片**，而不仅仅是生成的文本描述。

  

只是把图片信息转化为纯文本摘要，用户无法在对话中看到原始的图片。这在很多实际的场景中是无法满足需求的。

  

比如，如果企业文档中包含架构图、流程图，用户希望在问答过程中直接查看这些图，而之前的做法完全无法实现这一点。

  

我们可以倒推分析一下，应该怎么做，我们就能实现回复中带有原文图片了。

  

是不是可以想到，我们**针对这个部分做一些特殊处理**，比如改写成下面这种格式：

我们可以考虑将 PDF 中提取出来的图片上传至对象存储服务器，并返回一个上传成功的URL链接，并将之前用多模态模型生成的文本描述放置在description字段上，这样，我们的<image\>标签是不是就很完整了。

  

实现思路如下：

1. **提取 PDF 图片**：将原文中的图片内容抽取出来。
2. **上传对象存储**：将图片上传至 MinIO 等对象存储服务器，获取可访问的 URL。
3. **生成文字描述**：继续使用多模态模型生成图片描述，并放入 <image\> 标签的 description 字段。
4. **形成完整标签**：结合 URL 和描述，就得到既能展示图片，又包含详细信息的完整 <image\> 标签。

接下来的逻辑就是将纯文本和图片的标签，按照坐标顺序进行混合排序，最终生成一段纯文本。获取到这个纯文本之后，我们应该怎么做？是不是应该对其进行数据清洗+分块了，不过在这里有一个非常重要的问题：

  

在切分文本块时，我们是不是应该必须**保证 <image\></image\> 标签的完整性**？也就是说，图片标签不能被拆开成多个块，否则不仅会破坏图片的结构信息，也会严重影响后续的检索效果。

  

此外，在实际企业文档中，图片前后通常会有说明或标注信息，例如“图1. XXXX工作流程图”，这些上下文信息对于理解图片内容非常重要。因此，在切分文本块时，我们需要对包含图片的块做**特殊处理**：将图片周围的说明性文字适当加入到同一个块中，确保上下文完整。

  

对于纯文本内容的切分，则可以沿用常规的 **chunk-size + overlap** 策略，将长文本按大小分块，同时保持一定的重叠区域，以保证语义连续性。

  

我们可以先通过正则匹配的方式，将上面的纯文本进行**粗略分块**，也就是找到<image\>标签来进行文本切割：

```
private static final Pattern IMAGE_PATTERN =            Pattern.compile("<image\\b[^>]*>.*?</image>", Pattern.CASE_INSENSITIVE | Pattern.DOTALL);﻿private List<String> splitByImage(String text) {    List<String> blocks = new ArrayList<>();    Matcher matcher = IMAGE_PATTERN.matcher(text);﻿    int lastEnd = 0;    while (matcher.find()) {        int imgStart = matcher.start();        int imgEnd = matcher.end();﻿        if (imgStart > lastEnd) {            blocks.add(text.substring(lastEnd, imgStart));        }﻿        int afterImgEnd = findNextBreak(text, imgEnd);        blocks.add(text.substring(imgStart, afterImgEnd));﻿        lastEnd = afterImgEnd;    }﻿    if (lastEnd < text.length()) {        blocks.add(text.substring(lastEnd));    }﻿    return blocks;}
```

上面的方法就可以将原文，按照<image\>标签进行粗略分块，如下的效果，我们可以看到文本按照<image\>为分割点，被分成了6块。

基于此，我们对初步得到的粗粒度文本块再进行一轮细分处理。具体就是对每个文本块进行遍历时，会采用以下策略：

- **如果块中包含 <image\> 标签**，则进入**图片块的特殊处理流程**，确保图片标签的完整性，并将其前后的说明文字一并纳入同一块。
- **如果块的长度超过 chunkSize**，则按照既定的 **chunk-size + overlap** 策略进行常规切分，以保证语义连续性。
- **如果块的长度小于 chunkSize**，则无需进一步拆分，直接作为一个完整的文本块保留下来。

```
protected List<String> splitText(String text) {    if (text == null || text.isEmpty()) return Collections.emptyList();﻿    // 按图片切分为初步块    List<String> rawBlocks = splitByImage(text);    List<String> result = new ArrayList<>();﻿    for (int i = 0; i < rawBlocks.size(); i++) {        String currentBlock = rawBlocks.get(i).trim();        if (currentBlock.isEmpty()) continue;﻿        boolean containsImage = IMAGE_PATTERN.matcher(currentBlock).find();﻿        if (containsImage) {            // 图片块：应用前后 overlap            result.add(buildImageChunk(rawBlocks, i));﻿        } else if (currentBlock.length() > maxSize) {            // 超长纯文本块：按 maxSize 切分，不重叠            result.addAll(chunkPureTextNoOverlap(currentBlock));﻿        } else {            // 短纯文本块：直接加入，不应用 overlap            result.add(currentBlock);        }    }﻿    return result;}
```

接下来我们再看下**buildImageChunk**这个方法做了什么工作。

```
/** * 构建图片块 chunk，应用前后 overlap */private String buildImageChunk(List<String> blocks, int index) {    StringBuilder chunkBuilder = new StringBuilder();    String currentBlock = blocks.get(index).trim();﻿    // 前序 overlap    if (index > 0) {        String prevBlock = blocks.get(index - 1).trim();        int start = Math.max(0, prevBlock.length() - overlap);        String prevOverlap = prevBlock.substring(start);        if (!prevOverlap.isEmpty())             chunkBuilder.append(prevOverlap).append(SEPARATOR);    }﻿    // 当前图片块    chunkBuilder.append(currentBlock);﻿    // 后序 overlap    if (index < blocks.size() - 1) {        String nextBlock = blocks.get(index + 1).trim();        int end = Math.min(overlap, nextBlock.length());        String nextOverlap = nextBlock.substring(0, end);        if (!nextOverlap.isEmpty())             chunkBuilder.append(SEPARATOR).append(nextOverlap);    }﻿    return chunkBuilder.toString().trim();}
```

这段代码还是很容易理解的，就是在这个<image\>文本块的**前一个块和后一个块，分别取一段overlap**，这个overlap大概率是包含了一些图片描述的信息的，取得这个重叠部分，拼接在<image\>标签的前后，可以进一步提升我们<image\>语义的完整性。
