## Q1: 什么是 RAG Triad？三个维度如何理解？

**难度**: ⭐⭐ 中级

**参考答案**:

**RAG 三元评估（RAG Triad）**可用问题、检索资料和答案之间的关系解释。TruLens 使用以下三个维度：

| 关系 | 维度 | 要回答的问题 |
|:---|:---|:---|
| 问题 ↔ 检索上下文 | Context Relevance（上下文相关性） | 找到的资料对问题有用吗？ |
| 上下文 ↔ 答案 | Groundedness（依据性） | 答案中的陈述受资料支持吗？ |
| 问题 ↔ 答案 | Answer Relevance（答案相关性） | 答案回应了原问题吗？ |

Ragas 的 Faithfulness 等指标可评估类似目标，但不同框架名称相近不表示计算方式完全相同。Triad 是观察框架，不是一条统一打分公式；三项都好也不自动证明原始资料真实、最新或符合权限。

> 来源：[[AI项目/RAG评测/2.RAG评测之RAG Triad]]；术语校核：[TruLens RAG Triad](https://www.trulens.org/getting_started/core_concepts/rag_triad/)（2026-10-20）。

**追问**：三项都高就代表事实正确吗？不能，资料本身可能错误或过时。

## Q2: 检索层有哪些指标？Context Recall 和 Context Precision 需要参考数据吗？

**难度**: ⭐⭐ 中级

**参考答案**:

**先说结论**：必须指明指标实现和参考数据，不能统称 Context P/R 都不需要 Ground Truth（GT，参考标准）。

| 指标 | 衡量什么 | 所需依据 |
|:---|:---|:---|
| ID 级 Recall@K | 标注相关片段中有多少被取回 | 相关片段 ID 集合 |
| Precision@K | 返回前 K 个片段中有多少相关 | 逐片段相关性标注 |
| MRR | 第一个相关结果排名的倒数，再对问题取均值 | 二元相关性标注 |
| NDCG@K | 前 K 项的等级相关性与排序质量 | 相关性等级及理想排序 |
| Ragas LLM Context Recall | 参考答案的事实被检索上下文支持的比例 | 问题、检索上下文及 `reference` |
| Ragas Context Precision | 相关上下文是否靠前，具体实现有排序加权 | 参考答案、参考上下文，或无参考变体所需的生成答案等 |

**核心区别**：ID 级召回衡量“哪些片段找到了”；语义指标衡量“哪些参考事实得到支持”。语义评判不依赖精确相同的文档 ID，不代表完全不需要参考数据。无参考 Precision 变体也不能替代衡量遗漏信息的 Recall。

若答案有多个有效证据来源，标注应允许等价证据；更换分片策略后原 chunk ID 标签需重新映射。

> 来源：[[AI项目/RAG评测/3.RAG的核心评测指标有哪些]]；输入与实现校核：[Ragas Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)、[Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/)（2026-10-20）。

**追问**：语义召回不用 ID 就无需参考吗？不是，不用 ID 标注不代表不用参考事实。

## Q3: Faithfulness、Answer Relevancy 和 Correctness 有什么区别？

**难度**: ⭐⭐ 中级

**参考答案**:

| 维度 | 关注点 | 能否单独证明答案正确 |
|:---|:---|:---|
| 忠实度（Faithfulness） | 答案的事实陈述是否被检索资料支持 | 不能，资料本身可能有误或过期 |
| 回答相关性（Answer/Response Relevancy） | 是否回应问题 | 不能，相关的回答也可能事实错误 |
| 正确性（Correctness） | 是否符合可信参考与任务标准 | 依赖参考质量和具体判分规则 |

例如用户问 2023 版参数，模型忠实复述了错误召回的 2024 版资料：可能忠实度很高，但并未正确回答问题。

Ragas 常见 Faithfulness 实现将答案拆为声明，再判断上下文是否支持；相关性指标和正确性指标有各自实现，不能把“和参考答案相似”当作全部事实正确。

**无声明、空答案或拒答**要单独统计，不能靠少回答关键事实来换取看似很高的忠实度；评测实现对此的返回行为须按版本记录。

> 来源：[[AI项目/RAG评测/3.RAG的核心评测指标有哪些]]；[Ragas Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)、[Response Relevancy](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/answer_relevance/)（2026-10-20）。

**追问**：忠实复述错误版本算正确吗？不算，应分别评估依据、版本匹配与事实正确性。

## Q4: LLM-as-Judge 如何工作？有什么局限？

**难度**: ⭐⭐ 中级

**参考答案**:

**模型裁判（LLM-as-Judge）**根据给定规则对答案或证据进行语义评判，可输出分数、理由与证据位置，适合难以用字符串完全匹配评估的任务。

例如评估忠实度时，向裁判提供上下文和答案，让它逐条检查声明是否受支持；评估正确性时，还要提供可信参考或明确任务标准。

**局限**：裁判可能受提示、表述长度、呈现顺序、领域知识和被评材料中的指令影响。用更大模型不自动保证校准；传统规则、ID 对照与人工审核仍有价值。

**回答重点**：先定义评分标准和标注样例，再对照人工标注验证裁判，保留理由和分歧样本。解析失败与超时是评测运行错误，应与答案低分分开。

> 来源：[[AI项目/RAG评测/4.LLM-as-Judge]]、[[AI项目/RAG评测/7.RAGAS评测时，如何抑制模型幻觉导致的结果不稳定问题？]]。

**追问**：裁判输出 JSON 就可信吗？只改善解析，还须验证规则、偏差与人工一致性。

## Q5: Ragas 评测的输入、流程与版本边界是什么？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：Ragas 提供多种指标与评测能力，按所选指标准备字段；不存在一份字段格式永远适用于全部版本和指标。

| 语义字段 | 用途 |
|:---|:---|
| `user_input` | 用户原问题 |
| `response` | 被评系统实际答案 |
| `retrieved_contexts` | 实际提供给生成模型的上下文 |
| `reference` | 指标需要时提供可信参考答案 |
| `reference_contexts` / 相关 ID | 指标需要时提供参考证据 |

流程：固定数据与配置 → 跑被评系统并保存中间结果 → 按指标要求校验字段 → 执行评测 → 分析低分、异常与人工分歧 → 优化后回归。

旧教程的 `question/answer/ground_truth/contexts` 不能直接假设是新 API 的字段；需要显式转换并固定依赖。官方滚动文档区分 collections 指标与旧指标 API，本目录不提供跨版本混用的执行代码。

> 来源：[[AI项目/RAG评测/6.RAGAS框架初探&实现原理]]；API 与字段校核：[Ragas Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/)、[Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/)（2026-10-20）。⚠️ raw 缺失，待补充：本项目锁定版本与可运行评测脚本。

**追问**：评测时收集初始召回还是最终上下文？评估生成应使用实际入模上下文，检索各阶段另存以定位。

## Q6: 如何降低模型裁判的不稳定并验证评分可信度？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：降低波动与校准标准同时做，不能用 `temperature=0` 宣称输出完全确定。

1. 固定裁判模型版本、提示模板、指标实现、输入及运行配置；模型支持时采用较低采样随机性。
2. 用明确评分规则和少量人工标注示例对齐标准，要求结构化结果与证据理由。
3. 对边界样本重复评分，报告波动；分歧样本人工复核，而不是一律用平均分掩盖分歧。
4. 在独立人工标注集上验证一致性；换裁判后重新校准，不能直接对比旧分数。
5. 对失败、空输出与无法判断单独计数，记录有效样本覆盖率。

**易错点**：裁判自己输出的“置信度”未经校准不能当概率；更强模型可能仍有系统偏差。评测加速时换小模型也必须重新验证评分能力。

> 来源：[[AI项目/RAG评测/7.RAGAS评测时，如何抑制模型幻觉导致的结果不稳定问题？]]。本题为原文稳定化策略的审校整理，不承诺确定性。

**追问**：温度零能保证完全复现吗？不能，仍须记录配置、版本并观察重复运行波动。

## Q7: 如何准备有代表性的 RAG 评测集？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：覆盖真实问题和关键失败模式，规模取决于问题分布与误差要求，不能说达到 50 或 200 条就自然可靠。

| 维度 | 应覆盖的样本 |
|:---|:---|
| 问题类型 | 单事实、步骤、跨文档、多跳、表格图片 |
| 用户表达 | 简写、别名、专业术语、指代与中英混合 |
| 约束 | 文档版本、时间、租户、权限边界 |
| 可回答性 | 可回答、缺资料、条件不全、无权访问 |
| 来源 | 真实流量、人工设计、文档反向生成、历史错误样本 |

每条保存原问题、可信参考、证据定位、适用版本及类别。自动生成的问题须审核，避免只复述分片原句；参考答案不能随当前系统的错误输出修改。

调参集与独立测试集分开，防止针对已见题目反复优化造成虚高。不同分片策略比较时，证据最好能回到稳定文档位置；修改 chunk 后重核标签。

> 来源：[[AI项目/RAG评测/8.RAG的评测数据集该如何准备？]]、[[AI项目/RAG评测/9.怎样的评测集算是好的评测集？]]、[[AI项目/RAG评测/10.基于文档生成用于评测的数据集]]。独立测试与证据重映射为评测设计建议，⚠️ raw 缺失，待补充项目数据划分记录。

**深入追问**：

图片、表格和跨页证据如何标注？把文档版本、页码/区域、资源或表格标识与必需的事实点一起记录；表格还需保留行列、单位和条件。允许多个有效证据组合，避免只有某次分片 ID 才算正确。

分层评估：原件有证据但解析结果缺失，先归因解析；解析结果正确而候选没找到，再看检索；入模证据完整仍答错，再看生成。文字描述分数高不能证明原图事实完整。来源：[[AI项目/RAG/33.多模态RAG]]、[[AI项目/RAG/34.实战：多模态RAG智能问答系统]]。⚠️ raw 缺失，待补充：多模态证据标注集。

**追问**：自动生成题目能直接作为金标准吗？需审核覆盖、事实与证据，并避免数据泄漏。

## Q8: 评测低分有哪些常见原因？怎么选择优化动作？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

| 现象 | 优先检查 | 可能动作 |
|:---|:---|:---|
| 目标证据未进入候选集 | 解析、分片、索引、过滤和查询表达 | 修解析/约束错误，调整检索或补关键词 |
| 证据已召回但没进最终上下文 | 排序、去重、回填与 token 截断 | 重排、证据多样性、预算与映射修复 |
| 上下文正确但回答无依据 | 提示、历史冲突、模型遵循能力 | 强化证据约束与生成验证 |
| 答案忠实却事实错误 | 原文、版本和参考答案是否正确 | 更新资料、版本约束或修正错误标注 |
| 过度拒答 | 阈值、可回答性判断与证据覆盖 | 在标注集上校准拒答边界 |
| 引用错位 | 片段 ID、重排后映射、来源展示 | 维持稳定来源标识并检查支撑关系 |

指标只能提示线索，不是根因证明。例如相关性低不必然是查询改写问题，可能是生成忽略问题；先查看输入与中间结果，再改配置。

> 来源：[[AI项目/RAG评测/15.know-engine评测问题与优化（bad case）]]、[[AI项目/RAG评测/18.解决问题重写导致的召回不准问题]]、[[AI项目/RAG评测/19.解决RRF融合乱序和结果重复的问题]]、[[AI项目/RAG评测/20.解决引用信息补全导致参考资料乱序问题]]。

**追问**：分数低能直接指定某模块为根因吗？不能，应检查样本和阶段中间结果。

## Q9: 怎样区分检索、上下文组装和生成问题？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：检查完整证据链，并用受控替换帮助归因。

1. 原文有答案吗？没有则是资料覆盖或参考标注问题。
2. 解析结果保留答案了吗？没有则先修解析与分片。
3. 初始候选中有证据吗？没有再检查索引、过滤、嵌入和查询表达。
4. 最终输入模型的上下文还有证据吗？没有则检查融合、重排、父块回填与截断。
5. 证据完整且版本正确，仍答错，再查提示、历史和模型生成。

**受控实验**：用人工确认的正确上下文替换实际检索结果，保持问题与生成配置不变；若回答改善，检索或上下文处理是重要线索。继续逐阶段替换能缩小范围；单次实验不能排除随机波动和多处共同失败。

不要将高 Faithfulness 当作全部正确，也不要为了拉高某个分数牺牲可回答样本覆盖。

> 来源：[[AI项目/RAG评测/15.know-engine评测问题与优化（bad case）]]、[[AI项目/RAG评测/27.RAG评测总结]]。受控替换为排查设计建议，⚠️ raw 缺失，待补充实验记录。

**追问**：正确上下文替换后变好能完全排除生成问题吗？不能，可能存在随机波动或多个共同问题。

## Q10: 如何加速评测，同时保持结果可比？

**难度**: ⭐⭐ 中级

**参考答案**:

**先说结论**：减少重复工作与无效等待，不能预设“换小模型精度损失很小”或固定并发对应固定耗时。

- 用分层小样本做调试，通过后仍跑完整验收集；报告抽样范围。
- 按提供商限流和本机资源设置有界并发、超时、重试及退避，观察失败率与队列等待。
- 缓存时键包含指标实现、裁判模型、提示、问题、上下文、答案及指标需要的参考数据，避免配置变了仍复用旧分。
- 只运行当前比较所需指标，但最终验收仍覆盖关键业务要求。
- 更换裁判或指标实现后重新校准，不能直接拿新旧分数宣称系统进步。

API 配置随版本变化：Ragas 旧评测接口使用过 `RunConfig`，collections 方式的客户端配置不同；不能把未经核实的 `async_mode=True` 当通用开关。

> 来源：[[AI项目/RAG评测/14.RAGAS评测时，如何加速评测速度]]；版本校核：[Ragas 配置说明源码](https://github.com/vibrantlabsai/ragas/blob/main/docs/howtos/customizations/run_config.md)（2026-10-20）。缓存键为工程设计建议，⚠️ raw 缺失，待补充实现。

**追问**：只把失败评测样本丢掉可以吗？不应，应报告失败率与有效覆盖，否则均分可能虚高。

## Q11: 上线后如何持续评测与发现错误样本？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题骨架**：监控运行状态 → 授权范围内采样 → 质量评估与人工复核 → 错误归因 → 加入回归集 → 新版本离线对照与灰度验证。

| 场景 | 可做什么 | 不能直接承诺什么 |
|:---|:---|:---|
| 实时监控 | 超时、失败率、延迟、空结果、调用量与用户反馈 | 无人工参考仍可直接算真实召回率 |
| 抽样质量评估 | 忠实度、问题回应程度、引用支撑等 | 自动评分等于事实真相 |
| 有参考的回放集 | Recall、正确性、旧错误修复率 | 整体均分掩盖关键类别退化 |

没有参考答案或参考证据的真实流量，不能直接计算依赖参考的 Context Recall；先用可计算的信号筛选，再对审核标注样本回放。

保留模型、索引、提示与策略版本，复核隐私及权限范围内的日志；发布前比较质量、误拒、性能与费用，失败或退化时有明确回退路径。

> 来源：[[AI项目/RAG评测/28.线上幻觉Case的预发回放机制]]、[[AI项目/RAG评测/27.RAG评测总结]]。⚠️ raw 缺失，待补充：真实线上监控和灰度记录，以上为闭环设计。

**追问**：真实流量没参考能直接测 Recall 吗？不能直接计算依赖参考的召回指标，应先标注或用其他信号。
