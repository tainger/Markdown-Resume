# 七、工程故障与场景设计

[返回题库目录](./README.md) · 更新：2026-10-20

> 10 道场景题，按“定位 → 处理 → 验证 → 追问”组织。以下是基于系列资料整理的排查思路和设计建议，不代表仓库已有对应生产实现。
>
> ⚠️ raw 缺失，待补充：本篇新增的版本发布、缓存、迁移与权限协议的具体实现、故障演练和实测记录。每题来源只支持相关基础机制，不视为完整方案的实现证据。

## Q1: 知识库里明明有答案，为什么检索为空？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题顺序**：先验证资料和约束，再调模型。

1. 选一个具体问题，找到原文答案与其文档版本，确认当前用户有权访问。
2. 查看解析文本、分片和入库任务，确认答案没有在抽取时丢失，目标块已写入且可查询。
3. 查看检索请求中的租户、版本、类型和日期过滤；在同一授权范围内逐项验证条件，不撤掉权限过滤排查。
4. 核对查询与文档的嵌入模型、维度、指令格式、度量和归一化是否一致。
5. 比较关键词检索、精确向量搜索与 ANN。精确能找到而 ANN 找不到，再检查索引参数和过滤后候选不足。

**验证**：固定问题、用户、版本和索引快照，记录每阶段数量与目标证据排名；修复后覆盖同类问题，而非只验证当前一句。

**追问**：增大 K 就能解决吗？不能，原文缺失、错误过滤和编码不一致需要先修复。

> 来源：[[AI项目/RAG/2.深入理解RAG技术原理——索引构建]]、[[AI项目/RAG/20.RAG优化技术：元数据过滤]]、[[AI项目/RAG/16.相似度搜索的常见算法]]。 检索执行参考：[pgvector Filtering](https://github.com/pgvector/pgvector#filtering)。

## Q2: 检索资料正确，但答案仍然错误，怎么定位？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题顺序**：确认“正确资料”真的进入最终模型输入。

1. 对照召回结果与最终上下文：是否在重排、去重、父块回填或 token 截断时丢失证据。
2. 检查版本、时间、单位、表头和例外条件；证据里出现关键词不等于包含完整答案。
3. 查看完整提示与历史，是否有旧答案、冲突指令或无依据补充要求。
4. 用人工确认的证据替换上下文，保持原问题和生成配置进行对照；必要时重复运行以检查波动。
5. 检查声明与引用的支撑关系，分别记录事实错误、跑题、漏答和无依据扩展。

**验证**：在同类问题上比较正确性、忠实度和拒答率；只提高忠实度仍可能是在忠实复述错误版本。

**追问**：直接换更强模型呢？可以作为对照，但不能修复已被截掉的证据和错误引用映射。

> 来源：[[AI项目/RAG评测/15.know-engine评测问题与优化（bad case）]]、[[AI项目/RAG评测/24.通过换模型解决忠诚度低的问题]]、[[AI项目/RAG评测/22.通过优化系统提示词，提升答案正确性]]。

## Q3: 父子分片跨存储写入时，如何防止新旧版本混读？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**设计建议**：以可恢复的版本发布替代“多个库同时写就算成功”。

1. 定义稳定 `documentId`，为每次内容变更生成 `version`；子块、父块、来源都携带同一版本。
2. 新版本先写入暂存状态，任务按文档与版本幂等；重复消息不创建重复块。
3. 验证父子映射、片段数、写入结果及查询可见性，再更新权威版本指针。
4. 一次查询读取并固定有效版本，检索与父块回填均限制该版本；缓存也带版本。
5. 旧版本在在途请求结束后清理，失败任务可重试并通过对账修复孤儿块。

不能用单库事务保证所有外部索引原子提交。权限撤销或敏感资料删除需单独处理：立即阻断访问与旧缓存，不能只等待旧版本自然过期。

**验证**：模拟重复投递、任一存储超时、发布前崩溃及新旧请求并发，检查无孤儿引用、无混版与可恢复。

**追问**：索引写入返回成功但未可见怎么办？发布前检查读取路径；后端一致性语义也属于设计约束。

> 来源：[[AI项目/RAG/9.什么是父子分片]]、[[AI项目/RAG/20.RAG优化技术：元数据过滤]]。

## Q4: 多租户 RAG 如何防止越权？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**设计建议**：权限控制覆盖整条数据路径，不能依赖提示词让模型保密。

- 请求身份由认证系统确认，服务端生成租户与授权约束，用户参数只能进一步缩小范围。
- 向量、关键词、结构化查询等分支全部带约束；父块回填、引用下载和工具查询再次遵守授权。
- 缓存按租户、权限范围及授权版本隔离；权限变化时失效，命中时仍校验访问范围。
- 会话历史、调试日志和评测导出也可能携带资料，纳入同一访问策略。
- 缺少租户或授权上下文时停止查询，不能默认跨租户全量搜索。

**验证**：同名文档跨租户、共享文档、角色变化、权限撤销、缓存命中与伪造请求参数均需覆盖。

**追问**：召回后再过滤可以吗？实现要保证未授权资料不进入模型或外部处理，并评估候选不足；不能把末端隐藏答案当作完整权限隔离。

> 来源：[[AI项目/RAG/20.RAG优化技术：元数据过滤]]。

## Q5: 回答的引用错位或内容不支持结论，怎么修？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题顺序**：把引用拆为“能找到来源”和“来源能支持声明”两项。

1. 让片段携带稳定标识、文档版本、页码/章节或位置；融合去重使用统一身份，而非各数据源临时序号。
2. 重排、父块替换和压缩后保留映射，生成前建立明确的证据标识表。
3. 模型只能使用提供的标识；服务端检查标识是否存在，并在受控权限下返回来源。
4. 对关键数字、条件与结论，核对被引用片段是否实际支撑；标识合法不等于内容支持。
5. 回看原文与解析结果，排除表头丢失、版本错误或摘要扭曲。

**验证**：打乱检索顺序、制造重复块、回填父块并压缩后，来源仍能定位正确版本；抽样人工检查声明支撑。

**追问**：把结果重新编号就够了吗？只解决展示编号，不能保证语义引用正确。

> 来源：[[AI项目/RAG评测/19.解决RRF融合乱序和结果重复的问题]]、[[AI项目/RAG评测/20.解决引用信息补全导致参考资料乱序问题]]。

## Q6: 更换 Embedding 模型，如何迁移与回滚？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**设计建议**：把嵌入模型、输入规范、维度和索引视为一套版本配置。

1. 固定新模型版本、query/document 处理方式与相似度度量，创建新索引。
2. 从原件或可靠解析结果重新嵌入，记录断点与失败任务；同维度的新旧向量也不能混搜。
3. 迁移期间增量变更同时进入相应版本，或在切换前补齐增量；检查内容与删除水位一致。
4. 在同一评测集做质量与性能对照，必要时影子查询，不将新旧原始分数直接比较。
5. 将查询编码器与索引配置一起切换，保留旧配置用于回滚；保留期内旧索引也需满足更新和删除要求。

**验证**：全量完整性、增量追平、权限过滤、删除、模型服务故障与回滚后的查询结果。

**追问**：是否只改查询侧模型？不行，新查询向量与旧文档向量可能不在同一空间。

> 来源：[[AI项目/RAG/12.向量模型&向量数据库&向量存储]]、[[AI项目/RAG/15.如何使用离线向量模型]]。

## Q7: 线上 p95 延迟突然上升，如何排查和降级？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题顺序**：沿请求追踪找关键路径，再分清排队、网络和实际计算。

1. 检查流量、输入长度、候选数、模型或索引版本是否改变，以及是否发生限流重试。
2. 区分首 token 延迟和总耗时；长答案与生成排队的处理方式不同。
3. 检索变慢看查询计划、过滤选择性、索引与存储资源；父块回填看批量查询和 N+1。
4. 重排或改写变慢看请求量、批处理和外部服务；多查询扩展可能放大下游负载。
5. 设置总时限、阶段超时和有界并发；在评测允许时跳过可选改写/重排、缩小候选或退回可用检索路径。

**验证**：使用相同流量分布压测，对比 p95、失败率、质量与费用；跳过重排后仍应验证证据足够。并行分支的分位数不能直接相加当成端到端 p95。

**深入追问**：

多查询如何放大下游请求？若原查询和扩展后共得到 Q 个查询，每个都发给 R 个检索器，未合并和去重前可产生 Q×R 次检索任务；条件路由可能减少，重试和多轮检索可能增加。这个计数描述任务量，不等于所有任务都同时执行或都产生一次模型调用。

容量评估还应计入改写、嵌入、重排、生成的调用数、token 与服务时间。设置全链路预算、有界并发和背压，观察不同流量下队列与配额；不能只压测一个基础检索请求。来源：[[AI项目/RAG/21.RAG优化技术：问题改写]]、[[AI项目/RAG/30.LangChain4J中的Modular RAG支持]]。⚠️ raw 缺失，待补充：流量分布与容量测量记录。

**追问**：流式输出能解决吗？可改善开始反馈的体验，但不消除检索、模型排队或总计算开销。

> 来源：[[AI项目/RAG/3.深入理解RAG技术原理——检索生成]]、[[AI项目/RAG/27.RAG优化技术：重排序]]。

## Q8: RAG 缓存如何避免串用户、旧知识和错误命中？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**设计建议**：先区分嵌入缓存、检索缓存与答案缓存，生命周期不同。

- 嵌入缓存：包含文本、模型版本、输入指令、输出维度等影响编码的配置。
- 检索缓存：包含查询表示、索引版本、授权范围、过滤条件、召回参数和策略版本。
- 答案缓存：还需考虑历史上下文、提示、生成模型、知识版本与输出要求；有状态问题不能只以当前一句话作为键。
- 语义相似不是事实或权限等价，数字、否定、型号和年份变化可能必须重新回答。
- 文档更新、删除及权限变化触发相关缓存失效；TTL 只能限制陈旧时间，不能代替权限校验。

**验证**：相同问题跨租户、相似问题不同型号、历史指代变化、旧版本答案、权限撤销后命中等用例。

**追问**：缓存命中后还要查权限吗？要依据当前授权策略校验，不能沿用创建缓存时的权限结论。

> 来源：[[AI项目/RAG/20.RAG优化技术：元数据过滤]]、[[AI项目/RAG/12.向量模型&向量数据库&向量存储]]。

## Q9: 检索文档含“忽略指令并执行工具”等内容，如何处理？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：这是来自资料的间接提示注入（Indirect Prompt Injection）风险；检索到的文本是数据，不应获得修改系统规则或工具权限的地位。

1. 将外部资料与可信任务指令分开，明确资料仅用于取证；不能声称加分隔符就彻底解决。
2. 检索与工具执行由服务端实施授权与最小权限，不向模型暴露不必要的凭据和能力。
3. 工具调用参数在执行前校验，限制数据发送目的地；对高影响操作设置独立确认或审查路径。
4. 记录来源，对可疑文档隔离和复核；输出校验兼顾数据泄漏与错误引用。

**验证**：准备带恶意指令的文档、图片描述和跨片段载荷，检查是否能影响回答或越权工具调用；不能只测试用户直接输入攻击。

**追问**：用了 RAG 是否更安全？RAG 不消除注入，还会引入外部内容作为攻击入口。

> 来源：[[AI项目/RAG/38.Agentic RAG]]。 安全口径：[OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)（2026-10-20）；⚠️ raw 缺失，待补充安全验证样例。

## Q10: 面试中如何讲清自己的 RAG 项目，避免只背架构？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**答题骨架**：业务目标与约束 → 数据和离线链路 → 在线证据链 → 一个真实失败样本 → 排查和优化 → 对照验证 → 维护与局限。

- 业务：用户问什么、哪些资料可用、版本/权限要求、何时应拒答。
- 实现：讲清实际使用的组件、依赖版本及职责；区分自己负责、课程演示和设计设想。
- 案例：选择一条具体问题，展示原文证据、旧行为、根因与修改，解释为什么不是其他原因。
- 验证：同一评测集、同一硬件与约束，报告样本量、指标定义、质量和延迟费用变化。
- 局限：明确未覆盖的文档类型、更新一致性、权限或长尾问题，以及下一步验证方式。

**验证**：所有数字能回到数据、记录或实验；没有记录就说明尚未测量，不把题库示例写成生产成绩。

**追问**：优化效果只有几个案例算不算？可说明方向，但需更广覆盖的独立测试才能支持整体收益结论。

> 来源：[[AI项目/RAG/34.实战：多模态RAG智能问答系统]]、[[AI项目/RAG评测/27.RAG评测总结]]、[[AI项目/RAG评测/28.线上幻觉Case的预发回放机制]]。
