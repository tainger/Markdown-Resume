## Q1: OCR、图片描述与多模态向量分别解决什么问题？

**难度**: ⭐⭐ 中级

**参考答案**:

**先说结论**：分别关注文字识别、视觉内容解释和可检索表示，不能把其中一种等同于完整的多模态理解。

| 方式 | 主要作用 | 局限 |
|:---|:---|:---|
| 光学字符识别（OCR） | 从扫描页或图片识别文字，可能附位置 | 不能只凭文字就保证恢复图表关系 |
| 图片描述 | 用视觉模型描述图像内容、结构或含义 | 可能遗漏数字、细节或生成错误 |
| 多模态向量 | 将适配的图文内容编码用于检索 | 检索表示不等于可直接展示的原图或事实证明 |

本库主要使用图片转描述、文本嵌入再检索的路线，实战篇明确未覆盖完整表格、公式与扫描件处理。应按“要读文字、看布局、查数值还是找相似页面”选择并评测，而不是给所有图片统一生成一句摘要。

**验证**：使用扫描文字、流程图、参数表、照片和带数值图表，分别检查文字、结构和关键事实是否保留，以及目标证据能否被检索。

**追问**：OCR 成功就能准确回答表格问题吗？不能，仍需保留行列、单位、表头和条件。

## Q2: 如何关联图片描述、原图、图注与页码，返回正确图片？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**设计建议**：将“用于检索的文本”与“用于取证展示的资源”分开，用稳定身份关联，而不是让模型猜图片 URL。

1. 原图保存为受控资源，用 `imageId` 或对象键与文档版本、页码、区域关联；模型生成的描述标记为派生内容。
2. 图注与邻近正文按版面关系关联，不能只因同页就认定属于同一图片。
3. 片段保留资源标识和来源，检索后由服务端解析为当前用户可访问的原图。
4. 对短期签名 URL，在展示时按授权生成，避免把会过期的访问链接作为唯一长期身份。
5. 同图多次出现时区分资源去重和文档位置，重复图片不应导致来源位置丢失。

描述命中不保证原图支持答案，关键事实需要回看图像或人工抽查。

**验证**：覆盖同页多图、同图跨页、重排和父块回填、文档更新及访问链接过期，核对图片与说明、页码和权限均正确。

**追问**：把图片 URL 写进片段就够吗？不够，还要保证资源身份稳定、位置正确、访问受控。

## Q3: 图片描述包含引号、换行或标签字符时，直接拼接 image 标签有什么问题？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：描述是外部数据，直接拼接到属性中会混淆数据与结构；同时让分片、解析和渲染依赖脆弱字符串约定。

正文用 `<image src="URL" description="描述"></image>` 作为中间表示。描述含引号、尖括号、换行或类似结束标签时，若未正确编码与解析，可能破坏结构；正则匹配到标签也不能证明属性内容或 URL 合法。

可改为结构化资源记录：类型、资源 ID、描述、文档版本、页码与位置分别存储；通过序列化器生成中间数据，展示时再由可信代码构造 Markdown 或 UI 元素。

外部资源地址需按业务约束验证，渲染也要做相应处理。序列化能解决结构编码问题，但不能自动解决描述事实错误或提示注入，可信指令与资料仍需区分。

**验证**：覆盖双引号、换行、尖括号、伪结束标签、空描述和非法地址；往返解析应保留内容且不改变资源边界。

**追问**：只把双引号替换成单引号可以吗？不能覆盖所有编码、结构与渲染问题，应使用明确的数据格式与解析契约。

## Q4: 图片描述过长，怎样兼顾资源完整性与模型输入预算？

**难度**: ⭐⭐⭐ 高级

**参考答案**:

**先说结论**：保持资源身份完整，不等于把全部描述和相邻文字强行塞进一个无限大的 chunk。

1. 保留原图、原始描述和位置；将冗长描述拆为可检索子描述，各自指向同一资源与具体语义区域。
2. 检索命中后选择与问题相关的描述、图注及邻近证据；需要时回取原图，不无条件拼接整页。
3. 分别检查文本嵌入单条上限、生成端总预算；若实际发送图片，还需考虑目标视觉模型的图片与输入限制。
4. 表格数字、坐标和例外条件不能在摘要时随意省略；无足够细节时明确无法确认。

本库保证图片标签不被切开的思路，只解决结构边界的一部分问题；正文过长、描述重复和多图共同占用预算仍需单独设计。

**验证**：构造超长描述、同图多子描述、多图联合问题与边界事实，检查所有片段可定位原图、输入不超限且关键证据未被压掉。

**追问**：保留完整标签就一定不会超 token 吗？不会，标签内部描述和周围文本仍占输入预算。

> 来源：[[AI项目/RAG/9.什么是父子分片]]、[[AI项目/RAG/36.多模态文档处理]]。⚠️ raw 缺失，待补充：视觉输入限制核验、子描述策略和质量对照实验。
