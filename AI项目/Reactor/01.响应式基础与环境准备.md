# 01. 响应式基础与环境准备

> 目标：先理解程序如何交换数据与完成信号，再学习 API。返回 [[AI项目/Reactor/README]]。

## 1. Reactor 解决什么问题

一次请求可能依次查询数据库、调用远程服务、处理模型输出。传统同步写法容易理解，但等待 I/O 时会占着调用线程；回调写法能释放等待线程，却容易把依赖、异常和取消拆散。

Reactor 用可组合的数据流表达这些步骤：声明来源、变换与依赖，再由订阅者驱动执行。它实现 Reactive Streams 协议，并提供 `Mono`、`Flux` 及操作符。

```java
// 假设两个方法均返回 Mono
Mono<String> reply = loadUser(userId)
        .flatMap(user -> askModel(user))
        .map(answer -> "回答：" + answer);
```

这段代码表达步骤关系。是否使用网络事件循环、是否阻塞以及在哪个线程执行，还取决于来源、方法实现和调度配置。

依据：[响应式编程介绍](https://projectreactor.io/docs/core/release/reference/reactiveProgramming.html)。

## 2. 五个概念不要混在一起

| 概念 | 关注的问题 | 反例或边界 |
|:---|:---|:---|
| 响应式 Reactive | 怎样组合数据、错误、完成与需求信号 | 同步的 `Flux.range` 也可构成响应式链 |
| 异步 Asynchronous | 调用方是否必须等任务完成才继续 | 放进线程池的阻塞 JDBC 调用可以是异步的 |
| 非阻塞 Non-blocking | 等待资源时是否占着执行线程 | 返回 Mono 的方法内部仍可能调用阻塞 SDK |
| 并发 Concurrency | 多个任务能否交错推进 | 一个事件线程也能推进多个 I/O 任务 |
| 并行 Parallelism | 多个任务是否同时计算 | 需要实际执行资源，单写 `flatMap` 不会创建线程 |

Reactor 能帮助组织这些行为，不能把任意同步方法自动改造成非阻塞 I/O。

## 3. 协议中的四个角色

| 角色 | 职责 |
|:---|:---|
| `Publisher<T>` | 提供订阅入口，是数据源或经过处理的数据流 |
| `Subscriber<T>` | 接收订阅、数据、失败和完成 |
| `Subscription` | 接收 `request(n)` 与 `cancel()` |
| `Processor<T,R>` | 同时是 Subscriber 与 Publisher；新业务代码通常使用操作符或 Sinks |

一次订阅的典型交互：

```text
Subscriber → Publisher.subscribe(...)
Subscriber ← onSubscribe(subscription)
Subscriber → request(n)
Subscriber ← onNext(value)，最多满足当前累计需求
Subscriber ← onComplete() 或 onError(error)
```

错误和正常完成都是终止信号；取消是下游的控制动作，不等于收到 `onComplete`。没有需求时不能发送 `onNext`，但完成/错误信号不必等需求额度。

依据：[Reactive Streams Subscription](https://www.reactive-streams.org/reactive-streams-1.0.4-javadoc/org/reactivestreams/Subscription.html)、[Reactor 信号模型](https://projectreactor.io/docs/core/release/reference/reactiveProgramming.html)。

## 4. Mono、Flux 与集合/Future 的区别

| 类型 | 表达什么 |
|:---|:---|
| `T` | 一个已经拿到的普通值 |
| `List<T>` | 一组已经收集好的值 |
| `CompletableFuture<T>` | 一次异步完成的结果；是否已启动由创建方式决定 |
| `Mono<T>` | 0～1 个值，以及完成或错误；也可一直未终止 |
| `Flux<T>` | 0～N 个值，以及完成或错误；可为无限流 |
| `Mono<List<T>>` | 最多发射一个列表；列表里面可以有很多元素 |
| `Mono<Void>` | 不发射业务值，只表达成功完成或失败 |

Reactor 不允许通过 `onNext(null)` 发射 null；“没有结果”用空完成表达。

依据：[Mono](https://projectreactor.io/docs/core/release/reference/coreFeatures/mono.html)、[Flux](https://projectreactor.io/docs/core/release/reference/coreFeatures/flux.html)。

## 5. 环境与版本

本系列实验使用 Java 17、`reactor-core:3.8.2` 和 `reactor-test:3.8.2`。独立练习可显式指定两个依赖的同一版本；Spring Boot 项目优先沿用其依赖管理，升级前检查整套兼容性。

```xml
<dependency>
    <groupId>io.projectreactor</groupId>
    <artifactId>reactor-core</artifactId>
    <version>3.8.2</version>
</dependency>
<dependency>
    <groupId>io.projectreactor</groupId>
    <artifactId>reactor-test</artifactId>
    <version>3.8.2</version>
    <scope>test</scope>
</dependency>
```

本地版本证据：AgentScope 1.0.12 的 `agentscope-dependencies-bom/pom.xml` 指定 Reactor BOM `2025.0.2`，其 Core/Test 为 3.8.2。背景见 [[AI项目/AgentScope1.0/interview/09.版本口径与源码核对]]；官方 [3.8.2 API](https://projectreactor.io/docs/core/3.8.2/api/reactor/core/publisher/Flux.html)。

## 6. 练习与自测

1. 为什么 `Mono<List<Order>>` 不是 `Flux<Order>`？前者发射一个列表，后者逐个发射订单。
2. 为什么 `Mono.just(blockingCall())` 仍然阻塞？Java 先求参数，再调用 `just`。
3. 为什么“用了 WebFlux”不等于应用没有阻塞？要追踪数据库、SDK、文件和回调内部的实现。
