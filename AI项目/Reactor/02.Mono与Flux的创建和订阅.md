# 02. Mono 与 Flux 的创建和订阅

> 目标：分清组装、订阅、执行与接收。返回 [[AI项目/Reactor/README]]。

## 1. 三个阶段

```java
Mono<String> task = Mono.fromSupplier(() -> {
    System.out.println("执行 Supplier");
    return "hello";
}); // 组装流程，此处没有执行 Supplier

Mono<String> upper = task.map(String::toUpperCase); // 继续组装
upper.subscribe(System.out::println); // 订阅，执行并收到 HELLO
```

对这个延迟来源来说：创建 Mono → 添加操作符 → 订阅触发执行。不要把这句话扩大到已经启动的 Future、热源或组装时求值的 Java 方法。

## 2. 创建方法怎么选

| 方法 | 用途 | 需要注意 |
|:---|:---|:---|
| `Mono.just(value)` | 包装已经取得的非 null 值 | 参数表达式先执行 |
| `Mono.justOrEmpty(value)` | 将可能为 null 的值转成有值或空完成 | 不会延迟参数表达式 |
| `Mono.fromSupplier(supplier)` | 订阅时取得一个值 | Supplier 返回 null 时空完成 |
| `Mono.fromCallable(callable)` | 订阅时调用，可抛受检异常 | 不会自动切线程 |
| `Mono.defer(factory)` | 每次订阅时创建 Publisher | 回调应返回 Mono，而不是普通值 |
| `Mono.empty()` / `Mono.error(e)` | 表达无值完成/失败 | 两者语义不同 |
| `Mono.fromRunnable(task)` | 执行动作，只关心完成 | 返回 `Mono<Void>` |
| `Flux.just(...)` / `fromIterable(...)` | 从已有元素产生多值流 | 不自动复制可变集合 |
| `Flux.range(start,count)` | 有限整数序列 | 第二个参数是个数 |
| `Flux.interval(duration)` | 定时产生递增 long | 默认无限，练习时加 `take` |

依据：[创建与订阅](https://projectreactor.io/docs/core/release/reference/coreFeatures/simple-ways-to-create-a-flux-or-mono-and-subscribe-to-it.html)、[操作符索引](https://projectreactor.io/docs/core/release/reference/apdx-operatorChoice.html)。

## 3. just 与 defer 的时机

```java
AtomicInteger counter = new AtomicInteger();
Mono<Integer> eager = Mono.just(counter.incrementAndGet()); // 此处加到 1
Mono<Integer> lazy = Mono.defer(() -> Mono.just(counter.incrementAndGet()));

eager.block(); // 1，不再增加
eager.block(); // 仍为 1
lazy.block();  // 2
lazy.block();  // 3
```

`defer` 还适合每次订阅创建独立的累积器，避免多个请求复用同一个可变对象。

## 4. 三种消费方式

### 普通同步边界：block

```java
String result = Mono.just("hello").block(Duration.ofSeconds(2));
```

`block` 自己会订阅，并等待结果；Mono 空完成时返回 null，失败时抛异常。它适合命令行或明确允许阻塞的同步边界，不应放在 WebFlux 的非阻塞事件线程上。

### 应用拥有的回调边界：subscribe

```java
Disposable handle = Mono.just("hello").subscribe(
        value -> System.out.println("收到：" + value),
        error -> System.err.println("失败：" + error.getMessage()),
        () -> System.out.println("正常结束")
);
// handle.dispose(); // 请求取消；外部任务是否停止还取决于来源
```

`subscribe` 返回可取消的句柄，不返回业务结果。它不保证另开线程，也不保证一定等结果后才返回；同步来源可能在方法返回前已经完成。

### 框架拥有的边界：return

```java
public Mono<String> chat(Msg input) {
    return agent.call(input).map(Msg::getTextContent);
}
```

在 Spring WebFlux 控制器中返回 Publisher，由框架订阅和处理 HTTP 响应。服务层通常组合并返回，不自行启动独立订阅。

依据：[订阅 API](https://projectreactor.io/docs/core/release/reference/coreFeatures/simple-ways-to-create-a-flux-or-mono-and-subscribe-to-it.html)、[Mono API](https://projectreactor.io/docs/core/release/api/reactor/core/publisher/Mono.html)。项目用法见 [[AI项目/AgentScope1.0/2.AgentScope Java特性：流式输出、结构化输出、超时与重试、执行控制]]。

## 5. 不要忘记接住新的链

```java
Flux<String> source = Flux.just("a", "b");
source.map(String::toUpperCase); // 返回的新流被丢弃
source.subscribe(System.out::println); // a、b

source.map(String::toUpperCase)
        .subscribe(System.out::println); // A、B
```

操作符通常返回新的 Publisher，而不是原地修改变量。依据：[官方 FAQ](https://projectreactor.io/docs/core/release/reference/faq.html)。

## 6. 两次订阅的代价

```java
Mono<Msg> task = agent.call(input);
task.subscribe(System.out::println);
task.block(); // 再订阅一次，可能再次执行 Agent
```

冷源会为每次订阅重新执行；正在执行的同一 Agent 也可能拒绝第二次并发调用。先确定只需要一次消费，确实需要共享时再设计 `cache` 的范围，见 [[AI项目/Reactor/08.冷热流共享与Sinks]]。

## 7. 自测

- 创建一个 `Mono.fromCallable`，但不订阅：Callable 不执行。
- `Mono.just(null)`：不合法；使用 `justOrEmpty`。
- `Mono.empty().subscribe(v -> ...)`：不会进入接收值的回调，可收到完成信号。
- 在 main 中订阅异步流：要让进程活到任务结束；练习可在最后明确等待，不能据此给服务链随处加 block。
