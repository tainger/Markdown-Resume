# 03. 转换、过滤与聚合操作符

> 目标：先追踪输入输出类型，再判断操作符。返回 [[AI项目/Reactor/README]]。

## 1. map：普通值转换

```java
Mono<Integer> length = Mono.just("Reactor").map(String::length);
Flux<Integer> doubled = Flux.range(1, 3).map(i -> i * 2); // 2、4、6
```

`map` 的回调返回普通值；返回 null 会失败。同步转换抛出的异常会成为链上的错误信号。返回 `Mono` 则得到嵌套类型，异步组合应使用下一章的 `flatMap`。

## 2. filter、handle 与空结果

```java
Flux<Integer> even = Flux.range(1, 6).filter(i -> i % 2 == 0); // 2、4、6

Flux<Integer> parsed = Flux.just("12", "skip", "34")
        .<Integer>handle((text, sink) -> {
            if (!text.equals("skip")) sink.next(Integer.parseInt(text));
        }); // 12、34
```

`handle` 适合同步的筛选与转换，每次回调最多 `next` 一个值，不是用来直接接异步 SDK 回调的入口。

```java
Mono<String> name = Mono.<String>empty().defaultIfEmpty("匿名");
Mono<String> cached = loadCache(key)
        .switchIfEmpty(Mono.defer(() -> loadDatabase(key)));
```

`defaultIfEmpty` 补一个值，`switchIfEmpty` 切换来源。这里的 `defer` 确保备用方法到真正需要时再调用。空完成与失败不同，不能用 `switchIfEmpty` 处理异常。

依据：[操作符选型](https://projectreactor.io/docs/core/release/reference/apdx-operatorChoice.html)、[handle](https://projectreactor.io/docs/core/release/reference/coreFeatures/programmatically-creating-sequence.html)。

## 3. doOnNext：旁观，不替换结果

```java
Mono<String> result = Mono.just("hello")
        .doOnNext(value -> System.out.println("日志：" + value))
        .map(String::toUpperCase);
```

`doOnNext` 适合轻量同步观察。需要等待异步保存完成，就将保存接回主链：

```java
// save(value) 假设返回 Mono<Void>
Mono<String> saved = Mono.just("hello")
        .flatMap(value -> save(value).thenReturn(value));
```

不要用 `.doOnNext(v -> save(v))` 期待自动执行或等待保存；也不要在里面随意 `subscribe()` 形成失去统一错误/取消管理的独立任务。

## 4. then：看完成，不看原来的值

| 写法 | 结果类型 | 含义 |
|:---|:---|:---|
| `source.then()` | `Mono<Void>` | 丢弃值，只保留完成/错误 |
| `source.then(otherMono)` | `Mono<R>` | 前者成功完成，再订阅后者 |
| `source.thenReturn(value)` | `Mono<R>` | 前者成功完成，再发射固定值 |
| `source.thenMany(otherFlux)` | `Flux<R>` | 前者成功完成，再订阅多值流 |
| `source.delayUntil(v -> save(v))` | `Mono<T>` | 等关联流程成功完成，再发射原值 |

```java
Mono<String> done = Mono.fromRunnable(() -> System.out.println("执行动作"))
        .thenReturn("OK");
```

上游失败时，`then` 不会照常执行后续成功步骤；错误会往下传。

**延迟订阅不等于延迟 Java 参数求值。** 如果后续结果要读取运行中累积的状态：

```java
Mono<String> result = Flux.just("A", "B")
        .collect(StringBuilder::new, StringBuilder::append)
        .map(StringBuilder::toString); // 每次订阅独立累积
```

或者使用每订阅一次新建状态的 `defer`，再用 `then(Mono.fromSupplier(...))` 在结束后读取。AgentScope 的对应写法见 [[AI项目/Reactor/11.AgentScope与WebFlux实战]]。

## 5. Flux 聚合后往往变成 Mono

```java
Mono<List<Integer>> list = Flux.range(1, 4).collectList();
Mono<Integer> sum = Flux.range(1, 4).reduce(0, Integer::sum); // 10
Flux<Integer> running = Flux.range(1, 4).scan(0, Integer::sum); // 0、1、3、6、10
Mono<Long> count = Flux.range(1, 4).count(); // 4
```

| 需求 | 操作符 | 边界 |
|:---|:---|:---|
| 全部收集 | `collectList` | 等上游完成；无限源可能永远不返回并持续占内存 |
| 汇总一个结果 | `reduce` | 有初始值与无初始值的空源行为不同 |
| 观察中间汇总 | `scan` | 持续发射中间状态 |
| 第一条 | `next` | 得到第一条后取消上游；空源仍为空 |
| 必须恰好一条 | `single` | 空或多条都失败 |
| 最多一条 | `singleOrEmpty` | 空允许，多条失败 |

依据：[Flux 3.8.2 API](https://projectreactor.io/docs/core/3.8.2/api/reactor/core/publisher/Flux.html)。

## 6. 过滤、截取与分批不是一回事

- `take(n)`：只接收指定数量，达到后取消上游。
- `skip(n)`：跳过前 n 条，不是分页数据库查询。
- `distinct()`：去重可能长期记住历史键；无限流需要考虑状态增长。
- `distinctUntilChanged()`：只去掉相邻重复。
- `buffer(n)`：每 n 条形成一个列表，不会自动落库，也不是背压容量设置。

## 7. 自测

1. `Mono.empty().map(...)` 为什么不调用回调？没有 onNext。
2. `Mono<Void>.flatMap(...)` 为什么后续不执行？没有业务值；使用 `then`。
3. `collectList` 为什么不适合持续聊天事件流？它要等完成，且持续收集占内存。
