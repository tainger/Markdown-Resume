# 04. 异步组合、顺序与并发

> 目标：表达依赖、控制并发，并知道输出顺序是否等于副作用顺序。返回 [[AI项目/Reactor/README]]。

## 1. map 与 flatMap 的分界

```java
// loadUser 返回 Mono<User>，loadOrders 返回 Flux<Order>
Mono<String> name = loadUser(id).map(User::name);
Mono<Account> account = loadUser(id).flatMap(user -> loadAccount(user.id()));
Flux<Order> orders = loadUser(id).flatMapMany(user -> loadOrders(user.id()));
```

看回调的返回类型：普通值 → `map`；单值异步流程 → `Mono.flatMap`；Mono 后接多值流程 → `flatMapMany`。Flux 的 `flatMap` 则可以合并多个内部 Publisher。

## 2. 三种“逐条调服务”写法

假设 `fetch(i)` 返回延迟不同的 `Mono<String>`：

| 写法 | 内部任务何时启动 | 下游结果顺序 | 适合 |
|:---|:---|:---|:---|
| `flatMap(fetch, 4)` | 最多同时订阅 4 个内部流 | 可能交错 | 独立请求、吞吐优先 |
| `concatMap(fetch)` | 前一个完成后再订阅下一个 | 输入顺序 | 有先后依赖的修改 |
| `flatMapSequential(fetch, 4)` | 可并发订阅，结果可能等待缓存 | 输入顺序 | 独立计算且需要按序展示 |

**按序输出不等于按序执行。** `flatMapSequential` 无法保证第三个任务的外部写入发生在第二个之后；需要串行副作用时用 `concatMap` 并确保内部正确表达完成。

```java
Flux<String> ordered = Flux.just(1, 2, 3)
        .concatMap(i -> Mono.delay(Duration.ofMillis(10))
                .thenReturn("结果-" + i));
```

异步内部源允许任务重叠；如果 `fetch(i)` 在返回 Mono 之前就阻塞，`flatMap` 不会自动把那段代码并行化。线程见 [[AI项目/Reactor/05.线程模型与Scheduler]]。

依据：[操作符选型](https://projectreactor.io/docs/core/release/reference/apdx-operatorChoice.html)、[Flux API](https://projectreactor.io/docs/core/3.8.2/api/reactor/core/publisher/Flux.html)。

## 3. 有依赖就 flatMap，没有依赖再考虑 zip

```java
Mono<Detail> dependent = loadUser(id)
        .flatMap(user -> loadAccount(user.accountId()))
        .map(Detail::new);

Mono<Detail> independent = Mono.zip(loadUser(id), loadSettings(id))
        .map(tuple -> new Detail(tuple.getT1(), tuple.getT2()));
```

`zip` 需要各来源贡献一个值；它组合订阅，不自动保证使用多个线程。对异步来源，等待可以重叠。

## 4. zip 与 Mono<Void> 的空值陷阱

```java
// saveA/saveB 都返回 Mono<Void>
Mono<Void> both = Mono.when(saveA(), saveB());
Mono<String> result = both.thenReturn("全部保存完成");
```

`Mono.zip(saveA(), saveB())` 无法得到两个业务值，因为 Void 流不发射值；空源还可能让 zip 提前完成、取消其他源，不能依靠它确保所有动作都被执行。

`Mono.when` 用于协调成功完成；任一失败时通常传播失败并取消其他来源，仍然不提供数据库事务保证。确实要等所有结束后再汇报失败，可研究 `whenDelayError`，并明确部分成功如何补偿。

依据：[zip 空源 FAQ](https://projectreactor.io/docs/core/release/reference/faq.html)。

## 5. 多个流如何合并

| 操作符 | 行为 |
|:---|:---|
| `concat(a,b)` | a 完成后再订阅 b |
| `merge(a,b)` | 同时合并，按实际到达顺序发射 |
| `zip(a,b)` | 逐个配对，受较短流限制 |
| `combineLatest(a,b)` | 各方至少有值后，任一更新就组合最新值 |
| `switchMap(query -> search(query))` | 新查询到来时取消旧内部流的订阅 |

`switchMap` 适合搜索输入，取消旧订阅也不能撤销已经提交的扣款或数据库写入。

## 6. 并发额度放在哪里

```java
Flux<Result> results = Flux.fromIterable(ids)
        .flatMap(id -> callRemote(id), 8);
```

这里的 8 是**本次订阅内同时订阅内部流的上限**，不是全应用限流器，也不是每秒 8 次。100 个用户各自运行这条链，理论上可同时存在更多外部请求；还要结合连接池、全局并发控制和下游配额设计。

默认 prefetch、结果缓存及来源内部队列也会影响内存；单设 concurrency 不能说明整个系统已经有界。

## 7. 自测

1. 三个扣款必须有序：优先 `concatMap`，并由外部系统提供事务/幂等保证。
2. 三个独立查询希望按原顺序显示：考虑 `flatMapSequential`。
3. 两个无返回值保存只等完成：使用 `when`，不是 zip。
4. Hook 返回 Mono 为什么用 flatMap？这样能将完成、错误和取消接回调用链。
