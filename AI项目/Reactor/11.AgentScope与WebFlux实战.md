# 11. AgentScope 与 WebFlux 实战

> 目标：用 Reactor 类型和生命周期读懂 ReActAgent。版本固定 AgentScope Java **v1.0.12 / b9080f27**，不混入 2.0。返回 [[AI项目/Reactor/README]]。

## 1. 三个入口不要混淆

| 入口 | 类型 | 输出语义 |
|:---|:---|:---|
| `agent.call(msg)` | `Mono<Msg>` | Agent 最终回复 |
| `agent.stream(msg,options)` | `Flux<Event>` | Agent 的推理、工具、总结等事件 |
| `model.stream(messages,tools,options)` | `Flux<ChatResponse>` | 模型响应片段，由上层进一步累积 |

模型开启 stream 不代表调用者一定使用 `Flux<Event>`；`call` 内部也能消费模型片段，最终只返回一个 Msg。来源：[[AI项目/AgentScope1.0/2.AgentScope Java特性：流式输出、结构化输出、超时与重试、执行控制]]、[[AI项目/AgentScope1.0/8.AgentScope Java中ReactAgent的实现原理]]。

## 2. call 在订阅时进入执行

本地 `AgentBase.call` 使用 `Mono.using`：订阅时获取执行资格 → PreCall → doCall → PostCall → 清理执行状态。

```java
Mono<Msg> response = agent.call(input); // 定义本次调用
Msg result = response.block();         // 命令行同步边界订阅并等待
```

再 subscribe/block 一次可能再执行；同一实例正在运行时，默认运行检查还可能拒绝第二次并发调用。Reactor 允许组合并发，不等于该有状态 Agent 支持多请求同时修改 Memory。

## 3. reasoning 的类型变化

下面是说明性简化，省略中断、事件和错误分支：

```java
return checkInterruptedAsync() // Mono<Void>：通过检查后完成
        .then(notifyPreReasoningEvent(prepareMessages())) // Mono<PreReasoningEvent>
        .flatMapMany(event -> model.stream(
                event.getInputMessages(), toolkit.getToolSchemas(), options))
        .doOnNext(chunk -> context.processChunk(chunk)) // Flux<ChatResponse>
        .then(Mono.defer(() -> Mono.justOrEmpty(context.buildFinalMessage())))
        .flatMap(this::notifyPostReasoning); // Mono<PostReasoningEvent>
```

读法：前置检查 → 推理前 Hook → 模型片段流 → 累积状态 → 流结束后生成完整 Msg → 推理后 Hook。真实方法后面继续根据事件决定返回最终 Msg 还是进入工具执行。

`then` 丢弃片段值，不代表片段没被消费；`doOnNext` 已更新累积器。`defer` 确保生成最终消息时读取的是已累积状态，而不是组装链时的空状态。

源码：[ReActAgent.reasoning](</Users/rocky/study/profile/Markdown-Resume/AI项目/AgentScope1.0/repo/agentscope-java/agentscope-core/src/main/java/io/agentscope/core/ReActAgent.java:460>)。

## 4. 自定义业务链优先保持组合

```java
// saveAsync 返回 Mono<Void>
Mono<Msg> result = agent.call(input)
        .flatMap(reply -> saveAsync(reply).thenReturn(reply));
```

这样响应的完成包括保存完成，保存失败会进入同一错误链；如果在 doOnNext 内裸 subscribe 保存，主链可能提前返回，取消和 Context 也未必自动关联。

框架有些流式 chunk 通知本身采用独立订阅；那是要核对的实现边界，不能据此给所有业务回调都照搬 subscribe。来源：[[AI项目/AgentScope1.0/7.AgentScope Java特性：Hook]]、[[AI项目/gogo-agent/27.基于Reactor Context 实现多智能体之间的会话上下文传递]]。

## 5. WebFlux 返回单次结果

```java
@PostMapping("/chat")
public Mono<String> chat(@RequestBody ChatRequest request) {
    ReActAgent agent = createAgentForSession(request.sessionId());
    Msg input = Msg.builder().role(MsgRole.USER).textContent(request.text()).build();
    return agent.call(input).map(Msg::getTextContent);
}
```

这是接入结构示例，`ChatRequest`、会话管理和身份校验由应用实现；若创建、加载会话或 Agent 内 Hook 存在阻塞，还需对这些边界做 Scheduler 隔离。不要把示例当成完整可部署接口。

## 6. WebFlux 返回流式事件

```java
@PostMapping(value = "/chat/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<Event> stream(@RequestBody ChatRequest request) {
    ReActAgent agent = createAgentForSession(request.sessionId());
    Msg input = Msg.builder().role(MsgRole.USER).textContent(request.text()).build();
    StreamOptions options = StreamOptions.builder()
            .eventTypes(EventType.REASONING, EventType.TOOL_RESULT)
            .incremental(true)
            .includeReasoningChunk(true)
            .includeReasoningResult(false)
            .build();
    return agent.stream(input, options);
}
```

这里直接返回事件供编码器处理；不把全部事件 collectList，也不主动 subscribe。增量/累积模式会影响前端拼接方式；最终 Agent 结果事件需按 StreamOptions 显式选择，不能把所有事件都当成可追加的正文 token。

HTTP 响应提交后，后续失败不一定还能改成另一个状态码，应预先约定流内错误展示和连接结束语义。依据：[WebFlux 返回值](https://docs.spring.io/spring-framework/reference/web/webflux/controller/ann-methods/return-types.html)。

## 7. HTTP 断开不等于模型已停止

本地 `AgentBase.createEventStream` 在 `Flux.create` 内独立 subscribe 了 Agent 调用，并显式传回 Context；静态看该桥未把返回 Disposable 直接注册到 sink 的取消/释放回调。因此不能仅凭外层 Flux 被取消就声称内部 Agent/SDK 已取消。

同一段使用 BUFFER，也不能声称慢客户端已经受到有界保护。这些是版本特定的待验证边界，不是本教程已修复的行为。
