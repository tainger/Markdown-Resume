## 2. 实验覆盖

| 实验 | 观察重点 |
|:---|:---|
| 延迟来源与重复订阅 | 未订阅不执行；两次订阅得到两次执行 |
| just 提前求值 | 组装时已计算，订阅只发射捕获值 |
| map / flatMap | 普通转换与异步组合 |
| Void 与 then | 无 onNext 时 flatMap 不执行，then 可接完成 |
| zip 空源 / when | 值组合与完成协调不同 |
| concatMap / flatMap / flatMapSequential | 串行、有序输出、交错执行的区别 |
| 受控需求 | 初始需求为零，按 request 才发值 |
| 异常恢复范围 | 失败替换后不恢复原始未处理元素 |
| 重试 | 重新订阅，次数包含初次 |
| 超时 | 虚拟时间触发超时错误 |
| defer 构造最终消息 | 等 chunk 累积后再读取结果 |
| Context | 下游写、上游读；线程切换后可访问 |
| 订阅级状态 | 两次订阅独立累积，不共享 StringBuilder |
| 取消与资源清理 | cancel 信号及 using 的释放行为 |
| 缓存 | 重放正常值，也可重放错误 |
| 有限 Sinks 重放 | 晚订阅只拿有限历史 |
| 备用分支 | 用 PublisherProbe 证明真的订阅了 fallback |
| buffer/window | 列表分批与子流窗口 |
| 调度线程 | 阻塞适配模式将 Callable 安排到 boundedElastic |

## 4. 面试自测：先口述，再对照

1. **Mono 和 Flux 的区别？** 发射基数不同；都表达信号与生命周期，不等于已取得的对象/集合。
2. **Mono<List<T>> 与 Flux<T>？** 一次发一个列表与逐个发值，消费时机和内存不同。
3. **为什么没有订阅就没执行？** 对延迟冷源，工作在订阅时启动；just 参数和热源是重要边界。
4. **subscribe 会开线程吗？** 不必然，线程来自具体源或 Scheduler。
5. **map 与 flatMap？** 普通值转换与 Publisher 组合；别构造不需要的嵌套 Mono。
6. **concatMap 与 flatMapSequential？** 前者逐个订阅执行；后者可并发执行但按输入顺序发结果。
7. **Mono<Void> 后面为什么 flatMap 不执行？** 没有 onNext，使用 then 协调完成。
8. **zip 能组合两个保存操作吗？** 若都为 Void，改用 when；when 也不保证事务原子性。
9. **subscribeOn 与 publishOn？** 订阅/源工作调度与该点下游信号处理调度，要结合异步源分析。
10. **如何接阻塞 SDK？** fromCallable + 适合阻塞的 Scheduler，并设计超时、并发和取消。
11. **背压与限流？** request 表达需求额度，不是每秒配额；来源不减速时必须明确缓冲或过载策略。
12. **retry 会做什么？** 重新订阅，可能重复请求、输出和副作用。
13. **doOnError 能恢复吗？** 不能；恢复看 onErrorResume/onErrorReturn 的范围。
14. **Context 跟着线程吗？** 跟着 Subscriber，contextWrite 影响上游；跨独立订阅需要桥接。
15. **HTTP 断开会自动停止 LLM 吗？** 需验证取消是否贯穿适配器和 SDK，不能只看返回类型。
16. **cache 为什么会缓存失败？** 缓存的是终止/数据信号，应设计错误 TTL 与作用域。
17. **doFinally 能等待异步清理吗？** 不能把回调中的 Publisher 自动组合进主链；研究 usingWhen。
18. **怎样不用等待一小时测试一小时计时器？** withVirtualTime，在 Supplier 内创建相关定时流程。
19. **groupBy 为什么会挂住？** 组未及时消费与缓存/并发额度可能互相阻塞。
20. **如何读懂 Agent reasoning？** 沿 Mono 前置事件 → Flux 模型片段 → Mono 最终结果追踪类型。

这些答案是答题骨架；完整边界与官方来源分别见前十二章。测试依据：[官方 Testing](https://projectreactor.io/docs/core/release/reference/testing.html)。
