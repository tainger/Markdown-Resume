# ✅Harness工程——分层记忆体系

差旅 Agent 的对话有鲜明的"记忆半径"差异：

- **同一次请求内**：查询用户去上海的住宿标准，同一个会话里可能反复用到这个结果，没必要每次都查业务库。
- **同一会话内**：用户先问"帮我规划北京行程"，再问"刚才说的酒店太贵了"，模型必须记得前面对话。
- **跨会话长期**：用户偏好"always 选国航、靠窗座位、不早于 8 点起飞"，应该在每次规划时自动召回。

如果全部塞进同一份"聊天记录"，要么 token 爆炸，要么长期偏好被短期噪声淹没。gogo-agent 因此把记忆拆成三层：

| 层级 | 名称 | 生命周期 | 存储介质 | 作用 |
| --- | --- | --- | --- | --- |
| L1 | 请求级缓存 | 单次请求 | JVM 堆内存 | 缓存工具结果（政策、用户信息、差旅单 ID），避免同请求内重复查库 |
| L2 | 会话级短期记忆 | 单次会话 | MySQL + AutoContextMemory | 多轮对话历史、Agent 运行状态，支持中断恢复 |
| L3 | 用户级长期记忆 | 跨会话 | 百炼记忆库 + Redis 缓存 | 旅行偏好画像，跨会话长期可用 |
