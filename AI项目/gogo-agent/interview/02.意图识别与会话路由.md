# 意图识别与会话路由

> 答题骨架：为什么分层 → 命中条件 → 歧义放行 → 上下文 → 路由例外。返回 [[AI项目/gogo-agent/interview/README]]。

## Q09｜L0/L1/L2/L3 分别做什么？

**口述答案**：L0 是疑似多意图的结构守卫，L1 是内存关键词/正则规则，L2 是意图样本的向量语义检索，L3 是 LLM 兜底。先用低成本规则处理明确表达；规则漏掉但语义接近样本的交给向量层；复合请求、低分或歧义交给模型。`route()` 只实现快路径，返回空由外层决定调用 L3。

**追问**：L0 是第四个分类模型吗？不是，它是放行慢路径的启发式检查，不产生完整意图分类。

**边界**：日志里的 L1 50ms、L2 100ms 是软目标/告警阈值。L2 需要远程向量嵌入 Embedding，不是纯本地查询，也没有本次实测延迟。

## Q10｜L1 如何避免“你好，帮我订机票”被当成寒暄？

**口述答案**：寒暄规则锚定整句，只有问候/礼貌词及允许分隔符组成的句子才命中。业务规则配负向词和优先级，例如“报销政策”要走政策查询，而不是报销动作。规则对整句及子句求值，跨目标 Agent 多类命中时返回 `AMBIGUOUS`，避免单规则抢走其他任务。

**追问**：同一个目标 Agent 内多类命中呢？当前按规则顺序取优先项，所以它是路由优化，不能说成保留了所有细粒度业务意图。

**易错点**：关键词命中不是用户授权，例如“订机票”可能仍只是搜索阶段，预订还要看方案确认和业务条件。

**依据**：[[AI项目/gogo-agent/13.基于规则的L0-L1意图识别详解]]、[[AI项目/gogo-agent/15.L1-L2意图识别针对多意图的支持]]；[IntentRuleMatcher.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/intent/IntentRuleMatcher.java:111>)、[IntentRuleMatcher.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/intent/IntentRuleMatcher.java:232>)。

## Q11｜L2 的阈值和 Top-2 margin 怎么解释？

**口述答案**：检索 Top-2 样本，当前构造默认 top-1 分数至少 `0.75` 才是候选命中；若第二条属于不同意图，且分差小于 `0.05`，保守放行 L3。分数高且领先竞争意图才短路，避免“同时像两类”被误当成明确单意图。

**追问**：0.75 是 75% 正确率吗？不是，它是检索相似度阈值；还要核对向量库的评分定义，再用标注数据衡量准确率。Top-2 同类也不代表已检查所有其他类别。

**边界**：注释提到的阈值配置不能当成已接入；当前装配直接调用默认构造，未看到读取该阈值配置。调参应在独立验证集上验证误路由率与兜底比例。

**依据**：[[AI项目/gogo-agent/14.基于RAG的L2意图识别详解]]、[[AI项目/gogo-agent/19.引入L1-L2之后意图识别不准确问题修复]]；[IntentVectorMatcher.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/intent/IntentVectorMatcher.java:89>)、[IntentRouterKnowledgeConfig.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/config/IntentRouterKnowledgeConfig.java:110>)。

## Q12｜“查一下机票，顺便看看景点”怎么避免丢半个任务？

**口述答案**：先用 L0 检查句长、强连词及连词位置，疑似复合句直接跳过 L1/L2；L1 子句级命中多个目标 Agent 也跳过 L2；L2 再用异类 Top-2 margin 兜底。最后由 L3 输出多意图结构，Master 根据任务依赖安排对应子 Agent。

**追问**：为什么不对每个子句独立跑 L1 后直接执行？子句存在否定、指代和依赖，机械切句容易把条件当任务。当前守卫只负责降低丢意图风险，真正拆解交给模型。

**边界**：启发式不保证识别所有复合句。应加入无连词、多否定、跨句指代和同 Agent 多意图的测试样本。

**依据**：[[AI项目/gogo-agent/15.L1-L2意图识别针对多意图的支持]]、[[AI项目/gogo-agent/16.单次对话多意图识别与执行]]；[IntentRecognitionRouter.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/intent/IntentRecognitionRouter.java:131>)、[IntentVectorMatcher.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/intent/IntentVectorMatcher.java:128>)、[master-agent-system.md](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/resources/prompts/master-agent-system.md:1>)。

## Q13｜问题改写拿哪里的历史，为什么不只拿当前 Agent 的 Memory？

**口述答案**：跨 Agent 的用户可见对话在 `chat_message` 中；改写前读取最近 10 条，拼入本轮输入，用于消除“那里”“那个方案”等指代。每个 Agent 的运行 Memory 按名称隔离，只看某个子 Agent 的历史可能不知道上一轮另一个 Agent 查询出的目的地。

**追问**：取最近 10 条就不会丢上下文吗？会，旧事实可能被窗口截掉；也要检查本轮消息是否重复、历史顺序是否正确。改写结果应该补充已有事实，不能凭空填日期和订单号。

**边界**：快路径命中会跳过改写，因此快路径准确性和 Master 协调上下文仍然重要。

**依据**：[[AI项目/gogo-agent/11.通过问题改写融合多轮对话]]、[[AI项目/gogo-agent/17.意图识别与问题改写的流水线编排]]；[AgentPipelineService.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/service/AgentPipelineService.java:91>)、[AgentPipelineService.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/service/AgentPipelineService.java:623>)。

## Q14｜为什么高置信单意图也经过 Master？

**口述答案**：曾尝试让少数意图直跳子 Agent，但跨 Agent 切换时子 Agent 不一定持有上轮的业务事实，例如从“查询出差地点”切换到“那里天气怎样”。当前普通意图分发的直跳调用已注释，仍由 Master 依据意图和自身上下文构造委派任务。

**追问**：什么场景可以直跳？请求自包含、无需历史，或者有可验证的结构化共享状态时可以考虑。要比较的是省掉一次协调调用与上下文损失风险。

**易错点**：不能说 Master 能保证所有历史完整；其上下文也可能被压缩。能确认的是当前选择了统一协调路径。

**依据**：[[AI项目/gogo-agent/20.用户意图很明确时，直接路由给子智能体还是主智能体]]；[AgentPipelineService.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/service/AgentPipelineService.java:206>)。

## Q15｜用户只说“确认”“继续”时如何路由？

**口述答案**：聊天入口读取 `ActiveAgentSessionStore`，只有存在活跃 Agent 且命中 continuation 信号时才走续聊。若是业务子 Agent，Executor 直接调用；若是 Master/分析类 Agent，则按 Pipeline 的对应分支处理。没有命中续聊时回到普通识别链路。

**追问**：和点击 ask_user 表单提交一样吗？不一样。表单提交通过 `/respond` 回传 `toolUseId`，构造工具结果恢复挂起位置；普通“确认”是用户消息续聊。

**边界**：短确认词不天然包含明确授权对象，应绑定最新待确认任务和有效期；当前词表匹配不能视为严密业务确认状态机。

## Q16｜怎么评测意图识别，而不只看命中率？

**口述答案**：先按单意图、多意图、续聊指代、否定/歧义建立标注集，统计每层覆盖率、误路由率、多意图召回与各层延迟。阈值提升可能减少误判但增加模型调用；必须连同任务成功率、总延迟与成本一起看。种子样本用于构建索引，验证集要包含独立改写表达。

**现有证据**：已有规则、向量匹配、路由守卫和种子语料测试；语料测试还检查样本与 L1 规则的重叠。测试文件存在不等于本次已运行，更不等于线上评测通过。

**待补**：⚠️ raw 缺失，待补充：统一评测数据集、混淆矩阵、线上各层命中比例与分位延迟。此题的评测方案是建议。
