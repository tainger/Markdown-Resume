# 上下文工程与 RAG

> 答题骨架：状态分层 → 传播机制 → 降低重复输入 → 知识检索 → 一致性与信息损失。返回 [[AI项目/gogo-agent/interview/README]]。

## Q33｜chat_message、Agent Memory、长期记忆和 RAG 有何区别？

**口述答案**：`chat_message` 保存用户可见对话，用于历史展示和跨 Agent 改写上下文；Agent Memory 保存包含工具调用/结果的执行上下文，经 Session 持久化；长期记忆保存用户旅行偏好，跨会话召回；检索增强生成 Retrieval-Augmented Generation（RAG）提供政策、指南和景点等领域知识。候选与方案又属于任务中间数据，放 Redis，不能混成一个“聊天记忆库”。

**追问**：聊天记录能直接恢复挂起工具吗？不够，它没有完整工具调用链、pending 状态等执行信息，需要 Agent Session 与挂起元数据配合。

**易错点**：记忆摘要和检索结果都可能不完整，订单号、确认状态等关键业务事实应有结构化权威来源。

## Q34｜为什么同时使用 ThreadLocal、Reactor Context 和 ToolExecutionContext？

**口述答案**：它们服务三个阶段。ThreadLocal 给同步创建 prototype Agent 时的 `build()` 读取上下文；Reactor Context 跟随订阅链，在异步 Hook 中读取；ToolExecutionContext 保存已捕获的会话对象，供工具形参注入。子 Agent provider 延迟创建时，用 `AgentSessionContextHolder.bind` 捕获并临时绑定上下文，执行完还原。

**追问**：为什么不能只用 ThreadLocal？执行发生在线程切换后，原线程的值不会自动跟过去，线程复用还可能串请求；入口 `finally.clear()` 必须清理。Reactor Context 也不是 JVM 全局上下文。

**边界**：框架内部另起裸 `subscribe()` 的 chunk 回调可能丢 Context，项目进度 Hook 用 Agent ID 到 sessionId 的映射回退。

**依据**：[[AI项目/gogo-agent/26.多智能体之间的上下文传递方式]]、[[AI项目/gogo-agent/27.基于Reactor Context 实现多智能体之间的会话上下文传递]]、[[AI项目/gogo-agent/35.多智能体上下文参数传递遇到的坑]]；[AgentSessionContextHolder.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/context/AgentSessionContextHolder.java:31>)、[SessionReactorContext.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/context/SessionReactorContext.java:1>)、[ProgressNotifierHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/hook/ProgressNotifierHook.java:193>)。

## Q35｜自动压缩什么时候发生？有什么风险？

**口述答案**：`AgentMemoryFactory` 配置单条大负载阈值 4×1024 字符、卸载预览 300 字符、上下文 token 上限 128×1024、比例 0.75、消息阈值 60、最近保留 20 条，并配合 `AutoContextHook`。框架据这些配置压缩/卸载；大负载卸载与调用模型生成摘要是不同动作，后者会额外消耗模型调用。

**追问**：保留 20 轮吗？是最近 20 条消息，包含工具消息，不能等同于 20 轮用户对话。4KB 也不宜说成 4096 token。

**边界**：压缩会损失细节；重算/预订应从候选库或方案库取数据。此处核对的是项目配置，未验证框架所有策略的触发次序和运行效果。

**依据**：[[AI项目/gogo-agent/98.上下文工程——记忆自动压缩]]；[AgentMemoryFactory.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/memory/AgentMemoryFactory.java:39>)、[ItineraryPlanAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/ItineraryPlanAgent.java:106>)。

## Q36｜工具返回怎么瘦身？为什么只改 ToolResultBlock 不够？

**口述答案**：`CliResultCompressHook` 在工具结果回填 Memory 前处理 JSON，删除重复的 structuredContent、空值和指定冗余字段，再紧凑序列化；保留有意义的 0 和 false。它不仅替换 `ToolResultBlock`，还重建 `toolResultMsg`，因为框架最终写入 Memory 的是后者，只改前者可能让后续上下文仍然膨胀。

**追问**：删除 structuredContent 一定无损吗？当前逻辑在 content 非空时删，不能证明两个字段永远等价。需要供应商响应契约测试，确保外部单号、价格等关键字段未被删掉。

**易错点**：压缩日志里的字符差不能直接当 token 或费用节省，更不能称为已测得固定百分比收益。

**依据**：[[AI项目/gogo-agent/100.上下文工程——工具返回内容裁剪]]、[[AI项目/gogo-agent/104.上下文工程——工具返回用摘要代替完整内容]]；[CliResultCompressHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/hook/CliResultCompressHook.java:86>)。

## Q37｜Skill 延迟加载和正文折叠有什么作用？

**口述答案**：Skill 说明可能很长，太早加载会在每轮推理重复发送。规划提示词要求开始搜索时才加载搜索技能；`SkillContentCollapseHook` 在技能结果后已有至少 10 条消息时，把本轮模型输入中的正文替换为可重新加载的提示。Memory 原文不变，所以折叠是输入视图优化。

**追问**：为什么不直接从历史里删掉？后续可能需要恢复命令说明，输入视图折叠更容易重新取回。但模型仍可能反复加载，因此要观察加载次数与失败率。

**边界**：10 是消息数；折叠不是权限控制，也不代表当前每个历史技能都已经安全失效。

**依据**：[[AI项目/gogo-agent/99.上下文工程——如何对第三方Skill瘦身]]、[[AI项目/gogo-agent/101.上下文工程——Skill正文折叠（选学）]]；[SkillContentCollapseHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/hook/SkillContentCollapseHook.java:54>)、[itinerary-plan-agent-system.md](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/resources/prompts/itinerary-plan-agent-system.md:64>)。

## Q38｜为什么把动态时间移到第二条 SYSTEM 消息？

**口述答案**：长期稳定的系统指令放在第一条，当前时间由 `DynamicTimeInjectionHook` 在每轮推理前放到后面的独立 SYSTEM 消息，以减少动态内容对共同前缀的破坏。项目还设置 `cacheControl(true)` 请求模型侧缓存支持。这样提高前缀复用机会，同时保留日期推断所需时间。

**追问**：开启 cacheControl 就保证命中吗？不保证，还取决于服务商与模型支持、相同前缀长度、请求间隔等。验证应查看实际命中 token、费用和延迟，不能仅凭配置声称收益。

**边界**：该 Hook 在多个业务子 Agent 中挂载，不能说所有模型调用都采用相同模板。当前知识只描述本地实现，不引用教程中的计费折扣作现行价格。

**依据**：[[AI项目/gogo-agent/105.上下文工程——优化系统提示词利用KV缓存]]、[[AI项目/gogo-agent/107.上下文工程——上下文缓存（选学）]]；[DynamicTimeInjectionHook.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/hook/DynamicTimeInjectionHook.java:53>)、[ItineraryPlanAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/ItineraryPlanAgent.java:117>)。

## Q39｜长期偏好记忆如何隔离、缓存和更新？

**口述答案**：工厂按用户构建百炼长期记忆，Agent 通过 AGENT_CONTROL 模式自主召回/记录。召回结果缓存到 `ltm:travel-pref:{userId}`，默认 1800 秒；记录成功后主动删除缓存，Redis 异常时尝试回源，百炼检索失败返回空结果。用户维度隔离与会话 Memory 隔离是两件事。

**追问**：用户级缓存够精确吗？`retrieve(msg)` 与查询相关，但缓存键只有 userId，不含查询。当前假设偏好画像可以复用；若不同查询需要不同切片，可能返回不匹配的召回结果，宜改存完整画像或增加查询/版本维度。

**边界**：删除缓存加 TTL 不是强一致保证，仍可能出现并发旧检索回填；空串不缓存也可能反复回源。以上属于改进分析。

## Q40｜RAG 与结构化政策工具为什么同时存在？切分修过什么问题？

**口述答案**：InfoAgent 的 AGENTIC RAG 用于政策解释、指南和景点等文本问答，数值合规仍由结构化政策服务提供。政策/指南 DOCX 用 `FixedWordReader` 按段落切分，当前配置 chunkSize 分别为 400/500 字符、overlap=0、表格独立；向量模型 text-embedding-v4 配置 1024 维并与 InMemoryStore 一致。景点使用百炼知识库。

**追问**：WordReader 修复点是什么？保留 Word 空段落形成双换行，使段落切分能识别已有边界；它不保证所有文档都具备空段落，也不等于按标题语义切分。

**边界**：原文解释与政策表可能不一致，需版本/生效时间对齐。当前未展示混合检索、重排或召回评测，不将它们写成已实现；`Resource.getFile()` 的打包 JAR 兼容性也需验证。
