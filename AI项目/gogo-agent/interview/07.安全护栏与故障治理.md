# 安全护栏与故障治理

> 答题骨架：先说代码已做什么，再说覆盖范围，最后给针对性的改进和验证。返回 [[AI项目/gogo-agent/interview/README]]。

## Q49｜第三方 API Key 怎么让 Agent 使用，又不让它自己管理密钥？

**口述答案**：模型生成业务命令，`AbstractShellApiKeyHook` 在 PreActing 阶段按命令类型识别供应商，再用会话用户查询 ApiKeyService，把凭据注入实际命令。数据库和 Redis 中缓存的是密文，Redis 未命中回数据库，默认缓存 7 天。这样常规业务提示词不需要写每个用户的密钥。

**追问**：Hook 注入就保证模型永远看不到吗？不能。注入后的工具入参、调试日志、用户输入密钥及后续 Memory 都需要审计，不能仅凭注入位置作保证。

**边界**：保存密钥本身仍经过工具/对话入口，不能把“少让模型处理凭据”说成严格的全程密钥隔离。

## Q50｜项目的密钥加密都统一成 AES-GCM 了吗？

**口述答案**：没有，要区分实际调用路径。通用 `SecretCipher` 实现 AES-256-GCM，使用随机 12 字节 IV 并做认证校验；但 `ApiKeyService` 仍自己实现 AES-128-ECB/PKCS5Padding。两者共用配置密钥来源，不代表加密模式统一。不能看到新组件就推断旧路径已迁移。

**追问**：你会如何整改？建议统一凭据加密服务，密文带算法和密钥版本，先兼容读取旧值再迁移写入；配置密钥由部署环境提供，并制定轮换与失效策略。属于改进方案，当前未完成迁移。

**边界**：加密存储、文本脱敏和用户权限是三项不同能力；不能互相替代。

**依据**：[[AI项目/gogo-agent/61.如何实现API KEY的动态管理与加密、脱敏]]、[[AI项目/gogo-agent/111.隐私保护——全链路敏感信息脱敏]]；[SecretCipher.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/config/sensitive/SecretCipher.java:36>)、[ApiKeyService.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/apikey/service/ApiKeyService.java:156>)。

## Q51｜CLI 默认把登录信息写到公共目录，多用户怎么办？

**口述答案**：`RghUserIsolationHook` 为用户指定隔离的 CLI 工作目录，并在命令执行时投影用户环境。Redis Token 存储是跨节点权威源：有 Token 则投影到本地，无 Token 删除本地残留；命令后发现 Token 变化再写回，登出清两处。OAuth 登录用后台 watcher 等待用户授权，避免单次工具调用一直阻塞。

**追问**：这是不是完整多租户沙箱？不是，它主要隔离该 CLI 的状态目录；同机 Shell、读写工具和进程权限仍要单独控制。

**边界**：Hook 存在不代表所有第三方 CLI 都按同样方式处理，也不代表本地临时文件完全无依赖。

## Q52｜Shell 命令白名单为什么不等于安全沙箱？

**口述答案**：项目用 `ShellCommandTool` 限制命令集合，减少模型随意调用。但规划白名单含 bash、node、curl、env，并开启读写文件能力；通用解释器能执行的行为远多于命令名，不能证明文件、网络和进程已受隔离。提示词“不要执行危险操作”也只是软约束。

**追问**：如何让护栏更可信？建议优先改结构化业务工具；确需运行命令时用参数数组，明确目录与网络边界，使用低权限身份、资源限制和独立执行环境，并做超时/终止测试。

**边界**：这是从配置推导的风险分析，未在本任务尝试绕过白名单，也未修改源码部署。

## Q53｜全链路脱敏做了什么，还有什么缺口？

**口述答案**：`SensitiveMasker` 用正则定位手机号、证件号、银行卡、邮箱、密钥等，再交给统一策略打码。最终回复、错误和部分进度事件调用它，日志有专门转换器。但 HITL 只处理 question，保留 options/default_value/fields 原值以保持交互语义，不能把“全链路”理解成所有出口无遗漏。

**追问**：先打码再下单行不行？真实执行可能需要完整证件和联系方式，应区分受控执行数据与展示/日志数据，避免把打码值送到供应商。另一方面，展示中保留原值也必须逐字段判断必要性。

**边界**：流式碎片可能把敏感串拆开，逐 chunk 正则不能天然识别；需要跨片段检测或推送前缓冲，并核对持久历史及工具参数日志。

## Q54｜工具并行和重试怎么配置？哪些操作不能盲目重试？

**口述答案**：规划与预订的 Toolkit 都设置 parallel=true，允许同轮独立调用并行；BaseSubAgent 默认最多 3 次尝试（含首次）、初始退避 3 秒、单工具 1 分钟，仅 IOException 满足重试条件；规划改为 3 分钟，Master 另配 15 分钟/3 次。依赖数据的调用仍要顺序执行。

**追问**：供应商返回 `success=false` 会重试吗？如果表现为正常工具返回，而非匹配的异常，就不一定触发框架重试。`retryOn` 类型判断也不能代替完整错误分类。

**边界**：有副作用的下单超时需先查状态，再决定重试；框架重试配置不自动赋予供应商请求幂等性。

**依据**：[[AI项目/gogo-agent/85.工具并行执行&失败重试]]；[BaseSubAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/BaseSubAgent.java:196>)、[ItineraryPlanAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/ItineraryPlanAgent.java:112>)、[MasterAgent.java](</Users/rocky/study/profile/Markdown-Resume/AI项目/gogo-agent/repo/gogo-agent/src/main/java/com/gogo/travel/agent/MasterAgent.java:134>)。

## Q55｜工具熔断怎么让模型停止反复调用失败能力？

**口述答案**：Hook 在 PostActing 统计受监控工具的失败，达到阈值后从工具组卸载，使模型下一轮看不到；PreReasoning 根据共享 Redis 状态同步可用性。冷却后重新加入做半开探测，成功清状态，失败延长冷却。Redis 用 Lua 把计数/状态更新与过期时间组合成原子步骤。

**追问**：监控所有工具吗？不是。配置类初值关闭，当前 application 默认用环境变量开启，白名单默认 `query_weather,query_destination_news`；还需要工具注册在对应组中。不要把它讲成所有 MCP/CLI/业务写入都受保护。

**边界**：实际失败识别字符串是 `Tool execution failed`，不是注释所写的 `[ERROR]`；业务 JSON 失败可能漏计。半开期未见全局单探测锁，不能说只有一个请求放行。

## Q56｜外部网页、RAG 和 Skill 返回恶意指令怎么办？

**口述答案**：这些是外部数据来源，不能凭内容里的“系统命令”提升权限。当前项目有职责提示词、工具白名单、服务端身份和部分归属校验，但不能据此宣称实现完整提示注入防御。工具执行前应独立校验资源、允许动作和确认凭据，不让模型输出成为授权依据。

**追问**：如何验证？建议构造网页/检索段落夹带跨用户单号、跳过审批或要求读取凭据的样例，检查实际工具调用是否被服务端拒绝；同时验证正常查询不被误伤。

**待补**：⚠️ raw 缺失，待补充：项目注入攻击样本集、隔离测试报告与权限回归结果。这是防御建议，不是已验证成果。
