# know-engine 面试题集

> 10 个模块，96 道主问题，包含参考答案、验证方法、追问、来源双链和源码定位。面向 Java 技术栈（LangChain4J + ES + Redis + MySQL + MinerU + XXL-JOB）；更新于 2026-10-21（已对 repo/know-engine 源码全量校核）。

## 怎么复习

- **基础必答**：先刷 01 Q1/Q2、03 Q1/Q2/Q6、05 Q1，能用自己的话讲清「文档处理链路 + 问答链路」两条主线。
- **原理追问**：重点刷 03 切分与向量维度、05 混合检索/父子分段/重排、06 两级记忆架构与多轮问题重写。
- **工程面试**：先看 04 事件驱动 + 分布式锁，再练 08 版本管理/权限/缓存、07 回答全流程与多数据源。
- **踩坑复盘口述**：看 09 的 8 类案例，选自己实际处理过的两三个，按「现象→定位→根因→修复→回归」讲清，不把课程记录当成个人经历。
- **源码审阅**：看 10 的 12 题，遮住答案先自己 review 代码片段再对照；这类题背不出来，必须真读过代码，涵盖坏味道 review、配置排障、测试策略、演进考古四个维度。
- **练习方法**：先口述结论，再补原理、适用条件和代价；遮住答案回答追问，最后讲验证方法。

## 一条完整的项目答题路线

业务目标与三源数据 → 文档上传与 MinerU 解析 → Markdown 标题切分与父子分段 → 向量化入 ES（事件驱动 + XXL-JOB 兜底 + 分布式锁防并发）→ 意图识别与查询路由 → 问题重写与多轮记忆 → 混合检索 + 多级缓存 + BGE-ReRanker 重排 → 流式生成与引用/过程内容返回 → 版本管理、权限、问答缓存与监控保障。

先说明实际做了什么，再讲为什么这样选；没有测量的数字不填写，没有实现的方案明确说是设计建议。项目陈述模板见 [09 踩坑复盘与项目陈述](./09-踩坑复盘与项目陈述.md) Q2。

## 来源和版本约定

- 每题用从仓库根开始的双链溯源，不带 `.md` 后缀；站点尚未转换双链时，可复制路径在仓库打开。
- **源码定位**：每题 `> 源码：` 行给出 `repo/know-engine` 下的相对路径，复习时可直接跳转实现；纯选型/方法论题（如 01 Q5/Q6、09 Q2）无对应源码，不加此行。
- **校核口径**：2026-10-21 已对照 `repo/know-engine` 源码全量校核。笔记与源码不一致处以源码为准修正，并在题内加「源码校核：笔记中的 X 在源码中实际为 Y」说明——面试答题以校核后口径为准。
- 答案以 `AI项目/know-engine/` 下的课程笔记为准；笔记没有的扩展知识明确标注「通用补充」或「设计建议」，与已验证实现区分阅读。
- `⚠️ raw 缺失，待补充` 表示基础笔记尚无对应实现或实验材料。
- **已知缺口**：08 模块 Q5/Q8~Q10（问答缓存构建/使用/失效）对应源码不在当前 repo 中（可能未提交或在其他仓库），答案仍按笔记口径，未加源码行。
- 本目录是面试材料，不提供可编译工程或生产压测结果；笔记中的耗时、正确率等数字是笔记作者的实测记录，答题时应换成自己项目的真实数据。
- 同主题的通用 RAG 理论题（检索评估、嵌入原理、Spring AI 对比等）见 [RAG 面试题库](../RAG/interview/README.md)，两者配合使用：那边考原理，这边考项目落地。
