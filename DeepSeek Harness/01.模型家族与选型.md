# 01. 模型家族与选型

> 应用开发第一步是**选对模型**。DeepSeek 的 API 只暴露**两个模型名**（`deepseek-chat` / `deepseek-reasoner`），但底层对应不同版本，能力差异大。本文讲清家族谱系、能力矩阵、场景选型，以及本地部署用的蒸馏小模型。

---

## 一、API 模型名 vs 底层版本

| API 模型名 | 底层模型 | 定位 | 何时用 |
|:---|:---|:---|:---|
| `deepseek-chat` | DeepSeek-V3（V3.1 混合思考）| 通用对话 + 代码 + 工具调用 | 90% 业务：聊天、RAG、Agent 执行、Function Call |
| `deepseek-reasoner` | DeepSeek-R1 | 深度推理 | 数学/逻辑/规划/复杂 Agent 决策（会先「思考」再答）|

> ⚠️ 早期曾有 `deepseek-coder` 模型名，已并入 `deepseek-chat`（V3 的代码能力已很强）。新项目别再调 `deepseek-coder`。

---

## 二、家族时间线（应用开发者视角）

```
2024-05  V2        ← 首次引入 MLA + DeepSeekMoE
2024-07  Coder-V2  ← 代码 + 数学 MoE，FIM 补全
2024-09  V2.5      ← 合并 V2 对话 + Coder
2024-12  V3        ← 671B/37B 激活 + MLA + MTP + FP8 训练 + aux-loss-free 均衡
2025-01  R1 / R1-Zero ← 纯 RL（GRPO）推理模型，蒸馏 1.5B~70B 六档
2025-08  V3.1      ← 混合思考：V3（不思考）+ R1（思考）合一，思考可控（开关/预算）
```

> 时间线只作背景了解，**应用开发只需记「chat = V3 系，reasoner = R1 系」**。

---

## 三、能力矩阵

| 能力 | `deepseek-chat`(V3) | `deepseek-reasoner`(R1) |
|:---|:---:|:---:|
| 通用对话 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐（R1 偏推理，闲聊啰嗦）|
| 代码生成 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐（算法题强）|
| 数学/逻辑推理 | ⭐⭐⭐⭐ | ⭐⭐⭐⭐⭐（思考链长，准确率高）|
| 函数调用 (Function Call) | ✅ 支持 | ⚠️ 弱/不稳定（思考模型不太适合结构化工具调用）|
| JSON 输出 | ✅ | ⚠️ |
| 长上下文 | 64K~128K | 略短（思考占预算）|
| 响应延迟 | 低（37B 激活小）| 高（要先思考）|
| 单价 | 低 | 高（思考 token 多）|

> 💡 **铁律**：Function Call / 结构化输出 / 高并发低延迟 → 用 `deepseek-chat`；硬核推理 → 用 `deepseek-reasoner`。别拿 R1 做闲聊和工具调用。

---

## 四、场景 → 模型 决策

| 场景 | 选型 | 理由 |
|:---|:---|:---|
| 客服 / 知识问答（RAG） | `deepseek-chat` | 延迟低、便宜、对话强 |
| 代码补全 / 生成 | `deepseek-chat` | 代码能力强、FIM 支持 |
| Agent 执行层（调工具）| `deepseek-chat` | Function Call 稳定 |
| Agent 规划层（拆任务、定方案）| `deepseek-reasoner` | R1 推理强，能拆复杂目标 |
| 数学题 / 算法题 / 复杂逻辑 | `deepseek-reasoner` | 思考链准 |
| 普通闲聊、摘要、翻译 | `deepseek-chat` | R1 画蛇添足、贵、慢 |

**混合架构**：复杂 Agent 可用「R1 做规划 + V3 做执行」双模型分工（见 [03.RAG与Agent集成](03.RAG与Agent集成.md)）。

## 五、蒸馏小模型（本地部署）

R1 开源了六档蒸馏模型，给本地 / 端侧 / 低配部署用：

| 模型 | 基座 | 显存（FP16 大致）| 适合 |
|:---|:---|:---:|:---|
| DeepSeek-R1-Distill-1.5B | Qwen2.5-Math-1.5B | ~3GB | 端侧、CPU 也能跑 |
| DeepSeek-R1-Distill-7B | Qwen2.5-Math-7B | ~14GB | 单卡 16G |
| DeepSeek-R1-Distill-8B | Llama-3.1-8B | ~16GB | 单卡 16G |
| DeepSeek-R1-Distill-14B | Qwen2.5-14B | ~28GB | 单卡 40G |
| DeepSeek-R1-Distill-32B | Qwen2.5-32B | ~64GB | A100 80G |
| DeepSeek-R1-Distill-70B | Llama-3.3-70B | ~140GB | 多卡 |

> 蒸馏模型 = 把 R1 的推理能力「教」给小模型（SFT 蒸馏），**不是**完整 R1，能力递减但仍保留思考链风格。本地起服务用 Ollama / vLLM（见 [05.部署与成本](05.部署与成本.md)）。

## 六、易错点 ⚠️

| # | 易错点 | 正确理解 |
|:---:|:---|:---|
| 1 | 「`deepseek-coder` 还在」 | 已并入 `deepseek-chat`，调它要么报错要么重定向，新代码用 `deepseek-chat` |
| 2 | 「R1 也能稳定 Function Call」 | R1 思考前先输出一堆，工具调用解析不稳定，执行层用 V3 |
| 3 | 「蒸馏 70B = R1 全部能力」 | 蒸馏只 SFT 学了推理风格，没做 RL，能力低于满血 R1 |
| 4 | 「V3 671B 全激活」 | 是 MoE，每次只激活 37B，这就是它便宜快的根因 |
| 5 | 「版本号越高一定越好」 | R1 推理强但贵慢，闲聊反而不如 V3；按场景选不按版本选 |

---

## 七、一句话总结

API 只两个名：`deepseek-chat`=V3（通用/代码/Function Call，便宜快）、`deepseek-reasoner`=R1（推理强但贵慢、不适合工具调用）；执行用 V3、规划用 R1，本地用蒸馏小模型——**按场景选，不按版本号选**。
