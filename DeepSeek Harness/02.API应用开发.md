# 02. API 应用开发

> DeepSeek API **OpenAI 兼容**：换 `base_url` + `api_key` 即可复用 OpenAI SDK（Python / Java / JS）。本文讲 Chat、JSON、Function Call、FIM、Context Cache、R1 思考字段、流式与重试，全附可跑代码。

---

## 一、接入：三行替换 OpenAI

```python
# pip install openai
from openai import OpenAI

client = OpenAI(
    api_key="sk-xxxx",                          # 从 platform.deepseek.com 拿
    base_url="https://api.deepseek.com",        # ⭐ 唯一要改的地方
)
```

Java 用 OpenAI 兼容客户端（如 Spring AI、openai-java）同理，改 `base-url` 和 `api-key`。

> 端点路径同 OpenAI：`/v1/chat/completions`、`/v1/completions`、`/v1/embeddings`（如有）。`base_url` 写根域名，SDK 自动拼 `/v1/...`。

## 二、Chat 基础

```python
resp = client.chat.completions.create(
    model="deepseek-chat",                      # 或 "deepseek-reasoner"
    messages=[
        {"role": "system", "content": "你是资深 Java 工程师，回答简洁。"},
        {"role": "user", "content": "解释 ThreadLocal 为什么会内存泄漏。"},
    ],
    temperature=0.7,        # 0~2，事实问答用 0~0.3，创意用 0.7~1.2
    top_p=0.9,              # 与 temperature 二选一调
    max_tokens=1024,        # 生成上限
)
print(resp.choices[0].message.content)
```

| 参数 | 取值 | 说明 |
|:---|:---|:---|
| `model` | `deepseek-chat` / `deepseek-reasoner` | 见 [01.选型](01.模型家族与选型.md) |
| `temperature` | 0~2 | 越高越随机；代码/事实调低 |
| `top_p` | 0~1 | 核采样；与 temperature 只调一个 |
| `max_tokens` | int | 生成上限；R1 要算思考 token（见六）|
| `stream` | bool | true 走 SSE 流式 |
| `stop` | str[] | 命中停止序列即停 |

## 三、JSON Output（结构化输出）

```python
resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[
        {"role": "system", "content": "你是实体抽取器，输出 JSON。"},
        {"role": "user", "content": "从『张三，30岁，住北京』抽取信息，字段 name/age/city"},
    ],
    response_format={"type": "json_object"},   # ⭐ 强制 JSON
)
import json
data = json.loads(resp.choices[0].message.content)   # {name:张三, age:30, city:北京}
```

> ⚠️ 用 `response_format={"type":"json_object"}` 时，**system/user prompt 里必须出现 "json" 字样**（OpenAI 兼容约定），否则报错。

## 四、Function Calling（工具调用）

```python
tools = [{
    "type": "function",
    "function": {
        "name": "get_weather",
        "description": "查城市天气",
        "parameters": {
            "type": "object",
            "properties": {"city": {"type": "string"}},
            "required": ["city"],
        }
    }
}]

# 第 1 轮：让模型决定调哪个工具
resp = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role":"user","content":"北京今天天气"}],
    tools=tools,
)
call = resp.choices[0].message.tool_calls[0]      # name=get_weather, args={"city":"北京"}

# 第 2 轮：执行工具 → 把结果塞回去让模型总结
import json
messages = [{"role":"user","content":"北京今天天气"}, resp.choices[0].message]
messages.append({
    "role": "tool",
    "tool_call_id": call.id,
    "content": json.dumps({"temp": 25, "cond": "晴"}),  # 工具真实返回
})
final = client.chat.completions.create(model="deepseek-chat", messages=messages, tools=tools)
print(final.choices[0].message.content)          # "北京今天晴，25°C"
```

> 💡 DeepSeek 的 Function Call 与 OpenAI **格式完全一致**：`tools` + `tool_choice`，模型回 `tool_calls`，你回 `role:"tool"`。换 base_url 即可平移。
>
> ⚠️ 用 V3 做工具调用，别用 R1（思考链会干扰结构化输出）。

## 五、FIM 代码补全（prefix + suffix）

FIM（Fill-In-the-Middle）= 给前缀和后缀，模型补中间。Copilot 式补全用它。

```python
resp = client.completions.create(
    model="deepseek-chat",                     # 早期用 deepseek-coder，现并入 chat
    prompt="<｜fim▁begin｜>def fib(n):\n    <｜fim▁hole｜>\n    return result<｜fim▁end｜>",
    max_tokens=64,
    stop=["<｜fim▁end｜>"],
)
# 输出中间补全：if n <= 1: return n\n    result = fib(n-1)+fib(n-2)
```

> FIM 是 `/v1/completions`（非 chat），用特殊 token `<｜fim▁begin｜>` `<｜fim▁hole｜>` `<｜fim▁end｜>` 拼接。IDE 集成（Continue / 自建 Copilot）用这套。

## 六、Context Cache（自动前缀缓存）

DeepSeek **自动**对请求的前缀（system + 历史 messages 的公共前缀）做缓存，命中价 ≈ miss 的 1/4，**不用显式开**。

```
请求 A: [system(2K)] [Q1]            → 前缀 2K 写缓存，全价
请求 B: [system(2K)] [Q1] [A1] [Q2]  → 前缀 system+Q1+A1 命中缓存，只 Q2 全价
```

**优化技巧**：
- system prompt 放**最前面**且**固定不变**（改一个字就 cache miss）。
- 长文档 RAG 把文档段放 system/前部，用户问放尾部 → 文档部分缓存命中。
- few-shot 示例放前部固定，用户输入放尾部。

> 用量返回里有 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`，监控这俩调 prompt 结构。

## 七、R1 的 reasoning_content（思考字段）

```python
resp = client.chat.completions.create(
    model="deepseek-reasoner",
    messages=[{"role":"user","content":"证明根号2是无理数"}],
)
msg = resp.choices[0].message
print("思考过程:", msg.reasoning_content)   # ⭐ R1 专属：思考链
print("最终答案:", msg.content)              # 正式回答
```

| 字段 | 模型 | 含义 |
|:---|:---|:---|
| `content` | 两者都有 | 正式回答 |
| `reasoning_content` | R1 有，V3 无 | 思考过程（CoT）|

> ⚠️ R1 的 `max_tokens` **包含思考 token**：思考太长可能截断到没产出答案 → R1 调用时把 `max_tokens` 调大（如 8K+）。
>
> ⚠️ 流式时 R1 先吐 `reasoning_content` delta，再吐 `content` delta，前端要分两栏渲染。

## 八、流式 / 错误重试 / 限流

```python
# 流式
stream = client.chat.completions.create(model="deepseek-chat",
    messages=[...], stream=True)
for chunk in stream:
    delta = chunk.choices[0].delta.content
    if delta: print(delta, end="", flush=True)
```

| 关注点 | 处理 |
|:---|:---|
| **限流 429** | 指数退避重试（`Retry-After` 头）；按 organization 限流，监控 `X-RateLimit-*` |
| **超时/503** | 设 connect/read timeout，重试 2~3 次 |
| **token 越界** | 长对话要自己截断历史，别超 context window（64K~128K）|
| **idempotency** | 写入类操作（生成后落库）用业务幂等键，别靠重试兜底 |
| **计费监控** | 监控 `usage.prompt_tokens` / `completion_tokens` / `cache_hit_tokens` |

## 九、易错点 ⚠️

| # | 易错点 | 正确理解 |
|:---:|:---|:---|
| 1 | 「base_url 写到 `/v1`」 | 写根域名 `https://api.deepseek.com`，SDK 自己拼 `/v1/...`；写到 `/v1` 会变 `/v1/v1` |
| 2 | 「JSON 模式不用写 json 字样」 | 必须在 prompt 里出现 "json"，否则 API 报错 |
| 3 | 「R1 的 `max_tokens` 只算答案」 | 含思考 token，思考长会截断没答案 |
| 4 | 「改 system 一个字不影响」 | Context Cache 立即 miss，长 system 改一次贵一次 |
| 5 | 「Function Call 用 R1 更准」 | R1 思考链干扰工具调用解析，用 V3 |
| 6 | 「`deepseek-coder` 还在用」 | 已并入 `deepseek-chat`（见 01）|

---

## 十、一句话总结

DeepSeek API = OpenAI 兼容，**改 base_url + key 即可平移**；`deepseek-chat` 做对话/代码/Function Call，`deepseek-reasoner` 做推理（看 `reasoning_content`、`max_tokens` 含思考）；system 放前固定享 Context Cache，429 退避重试——应用层几乎零改造就能切过来。
