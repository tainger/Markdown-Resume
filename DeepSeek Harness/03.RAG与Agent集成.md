# 03. RAG 与 Agent 集成

> DeepSeek 是「OpenAI 兼容」的 LLM，主流框架（LangChain/LlamaIndex/Dify/AutoGen/CrewAI）都能直接接。本文讲它在 RAG 流水线里的位置、Agent 工具调用、V3+R1 分工架构、Prompt 工程模式。

---

## 一、DeepSeek 在 RAG 流水线的位置

```
用户提问
   │
   ▼
① Embedding 模型           ← 通常用 bge-m3 / text-embedding-3-large，不是 DeepSeek
   │
   ▼
② 向量库召回 top-k 文档     ← Milvus / Qdrant / pgvector
   │
   ▼
③ Rerank 稡型             ← bge-reranker / Cohere Rerank
   │
   ▼
④ 拼 Prompt（system + 文档 + 历史 + 问）
   │
   ▼
⑤ LLM 生成答案   ← DeepSeek 在这一步（deepseek-chat）
   │
   ▼
答案 + 引用来源
```

**关键点**：
- DeepSeek 在**第 5 步生成**，不在 1/2/3（DeepSeek 的 embedding 模型不是主流选择，通用 RAG 用 bge-m3 等）。
- 文档段拼在 **prompt 前部固定**，用户问题在尾部 → Context Cache 命中（见 [02.API](02.API应用开发.md#六context-cache自动前缀缓存)）。

> 💡 多轮 RAG：每轮把召回的新文档塞到固定位置会让前缀变化、cache miss。优化是把 system + few-shot 固定，文档段单独管理。

## 二、框架集成（一行换 base_url）

### LangChain

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
    model="deepseek-chat",
    api_key="sk-xxx",
    base_url="https://api.deepseek.com",
    temperature=0.3,
)
# 之后用法与 GPT 一致：llm.invoke / .stream / bind_tools
```

### LlamaIndex

```python
from llama_index.llms.openai_like import OpenAILike
llm = OpenAILike(
    model="deepseek-chat",
    api_key="sk-xxx",
    api_base="https://api.deepseek.com",
    is_chat_model=True,
)
```

### Dify / FastGPT / Flowise

这类低代码平台有「模型供应商」配置，填 base_url + key 即可，无需改代码。

> DeepSeek 官方也提供 SDK（`deepseek` 包），但**没必要用**——OpenAI 兼容 + 主流框架已经覆盖，用框架的原生 OpenAI 客户端更省事。

## 三、Agent 工具调用

DeepSeek-V3 的 Function Call 已成熟，可直接做工具型 Agent：

```python
from langchain_openai import ChatOpenAI
from langchain.agents import create_tool_calling_agent, AgentExecutor
from langchain.tools import Tool

llm = ChatOpenAI(model="deepseek-chat", base_url="https://api.deepseek.com", api_key="sk-xxx")

tools = [
    Tool(name="search_db", func=search_db, description="查订单库"),
    Tool(name="calc_refund", func=calc_refund, description="算退款金额"),
]

agent = create_tool_calling_agent(llm, tools, prompt)
executor = AgentExecutor(agent=agent, tools=tools, verbose=True)
executor.invoke({"input": "订单 123 退款多少？"})
```

| Agent 模式 | 推荐模型 | 说明 |
|:---|:---|:---|
| ReAct（思考-行动-观察循环）| V3 | 经典工具调用循环 |
| Plan-and-Solve（先拆任务再执行）| **R1 规划 + V3 执行** | R1 拆解、V3 跑每个子任务 |
| Reflexion（自我反思修正）| R1 | 反思能力强 |
| 多 Agent 协作（AutoGen/CrewAI）| V3 为主 | 并发多角色，R1 偶尔把关 |

## 四、V3 + R1 分工架构（推荐的高阶玩法）

```
用户复杂请求
   │
   ▼
deepseek-reasoner（R1）        ← 规划层：拆任务、定方案、选工具
   │  输出：步骤计划 + 工具序列
   ▼
deepseek-chat（V3）× N          ← 执行层：并行调工具、做总结
   │
   ▼
最终答案
```

**适用场景**：复杂业务 Agent（多步推理 + 多工具组合）。单纯问答别上 R1，贵且慢。

```python
# 伪代码
plan = r1_llm.invoke("把用户需求拆成 3~5 步，指定每步用哪个工具")  # R1 规划
for step in plan.steps:
    result = v3_llm.bind_tools(tools).invoke(step)                # V3 执行
final = v3_llm.invoke(f"根据各步结果总结：{all_results}")          # V3 收尾
```

> 💡 成本权衡：R1 单价高 + 思考 token 多，规划层只在复杂请求触发，简单请求直接 V3。

## 五、Prompt 工程模式

| 模式 | 写法 | 适用 |
|:---|:---|:---|
| **System 固定 + User 变化** | system 放角色/规则/few-shot，user 放当次输入 | Context Cache 命中，省钱 |
| **Few-shot 示例** | 3~5 个高质量 Q→A 范例放前部 | 格式控制、风格统一 |
| **JSON 结构化** | `response_format=json_object` + schema 描述 | 实体抽取、数据生成 |
| **Chain-of-Thought（V3）** | 让 V3 「先一步步思考再答」 | 中等推理；重度推理直接上 R1 |
| **R1 不需 CoT 指令** | R1 自带思考链，别再喊「let's think step by step」 | 反而拖慢、消耗 token |

> ⚠️ R1 用 V3 的 CoT prompt（「逐步思考」）反而**变慢变贵**——R1 自己会思考，再叠加指令是冗余。

## 六、易错点 ⚠️

| # | 易错点 | 正确理解 |
|:---:|:---|:---|
| 1 | 「RAG 里用 DeepSeek 做 embedding」 | DeepSeek embedding 非主流，通用 RAG 用 bge-m3 / OpenAI embedding-3 |
| 2 | 「Agent 全交给 R1」 | R1 工具调用不稳；执行层用 V3，规划层才用 R1 |
| 3 | 「多轮 RAG 把文档塞 system」 | 每轮文档变 → cache miss；system 只放固定规则，文档放 user 但控制前缀 |
| 4 | 「给 R1 加『逐步思考』prompt」 | R1 自带思考链，叠加指令冗余拖慢 |
| 5 | 「用官方 SDK 才能集成」 | OpenAI 兼容，主流框架换 base_url 即可，无需 deepseek 专属包 |
| 6 | 「框架里 model 写 deepseek-coder」 | 已弃用，写 `deepseek-chat`（见 01）|

---

## 七、一句话总结

DeepSeek 在 RAG 里做**生成**（embedding/召回用别的）；在 Agent 里用 **V3 做执行（Function Call 稳）、R1 做规划（推理强）** 的双模型分工；接入只需改 base_url，OpenAI 兼容让所有框架零改造；R1 别再叠 CoT 指令、执行别用 R1。
