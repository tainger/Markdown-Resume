# 05. 部署与成本

> 应用开发 90% 走官方 API（最省事），只在**数据合规 / 离线 / 超高并发成本 / 定制微调**时才自部署。本文讲两条路线、定价速查、并发与成本估算。

---

## 一、两条路线决策

| 维度 | 官方 API | 自部署（vLLM/SGLang 等）|
|:---|:---|:---|
| 接入成本 | 改 base_url 即可 | 要 GPU 机器 + 部署运维 |
| 数据安全 | 出网到 DeepSeek | 全程私有化（合规强）|
| 弹性扩容 | 平台兜底 | 自己扛并发 |
| 成本曲线 | 按 token 计费，低量便宜 | 固定 GPU 成本，高量摊薄 |
| 模型迭代 | 平台自动升级到最新 | 要自己拉新权重 |
| 定制 | 不能改 | 可微调 / 改 prompt 模板 / 加 LoRA |
| **建议** | **默认首选** | **合规/离线/超高并发/要微调 才上** |

> 决策口诀：**先 API 跑通业务，成本/合规扛不住再自部署**。别一上来就自部署，运维成本远超 token 费。

---

## 二、官方 API 定价速查（≈ 2026，以官网为准）

```
deepseek-chat（V3）:
  输入（cache miss）:  ~¥0.27 / 1M tokens
  输入（cache hit）:   ~¥0.07 / 1M tokens   ← 缓存命中约 1/4
  输出:               ~¥1.10 / 1M tokens

deepseek-reasoner（R1）:
  贵于 V3（思考 token 多），具体见官网
```

> ⚠️ 价格随版本变动频繁，**工程落地前查 [platform.deepseek.com](https://platform.deepseek.com) 定价页**，别照搬上表。

**省钱要点**：
1. **吃 Context Cache**：system 固定、长前缀不变（见 [02.API](02.API应用开发.md#六context-cache自动前缀缓存)）。
2. **简单任务别用 R1**：R1 思考 token 贵 + 多。
3. **截断历史**：多轮对话超长会爆 context + 计费，做摘要或滑窗。
4. **流式 + 早停**：用户取消就停，别等满。

## 三、自部署框架选型

| 框架 | 适合 | 特点 |
|:---|:---|:---|
| **vLLM** | 通用首选 | PagedAttention，MoE 专家并行，吞吐高 |
| **SGLang** | DeepSeek 官方推荐 V3 | RadixAttention，对 MLA/MTP 支持好 |
| **TensorRT-LLM** | 极致延迟 | nVidia 官方，工程重但快 |
| **LMDeploy** | 国产，文档友好 | OpenMMLab 出品，量化好 |
| **KTransformers** | 低显存跑 MoE | CPU+GPU 混合，单卡跑 671B（慢）|
| **Ollama** | 蒸馏小模型本地 | 1.5B~14B，个人/端侧 |

> V3 满血（671B）自部署门槛：多卡 H100/A100 80G ×8 起步，配 MoE 专家并行。蒸馏小模型（R1-Distill-7B 等）单卡可跑。

---

## 四、量化降显存

| 量化 | 显存降幅 | 精度损失 | 用法 |
|:---|:---|:---|:---|
| **FP8** | ~50% | 极小 | V3 原生训练精度，最佳 |
| **INT8 / W8A8** | ~50% | 小 | vLLM/TensorRT 通用 |
| **AWQ / GPTQ** | ~50%~66% | 中 | 社区量化版，小卡跑大模型 |
| **INT4** | ~75% | 较明显 | 极限省显存，质量下降 |

> 优先 FP8/INT8，质量敏感再 AWQ；INT4 是极限玩法，对话质量明显下降。

---

## 五、并发与成本估算

```
单请求 token = prompt(2K) + completion(1K) ≈ 3K
V3 输入 miss 2K × 0.27/1M + 命中 1K × 0.07/1M + 输出 1K × 1.10/1M
        = 0.00054 + 0.00007 + 0.0011 ≈ ¥0.0017/请求
1 万次/天 ≈ ¥17/天 ≈ ¥500/月
```

> 💡 **拐点估算**：月 token 费 > 一张 H100 月租（~¥15000）时，自部署才划算；且自部署要搭运维 + 弹性。**很多业务永远到不了这个拐点**，老实 API。

**并发瓶颈**：
- 官方 API：按 organization 限流（RPM/TPM），高峰 429 要退避。
- 自部署：吞吐取决于 GPU + 框架（vLLM 单 H100 几百~上千 tok/s）。

## 六、易错点 ⚠️

| # | 易错点 | 正确理解 |
|:---:|:---|:---|
| 1 | 「小项目也自部署省成本」 | 自部署运维 + 固定成本 > API token 费，小项目别上 |
| 2 | 「单卡跑满血 V3」 | 671B 要多卡 + 专家并行，单卡只能跑蒸馏版或 KTransformers（慢）|
| 3 | 「API 自动升级是坏事」 | 是好事——白嫖新版本；自部署要手动拉权重 |
| 4 | 「INT4 量化无损」 | 质量明显下降，对话任务别用，代码/创意更不行 |
| 5 | 「定价表抄死」 | 版本迭代会变，落地前查官网 |
| 6 | 「R1 高并发省钱」 | R1 思考 token 多，并发下成本暴涨，用 V3 兜底 |

---

## 七、一句话总结

**先 API 跑通业务**（改 base_url、吃 Context Cache、简单任务用 V3）；**成本/合规/微调扛不住才自部署**，框架选 vLLM 通用或 SGLang 跑 V3、量化优先 FP8/INT8；月 token 费到一张 H100 租金量级才是自部署拐点。
