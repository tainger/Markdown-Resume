# 06. 面试题

> 应用开发岗 + 必要原理的高频面试 Q&A。按「选型 → API → RAG/Agent → 原理 → 部署」分块，每题给一句话答法 + 展开要点。⭐ 越多越高频。

---

## 一、模型与选型

### Q1. ⭐⭐⭐ DeepSeek 的 API 有哪些模型？怎么选？

`deepseek-chat` = V3（通用/代码/Function Call，便宜快），`deepseek-reasoner` = R1（推理强但贵慢）。**执行层（对话、工具调用）用 chat，规划层（拆任务、复杂推理）用 reasoner**。别拿 R1 闲聊和 Function Call。

### Q2. ⭐⭐ `deepseek-coder` 还能用吗？

已并入 `deepseek-chat`——V3 的代码能力已足够，原 `deepseek-coder` 模型名要么报错要么重定向。新项目用 `deepseek-chat`。

### Q3. ⭐⭐ R1 的蒸馏小模型和满血 R1 区别？

蒸馏版（1.5B/7B/8B/14B/32B/70B）是用 R1 的输出做 SFT 教给小模型，**只学了思考链风格，没做 RL**，能力低于满血 R1。本地/端侧用蒸馏，线上推理用满血 R1 或 API。

### Q4. ⭐ V3 是 671B，为什么推理还便宜？

MoE 稀疏激活：总参 671B，每次只激活 **37B**。推理 FLOPs 由激活参数决定，所以又便宜又快。代价是**显存要装下全部 671B 权重**（自部署门槛高）。

## 二、API 应用

### Q5. ⭐⭐⭐ DeepSeek API 怎么接入？要换 SDK 吗？

不用。**OpenAI 兼容**，改 `base_url=https://api.deepseek.com` + `api_key` 即可复用 OpenAI SDK / LangChain / LlamaIndex。无需 deepseek 专属包。

### Q6. ⭐⭐⭐ Context Cache 怎么用？为什么能省钱？

**自动生效**，对请求公共前缀缓存，命中价 ≈ miss 的 1/4。优化：**system prompt + few-shot 放最前固定**，用户输入和动态文档放尾部。改一个字 system 就 cache miss，长 system 改一次贵一次。

### Q7. ⭐⭐ Function Call 怎么实现？和 OpenAI 一样吗？

完全一致：`tools` 定义函数 schema，模型回 `tool_calls`，你执行后用 `role:"tool"` + `tool_call_id` 回传结果。**用 V3 做工具调用，别用 R1**（思考链干扰结构化输出解析）。

### Q8. ⭐⭐ R1 的 `reasoning_content` 是什么？和 `content` 啥关系？

`reasoning_content` = R1 的思考链（CoT），`content` = 正式答案。**流式时先吐 reasoning delta 再吐 content delta**，前端要分两栏渲染。

### Q9. ⭐⭐ R1 的 `max_tokens` 设置有什么坑？

**含思考 token**——思考链太长会截断到没产出答案。R1 调用要把 `max_tokens` 调大（8K+），别用 V3 的 1K 思路。

### Q10. ⭐ JSON 输出模式有什么约束？

`response_format={"type":"json_object"}` 时，**prompt 里必须出现 "json" 字样**，否则 API 报错（OpenAI 兼容约定）。

### Q11. ⭐ FIM 是什么？什么场景用？

Fill-In-the-Middle，给前缀 + 后缀补中间。用 `/v1/completions`（非 chat）+ 特殊 token `<｜fim▁begin｜><｜fim▁hole｜><｜fim▁end｜>` 拼接。Copilot 式 IDE 补全用它。

## 三、RAG 与 Agent

### Q12. ⭐⭐⭐ DeepSeek 在 RAG 里做什么？embedding 也用它吗？

DeepSeek 做**生成**（第 5 步）。embedding / 召回 / rerank 用别的——通用 RAG 用 bge-m3 做 embedding、Milvus 做向量库、bge-reranker 做重排，DeepSeek 只负责最后基于文档生成答案。

### Q13. ⭐⭐ 多轮 RAG 怎么用 Context Cache？

system 放**固定规则 + few-shot**，每轮变化的召回文档放 user 但控制前缀结构。**别把每轮新文档塞 system**（system 一变 cache 全 miss）。

### Q14. ⭐⭐ Agent 用 R1 还是 V3？

**执行层用 V3**（工具调用稳、便宜快），**规划层用 R1**（拆任务、复杂决策）。复杂 Agent 用「R1 规划 + V3 执行」双模型分工；简单 Agent 全 V3。

### Q15. ⭐ 给 R1 加「let's think step by step」行不行？

**反而变慢变贵**——R1 自带思考链，再叠 CoT 指令是冗余。V3 才需要这种 CoT prompt，R1 别加。

## 四、核心原理（应用岗够用）

### Q16. ⭐⭐⭐ MoE 是什么？为什么 DeepSeek 便宜快？

稀疏激活：把 FFN 拆成多个专家，**每次只激活 top-k 个**。V3 是 671B 总参 / 37B 激活，推理 FLOPs 由激活参数决定 → 便宜快。DeepSeekMoE 创新：**细粒度专家 + 共享专家**。

### Q17. ⭐⭐⭐ MLA 解决了什么问题？

KV 缓存低秩压缩——传统 MHA/GQA 长上下文 KV 缓存爆炸，MLA 把 K/V 联合压成 latent 向量，**缓存小一个数量级**，所以 V3 能开 128K 上下文且不贵。与 GQA 思路相反（GQA 共享 K/V，MLA 低秩潜变量解压）。

### Q18. ⭐⭐⭐ R1 为什么是「突破」？

R1-Zero 证明：**不给 CoT 数据，只靠正确性奖励做 RL（GRPO），模型自己长出推理能力**（会验证、反思、顿悟）。工业落地用冷启动 + 多阶段 RL 修可读性，再蒸馏给小模型摊薄成本。

### Q19. ⭐⭐ GRPO 和 PPO 区别？

GRPO 不需要训 value 模型——组内采样 G 个回答，用**组内均值/最大**当基线，省一个 value 模型的显存和工程，适合大模型推理任务。

### Q20. ⭐ V3 训练为什么那么便宜？

三条工程加速：**FP8 混合精度**（省一半显存算力）、**DualPipe 双向流水线**（计算通信重叠）、**aux-loss-free 专家均衡**（不耗算力做均衡）。2048 张 H800 训 14.8T token 约 557 万美元，约为同级的 1/10。

## 五、部署与成本

### Q21. ⭐⭐⭐ 什么时候用官方 API，什么时候自部署？

**默认 API**（改 base_url、白嫖迭代、按 token 付费）。只有**数据合规要私有化、离线、超高并发成本、要微调**才自部署。决策口诀：先 API 跑通，扛不住再自部署。

### Q22. ⭐⭐ 自部署 V3 满血要什么资源？框架选哪个？

671B 满血要多卡 H100/A100 80G ×8 起步 + MoE 专家并行。框架：**vLLM 通用首选，SGLang 是 DeepSeek 官方推荐跑 V3**（对 MLA/MTP 支持好）。蒸馏小模型单卡可跑、Ollama 起本地。

### Q23. ⭐⭐ 成本拐点在哪？

月 token 费 > 一张 H100 月租（~¥15000）时自部署才划算，且自部署要搭运维 + 弹性。**很多业务永远到不了这个拐点**，老实 API。

### Q24. ⭐ 量化怎么选？

优先 **FP8（V3 原生训练精度，无损）→ INT8（小损）→ AWQ/GPTQ（中损）→ INT4（明显下降，别用对话）**。

## 六、综合 / 场景题

### Q25. ⭐⭐⭐ 设计：用 DeepSeek 做一个「客服 + 工单系统」Agent，怎么选型？

- 对话 + 查知识库（RAG）→ `deepseek-chat`
- 复杂投诉拆解（多步骤、跨部门流转）→ 路由到 `deepseek-reasoner` 出方案
- 工具调用（查订单、建工单、退款）→ V3 的 Function Call
- system 放固定客服人设 + few-shot → 吃 Context Cache
- 兜底：写入类操作（建工单）用业务幂等键，别靠 LLM 重试

### Q26. ⭐⭐ 用 DeepSeek 做 Copilot 式代码补全，怎么接？

用 FIM（`/v1/completions` + 特殊 token），不是 chat。模型用 `deepseek-chat`（代码能力强）。IDE 端用 Continue / 自建插件，prefix 取光标前、suffix 取光标后，模型补中间。

### Q27. ⭐ 接入 LangChain 报错「model not found」，怎么排查？

① base_url 写对没（根域名，别加 `/v1`）；② model 名写对没（`deepseek-chat`，别写 `deepseek-coder`）；③ key 有权限没；④ 框架版本支持 Function Call 没。

## 七、一句话总结

面试主线：**OpenAI 兼容零改造接入 → chat 做 Function Call、reasoner 做推理 → 吃 Context Cache 省钱 → 原理讲清 MoE/MLA/R1-Zero 突破 → 默认 API、扛不住才自部署**。记住「执行用 V3、规划用 R1、别给 R1 叠 CoT」三条，应用岗基本通杀。
