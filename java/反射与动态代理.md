# 反射与动态代理

反射是框架的发动机，动态代理是 AOP/RPC 的骨架。面试三连：**反射是什么、JDK 代理和 CGLIB 区别、你项目里哪里用到**——最后这问才是 P7 的胜负手。

---

## 一、反射基础

```java
// 获取 Class 对象三种方式（同一份运行时元数据）
Class<?> c1 = String.class;
Class<?> c2 = "a".getClass();
Class<?> c3 = Class.forName("java.lang.String");
```

| 能力 | API |
|:---|:---|
| 创建实例 | `clazz.getDeclaredConstructor().newInstance()`（JDK 9+ 推荐，`newInstance()` 已废弃） |
| 访问字段/方法 | `getDeclaredField / getDeclaredMethod`（Declared = 含私有，不含父类） |
| 绕过访问检查 | `setAccessible(true)`；JDK 17+ 受模块系统限制（需 `--add-opens`） |

### 反射为什么慢（必考）

| 开销点 | 说明 |
|:---|:---|
| 访问检查 | 每次调用都校验可见性（`setAccessible(true)` 可绕过） |
| 参数装箱 | `Method.invoke(Object...)` 要求 Object[]，基本类型拆装箱 |
| JIT 优化受限 | 反射调用链难内联（JDK 18+ 每次 invoke 重新检查才缓解安全漏洞，成本回升） |

**优化路径**：缓存 Method/Field（Class 解析一次）→ `MethodHandle` → **LambdaMetafactory**（生成函数式适配类，接近直接调用，Spring 6/MyBatis 已在用）。

---

## 二、JDK 动态代理（必考手撕）

### 原理

运行时**动态生成字节码类** `$Proxy0`：`extends Proxy implements 目标接口`，每个方法调用都转发到 `InvocationHandler.invoke`。

```java
UserService target = new UserServiceImpl();

UserService proxy = (UserService) Proxy.newProxyInstance(
        target.getClass().getClassLoader(),
        target.getClass().getInterfaces(),
        (p, method, args) -> {
            long start = System.nanoTime();
            Object result = method.invoke(target, args);   // 反射调用真实方法
            System.out.println(method.getName() + " 耗时: " + (System.nanoTime() - start));
            return result;
        });

proxy.findUser(1L);   // 代理对象上调用 → InvocationHandler → 反射 → 目标对象
```

**限制：只能代理接口**（$Proxy0 已继承 Proxy，Java 单继承无路可走）。

---

## 三、CGLIB 动态代理

### 原理

运行时生成**目标类的子类**字节码，覆写非 final 方法拦截；`MethodInterceptor` 回调 + **FastClass 机制**（给方法建索引，`invoke(index, obj, args)` 直接调用，避开反射）。

```java
Enhancer enhancer = new Enhancer();
enhancer.setSuperclass(UserServiceImpl.class);          // 生成子类
enhancer.setCallback((MethodInterceptor) (obj, method, args, proxy) -> {
    return proxy.invokeSuper(obj, args);                // 走父类原实现
});
UserServiceImpl proxy = (UserServiceImpl) enhancer.create();
```

**限制**：final 类不能被继承、final/private/static 方法不能被覆写拦截；构造函数会真实执行两次（Spring 用 **Objenesis** 绕过实例化）。

## 四、对比与框架应用（P7 关键）

| 维度 | JDK 动态代理 | CGLIB |
|:---|:---|:---|
| 实现方式 | 实现接口 + 继承 Proxy | **生成子类** |
| 前提 | 目标必须有接口 | 类可继承即可 |
| 调用机制 | 反射（`method.invoke`） | FastClass 索引调用（更快） |
| 方法限制 | 接口方法 | final/private/static 不可拦截 |
| 依赖 | JDK 内置 | 第三方（Spring 内置重新打包 cglib） |

**Spring AOP 的选择**：
- Spring Framework：有接口默认 JDK 代理，无接口用 CGLIB；`proxyTargetClass=true` 强制 CGLIB；
- **Spring Boot 2.x 起默认 `proxyTargetClass=true`（全 CGLIB）**——因为 CGLIB 对单例 Bean 无接口场景更省心，且避免「注入实现类失败」的经典报错。

**你项目里的代理（面试落点）**：
- MyBatis Mapper：`MapperProxy`（JDK 代理）把接口方法转成 SQL 执行 → [../Mybatis/核心架构与执行流程.md](../Mybatis/核心架构与执行流程.md)；
- Dubbo Consumer：Proxy 层生成接口代理，把调用转成 Invoker → [../dubbo/核心架构与执行流程.md](../dubbo/核心架构与执行流程.md)；
- Spring `@Transactional`/`@Async`：代理对象包住目标 Bean，失效场景（自调用、private 方法）就是代理机制问题；
- Mockito / 延迟加载（MyBatis 懒加载 `cglib`/javassist）。

---

## 五、代理 vs 装饰器 vs AOP（概念辨析）

| 概念 | 区别 |
|:---|:---|
| 装饰器模式 | 手写包装类，编译期确定；代理运行期动态生成 |
| 动态代理 | 运行时生成拦截逻辑，一个 Handler 服务任意接口 |
| AOP | **用代理实现的横切编程范式**（切入点/通知/织入），动态代理是它的实现手段之一 |

---

## 易错点

| 坑 | 说明 |
|:---|:---|
| `getInterfaces()` 丢接口 | 目标类实现多接口时传错集合，代理转型失败 |
| InvocationHandler 里 `this.method()` | 又走回代理对象 → 死循环（应调 target） |
| CGLIB 拦 final 方法 | 覆写不了，静默不拦截，切面失效 |
| Spring 自调用事务失效 | `this.method()` 绕过代理对象直调目标，@Transactional 不生效——高频场景题 |
| JDK 17 反射报 InaccessibleObjectException | 模块封闭，需 `--add-opens`；框架升级常见坑 |
| 反射无缓存反复 `forName/getMethod` | 每次字符串查找 + 数组复制，热点路径必缓存 |

---

## 一句话总结

**反射 = 运行时读 Class 元数据操作类**（慢在检查与装箱，解法是缓存/MethodHandle/LambdaMetafactory）；**JDK 代理靠接口 + InvocationHandler，CGLIB 靠子类 + FastClass**；Spring Boot 默认 CGLIB，而 **@Transactional 自调用失效是代理机制的最经典落地面试题**——答案永远指向「绕过了代理对象」。
