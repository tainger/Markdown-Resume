# 守护线程（Daemon Thread）

> 基础问答见 [线程面试题.md Q8](线程面试题.md)，本篇深挖 JVM 退出机制、源码细节、坑点与生产应用。

---

## 一、什么是守护线程

守护线程（Daemon Thread）是在程序运行时**在后台提供通用服务**的线程，它**不依赖任何用户线程**，当所有用户线程结束时，JVM 会自动退出，守护线程也随之终止。

```java
Thread daemon = new Thread(() -> System.out.println("daemon running"));
daemon.setDaemon(true);   // 必须在 start() 之前设置
daemon.start();
```

- `setDaemon(true)` 将线程标记为守护线程
- 默认继承父线程的 daemon 属性（主线程是用户线程，所以默认创建的都是用户线程）
- `isDaemon()` 查询

---

## 二、JVM 退出机制（核心原理）

### 2.1 JVM 何时退出

JVM 启动后会等待**非守护线程**（用户线程）全部结束。只要还有一个用户线程在运行，JVM 就不会退出。

### 2.2 JVM 退出源码逻辑

HotSpot 中 `Thread::exit()` 关键逻辑（C++ 伪代码）：

```cpp
void JavaThread::exit() {
  // 1. 从活跃线程表中移除
  remove_thread(this);

  // 2. 如果退出的是最后一个非守护线程，触发 JVM 关闭序列
  if (is_last_non_daemon_thread()) {
    // 执行 shutdown hooks
    // 关闭所有守护线程（不保证 finally）
    // 退出 JVM
    vm_exit(0);
  }
}
```

**关键点**：
- JVM 退出时**不会等待守护线程执行完**，直接强杀
- 守护线程的 `finally` 块**不保证执行**（可能还没跑到就被 kill 了）
- `System.exit()` 会强制触发关闭，无论还有多少用户线程

### 2.3 守护线程与 Shutdown Hook

```java
Runtime.getRuntime().addShutdownHook(new Thread(() -> {
    System.out.println("JVM 正在退出，执行清理...");
}));
```

- Shutdown Hook 是**用户线程**，不是守护线程
- JVM 退出时会**等待**所有 Shutdown Hook 执行完
- Hook 内部不能太耗时（有超时机制），否则会被强制终止

## 三、源码细节

### 3.1 Thread.setDaemon

```java
public final void setDaemon(boolean on) {
    checkAccess();
    // 必须在启动前设置，否则不生效（OpenJDK 只检查 isAlive，不抛异常，但设置无效）
    if (isAlive()) {
        throw new IllegalThreadStateException();
    }
    daemon = on;
}
```

**坑**：在 `start()` 之后调用 `setDaemon(true)` 会**抛异常**，不是静默失败。

### 3.2 守护线程的创建继承

```java
Thread t = new Thread(() -> {
    Thread child = new Thread(() -> {});
    // child 默认继承 t 的 daemon 属性
});
t.setDaemon(true);
t.start();
```

- 子线程**默认继承**父线程的 daemon 属性
- 所以在守护线程中创建的线程也是守护线程

### 3.3 守护线程组

`ThreadGroup` 本身不区分 daemon，组内每个线程独立设置。`ThreadGroup.setDaemon()` 只影响**组的默认属性**，不影响已存在的线程。

## 四、常见坑点（面试高频）

### 4.1 finally 块不保证执行

```java
Thread daemon = new Thread(() -> {
    try {
        while (true) {
            // 业务逻辑
        }
    } finally {
        // ⚠️ JVM 退出时不保证执行到这里
        System.out.println("清理资源");
    }
});
daemon.setDaemon(true);
daemon.start();
```

**结论**：守护线程**不能用来做需要清理资源的任务**（如写数据到磁盘、关闭连接）。需要可靠清理的应该用 Shutdown Hook。

### 4.2 start() 之后 setDaemon 抛异常

```java
Thread t = new Thread(() -> {});
t.start();
t.setDaemon(true);  // ❌ 抛 IllegalThreadStateException
```

### 4.3 守护线程中创建的默认也是守护线程

```java
Thread userThread = new Thread(() -> {});
userThread.start();

Thread daemon = new Thread(() -> {
    Thread child = new Thread(() -> {});
    // child.isDaemon() == true，继承父线程
});
daemon.setDaemon(true);
daemon.start();
```

### 4.4 守护线程不是后台线程的同义词

- "后台线程" 是口语，可能指 GUI 后台任务（如 SwingWorker）
- "守护线程" 是 Java 专有概念，特指随 JVM 退出而终止的线程

### 4.5 数据库连接/文件操作不要放守护线程

守护线程可能在任何时刻被终止，正在写文件的操作会导致文件损坏。关键 IO 操作必须放在用户线程中。

## 五、典型应用场景

### 5.1 JVM 内部守护线程

JVM 启动时自带几个守护线程：

| 线程 | 作用 |
|:---|:---|
| **GC 线程** | 垃圾回收（G1/CMS 各有多个 GC 线程） |
| **JIT 编译器线程** | C1/C2 即时编译 |
| **Reference Handler** | 处理引用对象（Weak/Soft/Phantom） |
| **Finalizer** | 执行对象的 finalize() 方法 |
| **Signal Dispatcher** | 分发操作系统信号 |
| **Attach Listener** | 接收 jstack/jmap 等工具的 attach 命令 |

### 5.2 业务中的守护线程

```java
// 1. 日志异步刷盘（不保证最终一致性，允许丢日志）
Thread logFlusher = new Thread(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        flushLogBuffer();
        try { Thread.sleep(1000); } catch (InterruptedException e) { break; }
    }
});
logFlusher.setDaemon(true);
logFlusher.setName("async-log-flusher");
logFlusher.start();

// 2. 监控线程（采集指标，允许丢失最后一次采集）
Thread metricsCollector = new Thread(() -> {
    while (true) {
        collectMetrics();
        try { Thread.sleep(5000); } catch (InterruptedException e) { break; }
    }
});
metricsCollector.setDaemon(true);
metricsCollector.setName("metrics-collector");
metricsCollector.start();

// 3. 心跳检测（连接保活，连接本身有重连机制）
Thread heartbeat = new Thread(() -> {
    while (connection.isOpen()) {
        sendHeartbeat();
        try { Thread.sleep(30000); } catch (InterruptedException e) { break; }
    }
});
heartbeat.setDaemon(true);
heartbeat.start();
```

### 5.3 不适合用守护线程的场景

| 场景 | 原因 |
|:---|:---|
| 数据库事务提交 | 可能提交到一半被 kill，数据不一致 |
| 文件写入/上传 | 可能写一半文件损坏 |
| 消息发送 | 可能丢失消息 |
| 分布式锁释放 | 锁无法释放，导致死锁 |
| 关键指标上报 | 最后一批指标丢失 |

## 六、面试问答

### Q1：守护线程和用户线程的区别？

| 维度 | 用户线程 | 守护线程 |
|:---|:---|:---|
| 创建 | `new Thread()` | `setDaemon(true)` |
| JVM 退出 | **所有用户线程结束** JVM 才退出 | 用户线程全挂后**自动终止** |
| finally 块 | 正常执行 | **不保证执行** |
| 典型用途 | 业务逻辑、异步任务 | GC、JIT、监控、日志刷盘 |
| Shutdown Hook | 会等待 | 不会触发守护线程清理 |

### Q2：为什么 JVM 退出时不等待守护线程？

因为守护线程的设计初衷是"**随 JVM 生随 JVM 灭**"的后台服务线程，不承载需要保证完成的业务逻辑。如果让 JVM 等待守护线程完成，守护线程中的死循环会导致 JVM 永远无法退出。

### Q3：守护线程中做资源清理（finally）可靠吗？

不可靠。JVM 退出时直接 kill 守护线程，finally 不一定执行。需要可靠清理的用 **Shutdown Hook**（用户线程，JVM 退出时会等待其完成）。

### Q4：如何优雅地停止守护线程？

```java
// 用 volatile flag 控制循环退出
private volatile boolean running = true;

Thread daemon = new Thread(() -> {
    while (running) {
        doWork();
        try { Thread.sleep(1000); } catch (InterruptedException e) {
            Thread.currentThread().interrupt();  // 恢复中断标志
            break;
        }
    }
    // 正常退出，finally 可以执行
});
daemon.setDaemon(true);
daemon.start();

// 停止
running = false;
daemon.interrupt();  // 唤醒可能 sleep 的线程
daemon.join();       // 等待退出（如果是用户线程）
```

### Q5：线程池中的线程是守护线程吗？

默认**不是**。`ThreadPoolExecutor` 默认使用 `Executors.defaultThreadFactory()` 创建用户线程。如果需要守护线程池，自定义 `ThreadFactory`：

```java
ExecutorService daemonPool = Executors.newFixedThreadPool(2, r -> {
    Thread t = new Thread(r);
    t.setDaemon(true);
    t.setName("daemon-pool-" + t.getId());
    return t;
});
```

## 七、一句话总结

> 守护线程是"**陪跑不陪终**"的后台服务线程——随用户线程而生，随用户线程全灭而止，finally 不保证，关键业务不用它，GC/JIT/监控才是它的家。
