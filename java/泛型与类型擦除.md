# 泛型与类型擦除

泛型题的分层很明显：用熟了答 PECS，学透了答**类型擦除与 Signature 属性**，P7 需要后者。

---

## 一、为什么需要泛型

```java
// 没有泛型（JDK5 前）：Object 进、强转出，运行期才炸
List list = new ArrayList();
list.add("a");
Integer i = (Integer) list.get(0);   // ClassCastException

// 有泛型：编译期检查 + 免强转 + 文档化
List<String> list2 = new ArrayList<>();
// list2.add(1);  ✗ 编译不过——错误左移到编译期
```

泛型是**编译期机制**：类型检查、类型推断都发生在编译时，运行期「忘了」类型——这就是类型擦除。

---

## 二、类型擦除（必考核心）

### 擦成什么

```java
<T>      T method(T t)  →  Object method(Object t)      // 无限定 → Object
<T extends Number>  →  Number                            // 有限定 → 左边界
List<String> 与 List<Integer> 运行期是同一个 Class 对象
```

### 擦除的证据（追问标准答法）

| 写法 | 结果 | 原因 |
|:---|:---|:---|
| `new T()` / `new T[]` | 编译不过 | 运行期不知道 T 是什么 |
| `obj instanceof List<String>` | 编译不过 | 运行期无参数类型信息 |
| `catch (MyEx<String> e)` | 编译不过 | 两个擦除后相同的 catch 不可区分 |

### 类型信息并没有完全丢：Signature 属性（加分点）

```java
// 反射仍能拿到泛型参数——信息存在字节码的 Signature 属性里（方法/字段元数据）
Field f = Pair.class.getDeclaredField("value");
Type t = f.getGenericType();        // ParameterizedType → String
```

这就是 **Gson `TypeToken`、Jackson `TypeReference`、Spring `ParameterizedTypeReference`** 的原理：用匿名子类把泛型参数固化在超类签名里，运行期反射读取——**「擦除的是实例类型，保留的是声明处的结构类型」**。

### 桥方法（bridge method）

```java
class MyComparator implements Comparator<Integer> {
    public int compare(Integer a, Integer b) { ... }   // 你的实现
}
// 擦除后接口方法是 compare(Object, Object)，编译器自动生成桥方法：
// public int compare(Object a, Object b) { return compare((Integer)a, (Integer)b); }
```
桥方法实现了「擦除后多态仍然正确」，反射遍历方法时可能看到它（`isBridge()` 判断）。

## 三、通配符与 PECS（必考）

```java
List<? extends Number> read;   // 生产者：只读（get 出来是 Number）
read.add(1);                   // ✗ 编译不过：编译器不知道确切子类型，拒绝写入

List<? super Integer> write;   // 消费者：可写 Integer
write.add(1);                  // ✓ Integer 及其子类都满足「Integer 的超类」
Object o = write.get(0);       // 只能以 Object 读出
```

| 记法 | 含义 | JDK 案例 |
|:---|:---|:---|
| **PECS** | Producer Extends, Consumer Super | `Collections.copy(List<? super T> dest, List<? extends T> src)`：src 生产数据用 extends，dest 消费数据用 super |
| `List<?>` | 无界通配：未知类型，除 null 外不可写 | `List<?>` ≠ `List<Object>`：前者是「某种类型的列表」（`List<String>` 能赋给它），后者是「Object 列表」（`List<String>` **不能**赋给它） |

> 白板推导：`? extends Number` 意为「Number 的某个子类型的列表」，编译器不知道具体是哪个 → 拒绝一切写入；`? super Integer` 意为「Integer 的某个超类」→ 放 Integer 永远合法。

## 四、数组与泛型的协变差异（高频追问）

```java
Object[] arr = new String[1];   // ✓ 数组协变（运行期检查）
arr[0] = 1;                     // ✓ 编译过，运行期 ArrayStoreException

List<Object> list = new ArrayList<String>();   // ✗ 泛型不变（编译期拦截）
```

- 数组**协变**：类型信息在运行期真实存在（数组头带 componentType），所以运行期兜底但把错误推迟；
- 泛型**不变**：擦除后无运行期类型，只能把检查放到编译期——这正是泛型更安全的原因；
- 所以 `List<String>` 不是 `List<Object>` 的子类型；想要通用读，用 `List<? extends Object>`。

---

## 五、泛型约束清单（易错合集）

| 不能 | 原因 |
|:---|:---|
| `new T()` / `new T[10]` | 运行期无 T 信息（可用 Class\<T> 传入 + 反射构造替代） |
| 泛型类静态成员引用 T | T 属于实例，静态成员属于类 |
| `instanceof List<String>` | 擦除 |
| 泛型类 extends Throwable | 泛型异常不能被多次 catch 区分 |
| 基本类型做参数 | `List<int>` 不行 → 装箱为 `List<Integer>`（性能话题的来源） |

---

## 一句话总结

**泛型 = 编译期类型安全 + 运行期擦除**：无限定擦成 Object、限定擦成边界，参数类型只存在 **Signature 元数据**里（TypeToken 系原理）；**PECS 决定通配方向（生产 extends 只读、消费 super 可写）**；数组协变靠运行期检查、泛型不变靠编译期拦截——后者更安全的根源。
