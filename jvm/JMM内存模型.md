# JMM 内存模型（Java Memory Model）

JMM 定义了**多线程下变量的读写规则**——即一个线程对共享变量的修改，何时、以何种顺序对其他线程可见。它是理解 `volatile`、`synchronized`、并发正确性的理论根基。注意：**JMM 是抽象规范，不是内存结构**（别和 [内存结构.md](内存结构.md) 混）。

---

## 一、为什么需要 JMM？三大问题

现代 CPU + 编译器为了性能会做各种优化（缓存、乱序），带来并发三大问题：

| 问题 | 根因 | 举例 |
|:---|:---|:---|
| **可见性** | 每个线程有自己的工作内存（CPU 缓存），改了不一定立刻同步到主内存 | 线程 A 改了 flag，线程 B 还在读旧值，死循环 |
| **原子性** | 一个操作被拆成多条指令，中间可能被打断 | `i++` 实际是读-改-写三步 |
| **有序性** | 编译器/CPU 会**指令重排**，只保证单线程结果不变 | 双重检查锁的对象「半初始化」问题 |

> JMM 通过规定**主内存 / 工作内存**的交互协议，以及 `happens-before` 规则，来约束这三个问题。

## 二、主内存与工作内存

```
       ┌──────────── 主内存 Main Memory ────────────┐
       │        共享变量（对应堆中实例字段等）          │
       └───────────────┬───────────────┬────────────┘
             read/write │               │ read/write
       ┌───────────────▼──┐         ┌───▼───────────────┐
       │  线程A 工作内存      │         │  线程B 工作内存       │
       │ （共享变量的副本）    │         │ （共享变量的副本）     │
       └──────────────────┘         └────────────────────┘
```

- 线程对变量的所有操作都在**工作内存**（副本）中进行，不能直接读写主内存。
- 线程间变量传递必须通过**主内存**中转。
- 这正是**可见性问题**的来源：A 的工作内存改了，没及时刷回主内存 / B 没重新从主内存读。

---

## 三、happens-before 原则（JMM 的核心）

**happens-before** 定义了「一个操作的结果对另一个操作可见」的偏序关系。**只要满足 hb，就保证可见性和有序性**，不必关心底层如何实现。

| 规则 | 含义 |
|:---|:---|
| **程序顺序规则** | 单线程内，前面的操作 hb 后面的操作 |
| **volatile 规则** | 对 volatile 变量的**写** hb 后续对它的**读** |
| **锁规则** | 对一个锁的**解锁** hb 后续对它的**加锁** |
| **传递性** | A hb B，B hb C，则 A hb C |
| **线程启动规则** | `Thread.start()` hb 该线程的所有操作 |
| **线程终止规则** | 线程所有操作 hb 其他线程检测到它终止（`join()` 返回） |

> 关键认知：hb **不代表时间上的先后**，而是**「可见性 + 有序性」的保证**。写并发代码只需保证关键操作间存在 hb 关系，就无需手动加内存屏障。

## 四、volatile 详解（高频）

`volatile` 是最轻量的同步手段，提供两个保证 + 一个不保证：

| 保证 | 说明 |
|:---|:---|
| ✅ **可见性** | 写 volatile 立即刷回主内存，读 volatile 立即从主内存读最新值 |
| ✅ **有序性**（禁止重排） | 通过**内存屏障**禁止 volatile 前后的特定指令重排序 |
| ❌ **不保证原子性** | `volatile int i; i++` 仍不安全（复合操作），要原子类或锁 |

### volatile 的两个经典用途

**1. 状态标志（利用可见性）**

```java
private volatile boolean running = true;

public void stop() { running = false; }   // 其他线程立即可见

public void run() {
    while (running) { /* 工作 */ }          // 没 volatile 可能死循环
}
```

**2. 双重检查锁 DCL 单例（利用禁止重排）**

```java
public class Singleton {
    // volatile 必不可少！
    private static volatile Singleton instance;
    public static Singleton getInstance() {
        if (instance == null) {                 // 第一次检查（免锁）
            synchronized (Singleton.class) {
                if (instance == null) {          // 第二次检查
                    instance = new Singleton();  // 见下方重排分析
                }
            }
        }
        return instance;
    }
}
```

> `instance = new Singleton()` 分三步：①分配内存 ②初始化对象 ③引用指向内存。②③可能被**重排**成①③②，导致另一线程看到「非 null 但未初始化」的半成品对象。`volatile` 禁止这种重排，DCL 才安全。

## 五、内存屏障与底层实现（P7 深度）

JMM 的有序性靠**内存屏障（Memory Barrier）**落地，编译器在 volatile 读写前后插入屏障：

| 屏障类型 | 作用 |
|:---|:---|
| LoadLoad | 屏障前的读，先于屏障后的读完成 |
| StoreStore | 屏障前的写，先于屏障后的写完成 |
| LoadStore | 屏障前的读，先于屏障后的写完成 |
| StoreLoad | 全能屏障，开销最大（volatile 写后插入） |

- **volatile 写**：前插 StoreStore，后插 StoreLoad → 保证写之前的操作不重排到写之后，且写立即可见。
- **volatile 读**：后插 LoadLoad、LoadStore → 保证读之后的操作不重排到读之前。

在 x86 上，StoreLoad 屏障通常用 `lock` 前缀指令实现（如 `lock addl`）。

## 六、两条基本原则

| 原则 | 含义 | 意义 |
|:---|:---|:---|
| **as-if-serial** | 不管怎么重排，**单线程**的执行结果不能变 | 保证单线程程序员无感 |
| **happens-before** | 正确同步的**多线程**程序按 hb 规则执行 | 保证多线程可见性/有序性 |

> 重排的边界：单线程看 as-if-serial（有数据依赖的不能重排），多线程看 happens-before。

---

## 七、JMM 与 synchronized / final

| 关键字 | JMM 语义 |
|:---|:---|
| **synchronized** | 加锁时清空工作内存、从主内存重读；解锁时把工作内存刷回主内存 → 同时保证原子性、可见性、有序性 |
| **final** | 正确构造（未逸出 this）的 final 字段，对象发布后其他线程一定能看到构造完成的值 |
| **volatile** | 可见性 + 有序性，不保证原子性 |

---

## 八、易错点

| 易错点 | 澄清 |
|:---|:---|
| **JMM 就是 JVM 内存结构** | JMM 是**并发规范**（抽象规则），运行时数据区是**物理内存划分**，两码事 |
| **volatile 保证原子性** | 不保证，`i++` 仍需 `AtomicInteger` 或锁 |
| **DCL 不加 volatile 也行** | 不加会有半初始化对象风险 |
| **happens-before = 时间先后** | 是「可见性 + 有序性」保证，不等于执行时间顺序 |
| **重排会破坏单线程正确性** | as-if-serial 保证单线程结果不变，重排只影响未正确同步的多线程 |

---

## 九、一句话总结

JMM 是约束**多线程共享变量可见性/有序性**的抽象规范：线程只操作**工作内存副本**、通过**主内存**交换数据，这引出可见性/原子性/有序性三大问题。**happens-before** 是判断并发正确性的金标准；**volatile** 靠内存屏障提供可见性和禁止重排（但不保证原子性），是理解 DCL 单例、状态标志的关键；**as-if-serial** 管单线程、**happens-before** 管多线程。
