# JVM 内存结构（运行时数据区）

JVM 在执行 Java 程序时，把它管理的内存划分为若干**运行时数据区**。理解每块区域「存什么、线程是否共享、什么时候 OOM」，是 JVM 面试的地基。

---

## 一、运行时数据区全景

```
┌───────────────────────── JVM 运行时数据区 ─────────────────────────┐
│                                                                    │
│   线程私有（随线程生灭）          线程共享（随 JVM 生灭）              │
│   ┌──────────────┐              ┌───────────────────────────┐     │
│   │ 程序计数器 PC  │              │            堆 Heap          │     │
│   ├──────────────┤              │  （对象实例，GC 主战场）      │     │
│   │ 虚拟机栈 VM    │              ├───────────────────────────┤     │
│   │  Stack        │              │   方法区 / 元空间 Metaspace  │     │
│   ├──────────────┤              │  （类元信息、运行时常量池）   │     │
│   │ 本地方法栈     │              └───────────────────────────┘     │
│   │ Native Stack  │                                                │
│   └──────────────┘         直接内存 Direct Memory（堆外，NIO 用）    │
└────────────────────────────────────────────────────────────────────┘
```

| 区域 | 线程 | 存什么 | 是否 GC | OOM? |
|:---|:---:|:---|:---:|:---:|
| **程序计数器** | 私有 | 当前线程执行字节码的行号指示器 | 否 | **唯一不 OOM** |
| **虚拟机栈** | 私有 | 栈帧（局部变量表、操作数栈…） | 否 | ✅ SOF / OOM |
| **本地方法栈** | 私有 | native 方法的栈信息 | 否 | ✅ SOF / OOM |
| **堆** | 共享 | 对象实例、数组 | ✅ 主战场 | ✅ OOM |
| **方法区 / 元空间** | 共享 | 类元信息、常量、静态变量 | ✅ 较少 | ✅ OOM |
| **直接内存** | 共享 | NIO DirectByteBuffer 堆外内存 | 否（靠 Cleaner） | ✅ OOM |

## 二、线程私有区域

### 1. 程序计数器（Program Counter Register）

记录当前线程**正在执行的字节码指令地址**（行号）。线程切换后能恢复到正确位置。

- 占用内存极小，**唯一一个不会抛 `OutOfMemoryError` 的区域**。
- 执行 native 方法时值为 `undefined`（native 不由字节码驱动）。

### 2. 虚拟机栈（JVM Stack）

每个方法调用对应一个**栈帧（Stack Frame）**，入栈执行、出栈返回。栈帧包含：

| 栈帧组成 | 作用 |
|:---|:---|
| **局部变量表** | 存方法参数、局部变量（基本类型、对象引用、returnAddress），以**变量槽 slot** 为单位 |
| **操作数栈** | 字节码运算的工作区（如 `iadd` 从栈弹两数、压回结果） |
| **动态链接** | 指向运行时常量池中该方法的引用，支持多态 |
| **方法返回地址** | 方法结束后回到调用处 |

两种异常：

| 异常 | 触发条件 | 参数 |
|:---|:---|:---|
| `StackOverflowError` | 栈深度超限（如无限递归） | `-Xss` 控制单线程栈大小 |
| `OutOfMemoryError` | 栈可动态扩展但无法申请到内存（线程过多） | — |

> 面试常问：**局部变量表大小编译期就确定**，运行期不变。基本类型变量直接存在栈上，对象只存**引用**，实例在堆上。

### 3. 本地方法栈

与虚拟机栈类似，区别是它服务 **native 方法**（C/C++ 实现）。HotSpot 直接把二者合二为一。

## 三、线程共享区域

### 1. 堆（Heap）—— GC 主战场

存放几乎所有**对象实例和数组**，是垃圾回收的主要区域。逻辑上分代（详见 [垃圾回收算法.md](垃圾回收算法.md)）：

```
                        堆 Heap
┌───────────────────────────┬───────────────────────┐
│        新生代 Young          │       老年代 Old        │
│  ┌──────┬────────┬────────┐│                       │
│  │ Eden │Survivor│Survivor ││   长寿对象、大对象      │
│  │      │  S0/from│ S1/to  ││                       │
│  └──────┴────────┴────────┘│                       │
│      默认比例 8 : 1 : 1      │  新生代 : 老年代 = 1 : 2 │
└───────────────────────────┴───────────────────────┘
```

- `-Xms` 初始堆、`-Xmx` 最大堆，生产环境常设为**相等**避免动态扩容抖动。
- 抛 `OutOfMemoryError: Java heap space`——最常见的 OOM。

### 2. 方法区（Method Area）与元空间（Metaspace）

存**类的元信息**：类结构、字段/方法数据、运行时常量池、静态变量、JIT 编译后的代码等。

**演进历史（重要）**：

| 版本 | 实现 | 位置 | 问题 |
|:---|:---|:---|:---|
| JDK 7 及以前 | **永久代 PermGen** | 堆内 | 大小固定难调，易 `OOM: PermGen space` |
| **JDK 8+** | **元空间 Metaspace** | **本地内存（堆外）** | 默认受物理内存限制，`-XX:MaxMetaspaceSize` 控制 |

> 为什么用元空间替代永久代？永久代大小与堆绑定、难以调优，且不利于类卸载；元空间用本地内存，上限更灵活，`OOM: Metaspace` 通常是类加载器泄漏（如反复热部署、动态代理生成大量类）。

**字符串常量池（String Pool）**：JDK 7 起从永久代移到**堆**中，`intern()` 行为随之变化。

### 3. 直接内存（Direct Memory）

不属于运行时数据区，但常被问到。NIO 的 `DirectByteBuffer` 通过 `Unsafe` 分配**堆外内存**，读写少一次拷贝（零拷贝），性能高。

- 不受 `-Xmx` 限制，由 `-XX:MaxDirectMemorySize` 控制。
- 靠 `Cleaner`（虚引用）在对象回收时释放，管理不当会 `OOM: Direct buffer memory`。

## 四、一图看懂 OOM 分类（P7 必答）

| OOM 类型 | 区域 | 常见原因 | 排查方向 |
|:---|:---|:---|:---|
| `Java heap space` | 堆 | 内存泄漏、大对象、缓存无上限 | dump 分析（MAT）、看 GC Roots 引用链 |
| `GC overhead limit exceeded` | 堆 | GC 占用 >98% 时间却回收 <2% | 同上，说明堆濒临爆满 |
| `Metaspace` | 元空间 | 类加载器泄漏、动态生成大量类 | 看加载类数、类加载器数量 |
| `unable to create new native thread` | 栈/系统 | 线程数过多，每线程占 `-Xss` | 减少线程、调小 `-Xss`、查线程池 |
| `Direct buffer memory` | 直接内存 | DirectByteBuffer 未释放 | 检查 NIO / Netty 堆外用量 |
| `StackOverflowError` | 虚拟机栈 | 递归过深、栈帧过大 | 查递归出口、调 `-Xss` |

## 五、易错点

| 易错点 | 澄清 |
|:---|:---|
| **String 常量池在方法区** | JDK 7 起已移到**堆**中 |
| **静态变量存在方法区** | JDK 7 起随类的 Class 对象存到**堆**（元空间存类元信息，不存静态变量实例） |
| **元空间在堆里** | 元空间在**本地内存**，不占堆 |
| **PC 会 OOM** | 程序计数器是唯一不 OOM 的区域 |
| **对象一定在堆上** | 逃逸分析后可能**栈上分配**，见 [对象与内存分配.md](对象与内存分配.md) |
| **`-Xss` 是总栈大小** | `-Xss` 是**每个线程**的栈大小 |

---

## 六、一句话总结

JVM 运行时数据区分**线程私有**（PC、虚拟机栈、本地方法栈）和**线程共享**（堆、方法区/元空间）两类，外加堆外的直接内存。**堆**是对象实例和 GC 的主战场，**元空间**（JDK 8 起取代永久代、位于本地内存）存类元信息。记牢每块区域「存什么 + 对应哪种 OOM」，就能应对大部分内存类追问。
