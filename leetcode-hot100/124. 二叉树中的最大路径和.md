## 题目描述

二叉树中的 **路径** 被定义为一条节点序列，序列中每对相邻节点之间都存在一条边。同一个节点在一条路径序列中 **至多出现一次** 。该路径 **至少包含一个** 节点，且不一定经过根节点。

**路径和** 是路径中各节点值的总和。

给你一个二叉树的根节点 `root` ，返回其 **最大路径和** 。

---

## 示例

**示例 1**

```
输入：root = [1,2,3]
     1
    / \
   2   3
输出：6
解释：最优路径是 2 -> 1 -> 3 ，路径和为 2 + 1 + 3 = 6
```

**示例 2**

```
输入：root = [-10,9,20,null,null,15,7]
      -10
      / \
     9   20
        /  \
       15   7
输出：42
解释：最优路径是 15 -> 20 -> 7 ，路径和为 15 + 20 + 7 = 42
```

## 思路

### 核心：区分「返回给父节点的值」与「在当前节点更新的答案」

一条路径在某个节点可以「拐弯」——从左子树上来、经过该节点、再下到右子树。但这条**拐弯路径无法再向上延伸**（父节点接不上一个已经用了左右两支的路径）。所以对每个节点要算两个不同的量：

- **向父节点返回的「单边最大贡献」** `gain(node)`：从 `node` 出发**只能往下走一条边**（要么不往下，要么选左/右中较大的一支），这样父节点才能接着往上拼。
  `gain(node) = node.val + max(0, max(gain(left), gain(right)))`
- **在 `node` 处更新的「拐点最大路径和」**：以 `node` 为最高点、左右都可以挂上的完整路径。
  `node.val + max(0, gain(left)) + max(0, gain(right))` → 用它更新全局答案 `maxSum`

```
      -10
      / \
     9   20
        /  \
       15   7
gain(15)=15, gain(7)=7
在20处拐点路径 = 20 + 15 + 7 = 42 → 更新全局 maxSum=42
gain(20) 返回给父 = 20 + max(15,7) = 35   （只能带一支上去）
在-10处拐点 = -10 + max(0,9) + max(0,35) = 34 < 42
答案 42 ✅
```

### 关键：负贡献用 0 截断

若子树的 `gain` 为负，带上它只会拖累路径和，**不如不要**——所以用 `max(0, gain(child))`，负的就当作 0（这条支不接）。

### 为什么必须后序遍历

当前节点的 `gain` 和拐点路径和都依赖左右子树的 `gain`，只能**先算孩子、再算自己**（左→右→根），这是后序。

- 时间复杂度：\(O(n)\)，每个节点访问一次
- 空间复杂度：\(O(h)\) 递归栈，`h` 为树高

## 代码

### 解法：后序 DFS + 全局维护答案（推荐）

```java
class Solution {
    private int maxSum = Integer.MIN_VALUE;    // 全局答案，可能全为负，初值取最小

    public int maxPathSum(TreeNode root) {
        gain(root);
        return maxSum;
    }

    // 返回：从 node 向下延伸「一条边」能获得的最大贡献
    private int gain(TreeNode node) {
        if (node == null) return 0;

        // 左右子树的贡献，负的截断为 0（不接这一支）
        int leftGain = Math.max(0, gain(node.left));
        int rightGain = Math.max(0, gain(node.right));

        // 以 node 为「拐点」的完整路径和（左 + 自己 + 右），更新全局答案
        maxSum = Math.max(maxSum, node.val + leftGain + rightGain);

        // 返回给父节点：只能选左右中较大的一支带上去
        return node.val + Math.max(leftGain, rightGain);
    }
}
```

## 个人总结

### 1. 全题灵魂：一个节点算两个量，用途不同

这是本题（也是「树形 DP 返回多信息」类题）的核心难点：

- **更新答案**用「拐点路径」：`node.val + 左贡献 + 右贡献`（左右都挂上，但这条路径到此为止，不能再上延）；
- **返回给父**用「单边贡献」：`node.val + max(左贡献, 右贡献)`（只能带一支，父节点才能继续拼）。

**想不清就记：答案里可以「拐弯」，返回值里不能「拐弯」。** 混淆这两者是本题最常见的错。

### 2. 负贡献截断为 0

`max(0, gain(child))`：子树整体是负担时就不接这一支。这一步让算法自动跳过拖后腿的分支。注意 `node.val` 本身**不**截断（路径至少含一个节点，哪怕它是负的也得算）。

### 3. 全局答案初值取 `Integer.MIN_VALUE`

节点值可为负，整棵树可能全是负数（如只有一个 `-3`，答案就是 `-3`）。若把 `maxSum` 初值设为 0，会错误返回 0。**必须用 `Integer.MIN_VALUE`**，保证至少选一个节点。

### 4. 和「打家劫舍 III」的异同

和你整理的 [337. 打家劫舍 III](337.%20打家劫舍%20III.md) 同属「后序 DFS 携带信息给父节点」的树形 DP，但携带方式不同：

| | 返回给父的信息 | 答案在哪更新 |
|:---|:---|:---|
| 337 打家劫舍 III | `[不偷, 偷]` 两个值 | 最后取根的两值最大 |
| 124 最大路径和 | 一个「单边最大贡献」 | 遍历中每个节点用「拐点路径」更新全局 |

**共同套路：DFS 返回值 ≠ 最终答案，答案往往在遍历过程中用全局变量维护。**

### 5. 后序遍历是树形 DP 的天然顺序

当前节点依赖左右孩子的计算结果，必须「先递归孩子，再算自己」。凡是「子树信息汇总到父节点」的树 DP 都用后序。
