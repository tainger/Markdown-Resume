## 题目描述

给定一个未排序的整数数组 `nums` ，找出数字连续的最长序列（不要求序列元素在原数组中连续）的长度。

请你设计并实现时间复杂度为 `O(n)` 的算法解决此问题。

---

## 示例

**示例 1**

```
输入：nums = [100,4,200,1,3,2]
输出：4
解释：最长数字连续序列是 [1, 2, 3, 4]。它的长度为 4。
```

**示例 2**

```
输入：nums = [0,3,7,2,5,8,4,6,0,1]
输出：9
```

**示例 3**

```
输入：nums = [1,0,1,2]
输出：3
```

- `-10^9 <= nums[i] <= 10^9`

## 思路

### 核心思想

要找「连续」序列（如 1,2,3,4），最自然的想法是排序后扫一遍，但排序是 `O(n log n)`，不满足题目 `O(n)` 要求。关键洞察：**用哈希集合把 O(1) 判断「某个数在不在」，并且只从每个连续序列的「起点」开始向上数**——一个数 `num` 是起点当且仅当 `num-1` 不在集合里。这样每个数最多被访问两次（一次作为遍历、一次作为某序列的成员），整体 `O(n)`。

### 解法一：排序（先跑通，但不满足 O(n)）

排序后线性扫描，统计当前连续段长度，遇到断点重置，注意跳过重复元素。

- 时间复杂度：\(O(n\log n)\)（排序主导），空间 \(O(1)\) 或 \(O(\log n)\)。思路直白，但没满足题目要求。

### 解法二：哈希集合 + 只从起点扩展（推荐，O(n)）

1. 把所有数放进 `HashSet`（自动去重，且 O(1) 查存在）。
2. 遍历集合中每个数 `num`：
   - **只有当 `num-1` 不在集合中**，`num` 才是某个连续序列的**起点**，才开始计数；
   - 从 `num` 出发，不断查 `num+1`、`num+2`… 是否在集合中，累加长度；
   - 更新全局最大长度。

```
nums = [100,4,200,1,3,2] → set = {100,4,200,1,3,2}
遍历：
  100: 99 不在 → 起点，向上数 101 不在 → 长度 1
  4:   3 在 → 不是起点，跳过（会被 1 那条数到）
  200: 199 不在 → 起点，长度 1
  1:   0 不在 → 起点，1→2→3→4 都在 → 长度 4 ✅
  3,2: 前驱都在 → 跳过
最长 = 4
```

**为什么是 O(n) 而不是 O(n²)？** 只有序列**起点**才会触发向上扩展的 while 循环，非起点直接跳过。每个数在「向上数」时最多被访问一次，所以内层 while 的总执行次数是 O(n)，不是每个数都跑一遍 while。

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(n)\)（哈希集合）。

## 代码

### 解法一：排序（先跑通，不满足 O(n)）

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        if (nums.length == 0) return 0;
        Arrays.sort(nums);
        int longest = 1, cur = 1;
        for (int i = 1; i < nums.length; i++) {
            if (nums[i] == nums[i - 1]) continue;          // 跳过重复
            if (nums[i] == nums[i - 1] + 1) {
                cur++;                                     // 连续，累加
            } else {
                cur = 1;                                   // 断了，重置
            }
            longest = Math.max(longest, cur);
        }
        return longest;
    }
}
```

### 解法二：哈希集合 + 只从起点扩展（推荐，O(n)）

```java
class Solution {
    public int longestConsecutive(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int x : nums) set.add(x);                     // 去重 + O(1) 查存在

        int longest = 0;
        for (int num : set) {                              // 遍历 set，避免重复元素重复计算
            // 只有 num-1 不存在时，num 才是序列起点
            if (!set.contains(num - 1)) {
                int cur = num;
                int len = 1;
                while (set.contains(cur + 1)) {            // 向上不断扩展
                    cur++;
                    len++;
                }
                longest = Math.max(longest, len);
            }
        }
        return longest;
    }
}
```

## 个人总结

### 1. 难点是「O(n) 要求」把排序堵死

看到「连续序列」第一反应是排序，但排序 `O(n log n)` 不达标。**做题先看复杂度要求**——正是这条要求逼出「哈希集合 + 只从起点扩展」的巧解。看到「无序数组 + 要求 O(n) + 判存在」，就该想到 HashSet。

### 2. 精髓：只从「序列起点」起头计数

如果对每个数都向上、向下扩展，会重复且退化成 `O(n²)`。关键剪枝是：**只有 `num-1` 不在集合里时，`num` 才是起点**，才触发扩展。这样每个连续序列只从最小的那个数被数一次，其余成员全跳过。**这一句 `if (!set.contains(num-1))` 是全题灵魂。**

### 3. 为什么总复杂度是 O(n)

不是「遍历 n 个数 × 每个数跑 while」= O(n²)。因为 while 只对起点触发，且每个数在「向上数」的过程中**至多被访问一次**（作为某条序列的成员）。所以外层遍历 O(n) + 内层 while 累计 O(n) = O(n)。理解这点才能反驳面试官「这不是双重循环吗」的追问。

### 4. 遍历 set 而不是遍历 nums

遍历原数组 `nums` 会对**重复元素**重复计算（虽然结果不错但浪费）。遍历去重后的 `set` 更干净。若一定遍历 `nums`，靠 `!set.contains(num-1)` 的起点判断也能保证正确，只是重复数会白跑几次。

### 5. 边界：空数组返回 0

`nums` 长度可能为 0，`longest` 初始化为 0 而非 1，否则空数组会错返回 1。排序解法要单独特判空数组。

### 6. 两种解法取舍

| 解法 | 时间 | 空间 | 定位 |
|:---|:---:|:---:|:---|
| 排序 | \(O(n\log n)\) | \(O(1)\)~\(O(\log n)\) | 直观，不满足 O(n) |
| 哈希集合 | \(O(n)\) ✅ | \(O(n)\) | 满足要求，最优 |

**面试建议**：先说排序（表明会做），再点出它不满足 O(n)，最后给哈希集合解法并**重点解释「只从起点扩展」为何保证 O(n)**——这是本题最出彩的地方。
