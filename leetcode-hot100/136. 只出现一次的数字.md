## 题目描述

给你一个 **非空** 整数数组 `nums` ，除了某个元素只出现**一次**以外，其余每个元素均出现**两次**。找出那个只出现了一次的元素。

你必须设计并实现线性时间复杂度的算法来解决此问题，且该算法只使用**常量**额外空间。

## 示例

**示例 1**

```
输入：nums = [2,2,1]
输出：1
```

**示例 2**

```
输入：nums = [4,1,2,1,2]
输出：4
```

**示例 3**

```
输入：nums = [1]
输出：1
```

---

## 提示

- `1 <= nums.length <= 3 * 10^4`
- `-3 * 10^4 <= nums[i] <= 3 * 10^4`
- 除了某个元素只出现一次以外，其余每个元素均出现两次

---

## 思路

### 核心思想

异或（XOR，`⊕`）三条性质：

| 性质 | 含义 |
|:---|:---|
| `x ⊕ x = 0` | 相同的数互相抵消 |
| `x ⊕ 0 = x` | 0 是异或的单位元 |
| 交换律 + 结合律 | 异或结果与顺序无关 |

把所有数**全部异或**在一起：由交换律可重排为「成对的数相邻 + 孤立的数」，成对的先抵消成 0，最后只剩那个只出现一次的数。

```
[4,1,2,1,2] → 4 ⊕ 1 ⊕ 2 ⊕ 1 ⊕ 2
            = 4 ⊕ (1 ⊕ 1) ⊕ (2 ⊕ 2)
            = 4 ⊕ 0 ⊕ 0
            = 4 ✅
```

### 解法一：哈希表（对比基准，不满足常量空间）

用 `HashSet`：元素不在集合中就加入，已在集合中说明第二次出现，删除它；遍历完集合里剩下的就是答案。（也可用 `HashMap` 计数再找 count = 1 的键。）

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(n)\)——**不满足题面的常量空间要求**，作为铺垫对比

### 解法二：异或位运算（推荐）

1. `ans = 0`，遍历数组执行 `ans ^= num`
2. 返回 `ans`

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\)

## 代码

### 解法一：哈希表（空间 O(n)，对比用）

```java
class Solution {
    public int singleNumber(int[] nums) {
        Set<Integer> set = new HashSet<>();
        for (int num : nums) {
            if (!set.add(num)) {          // add 返回 false → 已存在，第二次出现
                set.remove(num);          // 成对抵消，直接移除
            }
        }
        return set.iterator().next();     // 最后剩下的就是只出现一次的数
    }
}
```

### 解法二：异或位运算（推荐）

```java
class Solution {
    public int singleNumber(int[] nums) {
        int ans = 0;
        for (int num : nums) {
            ans ^= num;   // 成对的数异或抵消为 0，最后只剩出现一次的数
        }
        return ans;
    }
}
```

## 个人总结

### 1. 「成对抵消」是异或的专属技能，前提是出现两次

异或之所以可行，靠的是 `x⊕x=0`（两次出现归零）和交换律（顺序无关、无需真的相邻）。**推广到出现三次就不行**——`x⊕x⊕x = x` 不归零，见下表：

| 题目 | 条件 | 思路 |
|:---|:---|:---|
| 136（本题） | 其余出现 **2** 次 | 全部异或 |
| 137. 只出现一次的数字 II | 其余出现 **3** 次 | 逐位计数 `bit % 3`，或三进制逻辑运算 |
| 260. 只出现一次的数字 III | **两个**数出现 1 次，其余 2 次 | 全部异或得 `x⊕y`，取 `lowbit` 分两组各自异或 |

看到「其余出现两次 + 只剩一个」的描述，第一反应就该是异或。

### 2. 题面强制「线性时间 + 常量空间」，就是指向异或的提示

普通数组题这两个约束同时出现，基本是在点名位运算（或原地交换类技巧）。面试策略：先说哈希表 \(O(n)/O(n)\) 的朴素解，再指出空间不满足，顺势引出异或——展示「提出解 → 发现不满足约束 → 优化」的完整过程，比直接甩答案好。

### 3. 位运算小工具箱（本族题常用）

| 技巧 | 表达式 | 用途 |
|:---|:---|:---|
| 自反消去 | `a ^ a == 0` | 本题、去重 |
| 取最低位的 1 | `x & (-x)` | 260 按「该位为 0/1」分组 |
| 消去最低位的 1 | `x & (x - 1)` | 数 1 的个数（338 比特位计数） |
| 判奇偶 | `x & 1` | 替代 `x % 2` |

用户已刷 [338. 比特位计数](338.%20比特位计数.md)，可与本题一起归入「位运算基础包」。

### 4. 为什么哈希法里 `set.add()` 判重是优雅写法

`HashSet.add()` 的返回值直接告诉你「加之前存不存在」，一行完成「判重 + 抵消」，不必先 `contains` 再 `add/remove` 两次哈希查找。同理 `HashMap.getOrDefault` 计数也行，但写法冗长；面试写代码时优先用 API 的返回值简化逻辑。
