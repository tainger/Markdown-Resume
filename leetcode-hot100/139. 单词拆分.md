## 题目描述

给你一个字符串 `s` 和一个字符串列表 `wordDict` 作为字典。请你判断是否可以利用字典中出现的单词拼接出 `s` 。

**注意：** 不要求字典中出现的单词全部都使用，并且字典中的单词可以重复使用。

---

## 示例

**示例 1**

```
输入: s = "leetcode", wordDict = ["leet", "code"]
输出: true
解释: 返回 true 因为 "leetcode" 可以由 "leet" 和 "code" 拼接成。
```

**示例 2**

```
输入: s = "applepenapple", wordDict = ["apple", "pen"]
输出: true
解释: 返回 true 因为 "applepenapple" 可以由 "apple" "pen" "apple" 拼接成。
     注意，你可以重复使用字典中的单词。
```

**示例 3**

```
输入: s = "catsandog", wordDict = ["cats", "dog", "sand", "and", "cat"]
输出: false
```

---

## 提示

- `1 <= s.length <= 300`
- `1 <= wordDict.length <= 1000`
- `1 <= wordDict[i].length <= 20`
- `s` 和 `wordDict[i]` 仅由小写英文字母组成
- `wordDict` 中的所有字符串 **互不相同**

## 思路

### 核心思想

判断 `s` 能否被字典拆分：只要能找到一个切点 `j`，使得**前半段 `s[0..j)` 能被拆分**、且**后半段 `s[j..i)` 恰好是字典里的一个单词**，那么 `s[0..i)` 就能被拆分。这是一个「前缀能否拆分」的递推——天然的动态规划。因为单词可重复使用，本质是**完全背包**（求「能否装满」的布尔版）。

### 解法一：回溯 / 暴力（先跑通，会超时）

从起点 `start` 出发，枚举所有以 `start` 开头、且在字典里的单词，递归判断剩余部分。任一分支成功即返回 true。

- 时间复杂度：最坏 \(O(2^n)\)，指数级，会超时。存在大量**重复子问题**（同一个 `start` 被反复计算）。

### 解法二：记忆化搜索（回溯 + 缓存）

在回溯基础上，用 `memo[start]` 缓存「从 `start` 开始的后缀能否拆分」的结果，避免重复计算。

- 时间复杂度：\(O(n^2)\)（`n` 个起点 × 每个起点最多 `n` 种切分），空间 \(O(n)\)。

### 解法三：动态规划（推荐）

**状态**：`dp[i]` = 字符串 `s` 的**前 `i` 个字符**（即 `s[0..i)`）能否被字典拆分。

**初始化**：`dp[0] = true`（空串可被"拆分"，是递推的基石）。

**转移**：对每个 `i`（1..n），枚举切点 `j`（0..i-1）：

```
若 dp[j] == true 且 s[j..i) 在字典中：
    dp[i] = true，break（找到一种拆法即可）
```

**答案**：`dp[n]`。

```
s = "leetcode", wordDict = {"leet","code"}
dp[0]=T
dp[4]: dp[0]=T 且 s[0..4)="leet"∈dict → dp[4]=T
dp[8]: dp[4]=T 且 s[4..8)="code"∈dict → dp[8]=T
→ 返回 dp[8]=true ✅
```

- 时间复杂度：\(O(n^2)\)（双层循环）+ 子串哈希查找；空间复杂度：\(O(n)\)。

## 代码

### 解法一：回溯（会超时，仅理解题意）

```java
class Solution {
    public boolean wordBreak(String s, List<String> wordDict) {
        Set<String> dict = new HashSet<>(wordDict);
        return backtrack(s, 0, dict);
    }

    // 判断 s[start..] 能否被拆分
    private boolean backtrack(String s, int start, Set<String> dict) {
        if (start == s.length()) return true;      // 走到末尾，全部拆完
        for (int end = start + 1; end <= s.length(); end++) {
            if (dict.contains(s.substring(start, end)) && backtrack(s, end, dict)) {
                return true;
            }
        }
        return false;
    }
}
```

### 解法二：记忆化搜索

```java
class Solution {
    public boolean wordBreak(String s, List<String> wordDict) {
        Set<String> dict = new HashSet<>(wordDict);
        // memo[start]：0=未算，1=可拆，-1=不可拆
        int[] memo = new int[s.length() + 1];
        return dfs(s, 0, dict, memo);
    }

    private boolean dfs(String s, int start, Set<String> dict, int[] memo) {
        if (start == s.length()) return true;
        if (memo[start] != 0) return memo[start] == 1;   // 命中缓存
        for (int end = start + 1; end <= s.length(); end++) {
            if (dict.contains(s.substring(start, end)) && dfs(s, end, dict, memo)) {
                memo[start] = 1;
                return true;
            }
        }
        memo[start] = -1;
        return false;
    }
}
```

### 解法三：动态规划（推荐）

```java
class Solution {
    public boolean wordBreak(String s, List<String> wordDict) {
        Set<String> dict = new HashSet<>(wordDict);
        int n = s.length();
        boolean[] dp = new boolean[n + 1];
        dp[0] = true;                              // 空串可拆分（递推基石）
        for (int i = 1; i <= n; i++) {
            for (int j = 0; j < i; j++) {
                // 前 j 个可拆 且 s[j..i) 是字典单词 → 前 i 个可拆
                if (dp[j] && dict.contains(s.substring(j, i))) {
                    dp[i] = true;
                    break;                         // 找到一种拆法即可
                }
            }
        }
        return dp[n];
    }
}
```

## 个人总结

### 1. 状态定义：dp[i] 是「前 i 个字符」能否拆分

注意 `dp[i]` 对应的是 `s[0..i)`（前 `i` 个字符，长度 `i`），下标错一位是常见 bug。`dp` 数组长度是 `n+1`，`dp[0]` 表示空串。看到「前缀是否满足某性质」就想到这种「长度维」DP。

### 2. dp[0] = true 是灵魂

`dp[0]=true` 表示空串可被"拆分"，它是所有递推的起点。没有它，`dp[i]` 永远推不出 true。类比背包问题里「容量为 0 时可以装满（啥都不装）」。

### 3. 本质是完全背包（单词可重复用）

单词能重复使用 → **完全背包**。`s` 是背包容量，`wordDict` 是可无限选的物品。这里求的是「能否恰好装满」的**布尔版**（`||` 累积），而不是求方案数或最大价值。理解这点能把它和 [322 零钱兑换](322.%20零钱兑换.md)、[416 分割等和子集](416.%20分割等和子集.md) 串成一类。

### 4. 从回溯到 DP 的优化链路

暴力回溯 `O(2^n)` 的病根是**重复子问题**（同一 `start` 反复算）→ 加 `memo` 变记忆化搜索 `O(n²)` → 改成自底向上的递推就是 DP。这条「暴力 → 记忆化 → DP」的链路是动态规划题的通用套路，面试时能完整讲出来很加分。

**重复计算到底重复在哪？** 单看一条递归链看不出来，重复发生在「**不同的切法组合殊途同归到同一个 `start`**」。因为 `backtrack(start)` 的返回值**只跟 `start` 有关**（跟前面怎么切到这里无关），同一个 `start` 被反复调用就是纯粹的重复。把递归树画开就一目了然：

```
s = "aaab", wordDict = ["a", "aa", "aaa"]

backtrack(0)
├─ 切 "a"   → backtrack(1)
│              ├─ 切 "a"  → backtrack(2)   ★
│              └─ 切 "aa" → backtrack(3)   ●
├─ 切 "aa"  → backtrack(2)   ★  ← 又算一次 backtrack(2)
│              └─ 切 "a"  → backtrack(3)   ●  ← 又算一次 backtrack(3)
└─ 切 "aaa" → backtrack(3)   ●  ← 还算一次 backtrack(3)
```

- `backtrack(2)`（★）被算 2 次：路径 `a+a` 和 `aa` 都停在下标 2；
- `backtrack(3)`（●）被算 3 次：`a+aa` / `aa+a` / `aaa` 都落到下标 3。

前缀切法不同，但落到同一 `start` 后「从这里到结尾能否拆」的子问题**完全相同**。互异的 `start` 只有 `n+1` 个（0~n），却用指数级调用去解，绝大部分是白算——这正是 `O(2^n)` 的来源。`memo[start]` 命中缓存就直接返回，把每个 `start` 压到最多算一次，复杂度降到 `O(n²)`。

### 5. 找到一种拆法就 break

`dp[i]` 只要有**一个**切点 `j` 满足条件就为 true，无需继续枚举，`break` 剪枝。别忘了这个小优化。

### 6. 三种解法取舍

| 解法 | 时间 | 空间 | 定位 |
|:---|:---:|:---:|:---|
| 回溯暴力 | \(O(2^n)\) | \(O(n)\) | 理解题意，会超时 |
| 记忆化搜索 | \(O(n^2)\) | \(O(n)\) | 自顶向下，好想 |
| 动态规划 | \(O(n^2)\) | \(O(n)\) ✅ | 自底向上，最优雅 |

**面试建议**：先说回溯（点出重复子问题），再讲记忆化，最后给 DP，并说明它本质是完全背包的布尔版——层层递进最出彩。
