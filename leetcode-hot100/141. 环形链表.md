## 题目描述

给你一个链表的头节点 `head` ，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

如果链表中存在环 ，则返回 `true` 。 否则，返回 `false` 。

## 示例

**示例 1**

```
输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2**

```
输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3**

```
输入：head = [1], pos = -1
输出：false
解释：链表中没有环。
```

## 思路

### 核心思想

「是否有环」=「遍历会不会永远走不完」。要么用哈希表记录访问过的节点（第二次到达同一节点即有环），要么用 **Floyd 快慢指针**：快指针每次走 2 步、慢指针每次走 1 步——进环后快指针每轮追近 1 步，必然相遇。

### 解法一：快慢指针（Floyd 判圈，推荐）

1. `slow`、`fast` 都从头出发：`slow` 每次走 1 步，`fast` 每次走 2 步
2. 有环：两者先后进环，相对速度为 1，最慢指针进环一圈内必然相遇
3. 无环：`fast` 或 `fast.next` 先到 `null`，循环退出
4. 相遇即返回 `true`

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\)

### 解法二：哈希表

1. 依次遍历链表，把每个节点存入 `HashSet`
2. 遇到 `null` → 无环；某个节点已在集合中 → 有环（第二次到达同一节点）

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(n)\)

## 代码

### 解法一：快慢指针（Floyd 判圈，推荐）

```java
/**
 * Definition for singly-linked list.
 * class ListNode {
 *     int val;
 *     ListNode next;
 *     ListNode(int x) {
 *         val = x;
 *         next = null;
 *     }
 * }
 */
public class Solution {
    public boolean hasCycle(ListNode head) {
        ListNode slow = head, fast = head;
        // 双判：fast 一次跨 2 步，fast 和 fast.next 都可能撞 null
        while (fast != null && fast.next != null) {
            slow = slow.next;      // 慢指针一次 1 步
            fast = fast.next.next; // 快指针一次 2 步
            if (slow == fast) {    // 相遇 ⇒ 有环
                return true;
            }
        }
        return false; // fast 走到链尾 ⇒ 无环
    }
}
```

### 解法二：哈希表

```java
public class Solution {
    public boolean hasCycle(ListNode head) {
        Set<ListNode> visited = new HashSet<>();
        for (ListNode cur = head; cur != null; cur = cur.next) {
            // 同一节点第二次出现 ⇒ 有环；add 返回 false 说明已存在
            if (!visited.add(cur)) {
                return true;
            }
        }
        return false; // 走到 null，无环
    }
}
```

## 个人总结

### 1. 为什么快指针一定能「追上」而不是「跳过」

```
进环后每一轮：fast 比 slow 多走 1 步，两者距离每轮缩短 1
  距离:  4 → 3 → 2 → 1 → 0（相遇）
```

相对速度为 1，相遇前距离逐轮 -1，**不存在跳过**。这是「步长差为 1」的必然结果——若 fast 一次走 3 步（相对速度 2），距离会从 1 直接跳到环长 -1，可能永远错过 slow 导致误判。

### 2. 循环条件是 `fast != null && fast.next != null`

无环时 fast 一次跨 2 步，可能「一步跨过 null」造成空指针异常，所以两个判断缺一不可，且先判 `fast` 再判 `fast.next`。

### 3. 相等判断必须放在移动之后

`slow` 和 `fast` 出发时都指向 `head`：若先比较再移动，链表非空时第一轮就误判为「有环」。正确顺序是**先各走一步，再比较**。

### 4. Floyd 判圈是 142 题的地基

本题只判「有没有环」；进阶题 142. 环形链表 II 要找**入环点**：相遇后把一个指针放回 `head`，两指针同速前进，再次相遇处即入环点（可由 `a = c + (n-1)·环长` 推导）。把本题的相遇写法记牢，142 就是顺水推舟。
