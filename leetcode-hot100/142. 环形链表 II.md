## 题目描述

给定一个链表的头节点 `head` ，返回链表开始入环的第一个节点。 如果链表无环，则返回 `null`。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。 为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（**索引从 0 开始**）。如果 `pos` 是 `-1`，则在该链表中没有环。**注意：`pos` 不作为参数进行传递**，仅仅是为了标识链表的实际情况。

**不允许修改** 链表。

## 思路

### 核心思想

分两步：**先判断有没有环，再找到环的入口**。快慢指针（Floyd 判环）能在 O(1) 空间同时解决——快指针每次走 2 步、慢指针走 1 步，若有环必相遇；相遇后再用一个巧妙的数学关系定位入口。

### 解法一：哈希表（最直观）

从头遍历，把访问过的**节点**存进 `HashSet`。第一个「已经出现过」的节点就是环入口；若走到 `null` 都没重复，则无环。

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(n)\)（存所有节点）。简单但不满足进阶的 O(1)。
- 注意存的是**节点引用**，不是节点的值（值可能重复）。

### 解法二：Floyd 快慢指针（推荐，O(1) 空间）

**第一步：判环 + 找相遇点**
`slow` 每次 1 步，`fast` 每次 2 步。无环则 `fast` 先到 `null`；有环则两者必在环内某点相遇。

**第二步：找环入口**
相遇后，把 `slow` 重置到 `head`，`fast`（或另设一指针）留在相遇点，两者**同速（每次 1 步）**前进，再次相遇的节点就是环入口。

**为什么第二步成立？（数学推导）**
设头到环入口距离为 `a`，环入口到相遇点距离为 `b`，相遇点绕环回到入口距离为 `c`（环长 = `b + c`）。

```
head --a--> 入口 --b--> 相遇点 --c--> 回到入口
```

相遇时：慢指针走了 `a + b`，快指针走了 `a + b + k(b+c)`（在环里多绕 k 圈）。
因为快是慢的两倍：`2(a + b) = a + b + k(b + c)`
化简得：`a = (k-1)(b+c) + c`。

含义：**从 head 走 `a` 步到入口** 等于 **从相遇点走 `c` 步（可能多绕几圈）也到入口**。所以两个指针从 head 和相遇点同速出发，会在入口相遇。

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\) ✅（最优，满足进阶）。

## 代码

### 解法一：哈希表

```java
public class Solution {
    public ListNode detectCycle(ListNode head) {
        Set<ListNode> seen = new HashSet<>();
        ListNode cur = head;
        while (cur != null) {
            if (!seen.add(cur)) {          // add 返回 false 说明节点已存在 → 环入口
                return cur;
            }
            cur = cur.next;
        }
        return null;                       // 走到 null，无环
    }
}
```

### 解法二：Floyd 快慢指针（推荐，O(1) 空间）

```java
public class Solution {
    public ListNode detectCycle(ListNode head) {
        ListNode slow = head, fast = head;
        // 第一步：判环 + 找相遇点
        while (fast != null && fast.next != null) {
            slow = slow.next;              // 走 1 步
            fast = fast.next.next;         // 走 2 步
            if (slow == fast) {            // 相遇 → 有环
                // 第二步：slow 回到 head，两指针同速找入口
                ListNode ptr = head;
                while (ptr != slow) {
                    ptr = ptr.next;
                    slow = slow.next;
                }
                return ptr;                // 相遇处即环入口
            }
        }
        return null;                       // fast 到达 null，无环
    }
}
```

## 个人总结

### 1. 分两步：先判环，再定位入口

很多人卡在「判出有环之后不知道怎么找入口」。要牢记 Floyd 是**两阶段**：第一阶段快慢相遇只证明有环、拿到相遇点；第二阶段才靠「head 与相遇点同速再走」找到入口。两步缺一不可。

### 2. 第二步的数学关系是全题精华

结论 `a = (k-1)(b+c) + c` 说明：**从头走到入口的距离 a**，恰好等于**从相遇点绕环走到入口的距离（c + 若干整圈）**。所以让一个指针回到 head、另一个留在相遇点，同速前进必在入口相遇。记不住推导也要记住这个结论和操作。

### 3. 循环条件为什么是 `fast != null && fast.next != null`

`fast` 一次走两步，要访问 `fast.next.next`，所以必须保证 `fast` 和 `fast.next` 都非空，否则空指针异常。这也是判「无环」的出口：`fast` 能走到 `null` 就说明没环。

### 4. 哈希表存的是节点引用，不是值

链表节点的**值可能重复**，用值判重会误判。必须存 `ListNode` 引用（靠对象地址判等），`HashSet<ListNode>` 天然按引用比较。

### 5. 两种解法取舍

| 解法 | 时间 | 空间 | 定位 |
|:---|:---:|:---:|:---|
| 哈希表 | \(O(n)\) | \(O(n)\) | 直观好写，不满足进阶 |
| 快慢指针 | \(O(n)\) | \(O(1)\) ✅ | 满足进阶，最优 |

**面试建议**：先说哈希表（表明会做），再讲快慢指针并**主动推导第二步的数学关系**——这是本题最出彩的地方。
