## 题目描述

请你设计并实现一个满足 **LRU (最近最少使用) 缓存** 约束的数据结构。

实现 `LRUCache` 类：

- `LRUCache(int capacity)` 以 **正整数** 作为容量 `capacity` 初始化 LRU 缓存
- `int get(int key)` 如果关键字 `key` 存在于缓存中，则返回关键字的值，否则返回 `-1` 。
- `void put(int key, int value)` 如果关键字 `key` 已经存在，则变更其数据值 `value` ；如果不存在，则向缓存中插入该组 `key-value` 。如果插入操作导致关键字数量超过 `capacity` ，则应该 **逐出** 最久未使用的关键字。

函数 `get` 和 `put` 必须以 `O(1)` 的平均时间复杂度运行。

## 示例

**示例**

```
输入
["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]
[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]
输出
[null, null, null, 1, null, -1, null, -1, 3, 4]

解释
LRUCache lRUCache = new LRUCache(2);
lRUCache.put(1, 1); // 缓存是 {1=1}
lRUCache.put(2, 2); // 缓存是 {1=1, 2=2}
lRUCache.get(1);    // 返回 1
lRUCache.put(3, 3); // 该操作会使得关键字 2 作废，缓存是 {1=1, 3=3}
lRUCache.get(2);    // 返回 -1 (未找到)
lRUCache.put(4, 4); // 该操作会使得关键字 1 作废，缓存是 {4=4, 3=3}
lRUCache.get(1);    // 返回 -1 (未找到)
lRUCache.get(3);    // 返回 3
lRUCache.get(4);    // 返回 4
```

## 思路

### 核心思想

两个 O(1) 需求分工明确：**哈希表负责 O(1) 定位**，**双向链表负责 O(1) 维护使用顺序**。约定链表头部是「最近使用」、尾部是「最久未使用」；get/put 命中都要把节点搬到头部；容量满时淘汰尾部。

### 解法一：哈希表 + 双向链表（推荐）

1. `Node` 同时存 `key` 和 `value`——淘汰尾部时要反查哈希表删 key，所以 **key 必须存在节点里**
2. 用 **dummy 头 + dummy 尾** 哨兵夹住所有真实节点，插头/删尾不再有空的边界情况
3. `get(key)`：哈希表查不到返回 -1；查到则把节点移到头部，返回 value
4. `put(key, value)`：已存在 → 更新 value 并移到头部；不存在 → 头插新节点，若超容量则删尾节点并从哈希表移除其 key
5. 所有操作由 `addToHead` / `remove` 两个原子方法组装，`moveToHead = remove + addToHead`

- 时间复杂度：`get`/`put` 均为 \(O(1)\)，空间复杂度：\(O(capacity)\)

### 解法二：LinkedHashMap（偷懒解法）

1. `new LinkedHashMap<>(capacity, 0.75f, true)`：第三个参数 `accessOrder = true` 表示按**访问顺序**排列（默认是插入顺序）
2. 重写 `removeEldestEntry`：返回 `size() > capacity`，插入后自动淘汰最久未访问的条目
3. 面试一般不允许直接用，但可以主动提一句展示知识面

- 时间复杂度：`get`/`put` 均为 \(O(1)\)，空间复杂度：\(O(capacity)\)

## 代码

### 解法一：哈希表 + 双向链表（推荐）

```java
class LRUCache {

    // 节点必须同时存 key 和 value：淘汰时要拿 key 反查哈希表
    private class Node {
        int key, value;
        Node prev, next;
        Node(int key, int value) {
            this.key = key;
            this.value = value;
        }
    }

    private final int capacity;
    private final Map<Integer, Node> map; // key → 节点，O(1) 定位
    private final Node head, tail;        // 哨兵：head.next 最近使用，tail.prev 最久未用

    public LRUCache(int capacity) {
        this.capacity = capacity;
        map = new HashMap<>();
        head = new Node(0, 0);
        tail = new Node(0, 0);
        head.next = tail;
        tail.prev = head;
    }

    public int get(int key) {
        Node node = map.get(key);
        if (node == null) return -1;
        moveToHead(node); // 命中即「刚被使用」
        return node.value;
    }

    public void put(int key, int value) {
        Node node = map.get(key);
        if (node != null) {            // 已存在：更新 + 提到头部
            node.value = value;
            moveToHead(node);
        } else {                       // 不存在：头插新节点
            Node fresh = new Node(key, value);
            map.put(key, fresh);
            addToHead(fresh);
            if (map.size() > capacity) { // 超容量：淘汰尾部
                Node eldest = tail.prev;
                remove(eldest);
                map.remove(eldest.key);  // 节点里没存 key，这里就反查不到
            }
        }
    }

    // ---- 双向链表三个原子操作 ----

    private void addToHead(Node node) {
        node.prev = head;
        node.next = head.next;
        head.next.prev = node;
        head.next = node;
    }

    private void remove(Node node) {
        node.prev.next = node.next;
        node.next.prev = node.prev;
    }

    private void moveToHead(Node node) {
        remove(node);
        addToHead(node);
    }
}
```

### 解法二：LinkedHashMap（偷懒解法）

```java
class LRUCache extends LinkedHashMap<Integer, Integer> {
    private final int capacity;

    public LRUCache(int capacity) {
        // accessOrder = true：按访问顺序排列，最近访问的移到末尾
        super(capacity, 0.75f, true);
        this.capacity = capacity;
    }

    // 返回 true 时，插入后自动删除最老（最久未访问）的条目
    @Override
    protected boolean removeEldestEntry(Map.Entry<Integer, Integer> eldest) {
        return size() > capacity;
    }
}
```

## 个人总结

### 1. Node 里必须存 key

淘汰尾部时要用节点的 key 去 `map.remove(key)`。如果 Node 只存 value，淘汰时就反查不到该删哪个 key，哈希表里会留下脏数据。这是双向链表解法最隐蔽的坑。

### 2. 哨兵头尾让边界消失

没有哨兵时，插头/删尾都要讨论「链表为空」「只有一个节点」等边界；用 dummy head + dummy tail 后所有真实节点都在中间，`addToHead` / `remove` 永远不触碰 null。dummy 思想与 21、24 题一脉相承。

### 3. 「命中即移动」要覆盖 get 和 put 两种操作

get 命中、put 更新旧 key 都要 `moveToHead`——两者都属于「使用」。漏掉 put 更新时的 moveToHead 是高频 bug：更新旧 key 应视为最近使用，否则刚更新的数据可能被误淘汰。

### 4. LinkedHashMap 一句话偷懒

`new LinkedHashMap<Integer, Integer>(capacity, 0.75f, true)` + 重写 `removeEldestEntry`：`accessOrder=true` 让迭代顺序 = 访问顺序（最近访问的在尾部），容量超限时自动淘汰头部（最久未使用）。面试可提，但大概率会被要求手写双向链表版——所以解法一才是本体。
