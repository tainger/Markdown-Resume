## 题目描述

给你一个整数数组 `nums` ，判断是否存在三元组 `[nums[i], nums[j], nums[k]]` 满足 `i != j`、`i != k` 且 `j != k` ，同时还满足 `nums[i] + nums[j] + nums[k] == 0` 。请你返回所有**和为 `0` 且不重复**的三元组。

**注意**：答案中**不可以包含重复的三元组**。

## 示例

**示例 1**

```
输入：nums = [-1,0,1,2,-1,-4]
输出：[[-1,-1,2],[-1,0,1]]
解释：
nums[0] + nums[1] + nums[2] = (-1) + 0 + 1 = 0 。
nums[1] + nums[2] + nums[4] = 0 + 1 + (-1) = 0 。
nums[0] + nums[3] + nums[4] = (-1) + 2 + (-1) = 0 。
不同的三元组是 [-1,0,1] 和 [-1,-1,2] 。
注意，输出的顺序和三元组的顺序并不重要。
```

**示例 2**

```
输入：nums = [0,1,1]
输出：[]
解释：唯一可能的三元组和不为 0 。
```

**示例 3**

```
输入：nums = [0,0,0]
输出：[[0,0,0]]
解释：唯一可能的三元组和为 0 。
```

## 思路

### 核心思想

排序后固定第一个数 `nums[i]`，问题退化为「有序数组上找两数之和 = `-nums[i]`」，交给**左右双指针夹逼**；去重的关键是**三个位置各自跳过相邻重复值**。

### 解法一：暴力枚举 + 集合去重（基础）

1. 三重循环枚举所有三元组，和为 0 就收集；
2. 每个三元组先排序成规范形态，再放进 `HashSet` 去重。

- 时间复杂度：\(O(n^3)\)（`n = 3000` 会超时），空间复杂度：\(O(n)\)

### 解法二：排序 + 双指针（推荐）

1. 先 `Arrays.sort` 升序排序（双指针夹逼的前提）；
2. 枚举第一个数 `i`：
   - 若 `nums[i] > 0` 直接 `break`（最小的数都大于 0，后面不可能凑出 0）；
   - 若 `nums[i] == nums[i-1]` 则 `continue`（同一个首数只枚举一次，避免重复三元组）；
3. 在区间 `[i+1, n-1]` 上用 `l`、`r` 双指针夹逼 `sum`：
   - `sum < 0` → `l++`（和太小，右移左指针变大）；
   - `sum > 0` → `r--`（和太大，左移右指针变小）；
   - `sum == 0` → 收集答案；然后 `l` 向右跳过重复值、`r` 向左跳过重复值，再各走一步。

- 时间复杂度：\(O(n^2)\)（排序 \(O(n\log n)\) 被双重循环淹没），空间复杂度：\(O(\log n)\)（排序递归栈）

## 代码

### 解法一：暴力枚举（会超时，仅理解用）

```java
public List<List<Integer>> threeSum(int[] nums) {
    int n = nums.length;
    Set<List<Integer>> seen = new HashSet<>();     // 集合去重
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            for (int k = j + 1; k < n; k++) {
                if (nums[i] + nums[j] + nums[k] == 0) {
                    List<Integer> triple = Arrays.asList(nums[i], nums[j], nums[k]);
                    Collections.sort(triple);      // 排成统一形态再去重
                    seen.add(triple);
                }
            }
        }
    }
    return new ArrayList<>(seen);
}
```

### 解法二：排序 + 双指针（推荐）

```java
public List<List<Integer>> threeSum(int[] nums) {
    Arrays.sort(nums);                             // 排序是双指针夹逼的前提
    List<List<Integer>> ans = new ArrayList<>();
    int n = nums.length;
    for (int i = 0; i < n - 2; i++) {
        if (nums[i] > 0) break;                    // 最小的数都 > 0，后面必无解
        if (i > 0 && nums[i] == nums[i - 1]) continue;  // 跳过重复的第一个数
        int l = i + 1, r = n - 1;
        while (l < r) {
            int sum = nums[i] + nums[l] + nums[r];
            if (sum < 0) {
                l++;                               // 和太小，右移左指针
            } else if (sum > 0) {
                r--;                               // 和太大，左移右指针
            } else {
                ans.add(Arrays.asList(nums[i], nums[l], nums[r]));
                while (l < r && nums[l] == nums[l + 1]) l++;  // 跳过重复的第二个数
                while (l < r && nums[r] == nums[r - 1]) r--;  // 跳过重复的第三个数
                l++;                               // 指向下一个新值
                r--;
            }
        }
    }
    return ans;
}
```

## 个人总结

### 1. 去重要「三层都管」，漏一层就 WA

| 位置 | 去重写法 | 目的 |
|:---|:---|:---|
| 首数 `i` | `i > 0 && nums[i] == nums[i-1] → continue` | 同一个首数只枚举一次 |
| `l` | 找到解后 `while (nums[l] == nums[l+1]) l++` | 同一解中第二个数只收一次 |
| `r` | 找到解后 `while (nums[r] == nums[r-1]) r--` | 同一解中第三个数只收一次 |

最常漏的是 `l`/`r` 的去重；且这两个 `while` 必须带 `l < r` 保护，否则 `[0,0,0,0]` 这类用例会越界或漏解。

### 2. `nums[i] > 0` 是剪枝不是「可选优化」

排序后 `nums[i]` 是剩余候选中最小的数，它都 `> 0` 则三数之和必 `> 0`，后面全无解，要 `break`（不是 `continue`）。对边界 `[0,0,0]` 同样安全（`0 > 0` 为 false，正常进入循环）。

### 3. 找到解后的顺序：先去重，再 l++/r-- 各一步

顺序不能反：先跳过所有重复值，再各走一步指向「新值」。只走一步不去重，`[-2,0,0,2,2]` 会输出重复的 `[-2,0,2]`。

### 4. 为什么不用哈希表做三数之和

两数之和用哈希是 \(O(n)\)，但三数之和固定 `i` 后本质仍是「有序数组上的两数之和」——双指针不需要额外哈希空间，且排序后「相邻跳过」天然完成去重，比集合去重优雅得多。**排序 + 双指针是「n 数之和」家族的通用骨架**：四数之和就固定两个数再夹逼，层层套娃（LeetCode 18）。
