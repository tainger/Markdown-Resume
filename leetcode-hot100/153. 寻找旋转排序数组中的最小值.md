## 题目描述

已知一个长度为 `n` 的数组，预先按照升序排列，经由 `1` 到 `n` 次 **旋转** 后，得到输入数组。例如，原数组 `nums = [0,1,2,4,5,6,7]` 在变化后可能得到：

- 若旋转 `4` 次，则可以得到 `[4,5,6,7,0,1,2]`
- 若旋转 `7` 次，则可以得到 `[0,1,2,4,5,6,7]`

注意，数组 `[a[0], a[1], a[2], ..., a[n-1]]` **旋转一次** 的结果为数组 `[a[n-1], a[0], a[1], a[2], ..., a[n-2]]` 。

给你一个元素值 **互不相同** 的数组 `nums` ，它原来是一个升序排列的数组，并按上述情形进行了多次旋转。请你找出并返回数组中的 **最小元素** 。

你必须设计一个时间复杂度为 `O(log n)` 的算法解决此问题。

## 示例

**示例 1**

```
输入：nums = [3,4,5,1,2]
输出：1
解释：原数组为 [1,2,3,4,5] ，旋转 3 次得到输入数组。
```

**示例 2**

```
输入：nums = [4,5,6,7,0,1,2]
输出：0
解释：原数组为 [0,1,2,4,5,6,7] ，旋转 4 次得到输入数组。
```

**示例 3**

```
输入：nums = [11,13,15,17]
输出：11
解释：原数组为 [11,13,15,17] ，旋转 4 次得到输入数组（n = 4，转回原样）。
```

## 思路

### 核心思想

旋转后的数组由**两段各自升序**的部分组成，最小值就是**后一段的起点**（若旋转回原样，最小值就是首元素，可看作后一段起点 = 下标 0）。

二分时拿 `nums[mid]` 与 `nums[right]` 比较，**单点**就能判断 mid 落在哪一段：

- `nums[mid] > nums[right]`：mid 与 right 被「断崖」隔开，mid 在**前段** → 最小值在 `(mid, right]`
- `nums[mid] < nums[right]`：mid 在**后段**，mid 本身可能就是最小值 → 最小值在 `[left, mid]`

```
[3,4,5,1,2]  left=0 right=4 mid=2: 5>2 → 右半      [1,2,3,4,5]  mid=2: 3<5 → 左半(含mid)
[3] left=3 right=4 mid=3: 1<2 → 左半(含mid)         [1] right=2 → ...
left=right=3 → nums[3]=1 ✅                          left=right=0 → 1 ✅
```

### 解法一：线性扫描（对比基准）

从左往右找第一个 `nums[i] < nums[i-1]` 的「断崖」，其后一个位置就是最小值；没有断崖说明整体有序，首元素即答案。

- 时间复杂度：\(O(n)\)，**不满足题面 \(O(\log n)\) 要求**，作对比铺垫
- 空间复杂度：\(O(1)\)

### 解法二：二分查找（推荐）

1. `left = 0, right = n - 1`，循环不变量：最小值始终在 `[left, right]` 内
2. `mid = left + (right - left) / 2`：
   - `nums[mid] > nums[right]` → `left = mid + 1`
   - `nums[mid] < nums[right]` → `right = mid`（mid 可能就是答案，不能丢）
3. `left == right` 时收束到最小值，返回 `nums[left]`

元素互不相同，不会出现 `nums[mid] == nums[right]`（154 有重复时才需要 `right--` 兜底）。

- 时间复杂度：\(O(\log n)\)，空间复杂度：\(O(1)\)

## 代码

### 解法一：线性扫描（不满足复杂度要求）

```java
class Solution {
    public int findMin(int[] nums) {
        for (int i = 1; i < nums.length; i++) {
            // 找到「断崖」：前一个数比后一个数大 → 后一段起点就是最小值
            if (nums[i] < nums[i - 1]) {
                return nums[i];
            }
        }
        return nums[0];   // 没有断崖 → 整体有序，首元素即最小
    }
}
```

### 解法二：二分查找（推荐）

```java
class Solution {
    public int findMin(int[] nums) {
        int left = 0, right = nums.length - 1;
        while (left < right) {                        // 收束到只剩一个元素
            int mid = left + (right - left) / 2;      // 防溢出写法
            if (nums[mid] > nums[right]) {
                left = mid + 1;   // mid 在前段：最小值在 (mid, right]
            } else {
                right = mid;      // mid 在后段：最小值在 [left, mid]，mid 可能就是答案
            }
        }
        return nums[left];    // left == right，即最小值下标
    }
}
```

## 个人总结

### 1. 为什么和 `nums[right]` 比、不和 `nums[left]` 比

和 left 比**有二义性**：`nums[mid] > nums[left]` 时，最小值可能在右侧（`[4,5,6,7,0,1]`），也可能整个区间已有序（`[1,2,3]`），无法单点定方向；而 `right` 一定属于「后段或整体有序段」，`nums[mid]` 与它比较能唯一确定 mid 的归属。记住结论：**旋转数组找最小，锚点选右端**。

### 2. 两个分支的「丢不丢 mid」要区分

| 分支 | 含义 | 收缩 |
|:---|:---|:---|
| `nums[mid] > nums[right]` | mid 在前段，必不是最小值 | `left = mid + 1`（丢弃 mid） |
| `nums[mid] < nums[right]` | mid 在后段，**可能是**最小值 | `right = mid`（保留 mid） |

正是因为只有一个分支保留 mid，循环条件用 `while (left < right)` 且收缩严格（`mid < right` 恒成立），保证不死循环、不错过答案。这是「区间含答案」型二分的标准写法，区别于「找具体下标」型（`left <= right` + `±1` 收缩）。

### 4. 二分题先写「循环不变量」再写代码

本题不变量：**最小值下标始终在 [left, right] 内**。每个分支的赋值都必须维持它（`left = mid+1` 时 mid 被证明非最小；`right = mid` 时 mid 可能是最小所以保留）。写二分先在注释里写清不变量与终止条件，再推分支，能避免 90% 的边界错误；`mid` 用 `left + (right - left) / 2` 防溢出是肌肉记忆。
