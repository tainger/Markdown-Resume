# 19. 删除链表的倒数第 N 个结点

> **难度**：🟡 中等 | **标签**：链表、双指针 | **企业**：—

## 题目描述

给你一个链表，删除链表的倒数第 `n` 个结点，并且返回链表的头结点。

## 示例

**示例 1**

```
输入：head = [1,2,3,4,5], n = 2
输出：[1,2,3,5]
```

**示例 2**

```
输入：head = [1], n = 1
输出：[]
```

**示例 3**

```
输入：head = [1,2], n = 1
输出：[1]
```

---

## 提示

- 链表中结点的数目为 `sz`
- `1 <= sz <= 30`
- `0 <= Node.val <= 100`
- `1 <= n <= sz`
- **进阶**：你能尝试使用一趟扫描实现吗？

---

## 思路

### 核心思想：快慢指针，错位一步

删除一个节点需要它的**前驱**。快指针 `fast` 先走 `n + 1` 步，然后 `fast`、`slow` 同步前进——`fast` 到末尾时，`slow` 恰好停在待删节点的**前驱**，执行 `slow.next = slow.next.next`。

```
head = [1,2,3,4,5], n = 2，目标删除 4

fast 先走 n+1 = 3 步
fast: 1 → 2 → 3 → 4        slow 原地不动
然后同步走：
fast: 4 → 5 → null          slow: 1 → 2 → 3
                            ↑ slow 停在 4 的前驱 3
slow.next = slow.next.next  → 删除 4 → [1,2,3,5] ✓
```

### 解法一：快慢指针 + dummy（推荐，一趟扫描）

1. `dummy` 哑节点接在 head 前——**删头节点时也有前驱**，无需特判
2. `fast` 先走 `n + 1` 步（注意是 `n+1` 不是 `n`）
3. `fast`、`slow` 同步走，直到 `fast == null`
4. 此时 `slow` 是待删节点前驱：`slow.next = slow.next.next`
5. 返回 `dummy.next`

- 时间复杂度：\(O(sz)\)，空间复杂度：\(O(1)\)

### 解法二：两趟扫描（朴素）

1. 第一趟遍历数出链表长度 `len`
2. 第二趟走到第 `len - n` 个节点（即待删节点前驱），执行删除

- 时间复杂度：\(O(sz)\)，空间复杂度：\(O(1)\)
- 正确但扫描两遍；进阶要求「一趟扫描」时用解法一

## 代码

### 我的伪代码

> 👇 我的两次尝试（保留用于复盘）：**v1 唯一 bug 是 `return head`，v2 已修为 `return resNode.next`**——删头节点时返回被删节点的问题已解决，见下方 [个人总结](#个人总结)。

```java
class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode resNode = new ListNode(-1);      // ✅ dummy：删头节点也有前驱
        resNode.next = head;
        ListNode quick = resNode;
        ListNode slow = resNode;
        
        while(n > 0) {
            if(quick == null) {                   // 💡 死代码：n ≤ sz 保证不会越界
                return null;
            }
            quick = quick.next;
            n --;
        }
        ListNode preNode = null;
        while(quick != null) {
            quick = quick.next;
            preNode = slow;                       // ✅ 记录 slow 的前驱
            slow = slow.next;                     // slow 最终停在待删节点
        }

        preNode.next = preNode.next.next;         // ✅ 通过前驱删除
        return resNode.next;                      // ✅ v2 已修：dummy.next 才是删完后的头
        // v1 是 return head：删头节点时把「已摘除的节点」返回，
        // [1], n=1 → 输出 [1] ❌（链表实为 []）；改后全部用例通过
    }
}
```

### 解法一：快慢指针 + dummy（修正版）

```java
class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);   // ✅ 哑节点：删头节点也统一处理
        ListNode fast = dummy;
        ListNode slow = dummy;

        for (int i = 0; i < n + 1; i++) {         // ✅ 走 n+1 步，slow 最后停在「前驱」
            fast = fast.next;
        }
        while (fast != null) {                    // 同步走，fast 到末尾即停止
            fast = fast.next;
            slow = slow.next;
        }
        slow.next = slow.next.next;               // 删除倒数第 n 个节点
        return dummy.next;
    }
}
```

### 解法二：两趟扫描

```java
class Solution {
    public ListNode removeNthFromEnd(ListNode head, int n) {
        ListNode dummy = new ListNode(0, head);
        int len = 0;
        for (ListNode p = dummy; p != null; p = p.next) len++;   // 第一趟：数长度

        ListNode cur = dummy;
        for (int i = 0; i < len - n - 1; i++) cur = cur.next;    // 第二趟：走到前驱
        cur.next = cur.next.next;
        return dummy.next;
    }
}
```

> 💡 记忆：**「删倒数第 k 个」= 快慢指针错位 k 格**；要删节点就必须有**前驱**，所以 `fast` 走 `n + 1` 步而不是 `n` 步——「+1」就是为了让 `slow` 停在前驱。

## 个人总结

### 1. ✅ 已修：`return head` → `return resNode.next`

v1 的 `return head` 在删头节点时（`n == sz`）返回了**已被摘除的节点**，等于返回「删除前的链表」：

```
[1], n=1：preNode = dummy → dummy.next = null，链表实为 []
          v1 return head → 输出 [1] ❌；v2 return resNode.next → 输出 [] ✅
[1,2], n=2：dummy.next = 2，但 head 仍指向 1
          v1 return head → 输出 [1,2] ❌；v2 return resNode.next → 输出 [2] ✅
```

非删头场景下 `head` 和 `dummy.next` 指向同一节点，所以 v1 在示例 1、3 上「碰巧」正确——**只有删头用例能抓出这个 bug**。修复就一行，但教训值一篇总结：

**链表题通用原则：返回值永远用 `dummy.next`，别用原始 `head` 指针——head 可能已被删除。**

### 2. ✅ 你的 preNode 追踪是「n+1 步」的等价替代

```
标准写法：fast 走 n+1 步 → slow 停在「前驱」→ slow.next = slow.next.next
你的写法：fast 走 n   步 → slow 停在「待删节点」，preNode 记录前驱 → preNode.next = ...
```

殊途同归，删除时都有前驱可用。你的版本多一个变量但直觉更直白；标准版少一个变量。两种都要会——**面试先说标准版，preNode 版作为备选**（你的思路证明你已经理解「删除需要前驱」这个本质）。

### 3. 💡 `if (quick == null) return null;` 是死代码

题目保证 `1 <= n <= sz`，`quick` 走 n 步时链表必然还有节点，永远不会碰到 null。留着无害，但要知道它是防御性判断——真遇到空链表，返回 `null` 在 LeetCode 语境下也不是规范的「空结果」表示。

### 4. 自测用例：删头（n == sz）才能抓出 return 类 bug

```
[1,2,3], n=3 → 删头 → [2,3]   ← return head 的 bug 只有删头能暴露
[1,2,3], n=1 → 删尾 → [1,2]   ← 抓「前驱定位」错误
[1],     n=1 → 删唯一节点 → [] ← NPE / 返回错误高发区
```

v2 修复后三个用例全部通过 ✅。前两题（21 合并、2 相加）的坑这次都没踩（dummy 用了、前驱对了），**唯一栽在返回值**——这类「修改头节点可能变」的题，自测清单第一项永远是「删头」。
