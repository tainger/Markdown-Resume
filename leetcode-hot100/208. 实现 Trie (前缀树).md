## 题目描述

**[Trie](https://baike.baidu.com/item/字典树/9825209?fr=aladdin)**（发音类似 "try"）或者说 **前缀树** 是一种树形数据结构，用于高效地存储和检索字符串数据集中的键。这一数据结构有相当多的应用情景，例如自动补全和拼写检查。

请你实现 **Trie** 类：

- `Trie()` 初始化前缀树对象。
- `void insert(String word)` 向前缀树中插入字符串 `word` 。
- `boolean search(String word)` 如果字符串 `word` 在前缀树中，返回 `true`（即，在检索之前已经插入）；否则，返回 `false` 。
- `boolean startsWith(String prefix)` 如果之前已经插入的字符串 `word` 的前缀之一为 `prefix` ，返回 `true` ；否则，返回 `false` 。

## 示例

**示例 1**

```
输入
["Trie", "insert", "search", "search", "startsWith", "insert", "search"]
[[], ["apple"], ["apple"], ["app"], ["app"], ["app"], ["app"]]
输出
[null, null, true, false, true, null, true]

解释
Trie trie = new Trie();
trie.insert("apple");
trie.search("apple");   // 返回 True
trie.search("app");     // 返回 False
trie.startsWith("app"); // 返回 True
trie.insert("app");
trie.search("app");     // 返回 True
```

## 思路

### 核心思想

Trie 是一棵 **26 叉树**：每条边代表一个字母，从根到某节点的路径拼出一个前缀；节点上挂一个 `isEnd` 标记表示「有单词在此结束」。`search` 与 `startsWith` 的唯一区别就是**走完后看不看 `isEnd`**。

### 解法一：数组子节点 + isEnd（推荐）

1. 节点 `Trie` 含 `Trie[26] children` 与 `boolean isEnd`；
2. `insert`：从根逐字符下走，子节点不存在就新建，走完把**末节点** `isEnd = true`；
3. `search`：逐字符下走，中途断链返回 false，走完返回 **`isEnd`**；
4. `startsWith`：逐字符下走，中途断链返回 false，走完直接返回 true（前缀路径存在即可）。

- 时间复杂度：每个操作 \(O(L)\)，L 为字符串长度；空间复杂度：最坏 \(O(26 \cdot \text{总字符数})\)，前缀共享后实际远小

### 解法二：HashMap 子节点（扩展）

把 `Trie[26]` 换成 `Map<Character, Trie>`：字符集大（Unicode）或节点子树稀疏时省内存；字符集固定为 26 时数组更快且无哈希开销。其余逻辑与解法一完全相同。

- 时间复杂度：\(O(L)\)；空间复杂度：按实际出现的字符数计，稀疏时优于数组

## 代码

### 解法一：数组子节点（推荐）

```java
class Trie {
    private final Trie[] children;   // 26 个子节点，children[c - 'a'] 即字母 c 的边
    private boolean isEnd;           // 是否有单词在此节点结束

    public Trie() {
        children = new Trie[26];
    }

    public void insert(String word) {
        Trie node = this;
        for (char c : word.toCharArray()) {
            int idx = c - 'a';
            if (node.children[idx] == null) {
                node.children[idx] = new Trie();   // 缺链就建
            }
            node = node.children[idx];             // 沿边下走
        }
        node.isEnd = true;                         // 只标记末节点：单词在此结束
    }

    // 公共逻辑：沿字符串走到底，返回终点节点；断链返回 null
    private Trie find(String s) {
        Trie node = this;
        for (char c : s.toCharArray()) {
            node = node.children[c - 'a'];
            if (node == null) return null;
        }
        return node;
    }

    public boolean search(String word) {
        Trie node = find(word);
        return node != null && node.isEnd;         // 必须是完整单词
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;               // 前缀存在即可，不看 isEnd
    }
}
```

### 解法二：HashMap 子节点

```java
class Trie {
    private final Map<Character, Trie> children = new HashMap<>();
    private boolean isEnd;

    public void insert(String word) {
        Trie node = this;
        for (char c : word.toCharArray()) {
            node = node.children.computeIfAbsent(c, k -> new Trie());  // 缺链就建
        }
        node.isEnd = true;
    }

    public boolean search(String word) {
        Trie node = find(word);
        return node != null && node.isEnd;
    }

    public boolean startsWith(String prefix) {
        return find(prefix) != null;
    }

    private Trie find(String s) {
        Trie node = this;
        for (char c : s.toCharArray()) {
            node = node.children.get(c);
            if (node == null) return null;
        }
        return node;
    }
}
```

## 个人总结

### 1. `search` 与 `startsWith` 一字之差：isEnd

两者走树过程完全一样，唯一区别：`search` 要求终点 `isEnd == true`（**完整单词**），`startsWith` 只要**前缀路径存在**。样例里 `search("app")` 为 false 而 `startsWith("app")` 为 true，考的就是这一点。抽出公共 `find()` 方法，两个接口各剩一行判断，最不容易写错。

### 2. isEnd 只标末节点，别标「路过」

常见 bug：把路径上**每个节点**都置 `isEnd = true`，导致只插入过 `"apple"` 时 `search("app")` 误判 true。`isEnd` 的语义是「**有单词在此结束**」，不是「有单词经过这里」——只在 insert 走完后对末节点置 true。

### 3. 前缀共享是 Trie 的价值

插入 `"apple"` 和 `"app"` 共享前 3 个节点；查询成本只与**单词长度**有关、与已存词数无关（对比 HashSet 每次都要哈希整个串）。适用场景：前缀检索、自动补全、词频统计、以及 [212. 单词搜索 II](212.%20单词搜索%20II.md)（Trie + 网格回溯，[79. 单词搜索](79.%20单词搜索.md) 的多词版）。

### 4. 数组 vs HashMap 子节点，以及同族题

| | `Trie[26]` | `HashMap` |
|:---|:---|:---|
| 字符集 | 固定小写（26） | 任意字符 / Unicode |
| 单次访问 | 数组下标，最快 | 哈希查找，略慢 |
| 内存 | 每节点固定 26 槽，稀疏时浪费 | 按需分配，稀疏时省 |
| 面试默认 | ✅ 首选 | 提一句扩展性即可 |
