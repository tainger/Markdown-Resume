## 题目描述

给你一个链表数组，每个链表都已经按升序排列。

请你将所有链表合并到一个升序链表中，返回合并后的链表。

---

## 示例

**示例 1**

```
输入：lists = [[1,4,5],[1,3,4],[2,6]]
输出：[1,1,2,3,4,4,5,6]
解释：链表数组如下：
[
  1->4->5,
  1->3->4,
  2->6
]
将它们合并到一个有序链表中得到。
1->1->2->3->4->4->5->6
```

**示例 2**

```
输入：lists = []
输出：[]
```

**示例 3**

```
输入：lists = [[]]
输出：[]
```

## 提示

- `k == lists.length`
- `0 <= k <= 10^4`
- `0 <= lists[i].length <= 500`
- `-10^4 <= lists[i][j] <= 10^4`
- `lists[i]` 按 **升序** 排列
- `lists[i].length` 的总和不超过 `10^4`

## 思路

设总节点数为 `N`，链表条数为 `k`。核心是复用「合并两个有序链表」（[21 题](21.合并两个有序链表.md)）这块积木，区别只在**怎么组织 `k` 条链表的合并顺序**。

### 解法一：逐一顺序合并（最直观）

先用 [21](21.合并两个有序链表.md) 的方法把第 1、2 条合并成 `ans`，再把 `ans` 与第 3 条合并，依次吞并到最后一条。

- 时间复杂度：\(O(k \times N)\)。第 `i` 次合并，`ans` 已有约 `i×(N/k)` 个节点，累加起来是 \(O(k \cdot N)\)——**越往后 `ans` 越长、被反复扫描**，这是瓶颈。
- 空间复杂度：\(O(1)\)（迭代合并）

> 瓶颈：前面已经排好的长链表 `ans`，每合并一条新链表就被**从头再扫一遍**。想法是让「每个节点被比较的次数」从 `O(k)` 降到 `O(log k)`。

### 解法二：小顶堆（优先队列）

把 `k` 条链表的**头节点**全部放进小顶堆，每次弹出最小的接到结果链表尾部，再把它的 `next` 入堆。堆里始终最多 `k` 个节点：

1. 所有非空头节点入堆（按 `val` 排序）
2. 循环：弹出堆顶（当前全局最小），接到结果尾部；若它有 `next`，`next` 入堆
3. 堆空则结束

- 时间复杂度：\(O(N \log k)\)。每个节点进出堆各一次，堆操作 \(O(\log k)\)
- 空间复杂度：\(O(k)\) 堆

### 解法三：分治两两合并（归并思想，推荐）

把 `k` 条链表**两两配对合并**，`k → k/2 → k/4 → ... → 1`，像归并排序的「合并」层：

```
[l0 l1 l2 l3 l4 l5 l6 l7]
  \  /   \  /   \  /   \  /      两两合并
 [ m0     m1     m2     m3 ]
    \      /       \      /
   [   n0             n1   ]
        \               /
        [    最终结果      ]
```

- 时间复杂度：\(O(N \log k)\)。共 `log k` 层，每层所有合并加起来扫过全部 `N` 个节点
- 空间复杂度：\(O(\log k)\) 递归栈

**为什么比解法一快**：解法一里第一条链表被扫了 `k` 次；分治里每个节点只在每一层被扫一次，共 `log k` 层，所以是 `O(N log k)` 而非 `O(Nk)`。

## 代码

### 解法一：逐一顺序合并（先跑通）

```java
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        if (lists == null || lists.length == 0) return null;
        ListNode ans = null;
        for (ListNode list : lists) {
            ans = mergeTwo(ans, list);             // 依次把每条吞并进 ans
        }
        return ans;
    }

    // 合并两个有序链表（复用 21 题）
    private ListNode mergeTwo(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), cur = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { cur.next = a; a = a.next; }
            else                { cur.next = b; b = b.next; }
            cur = cur.next;
        }
        cur.next = (a != null) ? a : b;            // 接上剩余
        return dummy.next;
    }
}
```

### 解法二：小顶堆（优先队列）

```java
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        // 小顶堆，按节点值排序
        PriorityQueue<ListNode> pq = new PriorityQueue<>((a, b) -> a.val - b.val);
        for (ListNode node : lists) {
            if (node != null) pq.offer(node);      // 所有非空头节点入堆
        }

        ListNode dummy = new ListNode(0), cur = dummy;
        while (!pq.isEmpty()) {
            ListNode min = pq.poll();              // 当前全局最小
            cur.next = min;
            cur = cur.next;
            if (min.next != null) pq.offer(min.next);  // 该链表下一个入堆
        }
        return dummy.next;
    }
}
```

### 解法三：分治两两合并（推荐）

```java
class Solution {
    public ListNode mergeKLists(ListNode[] lists) {
        if (lists == null || lists.length == 0) return null;
        return merge(lists, 0, lists.length - 1);
    }

    // 分治合并 lists[lo..hi]
    private ListNode merge(ListNode[] lists, int lo, int hi) {
        if (lo == hi) return lists[lo];
        if (lo > hi) return null;
        int mid = lo + (hi - lo) / 2;
        ListNode left = merge(lists, lo, mid);     // 合并左半
        ListNode right = merge(lists, mid + 1, hi); // 合并右半
        return mergeTwo(left, right);              // 两半再合并
    }

    private ListNode mergeTwo(ListNode a, ListNode b) {
        ListNode dummy = new ListNode(0), cur = dummy;
        while (a != null && b != null) {
            if (a.val <= b.val) { cur.next = a; a = a.next; }
            else                { cur.next = b; b = b.next; }
            cur = cur.next;
        }
        cur.next = (a != null) ? a : b;
        return dummy.next;
    }
}
```

## 个人总结

### 1. 核心积木是「合并两个有序链表」

三种解法都在反复调用 [21. 合并两个有序链表](21.合并两个有序链表.md) 的 `mergeTwo`，区别只在**合并顺序的组织**：顺序串、堆调度、还是分治两两配对。**先把 21 写熟，本题就是它的调度问题**。

### 2. 为什么逐一合并慢：长链表被反复扫描

解法一的 \(O(Nk)\) 慢在——第一条链表参与了 `k` 次合并，每次都被从头扫。**把「1+2+3+…+k 次扫描」优化成「每个节点只被扫 log k 次」**，就得到堆和分治两种 \(O(N\log k)\) 解法。识别「重复扫描已处理数据」是优化信号。

### 3. 堆 vs 分治：两种 O(N log k) 思路

| | 小顶堆 | 分治 |
|:---|:---|:---|
| 思想 | 每步全局选最小，堆维护 k 个候选 | 两两归并，`k→k/2→…→1` |
| `log k` 来自 | 堆的高度 | 递归层数 |
| 空间 | \(O(k)\) 堆 | \(O(\log k)\) 栈 |
| 好写度 | 需会用 `PriorityQueue` | 递归结构清晰 |

两者复杂度相同，**堆更适合「流式/在线」场景，分治更贴近归并排序的直觉**。面试两种都值得会。

### 4. 堆解法的关键：只放「当前候选头」，不是全部节点

堆里始终最多 `k` 个节点（每条链表当前最靠前的那个）。弹出最小后，**只把它的 `next` 补进堆**——这样堆大小恒定 `≤k`，保证每次操作 \(O(\log k)\)。若把所有 `N` 个节点一次性入堆，就退化成 \(O(N\log N)\) 且丢了链表结构。

### 5. 分治的 `mid` 与递归边界

- `lo == hi`：只剩一条，直接返回；
- `lo > hi`：空区间（`lists` 为空时），返回 `null`；
- `mid = lo + (hi-lo)/2` 防溢出，左闭右闭区间 `[lo,mid]`、`[mid+1,hi]` 不重不漏。
