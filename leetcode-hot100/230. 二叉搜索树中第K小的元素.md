## 题目描述

给定一个二叉搜索树的根节点 `root` ，和一个整数 `k` ，请你设计一个算法查找其中第 `k` 小的元素（从 1 开始计数）。

## 示例

**示例 1**

```
输入：root = [3,1,4,null,2], k = 1
输出：1

树结构：
       3
      / \
     1   4
      \
       2
```

**示例 2**

```
输入：root = [5,3,6,2,4,null,null,1], k = 3
输出：3

树结构：
         5
        / \
       3   6
      / \
     2   4
    /
   1
```

---

## 提示

- 树中的节点数为 `n`
- `1 <= k <= n <= 10^4`
- `0 <= Node.val <= 1000`

---

## 进阶

如果二叉搜索树经常被修改（插入/删除操作）并且你需要频繁地查找第 `k` 小的值，你将如何优化算法？

> 方向：给每个节点维护「以它为根的子树节点数 cnt」，查找时比较 `k` 与 `left.cnt + 1` 决定走向，单次查询降到 O(h)；插入/删除时沿路径 O(h) 更新 cnt（即 AVL/Treap 的按名次查询思想）。

---

## 思路

### 核心思想

**BST 的中序遍历 = 升序序列**，所以"第 k 小" = 中序遍历时**第 k 个被访问**的节点。不需要遍历完整棵树：计数器从 k 递减，减到 0 时立即返回。

```
中序访问顺序（示例 2）：1 → 2 → 3 → 4 → 5 → 6
                       ①   ②   ③
                                k = 3 时第 3 个访问的是 3 → 答案
```

### 解法一：递归中序 + 计数器提前终止（基础）

1. 成员变量 `k`（剩余步数）与 `ans`
2. 中序递归：左子树 → 根（`--k == 0` 则记录答案）→ 右子树；`k == 0` 时全线剪枝

- 时间复杂度：\\(O(h+k)\\)（最坏 O(n)），空间复杂度：\\(O(h)\\)

### 解法二：迭代中序（栈）（推荐）

1. 标准迭代中序：一路向左入栈，弹栈访问，转右
2. 弹栈时 `--k == 0` 直接 `return cur.val`，天然提前终止、无成员变量

- 时间复杂度：\\(O(h+k)\\)，空间复杂度：\\(O(h)\\)

## 代码

### 解法一：递归中序 + 提前终止

```java
private int k;          // 剩余还需要访问的节点数
private int ans;

public int kthSmallest(TreeNode root, int k) {
    this.k = k;
    inorder(root);
    return ans;
}

// BST 中序遍历 = 升序序列，走到第 k 个"根位"访问即答案
private void inorder(TreeNode node) {
    if (node == null || k == 0) return;   // k == 0 提前剪枝
    inorder(node.left);
    if (--k == 0) {                       // 当前节点是第 k 个被访问的
        ans = node.val;
        return;
    }
    inorder(node.right);
}
```

### 解法二：迭代中序（推荐）

```java
public int kthSmallest(TreeNode root, int k) {
    Deque<TreeNode> stack = new ArrayDeque<>();
    TreeNode cur = root;
    while (cur != null || !stack.isEmpty()) {
        while (cur != null) {             // ① 一路向左，沿途入栈
            stack.push(cur);
            cur = cur.left;
        }
        cur = stack.pop();                // ② 弹栈 = 中序访问
        if (--k == 0) return cur.val;     //    第 k 个出栈的就是答案
        cur = cur.right;                  // ③ 转向右子树
    }
    return -1;                            // 不会到达（题目保证 1 <= k <= n）
}
```

## 个人总结

### 1. 为什么中序第 k 个就是第 k 小

BST 性质：左子树全部 < 根 < 右子树。中序"左 → 根 → 右"展开后恰好是升序排列——这不是巧合而是 BST 定义的直接推论。**"BST 上找第 k 小 / 区间第 k 大 / 中序后继"第一反应都该是中序遍历**，而不是去逐个比较大小。

### 2. 提前终止：找到就停，别全遍历

两种写法都要在 `--k == 0` 时立刻返回/剪枝。k 很小而树很大时（如 k=1 找最小值，一路向左即可），时间从 O(n) 降到 O(h+k)。递归版靠 `k == 0` 剪枝条件，迭代版靠 `return` 天然终止。

### 3. 递归版用成员变量的代价与写法

`k`、`ans` 放成员变量 + 辅助方法返回 `void`，是最省事的"携带状态递归"写法。注意两点：多测例共享 Solution 时成员变量必须重置（`this.k = k` 在入口做）；如果面试官不允许成员变量，直接写解法二迭代版，状态全在栈帧/局部变量里。

### 4. 进阶：频繁修改 + 频繁查询 → 节点带 cnt

中序方案每次查询 O(h+k)，树频繁插删时不够快。优化：每个节点存 `cnt`（子树节点总数），查询时三分支——`k <= left.cnt` 走左；`k == left.cnt + 1` 命中当前；否则 `k -= left.cnt + 1` 走右，单次 O(h)。插入/删除沿路径更新 cnt 即可。这就是平衡树家族（AVL/Treap/线段树套 BST）支持"按名次访问"的原理，面试能讲到这一层基本就通关了。
