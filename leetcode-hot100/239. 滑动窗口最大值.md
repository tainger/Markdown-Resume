## 题目描述

给你一个整数数组 `nums`，有一个大小为 `k` 的**滑动窗口**从数组的最左侧移动到数组的最右侧。你只可以看到在滑动窗口内的 `k` 个数字。滑动窗口每次只向右移动一位。

返回 **滑动窗口中的最大值** 。

## 示例

**示例 1**

```
输入：nums = [1,3,-1,-3,5,3,6,7], k = 3
输出：[3,3,5,5,6,7]
解释：
滑动窗口的位置                最大值
---------------               -----
[1  3  -1] -3  5  3  6  7       3
 1 [3  -1  -3] 5  3  6  7       3
 1  3 [-1  -3  5] 3  6  7       5
 1  3  -1 [-3  5  3] 6  7       5
 1  3  -1  -3 [5  3  6] 7       6
 1  3  -1  -3  5 [3  6  7]      7
```

**示例 2**

```
输入：nums = [1], k = 1
输出：[1]
```

## 思路

### 核心思想

窗口右移一格只发生两件事：**进一个新元素、出一个旧元素**。每个窗口都「重新找最大」必然重复劳动。用**单调队列（Monotonic Queue）**维护「还可能成为最大值的候选下标」，把注定没戏的元素提前淘汰——每个元素至多进出队一次，整体线性。

### 解法一：大顶堆存下标（基础）

1. 大顶堆放 `[值, 下标]`（**必须存下标**，否则无法判断过期）；
2. 窗口形成后（`i >= k-1`），先把堆顶中下标已滑出窗口的元素弹出（惰性删除），堆顶值即当前窗口最大值。

- 时间复杂度：\(O(n\log n)\)（每个元素进出堆各一次），空间复杂度：\(O(n)\)

### 解法二：单调双端队列（推荐）

1. 双端队列存**下标**，对应值从队头到队尾**单调递减**；
2. 每来一个 `nums[i]`：把队尾所有 `<= nums[i]` 的下标弹出（它们比新元素小、又比它先过期，永远不可能当最大值），再入队 `i`；
3. 队头下标若已滑出窗口左界（`<= i-k`）则从队头弹出（每步至多过期一个，`if` 足够）；
4. 窗口形成后（`i >= k-1`），队头下标对应的值就是答案。

- 时间复杂度：\(O(n)\)（每个下标至多入队一次、出队一次，均摊线性），空间复杂度：\(O(k)\)

## 代码

### 解法一：大顶堆存下标（惰性删除）

```java
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    // 大顶堆存 [值, 下标]，按值从大到小排
    PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> b[0] - a[0]);
    int[] ans = new int[n - k + 1];
    for (int i = 0; i < n; i++) {
        pq.offer(new int[]{nums[i], i});
        if (i < k - 1) continue;          // 窗口尚未形成
        // 堆顶下标不在窗口 [i - k + 1, i] 内 → 已过期，弹出（惰性删除）
        while (pq.peek()[1] <= i - k) {
            pq.poll();
        }
        ans[i - k + 1] = pq.peek()[0];
    }
    return ans;
}
```

### 解法二：单调双端队列（推荐）

```java
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    Deque<Integer> deque = new ArrayDeque<>();   // 存下标，对应值从队头到队尾单调递减
    int[] ans = new int[n - k + 1];
    for (int i = 0; i < n; i++) {
        // ① 队尾所有 <= 当前值的下标已无翻身机会，弹出
        while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);
        // ② 队头下标滑出窗口左界则弹出（每步至多过期一个，if 即可）
        if (deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }
        // ③ 窗口形成后，队头就是当前窗口最大值
        if (i >= k - 1) {
            ans[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return ans;
}
```

## 个人总结

### 1. 为什么存下标而不是存值

判断「队头是否已滑出窗口」需要**位置**信息，只存值无法判断过期。**单调栈/队列处理带时效性的窗口问题时，统一存下标**，需要值时用 `nums[下标]` 取。这是本题第一个面试考点，答错直接出局。

### 2. 队尾弹出用 `<=` 还是 `<`：都对，`<=` 更好

| 写法 | 行为 | 备注 |
|:---|:---|:---|
| `<=`（推荐） | 相等元素也弹出，队列里同值只留最新 | 队列更短更干净 |
| `<` | 相等元素都保留 | 也正确，队列稍长 |

边界提醒：弹出条件用 `nums[队尾] <= nums[i]` 时，新元素自己永远会入队（`while` 有 `!isEmpty()` 保护），答案取的是「当前窗口内最大值」而非「严格大于它的才换」。

### 3. 假双重循环、真线性——用均摊分析回答

内层 `while` 看似嵌套，但每个下标**至多入队一次、出队一次**，总操作数 `<= 2n`。与 128、41 同款追问，准备好「均摊（amortized）」这个词和「进出各一次」的解释。

### 4. 面试高频追问链（单调栈 / 单调队列家族）

| 追问 | 要点 |
