## 题目描述

给你一个会议时间安排的数组 `intervals` ，每个会议时间都会包括开始和结束的时间 `intervals[i] = [starti, endi]` ，返回 **所需会议室的最小数量** 。

> 会员题。约定：会议 `[s, e)` 为左闭右开，即一场会议在 `e` 结束、另一场在 `e` 开始，二者 **不冲突**，可复用同一间会议室。

---

## 示例

**示例 1**

```
输入：intervals = [[0,30],[5,10],[15,20]]
输出：2
解释：
[0,30] 与 [5,10] 重叠 → 需要 2 间；
[15,20] 时 [5,10] 已结束，可复用其房间，但 [0,30] 仍占用 → 峰值仍是 2。
```

**示例 2**

```
输入：intervals = [[7,10],[2,4]]
输出：1
解释：两场会议不重叠，一间会议室先后使用即可。
```

---

## 提示

- `1 <= intervals.length <= 10^4`
- `0 <= starti < endi <= 10^6`

## 思路

### 核心转化：最少会议室数 = 任一时刻最大重叠会议数

不用真的去「分配」哪场会进哪间房。所需房间的最小数量，恰好等于**在时间轴上的某一时刻，同时进行的会议数量的峰值**。因为峰值时刻这么多场会必须同时各占一间房；而只要备齐峰值那么多间，其它时刻一定够用。

```
时间轴（示例1）：
0        5   10   15   20        30
[========== 0,30 ===================]
    [5,10]
              [15,20]

t∈[5,10)  同时有 {[0,30],[5,10]} → 2 场重叠 ← 峰值
t∈[15,20) 同时有 {[0,30],[15,20]} → 2 场重叠 ← 峰值
所以答案 = 2
```

于是问题变成：**求区间的最大重叠数**。三种经典解法。

### 解法一：起止时间分别排序 + 双指针（最省，推荐）

把所有**开始时间**和**结束时间**各自拆出来排序，用两个指针扫：

- 遇到一个「开始」→ 有新会议要开，占用数 `+1`，更新峰值；
- 若当前最早的「开始」时间 `>=` 最早的「结束」时间 → 说明有会议已结束，可腾出房间，占用数 `-1`，结束指针后移。

因为只关心「某开始时刻之前已结束多少场」，开始和结束**各自有序**即可，不必保持配对。

### 解法二：按开始排序 + 小顶堆维护「最早结束时间」（最直观）

1. 按 **开始时间升序** 排序会议；
2. 用小顶堆存「当前正占用房间的会议们的结束时间」，堆顶 = 最早结束的那间；
3. 遍历每场会议：若堆非空且**堆顶结束时间 `<=` 当前会议开始时间**，说明那间房已空出 → `poll` 复用；然后把当前会议结束时间 `offer` 入堆；
4. 堆的大小即当前占用房间数，全程最大堆大小就是答案（实际上遍历完堆大小即为峰值，因为只增不减地记录过峰值）。

### 解法三：差分 / 扫描线（最好写，事件计数）

把每场会议拆成两个事件：`(start, +1)`、`(end, -1)`，按时间排序后扫描累加，过程最大值即峰值重叠数。

- **左闭右开的关键**：同一时间点，`end` 的 `-1` 要**排在** `start` 的 `+1` 之前（先释放再占用），这样 `[a,b)` 与 `[b,c)` 不算重叠。若题目视相接为冲突，则 `+1` 在前。

- 三种解法时间都是 \(O(n \log n)\)（瓶颈在排序），空间 \(O(n)\)。

## 代码

### 解法一：起止分别排序 + 双指针（推荐）

```java
class Solution {
    public int minMeetingRooms(int[][] intervals) {
        int n = intervals.length;
        int[] starts = new int[n];
        int[] ends = new int[n];
        for (int i = 0; i < n; i++) {
            starts[i] = intervals[i][0];
            ends[i] = intervals[i][1];
        }
        Arrays.sort(starts);                      // 开始时间单独排序
        Arrays.sort(ends);                        // 结束时间单独排序

        int rooms = 0, maxRooms = 0, j = 0;
        for (int i = 0; i < n; i++) {             // 遍历每个开始事件
            if (starts[i] >= ends[j]) {           // 有会议已结束，腾出一间（左闭右开用 >=）
                j++;                              // 结束指针后移，但 rooms 不 +1（净变化为 0）
            } else {
                rooms++;                          // 没有会议结束，需要新房间
            }
            maxRooms = Math.max(maxRooms, rooms);
        }
        return maxRooms;
    }
}
```

### 解法二：按开始排序 + 小顶堆（最直观）

```java
class Solution {
    public int minMeetingRooms(int[][] intervals) {
        if (intervals.length == 0) return 0;
        Arrays.sort(intervals, (a, b) -> a[0] - b[0]);   // 按开始时间升序

        // 小顶堆存「占用中会议的结束时间」，堆顶 = 最早结束
        PriorityQueue<Integer> heap = new PriorityQueue<>();
        for (int[] itv : intervals) {
            if (!heap.isEmpty() && heap.peek() <= itv[0]) {
                heap.poll();                              // 最早结束的房间已空出，复用
            }
            heap.offer(itv[1]);                           // 当前会议入住（无论是否复用）
        }
        return heap.size();                               // 堆大小 = 峰值房间数
    }
}
```

### 解法三：差分 / 扫描线（事件计数）

```java
class Solution {
    public int minMeetingRooms(int[][] intervals) {
        int n = intervals.length;
        int[][] events = new int[2 * n][2];       // {时间, +1/-1}
        int idx = 0;
        for (int[] itv : intervals) {
            events[idx++] = new int[]{itv[0], 1};   // 开始：+1
            events[idx++] = new int[]{itv[1], -1};  // 结束：-1
        }
        // 时间升序；同一时间，-1（结束）排在 +1（开始）前 → 左闭右开
        Arrays.sort(events, (a, b) -> a[0] != b[0] ? a[0] - b[0] : a[1] - b[1]);

        int cur = 0, max = 0;
        for (int[] e : events) {
            cur += e[1];
            max = Math.max(max, cur);
        }
        return max;
    }
}
```

## 个人总结

### 1. 题眼：把「最少会议室」翻译成「最大重叠数」

这是本题最关键的一步转化——**不去纠结怎么分配房间，而是求时间轴上同时进行的会议数峰值**。峰值多少就必须备多少间房，其它时刻一定够用。这个「资源数 = 并发峰值」的思路可推广到任务调度、区间染色、CPU 核数估算等场景。

### 2. 解法一「分别排序」为什么正确

初看「开始、结束拆开各自排序会打乱配对」很反直觉。但这题**只关心计数、不关心是谁**：某个开始时刻之前「已经结束了几场」只取决于结束时间的多少，与它们对应哪场会无关。所以开始序列、结束序列各自有序就足够，双指针一扫即得峰值。这是三种里最省空间（不用堆）的写法。

### 3. 解法二堆里存的是「结束时间」不是会议本身

小顶堆按**结束时间**排序，堆顶是「最有可能先腾出的房间」。每来一场新会议，只需看最早结束的那间是否已空（`堆顶 <= 新开始`）：空了就复用（`poll` 再 `offer`，堆大小不变），没空就新增（直接 `offer`，堆大小 +1）。**堆的最终大小就是峰值**，因为房间只会在需要时增加、复用时不增不减。

### 4. 左闭右开：相接不算冲突，用 `>=` / `<=`

`[5,10]` 和 `[10,20]` 能否共用一间房，取决于题目对「10 这一刻」的定义。本题左闭右开 `[s,e)`，10 点那场已散会，故：
- 解法一用 `starts[i] >= ends[j]`（含等号即可复用）；
- 解法二用 `heap.peek() <= itv[0]`；
- 解法三让 `-1` 排在 `+1` 前。

若某题规定「结束和开始同一时刻算冲突」，把这些等号去掉 / 调整排序次序即可。**边界等号是区间题最常翻车的点。**

### 5. 三种解法怎么选

| 解法 | 空间 | 特点 |
|:---|:---:|:---|
| 分别排序 + 双指针 | \(O(n)\)（仅两数组） | 最省，代码短，面试亮点 |
| 排序 + 小顶堆 | \(O(n)\) | 最直观，还能顺带知道每间房排了哪些会 |
| 差分 / 扫描线 | \(O(n)\) | 最好写，事件模型可扩展到带权重叠 |

三者复杂度都是 \(O(n \log n)\)，瓶颈在排序。面试推荐先讲堆（易懂）或双指针（惊艳），差分作为通用扫描线模型补充。
