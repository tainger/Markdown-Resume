## 题目描述

给你一个整数 `n` ，返回 **和为 `n` 的完全平方数的最少数量** 。

**完全平方数** 是一个整数，其值等于另一个整数的平方；换句话说，其值等于一个整数自乘的积。例如，`1`、`4`、`9` 和 `16` 都是完全平方数，而 `3` 和 `11` 不是。

## 示例

**示例 1**

```
输入：n = 12
输出：3 
解释：12 = 4 + 4 + 4
```

**示例 2**

```
输入：n = 13
输出：2
解释：13 = 4 + 9
```

---

## 提示

- `1 <= n <= 10^4`

---

## 思路

### 核心思想

把所有平方数 `1, 4, 9, 16, ...`（不超过 n 的）看成**硬币面额**，本题就是 [322. 零钱兑换](322.%20零钱兑换.md) 的换皮——**完全背包求最少个数**（每个平方数可重复使用）。定义 `dp[i]` = 凑出 `i` 的最少平方数个数：

```
dp[i] = min(dp[i - j*j]) + 1     对所有 j*j <= i
dp[0] = 0
```

即「凑出 `i`」= 枚举最后一个用的平方数 `j²`，剩下 `i - j²` 再最优地凑。

```
n=12: dp[12] = min(dp[11], dp[8], dp[3]) + 1
      dp[8] = 2 (4+4) → dp[12] = 3 (4+4+4) ✅
```

### 解法一：完全背包 DP（推荐）

1. `dp[0] = 0`，`dp[i]` 初始化为 `i`（全用 1 凑的合法上界，兼作哨兵）
2. `i` 从 1 到 n，枚举 `j*j <= i`：`dp[i] = min(dp[i], dp[i - j*j] + 1)`
3. 返回 `dp[n]`

- 时间复杂度：\(O(n\sqrt{n})\)（`n ≤ 10^4` 时约 \(10^6\)）
- 空间复杂度：\(O(n)\)

### 解法二：BFS（换一种建模）

从剩余金额 `n` 出发，每层「减去一个平方数」；**层数 = 已用平方数个数**，首次减到 0 的层就是最少数量。用 `visited[]` 剪枝——首次到达某个剩余金额时用的个数一定最少，之后再遇到直接跳过。

- 时间复杂度：\(O(n\sqrt{n})\)，空间复杂度：\(O(n)\) 队列 + visited

### 解法三：数学四平方和定理（加分项）

**拉格朗日四平方和定理**：任意正整数都能表示为至多 4 个完全平方数之和；结合**勒让德三平方和定理**可推出答案只有 1/2/3/4 四种：

1. 先剥离因子 4：`while (n % 4 == 0) n /= 4`（答案不变）
2. `n % 8 == 7` → 答案为 **4**（形如 \(4^k(8m+7)\) 不能表示成 3 个平方数之和）
3. `n` 本身是完全平方数 → **1**
4. 存在 `a² + b² = n` → **2**
5. 其余 → **3**

- 时间复杂度：\(O(\sqrt{n})\)，空间复杂度：\(O(1)\)

## 代码

### 解法一：完全背包 DP（推荐）

```java
class Solution {
    public int numSquares(int n) {
        int[] dp = new int[n + 1];          // dp[i]：凑出 i 的最少平方数个数
        for (int i = 1; i <= n; i++) {
            dp[i] = i;                      // 上界哨兵：全用 1 凑，最多 i 个
            for (int j = 1; j * j <= i; j++) {
                // 枚举最后一个用的平方数 j*j，剩余部分再最优地凑
                dp[i] = Math.min(dp[i], dp[i - j * j] + 1);
            }
        }
        return dp[n];
    }
}
```

### 解法二：BFS

```java
class Solution {
    public int numSquares(int n) {
        Queue<Integer> queue = new LinkedList<>();
        boolean[] visited = new boolean[n + 1];   // 剩余金额是否已出现过
        queue.offer(n);                            // 起点目标金额 n，已用 0 个平方数
        visited[n] = true;
        int level = 0;                             // 层数 = 已用平方数个数

        while (!queue.isEmpty()) {
            level++;                               // 每往下走一层多用一个平方数
            int size = queue.size();
            for (int i = 0; i < size; i++) {
                int cur = queue.poll();
                for (int j = 1; j * j <= cur; j++) {
                    int next = cur - j * j;        // 减去一个平方数
                    if (next == 0) return level;   // 首次减到 0 → 最少个数
                    if (!visited[next]) {
                        visited[next] = true;      // 入队时标记，防重复扩展
                        queue.offer(next);
                    }
                }
            }
        }
        return -1;   // 1 本身就是平方数，任何 n 都能凑出，不会走到这里
    }
}
```

### 解法三：数学四平方和定理（加分项）

```java
class Solution {
    public int numSquares(int n) {
        while (n % 4 == 0) n /= 4;          // 剥离 4^k 因子，答案不变
        if (n % 8 == 7) return 4;           // 4^k(8m+7) 型 → 恰好 4 个
        if (isSquare(n)) return 1;          // 本身是完全平方数
        for (int a = 1; a * a < n; a++) {   // 枚举能否拆成两个平方数之和
            if (isSquare(n - a * a)) return 2;
        }
        return 3;                           // 其余情况 → 3 个
    }

    private boolean isSquare(int x) {
        int r = (int) Math.sqrt(x);
        return r * r == x;                  // 用乘回验证，避免浮点误差
    }
}
```

## 个人总结

### 1. 「平方数当硬币」：与 322 零钱兑换完全同构

| | 322. 零钱兑换 | 279（本题） |
|:---|:---|:---|
| 硬币面额 | 题目给定的 `coins` | `1, 4, 9, ...`（≤ √n 的平方数） |
| 目标金额 | `amount` | `n` |
| 转移 | `dp[x] = min(dp[x - coin]) + 1` | `dp[i] = min(dp[i - j*j]) + 1` |
| 凑不出 | 返回 -1（可能凑不出） | 不会（1 一定能凑） |

见 [322. 零钱兑换](322.%20零钱兑换.md)。同款题还有 322 的兄弟 518（求组合数）。识别「最少由若干可重复元素凑出」→ 完全背包。

### 2. 哨兵初始化用合法上界，不用 MAX_VALUE

`dp[i] = i`（全用 1 的方案）既是**必然可达的合法上界**，又天然避免 `MAX_VALUE + 1` 溢出——和 322 里 `amount + 1` 的哨兵思路一致。DP 求最值的通用原则：初始值选「一个合法的平凡解」而不是无穷大。

### 3. BFS 与 DP 两种建模对比

| 维度 | 完全背包 DP | BFS |
|:---|:---|:---|
| 状态 | `dp[i]` = 凑出 i 的最少个数 | 节点 = 剩余金额，层 = 已用个数 |
| 答案来源 | `dp[n]` 递推到底 | 首次减到 0 的层数 |
| 剪枝 | 哨兵上界 | `visited[]` 入队时标记 |

BFS 与 322 的解法四一模一样（那里是从 0 加硬币，这里是从 n 减平方数）。`visited` 必须在**入队时**标记而非出队时，否则同一层多个节点会重复生成同一个 next。

### 4. 数学解是「降维打击」但别当首选

四平方和定理让答案域缩到 {1,2,3,4}，\(O(\sqrt n)\) 直接判定；但定理本身依赖记忆（先剥 4 因子 → 判 `n%8==7` → 判 1 → 判 2 → 兜底 3），写错一条就全错。面试策略：DP 作保底正解，收尾时提一句「其实由拉格朗日四平方和定理，答案只可能是 1~4，可以 O(√n) 判定」——既稳又加分。
