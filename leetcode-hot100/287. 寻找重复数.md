## 题目描述

给定一个包含 `n + 1` 个整数的数组 `nums` ，其数字都在 `[1, n]` 范围内（包括 `1` 和 `n`），可知至少存在一个重复的整数。

假设 `nums` 只有 **一个重复的整数** ，返回 **这个重复的数** 。

你设计的解决方案必须 **不修改** 数组 `nums` 且只用常量级 `O(1)` 的额外空间。

---

## 示例

**示例 1**

```
输入：nums = [1,3,4,2,2]
输出：2
```

**示例 2**

```
输入：nums = [3,1,3,4,2]
输出：3
```

**示例 3**

```
输入：nums = [3,3,3,3,3]
输出：3
```

## 提示

- `1 <= n <= 10^5`
- `nums.length == n + 1`
- `1 <= nums[i] <= n`
- `nums` 中 **只有一个整数** 出现 **两次或多次** ，其余整数均只出现 **一次**

**进阶**：

- 如何证明 `nums` 中至少存在一个重复的数字？
- 你可以设计一个线性级时间复杂度 \(O(n)\) 的解决方案吗？

## 思路

### 抽屉原理：为什么一定有重复

`n+1` 个数塞进 `[1, n]` 这 `n` 个「抽屉」，由**鸽巢原理**必然至少一个抽屉有 2 个数——这就是重复数存在的保证（回答进阶问题一）。

### 解法一：排序 / 哈希集合（最直观，但违反约束）

- **排序**：排完序后相邻相等即重复数。\(O(n\log n)\) 时间、但**修改了数组**，违反约束。
- **哈希集合**：遍历时记录见过的数，重复出现即答案。\(O(n)\) 时间、\(O(n)\) 空间，**违反 O(1) 空间**。

这两种最好写，用来跑通题意，但都踩题目红线（不改数组 + O(1) 空间），所以只是起点。

> 约束「不改数组 + O(1) 空间」把简单解法全堵死了——这正是本题难点所在，逼出下面两种巧解。

### 解法二：二分查找答案（不改数组，O(1) 空间）

**对「答案的取值」二分**，而非对数组二分。设 `mid`，统计数组中 `≤ mid` 的元素个数 `cnt`：

- 若无重复，`[1, mid]` 里应恰好有 `mid` 个数，即 `cnt == mid`；
- **若 `cnt > mid`**，说明重复数落在 `[1, mid]`（左半，多出来的挤在这），收缩右边界；
- 否则重复数在 `[mid+1, n]`，收缩左边界。

```
nums=[1,3,4,2,2], n=4
mid=2: ≤2 的有 {1,2,2}=3 个 > 2 → 重复数在 [1,2]
mid=1: ≤1 的有 {1}=1 个 == 1 → 重复数在 [2,2]
→ 答案 2
```

- 时间复杂度：\(O(n \log n)\)，二分 `log n` 轮、每轮扫全数组计数 `O(n)`
- 空间复杂度：\(O(1)\)，不改数组 ✅

### 解法三：快慢指针 / Floyd 判环（最优，O(n) O(1)）

**把数组看成链表**：从下标 `i` 连一条边到 `nums[i]`（`i → nums[i]`）。因为值域是 `[1,n]`、下标是 `[0,n]`，每个下标都有唯一后继。**存在重复数 ⟺ 这个链表存在环**，且**重复数就是环的入口**。

```
nums=[1,3,4,2,2]
下标: 0 →1 →3 →2 →4 →2 →4 →2 ...   （nums[0]=1, nums[1]=3, nums[3]=2, nums[2]=4, nums[4]=2 ...）
                     ↑___________|    2→4→2 成环，入口 = 2 = 重复数
```

于是套用 [142. 环形链表 II](142.%20环形链表%20II.md) 的 Floyd 算法找环入口：

1. **快慢指针找相遇点**：`slow = nums[slow]` 走一步，`fast = nums[nums[fast]]` 走两步，直到相遇；
2. **找环入口**：另起一指针从起点 0 出发，与相遇点同步单步走，再次相遇处即环入口 = 重复数。

- 时间复杂度：\(O(n)\)
- 空间复杂度：\(O(1)\)，不改数组 ✅（本题最优）

## 代码

### 解法一：哈希集合（先跑通，违反 O(1) 空间）

```java
class Solution {
    public int findDuplicate(int[] nums) {
        Set<Integer> seen = new HashSet<>();
        for (int x : nums) {
            if (!seen.add(x)) return x;        // add 返回 false 说明已存在 → 重复
        }
        return -1;                             // 题目保证有解，不会到这
    }
}
```

### 解法二：二分查找答案（不改数组，O(1) 空间）

```java
class Solution {
    public int findDuplicate(int[] nums) {
        int lo = 1, hi = nums.length - 1;      // 答案取值范围 [1, n]
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            int cnt = 0;
            for (int x : nums) if (x <= mid) cnt++;   // 统计 ≤ mid 的个数
            if (cnt > mid) {
                hi = mid;                      // 多出来 → 重复数在左半 [lo, mid]
            } else {
                lo = mid + 1;                  // 重复数在右半 [mid+1, hi]
            }
        }
        return lo;                             // lo == hi 即答案
    }
}
```

### 解法三：快慢指针 / Floyd 判环（推荐，O(n) O(1)）

```java
class Solution {
    public int findDuplicate(int[] nums) {
        // 第一步：快慢指针找相遇点（把 i → nums[i] 当链表）
        int slow = 0, fast = 0;
        do {
            slow = nums[slow];                 // 走一步
            fast = nums[nums[fast]];           // 走两步
        } while (slow != fast);

        // 第二步：从起点和相遇点同步单步走，相遇处即环入口 = 重复数
        slow = 0;
        while (slow != fast) {
            slow = nums[slow];
            fast = nums[fast];
        }
        return slow;
    }
}
```

## 个人总结

### 1. 约束是本题的灵魂：不改数组 + O(1) 空间

排序（改数组）、哈希集合（O(n) 空间）都能秒解，但题目**明令禁止**。**做题先看约束**——正是这两条约束把题目从「简单」抬到「中等偏难」，逼出二分和快慢指针两种巧解。看到「O(1) 空间 + 不改输入」，就该警觉常规解法行不通。

### 2. 最妙的转化：把数组看成链表找环

`nums[i]` 的值域 `[1,n]` ⊆ 下标域 `[0,n]`，于是 `i → nums[i]` 构成一条每个点都有唯一后继的「链表」。**重复数 ⟺ 有两个下标指向同一个值 ⟺ 链表成环，且重复数是环入口**。这一步转化是全题精华，直接复用了 [142. 环形链表 II](142.%20环形链表%20II.md) 的 Floyd 判环。

- 从 0 出发是因为下标 0 不会被任何 `nums[i]`（值 ≥1）指向，一定在环外，可作链表起点。

### 3. 二分的是「答案」不是「数组」

数组本身无序，没法直接二分下标；这里二分的是**重复数的取值** `[1,n]`，用「`≤mid` 的个数是否超过 `mid`」判断答案在哪半。**「对答案二分」是数组无序但答案单调时的通用套路**（能否满足某条件随 mid 单调变化）。

### 4. 三种解法取舍

| 解法 | 时间 | 空间 | 改数组 | 定位 |
|:---|:---:|:---:|:---:|:---|
| 哈希集合 | \(O(n)\) | \(O(n)\) ❌ | 否 | 最直观，违反空间约束 |
| 二分答案 | \(O(n\log n)\) | \(O(1)\) ✅ | 否 | 满足约束，好想好写 |
| 快慢指针 | \(O(n)\) ✅ | \(O(1)\) ✅ | 否 | 唯一同时满足 O(n)+O(1)，最优 |

**面试建议**：先说哈希（表明会做），再讲二分（满足约束），最后亮快慢指针（最优）——层层递进最出彩。

### 5. Floyd 两阶段别写反

- 第一阶段用 `do-while`：因为 `slow`、`fast` 初始都在 0，必须先各走一步再判等，否则一开始就相等直接退出。
- 第二阶段 `slow` 重置回 0、`fast` 留在相遇点，两者**同速**前进，相遇点即环入口。这套「相遇点→入口」的距离关系证明见 [142](142.%20环形链表%20II.md)。
