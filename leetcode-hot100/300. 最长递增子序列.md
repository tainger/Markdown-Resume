## 题目描述

给你一个整数数组 `nums`，找到其中**最长严格递增子序列**的长度。

**子序列**是数组中通过删除一些（也可以不删除）元素得到的新序列，**不改变剩余元素的相对顺序**（区别于「子数组」必须连续）。

## 示例

**示例 1**

```
输入：nums = [10,9,2,5,3,7,101,18]
输出：4
解释：最长递增子序列是 [2,3,7,101]（或 [2,3,7,18]），长度为 4。
```

**示例 2**

```
输入：nums = [0,1,0,3,2]
输出：4
解释：最长递增子序列是 [0,1,2,3]（注意不是 [0,1,0,3]，因为严格递增不能相等）。
```

**示例 3**

```
输入：nums = [7,7,7,7,7,7,7]
输出：1
```

## 提示

- `-10^4 <= nums[i] <= 10^4`

## 思路

### 核心：「子序列」不要求连续 → DP 填表；「维护最长」→ 贪心 + 二分

子序列问题与子数组问题的关键区别：**子序列可以跳着选**，所以不能像 53. 最大子数组和那样用「以 i 结尾」的连续前缀做状态——但 DP 思路依然适用，只是状态定义从「连续段」变成「跳着选」。

两种解法一条链：

| 解法 | 视角 | 时间 | 空间 |
|:---|:---|:---:|:---:|
| 解法一：DP | `dp[i]` = 以 `nums[i]` 结尾的最长递增子序列长度 | \(O(n^2)\) | \(O(n)\) |
| 解法二：贪心 + 二分 | 维护一个「最小尾值」数组 `tails`，每来一个数二分替换 | \(O(n\log n)\) | \(O(n)\) |

### 解法一：动态规划（\(O(n^2)\)，基础必会）

#### 推导链：暴力枚举 → 暴露子问题结构 → 转移方程浮出来

**第一步：从暴力枚举出发**

暴力：枚举所有子序列（\(2^n\) 个），逐个判是否递增——指数级，不可行。

换一个角度：**枚举「以每个位置 i 结尾」的 LIS**。对每个 i，看它前面哪些位置的数比 `nums[i]` 小，从那些位置「接上来」：

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]
                 ↑      ↑
                 2      3
      以 3 结尾的 LIS：可以接在 [2] 后面 → [2,3]，长度 2
      以 5 结尾的 LIS：可以接在 [2] 后面 → [2,5]，长度 2
      以 7 结尾的 LIS：可以接在 [2,3] 或 [2,5] 后面 → 长度 3
```

**第二步：暴露子问题结构**

「以 i 结尾的 LIS」 = 「i 之前所有 `nums[j] < nums[i]` 的位置里，`dp[j]` 最大的那个」+ 1。

这就是**重复子结构**：每个 i 都要扫一遍前面所有 j，但每个 j 的 `dp[j]` 是子问题答案，可以复用。

**第三步：状态定义 + 转移方程**

- 状态：$dp[i]$ = **以 `nums[i]` 结尾**的最长递增子序列长度（结尾必须含 i）
- 转移：

$$
dp[i] = \max_{\substack{j < i \\ nums[j] < nums[i]}} \big(\, dp[j] + 1 \,\big), \quad \text{初值 } dp[i] = 1
$$

**第四步：答案**

$dp[i]$ 是「以 i 结尾」的局部最优，全局答案是所有位置的最大值：

$$
\text{ans} = \max_{i} \, dp[i]
$$

> 注意：「以 i 结尾」的状态设计，与 [53. 最大子数组和](53.%20最大子数组和.md) 的 `dp[i]` 定义**同源**——都是「结尾必须连着」，全局答案另取 max。区别只在于 53 的依赖是**前一个位置**（连续），本题的依赖是**前面所有更小的位置**（跳选）。

### 解法二：贪心 + 二分（\(O(n\log n)\)，进阶加分）

#### 核心洞察：长度相同时，尾值越小越有潜力

DP 的瓶颈：每个 i 要扫前面所有 j。换一个完全不同的视角——

> 维护一个数组 `tails`，`tails[k]` = **长度为 k+1 的递增子序列的最小可能尾值**。

**为什么「最小尾值」有用**：长度都是 1 的两个子序列 `[10]` 和 `[9]`，选哪个更有潜力接到后面？选尾值小的 `[9]`——后面来一个 11，能接上 `[9,11]` 但接不上 `[10,11]`（10 < 11 没问题，等等，能接上……换个例子：来一个 9.5 能接 `[9]` 不能接 `[10]`）。**尾值越小，未来能接上的数越多**。

**操作规则**：遍历 `nums`，对每个 `x`：

1. 如果 `x` > `tails` 末尾 → **追加**到 `tails` 末尾（LIS 又长了一格）；
2. 否则 → 在 `tails` 里二分找到**第一个 ≥ x 的位置**，**替换**它（把那个长度的尾值变得更小，给后面更多机会）。

```
nums = [10, 9, 2, 5, 3, 7, 101, 18]

x=10：tails=[10]                     （长度1的尾值=10）
x=9 ：9 < 10，替换 → tails=[9]        （长度1的尾值从10降到9，更优）
x=2 ：2 < 9，替换 → tails=[2]         （长度1的尾值再降到2）
x=5 ：5 > 2，追加 → tails=[2,5]       （长度2的尾值=5）
x=3 ：3 < 5，替换 → tails=[2,3]       （长度2的尾值从5降到3，更优）
x=7 ：7 > 3，追加 → tails=[2,3,7]     （长度3的尾值=7）
x=101：101 > 7，追加 → tails=[2,3,7,101]（长度4的尾值=101）
x=18 ：18 < 101，替换 → tails=[2,3,7,18]（长度4的尾值从101降到18）

最终 len(tails) = 4 → LIS 长度 = 4 ✓
```

**关键点**：`tails` 数组本身**不一定是**真正的 LIS（例子里 `[2,3,7,18]` 恰好是，但有时不是），但它的**长度**一定等于 LIS 长度。这是因为 `tails` 始终保持严格递增（替换不会破坏有序性），且每次追加都对应一次「找到更长的递增序列」。

- 时间 \(O(n \log n)\)：每个元素一次二分，二分 \(O(\log n)\)
- 空间 \(O(n)\)

> **严格递增的保证**：二分找的是「第一个 ≥ x 的位置」（`lower_bound`），不是「第一个 > x 的位置」。这保证相等元素会替换到同一位置，不会错误地追加——比如 `[2,2]`，第二个 2 替换第一个 2，`tails` 仍是 `[2]`，长度 1，正确。如果要的是**非递减**（允许相等），改成找「第一个 > x 的位置」（`upper_bound`）即可。

## 代码

### 解法一：动态规划（\(O(n^2)\)）

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        int n = nums.length;
        int[] dp = new int[n];
        int ans = 1;
        
        for (int i = 0; i < n; i++) {
            dp[i] = 1;                              // 至少自己一个字符
            for (int j = 0; j < i; j++) {            // 扫前面所有更小的位置
                if (nums[j] < nums[i]) {
                    dp[i] = Math.max(dp[i], dp[j] + 1);
                }
            }
            ans = Math.max(ans, dp[i]);              // 全局取 max
        }
        return ans;
    }
}
```

- 外层枚举 i，内层扫 `[0, i)` 找所有 `nums[j] < nums[i]` 的位置取最大 `dp[j] + 1`
- `n = 2500` 时 \(n^2 = 6.25 \times 10^6\)，LeetCode 可过

### 解法二：贪心 + 二分（\(O(n\log n)\)，进阶）

```java
class Solution {
    public int lengthOfLIS(int[] nums) {
        // tails[k] = 长度为 k+1 的递增子序列的最小可能尾值
        int[] tails = new int[nums.length];
        int len = 0;                                 // tails 的有效长度
        
        for (int x : nums) {
            // 二分：找第一个 >= x 的位置（lower_bound，保证严格递增）
            int lo = 0, hi = len;                    // 搜索范围 [0, len)
            while (lo < hi) {
                int mid = lo + (hi - lo) / 2;
                if (tails[mid] < x) lo = mid + 1;
                else hi = mid;
            }
            // lo == hi == 「第一个 >= x 的位置」或 == len（x 比所有都大）
            if (lo == len) {
                tails[len++] = x;                   // 追加：x 比所有尾值都大，LIS 又长一格
            } else {
                tails[lo] = x;                      // 替换：把该长度的尾值降到 x
            }
        }
        return len;
    }
}
```

- `tails` 始终严格递增：替换用的是 `lower_bound`（第一个 ≥ x），不会把相等的数追加到末尾
- **`lo == len` 的含义**：二分范围是 `[0, len)`，如果 `x` 比所有尾值都大，`lo` 会走到 `len`（越界），此时走追加分支
- 返回 `len` 而非 `tails`——`tails` 不是真正的 LIS，但长度正确

## 个人总结

### 1. 题眼：子序列（不连续）+ 递增 → DP \(O(n^2)\) 是基础，二分 \(O(n\log n)\) 是加分

`n ≤ 2500` 时 \(O(n^2)\) 可过（约 \(6 \times 10^6\)）。**面试口径**：先讲 DP（状态定义清晰、必会），再主动说「有 \(O(n\log n)\) 的贪心 + 二分解法」并写出来——**能主动给出进阶解法是 P7 信号**。

### 2. 推导链：从「枚举以 i 结尾的 LIS」到「转移方程自己浮出来」

与 [53. 最大子数组和](53.%20最大子数组和.md) 第 2 点、[5. 最长回文子串](5.%20最长回文子串.md) 推导链同一套纪律：

```
暴力枚举所有子序列（2^n）
      ↓ 按「结尾位置 i」分组，找子问题结构
状态：dp[i] = 以 nums[i] 结尾的 LIS 长度
      ↓ 以 i 结尾的 LIS = 前面所有更小位置的 dp[j] 最大值 + 1
转移：dp[i] = max(dp[j] + 1) for all j < i, nums[j] < nums[i]
      ↓ dp[i] 是局部最优，全局另取
答案：ans = max(dp[0..n-1])
```

**关键洞察**：「以 i 结尾」的分组方式是所有子序列 DP 的通用套路——**子序列问题几乎都能用「以 i 结尾」+ 一维递推解决**。

### 3. DP vs 贪心 + 二分：两种视角的本质区别

| 维度 | DP（\(O(n^2)\)） | 贪心 + 二分（\(O(n\log n)\)） |
|:---|:---|:---|
| 状态 | `dp[i]` = 以 i 结尾的 LIS 长度 | `tails[k]` = 长度 k+1 的最小尾值 |
| 视角 | **看每个位置**：我这个位置能接在哪？ | **看每个长度**：这个长度的最小尾值是多少？ |
| 依赖 | 每个 i 扫前面所有 j | 每个元素二分找替换位置 |
| 能否还原 LIS | 能（记录前驱） | 不能直接还原（tails 不是真 LIS） |
| 适用 | 需要还原序列 / n 小 | 只问长度 / n 大 |

**面试答法**：先写 DP（保证正确、能还原序列），再讲贪心 + 二分（优化复杂度、只问长度）——**两条腿走路，先稳后快**。

### 4. 贪心 + 二分的第一大坑：`lower_bound` vs `upper_bound`

**严格递增**（本题）用 `lower_bound`（第一个 **≥** x 的位置）：

```
nums = [2, 2]：第二个 2 找到 tails=[2] 的位置 0，替换，tails 仍 [2]，长度 1 ✓
若用 upper_bound（第一个 > x）：找不到 > 2 的，追加 → tails=[2,2]，长度 2 ✗
```

**非递减**（允许相等，如 673. 最长递增子序列的个数）用 `upper_bound`（第一个 **>** x 的位置）。

> 一句话记忆：**严格递增找 ≥（lower_bound），非递减找 >（upper_bound）**。写反就错。

### 5. `tails` 数组不是真正的 LIS，但长度正确

`tails` 在替换过程中会「打乱」元素来源——比如 `tails = [2, 3, 7, 18]`，但某个替换可能把一个本该属于不同子序列的尾值混进来。**`tails` 的长度 = LIS 镴度**是成立的（每次追加都对应一次真正的递增扩展），但**内容不一定是合法 LIS**。

如果题目要求**还原** LIS 序列本身，必须用 DP + 记录前驱指针 `prev[i]`，最后从 `dp` 最大的位置回溯。贪心 + 二分只适合「只问长度」的场景。

### 6. 同源题族：「LIS 模板」的迁移

| 题目 | 变化点 | 迁移要点 |
|:---|:---|:---|
| 354. 俄罗斯套娃信封问题 | 一维 → 二维 | 先按宽度升序、高度降序排，再对高度做一维 LIS |
| 673. 最长递增子序列的个数 | 问个数 | DP 同时记 `length[i]` 和 `count[i]` 两个状态 |
| 1671. 得到山形数组的最少删除次数 | 双向 LIS | 从左和从右各做一次 LIS，拼山形 |
| 1964. 俄式套娃（二维 LIS） | 同 354 | 同上，排序后一维化 |

> 记忆：**LIS = DP \(O(n^2)\)：以 i 结尾，扫前面更小的 j 取 max + 1；进阶贪心 + 二分 \(O(n\log n)\)：维护 tails 最小尾值数组，追加或替换，长度即答案；严格递增用 lower_bound，非递减用 upper_bound。**
