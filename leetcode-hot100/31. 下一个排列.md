# 31. 下一个排列

> **难度**：🟡 中等 | **标签**：数组、双指针 | **企业**：—

## 题目描述

整数数组的一个 **排列** 就是将其所有成员以序列或线性顺序排列。

例如，`arr = [1,2,3]`，以下这些都可以视作 arr 的排列：`[1,2,3]`、`[1,3,2]`、`[3,1,2]`、`[2,3,1]`。

整数数组的 **下一个排列** 是指其整数的**下一个字典序更大的排列**。更正式地，如果数组的所有排列根据其字典顺序从小到大排列在一个容器中，那么数组的 **下一个排列** 就是在这个有序容器中排在它后面的那个排列。如果不存在下一个更大的排列，那么这个数组必须重排为字典序最小的排列（即，其元素按升序排列）。

- 例如，`arr = [1,2,3]` 的下一个排列是 `[1,3,2]`。
- 类似地，`arr = [2,3,1]` 的下一个排列是 `[3,1,2]`。
- 而 `arr = [3,2,1]` 的下一个排列是 `[1,2,3]`，因为 `[3,2,1]` 不存在一个字典序更大的排列。

必须 **原地** 修改，只允许使用额外常数空间。

## 示例

**示例 1**

```
输入：nums = [1,2,3]
输出：[1,3,2]
```

**示例 2**

```
输入：nums = [3,2,1]
输出：[1,2,3]
```

**示例 3**

```
输入：nums = [1,1,5]
输出：[1,5,1]
```

- `0 <= nums[i] <= 100`

## 思路

### 核心思想：找下降点 → 交换 → 反转后缀

字典序「下一个」的本质：**把尽可能靠右的一位变大一点点，然后把右边的尾巴从降序翻成升序**（升序尾巴是这段能组成的最小排列）。

```
1 2 3       1 3 2
  ↑   ↓       ↑ ↓
  下降点 i=1  交换 2 和 3，后缀 [3] 只有一位 → 1 3 2

1 3 2       2 1 3
↑     ↑      ↑ ↓ ↓
i=0         从右找第一个 > 1 的是 2 → 交换 → 2 3 1 → 反转后缀 [3,1] → 2 1 3
```

### 解法一：标准三步（推荐）

1. **找下降点**：从右往左找第一个 `nums[i] < nums[i+1]` 的位置 `i`（后缀 `[i+1, n)` 是降序）
2. **交换**：从右往左找第一个 `nums[j] > nums[i]`（后缀降序 → 它就是「比 `nums[i]` 大的最小元素」），交换 `nums[i]`、`nums[j]`
3. **反转**：反转 `[i+1, n)` 为升序——这是「尾巴能组成的最小排列」

若第 1 步找不到 `i`（整个数组降序，已是最大排列），直接反转整个数组得到最小排列。

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\)

### 解法二：交换 + 后缀排序（正确但可优化）

1. 找下降点、交换步骤同解法一
2. 最后用 `Arrays.sort(nums, i+1, n)` 代替手动反转

- 时间复杂度：\(O(n \log n)\)，空间复杂度：\(O(\log n)\)（排序内部）
- 正确但没必要：`[i+1, n)` 交换后**仍然是降序**，反转（\(O(n)\)）即可变升序，排序是杀鸡用牛刀

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;   // ✅ 找下降点对了

        if (i >= 0) {
            // ❌ ① 直接交换 i 和 i+1，没找「右边第一个比 nums[i] 大的元素」
            //    [1,3,2]：i=0，应交换 nums[2]=2，这里却交换了 nums[1]=3
            //    → [3,1,2]（正确应为 [2,1,3]）
            int tmp = nums[i];
            nums[i] = nums[i + 1];
            nums[i + 1] = tmp;
        }
        // ❌ ② 漏了反转后缀 [i+1, n)
        //    [3,2,1]：i == -1，什么都不做 → 输出 [3,2,1]（应为 [1,2,3]）
        //    [1,2,3] 碰巧对（交换后后缀只有 1 位），换个例子立刻露馅
    }
}
```

### 解法一：标准三步（双指针原地反转）

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;
        int i = n - 2;

        // 1. 找下降点：从右往左第一个 nums[i] < nums[i+1]
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            // 2. 从右往左找第一个 > nums[i] 的元素（后缀降序 → 即「比它大的最小」）
            int j = n - 1;
            while (j > i && nums[j] <= nums[i]) j--;
            swap(nums, i, j);
        }

        // 3. 反转后缀 [i+1, n)（i == -1 时反转整个数组 → 最小排列）
        reverse(nums, i + 1, n - 1);
    }

    private void swap(int[] a, int l, int r) {
        int t = a[l];
        a[l] = a[r];
        a[r] = t;
    }

    private void reverse(int[] a, int l, int r) {
        while (l < r) swap(a, l++, r--);
    }
}
```

### 解法二：交换 + 后缀排序

```java
class Solution {
    public void nextPermutation(int[] nums) {
        int n = nums.length;
        int i = n - 2;
        while (i >= 0 && nums[i] >= nums[i + 1]) i--;

        if (i >= 0) {
            int j = n - 1;
            while (j > i && nums[j] <= nums[i]) j--;
            int t = nums[i];
            nums[i] = nums[j];
            nums[j] = t;
        }
        // Arrays.sort 对 int[] 的 [from, to) 区间排序
        Arrays.sort(nums, i + 1, n);   // 正确，但 O(n log n) 不如反转 O(n)
    }
}
```

> 💡 记忆：**「下一个排列」三步曲 = 找下降点 → 换右侧最小更大 → 反转尾巴**。后缀必然是降序，这是整个算法能 O(n) 的关键。

## 个人总结

### 1. 交换对象错了：不是 `i+1`，是「右边第一个比 `nums[i]` 大的」

后缀 `[i+1, n)` 是降序，所以**从右往左第一个 `> nums[i]` 的元素，恰好就是「比它大的最小元素」**——交换它，字典序增幅才最小，才是「下一个」而不是「跳过一串」。

```
[1,3,2]：i=0，应找右边第一个 > 1 的元素 → 2（下标 2）
❌ 交换 i 和 i+1 → [3,1,2]（跳过了 [2,1,3]、[2,3,1]、[3,1,2] 之前的所有排列）
✅ 交换 1 和 2 → [2,3,1] → 反转 → [2,1,3] ✓
```

### 2. 反转后缀不能省，`i == -1` 时也要反转

官方示例 2（`[3,2,1]` → `[1,2,3]`）就是抓漏反转的：整个数组已降序，`i == -1`，此时要**反转整个数组**得到最小排列。漏了就直接原样输出。

`[1,2,3]` 这类「后缀只有一位」的用例会**碰巧通过**（反转区间为空），掩盖 bug——和 #3 一样，官方样例全过不代表对。

### 3. 必测用例：`[1,3,2]`

```
[1,3,2] 的下一个排列是 [2,1,3]
```

这是最经典的坑：`i` 不在倒数第二位（交换对象不是 `i+1`），且后缀有两位（必须反转）。**任何「下一个排列」的实现，先拿它测。**

### 4. 套路位置：它是回溯全排列的「相邻生成器」

LeetCode 46（全排列）按字典序输出的相邻两个排列，就是依次做一次 next permutation。想通了「找下降点 + 反转尾巴」的几何含义（把后缀从最大翻成最小），46 题的去重逻辑也会更好理解。
