## 题目描述

给你一个整数数组 `coins` ，表示不同面额的硬币；以及一个整数 `amount` ，表示总金额。

计算并返回可以凑成总金额所需的 **最少的硬币个数** 。如果没有任何一种硬币组合能组成总金额，返回 `-1` 。

你可以认为每种硬币的数量是 **无限的** 。

---

## 示例

**示例 1**

```
输入：coins = [1, 2, 5], amount = 11
输出：3
解释：11 = 5 + 5 + 1
```

**示例 2**

```
输入：coins = [2], amount = 3
输出：-1
```

**示例 3**

```
输入：coins = [1], amount = 0
输出：0
```

## 提示

- `1 <= coins.length <= 12`
- `1 <= coins[i] <= 2^31 - 1`
- `0 <= amount <= 10^4`

## 思路

### 核心：求「凑出 amount」的最少硬币数

每种硬币可**无限次**使用（这是「完全背包」的标志，区别于 [416 分割等和子集](416.%20分割等和子集.md) 的 0-1 背包每个数只用一次）。目标是**最少个数**，凑不出返回 `-1`。

定义子问题：`f(x)` = 凑出金额 `x` 所需的最少硬币数。则

```
f(x) = min( f(x - coin) + 1 )   对每个 coin，且 x - coin >= 0
f(0) = 0                        凑 0 元需要 0 枚
```

即「凑 `x` 元」= 枚举最后一枚硬币用哪种 `coin`，剩下 `x-coin` 元再最优地凑，取最小。

```
amount=11, coins=[1,2,5]
f(11) = min( f(10)+1, f(9)+1, f(6)+1 )
                最后用1     最后用2    最后用5
一路递归到 f(0)=0，回溯取最小 → 3（5+5+1）
```

### 解法一：回溯（暴力枚举，理解入口）

直接按定义递归枚举「每一步选哪种硬币」，凑到 0 就记录用了几枚，取全局最小。

- 时间复杂度：最坏 \(O(n^{amount})\)（每步 n 种选择、深度约 amount），指数级
- 空间复杂度：\(O(amount)\) 递归栈
- `amount ≤ 10^4` 时**必然 TLE**，仅用于理解「枚举最后一枚 + 递归剩余」的结构

> 瓶颈：`f(6)` 会被 `f(11)→f(6)`、`f(11)→f(9)→...` 等多条路径**反复计算**——重叠子问题，正是记忆化/DP 的信号。

### 解法二：记忆化搜索（自顶向下 + 缓存）

给回溯加一个 `memo[x]` 缓存「凑 `x` 元的最少硬币数」，每个 `x` 只算一次：

1. `memo[x]` 已算过 → 直接返回
2. 否则枚举每种 `coin`，递归 `dfs(x - coin)`，取 `min + 1`
3. 凑不出记为 `-1`（用一个特殊值区分）

- 时间复杂度：\(O(amount \times n)\)，状态数 `amount`，每个状态枚举 `n` 种硬币
- 空间复杂度：\(O(amount)\) 缓存 + 递归栈

### 解法三：完全背包 DP（自底向上，推荐）

`dp[x]` = 凑出金额 `x` 的最少硬币数。**外层遍历金额、内层遍历硬币**（求最值时两层顺序都可）：

1. 初始化 `dp[0] = 0`，其余 `dp[x] = amount + 1`（一个不可能达到的大值，代表暂时凑不出）
2. 对每个金额 `x` 从 1 到 amount，对每种 `coin`：若 `x >= coin`，`dp[x] = min(dp[x], dp[x-coin] + 1)`
3. 最后 `dp[amount] > amount` 说明凑不出，返回 `-1`；否则返回 `dp[amount]`

- 时间复杂度：\(O(amount \times n)\)
- 空间复杂度：\(O(amount)\)

> 为什么初值用 `amount+1` 而不是 `Integer.MAX_VALUE`：凑出 `amount` 最多用 `amount` 枚（全用面额 1），所以 `amount+1` 就是「不可达」的安全哨兵，还能避免 `MAX_VALUE + 1` 溢出。

## 代码

### 解法一：回溯（会 TLE，理解入口）

```java
class Solution {
    private int ans = Integer.MAX_VALUE;

    public int coinChange(int[] coins, int amount) {
        backtrack(coins, amount, 0);
        return ans == Integer.MAX_VALUE ? -1 : ans;
    }

    // rest：还需凑的金额；count：已用硬币数
    private void backtrack(int[] coins, int rest, int count) {
        if (rest == 0) {                       // 凑成功
            ans = Math.min(ans, count);
            return;
        }
        if (count >= ans) return;              // 剪枝：已经不比当前最优更好
        for (int coin : coins) {
            if (coin <= rest) {
                backtrack(coins, rest - coin, count + 1);
            }
        }
    }
}
```

### 解法二：记忆化搜索（自顶向下 + 缓存）

```java
class Solution {
    private int[] memo;

    public int coinChange(int[] coins, int amount) {
        memo = new int[amount + 1];
        Arrays.fill(memo, -2);                 // -2 = 未计算；-1 = 凑不出
        return dfs(coins, amount);
    }

    // 返回凑出 rest 的最少硬币数，凑不出返回 -1
    private int dfs(int[] coins, int rest) {
        if (rest == 0) return 0;               // 凑 0 元需要 0 枚
        if (rest < 0) return -1;               // 超了，不可行
        if (memo[rest] != -2) return memo[rest];  // 已算过

        int min = Integer.MAX_VALUE;
        for (int coin : coins) {
            int sub = dfs(coins, rest - coin);
            if (sub != -1) min = Math.min(min, sub + 1);  // 可行才更新
        }
        memo[rest] = (min == Integer.MAX_VALUE) ? -1 : min;
        return memo[rest];
    }
}
```

### 解法三：完全背包 DP（推荐）

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int[] dp = new int[amount + 1];
        Arrays.fill(dp, amount + 1);           // 哨兵大值：最多 amount 枚（全用面额1）
        dp[0] = 0;                             // 凑 0 元需要 0 枚

        for (int x = 1; x <= amount; x++) {    // 外层：每个金额
            for (int coin : coins) {           // 内层：每种硬币
                if (coin <= x) {
                    dp[x] = Math.min(dp[x], dp[x - coin] + 1);
                }
            }
        }
        return dp[amount] > amount ? -1 : dp[amount];  // 仍是哨兵值 → 凑不出
    }
}
```

## 个人总结

### 1. 「每种硬币无限用」→ 完全背包

看到「物品可重复选无限次 + 求方案（最少/方案数）」，就是**完全背包**；若每个物品只能选一次，则是 [416](416.%20分割等和子集.md) 那样的 **0-1 背包**。二者转移几乎一样，区别只在一维数组内层循环的**遍历方向**（见第 4 点）。

### 2. 从回溯到记忆化到 DP 的完整演进

| 解法 | 复杂度 | 关键 |
|:---|:---:|:---|
| 回溯 | \(O(n^{amount})\) | 枚举每步选哪枚，重复算子问题，TLE |
| 记忆化搜索 | \(O(amount \times n)\) | 加 `memo` 缓存，自顶向下 |
| 完全背包 DP | \(O(amount \times n)\) | 自底向上递推，最优 |

这是**动态规划三部曲的标准路径**：先写出暴力递归（找到「子问题 + 递推关系」），发现重叠子问题→加缓存变记忆化，再翻成自底向上的 DP。理解不了 DP 时，从回溯往下推最稳。

### 3. 状态定义与转移

- 状态：`dp[x]` = 凑出金额 `x` 的最少硬币数
- 转移：`dp[x] = min(dp[x - coin] + 1)`，枚举「最后一枚用哪种硬币」
- 初始：`dp[0] = 0`（凑 0 元 0 枚），其余设为不可达大值

### 4. 求最值：内外层循环顺序无所谓；求方案数才讲究

本题求**最少个数**（最值），外层金额/内层硬币、或外层硬币/内层金额**都对**。但如果是「求凑成 amount 的**组合数**」（如 518 零钱兑换 II），就必须**外层硬币、内层金额**，否则会把顺序不同的排列重复计数。**最值不敏感、计数敏感**，是背包问题的易混点。

### 5. 哨兵大值用 `amount + 1`，别用 `MAX_VALUE`

凑出 `amount` 最多用 `amount` 枚（全 1 元面额），所以任何合法解都 `≤ amount`，用 `amount + 1` 作「凑不出」标记既安全又能避免 `Integer.MAX_VALUE + 1` 整数溢出。最后判 `dp[amount] > amount` 即凑不出。

### 6. 记忆化里 `-1` 和「未计算」要用不同标记

记忆化时 `-1` 是「凑不出」的合法结果，不能同时用它表示「未计算」——否则凑不出的状态会被反复重算。代码里用 `-2` 表示未计算、`-1` 表示凑不出，区分开。
