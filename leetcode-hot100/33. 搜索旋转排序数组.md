## 题目描述

整数数组 `nums` 按升序排列，数组中的值 **互不相同** 。

在传递给函数之前，`nums` 在预先未知的某个下标 `k`（`0 <= k < nums.length`）上进行了 **旋转**，使数组变为 `[nums[k], nums[k+1], ..., nums[n-1], nums[0], nums[1], ..., nums[k-1]]`（下标 **从 0 开始** 计数）。例如， `[0,1,2,4,5,6,7]` 在下标 `3` 处经旋转后可能变为 `[4,5,6,7,0,1,2]` 。

给你 **旋转后** 的数组 `nums` 和一个整数 `target` ，如果 `nums` 中存在这个目标值 `target` ，则返回它的下标，否则返回 `-1` 。

你必须设计一个时间复杂度为 `O(log n)` 的算法解决此问题。

## 思路

### 核心思想

旋转数组被旋转点分成**两段各自有序**的区间，二分后 `[left, mid]` 与 `[mid, right]` **至少有一半完全有序**（旋转点只能落在其中一侧）——用有序半区的两个端点就能判断 `target` 落不落在里面，从而把搜索范围安全地缩到一半，保持 \(O(\log n)\)。

### 解法一：两次二分（先找旋转点，再在有序段内找，基础）

1. 第一趟二分找**最小值（旋转点）下标**：`nums[mid] > nums[right]` → 最小值在右半，`lo = mid + 1`；否则在含 `mid` 的左半，`hi = mid`，结束时 `lo` 即旋转点；
2. 用 `target <= nums[n-1]` 判断 target 属于旋转点右侧段还是左侧段，圈定有序区间 `[lo, hi]`；
3. 第二趟在 `[lo, hi]` 上做**标准二分**，找不到返回 `-1`。

- 时间复杂度：\(O(\log n)\)，两趟二分；空间复杂度：\(O(1)\)

### 解法二：一次二分，判断哪半有序（推荐）

1. 闭区间 `while (left <= right)` 二分框架，`nums[mid] == target` 直接返回；
2. **判哪半有序**：`nums[left] <= nums[mid]` → 左半 `[left, mid]` 有序，否则右半 `[mid, right]` 有序；
3. 在**有序的那一半**用端点判断 target 是否在范围内：
   - 左半有序：`nums[left] <= target < nums[mid]` → `right = mid - 1`；否则 `left = mid + 1`；
   - 右半有序：`nums[mid] < target <= nums[right]` → `left = mid + 1`；否则 `right = mid - 1`；
4. 循环结束未命中返回 `-1`。

- 时间复杂度：\(O(\log n)\)；空间复杂度：\(O(1)\)

## 代码

### 解法一：两次二分（先找旋转点）

```java
class Solution {
    public int search(int[] nums, int target) {
        int n = nums.length;
        // 第一趟：二分找最小值（旋转点）下标
        int lo = 0, hi = n - 1;
        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] > nums[hi]) lo = mid + 1;   // 最小值在 mid 右侧
            else hi = mid;                            // 最小值在 mid 及左侧
        }
        int pivot = lo;
        // 第二趟：按 target 与末元素的大小关系锁定有序段，标准二分
        lo = (target <= nums[n - 1]) ? pivot : 0;
        hi = (target <= nums[n - 1]) ? n - 1 : pivot - 1;
        while (lo <= hi) {
            int mid = lo + (hi - lo) / 2;
            if (nums[mid] == target) return mid;
            else if (nums[mid] < target) lo = mid + 1;
            else hi = mid - 1;
        }
        return -1;
    }
}
```

### 解法二：一次二分（推荐）

```java
class Solution {
    public int search(int[] nums, int target) {
        int left = 0, right = nums.length - 1;
        while (left <= right) {
            int mid = left + (right - left) / 2;
            if (nums[mid] == target) return mid;      // 命中
            if (nums[left] <= nums[mid]) {            // 左半 [left, mid] 有序
                if (nums[left] <= target && target < nums[mid]) {
                    right = mid - 1;                  // target 在有序左半内
                } else {
                    left = mid + 1;                   // 否则去右半找
                }
            } else {                                  // 右半 [mid, right] 有序
                if (nums[mid] < target && target <= nums[right]) {
                    left = mid + 1;                   // target 在有序右半内
                } else {
                    right = mid - 1;                  // 否则去左半找
                }
            }
        }
        return -1;
    }
}
```

## 个人总结

### 1. 判断哪半有序：`nums[left] <= nums[mid]` 的 `<=` 不能丢

值虽互不相同，但区间可能收缩到只剩一两个元素（`left == mid`），此时 `nums[left] == nums[mid]`，必须视为「左半有序」（单元素天然有序）。写成 `<` 会在短区间误判，走进错误分支漏解——这是本题最高频 bug。

### 2. target 的范围判断：端点要一开一闭

有序左半的判断是 `nums[left] <= target && target < nums[mid]`：`mid` 已在 `== target` 分支排除过，所以右端取开；左端必须含 `nums[left]`。两端都写 `<=` 会让边界 target 走错方向。右半对称地取 `nums[mid] < target <= nums[right]`。

### 3. 为什么这样二分不会漏解

旋转点只可能落在 `[left, mid]` 或 `[mid, right]` 之一，所以**每轮至少有一半完全有序**。在有序半区做范围判断是安全的：target 在 → 进有序半区（等价标准二分）；不在 → 有序半区整体与 target 无缘（可能包含旋转点的那半才是出路）。每轮都确定性排除一半，\(O(\log n)\) 成立。不放心时用 `[4,5,6,7,0,1,2]` 手推两轮即可验证。
