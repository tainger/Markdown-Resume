## 题目描述

给你一个整数数组 `nums` 和一个整数 `k` ，请你返回其中出现频率前 `k` 高的元素。你可以按 **任意顺序** 返回答案。

---

## 示例

**示例 1**

```
输入：nums = [1,1,1,2,2,3], k = 2
输出：[1,2]
```

**示例 2**

```
输入：nums = [1], k = 1
输出：[1]
```

---

## 提示

- `1 <= nums.length <= 10^5`
- `k` 的取值范围是 `[1, 数组中不相同的元素的个数]`
- 题目数据保证答案唯一，换句话说，数组中前 `k` 个高频元素的集合是唯一的
- **进阶**：你所设计算法的时间复杂度 **必须** 优于 \(O(n \log n)\)，其中 `n` 是数组大小

---

## 思路

### 两步走：先统计频次，再选出频次最大的 K 个

不管哪种解法，第一步都一样：**用哈希表 `HashMap<数值, 频次>` 统计每个元素出现次数**，\(O(n)\)。区别在第二步「怎么从频次里挑出最大的 K 个」。

```
nums = [1,1,1,2,2,3]  →  频次表 {1:3, 2:2, 3:1}  →  取频次最大的 2 个 → [1, 2]
```

### 解法一：计数 + 按频次全排序（最直观，先跑通）

统计频次后，把所有不同元素按频次**降序排序**，取前 `k` 个。

- 时间复杂度：\(O(n + m \log m)\)，`m` 为不同元素个数，最坏 `m = n` 即 \(O(n \log n)\)
- 空间复杂度：\(O(m)\)
- 最好理解，但**不满足进阶要求**（进阶要求优于 \(O(n \log n)\)）；作为优化的起点

> 瓶颈：我们只要**前 K 个**，却把全部 `m` 个元素都完整排序了，做了多余的功——只需维护「当前最大的 K 个」即可，这就是堆的用武之地。

### 解法二：小顶堆维护「当前频次最大的 K 个」（推荐，满足进阶）

维护一个**大小为 K 的小顶堆**（堆顶是这 K 个里频次最小的）：

1. 遍历频次表的每个 `(数值, 频次)`：
2. 若堆未满（`< k`），直接入堆；
3. 若堆已满，比较当前频次与堆顶（堆里最小频次）：**更大就弹出堆顶、把当前压入**；否则跳过。
4. 遍历完，堆里就是频次最大的 K 个。

**为什么用小顶堆而非大顶堆**：要保留「最大的 K 个」，就得能随时**淘汰掉这 K 个里最小的那个**——小顶堆堆顶恰是最小值，淘汰 \(O(\log k)\)。若用大顶堆，堆顶是最大值，没法高效淘汰最小的。

- 时间复杂度：\(O(n + m \log k)\)，一般记 \(O(n \log k)\)，**优于 \(O(n \log n)\)**（因 `k ≤ m ≤ n`）
- 空间复杂度：\(O(m + k)\)

### 解法三：桶排序（\(O(n)\)，频次当下标）

**频次的范围是已知且有界的**：任何元素的频次都在 `[1, n]` 之间。于是可以**以频次为下标建桶**：`bucket[f]` 存所有「出现 f 次」的元素。

1. 统计频次表
2. 建 `n+1` 个桶，把每个元素放进 `bucket[它的频次]`
3. **从高频次的桶往低频次遍历**，依次取出元素，凑够 K 个即停

- 时间复杂度：\(O(n)\)，无排序，纯遍历
- 空间复杂度：\(O(n)\)
- 这是最优解，用「频次值域有界」换掉了排序/堆的 log。详见 [桶思想.md](../算法思想/桶思想.md)

## 代码

### 解法一：计数 + 按频次全排序（先跑通）

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : nums) cnt.merge(x, 1, Integer::sum);   // 统计频次

        // 所有不同元素按频次降序排序
        List<Integer> keys = new ArrayList<>(cnt.keySet());
        keys.sort((a, b) -> cnt.get(b) - cnt.get(a));

        int[] ans = new int[k];
        for (int i = 0; i < k; i++) ans[i] = keys.get(i);   // 取前 k 个
        return ans;
    }
}
```

### 解法二：小顶堆（推荐，满足进阶）

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : nums) cnt.merge(x, 1, Integer::sum);

        // 小顶堆，按频次升序（堆顶 = 当前 K 个里频次最小的）
        PriorityQueue<Integer> heap =
            new PriorityQueue<>((a, b) -> cnt.get(a) - cnt.get(b));

        for (int key : cnt.keySet()) {
            heap.offer(key);
            if (heap.size() > k) heap.poll();               // 超过 K 个就弹掉最小频次的
        }

        int[] ans = new int[k];
        for (int i = 0; i < k; i++) ans[i] = heap.poll();   // 堆里剩的就是答案
        return ans;
    }
}
```

### 解法三：桶排序（\(O(n)\)，最优）

```java
class Solution {
    public int[] topKFrequent(int[] nums, int k) {
        Map<Integer, Integer> cnt = new HashMap<>();
        for (int x : nums) cnt.merge(x, 1, Integer::sum);

        // 以频次为下标建桶：bucket[f] = 出现 f 次的元素列表；频次范围 [1, n]
        List<Integer>[] bucket = new List[nums.length + 1];
        for (Map.Entry<Integer, Integer> e : cnt.entrySet()) {
            int f = e.getValue();
            if (bucket[f] == null) bucket[f] = new ArrayList<>();
            bucket[f].add(e.getKey());
        }

        int[] ans = new int[k];
        int idx = 0;
        for (int f = nums.length; f >= 1 && idx < k; f--) {  // 从高频次往低遍历
            if (bucket[f] == null) continue;
            for (int x : bucket[f]) {
                ans[idx++] = x;
                if (idx == k) break;
            }
        }
        return ans;
    }
}
```

## 个人总结

### 1. 从全排序到堆：只要前 K 个就别全排序

暴力解法把全部 `m` 个不同元素**完整排序**（\(O(n \log n)\)）只为取前 K 个，做了多余的功。**「求前 K 大 / 前 K 小」几乎都不该全排序——用大小为 K 的堆维护候选集**，把复杂度从 \(O(n \log n)\) 降到 \(O(n \log k)\)，这也是本题进阶要求的核心。识别「只要 Top-K，不要全序」是优化信号。

### 2. Top-K 最大 → 用小顶堆（反直觉但正确）

要保留**频次最大的 K 个**，堆里得能高效淘汰「这 K 个里最小的」，所以用**小顶堆**（堆顶 = 最小）：新元素频次比堆顶大就替换堆顶。

> 口诀：**求前 K 大用小顶堆，求前 K 小用大顶堆**——堆顶永远放「最容易被淘汰的那个」。

### 3. 桶排序：频次值域有界 → 换掉 log

任一元素频次 ∈ `[1, n]`，值域有界，就能**以频次为下标建桶**，从高频桶往低频桶取，\(O(n)\) 无排序。这是本题理论最优解，本质与 [桶思想.md](../算法思想/桶思想.md) 里「值域/频率分桶」一脉相承，也和 [621. 任务调度器](621.%20任务调度器.md) 的桶模型属同一族。

### 4. 三种解法的取舍

| 解法 | 时间 | 是否满足进阶 | 定位 |
|:---|:---:|:---:|:---|
| 计数 + 全排序 | \(O(n \log n)\) | ❌ | 最直观，跑通用 |
| 小顶堆 | \(O(n \log k)\) | ✅ | 面试首选，好讲好写 |
| 桶排序 | \(O(n)\) | ✅ | 理论最优，值域有界时用 |

**面试推荐小顶堆**：既满足进阶、代码又短；桶排序作为「还能更快」的加分项。

### 5. 频次统计的写法：`merge`

`cnt.merge(x, 1, Integer::sum)` 等价于「不存在则置 1，存在则 +1」，比 `getOrDefault(x,0)+1` 再 `put` 更简洁。这是频次统计的通用写法。

### 6. 别忘了「进阶」是硬要求

本题进阶明确要求**优于 \(O(n \log n)\)**，所以解法一虽能 AC 但不达标，堆或桶才是目标解。做题时先看有没有进阶约束，它往往就是出题人想考的点。
