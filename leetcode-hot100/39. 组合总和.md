## 题目描述

给你一个 **无重复元素** 的整数数组 `candidates` 和一个目标整数 `target` ，找出 `candidates` 中可以使数字和为目标数 `target` 的 所有 **不同组合** ，并以列表形式返回。你可以按 **任意顺序** 返回这些组合。

`candidates` 中的 **同一个** 数字可以 **无限制重复被选取** 。如果至少一个数字的被选数量不同，则两种组合是不同的。

对于给定的输入，保证和为 `target` 的不同组合数少于 `150` 个。

---

## 示例

**示例 1**

```
输入：candidates = [2,3,6,7], target = 7
输出：[[2,2,3],[7]]
解释：
2 和 3 可以形成一组候选，2 + 2 + 3 = 7 。注意 2 可以使用多次。
7 也是一个候选， 7 = 7 。
仅有这两种组合。
```

**示例 2**

```
输入：candidates = [2,3,5], target = 8
输出：[[2,2,2,2],[2,3,3],[3,5]]
```

**示例 3**

```
输入：candidates = [2], target = 1
输出：[]
```

## 思路

### 核心：回溯枚举组合，用 `start` 既允许重复选、又避免重复组合

要求「所有不同组合」+「同一数字可重复选」，是**回溯（DFS）**的典型场景。两个关键设计：

1. **可重复选同一个数** → 递归时把起点 `start` 传 `i`（**不是** `i+1`），下一层还能再选当前这个数；
2. **避免重复组合**（`[2,3]` 和 `[3,2]` 算同一个）→ 用 `start` 限定「只能选下标 `>= start` 的数」，即**每层从当前元素往后选，不回头**，保证组合内下标非递减，天然去重。

```
candidates = [2,3,6,7], target = 7

选 2 → 剩 5 → 选 2(还从2开始) → 剩 3 → 选 3 → 剩 0 ✅ [2,2,3]
                              → 选 6/7 剩负，剪枝
选 3 → 剩 4 → 选 3 → 剩 1 → 无解回溯
选 6 → 剩 1 → 无解
选 7 → 剩 0 ✅ [7]
```

### 剪枝：排序后剩余不够就停

先把 `candidates` **排序**，回溯时若 `candidates[i] > remain`（当前数已超过剩余目标），由于后面的数更大，可**直接 break** 整个循环，不必再试。这是显著的效率优化。

### 步骤

1. 排序 `candidates`（为剪枝）；
2. DFS(`start`, `remain`, `path`)：
   - `remain == 0` → 找到一组，加入结果；
   - 从 `i = start` 遍历：若 `candidates[i] > remain` break；否则选入 `path`，递归 `dfs(i, remain - candidates[i])`（**start 传 i**），回溯撤销。

- 时间复杂度：与解的个数和深度相关，最坏 \(O(S)\)（`S` 为所有可行组合的总规模）
- 空间复杂度：\(O(target / \min)\) 递归深度

## 代码

### 解法：回溯 + 排序剪枝（推荐）

```java
class Solution {
    private List<List<Integer>> ans = new ArrayList<>();

    public List<List<Integer>> combinationSum(int[] candidates, int target) {
        Arrays.sort(candidates);                 // 排序，便于剪枝
        dfs(candidates, 0, target, new ArrayList<>());
        return ans;
    }

    // start: 本层允许选择的最小下标；remain: 剩余目标
    private void dfs(int[] candidates, int start, int remain, List<Integer> path) {
        if (remain == 0) {                       // 凑齐目标
            ans.add(new ArrayList<>(path));      // 拷贝一份存入
            return;
        }
        for (int i = start; i < candidates.length; i++) {
            if (candidates[i] > remain) break;   // 排序后：当前已超，后面更大，直接停
            path.add(candidates[i]);             // 选 candidates[i]
            dfs(candidates, i, remain - candidates[i], path);  // 注意传 i：可重复选
            path.remove(path.size() - 1);        // 回溯撤销
        }
    }
}
```

## 个人总结

### 1. 题眼：求「所有组合」→ 回溯；「可重复选」→ start 传 i

「返回所有满足条件的组合」是回溯的标志。本题特殊在**元素可无限重复选**，所以递归下一层的起点传 **`i` 而非 `i+1`**——让同一个数下一层还能再被选中。这是它和 [40. 组合总和 II](40.%20组合总和%20II.md)（每个数只能用一次，传 `i+1`）的唯一核心区别。

### 2. `start` 参数一石二鸟

`start` 同时解决两个问题：
- **允许重复**：传 `i` 让当前数可再选；
- **避免重复组合**：只从 `start` 往后选、不回头，使组合内下标非递减，`[2,2,3]` 只会以这一种顺序生成，不会再出现 `[2,3,2]`、`[3,2,2]`。

**「求组合用 start 控制起点、求排列用 used 数组」**——这是回溯两大分支的分水岭，和你整理的 [回溯.md](../算法思想/回溯.md) 一致。

### 3. 排序 + break 剪枝是关键优化

先排序，循环里遇到 `candidates[i] > remain` 直接 `break`（不是 `continue`）：因为已排序，当前数都超了，后面只会更大，整层没必要再试。不排序就只能 `continue` 跳过单个，效率差很多。

### 4. 用「剩余目标 remain」比「累加和 sum」更简洁

递归传「剩余还要凑多少」`remain - candidates[i]`，终止条件 `remain == 0` 即可，还能顺手用 `candidates[i] > remain` 剪枝。比维护一个累加 `sum` 再和 `target` 比更省事。

### 5. 收集答案要拷贝 `new ArrayList<>(path)`

`path` 全程是同一个可变列表，回溯会不断增删。存入结果时必须**拷贝快照** `new ArrayList<>(path)`，否则存进去的都是同一个引用，最终全被清空或错乱。这是回溯题最常见的低级错。
