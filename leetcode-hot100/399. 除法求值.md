## 题目描述

给你一个变量对数组 `equations` 和一个实数值数组 `values` 作为已知条件，其中 `equations[i] = [Ai, Bi]` 和 `values[i]` 共同表示等式 `Ai / Bi = values[i]`。每个 `Ai` 或 `Bi` 是一个表示单个变量的字符串。

另有一些以数组 `queries` 表示的问题，其中 `queries[j] = [Cj, Dj]` 表示第 `j` 个问题，请你根据已知条件找出 `Cj / Dj = ?` 的结果作为答案。

返回 **所有问题的答案** 。如果存在某个无法确定的答案，则用 `-1.0` 替代这个答案。如果问题中出现了给定的已知条件中没有出现的字符串，也需要用 `-1.0` 替代这个答案。

**注意**：输入总是有效的。你可以假设除法运算中不会出现除数为 0 的情况，且不存在任何矛盾的结果。

## 示例

**示例 1**

```
输入：equations = [["a","b"],["b","c"]], values = [2.0,3.0],
      queries = [["a","c"],["b","a"],["a","e"],["a","a"],["x","x"]]
输出：[6.00000,0.50000,-1.00000,1.00000,-1.00000]
解释：
a/b = 2.0, b/c = 3.0
问题：a/c=? → 6.0；b/a=? → 0.5；a/e=? → -1.0（e 未出现）；
     a/a=? → 1.0；x/x=? → -1.0（x 未出现）
```

```
输出：[3.75000,0.40000,5.00000,0.20000]
```

## 思路

### 核心洞察：这是一道带权图题

把每个变量看成**节点**，等式 `a / b = k` 看成一条**带权有向边**，同时补一条反向边：

```
a --(k)---> b        （a / b = k）
b --(1/k)-> a        （b / a = 1/k）
```

于是查询 `x / y` = 从 `x` 走到 `y` 的路径上**所有边权的乘积**：

```
a --2.0--> b --3.0--> c

a/c = 2.0 × 3.0 = 6.0    （沿路径累乘）
b/a = 1/2.0 = 0.5        （走反向边）
```

**查询就变成「图中找一条 `x→y` 路径，累乘边权」**：

- 找不到路径（不连通）→ `-1.0`
- 任一变量没在图里出现过 → `-1.0`
- `x/x` 且 `x` 出现过 → `1.0`

### 关键陷阱

1. **变量未出现**：直接返回 `-1.0`，别去搜索。
2. **`x/x` 边界**：`x` 出现过返回 `1.0`；没出现过返回 `-1.0`。
3. **必须双向建边**：`a/b=k` 要同时加正向权 `k` 和反向权 `1/k`，否则反向查询失败。
4. **连通但要防环**：DFS 时记得标记 `visited`，避免在环里绕。

### 解法一：建图 + DFS（最直观，推荐入门）

1. 建图：`graph[a][b] = k`，`graph[b][a] = 1/k`（用 `Map<String, Map<String, Double>>`）
2. 每个查询 `(x, y)`：若 `x` 或 `y` 不在图中 → `-1.0`；否则从 `x` 出发 DFS，累乘边权找 `y`
3. DFS 用 `visited` 防环，找到 `y` 返回累积乘积，走投无路返回 `-1.0`

- 时间复杂度：建图 \(O(E)\)，每次查询 \(O(V+E)\)，共 \(O(Q \times (V+E))\)
- 空间复杂度：\(O(V+E)\)

### 解法二：Floyd 传递闭包（预处理所有点对）

若查询很多，可先用 Floyd **预处理任意两点的比值**，之后每次查询 \(O(1)\)：

1. 初始化 `d[i][i] = 1`，已知边 `d[a][b] = k`、`d[b][a] = 1/k`
2. 三重循环：`d[i][j] = d[i][k] * d[k][j]`（若两段都可达，则拼接）
3. 查询直接取 `d[x][y]`，不存在返回 `-1.0`

- 时间复杂度：预处理 \(O(V^3)\)，每次查询 \(O(1)\)
- 空间复杂度：\(O(V^2)\)
- 本题 `V ≤ 40`，\(V^3\) 很小，查询多时最划算

### 解法三：带权并查集（最优雅）

维护每个节点到其**根节点的比值** `weight[x] = x / root`，合并时更新权值：

- `find(x)`：路径压缩的同时，把 `weight[x]` 累乘成「x 到根」的比值
- `union(a, b, k)`（`a/b=k`）：把两棵树的根接起来，按 `weight` 关系推出根间比值
- 查询 `(x, y)`：若同根，答案 = `weight[x] / weight[y]`；否则 `-1.0`

- 时间复杂度：近 \(O(1)\) 每次操作（反阿克曼）
- 空间复杂度：\(O(V)\)
- 权值更新推导稍绕，但操作最省

## 代码

### 解法一：建图 + DFS（推荐入门）

```java
class Solution {
    public double[] calcEquation(List<List<String>> equations, double[] values,
                                 List<List<String>> queries) {
        // 建带权图：graph.get(a).get(b) = a/b 的比值
        Map<String, Map<String, Double>> graph = new HashMap<>();
        for (int i = 0; i < values.length; i++) {
            String a = equations.get(i).get(0), b = equations.get(i).get(1);
            graph.computeIfAbsent(a, x -> new HashMap<>()).put(b, values[i]);
            graph.computeIfAbsent(b, x -> new HashMap<>()).put(a, 1.0 / values[i]);
        }

        double[] ans = new double[queries.size()];
        for (int i = 0; i < queries.size(); i++) {
            String x = queries.get(i).get(0), y = queries.get(i).get(1);
            if (!graph.containsKey(x) || !graph.containsKey(y)) {
                ans[i] = -1.0;                       // 变量未出现
            } else {
                ans[i] = dfs(graph, x, y, new HashSet<>());
            }
        }
        return ans;
    }

    // 从 cur 出发找 target，返回 cur/target 的比值，找不到返回 -1.0
    private double dfs(Map<String, Map<String, Double>> graph,
                       String cur, String target, Set<String> visited) {
        if (cur.equals(target)) return 1.0;          // 含 x/x = 1.0
        visited.add(cur);
        for (Map.Entry<String, Double> e : graph.get(cur).entrySet()) {
            String next = e.getKey();
            if (visited.contains(next)) continue;    // 防环
            double sub = dfs(graph, next, target, visited);
            if (sub != -1.0) return e.getValue() * sub;   // 累乘边权
        }
        return -1.0;                                 // 走投无路
    }
}
```

### 解法二：Floyd 传递闭包

```java
class Solution {
    public double[] calcEquation(List<List<String>> equations, double[] values,
                                 List<List<String>> queries) {
        // 变量映射到下标
        Map<String, Integer> id = new HashMap<>();
        for (List<String> eq : equations) {
            id.putIfAbsent(eq.get(0), id.size());
            id.putIfAbsent(eq.get(1), id.size());
        }
        int n = id.size();
        double[][] d = new double[n][n];             // d[i][j] = i/j，0 表示不可达
        for (int i = 0; i < n; i++) d[i][i] = 1.0;
        for (int i = 0; i < values.length; i++) {
            int a = id.get(equations.get(i).get(0)), b = id.get(equations.get(i).get(1));
            d[a][b] = values[i];
            d[b][a] = 1.0 / values[i];
        }
        // Floyd 传递：i→k→j 拼接
        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++)
                for (int j = 0; j < n; j++)
                    if (d[i][k] != 0 && d[k][j] != 0)
                        d[i][j] = d[i][k] * d[k][j];

        double[] ans = new double[queries.size()];
        for (int q = 0; q < queries.size(); q++) {
            Integer x = id.get(queries.get(q).get(0)), y = id.get(queries.get(q).get(1));
            ans[q] = (x == null || y == null || d[x][y] == 0) ? -1.0 : d[x][y];
        }
        return ans;
    }
}
```

### 解法三：带权并查集

```java
class Solution {
    private Map<String, String> parent = new HashMap<>();
    private Map<String, Double> weight = new HashMap<>();   // weight[x] = x / parent[x]

    public double[] calcEquation(List<List<String>> equations, double[] values,
                                 List<List<String>> queries) {
        for (int i = 0; i < values.length; i++) {
            String a = equations.get(i).get(0), b = equations.get(i).get(1);
            add(a); add(b);
            union(a, b, values[i]);
        }
        double[] ans = new double[queries.size()];
        for (int i = 0; i < queries.size(); i++) {
            String x = queries.get(i).get(0), y = queries.get(i).get(1);
            if (!parent.containsKey(x) || !parent.containsKey(y)
                    || !find(x).equals(find(y))) {
                ans[i] = -1.0;
            } else {
                ans[i] = weight.get(x) / weight.get(y);      // 同根：x/y = (x/root)/(y/root)
            }
        }
        return ans;
    }

    private void add(String x) {
        parent.putIfAbsent(x, x);
        weight.putIfAbsent(x, 1.0);
    }

    // 路径压缩，同时把 weight[x] 累乘成「x 到根」的比值
    private String find(String x) {
        if (!parent.get(x).equals(x)) {
            String root = find(parent.get(x));
            weight.put(x, weight.get(x) * weight.get(parent.get(x)));
            parent.put(x, root);
        }
        return parent.get(x);
    }

    // a/b = value，合并两棵树
    private void union(String a, String b, double value) {
        String ra = find(a), rb = find(b);
        if (ra.equals(rb)) return;
        parent.put(ra, rb);
        // 推导：weight[ra] 使 ra/rb 成立 → value = (a/ra·weight[ra]) 关系反解
        weight.put(ra, value * weight.get(b) / weight.get(a));
    }
}
```

### 解法四：对数域 Floyd（抗长链浮点误差）

当链很长时，`double` 连乘 20+ 次会累积舍入误差（见 [个人总结](#个人总结) 第 7 点的 `a/u` 用例）。把「乘边权」改成「加边权的对数」，最后 `exp` 回来——**加法的误差远小于连乘**，能稳过长链卡精度的用例：

```java
class Solution {
    public double[] calcEquation(List<List<String>> equations, double[] values,
                                 List<List<String>> queries) {
        Map<String, Integer> id = new HashMap<>();
        for (List<String> eq : equations) {
            id.putIfAbsent(eq.get(0), id.size());
            id.putIfAbsent(eq.get(1), id.size());
        }
        int n = id.size();
        // logD[i][j] = log(i/j)，用 NaN 表示不可达（加法域里 0 是合法值）
        double[][] logD = new double[n][n];
        for (double[] row : logD) Arrays.fill(row, Double.NaN);
        for (int i = 0; i < n; i++) logD[i][i] = 0.0;    // log(1) = 0
        for (int i = 0; i < values.length; i++) {
            int a = id.get(equations.get(i).get(0)), b = id.get(equations.get(i).get(1));
            logD[a][b] = Math.log(values[i]);            // log(a/b)
            logD[b][a] = -Math.log(values[i]);           // log(b/a) = -log(a/b)
        }
        // Floyd：乘积 → 对数相加
        for (int k = 0; k < n; k++)
            for (int i = 0; i < n; i++)
                for (int j = 0; j < n; j++)
                    if (!Double.isNaN(logD[i][k]) && !Double.isNaN(logD[k][j]))
                        logD[i][j] = logD[i][k] + logD[k][j];

        double[] ans = new double[queries.size()];
        for (int q = 0; q < queries.size(); q++) {
            Integer x = id.get(queries.get(q).get(0)), y = id.get(queries.get(q).get(1));
            ans[q] = (x == null || y == null || Double.isNaN(logD[x][y]))
                     ? -1.0 : Math.exp(logD[x][y]);      // exp 还原
        }
        return ans;
    }
}
```

> 💡 对数域把 20 次连乘变成 20 次相加。对上面的 `a/u` 用例：`log(1e-5)` 相加相消后总和 ≈ 0，`exp(0) = 1.0`，精度稳定。工程上处理「大量小数连乘」（如概率、似然）时也常用这招防下溢/误差。

## 个人总结

### 1. 把「除法链」翻译成「带权图路径」是解题第一步

看到「`a/b`、`b/c` 已知，求 `a/c`」这种**可传递的比值关系**，立刻联想图：变量是点，等式是带权边，查询是路径边权累乘。**「关系可传递 + 求两元素间的复合关系」是图论建模的信号**。

### 2. 双向建边不能漏

`a/b = k` 必须同时建 `a→b`（权 `k`）和 `b→a`（权 `1/k`）。漏了反向边，`b/a` 这类查询就搜不到。这是本题最常见的低级错。

### 3. 三个返回 `-1.0` 的情形要分清

| 情形 | 判断 |
|:---|:---|
| 变量未在等式中出现 | 建图前先查 `graph.containsKey` |
| 两变量都出现但不连通 | DFS 搜不到 / 并查集不同根 |
| —— | （`x/x` 且 x 出现过是 `1.0`，不是 -1.0，别混） |

### 4. 三种解法的取舍

| 解法 | 预处理 | 单次查询 | 适用 |
|:---|:---:|:---:|:---|
| DFS/BFS | 建图 \(O(E)\) | \(O(V+E)\) | 最直观，查询不多时首选 |
| Floyd | \(O(V^3)\) | \(O(1)\) | 点少查询多，预处理全点对 |
| 带权并查集 | 近 \(O(1)\) | 近 \(O(1)\) | 最省，但权值更新推导难 |

本题 `V ≤ 40`、`Q ≤ 20`，三种都轻松过；**面试首选 DFS 讲清思路，行有余力再上并查集**。

### 5. 带权并查集的难点：`weight` 更新公式

`weight[x] = x / parent[x]`。两处更新最容易错：

- **find 路径压缩**：`weight[x] *= weight[parent[x]]`，把「x→旧父」和「旧父→根」两段比值乘起来，得到「x→根」。
- **union(a,b,value)**（`a/b=value`）：把 `ra` 挂到 `rb`，`weight[ra] = value * weight[b] / weight[a]`。推导：`a/b=value`，而 `a/ra=weight[a]`、`b/rb=weight[b]`，要求 `ra/rb`，代入解出即得。

理解不了先用 DFS AC，再回头推这个公式。

### 6. 浮点精度坑：长链连乘的误差累积

**踩坑用例**（20 条边的长链，每条 `x/y = 1e-05`）：

```
equations = [["b","a"],["c","b"],["d","c"],["e","d"],["f","e"],["g","f"],
             ["h","g"],["i","h"],["j","i"],["k","j"],["k","l"],["l","m"],
             ["m","n"],["n","o"],["o","p"],["p","q"],["q","r"],["r","s"],
             ["s","t"],["t","u"]]
values  = [1e-05, ... 20 个 ...]
queries = [["a","u"]]

我的输出：[0.99994]      预期：[1.0]     ❌
```

**数学上精确等于 1.0**：从 `a` 到 `k` 走 10 条反向边（每步 `×1e5`），从 `k` 到 `u` 走 10 条正向边（每步 `×1e-5`）：

$$
a/u = (1e5)^{10} \times (1e{-}5)^{10} = 1e^{50} \times 1e^{-50} = 1.0
$$

但 `1e-05` 在二进制里无法精确表示，`double` **连乘 20 次**把微小舍入误差放大到小数点后第 5 位，得到 `0.99994`。

**为什么被判错**：LeetCode 按**相对/绝对误差 `1e-5`** 判分，而 `|0.99994 - 1.0| = 6e-5 > 1e-5`，刚好超容差。

**要点**：

1. 这**不是逻辑 bug**——DFS / Floyd / 带权并查集三种解法都是浮点连乘，全都会有此误差，只是这个用例恰好卡在容差边界。
2. `a/u` 无论怎么走都是 20 条边，**选「最短跳数路径」救不了它**，误差是 20 次连乘的固有产物。
3. 稳过的办法是 **[解法四：对数域 Floyd](#解法四对数域-floyd抗长链浮点误差)**：把「乘边权」换成「加 `log(边权)`」，最后 `exp` 还原。20 次连乘变 20 次相加，误差数量级骤降，`log(1e-5)` 相加相消 ≈ 0 → `exp(0) = 1.0`。

> 教训：**大量小数连乘 → 优先转对数域相加**。这在概率/似然计算（防下溢）里是通用技巧。
