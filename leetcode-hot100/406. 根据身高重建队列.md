## 题目描述

假设有打乱顺序的一群人站成一个队列，数组 `people` 表示队列中一些人的属性（不一定按顺序）。每个 `people[i] = [hi, ki]` 表示第 `i` 个人的身高为 `hi`，前面 **正好** 有 `ki` 个身高大于或等于 `hi` 的人。

请你重新构造并返回输入数组 `people` 所表示的队列。返回的队列应该格式化为数组 `queue`，其中 `queue[j] = [hj, kj]` 是队列中第 `j` 个人的属性（`queue[0]` 是排在队列前面的人）。

**示例 1**

```
输入：people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]
输出：[[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]
解释：
编号为 0 的人身高为 5，没有比他更高或一样高的人排在他前面。
编号为 1 的人身高为 7，没有比他更高或一样高的人排在他前面。
编号为 2 的人身高为 5，有 2 个比他更高或一样高的人排在他前面，即编号为 0 和 1 的人。
编号为 3 的人身高为 6，有 1 个比他更高或一样高的人排在他前面，即编号为 1 的人。
编号为 4 的人身高为 4，有 4 个比他更高或一样高的人排在他前面，即编号为 0、1、2、3 的人。
编号为 5 的人身高为 7，有 1 个比他更高或一样高的人排在他前面，即编号为 1 的人。
因此 [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]] 是重新构造后的队列。
```

## 思路

### 核心难点：两个维度（h 和 k）互相牵制

`ki` 的定义是「前面有几个身高 **≥ hi** 的人」。直接同时满足所有人的 `k` 很难，因为插入一个人会影响别人的计数。贪心的关键是**先固定一个维度，让另一个维度的插入互不干扰**。

### 核心思想：先按身高降序排，再按 k 值当下标插入

**两步走**：

1. **排序**：按身高 `h` **降序**；`h` 相同时按 `k` **升序**。
2. **插入**：依次取出每个人，把他插入到结果列表的**第 `k` 个位置**（`list.add(k, person)`）。

**为什么这样可行**——关键洞察：

- 先处理**最高**的人，此时列表里全是「身高 ≥ 他」的人（因为降序，先来的都不比他矮）。所以对当前这个人来说，插到下标 `k`，前面正好有 `k` 个「≥ 他」的人，恰好满足他的 `ki`。
- 之后再插入**更矮**的人：矮的人插在任何位置都**不会改变已在列表里那些更高的人前面「≥ 他们」的计数**（因为矮的人不计入「≥ 更高者」）。所以后插入的人不破坏前面已排好的约束。

```
people = [[7,0],[4,4],[7,1],[5,0],[6,1],[5,2]]

排序后（h 降序，h 同则 k 升序）：
[7,0] [7,1] [6,1] [5,0] [5,2] [4,4]

逐个按 k 当下标插入：
[7,0]          → 插下标0 → [[7,0]]
[7,1]          → 插下标1 → [[7,0],[7,1]]
[6,1]          → 插下标1 → [[7,0],[6,1],[7,1]]
[5,0]          → 插下标0 → [[5,0],[7,0],[6,1],[7,1]]
[5,2]          → 插下标2 → [[5,0],[7,0],[5,2],[6,1],[7,1]]
[4,4]          → 插下标4 → [[5,0],[7,0],[5,2],[6,1],[4,4],[7,1]]  ✅
```

### 为什么 h 相同时 k 要升序

同身高的人彼此**互相算作「≥」**。若 `k` 大的先插，会占掉小 `k` 该在的靠前位置，导致后插的小 `k` 落在他后面、计数错误。让 `k` 小的先插到更靠前的位置，才符合「前面 ≥ 的人更少」。

### 解法一：贪心 + 按 k 插入（推荐）

1. 排序：`h` 降序，`h` 同则 `k` 升序
2. 遍历排序后的人，`list.add(person[k], person)` 插入
3. 转成数组返回

- 时间复杂度：\(O(n^2)\)，`ArrayList.add(index, e)` 单次插入是 \(O(n)\)（移动后续元素），共 n 次
- 空间复杂度：\(O(n)\)，结果列表

## 代码

### 解法一：贪心 + 按 k 插入（推荐）

```java
class Solution {
    public int[][] reconstructQueue(int[][] people) {
        // 排序：身高 h 降序；h 相同时 k 升序
        Arrays.sort(people, (a, b) -> {
            if (a[0] != b[0]) return b[0] - a[0];   // h 大的在前
            return a[1] - b[1];                     // h 同则 k 小的在前
        });

        List<int[]> list = new LinkedList<>();
        for (int[] p : people) {
            list.add(p[1], p);                      // 插到第 k 个位置
        }
        return list.toArray(new int[list.size()][]);
    }
}
```

> 💡 用 `LinkedList` 还是 `ArrayList`？两者按索引插入总体都是 \(O(n^2)\)：`ArrayList` 是「定位 O(1) + 移动 O(n)」，`LinkedList` 是「定位 O(n) + 插入 O(1)」。数据量 `n ≤ 2000` 时都能轻松通过，用 `ArrayList` 也完全可以。

## 个人总结

### 1. 贪心核心：固定一维，让另一维插入互不干扰

两个维度互相牵制时，贪心的通法是**先按其中一维排序把它「锁死」，使得处理另一维时不会反过来破坏已排好的部分**。这里锁死的是身高——**先高后矮**保证「后插入的矮个子不影响已确定的高个子的 k 计数」。这正是 [贪心算法.md](../算法思想/贪心算法.md) 里「排序 + 局部最优」的典型套路。

### 2. 为什么按 k 当下标插入就一定对

关键靠「降序」这个前提：处理到某人时，**列表里现有的人全都 ≥ 他**。于是把他插到下标 `k`，他前面恰好有 `k` 个「≥ 他」的人——直接满足 `ki` 定义。这是本题最妙的一步，务必记住「插入时刻，前面的人都比我高或一样高」。

### 3. 排序规则：h 降序 + k 升序，两个都不能错

| 规则 | 写错的后果 |
|:---|:---|
| h **降序** | 若升序，先插矮的，后插的高个子会打乱矮个子已定好的位置，计数全乱 |
| h 相同 k **升序** | 若同高按 k 降序，大 k 先占前排位置，小 k 被挤到后面，违反「前面 ≥ 的更少」 |

### 4. 「前面有 k 个 ≥ 我的人」是关键定义

`ki` 数的是「≥」（大于**或等于**），不是「>」。这就是「同身高互相计数」的来源，也是排序第二关键字必须用 k 升序的根本原因。读题时先把 `k` 的定义抠清楚，是这题不踩坑的前提。

### 5. 复杂度与数据结构

单次按索引插入是 \(O(n)\)，总体 \(O(n^2)\)，`n ≤ 2000` 时约 `4×10^6`，稳过。不必纠结 `LinkedList`/`ArrayList`，量小时差异可忽略。
