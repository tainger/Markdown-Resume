## 题目描述

给定一个二叉树的根节点 `root`，和一个整数 `targetSum`，求该二叉树里节点值之和等于 `targetSum` 的 **路径** 的数目。

路径 **不需要从根节点开始，也不需要在叶子节点结束**，但是路径方向必须是**向下的**（只能从父节点到子节点）。

---

## 示例

**示例 1**

```
输入：root = [10,5,-3,3,2,null,11,3,-2,null,1], targetSum = 8
输出：3
解释：和等于 8 的路径有 3 条，如图所示。
```

**示例 2**

```
输入：root = [5,4,8,11,null,13,4,7,2,null,null,5,1], targetSum = 22
输出：3
```

---

## 提示

- 二叉树的节点个数的范围是 `[0, 1000]`
- `-10^9 <= Node.val <= 10^9`
- `-1000 <= targetSum <= 1000`
- **注意**：节点值**可以为负数**，路径可以从任意节点开始向下——这决定了它是「前缀和」而非贪心问题。

## 思路

### 核心思想：把它看成 [560. 和为 K 的子数组](560.%20和为%20K%20的子数组.md) 的树上版本

数组里「和为 `k` 的**连续子数组**」，到树上就变成「和为 `targetSum` 的**向下路径**」。二者本质相同：

| | 560. 和为 K 的子数组 | 437. 路径总和 III |
|:---|:---|:---|
| 载体 | 一维数组 | 树的**根到当前节点的一条链** |
| 目标 | 连续子数组和 = `k` | 向下路径和 = `targetSum` |
| 恒等式 | `prefix[i] - prefix[j] = k` | `curSum - prefix[祖先] = targetSum` |
| 关键结构 | 前缀和 + 哈希表 | **同款**，只是沿 DFS 路径维护 |

区别只在于：数组是一条直线，树是**从根往下分叉的多条链**。所以要在 DFS 过程中动态维护「当前这条根到节点链」上的前缀和哈希表——**进入节点时加入、回溯离开时删除**（否则会污染兄弟分支）。

### 关键陷阱

1. **节点值含负数** → 不能靠「路径和超了就停」剪枝，必须老实累加，这也是要用前缀和的原因。
2. **`targetSum` 和路径和可能溢出 `int`**：节点值 ±10^9、最多 1000 个节点，累加和可能超过 `int` 范围，前缀和变量要用 **`long`**。

### 解法一：双重递归（暴力，易理解）

「路径可以从任意节点开始」→ 那就**以每个节点为起点各跑一次**：

1. 外层 `dfs`：遍历每个节点，把它当作路径起点
2. 内层 `countPath`：从该起点向下走，累加路径和，等于 `targetSum` 就 +1（注意负数存在，命中后**不能提前返回**，要继续往下找）

- 时间复杂度：\(O(n^2)\)，最坏（链状树）每个起点向下走 \(O(n)\)
- 空间复杂度：\(O(n)\)，递归栈深度
- `n ≤ 1000` 时 \(n^2 = 10^6\)，能过；是理解题意的入口

### 解法二：前缀和 + 哈希表（推荐）

沿用 560 的套路，只是把「一次遍历数组」换成「一次 DFS 遍历树」：

1. `prefix` 哈希表记录「从根到当前节点链上，每个前缀和出现的次数」，初始化 `prefix[0] = 1`（空前缀）
2. DFS 到某节点，累加当前前缀和 `curSum`
3. 累加 `prefix[curSum - targetSum]` 到答案——存在若干个祖先，使「祖先到当前节点」这段路径和恰为 `targetSum`
4. 把 `curSum` 计入 `prefix`，递归左右子树
5. **回溯**：返回上层前，把 `curSum` 从 `prefix` 中减回去（**关键**，避免影响其它分支）

- 时间复杂度：\(O(n)\)，每个节点只访问一次
- 空间复杂度：\(O(n)\)，哈希表 + 递归栈

### 图解（为什么要回溯删除）

```
        10
       /  \
      5   -3
     ...   ...

DFS 走到左子树时，prefix 里存的是 {根→5} 这条链的前缀和；
回到根、要走右子树 -3 前，必须把 5 这条链的前缀和删掉，
否则 -3 分支会错误地匹配到「5 分支」的前缀和 → 把不在同一条链上的节点算成一条路径。
```

## 代码

### 解法一：双重递归（暴力）

```java
class Solution {
    public int pathSum(TreeNode root, int targetSum) {
        if (root == null) return 0;
        // 以 root 为起点的路径数 + 左子树里的所有路径 + 右子树里的所有路径
        return countPath(root, targetSum)
             + pathSum(root.left, targetSum)
             + pathSum(root.right, targetSum);
    }

    // 统计从 node 向下、和为 target 的路径数（node 必须是起点）
    private int countPath(TreeNode node, long target) {
        if (node == null) return 0;
        int count = 0;
        if (node.val == target) count++;        // 命中，但因含负数不能 return，要继续往下
        count += countPath(node.left,  target - node.val);
        count += countPath(node.right, target - node.val);
        return count;
    }
}
```

### 解法二：前缀和 + 哈希表（推荐）

```java
class Solution {
    public int pathSum(TreeNode root, int targetSum) {
        Map<Long, Integer> prefix = new HashMap<>();
        prefix.put(0L, 1);                       // 空前缀：前缀和为 0 出现 1 次
        return dfs(root, prefix, 0L, targetSum);
    }

    private int dfs(TreeNode node, Map<Long, Integer> prefix, long curSum, int target) {
        if (node == null) return 0;

        curSum += node.val;                       // 根到当前节点的前缀和
        // 先查：存在 curSum-target 说明有某个祖先，其后一段到当前节点和为 target
        int count = prefix.getOrDefault(curSum - target, 0);

        // 后存：把当前前缀和计入，供子孙节点查询
        prefix.merge(curSum, 1, Integer::sum);
        count += dfs(node.left,  prefix, curSum, target);
        count += dfs(node.right, prefix, curSum, target);
        // 回溯：离开当前节点前撤销，避免污染其它分支
        prefix.merge(curSum, -1, Integer::sum);

        return count;
    }
}
```

## 个人总结

### 1. 一句话：这就是 560 搬到树上

看到「路径和 = 定值」「路径可从任意节点开始」「节点含负数」，直接联想 [560. 和为 K 的子数组](560.%20和为%20K%20的子数组.md)。恒等式完全一样：

$$
\text{某段向下路径和} = curSum - prefix[\text{某祖先}]
$$

要它等于 `targetSum`，即查历史前缀和里有几个等于 `curSum - targetSum`。**唯一新增的动作是「回溯删除」**，因为树有分叉，一维数组没有。

### 2. 回溯删除是树版本的灵魂

数组是一条直线，前缀和只增不减；树有分叉，一条链走完回到父节点要走**另一条链**，此时必须把刚才那条链独有的前缀和从哈希表里撤销：

```java
prefix.merge(curSum, 1, Integer::sum);   // 进入：登记
... 递归左右子树 ...
prefix.merge(curSum, -1, Integer::sum);  // 离开：撤销 ← 漏了就会跨分支误匹配
```

漏掉这一步，`-3` 分支就可能匹配到 `5` 分支的前缀和，把两条不在同一条根到叶链上的节点当成一条路径。

### 3. `prefix.put(0L, 1)` 的含义（同 560）

`prefix[0] = 1` 表示「空前缀」。当某节点的 `curSum` 恰好等于 `targetSum` 时，`curSum - targetSum = 0`，需要一个 `0` 来匹配——对应「从根一路到当前节点」这整条路径。漏了会少算这类答案。

### 4. 「先查后存」顺序不能反（同 560）

必须**先** `count += prefix[curSum - target]`，**再** `prefix.merge(curSum, 1, ...)`。若先存后查，当 `target = 0` 时 `curSum - target = curSum` 会匹配到自己，把「空路径」误算进去。口诀依旧：**先查答案，再存自己**。

### 5. 用 `long` 防溢出

节点值范围 ±10^9、最多 1000 个节点，前缀和累加最大约 10^12，超出 `int`。`curSum` 和哈希表的键都要用 `long`，否则大数据会溢出得到错误结果。

### 6. 暴力命中后为什么不能提前返回

`countPath` 里 `node.val == target` 命中后仍要继续递归子节点。因为**节点含负数**，一条路径当前和为 0 之后可能再加正数又变回 0，即同一条向下路径上可能有**多个**符合条件的终点。数组版 560 里也是同理（`map` 累加而非置位）。
