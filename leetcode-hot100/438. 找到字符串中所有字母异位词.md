## 题目描述

给定两个字符串 `s` 和 `p`，找到 `s` 中所有 `p` 的 **异位词** 的子串，返回这些子串的起始索引。不考虑答案输出的顺序。

**异位词** 指由相同字母重排列形成的字符串（包括相同的字符串）。

---

## 示例

**示例 1**

```
输入：s = "cbaebabacd", p = "abc"
输出：[0,6]
解释：
起始索引等于 0 的子串是 "cba"，它是 "abc" 的异位词。
起始索引等于 6 的子串是 "bac"，它是 "abc" 的异位词。
```

**示例 2**

```
输入：s = "abab", p = "ab"
输出：[0,1,2]
解释：
起始索引等于 0 的子串是 "ab"，它是 "ab" 的异位词。
起始索引等于 1 的子串是 "ba"，它是 "ab" 的异位词。
起始索引等于 2 的子串是 "ab"，它是 "ab" 的异位词。
```

---

## 提示

- `1 <= s.length, p.length <= 3 * 10^4`
- `s` 和 `p` 仅包含小写字母

---

## 思路

### 核心思想：定长滑动窗口 + 词频比较

「异位词」= **字母组成完全相同、顺序无关**。所以只需在 `s` 上滑动一个**长度固定为 `p.length()`** 的窗口，判断「窗口内每个字母的出现次数」是否与 `p` 完全一致即可。

窗口定长是这题和 [无重复字符的最长子串](3.%20无重复字符的最长子串.md) 的最大区别：那题窗口大小随合法性伸缩，这题窗口大小恒等于 `p.length()`，右指针进一个、左指针就出一个。

```
s = "cbaebabacd", p = "abc"   (窗口长度 = 3)

[c b a] e b a b a c d   窗口 "cba" 词频 = {a:1,b:1,c:1} == p ✅ → 记 0
 c[b a e]b a b a c d    窗口 "bae" ❌
 ...滑动...
 c b a e b a[b a c]d    窗口 "bac" == p ✅ → 记 6
```

### 关键前提检查

若 `p.length() > s.length()`，`s` 中不可能存在长度为 `|p|` 的子串，直接返回空列表（否则窗口越界）。

### 解法一：暴力枚举每个起点（最直观，先跑通）

最朴素的想法：**枚举 `s` 中每个可能的起点**，取出长度为 `m = p.length()` 的子串，判断它是不是 `p` 的异位词。判断异位词只需比较两者的词频数组。

1. 起点 `i` 从 `0` 到 `n - m`（保证子串不越界）
2. 对每个 `i`，统计子串 `s[i..i+m)` 的词频 `window`，与 `p` 的词频 `need` 比较
3. 相等则把 `i` 加入答案

- 时间复杂度：\(O((n-m+1) \times m)\)，最坏 \(O(n \times m)\)，每个起点都要重新扫一遍窗口内 `m` 个字符
- 空间复杂度：\(O(26)\) = \(O(1)\)
- `n, m ≤ 3×10^4` 时，最坏约 \(9×10^8\)，在 LeetCode 上大概率 **超时（TLE）**；它的价值是把题意跑通、作为优化的起点，呼应下面的滑动窗口

> 瓶颈：每挪一个起点就把窗口内 `m` 个字符**从头统计一遍**，相邻两个窗口其实只差「最左出一个、最右进一个」两个字符，重复计算了中间 `m-1` 个 —— 这正是滑动窗口能优化掉的部分。

### 解法二：两个频次数组逐窗口比较（定长滑动窗口，推荐）

1. `p` 只含小写字母，用 `int[26]` 统计 `p` 的词频 `need`
2. 维护窗口词频 `window`，先填入前 `p.length()` 个字符
3. 每滑动一步：右边新字符 `+1`，左边旧字符 `-1`，比较 `window` 与 `need` 是否相等，相等则记录左端点

- 时间复杂度：\(O(n \times 26)\)，每次比较两个长度 26 的数组
- 空间复杂度：\(O(26)\) = \(O(1)\)

### 解法三：维护「差异计数 diff」免去每次数组比较（优化）

每次比较两个数组是 \(O(26)\)，可以用一个变量 `diff` 记录「当前窗口有多少种字母的频次和 `need` 不一致」，`diff == 0` 即为异位词：

- 初始 `diff` = `p` 中出现的不同字母种数（先把 `need` 记好）
- 字符进窗口 `c`：`window[c]++`；若加完后 `window[c] == need[c]` 说明这个字母对上了 `diff--`，若加之前刚好相等（`window[c]-1 == need[c]`）说明本来对上现在又错开了 `diff++`
- 字符出窗口 `c`：`window[c]--`，同理对称更新 `diff`
- `diff == 0` → 窗口是异位词

- 时间复杂度：\(O(n)\)，每步 \(O(1)\) 更新
- 空间复杂度：\(O(26)\) = \(O(1)\)

## 代码

### 解法一：暴力枚举每个起点（先跑通，可能 TLE）

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> ans = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (m > n) return ans;

        int[] need = new int[26];                     // p 的词频（固定不变）
        for (int i = 0; i < m; i++) need[p.charAt(i) - 'a']++;

        for (int i = 0; i + m <= n; i++) {            // 枚举每个起点 i
            int[] window = new int[26];               // 每个起点都重新统计（重复计算的根源）
            for (int j = i; j < i + m; j++) {         // 扫窗口内 m 个字符
                window[s.charAt(j) - 'a']++;
            }
            if (Arrays.equals(need, window)) {        // 词频相同 → 异位词
                ans.add(i);
            }
        }
        return ans;
    }
}
```

### 解法二：定长窗口 + 频次数组比较（推荐，最易理解）

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> ans = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (m > n) return ans;                    // 关键前提：p 比 s 长，不可能存在

        int[] need = new int[26];                 // p 的词频
        int[] window = new int[26];               // 当前窗口词频
        for (int i = 0; i < m; i++) {             // 先填入前 m 个字符（第一个窗口）
            need[p.charAt(i) - 'a']++;
            window[s.charAt(i) - 'a']++;
        }
        if (Arrays.equals(need, window)) ans.add(0);

        for (int right = m; right < n; right++) {
            window[s.charAt(right) - 'a']++;      // 右边新字符进窗口
            window[s.charAt(right - m) - 'a']--;  // 左边旧字符出窗口（保持定长）
            if (Arrays.equals(need, window)) {
                ans.add(right - m + 1);           // 记录窗口左端点
            }
        }
        return ans;
    }
}
```

### 解法三：差异计数 diff（优化，去掉每次数组比较）

```java
class Solution {
    public List<Integer> findAnagrams(String s, String p) {
        List<Integer> ans = new ArrayList<>();
        int n = s.length(), m = p.length();
        if (m > n) return ans;

        int[] need = new int[26];
        for (char c : p.toCharArray()) need[c - 'a']++;

        int[] window = new int[26];
        int diff = 0;                              // 窗口中与 need 不一致的字母种数
        for (char c : p.toCharArray()) if (need[c - 'a'] > 0) diff++;
        // 说明：diff 初始 = p 出现的不同字母数，代表这些字母当前都还没凑齐

        for (int right = 0; right < n; right++) {
            int in = s.charAt(right) - 'a';
            window[in]++;
            if (window[in] == need[in]) diff--;        // 刚好凑齐，少一种不一致
            else if (window[in] == need[in] + 1) diff++; // 从相等变超出，多一种不一致

            if (right >= m) {                           // 窗口超长，左边出一个
                int out = s.charAt(right - m) - 'a';
                window[out]--;
                if (window[out] == need[out]) diff--;        // 减回相等
                else if (window[out] == need[out] - 1) diff++; // 从相等变不足
            }

            if (diff == 0) ans.add(right - m + 1);      // 全部对齐 → 异位词
        }
        return ans;
    }
}
```

## 个人总结

### 1. 从暴力枚举到滑动窗口：消除重复统计

暴力解法直接枚举 `n - m + 1` 个起点，每个起点都把窗口内 `m` 个字符**从头统计一遍**，复杂度 \(O(n \times m)\)，本题会 TLE。但它是理解题意最好的入口：

```
起点 i:   [c b a] e b a b a c d   统计 c,b,a
起点 i+1:  c[b a e]b a b a c d    又统计 b,a,e —— 其中 b,a 上一步已经数过！
```

相邻窗口只差「最左 `s[i]` 出、最右 `s[i+m]` 进」两个字符，中间 `m-1` 个是重复计算的。**把「每次重算整窗」改成「增量更新（出一个、进一个）」，就从 \(O(n \times m)\) 降到 \(O(n \times 26)\)** —— 这就是解法二的滑动窗口。识别「相邻子问题高度重叠」是优化的信号。

### 2. 定长窗口是「异位词」题的标志

只要看到「找 `p` 的异位词 / 排列」，窗口长度就**固定为 `p.length()`**，不需要像最长子串那样伸缩。模板是「右进一个、左出一个」，窗口大小恒定。这与 [3. 无重复字符的最长子串](3.%20无重复字符的最长子串.md) 的**变长窗口**形成对照：

| | 窗口大小 | 收缩条件 |
|:---|:---|:---|
| 438 异位词 | **固定** = `\|p\|` | 每步右进左出，恒定 |
| 3 最长子串 | **可变** | 出现重复字符时收缩 |

### 3. 只含小写字母 → 用 `int[26]` 而非 HashMap

题目限定 `s`、`p` 仅含小写字母，用 `int[26]` 数组（下标 `c - 'a'`）比 `HashMap` 更快、更省内存，比较也能直接用 `Arrays.equals`。**字符集已知且小，优先数组计数**。

### 4. 别漏 `p.length() > s.length()` 的前提

若不判断，第一个窗口填充 `for (int i = 0; i < m; i++)` 就会 `s.charAt(i)` 越界。这是定长窗口题最容易翻车的边界。

### 5. 解法三 `diff` 的更新为什么用「==」而非「>」

`diff` 只在**频次跨越「恰好相等」这条线**时才变化：

- 进字符后 `window[in] == need[in]`：刚补齐 → `diff--`
- 进字符后 `window[in] == need[in] + 1`：从相等变成多 1 → `diff++`

用 `==` 精确捕捉「相等 ↔ 不相等」的临界跳变，避免每次 \(O(26)\) 全量比较。出窗口对称处理。**理解不了就先用解法二，AC 后再琢磨 diff 优化**。

### 6. 记录的是窗口「左端点」

答案要的是起始索引。第一个窗口左端点是 0；之后每步 `right` 从 `m` 开始，对应左端点 `right - m + 1`。别记成 `right`。
