## 题目描述

给你一个非负整数数组 `nums` 和一个整数 `target` 。

向数组中的每个整数前添加 `'+'` 或 `'-'` ，然后串联起所有整数，可以构造一个 **表达式** ：

- 例如，`nums = [2, 1]` ，可以在 `2` 之前添加 `'+'` ，在 `1` 之前添加 `'-'` ，然后串联起来得到表达式 `"+2-1"` 。

返回可以通过上述方法构造的、运算结果等于 `target` 的不同 **表达式** 的数目。

---

## 示例

**示例 1**

```
输入：nums = [1,1,1,1,1], target = 3
输出：5
解释：一共有 5 种方法让最终目标和为 3。
-1+1+1+1+1 = 3
+1-1+1+1+1 = 3
+1+1-1+1+1 = 3
+1+1+1-1+1 = 3
+1+1+1+1-1 = 3
```

**示例 2**

```
输入：nums = [1], target = 1
输出：1
```

## 提示

- `1 <= nums.length <= 20`
- `0 <= nums[i] <= 1000`
- `0 <= sum(nums[i]) <= 1000`
- `-1000 <= target <= 1000`

## 思路

### 核心思想

给每个数选 `+` 或 `-`，把它们分成两组：**加正号的一组 `P`** 和 **加负号的一组 `N`**。设：

$$
\text{sum}(P) - \text{sum}(N) = target, \quad \text{sum}(P) + \text{sum}(N) = sum
$$

两式相加消去 `N`：

$$
\text{sum}(P) = \frac{sum + target}{2}
$$

于是问题转化为：**从 `nums` 中选一个子集，使其和恰好等于 `(sum + target) / 2`，求方案数**——这正是 **0-1 背包「装满容量的方案数」** 问题。

### 关键前提检查

设 `bagSize = (sum + target) / 2`，两个必须处理的边界：

1. **`sum + target` 为奇数** → `bagSize` 不是整数 → 无解，返回 0
2. **`|target| > sum`** → 正号全加也够不到 → 无解，返回 0

### 解法一：回溯（暴力，易理解）

对每个数枚举 `+` / `-` 两种选择，递归到底判断累加和是否等于 `target`。
- 时间复杂度：\(O(2^n)\)，每个数两种选择
- 空间复杂度：\(O(n)\)，递归深度
- `n ≤ 20` 时 \(2^{20} \approx 10^6\)，能过，但不是最优；呼应 [回溯.md](../算法思想/回溯.md)

### 解法二：0-1 背包 DP（推荐）

转化为「选子集和为 `bagSize` 的方案数」：

- **状态**：`dp[j]` = 从已考虑的数中选，凑出和为 `j` 的方案数
- **转移**：`dp[j] += dp[j - num]`（不选 num：保持 `dp[j]`；选 num：加上 `dp[j-num]`）
- **初始化**：`dp[0] = 1`（凑和为 0 有 1 种方案：什么都不选）
- **遍历顺序**：外层遍历物品 `num`，内层容量 **倒序** `j` 从 `bagSize` 到 `num`（0-1 背包一维数组必须倒序）
- 时间复杂度：\(O(n \times bagSize)\)
- 空间复杂度：\(O(bagSize)\)，一维滚动数组

### 图解（`nums=[1,1,1,1,1], target=3`）

```
sum = 5, target = 3
bagSize = (5 + 3) / 2 = 4        （选正号的子集和要等于 4）

问题变成：从 [1,1,1,1,1] 选子集和为 4 的方案数
= 从 5 个 1 里选 4 个 = C(5,4) = 5   ✅ 与答案一致

（等价于：4 个正号 + 1 个负号，sum(P)=4, sum(N)=1, 4-1=3）
```

## 代码

### 我的伪代码

> 👇 初次尝试的原始版本（保留用于复盘）。本题我的第一版就是回溯，**思路正确、能 AC**，没有实现错误；真正值得复盘的是「如何从这版指数级回溯优化到多项式级的 0-1 背包」，见下方 [个人总结](#个人总结)。

```java
class Solution {
    private int sum = 0;      // 当前累加值（回溯状态）
    private int count = 0;    // 满足 sum==target 的方案数

    public int findTargetSumWays(int[] nums, int target) {
        findTargetSumWaysIndex(nums, 0, target);
        return count;
    }

    public void findTargetSumWaysIndex(int[] nums, int index, int target) {
        // 终止条件：所有数都定了符号
        if (index > nums.length - 1) {
            if (sum == target) {
                count++;
            }
            return;
        }

        int newIndex = index + 1;

        // 选 + 号：加上 → 递归 → 撤销
        sum += nums[index];
        findTargetSumWaysIndex(nums, newIndex, target);
        sum -= nums[index];

        // 选 - 号：减去 → 递归 → 撤销
        sum += -nums[index];
        findTargetSumWaysIndex(nums, newIndex, target);
        sum -= -nums[index];
    }
}
```

> 说明：`sum += -nums[index]` 等价于 `sum -= nums[index]`，写成对称形式便于对照「+/-」两个分支。这版能过（`n ≤ 20`，\(2^{20} \approx 10^6\)），瓶颈在指数级复杂度，优化方向见解法二。

### 解法一：回溯（简化版，参数传递）

上面的成员变量写法也可以改成参数传递，用返回值累加，省去 `sum`/`count` 成员变量和手动撤销：

```java
public int findTargetSumWays(int[] nums, int target) {
    return backtrack(nums, target, 0, 0);
}

private int backtrack(int[] nums, int target, int index, int sum) {
    if (index == nums.length) {              // 所有数都定了符号
        return sum == target ? 1 : 0;
    }
    // 当前数选 + 号 和 选 - 号 两个分支之和
    return backtrack(nums, target, index + 1, sum + nums[index])
         + backtrack(nums, target, index + 1, sum - nums[index]);
}
```

### 解法二：0-1 背包 DP（修正版）

```java
public int findTargetSumWays(int[] nums, int target) {
    int sum = 0;
    for (int x : nums) sum += x;
    // 无解剪枝：容量不是整数，或目标绝对值超过总和
    if ((sum + target) % 2 != 0 || Math.abs(target) > sum) {
        return 0;
    }
    int bagSize = (sum + target) / 2;
    int[] dp = new int[bagSize + 1];
    dp[0] = 1;                               // 凑和为 0 有 1 种方案（什么都不选）
    for (int num : nums) {                   // 外层遍历物品
        for (int j = bagSize; j >= num; j--) {   // 内层容量倒序（0-1 背包关键）
            dp[j] += dp[j - num];            // 不选 + 选 两种方案累加
        }
    }
    return dp[bagSize];
}
```

## 个人总结

### 1. 核心转化：+/- 分组 → 子集和 → 0-1 背包

这题的精髓是**数学转化**。设正号组和为 `P`、负号组和为 `N`：

$$
P - N = target, \quad P + N = sum \implies P = \frac{sum + target}{2}
$$

于是「加正负号凑 target」等价于「选子集和为 `P` 的方案数」，直接套 0-1 背包「装满容量的方案数」模板。**看到「每个元素二选一（选/不选、正/负）求方案数」，先想能不能转成背包**。

### 2. 两个无解剪枝不能漏

| 情况 | 原因 | 后果（若不判） |
|:---|:---|:---|
| `(sum + target)` 为奇数 | `bagSize` 不是整数，子集和必为整数 | 无解，但 `int` 除法会算出错误的 `bagSize` |
| `\|target\| > sum` | 全选正号也够不到 target | `bagSize` 为负 → `new int[负数]` 越界崩溃 |

这是从回溯优化到 DP 时最容易翻车的两个边界，`494` 尤其常在此出错。

### 3. 0-1 背包一维数组为什么必须倒序

`dp[j] += dp[j - num]` 中，`dp[j - num]` 必须是**上一轮（不含当前 num）**的值：

- **倒序**（`j` 从大到小）：算 `dp[j]` 时，`dp[j-num]` 还没被本轮更新，是旧值 → 每个 num 只用一次 ✅
- **正序**（`j` 从小到大）：算 `dp[j]` 时，`dp[j-num]` 已被本轮更新过 → num 被重复使用 → 变成**完全背包** ❌

写 DP 版本时若把内层容量写成正序，就会踩这个坑；这也是 0-1 背包与完全背包在一维数组上的唯一区别。详见 [动态规划.md](../算法思想/动态规划.md) 背包模型。

### 4. `dp[0] = 1` 的含义

`dp[0]` 表示「凑出和为 0 的方案数」。空集（什么都不选）的和就是 0，所以有 1 种方案。这是递推的起点，若设为 0 则全盘皆 0。

> 特别注意：当 `nums` 含 0 时，每个 0 既可选正也可选负，会让方案数翻倍——本题 `dp` 转移天然处理了这点（`dp[j] += dp[j-0]` 即 `dp[j] += dp[j]`，数量正确翻倍）。

### 5. 回溯 vs 背包 DP

| 解法 | 时间 | 空间 | 特点 |
|:---|:---:|:---:|:---|
| 回溯 | \(O(2^n)\) | \(O(n)\) | 直观，n≤20 能过，是理解题意的入口 |
| 背包 DP | \(O(n \times bagSize)\) | \(O(bagSize)\) | 最优解，把指数级降为多项式 |

回溯是「暴力枚举每个符号」，背包 DP 是「发现子问题重叠后用数学转化 + 递推」。这题正好串起你整理的 [回溯.md](../算法思想/回溯.md) 和 [动态规划.md](../算法思想/动态规划.md) 两大思想。
