## 题目描述

给你一个字符串 `s`，找到 `s` 中最长的**回文子串**。

**子串**是字符串中**连续**的字符序列（区别于可不连续的「子序列」）。

## 示例

**示例 1**

```
输入：s = "babad"
输出："bab"
解释："aba" 同样是符合题意的答案。
```

**示例 2**

```
输入：s = "cbbd"
输出："bb"
```

---

## 提示

- `1 <= s.length <= 1000`
- `s` 仅由数字和英文字母组成

## 思路

### 核心：枚举「回文的形状」，而不是枚举所有子串

暴力枚举所有子串再逐个判回文是 \(O(n^3)\)。优化思路是利用回文的**递推结构**：

> 一个串是回文 ⇔ **首尾字符相等**，且**去掉首尾后的内部子串也是回文**。

「大回文由小回文推出」——这就是区间 DP；沿另一条路走：从每个可能的**回文中心**向两边扩展——这就是中心扩展。

```
b a b a d
    ↑ 中心 = 'b'，向两边扩：a==a ✓ → 继续扩越界停止 → "aba"（奇长度）
      ↑↑ 中心 = "bb" 间隙（cbbd 中）→ 向两边扩 → "bb"（偶长度）
```

### 解法链总览：暴力递归 → 记忆化 → 递推 DP（先笨后巧）

三版解法的**递归定义完全一致**：`isPal(i, j) = s[i]==s[j] && (j-i<3 || isPal(i+1, j-1))`，区别只在「算过的结果存不存、怎么取」：

| 版本 | 结果存哪 | 取结果方式 | 时间 | 备注 |
|:---|:---|:---|:---|:---|
| 解法一：暴力递归 | 不存 | 每次从头重算 | \(O(n^3)\) | 会 TLE，但定义清晰，是后续优化的地基 |
| 解法二：记忆化搜索 | `memo[i][j]` | 自顶向下，递归前查缓存 | \(O(n^2)\) | 「自顶向下的 DP」，无遍历顺序烦恼 |
| 解法三：递推 DP | `dp[i][j]` | 自底向上，循环顺序保证依赖就绪 | \(O(n^2)\) | 去掉递归调用栈 |
| 解法四：中心扩展 | 不存 | 换枚举维度：按中心向外扩 | \(O(n^2)\) / \(O(1)\) 空间 | 面试标准答案 |
| 解法五：for 枚举长度 + 滑动窗口 | 不存 | 枚举长度从大到小，窗口滑动判回文 | 最坏 \(O(n^3)\) | 直觉好写，练手感用；面试不够优 |

> 「递归 → 记忆化 → DP」的通用套路链见 [算法思想/0.递归](../算法思想/0.递归.md) 与 [1.动态规划](../算法思想/1.动态规划.md)。

### 解法三：动态规划（自底向上递推，好想）

1. 定义 `dp[i][j]`：子串 `s[i..j]` 是否为回文
2. 转移：`dp[i][j] = (s[i] == s[j]) && (j - i < 3 || dp[i+1][j-1])`
   - `j - i < 3`（长度 1/2/3）时内部无子串或单字符，首尾相等即回文
3. 遍历顺序：`dp[i][j]` 依赖**左下角** `dp[i+1][j-1]` → **i 从大到小、j 从小到大**（或按子串长度从小到大枚举）
4. 过程中用 `s[i..j]` 是回文时更新最长起点和长度

- 时间复杂度：\(O(n^2)\)，空间复杂度：\(O(n^2)\)（DP 表）

### 解法四：中心扩展（推荐）

1. 回文中心共 **2n−1 个**：n 个字符（奇长度回文）+ n−1 个字符间隙（偶长度回文）
2. 对每个中心，双指针 `l/r` 向两边扩：`s[l] == s[r]` 就继续，否则停
3. 记录扩展出的最长回文的**起点和长度**，最后 `substring` 截取

- 时间复杂度：\(O(n^2)\)（n 个中心 × 每次最多扩 n/2），空间复杂度：\(O(1)\)

### 解法五：for 循环枚举长度 + 滑动窗口（练手用）

思路很直接：**从最长的可能长度开始，固定窗口长度扫一遍，找到第一个回文就直接返回**。

1. 外层 `for`：长度 `len` 从 `n` 倒序到 `1`（最长优先，找到就 return）；
2. 内层窗口：左端点 `i` 从 `0` 到 `n - len`，每个长度为 `len` 的窗口对应子串 `s[i..i+len-1]`；
3. 窗口内判回文：双指针两端对撞（\(O(len)\)）；
4. 找到第一个回文窗口 → 直接返回（因为我们从最长的开始枚举，第一个命中的就是全局最长）。

```
s = "babad", n = 5

len=5：窗口 s[0..4] = "babad" → 判回文 ✗
len=4：窗口 s[0..3]="baba" ✗、s[1..4]="abad" ✗
len=3：窗口 s[0..2]="bab" ✓ → 直接返回 "bab"（后面的 len 不用再看）
```

- **最优情况**：整串就是回文（`len=n` 直接命中），时间 \(O(n)\)；
- **平均情况**：比暴力枚举所有子串再判回文**快一截**——因为一找到就收手，不需要把所有 \(O(n^2)\) 个子串全扫完；
- **最坏情况**：长 1 的单字符才是答案（如 `"abcde"`），要扫完所有长度，每个窗口判回文 \(O(n)\)，时间退化为 **\(O(n^3)\)**，`n=1000` 勉强擦边但仍可能 TLE；
- 空间复杂度：\(O(1)\)。

> 关键巧思：**长度从大到小枚举**，找到直接 return。如果从小到大枚举再比较长度，就彻底退化成暴力 \(O(n^3)\) 且没有任何提前收手的可能。

## 代码

### 解法一：暴力递归（TLE，练手 + 验证正确性用）

```java
class Solution {
    int start = 0, maxLen = 1;

    public String longestPalindrome(String s) {
        for (int i = 0; i < s.length(); i++)
            for (int j = i; j < s.length(); j++)
                if (isPal(s, i, j) && j - i + 1 > maxLen) {   // 每个区间都问一遍：是回文吗
                    start = i;
                    maxLen = j - i + 1;
                }
        return s.substring(start, start + maxLen);
    }

    // 递归判 s[i..j]：首尾相等 && 内部也是回文（递归出口：长度 ≤ 3）
    private boolean isPal(String s, int i, int j) {
        if (j - i < 3) return s.charAt(i) == s.charAt(j);
        return s.charAt(i) == s.charAt(j) && isPal(s, i + 1, j - 1);
    }
}
```

- \(O(n^2)\) 个区间 × 每次递归判定最多 \(O(n)\) 层 = \(O(n^3)\)，`n=1000` 时约 \(10^9\) 级操作，**LeetCode 会超时**。
- 价值在于：`isPal` 这行递归定义就是后续记忆化 / DP 的**唯一核心逻辑**，先把最笨的写对，优化只动「缓存」不动「逻辑」。

### 解法二：记忆化搜索（自顶向下的 DP）

```java
class Solution {
    int start = 0, maxLen = 1;
    Boolean[][] memo;                            // Boolean 三态：null = 还没算过

    public String longestPalindrome(String s) {
        int n = s.length();
        memo = new Boolean[n][n];
        for (int i = 0; i < n; i++)
            for (int j = i; j < n; j++)
                if (isPal(s, i, j) && j - i + 1 > maxLen) {
                    start = i;
                    maxLen = j - i + 1;
                }
        return s.substring(start, start + maxLen);
    }

    private boolean isPal(String s, int i, int j) {
        if (j - i < 3) return s.charAt(i) == s.charAt(j);
        if (memo[i][j] != null) return memo[i][j];            // ★ 查缓存，命中直接返回
        boolean res = s.charAt(i) == s.charAt(j) && isPal(s, i + 1, j - 1);
        return memo[i][j] = res;                              // ★ 存缓存（赋值表达式返回值即 res）
    }
}
```

- 与暴力递归**只差两行**（查缓存 + 存缓存），重复子问题从指数级降到 \(O(n^2)\) 个状态，时间 \(O(n^2)\)、空间 \(O(n^2)\) + 递归栈 \(O(n)\)。
- **不用纠结遍历顺序**：递归天然「先算内部、再算外层」，这正是它比递推 DP 好写的地方。

### 解法三：动态规划（自底向上递推）

```java
class Solution {
    public String longestPalindrome(String s) {
        int n = s.length();
        boolean[][] dp = new boolean[n][n];      // dp[i][j]: s[i..j] 是否回文
        int start = 0, maxLen = 1;               // 至少整串有单字符回文

        for (int i = n - 1; i >= 0; i--) {       // i 从大到小：先算出左下角 dp[i+1][*]
            for (int j = i; j < n; j++) {
                if (s.charAt(i) != s.charAt(j)) continue;     // 首尾不等，必非回文
                if (j - i < 3 || dp[i + 1][j - 1]) {          // 长度≤3 或 内部是回文
                    dp[i][j] = true;
                    if (j - i + 1 > maxLen) {                 // 更新最长回文
                        start = i;
                        maxLen = j - i + 1;
                    }
                }
            }
        }
        return s.substring(start, start + maxLen);
    }
}
```

### 解法四：中心扩展（推荐）

```java
class Solution {
    public String longestPalindrome(String s) {
        int n = s.length(), start = 0, maxLen = 1;

        for (int k = 0; k < n; k++) {
            // 奇长度：中心是字符 s[k] 本身
            int[] r1 = expand(s, k, k);
            // 偶长度：中心是 s[k] 与 s[k+1] 的间隙
            int[] r2 = expand(s, k, k + 1);
            for (int[] r : new int[][]{r1, r2}) {
                if (r[1] > maxLen) {
                    maxLen = r[1];
                    start = r[0];
                }
            }
        }
        return s.substring(start, start + maxLen);
    }

    // 从中心 l/r 向两边扩展，返回 {最长回文起点, 长度}
    private int[] expand(String s, int l, int r) {
        while (l >= 0 && r < s.length() && s.charAt(l) == s.charAt(r)) {
            l--; r++;                        // 匹配成功，继续向外扩
        }
        // 退出时 s[l] != s[r]（或越界），回文实际是 (l, r) 开区间内
        int len = r - l - 1;
        return new int[]{l + 1, len};
    }
}
```

### 解法五：for 循环枚举长度 + 滑动窗口

```java
class Solution {
    public String longestPalindrome(String s) {
        int n = s.length();

        // 外层：长度从大到小枚举，第一个命中即全局最长，直接 return
        for (int len = n; len >= 1; len--) {
            // 内层：窗口左端点 i，窗口范围 [i, i+len)
            for (int i = 0; i + len <= n; i++) {
                // 判断 s[i..i+len-1] 是否为回文
                if (isPal(s, i, i + len - 1)) {
                    return s.substring(i, i + len);   // ★ 找到即全局最长，提前终止
                }
            }
        }
        return "";   // 不会执行到（len=1 时每个字符本身就是回文）
    }

    // 双指针两端对撞，判 s[l..r] 是否回文 O(r-l+1)
    private boolean isPal(String s, int l, int r) {
        while (l < r) {
            if (s.charAt(l) != s.charAt(r)) {
                return false;
            }
            l++; r--;
        }
        return true;
    }
}
```

- **巧思就在 `return s.substring(...)` 这行**：枚举长度从 n→1，只要当前长度能找到一个回文窗口，它就必然是全局最长，直接返回不看后面——这也是为什么它平均表现比暴力快得多。
- 但**最坏仍是 \(O(n^3)\)**：比如 `"abcde"` 这种每个窗口都得判完才返回 false，对 `len=n` 有 1 个窗口 → `len=n-1` 有 2 个 → … → `len=1` 有 n 个，每个窗口判回文 \(O(n)\)，总和 \(\sum_{k=1}^{n} k \cdot O(n) = O(n^3)\)。

## 个人总结

### 1. 题眼：连续子串 + 回文结构 → DP 或中心扩展，\(O(n^2)\) 是面试预期

`n ≤ 1000` 说明 \(O(n^2)\) 可过（约 \(10^6\) 次操作）。回文有两层结构可利用：**区间可递推**（DP）与**中心对称**（中心扩展）。中心扩展不占额外空间，是面试的标准答案；DP 的价值在于它的转移方程是很多回文题（647、516、132）的公共底座。

### 2. 一条链练透：暴力递归 → 记忆化 → 递推 DP

三版 `isPal(i, j)` 定义**一字不改**，优化的只是「重复计算」：
- **暴力递归**：每次重算 → \(O(n^3)\) TLE，但先用它把「正确」做实；
- **记忆化搜索**：给递归加 `memo`（查缓存 + 存缓存两行）→ \(O(n^2)\)，**自顶向下**，循环顺序免想；
- **递推 DP**：把 `memo` 换成 `dp`、递归换成倒序循环 → \(O(n^2)\)，**自底向上**，省递归栈，但必须手动保证「依赖先算好」（见下一点）。

> 选型经验：依赖方向明显（如本题左下角）直接写递推 DP；依赖复杂、循环序不好定时，先写记忆化搜索，必要时再手动转 DP。通用方法论见 [算法思想/0.递归](../算法思想/0.递归.md)、[1.动态规划](../算法思想/1.动态规划.md)。

### 3. DP 的遍历顺序：依赖「左下角」必须 i 倒序

`dp[i][j]` 依赖 `dp[i+1][j-1]`（左下角）。若 i 正序枚举，算 `dp[i][j]` 时 `dp[i+1][...]` 还没算出来 → 全错。两个正确的顺序：
- **i 从大到小**、j 从小到大（本笔记写法）；
- **按子串长度枚举**：长度 1 → 2 → 3 → …（更直观，推荐）。

### 4. 中心扩展的关键细节：中心有 2n−1 个，不是 n 个

奇长度回文（"aba"）中心是**字符**，偶长度（"bb"）中心是**两个字符之间的间隙**。漏掉偶长度中心，`"cbbd"` 会返回单字符而非 `"bb"`——这是本题第一大坑。写法上用 `expand(s, k, k)` 和 `expand(s, k, k+1)` 两次调用统一处理，避免复制两份扩展逻辑。

### 5. 记「起点 + 长度」，别只记长度

最后要返回**子串**，必须同时记录 `start` 和 `maxLen`。扩展函数退出时 `l`、`r` 都已多走一步（`s[l] != s[r]` 或越界），所以回文是**开区间** `(l, r)`：长度 = `r - l - 1`，起点 = `l + 1`。这两个「减一/加一」最容易写错，手推一遍 `"babad"`（中心 k=1 时 l 从 1 扩到 −1、r 从 1 扩到 3，len = 3−(−1)−1 = 3 → "bab"）即可验证。

### 6. 子串 vs 子序列：一字之差两道题

| 对比 | 5. 最长回文**子串** | 516. 最长回文**子序列** |
|:---|:---|:---|
| 连续性 | 必须连续 | 可不连续 |
| 解法 | 中心扩展 / 区间 DP | 区间 DP（`dp[i][j]` = 区间内最长回文子序列长度） |
| 空间 | 中心扩展可 \(O(1)\) | 必须 \(O(n^2)\) |

### 7. for 循环 + 滑动窗口的优劣：好写但不够优，面试要说明取舍

**为什么它好写**：完全符合直觉——「要最长的，就从最长的长度开始试，试到对就交卷」。两层 for + 一个判回文函数，三分钟就能写完。

**为什么它不够优**：**瓶颈在「判回文仍要 O(n)」**——窗口从一端滑到另一端，相邻两个窗口只差一个字符，但判回文不能复用之前的结论，每个窗口都要双指针对撞扫一遍。这是它和真正的「滑动窗口（双端单调，增量维护窗口信息）」的本质区别：

| 真正的滑动窗口（如 [3. 无重复最长子串](3.%20无重复字符的最长子串.md)） | 本题「固定长度 + 判回文」 |
|:---|:---|
| 窗口滑动时 **O(1) 增量维护**（进一个字符、出一个字符、更新哈希表） | 窗口滑动时 **O(len) 重新判回文**，信息完全丢弃重来 |
| 整体 \(O(n)\) 或 \(O(n \cdot \Sigma)\) | 整体最坏 \(O(n^3)\) |

**面试答法**：先讲「for 枚举长度 + 窗口滑动」的直觉，然后主动指出它的复杂度局限 → 自然过渡到「怎么优化判回文？」→ 引出中心扩展（从中心扩天然避免重复扫）或 DP（用子结构复用）——**能自我批判、再抛出更优解是加分信号**。
