## 题目描述

给你一个非负整数数组 `nums` ，你最初位于数组的 **第一个下标** 。数组中的每个元素代表你在该位置可以跳跃的**最大长度**。

判断你是否能够到达最后一个下标，如果可以，返回 `true` ；否则，返回 `false` 。

## 示例

**示例 1**

```
输入：nums = [2,3,1,1,4]
输出：true
解释：可以先跳 1 步，从下标 0 到达下标 1, 然后再从下标 1 跳 3 步到达最后一个下标。
```

**示例 2**

```
输入：nums = [3,2,1,0,4]
输出：false
解释：无论怎样，总会到达下标为 3 的位置。但该下标的最大跳跃长度是 0 ， 所以永远不可能到达最后一个下标。
```

---

## 提示

- `1 <= nums.length <= 10^4`
- `0 <= nums[i] <= 10^5`

---

## 思路

### 核心思想

不需要关心具体怎么跳，只需要知道**哪些位置可达**。可达位置是一个**连续的前缀区间**：从下标 0 出发，只要 `i <= maxReach`（当前能走到的最远下标），位置 `i` 就可达；而到达 `i` 后又能用 `nums[i]` 把边界推到 `max(maxReach, i + nums[i])`。一旦 `i > maxReach`，说明被卡住了，后面全部不可达，返回 `false`。

```
nums = [2,3,1,1,4]              nums = [3,2,1,0,4]
i=0: maxReach = 0+2 = 2         i=0: maxReach = 0+3 = 3
i=1: maxReach = max(2, 4) = 4   i=1: maxReach = max(3, 3) = 3
i=2: maxReach = max(4, 3) = 4   i=2: maxReach = max(3, 3) = 3
i=3: maxReach = max(4, 4) = 4   i=3: maxReach = max(3, 3) = 3
i=4: 4 <= 4 可达 → true         i=4: 4 > 3 卡死 → false ✅
```

### 解法一：动态规划（基础）

按定义直接推：`dp[i]` 表示下标 `i` 是否可达。`dp[0] = true`；对每个 `i`，枚举任意可达的 `j`（`dp[j] == true` 且 `j + nums[j] >= i`），则 `dp[i] = true`。

- 时间复杂度：\(O(n^2)\)，两层循环
- 空间复杂度：\(O(n)\) dp 数组

### 解法二：贪心（推荐）

一次遍历，维护**最远可达位置** `maxReach`：

1. 遍历到 `i` 时，若 `i > maxReach` → 卡死，返回 `false`
2. 否则用 `nums[i]` 扩展：`maxReach = max(maxReach, i + nums[i])`
3. 若 `maxReach >= n - 1`，已能覆盖终点，提前返回 `true`

- 时间复杂度：\(O(n)\)
- 空间复杂度：\(O(1)\)

## 代码

### 解法一：动态规划

```java
class Solution {
    public boolean canJump(int[] nums) {
        int n = nums.length;
        boolean[] dp = new boolean[n];       // dp[i]：下标 i 是否可达
        dp[0] = true;                        // 起点天然可达
        for (int i = 1; i < n; i++) {
            for (int j = 0; j < i; j++) {    // 枚举从哪个位置跳过来
                // j 可达，且从 j 一步能跳到 i
                if (dp[j] && j + nums[j] >= i) {
                    dp[i] = true;
                    break;
                }
            }
        }
        return dp[n - 1];
    }
}
```

### 解法二：贪心（推荐）

```java
class Solution {
    public boolean canJump(int[] nums) {
        int maxReach = 0;                            // 当前能到达的最远下标
        for (int i = 0; i < nums.length; i++) {
            if (i > maxReach) return false;          // 当前格都够不着，后面更没戏
            maxReach = Math.max(maxReach, i + nums[i]);  // 扩展最远可达边界
            if (maxReach >= nums.length - 1) return true; // 覆盖终点，提前结束
        }
        return true;
    }
}
```

## 个人总结

### 1. 可达集合是「连续前缀区间」，这是贪心成立的前提

`maxReach` 不是某一条具体路径的终点，而是**所有可达位置的右边界**——可达下标恰好构成 `0..maxReach` 的连续区间（能到 `i` 就能经过途中的每个点）。所以只需维护一个边界变量，而无须记录任何具体路径。这是本题与一般搜索题的本质区别。

### 2. 卡死的判定是 `i > maxReach`，不是「遇到 0」

示例 2 `[3,2,1,0,4]` 里 `maxReach` 一直停在 3，`i=4 > 3` 才判 false；中间下标 3 的值是 0 并不是 false 的直接原因——即使某处是 0，只要 maxReach 已经越过它就没事。判定条件统一成「边界覆盖不住当前下标」，不用对 0 特判。

### 3. 与 45. 跳跃游戏 II 的关联

| 题目 | 问法 | 解法 | 关键变量 |
|:---|:---|:---|:---|
| 55. 跳跃游戏 | 能不能到（可行性） | 贪心，一次遍历 | `maxReach` |
| 45. 跳跃游戏 II | 最少跳几步（最步数） | 贪心，分层推进 | `maxReach` + `currentEnd`（本步边界） |

45 在 55 的基础上多维护一个「当前步的边界」：走到边界时步数 +1，并把下一步的边界更新为层内能扩展到的最远值。同族思想还有 1024 视频拼接、1326 灌溉花园的「区间覆盖」贪心。

### 4. DP 与贪心的取舍

DP \(O(n^2)\) 是转移方程的直译，`n = 10^4` 时最坏 \(10^8\) 有超时风险；贪心 \(O(n)\) 才是正解。面试先答贪心并讲清「可达 = 连续区间」，DP 可以作为从「定义出发」的过渡思路展示推导链。
