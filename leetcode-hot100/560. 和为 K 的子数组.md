## 题目描述

给你一个整数数组 `nums` 和一个整数 `k` ，请你统计并返回 **该数组中和为 `k` 的连续子数组的个数** 。

子数组是数组中元素的连续非空序列。

---

## 示例

**示例 1**

```
输入：nums = [1,1,1], k = 2
输出：2
解释：[1,1]（下标 0-1）和 [1,1]（下标 1-2）两个子数组。
```

**示例 2**

```
输入：nums = [1,2,3], k = 3
输出：2
解释：[1,2]（和为 3）和 [3]（和为 3）两个子数组。
```

---

## 提示

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`
- **注意**：数组元素**可以为负数**，这决定了不能用滑动窗口。

## 思路

### 核心思想

**前缀和 + 哈希表**：定义 `prefix[i]` = `nums[0..i-1]` 的和。则子数组 `nums[j..i-1]` 的和 = `prefix[i] - prefix[j]`。

要找「和为 `k` 的子数组」，即找满足 `prefix[i] - prefix[j] = k` 的 `(i, j)` 对，变形为：

$$
prefix[j] = prefix[i] - k
$$

于是**边遍历边用哈希表记录「每个前缀和出现的次数」**，当前缀和为 `cur` 时，累加 `map[cur - k]` 即可。

### 关键陷阱：为什么不能用滑动窗口

滑动窗口要求「窗口和随右指针右移单调不减、随左指针右移单调不增」，这依赖**所有元素非负**。本题**含负数**，右移右指针可能让窗口和变小，滑动窗口的收缩逻辑失效。

| 前提 | 滑动窗口 | 前缀和 + 哈希 |
|:---|:---:|:---:|
| 元素全为正 | ✅ 可用 | ✅ 可用 |
| **元素含负数** | ❌ 失效 | ✅ 可用 |

> 看到「子数组和 / 计数」且**含负数**，几乎必然是**前缀和 + 哈希表**。

### 解法一：前缀和 + 哈希表（推荐）

1. 用哈希表 `map` 记录「某个前缀和出现了几次」，初始化 `map[0] = 1`（表示空前缀）
2. 遍历数组，累加当前前缀和 `cur`
3. 若 `map` 中存在 `cur - k`，说明存在若干个 `j` 使 `prefix[j] = cur - k`，累加其次数到答案
4. 把当前 `cur` 计入 `map`
- 时间复杂度：\(O(n)\)，一次遍历
- 空间复杂度：\(O(n)\)，哈希表最多存 n 个前缀和

### 解法二：暴力枚举（对照用）

1. 枚举所有子数组的起点 `i` 和终点 `j`
2. 累加区间和，等于 `k` 则计数
- 时间复杂度：\(O(n^2)\)（用前缀和优化区间求和后仍是 \(O(n^2)\)）
- 空间复杂度：\(O(1)\)
- `n = 2×10^4` 时 \(n^2 = 4×10^8\)，**可能 TLE**，仅作思路对照

```java
// ❌ 错误1：忘了初始化 map.put(0, 1)，会漏掉「从下标 0 开始就等于 k」的子数组
// ❌ 错误2：先把 cur 放进 map 再查 cur-k，导致 k=0 时把自己也算进去（顺序错）
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> map = new HashMap<>();
    int cur = 0, count = 0;
    for (int x : nums) {
        cur += x;
        map.put(cur, map.getOrDefault(cur, 0) + 1);   // ❌ 应该先查后存
        if (map.containsKey(cur - k)) {
            count += map.get(cur - k);                // ❌ 因为上一行先存了，逻辑被污染
        }
    }
    return count;                                      // ❌ 且缺少 map.put(0,1) 初始化
}
```

### 解法一：前缀和 + 哈希表（修正版）

```java
public int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> map = new HashMap<>();
    map.put(0, 1);                          // 空前缀：前缀和为 0 出现 1 次
    int cur = 0, count = 0;
    for (int x : nums) {
        cur += x;                           // 当前前缀和
        // 先查：存在 cur-k 说明有以当前位置结尾、和为 k 的子数组
        count += map.getOrDefault(cur - k, 0);
        // 后存：把当前前缀和计入，供后续位置查询
        map.put(cur, map.getOrDefault(cur, 0) + 1);
    }
    return count;
}
```

### 解法二：暴力枚举

```java
public int subarraySum(int[] nums, int k) {
    int n = nums.length, count = 0;
    for (int i = 0; i < n; i++) {
        int sum = 0;
        for (int j = i; j < n; j++) {       // 以 i 为起点，向右累加
            sum += nums[j];
            if (sum == k) count++;
        }
    }
    return count;
}
```

## 个人总结

### 1. 前缀和的核心恒等式

$$
\text{子数组 } nums[j..i-1] \text{ 的和} = prefix[i] - prefix[j]
$$

「和为 k」即 `prefix[i] - prefix[j] = k`，变形为 `prefix[j] = prefix[i] - k`。于是问题从「枚举子数组」转化为「查历史前缀和里有几个等于 `cur - k`」，这是 \(O(n^2)\) 降到 \(O(n)\) 的关键。

### 2. 前缀和为什么天然保证子数组「连续」

这是前缀和最容易犯迷糊的点：**连续性由前缀和的定义本身保证，不需要额外操作。**

关键在于 `prefix[i] - prefix[j]` 这个减法的几何含义：

```
prefix[i] = nums[0] + nums[1] + ... + nums[i-1]     (前 i 项之和)
prefix[j] = nums[0] + nums[1] + ... + nums[j-1]     (前 j 项之和，j < i)

两者相减，前面 [0..j-1] 部分完全抵消：
prefix[i] - prefix[j] = nums[j] + nums[j+1] + ... + nums[i-1]
                        └────────── 连续的一段 ──────────┘
```

因为前缀和是「从头累加到某处」，两个前缀和之差**必然是中间某一段连续区间**，不可能跳着取。

**那哈希表会不会匹配到不连续的组合？不会**——哈希表存的每个键都是「某个真实位置的前缀和 `prefix[j]`」（带位置含义），当前 `cur = prefix[i]`。无论命中哪个历史 `prefix[j]`，相减后剩下的永远是 `nums[j..i-1]` 这一整段连续区间。哈希表只是加速「找匹配的 `prefix[j]`」，不改变「差 = 连续区间和」这个本质。

**走查 `nums=[1,1,1], k=2`**：

| 遍历到 | cur | 查 `cur-k` | 命中含义 |
|:---:|:---:|:---:|:---|
| 下标 1 | 2 | 查 `0`，命中 `prefix[0]` | `prefix[2]-prefix[0]` = `nums[0..1]` = `[1,1]`（连续） |
| 下标 2 | 3 | 查 `1`，命中 `prefix[1]` | `prefix[3]-prefix[1]` = `nums[1..2]` = `[1,1]`（连续） |

两次命中的区间都是连续的一段，没有一次是「跳着选」。

### 3. `map.put(0, 1)` 为什么必须初始化

`prefix[0] = 0` 表示「空前缀」。如果某个位置的前缀和 `cur` 恰好等于 `k`，那么 `cur - k = 0`，需要 `map` 里有一个 `0` 来匹配——这对应「从下标 0 一直到当前位置」这整段子数组。

**反例**：`nums = [1,1,1], k = 2`，遍历到下标 1 时 `cur = 2`，`cur - k = 0`，若没有 `map[0]=1` 就会漏掉 `[1,1]` 这个答案。

### 4. 「先查后存」的顺序不能反

必须**先** `count += map[cur-k]`，**再** `map.put(cur, ...)`：

- **先查**：保证查询的是「当前位置**之前**的前缀和」，符合子数组必须非空的要求
- **若先存后查**：当 `k = 0` 时，`cur - k = cur` 刚好等于自己，会把「长度为 0 的空子数组」误算进去

> 口诀：**先查答案，再存自己**。

### 5. 为什么含负数就不能用滑动窗口

滑动窗口的收缩逻辑「窗口和超了就右移左指针缩小」依赖**窗口和随长度单调**。含负数时，加入一个负数反而让和变小，右移右指针不再单调，收缩条件失效。

| 题目 | 元素范围 | 正确解法 |
|:---|:---|:---|
| 209. 长度最小的子数组 | 全为正 | 滑动窗口 |
| **560. 和为 K 的子数组** | **含负数** | **前缀和 + 哈希** |

这是区分「滑动窗口」和「前缀和 + 哈希」的核心判据。

### 6. 前缀和 + 哈希的通用套路

这题是「**前缀和 + 哈希表计数**」的模板题，同类题都可套：

| 题目 | 变体 |
|:---|:---|
| 560. 和为 K 的子数组 | 求和为 k 的子数组**个数** |
| 974. 和可被 K 整除的子数组 | 哈希表存前缀和的**余数** |
| 523. 连续的子数组和 | 存余数 + 判断下标间隔 |
| 525. 连续数组（0/1 等长） | 把 0 看作 -1，求和为 0 的最长子数组 |

> 记忆：**「子数组和满足某条件的计数 / 最值」 + 含负数 → 前缀和 + 哈希表**。

### 7. 暴力 vs 前缀和哈希

| 解法 | 时间 | 空间 | 说明 |
|:---|:---:|:---:|:---|
| 暴力枚举 | \(O(n^2)\) | \(O(1)\) | n=2×10⁴ 时 4×10⁸ 次运算，可能 TLE |
| 前缀和 + 哈希 | \(O(n)\) | \(O(n)\) | 用空间换时间，把「枚举 j」变成「哈希查询」 |

本质区别：暴力对每个终点都重新往前扫一遍找起点（\(O(n)\)）；前缀和哈希把「找起点」变成 \(O(1)\) 的哈希查询，这与 [每日温度（739）](739.%20每日温度.md) 里「单调栈复用信息」是同一种优化思想——**用额外结构记住历史，避免重复扫描**。
