## 题目描述

给你一个用字符数组 `tasks` 表示的 CPU 需要执行的任务列表，用字母 A 到 Z 表示，其中每个字母表示一种不同种类的任务。任务可以以任意顺序执行，并且每个任务都可以在 1 个单位时间内执行完。在任何一个单位时间，CPU 可以完成一个任务，或者处于待命状态。

然而，两个 **相同种类** 的任务之间必须有长度为整数 `n` 的冷却时间，因此至少有连续 `n` 个单位时间内 CPU 在执行不同的任务，或者在待命状态。

你需要计算完成所有任务所需要的 **最短时间间隔**。

---

## 示例

**示例 1**

```
输入：tasks = ["A","A","A","B","B","B"], n = 2
输出：8
解释：一种可能的序列是：A -> B -> (待命) -> A -> B -> (待命) -> A -> B
     在完成任务 A 之后，必须等待两个间隔。对任务 B 来说也是一样。
     在第 3 个间隔，A 和 B 都不能完成，所以需要待命。
```

**示例 2**

```
输入：tasks = ["A","C","A","B","D","B"], n = 1
输出：6
解释：一种可能的序列是：A -> B -> C -> D -> A -> B
     任务种类足够多，空隙都被填满，无需待命，总时间等于任务数。
```

**示例 3**

```
输入：tasks = ["A","A","A","B","B","B"], n = 3
输出：10
解释：一种可能的序列为：A -> B -> idle -> idle -> A -> B -> idle -> idle -> A -> B
     只有 A、B 两种任务，需要被 3 个间隔分割，导致每次重复之间有两次待命。
```

## 思路

### 核心思想

**贪心**：优先安排出现次数最多的任务，让它撑起整个时间轴的「骨架」，其余任务和待命填入空隙。属于 [贪心算法.md](../算法思想/贪心算法.md) 中「排序 / 计数 + 填空隙」的模型。

### 桶思想（关键模型）

设 `maxCount` = 出现最多的任务的次数，`maxNum` = 有多少种任务并列达到 `maxCount`。

以出现最多的任务为「行首」，每 `(n+1)` 个格子为一个「桶」：

```
以 A 出现 3 次、n = 2 为例（每桶 n+1 = 3 格）：

桶1: A  ?  ?
桶2: A  ?  ?
桶3: A            ← 最后一桶只放并列最多的任务，不需填满

前 (maxCount-1) 个桶必须占满 n+1 格（不够就 idle 待命）
最后一桶放 maxNum 个并列最多的任务
```

### 公式推导

$$
\text{结果} = \max\Big((maxCount - 1) \times (n + 1) + maxNum,\ \ \text{tasks.length}\Big)
$$

**为什么两项取 max**：

| 情况 | 谁更大 | 原因 |
|:---|:---|:---|
| 任务种类少、冷却 `n` 大 | 公式项 | 空隙填不满，必须 idle 待命 |
| 任务种类多、冷却 `n` 小 | `tasks.length` | 空隙被其他任务填满，无需 idle，总时间 = 任务总数 |

**用三个示例验证公式**：

| 示例 | maxCount | maxNum | n | 公式项 | tasks.length | 取 max | 答案 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 1 | 3 (A/B) | 2 | 2 | `(3-1)×3+2=8` | 6 | **8** | 8 ✅ |
| 2 | 2 (A/B) | 2 | 1 | `(2-1)×2+2=4` | 6 | **6** | 6 ✅ |
| 3 | 3 (A/B) | 2 | 3 | `(3-1)×4+2=10` | 6 | **10** | 10 ✅ |

> 示例 2 正是「种类多、空隙填满」的情况：公式项 4 < 任务数 6，答案取任务数 6。

### 解法一：贪心 + 桶（公式法，推荐）

1. 统计每种任务的出现次数（26 个字母桶）
2. 求 `maxCount`（最大次数）和 `maxNum`（并列最大的任务数）
3. 套公式 `max((maxCount-1)*(n+1) + maxNum, tasks.length)`
- 时间复杂度：\(O(n)\)，n 为任务总数（统计词频线性，求最值遍历 26 常数）
- 空间复杂度：\(O(1)\)，固定 26 个计数

### 解法二：优先队列模拟（直观但慢）

1. 用大顶堆按剩余次数排序所有任务
2. 每一轮取出最多 `n+1` 个任务执行（这就是一个冷却周期）
3. 执行后剩余次数减 1 的任务重新入堆
4. 累加每轮耗时，最后一轮不补 idle
- 时间复杂度：\(O(\text{总时间} \times \log 26)\)
- 空间复杂度：\(O(26)\)

### 解法一：贪心 + 桶（修正版）

```java
public int leastInterval(char[] tasks, int n) {
    int[] cnt = new int[26];
    for (char c : tasks) {
        cnt[c - 'A']++;
    }
    int maxCount = 0;                       // 出现最多的次数
    for (int x : cnt) {
        maxCount = Math.max(maxCount, x);
    }
    int maxNum = 0;                         // 有几种任务并列最多
    for (int x : cnt) {
        if (x == maxCount) {
            maxNum++;
        }
    }
    // 桶公式 与 任务总数 取较大者
    return Math.max((maxCount - 1) * (n + 1) + maxNum, tasks.length);
}
```

### 解法二：优先队列模拟

```java
public int leastInterval(char[] tasks, int n) {
    int[] cnt = new int[26];
    for (char c : tasks) {
        cnt[c - 'A']++;
    }
    // 大顶堆：剩余次数多的任务优先执行
    PriorityQueue<Integer> heap = new PriorityQueue<>((a, b) -> b - a);
    for (int x : cnt) {
        if (x > 0) heap.offer(x);
    }
    int time = 0;
    while (!heap.isEmpty()) {
        int round = n + 1;                  // 一个冷却周期最多执行 n+1 个不同任务
        List<Integer> temp = new ArrayList<>();
        while (round > 0 && !heap.isEmpty()) {
            int c = heap.poll();
            if (c - 1 > 0) temp.add(c - 1);  // 执行一次后剩余次数
            time++;                          // 每执行一个任务耗时 1
            round--;
        }
        for (int r : temp) heap.offer(r);    // 剩余任务重新入堆
        // 若堆已空，说明是最后一轮，不需补 idle；否则本轮不足 n+1 的部分是待命
        if (!heap.isEmpty()) time += round;
    }
    return time;
}
```

## 个人总结

### 1. 桶思想是怎么想到的

把「出现最多的任务」当作时间轴的**骨架**：它出现 `maxCount` 次，就把时间切成 `maxCount` 段。相邻两次之间必须间隔 `n`，所以每段长 `n+1`（自己 1 格 + 冷却 n 格）。

- 前 `maxCount - 1` 段必须占满 `n+1` 格 → `(maxCount-1) * (n+1)`
- 最后一段不需要冷却，只放并列最多的 `maxNum` 个任务 → `+ maxNum`

一句话：**「谁最多谁排骨架，其余填空隙」**。

### 2. 为什么最后一段不需要冷却

**核心：冷却是「两次相同任务之间的保护带」，是间隔，不是结尾。** 冷却时间夹在两次相同任务的**中间**，用来让下一次相同任务满足间隔要求；而最后一次任务之后再没有相同任务要执行，自然无需为谁腾出冷却。

```
A 出现 3 次，n = 2，每段 n+1 = 3 格：

段1: [A _ _]  段2: [A _ _]  段3: [A]
      ↑__冷却__↑    ↑__冷却__↑    ↑
     保护第2个A      保护第3个A     后面没有A了，无需冷却
```

- 段1 的 `_ _`：为了让**第 2 个 A** 满足间隔
- 段2 的 `_ _`：为了让**第 3 个 A** 满足间隔
- 段3 的 A 是**最后一个**，后面不再有 A，不需要尾随冷却

换个角度理解：`maxCount` 个相同任务之间，只需要 `maxCount - 1` 个间隔（就像 3 根柱子之间只有 2 道栅栏）：

```
A ─间隔─ A ─间隔─ A      3 个 A，只有 2 个间隔
```

所以公式拆成两部分：
- **前 `maxCount - 1` 段**：每段「1 个任务 + n 格冷却」→ `(maxCount-1) × (n+1)`
- **最后 1 段**：只放任务本身，无尾随冷却 → `+ maxNum`

> 如果给最后一段也补冷却，示例 1 会算成 9，但第 3 个 A、B 后面根本没有任务，那段等待是多余的——题目求**最短**时间，不会加它。

### 3. 为什么最后要和 `tasks.length` 取 max

公式项只考虑了「骨架 + 待命」，但当任务**种类足够多**时，空隙会被其他任务填满，根本不需要 idle。这时真实耗时就是任务总数本身。

| 场景 | 例子 | 结果 |
|:---|:---|:---|
| 空隙填不满 | 示例 3：只有 A、B，n=3 | 公式项 10 > 任务数 6，取 10（有 idle） |
| 空隙被填满 | 示例 2：4 种任务，n=1 | 任务数 6 > 公式项 4，取 6（无 idle） |

> 漏掉这个 max 是最经典的错，示例 2 就会算错。

### 4. `maxNum` 为什么要统计「并列最多」

最后一个桶里，**每一种达到 `maxCount` 次的任务都要占一格**。比如 A、B 都出现 3 次，最后一桶就是 `A B`（两格），所以 `+maxNum` 而不是 `+1`。

反例：如果写死 `+1`，示例 1（A、B 并列 3 次）会算成 `(3-1)×3+1 = 7`，比正确答案 8 少 1。

### 5. 公式法 vs 优先队列模拟

| 维度 | 公式法 | 优先队列模拟 |
|:---|:---|:---|
| 时间 | \(O(n)\) | \(O(\text{总时间} \times \log 26)\) |
| 空间 | \(O(1)\) | \(O(26)\) |
| 思维 | 需要想到桶模型（较难） | 直接模拟过程（直观） |
| 推荐度 | ⭐ 面试首选 | 理解过程用 |

> 面试建议：先讲桶公式 \(O(n)\)，如果面试官想看你对过程的理解，再补优先队列模拟。

### 6. 与贪心笔记的呼应

这题的贪心策略是「**每轮优先安排剩余次数最多的任务**」：

- **优先队列模拟法** = [贪心算法.md](../算法思想/贪心算法.md) 第四节「堆贪心」的直接应用（大顶堆每次取最多）
- **公式法** = 贪心洞察的数学化——不用真的模拟，直接算出骨架长度

两种解法本质是同一个贪心思想的两种表达：一个「动手排」，一个「算骨架」。

### 7. 易错边界

| 边界 | 处理 |
|:---|:---|
| `n = 0` | 无冷却，公式退化为 `max(maxCount-1+maxNum, len) = len`，即任务总数 |
| 所有任务相同 | 如 `["A","A","A"], n=2`，maxNum=1，结果 `(3-1)×3+1 = 7` |
| 单个任务 | 直接返回 1 |
