# 70. 爬楼梯

> **难度**：🟢 简单 | **标签**：动态规划、数学、记忆化搜索 | **企业**：—

## 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶呢？

## 示例

**示例 1**

```
输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶
```

**示例 2**

```
输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶
```

---

## 提示

- `1 <= n <= 45`

## 思路

### 核心思想：斐波那契 / 动态规划

到达第 `n` 阶，上一步一定在第 `n-1` 阶（再爬 1 步）或第 `n-2` 阶（再爬 2 步）。因此：

\[dp[n] = dp[n-1] + dp[n-2]\]

本质上就是**斐波那契数列**，只是初始值不同：`dp[1] = 1, dp[2] = 2`。

```
n=1: 1 种  →  1
n=2: 2 种  →  1+1, 2
n=3: 3 种  →  dp[2] + dp[1] = 2 + 1
n=4: 5 种  →  dp[3] + dp[2] = 3 + 2
```

### 解法一：迭代 DP（推荐）

1. 两个变量 `prev2`（dp[i-2]）、`prev1`（dp[i-1]）滚动更新
2. 从 3 遍历到 n，每一步 `curr = prev1 + prev2`
3. 最后返回 `prev1`（当 n=1 或 2 时直接返回 n）

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\)

### 解法二：递归 + 记忆化

1. 递归定义：`climbStairs(n) = climbStairs(n-1) + climbStairs(n-2)`
2. 用数组/Map 缓存已计算的结果，避免重复计算

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(n)\)

### 解法三：矩阵快速幂 / 通项公式（加分项）

斐波那契可以用矩阵快速幂优化到 \(O(\log n)\)，或直接用通项公式 \(O(1)\)。n ≤ 45 时不需要，但提一句展示数学功底。

```java
class Solution {
    public int climbStairs(int n) {
        // ✅ 基准条件方向对，但 n==3 多余
        if (n == 1) {
            return 1;
        }
        if (n == 2) {
            return 2;
        }
        if (n == 3) {          // ❌ 冗余，递归公式已覆盖
            return 3;
        }
        // ❌ 递归无记忆化，O(2^n)，n=45 必然超时
        return climbStairs(n - 1) + climbStairs(n - 2);
    }
}
```

### 解法一：迭代 DP（滚动变量）

```java
public int climbStairs(int n) {
    if (n == 1 || n == 2) {
        return n;
    }
    int prev2 = 1, prev1 = 2;
    for (int i = 3; i <= n; i++) {
        int curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
```

### 解法二：递归 + 记忆化

```java
public int climbStairs(int n) {
    int[] memo = new int[n + 1];
    return helper(n, memo);
}

private int helper(int n, int[] memo) {
    if (n == 1 || n == 2) return n;
    if (memo[n] != 0) return memo[n];
    memo[n] = helper(n - 1, memo) + helper(n - 2, memo);
    return memo[n];
}
```

### 解法三：矩阵快速幂（加分项）

```java
public int climbStairs(int n) {
    if (n == 1 || n == 2) return n;
    int[][] base = {{1, 1}, {1, 0}};
    int[][] result = matrixPow(base, n - 2);
    return 2 * result[0][0] + result[0][1];
}

private int[][] matrixPow(int[][] m, int p) {
    int[][] result = {{1, 0}, {0, 1}};
    while (p > 0) {
        if ((p & 1) == 1) result = multiply(result, m);
        m = multiply(m, m);
        p >>= 1;
    }
    return result;
}

private int[][] multiply(int[][] a, int[][] b) {
    return new int[][]{
        {a[0][0] * b[0][0] + a[0][1] * b[1][0], a[0][0] * b[0][1] + a[0][1] * b[1][1]},
        {a[1][0] * b[0][0] + a[1][1] * b[1][0], a[1][0] * b[0][1] + a[1][1] * b[1][1]}
    };
}
```

## 个人总结

### 1. 递归思路对，但必须加记忆化

递归公式 `climbStairs(n) = climbStairs(n-1) + climbStairs(n-2)` 本身没错，但纯递归会产生大量重复计算：

```
climbStairs(5)
├── climbStairs(4)
│   ├── climbStairs(3)
│   │   ├── climbStairs(2)
│   │   └── climbStairs(1)
│   └── climbStairs(2)    ← 又算一遍
└── climbStairs(3)         ← 又算一遍
```

n=45 时递归树爆炸，每个节点分裂两个子节点，调用次数 ≈ 2⁴⁵，必然超时。解法：加数组缓存（记忆化）或直接用迭代。

### 2. 多余的 base case 没必要

```java
// ❌ n == 3 是冗余的
if (n == 3) return 3;

// ✅ dp[1]=1, dp[2]=2 就够了，n=3 时递归自己算得出来
dp[3] = climbStairs(2) + climbStairs(1) = 2 + 1 = 3
```

多写 n==3 不会让程序变快，反而说明没有真正理解递推的完备性——只要 base case 覆盖了最小子问题，递推公式会自动处理后续所有 n。

### 3. 递归 → 迭代是 DP 题的常见优化方向

斐波那契/爬楼梯是 DP 入门题，核心思想：**用迭代 + 滚动变量替代递归**，把空间从 O(n) 压到 O(1)。
