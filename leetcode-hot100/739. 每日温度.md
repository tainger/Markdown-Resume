## 题目描述

给定一个整数数组 `temperatures` ，表示每天的温度，返回一个数组 `answer` ，其中 `answer[i]` 是指对于第 `i` 天，下一个更高温度出现在几天后。如果气温在这之后都不会升高，请在该位置用 `0` 来代替。

---

## 示例

**示例 1**

```
输入: temperatures = [73,74,75,71,69,72,76,73]
输出: [1,1,4,2,1,1,0,0]
```

**示例 2**

```
输入: temperatures = [30,40,50,60]
输出: [1,1,1,0]
```

**示例 3**

```
输入: temperatures = [30,60,90]
输出: [1,1,0]
```

---

## 提示

- `1 <= temperatures.length <= 10^5`
- `30 <= temperatures[i] <= 100`

---

## 思路

### 核心思想

**单调栈**：栈中维护「还没找到下一个更暖天的下标」，按温度从栈底到栈顶保持**单调递减**。遇到更暖的一天时，弹栈并结算距离。

### 解法一：单调栈（推荐）

1. 维护一个栈，存放**下标**；栈内下标对应的温度从栈底到栈顶**单调递减**
2. 遍历数组，对每个 `i`：
   - 当栈非空且 `temperatures[i] > temperatures[栈顶]`：弹栈得到 `prev`，`answer[prev] = i - prev`
   - 重复弹栈直到栈顶温度 ≥ 当前温度（或栈空）
   - 把 `i` 入栈
3. 栈中剩余下标说明后面没有更暖天，默认 0，无需额外处理
- 时间复杂度：\(O(n)\)，每个下标最多入/出栈各一次
- 空间复杂度：\(O(n)\)，最坏栈深 n（如严格递减序列）

### 解法二：逆序 + 跳跃指针

1. 从右向左遍历，对每个 `i`，令 `j = i + 1`
2. 若 `temperatures[j] > temperatures[i]`：`answer[i] = j - i`，结束
3. 否则借助已计算的 `answer[j]` 直接把 `j` 跳到「j 的下一个更暖天」位置继续比较；若 `answer[j] == 0` 说明 j 后面没有更暖天，i 必然也没有
- 时间复杂度：均摊 \(O(n)\)，每次跳跃都让 `j` 指向更靠后的位置
- 空间复杂度：\(O(1)\) 额外空间（不计输出数组）

## 代码

### 我的伪代码

> 👇 初次尝试的暴力版本（保留用于复盘），具体问题见下方 [个人总结](#个人总结)。

```java
// ❌ 时间复杂度 O(n²)，n=10^5 时约 10^10 次比较，会 TLE
// ❌ 内层循环对每个 i 都从 i+1 重新扫描，没有利用已计算过的信息
public int[] dailyTemperatures(int[] temperatures) {
    int length = temperatures.length;
    int[] answer = new int[length];
    for (int i = 0; i < temperatures.length; i++) {
        for (int j = i + 1; j < temperatures.length; j++) {
            if (temperatures[j] > temperatures[i]) {
                answer[i] = j - i;
                break;                              // 找到第一个更暖天就停，正确
            }
        }
    }
    return answer;
}
```

### 解法一：单调栈（推荐）

```java
public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] answer = new int[n];                       // 默认 0，剩余下标天然为 0
    Deque<Integer> stack = new ArrayDeque<>();        // 存下标，不存温度
    for (int i = 0; i < n; i++) {
        // 严格大于才弹栈（相等不算更暖）
        while (!stack.isEmpty() && temperatures[i] > temperatures[stack.peek()]) {
            int prev = stack.pop();
            answer[prev] = i - prev;
        }
        stack.push(i);
    }
    return answer;
}
```

### 解法二：逆序 + 跳跃优化（常数优化）

```java
public int[] dailyTemperatures(int[] temperatures) {
    int n = temperatures.length;
    int[] answer = new int[n];
    for (int i = n - 2; i >= 0; i--) {
        int j = i + 1;
        while (j < n) {
            if (temperatures[j] > temperatures[i]) {
                answer[i] = j - i;
                break;
            }
            // 借助已计算的 answer[j] 直接跳到下一个候选位置
            if (answer[j] == 0) break;               // j 后面没有更暖天，i 也别找了
            j += answer[j];
        }
    }
    return answer;
}
```

> 时间复杂度均摊 \(O(n)\)，空间 \(O(1)\) 额外（不计输出数组）。

## 个人总结

### 1. 暴力解法为什么超时

| 维度 | 数据 | 说明 |
|:---|:---|:---|
| n | \(10^5\) | 题目上限 |
| 操作数 | \(\approx n^2/2 \approx 5 \times 10^9\) | 双重循环最坏情况 |
| Java 1s 内可执行 | \(\approx 10^8\) | 远超时限 |

暴力解法本身**逻辑正确**（`break` 用得对、`>` 关系也对），瓶颈纯粹是复杂度——这道题的分水岭就是「能不能想到 O(n)」。

### 2. 暴力的浪费在哪：重复扫描

对每个 `i` 都从 `i+1` 开始重新扫描，但实际上：
- 当 `i` 找到 `j` 是更暖天时，意味着 `i` 和 `j` 之间的那些位置温度都 ≤ `temperatures[i]`
- 这些信息可以被后续 `i'`（介于 i 和 j 之间）的搜索复用

**单调栈**就是把这个观察形式化：让"还没找到更暖天"的下标留在栈里，遇到更暖的就批量结算。
**跳跃指针**则更直接：让 `j` 不要一格一格走，而是借助 `answer[j]` 直接跳到下一个候选。

### 3. 单调栈的三个易错点

| 点 | 正确写法 | 反面 |
|:---|:---|:---|
| 栈存什么 | **下标** | 存温度值就没办法算 `i - prev` |
| 弹栈用 | `while` | `if` 只弹一次，漏掉栈里同样待结算的下标 |
| 比较符 | `temperatures[i] > temperatures[stack.peek()]` | `>=` 会让相等温度也结算（题目要"更高"） |

举例 `[73,74,75]`：到 75 时栈里有 `[0(73),1(74)]`，必须 `while` 弹两次；用 `if` 只弹一次，74 永远等不到答案。

### 4. 跳跃指针的妙处

跳跃指针本质上把 `answer[]` 当成一个**隐式跳表**：

```
j → j + answer[j] → j' + answer[j'] → ...
```

每次跳跃都让 `j` 严格向右推进到「下一个比 `temperatures[j]` 更大的位置」，所以总跳跃次数有上限，均摊 \(O(n)\)。它不需要栈，空间更省，是单调栈的等价变形。

### 5. 剩余下标为什么不用单独处理

Java 中 `new int[n]` 默认初始化为 0：

- 单调栈结束时，栈里剩下的下标对应的 `answer` 值本来就是 0，正好符合「后面没有更暖天填 0」的题意
- 跳跃指针中 `answer[j] == 0` 自然成为"j 后无更暖天"的哨兵条件

无需额外循环填 0。

### 6. 用 `ArrayDeque` 而非 `Stack`

| 类型 | 推荐 | 原因 |
|:---|:---|:---|
| `java.util.Stack` | ❌ | 继承 Vector，方法都加 synchronized，性能差 |
| `ArrayDeque` | ✅ | 基于数组实现，无同步开销，是 Java 6+ 的栈首选 |

注意 `ArrayDeque` 不允许 `null` 元素（栈为空时 `peek()` 返回 `null`，配合 `isEmpty()` 判空即可）。
