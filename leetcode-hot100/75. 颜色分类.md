## 题目描述

给定一个包含红色、白色和蓝色、共 `n` 个元素的数组 `nums` ，**原地** 对它们进行排序，使得相同颜色的元素相邻，并按照红色、白色、蓝色顺序排列。

我们使用整数 `0`、 `1` 和 `2` 分别表示红色、白色和蓝色。

必须在不使用库内置的 sort 函数的情况下解决这个问题。

---

## 示例

**示例 1**

```
输入：nums = [2,0,2,1,1,0]
输出：[0,0,1,1,2,2]
```

**示例 2**

```
输入：nums = [2,0,1]
输出：[0,1,2]
```

## 思路

### 核心思想

数组只有 `0/1/2` 三种值，要把它们按序分成三段。最直白是**计数排序**（数三种数各多少，再重写），但要扫两趟。进阶要求**一趟 + 原地**——用**三指针（荷兰国旗问题，Dutch National Flag）**：两个指针 `p0`、`p2` 分别守住「已放好的 0 区右边界」和「已放好的 2 区左边界」，`cur` 从左到右扫，边扫边把 0 换到左、2 换到右，中间自然剩下 1。

### 解法一：计数排序（两趟，先跑通）

第一趟数出 0、1、2 各有几个；第二趟按数量依次填回 0、1、2。

- 时间复杂度：\(O(n)\)（两趟），空间 \(O(1)\)。简单可靠，但不满足「一趟」的进阶要求。

### 解法二：荷兰国旗 / 三指针（推荐，一趟原地）

维护三个指针，把数组划分成四个区间：

```
[0, p0)      → 已确定的 0
[p0, cur)    → 已确定的 1
[cur, p2]    → 待处理（未知）
(p2, n-1]    → 已确定的 2
```

`cur` 从 `0` 扫到 `p2`，根据 `nums[cur]`：

- **== 0**：与 `nums[p0]` 交换，`p0++`、`cur++`（换来的必是 1 或已处理过，可放心前进）；
- **== 1**：`cur++`（1 归位在中间，不动）；
- **== 2**：与 `nums[p2]` 交换，`p2--`，**`cur` 不动**（换过来的值还没检查，需下一轮再判）。

```
nums=[2,0,2,1,1,0]，p0=0,cur=0,p2=5
cur=0:2 → 换nums[5]:[0,0,2,1,1,2] p2=4, cur不动
cur=0:0 → 换nums[0]:[0,0,2,1,1,2] p0=1,cur=1
cur=1:0 → 换nums[1]:[0,0,2,1,1,2] p0=2,cur=2
cur=2:2 → 换nums[4]:[0,0,1,1,2,2] p2=3, cur不动
cur=2:1 → cur=3
cur=3:1 → cur=4，此时 cur>p2 结束
→ [0,0,1,1,2,2] ✅
```

- 时间复杂度：\(O(n)\)（一趟），空间 \(O(1)\)（最优，满足进阶）。

## 代码

### 解法一：计数排序（两趟）

```java
class Solution {
    public void sortColors(int[] nums) {
        int[] count = new int[3];              // count[0/1/2]
        for (int x : nums) count[x]++;         // 第一趟：计数
        int idx = 0;
        for (int c = 0; c < 3; c++) {          // 第二趟：按数量重写
            while (count[c]-- > 0) {
                nums[idx++] = c;
            }
        }
    }
}
```

### 解法二：荷兰国旗三指针（推荐，一趟原地）

```java
class Solution {
    public void sortColors(int[] nums) {
        int p0 = 0, cur = 0, p2 = nums.length - 1;
        while (cur <= p2) {                     // 注意是 <= p2
            if (nums[cur] == 0) {
                swap(nums, p0, cur);
                p0++;
                cur++;                          // 换来的是已处理的 1，安全前进
            } else if (nums[cur] == 2) {
                swap(nums, p2, cur);
                p2--;
                // cur 不前进！换来的值还没检查
            } else {                            // == 1
                cur++;
            }
        }
    }

    private void swap(int[] nums, int a, int b) {
        int t = nums[a]; nums[a] = nums[b]; nums[b] = t;
    }
}
```

## 个人总结

### 1. 只有 3 个值 → 想到计数排序或三指针

「值域极小（只有 0/1/2）」是强信号：要么计数排序（两趟），要么荷兰国旗三指针（一趟）。看到有限枚举值排序，先往这两个方向想。

### 2. 荷兰国旗的最大坑：换到 2 时 cur 不能前进

- **换 0 时 cur++**：因为 `p0 <= cur`，`p0` 位置的值一定是已经扫描过、确定为 1 的（或就是 cur 自己），换过来后无需再看，cur 可前进。
- **换 2 时 cur 不动**：`p2` 位置的值是**从未检查过**的（在待处理区右端），换过来后可能是 0/1/2，必须留在原地下一轮重新判断。**这一条最容易写错——换 2 后手滑写了 cur++ 就会漏判。**

### 3. 循环条件是 cur <= p2，不是 cur < n

`cur` 越过 `p2` 就说明待处理区空了，右边全是 2、已排好。写成 `cur < n` 会在 cur 追上 p2 后继续和已排好的 2 区做无效交换甚至出错。**边界 `<=` 要牢记。**

### 4. 区间定义要清晰

四个区间 `[0,p0)` 全 0、`[p0,cur)` 全 1、`[cur,p2]` 未知、`(p2,n-1]` 全 2。想清每个指针的含义，交换和移动逻辑自然就对了。这是"循环不变量"式思维，是双指针题的核心。

### 5. 两种解法取舍

| 解法 | 趟数 | 时间 | 空间 | 定位 |
|:---|:---:|:---:|:---:|:---|
| 计数排序 | 两趟 | \(O(n)\) | \(O(1)\) | 简单可靠，不满足「一趟」 |
| 荷兰国旗 | 一趟 | \(O(n)\) | \(O(1)\) ✅ | 满足进阶，最优 |

**面试建议**：先说计数排序（表明会做），再点出它要两趟，最后给荷兰国旗三指针并**重点强调「换 2 时 cur 不动」**——这是本题最出彩、最易错的地方。
