## 题目描述

给你一个字符串 `s` 。我们要把这个字符串划分为尽可能多的片段，同一字母最多出现在一个片段中。例如，字符串 `"ababcc"` 能够被分为 `["abab", "cc"]`，但类似 `["aba", "bcc"]` 或 `["ab", "ab", "cc"]` 的划分是非法的。

注意，划分结果需要满足：将所有划分结果按顺序连接，得到的字符串仍然是 `s` 。

返回一个表示每个字符串片段的长度的列表。

## 示例

**示例 1**

```
输入：s = "ababcbacadefegdehijhklij"
输出：[9,7,8]
解释：
划分结果为 "ababcbaca"、"defegde"、"hijhklij" 。
每个字母最多出现在一个片段中。
像 "ababcbacadefegde", "hijhklij" 的划分是错误的，因为划分的片段数较少。
```

**示例 2**

```
输入：s = "eccbbbbdec"
输出：[10]
```

## 提示

- `1 <= s.length <= 100`
- `s` 仅由小写英文字母组成

## 思路

### 核心思想

每个字母的「最后一次出现位置」决定了它的**活动范围**：一个片段一旦包含字母 `c`，就必须延伸到 `end[c]`，否则 `c` 会出现在两个片段里。于是贪心如下——

维护当前片段的右边界 `cut`，遍历时不断把边界推远：

```
cut = max(cut, end[s.charAt(i)])
```

当 `i` 走到 `cut` 时，说明 `[start, cut]` 内出现的每个字母都已在区间内被「覆盖完」，可以**切一刀**。能切就切（切点越靠左，后续可切的段越多），保证片段数最多。

```
s = "ababcbacadefegdehijhklij"
     a 的 end=8，b 的 end=6，c 的 end=8 → cut 一路推到 8 → 第 1 段 [0,8] 长 9
     d/e/g 的 end 都 ≤ 14 → cut=14 → 第 2 段 长 7
     h..j 的 end ≤ 22 → cut=22 → 第 3 段 长 8
输出 [9,7,8] ✅
```

### 解法一：贪心 + 最后出现位置（推荐）

1. 第一遍扫描，记 `end[c]` = 字母 `c` 最后出现的下标
2. 第二遍扫描：`cut = max(cut, end[当前字母])`；`i == cut` 时结算片段长度 `i - start + 1`，`start = i + 1`

- 时间复杂度：\(O(n)\)，空间复杂度：\(O(1)\)（26 长度数组）

### 解法二：区间合并视角（换个建模）

把每个字母看成一个区间 `[first, last]`；「同一字母不出现在两个片段」 ⇔ 片段切分点不能落在任何区间内部 ⇔ **对 26 个区间做合并**，每个合并后的大区间就是一个片段。

- 时间复杂度：\(O(n + |\Sigma|\log|\Sigma|)\)（`|Σ| = 26`，排序可忽略），空间复杂度：\(O(1)\)

## 代码

### 解法一：贪心 + 最后出现位置（推荐）

```java
class Solution {
    public List<Integer> partitionLabels(String s) {
        int[] end = new int[26];                        // 每个字母最后出现的下标
        for (int i = 0; i < s.length(); i++) {
            end[s.charAt(i) - 'a'] = i;                 // 不断覆盖，扫完即是最后位置
        }

        List<Integer> res = new ArrayList<>();
        int start = 0, cut = 0;                         // 当前片段的起、止
        for (int i = 0; i < s.length(); i++) {
            // 当前字母的活动范围可能把片段右边界往右推
            cut = Math.max(cut, end[s.charAt(i) - 'a']);
            if (i == cut) {                             // 走到边界：片段内字母已全部覆盖
                res.add(i - start + 1);
                start = i + 1;                          // 开启新片段
            }
        }
        return res;
    }
}
```

### 解法二：区间合并视角

```java
class Solution {
    public List<Integer> partitionLabels(String s) {
        int[] first = new int[26], last = new int[26];
        Arrays.fill(first, -1);
        for (int i = 0; i < s.length(); i++) {          // 每个字母的区间 [first, last]
            int c = s.charAt(i) - 'a';
            if (first[c] == -1) first[c] = i;
            last[c] = i;
        }

        List<int[]> intervals = new ArrayList<>();
        for (int c = 0; c < 26; c++) {
            if (first[c] != -1) intervals.add(new int[]{first[c], last[c]});
        }
        intervals.sort((a, b) -> a[0] - b[0]);          // 按起点排序

        List<Integer> res = new ArrayList<>();
        int start = intervals.get(0)[0], endVal = intervals.get(0)[1];
        for (int[] it : intervals) {
            if (it[0] > endVal) {                       // 与当前区间无交集 → 结算一个片段
                res.add(endVal - start + 1);
                start = it[0];
            }
            endVal = Math.max(endVal, it[1]);           // 有交集 → 合并，延长右端
        }
        res.add(endVal - start + 1);                    // 最后一个合并区间别漏
        return res;
    }
}
```

## 个人总结

### 1. `cut = max(cut, end[c])`：贪心的「边界扩张 + 到界结算」

正确性两句话：**片段合法性** = 片段内任一字母的最后出现位置不越过片段右边界（否则跨段）；**最多片段数** = 每到边界就立刻切（交换论证：任何合法划分的第一个切点不会比贪心的切点更靠左）。这是「贪心维护可达/必须覆盖的边界，走到边界就结算」的标准形态，与 [55. 跳跃游戏](55.%20跳跃游戏.md) 的 `maxReach` 一一对应：

| | 55. 跳跃游戏 | 763（本题） |
|:---|:---|:---|
| 边界含义 | 能跳到的最远下标 | 必须覆盖到的最远下标 |
| 扩张 | `max(maxReach, i + nums[i])` | `max(cut, end[c])` |
| 到边界时 | 结束（能到 / 卡死） | 结算一段，开启新段 |

### 2. 区间建模是同一问题的另一个视角

把「字母最后出现位置」翻译成「字母的存活区间 [first, last]」，问题立刻变成区间合并（56. 合并区间 的应用）：切分点不能落在任何区间内部 ⟺ 合并后的区间边界就是切分点。一题两解展示的是**建模迁移能力**——同一个约束，贪心扫描和区间合并都能解，面试时点出这种等价性很加分。

### 3. 两次扫描是字符串题的常用节奏

第一遍收集全局信息（last/first/计数），第二遍利用信息做决策。同款：438. 找到字符串中所有字母异位词（先统计 p 的字符计数再滑窗）、917 仅仅反转字母。先扫一遍 `end[]` 让第二遍的判断变成 O(1) 查表，避免边扫边回溯。

### 4. 复杂度与实现细节

解法一不需要排序，严格 \(O(n)\)，是首选实现；解法二多一层排序（但 |Σ|=26 是常数）。「结算时 `res.add(i - start + 1)`、`start = i + 1`」这两个下标更新是最容易写错的细节；循环外的 `res.add(endVal - start + 1)`（解法二最后一段）也别漏。示例 2 `"eccbbbbdec"` 全串因为 `e` 首尾夹住 `bbbb`，10 个字符只能切成 1 段——是验证理解的好例子。
