# Redis 数据类型与底层结构面试题

Redis 是一个基于内存的 K-V 数据库，"快"是它的核心标签。而快的根本原因之一，就是**上层数据类型**和**底层数据结构**做了精细的分离与优化：同一个数据类型（如 List、Hash、ZSet），Redis 会根据数据量大小自动切换不同的底层实现，在**省内存**和**高性能**之间做权衡。

---

## 一、Redis 为什么快？

| 原因 | 说明 |
|:---|:---|
| **纯内存操作** | 数据在内存中，读写不走磁盘 |
| **单线程 + IO 多路复用** | 命令执行单线程，避免锁竞争和上下文切换；网络 IO 用 epoll 处理海量连接 |
| **高效的数据结构** | SDS、跳表、压缩列表等针对场景专门优化 |
| **Reactor 网络模型** | 基于事件驱动，一个线程处理成千上万连接 |

> **单线程为什么还快？** 因为瓶颈不在 CPU 而在内存和网络。单线程省掉了锁和上下文切换的开销，配合 IO 多路复用，性能足够。
> 注意：Redis 6.0 后引入**多线程处理网络 IO**（读写 socket、协议解析），但**命令执行仍是单线程**。

---

## 二、5 种基本数据类型

| 类型 | 底层结构（可切换） | 典型应用场景 |
|:---|:---|:---|
| **String** | int / embstr / raw（SDS） | 缓存对象、计数器、分布式锁、限流 |
| **List** | quicklist（3.2 后）| 消息队列、最新列表、栈/队列 |
| **Hash** | listpack / hashtable | 存储对象（购物车、用户信息） |
| **Set** | intset / listpack / hashtable | 去重、抽奖、共同好友（交并差集） |
| **ZSet** | listpack / skiplist + hashtable | 排行榜、延迟队列、范围查询 |

---

## 三、String

### 底层：SDS（Simple Dynamic String 简单动态字符串）

Redis 没有直接用 C 语言的 `char[]`，而是自己封装了 SDS：

```
struct sdshdr {
    int len;      // 已使用长度   → O(1) 获取长度
    int free;     // 剩余空间     → 空间预分配、惰性释放
    char buf[];   // 字节数组     → 遵循 C 字符串以 \0 结尾（兼容部分 C 函数）
}
```

**SDS 相比 C 字符串的优势：**

| 维度 | C 字符串 | SDS |
|:---|:---|:---|
| 获取长度 | O(n) 遍历到 `\0` | O(1) 直接读 `len` |
| 缓冲区溢出 | 拼接时可能溢出 | 拼接前检查 `free`，不够就扩容 |
| 内存重分配 | 每次增减都要 realloc | **空间预分配 + 惰性释放**，减少次数 |
| 二进制安全 | 以 `\0` 判断结尾，不能存二进制 | 用 `len` 判断，可存图片/序列化对象 |

**int / embstr / raw 三种编码：**

| 编码 | 触发条件 | 特点 |
|:---|:---|:---|
| **int** | 值是整数且能用 long 表示 | 直接存整数 |
| **embstr** | 字符串 ≤ 44 字节 | 一次内存分配，redisObject 和 SDS 连续存放 |
| **raw** | 字符串 > 44 字节 | 两次内存分配，分开存放 |

## 四、List

**3.2 版本后统一用 quicklist（快速列表）。**

- 早期是 ziplist（元素少时）+ linkedlist（元素多时）双实现。
- **quicklist = 双向链表 + 压缩列表**：链表的每个节点是一个 ziplist/listpack，既有链表的两端操作快，又用压缩列表省内存、避免过多的链表指针开销。

```
quicklist:  [node1] <-> [node2] <-> [node3]
              ↓          ↓          ↓
           listpack   listpack   listpack   (每个节点内是紧凑数组)
```

> **应用：消息队列**。`lpush` + `brpop`（阻塞弹出）可以实现简单的生产者-消费者队列。

## 五、Hash

| 编码 | 触发条件（默认） | 说明 |
|:---|:---|:---|
| **listpack**（7.0 前是 ziplist） | 字段数 ≤ 128 且每个值 ≤ 64 字节 | 紧凑数组，省内存 |
| **hashtable** | 超过上述阈值 | 标准哈希表，O(1) 读写 |

```
# 配置阈值
hash-max-listpack-entries 128
hash-max-listpack-value   64
```

> **Hash vs String 存对象**：Hash 可以单独修改某个字段，更省内存；String（存 JSON）要整体读写。字段多、需要局部更新时用 Hash。

---

## 六、Set

| 编码 | 触发条件 | 说明 |
|:---|:---|:---|
| **intset** | 元素**全是整数**且数量 ≤ 512 | 有序整数数组，省内存 |
| **listpack**（7.2 后） | 元素少且不全是整数 | 紧凑列表 |
| **hashtable** | 超过阈值 | 值存 key，value 为 null |

> **应用**：抽奖（`spop` 随机弹出）、共同好友（`sinter` 交集）、UV 去重统计。

---

## 七、ZSet（有序集合，重点）

**底层是 `跳表(skiplist) + 哈希表(hashtable)` 组合**（元素少时是 listpack）。

| 编码 | 触发条件（默认） |
|:---|:---|
| **listpack**（7.0 前是 ziplist） | 元素 ≤ 128 且每个 ≤ 64 字节 |
| **skiplist + hashtable** | 超过阈值 |

**为什么用跳表 + 哈希表两个结构？**

| 结构 | 作用 | 支持的操作 |
|:---|:---|:---|
| **哈希表** | member → score 的映射 | `zscore` 查分数 O(1) |
| **跳表** | 按 score 有序排列 | 范围查询 `zrange`、排名 `zrank` O(log n) |

### 跳表（Skip List）

跳表是一种**多层有序链表**，通过在上层建"索引"来加速查找，用空间换时间，把链表的查找从 O(n) 优化到 **O(log n)**。

```
第3层  1 --------------------> 9
第2层  1 --------> 5 --------> 9
第1层  1 -> 3 -> 5 -> 7 -> 9      (原始链表)
```

**为什么 ZSet 用跳表而不用红黑树/B+树？**

| 对比 | 说明 |
|:---|:---|
| **vs 红黑树** | 跳表实现更简单；**范围查询更方便**（找到起点后沿底层链表顺序遍历即可，红黑树要中序遍历） |
| **vs B+ 树** | B+ 树为磁盘设计（减少 I/O），Redis 是纯内存，不需要；跳表更轻量 |
| **并发友好** | 跳表插入删除只需局部调整指针，红黑树旋转影响范围大 |

> **应用**：排行榜（`zadd` 加分、`zrevrange` 取 Top N）、延迟队列（score 存执行时间戳）。

## 八、3 种特殊数据类型（了解）

| 类型 | 底层 | 用途 |
|:---|:---|:---|
| **Bitmap** | String（位操作） | 签到统计、活跃用户（`setbit`/`bitcount`），1 亿用户仅需 12MB |
| **HyperLogLog** | String | 海量 UV 基数统计，12KB 固定内存，有约 0.81% 误差 |
| **GEO** | ZSet | 附近的人、距离计算（底层用 GeoHash 编码为 score） |

## 九、易错点

| 易错点 | 说明 |
|:---|:---|
| **以为 Redis 完全单线程** | 6.0 后网络 IO 是多线程，只有命令执行是单线程 |
| **String 编码阈值记错** | embstr/raw 分界是 **44 字节** |
| **ziplist / listpack 混淆** | 7.0 后 ziplist 被 listpack 取代（解决连锁更新问题） |
| **ZSet 只想到跳表** | 还有哈希表配合，`zscore` 才能 O(1) |
| **List 还以为是 linkedlist** | 3.2 后是 quicklist |
| **大 key 问题** | 单个 Hash/ZSet 元素过多，会拖慢操作、阻塞主线程 |

---

## 十、一句话总结

Redis 快的核心是**纯内存 + 单线程命令执行 + IO 多路复用 + 高效数据结构**。5 种类型（String/List/Hash/Set/ZSet）都会根据数据量在**紧凑结构**（listpack/intset）和**标准结构**（hashtable/skiplist）间切换：小数据省内存，大数据保性能。String 用 **SDS** 解决 C 字符串的痛点；ZSet 用 **跳表 + 哈希表** 兼顾范围查询和 O(1) 查分。
