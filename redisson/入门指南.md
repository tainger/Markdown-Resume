## 一、30 秒搞清楚 Redisson 是什么

Redisson = **基于 Netty NIO 的 Redis Java 高级客户端**。别再手写 JedisPool + `SET NX + Lua` 分布式锁了，Redisson 帮你封装好 40+ 种分布式工具（锁/Map/队列/限流…），**API 和 JUC 本地并发工具几乎一样**，上手零门槛。

```
本地 JUC 工具：        ReentrantLock   ConcurrentHashMap   Semaphore   BlockingQueue   CountDownLatch
                          ↓ 同名接口前加 R 即可 ↓
Redisson 分布式版：      RLock              RMap          RSemaphore  RBlockingQueue  RCountDownLatch
```

**一句话决定：你的项目要不要上 Redisson？**
- 你需要**分布式锁/延迟队列/限流器** → 必须上（手写要 100 行，Redisson 3 行搞定）
- 你只做简单 `get/set` 缓存，Spring Cache 都不用写 → 可以用 Lettuce / RedisTemplate 就行
- 90% 企业级项目都会推荐用 Redisson

## 二、Step 1：加依赖（Maven / Gradle）

### ⚠️ 先看 Spring Boot 版本，别引错！

Redisson Starter 版本**严格和 Spring Boot 大版本对应**：

| Spring Boot | JDK | Redisson Starter 依赖 |
|:---|:---|:---|
| **3.x** (Spring Boot 3) | JDK 17+ | `org.redisson:redisson-spring-boot-starter:3.25.x` |
| **2.x** (Spring Boot 2.6/2.7) | JDK 8 / 11 | `org.redisson:redisson-spring-boot-starter:3.25.x` |

**Maven `pom.xml`：**
```xml
<!-- Spring Boot 3.x 项目：直接加这一个依赖即可，自动装配 RedissonClient -->
<dependency>
    <groupId>org.redisson</groupId>
    <artifactId>redisson-spring-boot-starter</artifactId>
    <version>3.25.0</version>
</dependency>
```

> **Spring Boot 2.x** 项目一样的坐标，还是 `3.25.x`，Starter 内部会自动适配 2.x 的 Spring Data Redis 版本，不用管。

**Gradle：**
```groovy
implementation 'org.redisson:redisson-spring-boot-starter:3.25.0'
```

## 三、Step 2：写配置（3 种常用模式直接抄）

### 方式 A：最简单（单节点本地测试）

Spring Boot 2/3 都能用，直接用 `spring.redis:` 前缀，**一行 Redisson 配置都不用写**，Starter 会自动装配：

```yaml
spring:
  redis:
    host: 127.0.0.1
    port: 6379
    password:              # 没密码留空或不写
    database: 0            # 默认 DB 0
    timeout: 3s
```

> ✅ 适合本地测试。但生产需要**哨兵/集群/序列化/连接池**高级配置，就用下面的方式 B。

### 方式 B：⭐ 推荐生产（独立 YAML + 引用）

`application.yml` 里只做一行引用，然后把 Redisson 专属配置写在 `resources/redisson-config.yml`：

```yaml
# ========== application.yml ==========
spring:
  redis:
    redisson:
      config: classpath:redisson-config.yml   # 引用类路径下的独立配置
```

#### 🔹 模式 1：Redis 单节点（生产单实例）
```yaml
# ========== resources/redisson-config.yml ==========
singleServerConfig:
  address: "redis://127.0.0.1:6379"
  password: "你的密码"
  database: 0
  connectionPoolSize: 64               # 连接池上限
  connectionMinimumIdleSize: 24        # 空闲连接数（冷启动不临时建连接）
  connectTimeout: 10000                # 建连 10s 超时
  timeout: 1500                        # 命令 1.5s 超时

# === 全局配置 ===
threads: 16                            # Netty 线程，默认 CPU*2
nettyThreads: 16
# ⚠️ 生产必切 Kryo5（比默认 JDK 体积小 10 倍、速度快 10+ 倍）
codec: !<org.redisson.codec.Kryo5Codec> {}
```

#### 🔹 模式 2：⭐ 哨兵模式（生产高可用，3 哨兵 + 1 主 N 从）
```yaml
sentinelServersConfig:
  masterName: "mymaster"                     # 必须 = sentinel.conf 里配置的主节点名
  sentinelAddresses:
    - "redis://sentinel1:26379"
    - "redis://sentinel2:26379"
    - "redis://sentinel3:26379"
  password: "redis服务端密码"                 # Redis 本身密码，不是 sentinel 密码
  database: 0
  masterConnectionMinimumIdleSize: 24
  slaveConnectionMinimumIdleSize: 24
  readMode: "SLAVE"                          # 读走从库（读写分离）
  subscriptionMode: "SLAVE"                   # Pub/Sub 走从库

threads: 16
codec: !<org.redisson.codec.Kryo5Codec> {}
```

#### 🔹 模式 3：Cluster 集群（≥3 主 3 从，数据分片）
```yaml
clusterServersConfig:
  nodeAddresses:
    - "redis://node1:6379"
    - "redis://node2:6379"
    - "redis://node3:6379"
    - "redis://node4:6379"
    - "redis://node5:6379"
    - "redis://node6:6379"
  password: "redis密码"
  scanInterval: 2000                         # 2s 扫描一次集群拓扑（自动感知槽位迁移）
  masterConnectionMinimumIdleSize: 32
  slaveConnectionMinimumIdleSize: 32
  readMode: "SLAVE"

threads: 16
codec: !<org.redisson.codec.Kryo5Codec> {}
```

## 四、Step 3：Hello World（直接抄）

### 4.1 纯 Java 主函数（无 Spring）

```java
import org.redisson.Redisson;
import org.redisson.api.RLock;
import org.redisson.api.RedissonClient;
import org.redisson.config.Config;

public class RedissonHello {
    public static void main(String[] args) {
        // 1. 构造配置（最简单 3 行）
        Config config = new Config();
        config.useSingleServer().setAddress("redis://127.0.0.1:6379");

        // 2. 拿到 RedissonClient——全局一个实例就行（重量级，别每次 new）
        RedissonClient redisson = Redisson.create(config);

        // 3. 分布式 Map：和 HashMap 一样 put/get
        redisson.getMap("demo:map").put("hello", "Redisson");
        System.out.println("Map 读：" + redisson.getMap("demo:map").get("hello"));
        // 输出：Map 读：Redisson

        // 4. 分布式可重入锁：和 ReentrantLock 一样 lock()/unlock()
        RLock lock = redisson.getLock("demo:lock");
        lock.lock();                         // ⭐ 不开 leaseTime → 自动启看门狗（10s续到30s）
        try {
            System.out.println("拿到锁，执行业务…");
            Thread.sleep(1000);
        } finally {
            lock.unlock();                   // ⚠️ finally 必写！
        }

        // 5. 关闭（Spring 容器销毁自动调，这里手动关）
        redisson.shutdown();
    }
}
```

### 4.2 Spring Boot 项目（@Autowired 直接用）

加完依赖和 application.yml 配置后，**什么额外代码都不用写**，直接注入：

```java
@RestController
@RequestMapping("/demo")
public class RedissonDemoController {

    // ✅ Starter 自动装配，直接 @Autowired 注入
    @Autowired
    private RedissonClient redisson;

    /**
     * 演示 1：分布式互斥锁
     * 浏览器多窗口同时开 5 个快速请求 http://localhost:8080/demo/lock/1001
     * 你会看到 5 个线程是串行执行的（一个一个拿锁，排队）
     */
    @GetMapping("/lock/{skuId}")
    public String lockDemo(@PathVariable String skuId) throws Exception {
        long start = System.currentTimeMillis();
        RLock lock = redisson.getLock("demo:stock:" + skuId);
        // ⭐ 生产必写 tryLock(wait, lease, unit)，不要 lock() 无限等！
        boolean got = lock.tryLock(5, 30, TimeUnit.SECONDS);
        if (!got) return "❌ 5 秒内没抢到锁，请稍后";
        try {
            Thread.sleep(1000);  // 模拟业务执行 1 秒
            return "✅ 拿到锁，等了 " + (System.currentTimeMillis() - start) + " ms";
        } finally {
            lock.unlock();  // finally 必写
        }
    }

    /**
     * 演示 2：分布式 RMap（和 HashMap 用法一模一样）
     */
    @GetMapping("/map/{key}")
    public String mapDemo(@PathVariable String key,
                          @RequestParam String value) {
        redisson.<String, String>getMap("demo:user")
                .put(key, value);          // 写
        return "Map 已写入：key=" + key + ", value=" + value;
    }

    @GetMapping("/map")
    public Map<String, String> mapRead() {
        return redisson.<String, String>getMap("demo:user").readAllMap();  // 读全量
    }
}
```

启动 Spring Boot，`curl http://localhost:8080/demo/map/a?value=tomcat` → `curl http://localhost:8080/demo/map` 就能看到值。

## 五、⭐ 最常用 API 速查表（工作中直接抄）

### 5.1 分布式锁（90% 场景用 RLock）

| API（RedissonClient.xxx） | JUC 对照 | 一句话用法 | 示例 |
|:---|:---|:---|:---|
| `getLock(name)` → `RLock` | ReentrantLock | 可重入互斥锁，最常用 | `lock.tryLock(5, 30, SECONDS)` |
| `getFairLock(name)` → `RFairLock` | ReentrantLock(fair=true) | 公平锁：先到先得，防饥饿 | `fairLock.lock()` |
| `getReadWriteLock(name)` → `RReadWriteLock` | ReentrantReadWriteLock | 读多写少：读读共享，读写/写写互斥 | `rw.readLock().lock()` / `writeLock` |
| `getSemaphore(name)` → `RSemaphore` | Semaphore | 限并发：同时最多 N 个线程执行 | `sem.trySetPermits(100); sem.acquire()` |
| `getCountDownLatch(name)` → `RCountDownLatch` | CountDownLatch | 多任务汇合：5 个子任务全做完再继续 | `latch.trySetCount(5); latch.countDown(); latch.await()` |

> ⚠️ **锁的两条天条**：① 生产全部用 `tryLock(wait, lease, 单位)` 别 `lock()` 永久等；② **finally 必须 unlock**，不然要等看门狗/TTL 到点才释放。

### 5.2 分布式 Map/集合

| API | JUC/Java 对照 | 一句话用法 |
|:---|:---|:---|
| `getMap(name)` → `RMap<K,V>` | ConcurrentHashMap | 最基础分布式 HashMap |
| `getMapCache(name)` → `RMapCache<K,V>` | 无对照 | **每个 key 单独设 TTL**（验证码/临时 token）：`put(k, v, 5, MINUTES)` |
| `getLocalCachedMap(name, opts)` → `RLocalCachedMap` | 本地 ConcurrentHashMap + Redis | **二级缓存**：同时存 JVM 本地+Redis，QPS/RT 性能飙升，高频读用 |
| `getSet(name)` → `RSet` | HashSet | 去重、交并差集：`s1.intersection(s2)` |
| `getScoredSortedSet(name)` → `RScoredSortedSet` | TreeSet（可排序） | 排行榜：`add(score, member); range(0, 10)` |
| `getBloomFilter(name)` → `RBloomFilter` | 无对照 | 布隆过滤器：`tryInit(1_000_000, 0.001)` 后 `add`/`contains` |

### 5.3 队列 & 延迟 & 限流（不用 MQ 也能做）

| API | 功能 | 典型场景 |
|:---|:---|:---|
| `getBlockingQueue(name)` → `RBlockingQueue` | 阻塞队列：take() 空就等 | 简单消息队列（并发不高的场景） |
| `getDelayedQueue(queue)` → `RDelayedQueue` | 延迟队列：元素到时间才出现在目标阻塞队列 | **订单 30 分钟未支付自动取消**：`offer(task, 30, MINUTES)` |
| `getRateLimiter(name)` → `RRateLimiter` | 限流器：令牌桶/漏桶/滑动窗口 | **接口限流**：`trySetRate(OVERALL, 1000, 1, SECONDS)`，`tryAcquire()` 拿令牌 |
| `getAtomicLong(name)` → `RAtomicLong` | 分布式自增计数 | 发号器、计数器：`incrementAndGet()` |

## 六、Spring Boot 三个常用注解小抄

加了 Starter 后，下面三个注解不用自己写 RedisTemplate：

### 6.1 @Cacheable（查缓存，击穿零代码）
```java
@Service
public class ProductService {
    /**
     * sync=true = 同一 skuId 并发过来，自动加 Redisson 分布式互斥锁
     *            只让第一条查 DB，其余线程等结果 → 击穿零代码
     */
    @Cacheable(cacheNames = "product", key = "#skuId", sync = true)
    public Product getProduct(Long skuId) {
        return productMapper.selectById(skuId);   // 只有缓存 miss 才会走到这里
    }

    @CacheEvict(cacheNames = "product", key = "#product.id")
    public void update(Product product) {
        productMapper.updateById(product);          // 先更 DB → 后删缓存（正确顺序）
    }
}
```
Cache 配置见 [Spring集成与生产调优.md → RedissonSpringCacheManager](Spring集成与生产调优.md#二spring-cache-注解整合cacheable--cacheevict--cacheput-)。

### 6.2 自定义 @DistributedLock 注解（事务外锁神器）
完整切面代码见 [Spring集成与生产调优.md → 正确写法 B](Spring集成与生产调优.md#方式-b切面--order-控制推荐不用每个-controller-写)。之后你就可以：

```java
// ⭐ @Order(1) 切面在 @Transactional（默认Order最大）外层 → 事务外锁，100% 不会超卖
@DistributedLock(key = "'stock:' + #skuId", waitTime = 3, leaseTime = 20)
@Transactional(rollbackFor = Exception.class)
public void deductStock(Long skuId, int qty) {
    // 扣库存代码（保证拿到锁→开事务→扣→事务提交→解锁）
}
```

## 七、⭐ 入门必踩 10 个坑（FAQ）

| # | 现象 / 问题 | 原因 + 正确做法 |
|:---:|:---|:---|
| 1 | 启动报错 `NoClassDefFoundError: org/nustaq/serialization/FSTConfiguration` 类的 | 序列化 codec 没写对类全路径；配置里写完整 `<包名>.<Codec类>` |
| 2 | 引入后发现还是 RedisTemplate，没 RedissonClient | 检查是否引了 `redisson-spring-boot-starter`（只引 `redisson` 本身不会自动装配）；确认 `spring.redis.host` 或 `spring.redis.redisson.config` 至少有一个配置 |
| 3 | **序列化的类一改字段，反序列化直接炸** | 默认 JDK 序列化兼容极差；**生产切 Kryo5Codec**（自动兼容新增/删除字段） |
| 4 | 业务执行 1 分钟，锁 30s 就过期了，并发脏写 | 要么传 `leaseTime=-1`（开看门狗自动续）；要么预估业务最大耗时 **leaseTime 设成 2×** |
| 5 | 用了 `lock.lock()`，偶尔线程永久挂起不响应 | 改成 `lock.tryLock(5, 30, SECONDS)`，超时就返回错误提示，别无限等 |
| 6 | 报错 `attempt to unlock lock, not locked by current thread by node id ...` | ① 把别人的锁解锁了（你判断 value 不是自己的就别解）；② RedissonClient 不是同一个实例（比如你锁后手动 new 了另一个 RedissonClient 去解） |
| 7 | 切了哨兵模式启动一直 `sentinel added` 刷屏日志 | 正常现象（`scanInterval` 定时刷新，级别 INFO 不影响），如果觉得吵把 `org.redisson` 日志设 WARN |
| 8 | 写了哨兵模式报 `Can't find master with name: xxx` | 检查 `masterName` 是否和 sentinel.conf 里 `sentinel monitor <mastername> ...` 配的一样（大小写敏感！） |
| 9 | Cluster 模式报错 `Many slots aren't covered` | 少写了节点地址，导致 16384 槽没全覆盖；至少把所有主节点地址都写上，Redisson 会自动发现从节点 |
| 10 | **锁 + @Transactional 一起用，压测还是超卖** | 99% 是「事务包锁」顺序错（方法 @Transactional，锁在方法里）→ 解锁在 finally（方法返回前）→ 但事务 commit 在 AOP 后置（方法返回后）→ 锁放了 DB 没提交 → 其他线程拿锁查到旧值。**解法：锁在 Controller 层显式写 或 用 @DistributedLock 切面 Order=1 在外层**。 |
