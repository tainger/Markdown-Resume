# B树 与 B+树（外加跳表）

> 一句话：磁盘索引选 B+树——矮胖少 IO、叶子链表利于范围扫描；内存有序结构选跳表——实现简单、并发友好。

## 对比表

| 维度 | B树 | B+树 | 跳表 |
|:---|:---|:---|:---|
| 数据位置 | 所有节点 | 仅叶子节点 | 链表节点 |
| 树高/IO | 较高 | **更矮**（非叶只存键） | 多层指针，内存操作 |
| 范围查询 | 中序回溯 | **叶子双向链表顺序扫** | 底层链表顺序扫 |
| 等值查询 | 快 | 快 | 期望 O(log n) |
| 实现复杂度 | 高 | 高 | **低** |
| 典型应用 | 文件系统 | MySQL InnoDB 索引 | Redis zset、LevelDB/RocksDB |

## 选型结论

- **MySQL 索引 = B+树**：非叶节点不存数据 → 单页放更多键 → 树更矮 → 磁盘 IO 更少；叶子链表天然支持范围查询与排序
- **Redis zset = 跳表**：纯内存场景 IO 不是瓶颈，跳表实现简单且无需旋转（对比 [[数据结构/红黑树]]）
