# RAG 检索方案选型

| 对比 | 方案一 | 方案二 | 选型结论与来源 |
|:---|:---|:---|:---|
| 精确搜索 / 近似最近邻搜索（ANN） | 精确扫描逐个计算距离，适合小规模或要求精确近邻 | ANN 用近似搜索换速度 | 按规模、精度与延迟约束选，不能把生产环境等同于必须 ANN；[[AI项目/RAG/16.相似度搜索的常见算法]] |
| IVF / HNSW | IVF 聚类分桶，`nprobe` 影响搜索范围，可结合 PQ 压缩 | HNSW 分层图导航，支持插入，但图结构占内存、构建有成本 | 看内存、召回与更新需求，避免“唯一代价”“综合最优”等无条件表述；[[AI项目/RAG/16.相似度搜索的常见算法]] |
| 向量 / 关键词检索 | 向量侧重语义接近 | 关键词侧重字面线索 | 术语、型号与自然语言混合时考虑互补召回；[[AI项目/RAG/interview/03-向量检索与存储]] |
| RRF / 模型重排序（Reranking） | RRF 依赖多个列表的排名融合 | 模型重排序重新判断问题与候选相关性 | 区分融合与语义打分，候选规模和调用成本需评估；[[AI项目/RAG/27.RAG优化技术：重排序]] |
| 普通分片 / 父子分片 | 单层分片实现较简单，粒度影响上下文完整性 | 子块检索后取父块，增加存储、查询和去重成本 | 需要更完整章节上下文时考虑父子分片，成本不固定等于两倍；[[AI项目/RAG/9.什么是父子分片]] |
| pgvector / 独立向量库 / ES | pgvector 便于复用 PostgreSQL；独立向量库提供专门检索能力 | ES 便于已有关键词检索体系扩展 | 综合现有基础设施、运维、规模、过滤与混合检索需求，不把产品排成固定升级路线；[[AI项目/RAG/14.向量是数据库如何选型]] |
| Spring AI / LangChain4J | Spring AI 资料以 Advisor 与 DocumentRetriever 等组件组织 | LangChain4J 资料以 RetrievalAugmentor、ContentRetriever 等组件组织 | 可按生态和扩展需求比较；⚠️ raw 缺失，待补充：明确依赖版本后的能力验证，原文“不支持”暂不作为当前事实；[[AI项目/RAG/32.Spring AI 和 LangChain4J的模块化RAG功能对比]] |
| 固定 RAG / Agentic RAG | 预设先检索、后生成 | Agent 决定是否及何时调用检索工具 | 固定知识问答先说明固定链路；动态任务再说明 Agent 的决策职责；[[AI项目/RAG/38.Agentic RAG]] |

选型答题顺序：需求约束 → 原理差异 → 工程代价；框架来自 [[AI项目/RAG/interview/README]]。完整口述见 [[wiki/synthesis/RAG面试答题主线]]，证据局限见 [[wiki/synthesis/RAG资料审校与补齐清单]]。
