# RAG 面试答题主线

> 按“需求 → 数据 → 检索 → 生成 → 评测 → 维护”组织口述。入口：[[wiki/concepts/RAG]]；存疑口径见 [[wiki/synthesis/RAG资料审校与补齐清单]]。

## 1. 先交代目标与边界

**答题骨架**：检索增强生成（Retrieval-Augmented Generation，RAG）先检索外部资料，再将资料与问题一起交给模型生成答案；适合知识更新与来源追溯需求。微调解决的问题与之不同，可以组合使用。来源：[[AI项目/RAG/interview/01-基础与范式演进]]。

**追问**：为什么不直接塞全文？长上下文与 RAG 怎么取舍？回答时回到文档规模、相关资料筛选和更新需求。来源：[[AI项目/RAG/interview/01-基础与范式演进]]。

## 2. 说清离线入库

**答题骨架**：读取文档 → 预处理 → 分片 → 向量化 → 写入索引。在线查询使用已构建的索引。来源：[[AI项目/RAG/2.深入理解RAG技术原理——索引构建]]、[[AI项目/RAG/3.深入理解RAG技术原理——检索生成]]。

**父子分片回答**：小子块负责语义匹配，命中后通过 `parentChunkId` 取父块，生成时补齐上下文；代价是额外存储、父块查询和去重。父块仍需考虑生成输入预算，不能把“不参与嵌入”说成“无限长”。来源：[[AI项目/RAG/9.什么是父子分片]]、[[AI项目/RAG/interview/02-文档处理与分片]]。

**追问**：同一父块被多个子块命中怎么办？跨父块问题怎么办？先答父块去重，再说明单个父块并不保证覆盖跨文档答案。来源：[[AI项目/RAG/9.什么是父子分片]]。

## 3. 说清在线检索

**答题骨架**：问题预处理 → 查询向量化 → 向量/关键词召回 → 融合 → 按需重排序 → 上下文组装 → 生成。来源：[[AI项目/RAG/interview/05-框架与工程实践]]。

**混合检索回答**：向量检索覆盖语义表达，关键词检索补充型号、术语等字面线索；用倒数排名融合（Reciprocal Rank Fusion，RRF）合并不同检索器排名，避免直接相加不可比的原始分数。来源：[[AI项目/RAG/interview/03-向量检索与存储]]、[[AI项目/RAG/27.RAG优化技术：重排序]]。

**公式**：`RRF(d) = Σ 1 / (k + rank_i(d))`，排名从 1 开始，未出现的列表不贡献得分；课程常用 `k=60`。模型重排序则对问题与候选文本重新打分，两者机制不同。来源：[[AI项目/RAG/27.RAG优化技术：重排序]]。

**追问**：ANN 是否必选？先说明数据规模、精度和延迟约束，再比较精确扫描与 ANN，不使用“生产必须 ANN”。来源：[[AI项目/RAG/16.相似度搜索的常见算法]]。选型表见 [[wiki/comparisons/RAG检索方案选型]]。

## 4. 解释优化为什么加

**答题骨架**：按错误样本选择手段：版本误召回检查元数据过滤；表达不匹配检查问题改写；相关候选排名靠后检查重排序；跨文档漏证据检查问题分解。来源：[[AI项目/RAG/interview/04-RAG优化技术]]、[[AI项目/RAG/interview/06-RAG评测体系]]。

**追问**：每个请求都做改写、HyDE 和重排吗？先解释各模块解决的问题，再交代调用成本；题库中的组合架构作为候选设计，不作为全部必开的要求。来源：[[AI项目/RAG/interview/04-RAG优化技术]]。

## 5. 解释生成与质量验证

**答题骨架**：把筛选后的资料与问题组装为提示，要求基于证据回答；评测分别看检索资料是否有用、答案是否被资料支撑、是否回应问题、是否符合参考答案。来源：[[AI项目/RAG/interview/06-RAG评测体系]]。

**错误样本（Bad Case）排查**：先检查检索片段有没有答案，再检查噪声和排序，最后检查生成是否忠于上下文；将确认的错误样本加入回归集。来源：[[AI项目/RAG/interview/06-RAG评测体系]]。

**追问**：评测是否需要参考答案？必须说明具体指标与实现，现有材料对此有冲突，暂不背诵统一的“需要/不需要”。来源：[[AI项目/RAG/interview/06-RAG评测体系]]；待核实项见 [[wiki/synthesis/RAG资料审校与补齐清单]]。

## 6. 工程落地与项目证据

**答题骨架**：解释框架如何接入查询处理、内容检索和提示增强；固定 RAG 按预设流程检索，Agentic RAG 把检索作为 Agent 可选择调用的工具。来源：[[AI项目/RAG/32.Spring AI 和 LangChain4J的模块化RAG功能对比]]、[[AI项目/RAG/38.Agentic RAG]]。

**维护回答**：文档变更后重新处理对应内容，考虑旧分片删除、版本过滤和回归评测。当前笔记包含增量更新思路，但不是已验证的部署实现。来源：[[AI项目/RAG/interview/05-框架与工程实践]]。

⚠️ raw 缺失，待补充：本人项目的数据规模、依赖版本、并发量、延迟分位数、真实评测结果及优化前后对照。不要把题库的示例耗时、示例模型或课程项目当成本人生产经验。示例所在：[[AI项目/RAG/interview/05-框架与工程实践]]。
