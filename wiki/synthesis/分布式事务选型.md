# 分布式事务选型

> 一句话：能不用分布式事务就不用；要用时按「一致性强度 vs 性能」选——强一致 2PC，最终一致 TCC/本地消息表/事务消息，越靠后吞吐越高。

## 答题骨架

```
2PC/XA：    强一致，同步阻塞，吞吐低 → 传统数据库间
TCC：       业务层两阶段，Try-Confirm-Cancel，侵入大 → 资金类
本地消息表：业务与消息同库事务，异步投递 → 主力方案
事务消息：  MQ 半消息 + 回查（RocketMQ 原生） → 见 [[wiki/entities/RocketMQ]]
Saga：      长事务 + 正反补偿 → 跨系统长流程
```
