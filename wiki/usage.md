# LLM Wiki 使用手册（12 个核心 Case）

> 面向使用者的操作手册：每个 Case = 你说什么 → Agent 做什么 → 仓库发生什么变更。
> 维护规范（所有权/页面类型/双链语法）见根目录 `AGENTS.md`。

## 指令速查

| 指令 | 场景 |
|:---|:---|
| `消化 <笔记路径>` | 写完/改完一篇笔记，挂载进知识网 |
| 直接提问 | 平时问技术问题，Agent 自动基于 wiki 回答 |
| `lint wiki` | 定期体检：死链/矛盾/孤立页/过期 |
| `从 wiki 出草稿` | 写公众号：从 synthesis/comparison 蒸馏 |

---

## Case 1｜Ingest：写完新笔记，一句话挂进知识网

**你说**：

> 消化 java/Stream与Lambda.md

**Agent 做**：

1. 读这篇笔记 → 识别「语言核心」主题
2. 找挂载点：[[wiki/entities/JVM]] 的「关联」区追加 `[[java/Stream与Lambda]]`，index 同步
3. [[wiki/log]] 追加一条 `[ingest]` 记录

**变更**：只动 2~3 个 wiki 文件，raw 笔记零改动。之后问「Stream 惰性求值」直接命中，不用全库扫描。

## Case 2｜Query：带着双链回答（现场演示）

**你问**：ThreadLocal 内存泄漏是怎么回事，面试怎么答？

**对比**：不查 wiki → 现场推导，口径可能与你已有笔记不一致；查 wiki → 口径统一 + 每个论断可溯源。演示：

> 按 [[wiki/entities/JVM]] 的追问链 + [[java/ThreadLocal源码分析]] 的口径作答：
>
> **骨架**：ThreadLocalMap 的 key 是弱引用、value 是强引用 → GC 后 key 变 null 但 value 挂在 Thread 上 → 线程长寿命（线程池）时 value 永不回收 → 内存泄漏。
>
> **追问防御**：为什么 key 设计成弱引用？（帮助 GC 尽早发现 stale entry）→ 为什么还是泄漏？（value 强引用，靠 get/set/remove 的探测式清理兜底）→ 与 [[redis/过期与内存淘汰]] 的「惰性删除」类比记忆。
>
> **来源**：[[java/ThreadLocal源码分析]]、[[jvm/垃圾收集器]]

## Case 3｜Drill：模拟面试官追问链

**你说**：

> 用 Redis 实体页的追问链面我，我答一层你追一层

**Agent 做**：按 [[wiki/entities/Redis]] 的追问链逐层下钻：

```
第 1 层：为什么快？（单线程+多路复用+内存）
第 2 层：zset 为什么用跳表不用红黑树？→ 触达 [[wiki/comparisons/B树与B+树]]
第 3 层：RDB 和 AOF 怎么选？→ 触达 [[redis/持久化]]
第 4 层：缓存穿透和击穿的区别、各自方案？→ 触达 [[wiki/synthesis/缓存体系与一致性]]
第 5 层：答不上来时给骨架 + 指回对应笔记补漏
```

答完输出「薄弱点表」→ 补完笔记说「消化」，形成闭环。

## Case 4｜Lint：矛盾体检（真实案例，2026-08-30）

**你说**：lint wiki

**实际发生**（完整记录见 [[wiki/log]]）：

- 扫出 `算法思想/` 与 `数据结构/` 有 6 对同名笔记
- 逐对内容比对 → 2 对真重复（前缀和与差分、并查集）：独有内容并入数据结构版后删除，修复 9 处入链
- 4 对（哈希表/栈/队列/链表）确认为「结构 vs 套路」差异化双篇，误报平反，wiki 页标注定位

价值：**坏链与漂移在变烂之前被抓住，维护面收敛到单一出处**。

## Case 5｜Output：从 wiki 蒸馏公众号文章

**你说**：

> 把 B树与B+树 那页写成公众号草稿，口语化一点

**Agent 做**：

1. 读 [[wiki/comparisons/B树与B+树]]（对比表 + 选型结论现成）
2. 补 raw 细节：[[数据结构/B+树]]、[[mysql/索引]]、[[redis/数据类型与底层结构]]
3. **新建** `自媒体/微信公众号/探小虎/xxx.md`，log 记录 `[output]`

**关键**：新建文件，不动已定稿文章（所有权纪律）。

## Case 6｜Plan：考前复习计划

**你说**：

> 两周后面字节，按 wiki 给我排复习计划

**Agent 做**：读 [[wiki/synthesis/P7面试复习主线]] + [[面试/大厂面试特点与真题]]（字节：算法占比高、八股深挖），输出：

- 第 1 周：28 高频题过一遍（[[面试/Java后端高频面经速查]]）+ 每天 2 题保温
- 第 2 周：字节向——手撕算法加量（[[面试/算法面试实战指南]] 节奏表）+ 项目深挖预演（[[wiki/synthesis/高并发库存扣减]]）
- 每天 20 分钟走一条实体页追问链

## Case 7｜Deep-dive：项目深挖演练

**你说**：

> 简历上写了高并发扣库存，帮我预演面试官 10 连问

**Agent 做**：沿 [[wiki/synthesis/高并发库存扣减]] 的答题骨架出题：

```
Q1 为什么 Redis 预扣还要 DB 兜底？      → 骨架现成答案
Q2 预扣成功但下单失败怎么回补？          → 骨架"兜底"层
Q3 Redis 挂了库存准不准？               → 跳到 [[redis/高可用与集群]]
Q4 扣减最终一致性怎么保证？              → 跳到 [[wiki/synthesis/分布式事务选型]]
Q5 削峰为什么选 RocketMQ 不选 Kafka？   → 跳到 [[wiki/entities/RocketMQ]]
```

一个项目问题自动串起 4 个目录的笔记——这正是 wiki 的意义。

## Case 8｜复盘回流（Backflow）：真题喂回 wiki

**你说**：

> 今天一面被问倒了：RocketMQ 顺序消费的实现、MySQL 间隙锁的范围

**Agent 做**：每道题挂到对应实体页，标 `⚠️ 真题实录·被问倒`（[[wiki/entities/RocketMQ]]、[[wiki/entities/MySQL]]），给出 3 分钟版骨架答案 + 指回笔记补漏，log 记录。

价值：对应调研文章的「知识回流」——**面过的试不白面**，每次面试都在喂养知识网。

## Case 9｜JD Gap 分析：投递前知道哪里翻车

**你说**：

> 消化 jd/Java高级工程师.md，对照 wiki 找缺口

**Agent 做**：提 JD 技术点 → 对照 wiki 覆盖 → 输出三档清单：

| 档位 | 含义 | 动作 |
|:---|:---|:---|
| ✅ 有背书 | raw 有成稿 + wiki 有页 | 附双链，直接复习 |
| ⚠️ 单薄 | raw 有但不成体系 | 列入补写清单 |
| ❌ 缺失 | 完全没写过 | 生成 seed 页或从计划里删掉 |

## Case 10｜Locator：「我写过啥」定位器

**你说**：

> epoll 相关的内容我都写在哪了？

**Agent 做**：不走全库 grep，直接按 [[wiki/index]] 给知识地图：

```
io/NIO与多路复用（主战场：select/poll/epoll 对比）
→ io/Netty（应用层：EventLoop 即 Reactor）
→ wiki/entities/网络与IO（追问链入口）
→ redis（单线程模型类比关联）
```

## Case 11｜简历背书审计

**你说**：

> 审计 简历/resume.md，哪些技术点经不起深挖

**Agent 做**：提简历每个技术关键词 → 查 wiki/raw 支撑度 → 三档表：

- **有背书**（面试敢写）：如 Redis/MySQL/JVM —— 成稿充足
- **背书薄弱**（会被问穿）：只有零散段落 → 列入补写
- **无背书**（赶紧删或补）：raw 无任何笔记 → 决策：删掉或开 seed

原则：**简历上每个词都有笔记兜底**。

## Case 12｜新主题播种（Seed）：学到哪喂到哪

**你说**：

> 我要开始学 K8s 了

**Agent 做**：

1. 查 wiki 确认无覆盖 → 在 `concepts/` 新建 seed 页（只有骨架 + ⚠️ 待补充标注）
2. 给学习路线 + **与已有知识的 3 个连接点**：Netty 的 Reactor ↔ kubelet 事件循环、JVM 资源模型 ↔ Pod limit、Dubbo 服务治理 ↔ Service/Endpoint
3. 之后每学一篇 `消化` 一篇，seed 逐步长成 stable

原则：**不做孤立笔记，新知识第一天就挂进知识网**。
