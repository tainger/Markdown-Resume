AI应用开发岗·能力分级
面向「LLM应用开发 / AI Infra 应用层」岗位的能力分级参考。级别映射以阿里体系为基准，其他公司可按职责宽度平移。
一、级别总览

| 级别 | 常见映射 | 一句话画像 | 核心分水岭 |
| --- | --- | --- | --- |
| 初级 | P5 / L3 | 会用大模型把功能做出来 | 能不能独立交付一个确定需求 |
| 中级 | P6 / L4 | 能独立负责一个AI模块的端到端质量 | 能不能把效果做稳定、可度量 |
| 高级 | P7 / L5 | 能设计一条AI链路并对指标负责，带1‑3人 | 能不能定义方案与评测体系，带1‑3人 |
| 专家 | P8 | 能负责一个AI产品/平台的技术架构 | 能不能做技术选型与成本/收益决策，跨团队拿结果 |
| 高级技术专家 | P9 | 定义领域技术方向与组织能力 | 能不能创造新战场，让别人复用你的体系 |

| 数据能力 | 会准备少量样例数据 | 会做数据清洗/标注规范/Badcase收集 | 搭建数据飞轮（标注→训练→优化→回归） | 数据资产与合规治理，训练/评测/测试数据集分层 | 什么数据构成壁垒 |

| 业务理解 | 理解需求文档 | 能从用户使用数据反推优化点 | 能判断「这个场景该不该用AI」，定义指标 | 能做ROI决策、砍掉不该做的事 | 定义产品技术战略与商业化路径 |
| 影响力 | 完成分配任务 | 主动补文档，帮同学解决问题 | 带1‑3人，Code Review、方案评审 | 跨团队协同拿结果，培养高级工程师 | 影响组织与行业（开源、标准、对外技术品牌） | 

二、各级别详解

初级（P5）：把功能做出来

能力要求

• 熟练调用主流大模型API，理解token计费、上下文窗口、流式返回。

• 能写出稳定产出结构化结果的Prompt，会用JSON Schema / Function‑Calling约束输出。

• 能按已有架构完成RAG的某一环（文档解析、切片、入库、检索接口）。

• 具备一门主语言扎实工程能力（Java / Python），会Git、单测、日志。

典型产出

• 一个明确定义的功能模块，如「上传文档并入库」、「某类工具的Function‑Call接入」。

判定标准

• 有人给方案，能够独立写完代码并自测通过，Bug率可接受。

• 出问题会看日志定位，而不是只说“模型不行”。

反面信号

• Prompt全靠试；输出解析失败没有兜底；不做异常处理。

中级（P6）：把效果做稳定

能力要求

• 理解Transformer基本原理、注意力机制、KV‑Cache对成本/延迟的影响，能够解释幻觉来源。

• RAG调优实战：切片粒度、Overlap、混合检索（向量+关键词/BM25）、Rerank、Query改写与同义词映射。

• Prompt工程化：版本管理、Few‑shot选择、按失败模式迭代（不是拍脑袋改）。

• 会构建Case集并给出量化指标（召回率、答拒率）。

• 工程能独立处理流式输出(SSE粘包/半包/中断)、异步任务、幂等、分布式锁、缓存。

典型产出

• 一个稳定、可度量的AI模块。
分水岭：不只跑通，要有指标，知道如何衡量好坏。
高级（P7）：能设计链路，对指标负责

能力要求

• 方案选型能力：清楚 Prompt / RAG / 微调 / 工具调用各自成本与适用边界，给出选型依据而非跟风。

• 架构设计：多路检索架构、检索决策分级（命中什么才触发检索、何时反问、何时拒答）、上下文预算分配。

• Agent架构判断力：知道ReAct循环适用边界；推理发散/链路超时，可果断改为过程式流水线；可设计状态机、并发隔离、幂等重跑。

• 评测体系：LLM‑as‑Judge语义评判 + 接口真实校验双引擎，接入发布流水线作为可阻断质量卡点。

• 成本与性能：缓存命中率、模型分层调用、并发超时治理、Token成本核算。

• 带人：任务拆解给同级同学，做方案评审与Code Review。

典型产出

• 一条完整AI链路技术方案 + 落地 + 指标承诺（答准率、首字延迟、单次会话成本）。

判定标准

• 面对“效果不好”能系统性归因：检索没召回 / 上下文截断 / Prompt冲突 / 模型能力上限。

• 主动做技术取舍，写清Trade‑off。

反面信号

• 什么场景都套Agent；没有Eval就上线；只会堆Prompt补丁。

专家（P8）：对产品/平台技术架构负责

能力要求

• 平台化架构：Agent运行时、Skill体系、沙箱隔离、工具权限、多租户、审计、全链路可观测（OpenTelemetry / Trace）。

• 知识与数据治理：知识库入库标准、时效性与权限、评测数据分层、数据飞轮机制设计。

• 模型路线决策：闭源API vs开源自部署、微调 vs蒸馏的技术经济学分析；推理显存/吞吐/并发容量规划。

• 质量运营闭环：线上点赞点踩反馈 → Badcase沉淀 → 数据集扩充 → 自动回归 → 发布门禁，靠机制而不是人盯。

• 跨多方对齐：和产品、算法、运维、安全对齐，推动落地并度量业务价值（人效节省、故障MTTR下降、转化提升）。

• 人才培养：把高级工程师带到可以独立承担方案的水平。

典型产出

• 一个被多个业务方复用的AI平台/中台能力，有明确接入方数量与业务收益数据。

判定标准

• 能对“不做什么”给出判断并说服上下游。

• 遇到组织级问题（重复建设、标准不一），能推动收敛。

反面信号

• 只谈技术不谈业务价值；架构漂亮但无人接入。

高级技术专家（P9）：定义方向与组织能力

能力要求

• 技术趋势判断：对长上下文、多模态、Agent原生架构、推理成本曲线做前瞻判断，提前布局，承担不确定性。

• 战略级选择：定义“我们的技术壁垒是什么”——数据、场景闭环、运行时能力，并据此分配资源。

• 标准与生态：制定组织级规范（Prompt资产、Agent协议、AI质量红线、安全合规基线），推动多BU落地。

• 组织能力建设：设计团队能力模型与培养路径，批量产出P7/P8。

• 行业影响力：开源项目、技术标准、对外技术输出，吸引人才。

典型产出

• 一个新的技术方向/产品形态从0‑1，成为组织既定战略。

判定标准

• 别人在用你定义的架构与标准做事。

• 在信息不完备下做出方向判断，事后被验证是正确。

反面信号

• 只会讲趋势落不了地；影响力依靠汇报，不是实际被复用。

三、级别跃迁的关键动作

| 跃迁 | 卡点 | 突破动作 |
| --- | --- | --- |
| 初级 → 中级 | 只会实现，不会度量 | 给自己负责模块建Case集与指标，用数据说明优化效果 |
| 中级 → 高级 | 只会调优，不会设计 | 主动写方案文档，包含选型对比、Trade‑off、失败预案、评测方案 |
| 高级 → 专家(P8) | 只对模块负责，不对全局负责 | 建机制（而不是修Bug）；主动承接跨团队难题；把能力做成平台被复用 |
| 专家 → 高级技术专家(P9) | 只优化存量，不创造增量 | 找到尚未被定义的战场并证明成立；培养可以接你位置的人 |

补齐优先级（面试/晋升杠杆从高到低）

1. 补数字指标：为每个模块补上「指标改善前后对比」和「成本/延迟数据」——P7面试通过率最高杠杆。

2. 补安全叙述：主动讲自研脱敏与权限Hook；坦诚RAG权限隔离、Prompt注入防御缺口，讲未来改进方案。

3. 补平台价值：Skill体系，讲多少业务在用、沉淀多少技能、替代多少人工时。

4. 补人证证据：方案评审、Code Review、新人上手文档，P7→P8必要材料。

5. 补带人证据：任务拆解、指导同学落地的具体案例。
