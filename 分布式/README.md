## P7 必背清单（速查）

- **分布式事务选型口诀**：强一致选 XA/2PC（性能差）、长事务选 Saga（反向补偿）、TCC 性能好但代码侵入、**首选本地消息表（最通用最稳）**、非核心通知选最大努力通知。
- **CAP 三选二的真相**：P 是分布式的前提（网络分区必然存在），所以实际是 **CP 或 AP 二选一**——注册中心宁可旧可用不可新不可用 → Nacos 选 AP；分布式锁宁可不可用也不能错 → 选 CP（ZK）。
- **Raft 三个角色**：Leader（处理读写）、Follower（被动同步）、Candidate（选举中间态）；Leader 靠心跳保权，超时没心跳 → Followe → Candidate → 投票选新 Leader。
- **Sentinel 限流 4 种算法**：计数器（突刺）→ 滑动窗口（平滑）→ 漏桶（匀速，防下游）→ 令牌桶（允许突发，防自身）；默认滑动窗口。
- **幂等 10 法分类**：唯一约束型（DB 唯一键/Redis SETNX/ZK 临时节点）、去重表型（业务去重表/状态机）、Token 型（防重复提交）、多版本型（乐观锁版本号/CAS）。
- **分布式锁选型**：**性能**（Redis > ZK ≫ DB）、**可靠性**（ZK > Redis > DB）、**成本**（DB < Redis < ZK）；业务首选 Redis Redisson + 看门狗，金融级对可靠性极致要求选 ZK Curator。
- **蓝绿 vs 金丝雀**：蓝绿 = 两个全量集群一次性切流量（快但贵）；金丝雀 = 小比例流量灰度验证再逐步放大（稳但慢）；**生产标准 = 金丝雀分批 + 可一键回滚**。
- **链路追踪三要素**：TraceID（全链路唯一）、SpanID（单跳父子）、Annotation（关键事件埋点）；SkyWalking 走字节码增强（无侵入），Zipkin 走显式埋点。
- **Seata AT 核心两阶段**：一阶段 = 业务 SQL + 前后镜像 + 本地提交 + 全局锁；二阶段 Commit = 异步删反向 SQL/解锁，Rollback = 用前镜像补偿回滚。
- **Raft vs Paxos 记忆**：Raft 是 Paxos 的可实现简化版，把「选主 + 日志复制 + 安全性」拆分，选主靠随机超时打散选票冲突，更容易理解和落地。

## 学习建议

1. 按 1→5 顺序建立体系：**事务是日常最多坑 → 一致性是分布式地基 → 高可用是 P7 系统设计必考 → 服务治理是生产落地细节 → 分布式锁是高频面试开场题**。
2. 每篇「一句话总结」当作口述提纲，能复述即过关。
3. 「选型对比表」是 P7 面试的核心——面试官不只要你背原理，更要问「**你的项目里为什么选 A 不选 B，trade-off 是什么**」。
4. P7 面试重「落地」：结合项目经历准备 1~2 个真实分布式案例（STAR 结构）——比如你 AgentMate 里的幂等设计、分布式锁防重复触发、钉钉 Stream 消息至少一次+幂等处理。
