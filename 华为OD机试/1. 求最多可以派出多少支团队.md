# 1. 求最多可以派出多少支团队

> **难度**：🟢 简单 | **分值**：100 | **标签**：排序、双指针 | **考点**：贪心

## 题目描述

用数组 `abilities` 代表每个人的能力值。一个比赛活动要求参赛团队的**最低能力值为 `n`**，每个团队可以由 **1 人或者 2 人**组成，且 1 个人只能参加 1 个团队。

返回最多可以派出多少支符合要求的团队。

### 函数签名

```java
class Solution {
    public int maxTeams(int[] abilities, int n) {
        // ...
    }
}
```

---

## 示例

### 示例 1

```
输入：abilities = [3, 1, 5, 7, 9], n = 8
输出：3
```

**解释**：`9` 单独成队（9 ≥ 8）；`7 + 1 = 8` 成队；剩余 `3`、`5` 组队为 `3 + 5 = 8`，也可成队 → 共 **3 支**。

> 注：示例为流传版本，实际以考试输入为准；另一版本无「单人成队」规则，此时答案可能不同。

---

## 提示

- `1 <= abilities.length <= 10^5`
- `1 <= abilities[i], n <= 10^9`
- 1 人只能参加 1 个团队，不能重复使用
- 单人成队条件：能力值 ≥ n
- 优先考虑大能力值的人，避免浪费

---

## 思路

### 核心思想

排序 + 双指针（贪心）：

```
排序后：
left = 0（最小），right = n-1（最大）

1. a[right] >= N  → 单独成队（最大的一定能带上别人，但单独用最划算）
   count++, right--
2. a[left] + a[right] >= N  → 两人成队
   count++, left++, right--
3. 否则 → a[left] 谁都配不了（和最大的组都不够），丢弃
   left++
```

**为什么贪心是对的**：最大的人若能单独成队就单独出（不浪费别人）；最小的若和最大的都组不了队，那和谁都组不了，直接丢弃。

**逐步演示**（`[1,3,5,7,9]`，N=8）：

```
排序: [1, 3, 5, 7, 9]    left=0, right=4, count=0

right=4: 9 >= 8 → 单独成队         count=1, right=3
right=3: 7 + 1 = 8 >= 8 → 成队     count=2, left=1, right=2
right=2: 5 + 3 = 8 >= 8 → 成队     count=3, left=2, right=1

left >= right → 结束，输出 3 ✓
```

- 时间复杂度：\(O(n \log n)\)（排序主导）
- 空间复杂度：\(O(1)\)

### 解法（Java）

```java
import java.util.*;

class Solution {
    public int maxTeams(int[] abilities, int n) {
        int[] a = abilities.clone();   // 避免污染入参
        Arrays.sort(a);

        int left = 0, right = a.length - 1;
        int count = 0;

        while (left < right) {
            if (a[right] >= n) {
                // 最大者单独成队
                count++;
                right--;
            } else if (a[left] + a[right] >= n) {
                // 最小 + 最大 成队
                count++;
                left++;
                right--;
            } else {
                // 最小的配谁都组不了队，丢弃
                left++;
            }
        }
        // 最后若只剩 1 人，单独检查
        if (left == right && a[left] >= n) {
            count++;
        }

        return count;
    }
}
```

### 复杂度分析

- **时间复杂度**：\(O(n \log n)\)，排序主导；双指针扫描仅 \(O(n)\)。
- **空间复杂度**：\(O(n)\)，用于克隆入参数组；若允许原地修改入参可降到 \(O(1)\)。

> 💡 若题目版本**不允许单人成队**，去掉 `a[right] >= n` 分支即可，其余逻辑不变。

## 个人总结

### 暴力解踩坑记录

最初给出的暴力解：

```java
public int maxGroup(int[] people, int n) {
    int count = 0;
    for (int i = 0; i < people.length; i++) {
        int cur = people[i];
        if (cur >= n) {
            count++;
            continue;
        }
        for (int j = i + 1; j < people.length; j++) {
            int next = people[j];
            if (cur + next >= n) {
                count++;
            }
        }
    }
    return count;
}
```

#### 问题 1：没有「已使用」标记

配对成功后，`i` 和 `j` 两人都应该被消费掉，但代码完全没记录这件事。结果是：
- 内层 `j` 循环里，`i` 会被反复计入多次（与每个满足的 `j` 都 `count++` 一次，但 `i` 只能用一次）
- 当外层循环走到 `j` 时，`j` 又被当作「新人」重新处理

#### 问题 2：贪心方向也错了

对单个 `i`，应该是「**至多配一个 `j`**」，而代码是「**所有满足的 `j` 都 count**」。

#### 追踪示例（`[3,1,5,7,9]`，n=8）

```
i=0 (3): 与 5✓、7✓、9✓ 都满足  → count=3
i=1 (1): 与 7✓、9✓ 满足         → count=5
i=2 (5): 与 7✓、9✓ 满足         → count=7
i=3 (7): 与 9✓ 满足             → count=8
i=4 (9): 9>=8 单独成队          → count=9
输出 9，正确答案 3 ❌
```

`7` 这一个人被算了 4 次（和 3、1、5、9 各配一次），`9` 也被算了 5 次。

#### 正确的暴力解（回溯 + used 数组）

```java
public int maxGroup(int[] people, int n) {
    boolean[] used = new boolean[people.length];
    return dfs(people, n, used, 0);
}

private int dfs(int[] people, int n, boolean[] used, int idx) {
    if (idx >= people.length) return 0;
    if (used[idx]) return dfs(people, n, used, idx + 1); // 跳过已用的

    int best = dfs(people, n, used, idx + 1); // 不用 idx 这个人

    if (people[idx] >= n) {                   // 单独成队
        used[idx] = true;
        best = Math.max(best, 1 + dfs(people, n, used, idx + 1));
        used[idx] = false;
    }

    for (int j = idx + 1; j < people.length; j++) {  // 与某个未用的人配对
        if (!used[j] && people[idx] + people[j] >= n) {
            used[idx] = used[j] = true;
            best = Math.max(best, 1 + dfs(people, n, used, idx + 1));
            used[idx] = used[j] = false;
        }
    }
    return best;
}
```

- 时间复杂度：\(O(2^n \cdot n)\)，仅用于小数据验证
- 正确高效解法仍是「排序 + 双指针贪心」

#### 反思

- **配对/分组类问题，一定要有「占用」状态**：要么用 `used[]` 数组，要么用指针从两端向中间收缩（双指针本身就隐含了「已使用」语义）
- **「至多配一个」与「所有满足的都配」是两类完全不同的问题**，写循环前先想清楚题意
- 暴力解虽然慢，但它是验证贪心正确性的标尺——先写对暴力，再优化

### 双指针+排序 优化了哪些问题

双指针+排序把暴力解的两个根本问题一次性都解决了，核心是「**排序提供语义**」+「**指针移动等价于 used 标记**」。

#### 问题对照表

| 维度 | 暴力解 | 排序+双指针 | 解决了什么 |
|---|---|---|---|
| **占用状态** | ❌ 没有 `used[]`，人被反复计入 | ✅ `left`/`right` 之间的元素 = 未用，之外 = 已用 | 指针移动本身就隐含「消费」语义 |
| **配对数量** | ❌ 一个 `i` 与所有满足的 `j` 都 `count++` | ✅ 每轮至多配一对，配完两端都收缩 | 把「全部配」修正为「至多配一个」 |
| **决策依据** | ❌ 任意顺序，无贪心方向 | ✅ 排序后从两端逼近，「最大单独出」「最小配最大」 | 排序赋予「最大/最小」明确含义 |
| **丢人策略** | ❌ 没有，谁都舍不得丢 | ✅ `a[left]+a[right] < n` 时 `left++` 丢最小者 | 最小者与最大都配不了，必然报废 |
| **时间复杂度** | 即使改成正确回溯也要 \(O(2^n \cdot n)\) | \(O(n \log n)\) | 排序主导，扫描仅 \(O(n)\) |
| **空间复杂度** | 回溯需 `used[]` \(O(n)\) + 递归栈 \(O(n)\) | \(O(1)\)（原地排序） | 无需额外标记数组 |

#### 双指针如何「隐式」解决 used 问题

这是最关键的优化点。暴力解的痛点是「配对后没标记」，而双指针**用区间划分代替了标记数组**：

```
排序后数组：  [1, 3, 5, 7, 9]
              ↑           ↑
            left        right
            └─未用区间─┘
   已用区间在左外   已用区间在右外

每轮决策：
  a[right] >= n         → right 单独出，right--（右侧区间+1）
  a[left]+a[right] >= n → 两人出，left++ right--（两侧各+1）
  否则                  → left 太小必废，left++（左侧区间+1）
```

`left++` 或 `right--` 本质上就是 `used[i] = true`，但**不需要数组、不需要回溯、不需要递归栈**。这是双指针替代回溯最优雅的地方——把「状态管理」压缩成了两个整数。

#### 排序如何让贪心「正确」

暴力解即使补上 `used[]`（变成回溯），还是 \(O(2^n)\)，因为它在**任意顺序**下做选择。排序后：

1. **「最大者单独出」是最优的**：最大的人若能单独成队，单独出不会比「和别人组队再让一个小的单独出」更差，因为别人单独大概率出不了。
2. **「最小者与最大者配」是最优的**：最小者最难配，给它配最大的最有可能凑够 N；如果连最大的都凑不够，那最小者与谁都凑不够，直接丢弃。

这两条贪心规则**必须依赖排序**才成立。不排序时根本不知道谁是「最大」「最小」，也就无法做这种局部最优决策——只能暴力枚举所有组合。

#### 一句话总结

> **排序把「无序选择」变成了「有序决策」，双指针把「used 数组+回溯」压缩成了「两个指针的移动」**——前者降复杂度，后者省空间，两者合起来把 \(O(2^n \cdot n)\) 优化到 \(O(n \log n)\)。

### 错误实现分析

最初写出的双指针版本：

```java
public static int maxGroup1(int[] people, int n) {
    int count = 0;
    Arrays.sort(people);
    int left = 0;
    int right = people.length - 1;

    while (left <= right) {
        if (people[right] >= n) {
            count++;
            right--;
            continue;
        }
        if (people[left] + people[right] >= n) {
            right--;
            left++;
            count++;
        }
        if (people[left] + people[right] < n) {
            left++;
        }
    }
    return count;
}
```

#### Bug 1：`left == right` 时会「自配对」（最严重）

`while (left <= right)` 让循环走到只剩 1 人时还在跑，此时第二分支 `people[left] + people[right]` 实际是 `2 * people[left]`（自己加自己），如果 ≥ n 就错误地 `count++`。

**反例**：`[1, 2, 3, 4, 9]`，n=8

```
正确答案：1（只有 9 单独成队；1,2,3,4 两两组合最大 4+3=7 < 8，全废）

代码追踪：
left=0, right=4: 9>=8 → count=1, right=3, continue
left=0, right=3: 4<8, 1+4=5<8 → 三分支 left=1
left=1, right=3: 4<8, 2+4=6<8 → 三分支 left=2
left=2, right=3: 4<8, 3+4=7<8 → 三分支 left=3
left=3, right=3: 4<8, 4+4=8>=8 ❌ 自配对！count=2, right=2, left=4
返回 2 ❌（多算了 1）
```

#### Bug 2：三个 if 没有 else 串联

第二分支执行 `right--; left++;` 后，第三分支用**新指针**再判断，可能错误地再 `left++`，一轮动两次指针。

**反例**：`[2, 3, 5, 5]`，n=8

```
left=0, right=3: 5<8, 2+5=7<8 → 三分支 left=1
left=1, right=3: 5<8, 3+5=8>=8 → 二分支 count=1, right=2, left=2
  → 紧接着第三分支：people[2]+people[2]=5+5=10, 不<8, 不触发（这次侥幸）
left=2, right=2: 5<8, 5+5=10>=8 ❌ 自配对！count=2, right=1, left=3
返回 2 ❌（正确答案是 1：5+3=8 一队，剩 2 和 5 配 7<8 废弃）
```

#### Bug 3：数组越界（崩溃级）

**反例**：`[3]`，n=5

```
left=0, right=0: 3<5, 3+3=6>=5 → 二分支 count=1, right=-1, left=1
  → 第三分支：people[1] 数组越界！ArrayIndexOutOfBoundsException
```

#### 修正版

```java
public static int maxGroup1(int[] people, int n) {
    int count = 0;
    Arrays.sort(people);
    int left = 0, right = people.length - 1;

    while (left < right) {                    // 严格小于，留最后 1 人单独处理
        if (people[right] >= n) {             // 最大者单独成队
            count++;
            right--;
        } else if (people[left] + people[right] >= n) {  // 最小+最大
            count++;
            left++;
            right--;
        } else {                              // 最小者必废
            left++;
        }
    }
    if (left == right && people[left] >= n) { // 最后剩 1 人单独检查
        count++;
    }
    return count;
}
```

关键修正：

1. `while (left < right)` —— 避免自配对
2. `if / else if / else` —— 三分支互斥，一轮只动一次指针
3. 循环外补 `left == right` 的单人检查 —— 处理最后剩 1 人的情况

#### 边界用例验证表

| 用例 | n | 期望 | 考察点 |
|---|---|---|---|
| `[3]` | 5 | 0 | 单元素不够 |
| `[5]` | 5 | 1 | 单元素刚好 |
| `[1, 9]` | 5 | 1 | 1 大 1 小 |
| `[1, 4]` | 5 | 1 | 刚好配对 |
| `[1, 2, 3, 4, 9]` | 8 | 1 | Bug 1 反例 |
| `[2, 3, 5, 5]` | 8 | 1 | Bug 2 反例 |
| `[3, 1, 5, 7, 9]` | 8 | 3 | 原题示例 |
| `[1, 1, 1, 1]` | 2 | 2 | 全配对 |
| `[5, 5, 5, 5]` | 5 | 4 | 全单独成队 |
| `[]` | 5 | 0 | 空数组 |

#### 反思

- **双指针边界用 `<` 还是 `<=` 要想清楚**：配对类问题用 `<`，避免自配对；快慢指针类用 `<=` 或具体条件。判断依据是「左右指针相遇时是否还有合法语义」。
- **多分支条件必须用 `else if` 串联**：一旦某分支已经移动了指针，后续分支就不应该再基于「新指针」做判断——否则会出现「一轮动两次指针」的隐蔽 bug。
- **边界用例优先想「只剩 1 人」「空数组」「全够」「全不够」四类**：这是配对问题的经典 corner case 集合，先过这四类再写主逻辑。
