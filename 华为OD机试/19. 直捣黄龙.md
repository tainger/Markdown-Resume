# 19. 直捣黄龙

> **难度**：🔴 困难 | **分值**：200 | **卷次**：新系统 2026-04-08 | **标签**：BFS | **考点**：最短路径 + 路径计数

## 题目描述

小王在玩一款叫做「直捣黄龙」的小游戏：他从**入口**位置进入敌营，需要绕过哨兵的层层封锁，到达**敌军司令部**执行斩首行动。

地图是一个 **M × N 的网格**：

- `S`：入口（起点）
- `E`：敌军司令部（终点）
- `#`：哨兵/封锁区（不可走）
- `.`：空地（可走）
- 只能**上下左右**移动，每步耗时相等（1 个单位时间）

求从入口到司令部的最短路径中，一共有**多少条不同的最短路径**。

> ⚠️ 具体输入/输出细节随版本有差异（有的版本输出「最短时间 + 路径条数」），核心算法一致。

**函数签名**：

```java
// grid: 地图（'S' 起点，'E' 终点，'#' 障碍，'.' 空地）
// 返回从 S 到 E 的最短路径条数；不可达返回 0
public int countShortestPaths(char[][] grid)
```

## 示例

```
输入：
grid = [
  ['S', '.', '.'],
  ['#', '#', '.'],
  ['.', '.', 'E']
]
输出：
1
```

**解释**：唯一最短路径 `(0,0) → (0,1) → (0,2) → (1,2) → (2,2)`，长度 4 → 1 条。

**示例 2**（多条最短路径）

```
输入：
grid = [
  ['S', '.', '.'],
  ['.', '.', 'E']
]
输出：
3
```

**解释**：从 (0,0) 到 (1,2) 的最短距离为 3，共 3 条：

```
路径1: (0,0) → (1,0) → (1,1) → (1,2)
路径2: (0,0) → (0,1) → (1,1) → (1,2)
路径3: (0,0) → (0,1) → (0,2) → (1,2)
```

（每步向下或向右，恰好 3 步到达）→ 输出 3 ✓

---

## 提示

- 网格 BFS 天然给出**最短路径长度**；
- 要数**条数**，BFS 时不能简单用 visited 布尔，要额外记录：
  - `dist[x][y]`：起点到该点的最短距离；
  - `count[x][y]`：起点到该点的最短路径条数；
- 同层到达（`dist[nx][ny] == dist[x][y] + 1`）时**累加**条数；首次到达时**继承**条数。

---

## 思路

### 核心思想

**BFS + 路径计数**（在经典 BFS 上增加 `count[][]` 数组）：

```
dist[x][y]  = 起点到 (x,y) 的最短距离（初始 -1）
count[x][y] = 起点到 (x,y) 的最短路径条数（初始 0，起点为 1）

BFS 扩展 (x,y) → (nx,ny)：
  1. dist[nx][ny] == -1（首次到达）
     → dist[nx][ny] = dist[x][y] + 1; count[nx][ny] = count[x][y]; 入队
  2. dist[nx][ny] == dist[x][y] + 1（同层再次到达）
     → count[nx][ny] += count[x][y]   ← 关键：累加而不是覆盖
  3. 其他情况跳过
```

**为什么示例 2 是 3 条**：从 (0,0) 到 (1,2)，最短距离 = 3（1 步向下 + 2 步向右，顺序任意），`C(3,1) = 3` 种走法恰好对应 3 条最短路径。BFS 的 `count[][]` 累加会自动数出这个数——**最短路径条数只统计距离恰好等于最短距离的路径**，`count[E]` 即为答案。

**逐步演示**（示例 1）：

```
dist 初始化: 起点 (0,0) dist=0, count=1

(0,0) → (0,1): 首次到达, dist=1, count=1
(0,1) → (0,2): dist=2, count=1
(0,2) → (1,2): dist=3, count=1
(1,2) → (2,2): dist=4, count=1
(2,2) 是 'E' → count = 1 ✓
```

- 时间复杂度：\(O(M \times N)\)
- 空间复杂度：\(O(M \times N)\)

### 解法（Java，BFS + 计数）

```java
import java.util.*;

class Solution {
    public int countShortestPaths(char[][] grid) {
        // ---------- 第一步：读地图尺寸，找起点 S 和终点 E 的坐标 ----------
        int m = grid.length;        // m = 行数（有多少行）
        int n = grid[0].length;     // n = 列数（每行有多少格）
        int sx = 0, sy = 0;         // 起点坐标 (sx, sy)，先随便给个初值
        int ex = 0, ey = 0;         // 终点坐标 (ex, ey)
        for (int i = 0; i < m; i++) {              // i 从上到下扫每一行
            for (int j = 0; j < n; j++) {          // j 从左到右扫每一列
                if (grid[i][j] == 'S') { sx = i; sy = j; }  // 找到 S，记下它在第 i 行第 j 列
                if (grid[i][j] == 'E') { ex = i; ey = j; }  // 找到 E，同理记下
            }
        }

        // ---------- 第二步：准备两张“记录表”，每个格子各一格 ----------
        int[][] dist = new int[m][n];    // dist[x][y] = 从起点走到格子(x,y)的“最短步数”
        long[][] count = new long[m][n]; // count[x][y] = 走到(x,y)的“最短路径有几条”，用 long 防条数太大溢出
        for (int[] row : dist) {
            Arrays.fill(row, -1);        // dist 全部填 -1，代表“这个格子还没走到过”
        }

        // ---------- 第三步：定义“上下左右”四个走法（配套的两个数组一起看）----------
        // 第 d 个方向 = (dx[d], dy[d])：右、左、下、上
        int[] dx = {0, 0, 1, -1};   // 行的变化量：不动、不动、+1(下)、-1(上)
        int[] dy = {1, -1, 0, 0};   // 列的变化量：+1(右)、-1(左)、不动、不动

        // ---------- 第四步：BFS 初始化——把起点放进队列 ----------
        Queue<int[]> queue = new ArrayDeque<>(); // 队列里存待扩展的格子坐标 {x, y}
        dist[sx][sy] = 0;           // 起点到自己走 0 步
        count[sx][sy] = 1;          // 到起点的“路径”只有 1 条（就是站在原地这一种）
        queue.offer(new int[]{sx, sy}); // 起点入队，从它开始一圈一圈往外扩

        // ---------- 第五步：BFS 主循环——一层一层往外扩散 ----------
        while (!queue.isEmpty()) {           // 队列不空就继续
            int[] cur = queue.poll();        // 取出一个当前格子
            int x = cur[0], y = cur[1];      // 它的坐标 (x, y)
            for (int d = 0; d < 4; d++) {    // 尝试往“上下左右”四个方向走一步
                int nx = x + dx[d];          // 走一步后的新行号
                int ny = y + dy[d];          // 走一步后的新列号
                // 越界：新格子跑到地图外面了，这一步不合法，跳过
                if (nx < 0 || nx >= m || ny < 0 || ny >= n) continue;
                // 撞墙：新格子是哨兵/障碍 '#'，不能走，跳过
                if (grid[nx][ny] == '#') continue;

                if (dist[nx][ny] == -1) {
                    // 情况① 新格子第一次被走到（之前是 -1）
                    dist[nx][ny] = dist[x][y] + 1; // 它的最短步数 = 当前格子步数 + 1
                    count[nx][ny] = count[x][y];   // 路径条数“继承”当前格子（第一次到达，先照抄）
                    queue.offer(new int[]{nx, ny}); // 第一次到达才入队（避免重复扩展）
                } else if (dist[nx][ny] == dist[x][y] + 1) {
                    // 情况② 新格子之前到过，且这次来的步数“正好相等”（同为最短）
                    // 说明又找到一条同样长的最短路，条数要“累加”上来，而不是覆盖
                    count[nx][ny] += count[x][y];
                }
                // 情况③ dist[nx][ny] < dist[x][y]+1：从这边过去更远，不是最短，什么都不做
            }
        }

        // ---------- 第六步：终点格子记录的条数就是答案 ----------
        // 若 E 从没被走到（不可达），count 保持初始 0，正好符合“不可达返回 0”
        return (int) count[ex][ey];
    }
}
```

> 💡 要点：**「最短路径条数」= BFS + dist 分层 + count 继承/累加**。区分「首次到达（继承）」和「同层再次到达（累加）」是关键，用 `long` 防溢出。
>
> 🧭 三种情况一句话记：**① 第一次到 → 抄条数；② 再到且步数相等 → 加条数；③ 再到但更远 → 忽略**。
>
> ⚠️ 若题目还要求输出最短时间，直接输出 `dist[E]` 即可。

## 个人总结

### 为什么用 BFS 而不用 DFS

这题要的是**最短路径的条数**，「最短」正好是 BFS 的天赋、DFS 的软肋：

| 关键点 | BFS + count | DFS 数路径 |
|:---|:---|:---|
| 保证「最短」 | 按层扩散，出队距离天然递增，弹到 `E` 即最短 | 到 `E` 时可能绕远，得枚举**所有**路径再筛最短 |
| 应对四向成环 | `dist[nx]==dist[x]+1` 只认「更外一层」，环被自动挡住 | 允许重复经过才不漏路径 → 环导致指数爆炸/死循环 |
| 复杂度 | \(O(MN)\) 一次遍历 | 最坏**指数级**，大图必 TLE |

**四向移动是关键坑**：题目允许上下左右走（不像「只能右/下」那种 DAG），网格里存在环——

```
2×2 全空地，S 到 E：
  ┌───┬───┐
  │ S │ . │   DFS 若绕圈: S→右→下→左→上→右… 无限打转
  ├───┼───┤   BFS 靠 dist 分层: 每格只在"它那层"结算一次，干净
  │ . │ E │
  └───┴───┘
```

### 各方法适用边界

| 场景 | 方法 |
|:---|:---|
| 无权网格，求最短 + 数条数（本题） | **BFS 分层 + count** |
| 每步耗时不等（带权变体） | Dijkstra + count |
| 「只能右/下」的 DAG 计数 | DFS + 记忆化 / DP（≈[不同路径 62](../leetcode-hot100/)） |
| 纯枚举全部路径 | DFS/回溯（本题会指数爆炸，不适用） |

> 一句话：**BFS 的「按层扩散」把"最短"免费送给你**，配 `count` 累加一次遍历即得条数；DFS 没有分层保证，四向成环下既难保证最短、又会因枚举全路径指数爆炸——所以这题是 BFS 的主场。
