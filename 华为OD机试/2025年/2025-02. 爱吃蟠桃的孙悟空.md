# 2025-02. 爱吃蟠桃的孙悟空（2025 A 卷）

> **难度**：🟡 中等 | **分值**：100 | **卷次**：2025 A 卷 | **标签**：二分答案 | **考点**：二分查找最小可行速度（同 LeetCode 875 珂珂吃香蕉）

## 题目描述

孙悟空有 `N` 堆蟠桃，第 `i` 堆有 `piles[i]` 个。守卫会在 `H` 小时后回来。

孙悟空每小时选择一堆，以速度 `K`（每小时吃 `K` 个）吃：

- 若该堆桃子数 ≥ K，则这一小时吃掉 K 个；
- 若该堆桃子数 < K，则这一小时吃完这堆就休息（**一小时最多只吃一堆**，吃不满也不会去吃下一堆）。

孙悟空想在守卫回来前（即 `H` 小时内）吃完所有桃子，同时希望吃得**尽量慢**。求能在 `H` 小时内吃完的**最小速度 K**。

约束：`1 ≤ N ≤ 10^4`，`piles[i] ≥ 1`，`N ≤ H`（保证有解）。

> 新系统（力扣模式）：直接实现函数。

**函数签名**：

```java
// piles: 各堆桃子数；H: 限定小时数
// 返回 H 小时内吃完所需的最小速度 K
public int minEatingSpeed(int[] piles, int H)
```

## 示例

**示例 1**

```
输入：
piles = [3,6,7,11], H = 8
输出：
4
```

**解释**：K=4 时，各堆耗时 ⌈3/4⌉+⌈6/4⌉+⌈7/4⌉+⌈11/4⌉ = 1+2+2+3 = 8 ≤ 8，且 K=3 时需 1+2+3+4=10>8，故最小 K=4。

**示例 2**

```
输入：
piles = [30,11,23,4,20], H = 6
输出：
23
```

**解释**：只有 6 小时、5 堆，速度必须很大；K=23 时耗时 2+1+1+1+1=6 恰好。

## 提示

- **答案具有单调性**：K 越大，吃完总时长越短。存在一个「临界 K」，≥ 它都能按时吃完，< 它都不行 → **二分答案**。
- 速度范围：最小 1，最大 = `max(piles)`（速度再大也没意义，一小时最多吃一堆）。
- 判定函数：给定 K，算总耗时 `Σ⌈piles[i]/K⌉`，与 H 比较。

---

## 思路

### 核心思想

**二分答案 + 可行性检查**。这是「求最小满足条件的值」的经典二分模型：

```
1. 确定二分区间 [lo, hi] = [1, max(piles)]
2. 对候选速度 mid，计算吃完总耗时 hours(mid) = Σ ⌈piles[i]/mid⌉
3. 若 hours(mid) <= H：mid 可行，尝试更小 → hi = mid
4. 否则：mid 太慢 → lo = mid + 1
5. 区间收敛到最小可行 K
```

**为什么能二分**：耗时关于 K 单调递减——K 越大越快吃完。于是「能否在 H 小时吃完」关于 K 是「false...false, true...true」的分界结构，二分找第一个 true。

**向上取整技巧**：`⌈a/b⌉ = (a + b - 1) / b`（整数除法），避免浮点。

**逐步演示**（`piles=[3,6,7,11]`, `H=8`，区间 [1,11]）：

```
mid=6: 1+1+2+2=6 ≤8 可行 → hi=6
mid=3: 1+2+3+4=10>8 不可行 → lo=4
mid=5: 1+2+2+3=8 ≤8 可行 → hi=5
mid=4: 1+2+2+3=8 ≤8 可行 → hi=4
lo==hi==4 → 返回 4 ✓
```

- 时间复杂度：\(O(N \log(\max piles))\)
- 空间复杂度：\(O(1)\)

### 解法（Java，二分答案）

```java
public class Main {
    public int minEatingSpeed(int[] piles, int H) {
        int lo = 1, hi = 0;
        for (int p : piles) hi = Math.max(hi, p);   // 上界 = 最大堆

        while (lo < hi) {
            int mid = lo + (hi - lo) / 2;           // 防溢出写法
            if (hoursNeeded(piles, mid) <= H) {
                hi = mid;                           // 可行，压缩上界找更小 K
            } else {
                lo = mid + 1;                       // 太慢，抬高下界
            }
        }
        return lo;   // lo==hi 即最小可行速度
    }

    // 速度 K 下吃完所需小时数：一堆耗 ⌈p/K⌉ 小时
    private long hoursNeeded(int[] piles, int K) {
        long hours = 0;
        for (int p : piles) {
            hours += (p + K - 1) / K;   // 向上取整
        }
        return hours;
    }
}
```

> 💡 记忆：看到「**最小的满足…的速度/容量/时间**」且答案单调 → **二分答案**。三件套：定区间、写判定、按判定收缩。
>
> ⚠️ 易错：① 上界取 `max(piles)` 而非 `sum`（一小时只吃一堆，速度超过最大堆无收益）；② 耗时累加用 `long` 防溢出；③ 用 `lo<hi` + `hi=mid` 的「找左边界」写法，返回 `lo`，别写成会漏边界的 `lo<=hi`。
