# 2025-04. 最富裕的小家庭（2025 A/C 卷）

> **难度**：🟢 简单 | **分值**：100 | **卷次**：2025 A 卷 / C 卷 | **标签**：树、哈希、模拟 | **考点**：父子聚合（一层子树求和）

## 题目描述

在一棵树中，每个节点代表一个家庭成员，节点的数字表示其**个人财富值**。**一个节点及其所有直接相连的子节点**被定义为一个「小家庭」。

给你这棵树，计算出**最富裕的小家庭**的财富和（即某父节点的个人财富 + 其所有直接子节点的个人财富，取最大值）。

**输入**：

- 第一行：成员总数 `N`，成员编号 `1~N`（`1 ≤ N ≤ 1000`）。
- 第二行：`N` 个空格分隔的数，为编号 `1~N` 的个人财富值（`0 ≤ 财富值 ≤ 1000000`）。
- 接下来 `N-1` 行：每行两个整数 `(N1, N2)`，表示 `N1` 是 `N2` 的**父节点**。

**输出**：最富裕小家庭的财富和。

> 注意「小家庭」只含**父节点 + 它的直接（一层）子节点**，不包含孙节点。

**函数签名（新系统抽象）**：

```java
// wealth[i]: 编号 i+1 成员的财富（或用 1-indexed 数组）；edges: [父, 子] 对
// 返回最富裕小家庭的财富和
public int richestFamily(int[] wealth, int[][] edges)
```

## 示例

**示例 1**

```
输入：
4
100 200 300 500
1 2
1 3
2 4
输出：
700
```

**解释**：树为 1→{2,3}，2→{4}。
- 以 1 为父：`100 + 200 + 300 = 600`；
- 以 2 为父：`200 + 500 = 700`；
- 以 3、4 为父：各自无子节点，就是自身 300、500。

最大为 **700**。

---

## 提示

- 「小家庭」= 父 + 一层子节点，本质是对每个节点求「自身 + 直接子节点之和」。
- N ≤ 1000，直接哈希/数组累加即可，`O(N)`。
- ⚠️ **不要用 `wealth[fa] += wealth[ch]` 直接改财富数组**（见个人总结的坑），要单独开一个家庭和数组。

---

## 思路

### 核心思想

**遍历每条边，把子节点的个人财富累加到父节点的「家庭和」上**。无需真正建树，也无需找根节点：

```
1. family[i] 初始化为 i 的个人财富（父节点自己一定在小家庭里）
2. 对每条边 (fa, ch)：family[fa] += 个人财富[ch]
   —— 注意加的是 ch 的【个人财富】，不是 ch 的家庭和
3. 答案 = max(family[i])
```

**为什么初始化为个人财富**：每个节点都可能作为某个小家庭的父节点，它自身财富必须计入；没有子节点的节点，其家庭和就等于个人财富。

**关键陷阱**：绝不能写成 `wealth[fa] += wealth[ch]` 去修改原财富数组。因为输入的边顺序不保证自顶向下，若某子节点 `ch` 的财富已被它自己的子节点污染，再把它加给父节点就会重复计入孙节点。**必须用独立的 `family` 数组累加、且始终加「原始个人财富」**。

**逐步演示**（示例 1，1-indexed）：

```
个人财富 wealth = [_, 100, 200, 300, 500]
family 初始化   = [_, 100, 200, 300, 500]
边 (1,2): family[1] += wealth[2]=200 → family[1]=300
边 (1,3): family[1] += wealth[3]=300 → family[1]=600
边 (2,4): family[2] += wealth[4]=500 → family[2]=700
max(600, 700, 300, 500) = 700 ✓
```

- 时间复杂度：\(O(N)\)
- 空间复杂度：\(O(N)\)

### 解法（Java，父子聚合）

```java
public class Main {
    // wealth 为 1-indexed（下标 1~N），edges 每项 [父, 子]
    public int richestFamily(int[] wealth, int[][] edges) {
        int n = wealth.length - 1;              // 有效成员数
        long[] family = new long[n + 1];
        for (int i = 1; i <= n; i++) {
            family[i] = wealth[i];              // 父节点自身先计入
        }
        for (int[] e : edges) {
            int fa = e[0], ch = e[1];
            family[fa] += wealth[ch];           // 只加子节点的【个人】财富
        }
        long max = 0;
        for (int i = 1; i <= n; i++) {
            max = Math.max(max, family[i]);
        }
        return (int) max;
    }
}
```

**老系统输入输出版**：

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int n = Integer.parseInt(sc.nextLine().trim());
        int[] wealth = new int[n + 1];          // 1-indexed
        StringTokenizer st = new StringTokenizer(sc.nextLine());
        for (int i = 1; i <= n; i++) wealth[i] = Integer.parseInt(st.nextToken());

        long[] family = new long[n + 1];
        for (int i = 1; i <= n; i++) family[i] = wealth[i];

        for (int i = 0; i < n - 1; i++) {
            st = new StringTokenizer(sc.nextLine());
            int fa = Integer.parseInt(st.nextToken());
            int ch = Integer.parseInt(st.nextToken());
            family[fa] += wealth[ch];           // 加个人财富，别加 family[ch]
        }
        long max = 0;
        for (int i = 1; i <= n; i++) max = Math.max(max, family[i]);
        System.out.println(max);
    }
}
```

> 💡 记忆：**小家庭 = 父 + 一层子**。开独立 `family` 数组，`family[父] += 子的个人财富`，取最大。
>
> ⚠️ 易错：① **别直接改 `wealth` 数组**（`wealth[fa]+=wealth[ch]` 会把已聚合的孙辈财富重复计入）；② 编号 1~N，数组开 `N+1` 从 1 用起；③ 财富最大 1e6、成员 1000，和最大约 1e9 未溢出 int，但用 `long` 更稳。

> 📌 出题人埋的坑（务必记住）：很多人第一反应写 `wealth[fa] += wealth[ch]` 原地累加。反例：
>
> ```
> 5
> 100 200 300 400 500
> 3 4
> 3 5
> 1 3
> 1 2
> ```
> 边 `3→4`、`3→5` 先出现，若原地累加会把 `wealth[3]` 变成 `300+400+500=1200`；轮到边 `1→3` 时 `wealth[1] += 1200`，把节点 3 的孙辈（4、5）也算进了节点 1 的小家庭——但小家庭只含**一层**子节点。正解是用独立 `family` 数组、始终累加**原始个人财富**，即可规避。
