# 2026-07-22a. 不同Tag类型统计

> **难度**：🟢 简单 | **分值**：100 | **卷次**：新系统 2026-07-22 | **标签**：模拟 | **考点**：TLV 解析 + 4 字节对齐 + 格式校验

## 题目描述

某通信协议使用 **TLV（Tag-Length-Value）** 格式传输数据。给定一段按字节存储的整数数组 `arr`，请按 TLV 格式解析，统计其中出现的**不同 Tag 类型数量**。

### TLV 结构

每条 TLV 由三部分组成：

- **Tag**（1 字节）：标签类型，1 个整数
- **Length**（1 字节）：紧随其后的 Value 字节数，**必须 > 0**
- **Value**（Length 字节）：实际数据

### 对齐规则

每条 TLV 整体长度为 `2 + Length`（Tag + Length + Value）。为便于传输，**每条 TLV 实际占用空间按 4 字节向上对齐**（不足部分补 0，但不影响下一条 TLV 的起始位置）。

### 校验规则

只要满足以下任一条件，即视为**格式错误**，立即返回 `0`：

1. 剩余字节不足 2，无法读取 Tag + Length
2. `Length ≤ 0`
3. Value 字段加上对齐补位后超出数组范围

## 输入描述

- 参数：整数数组 `arr`，表示按字节存储的 TLV 报文
- 约束：`1 ≤ arr.length ≤ 100000`，元素为 0-255 的整数

## 输出描述

- 输出：不同的 Tag 类型数量
- 格式错误时输出 `0`

---

## 示例

### 示例 1

```
输入：[1, 2, 9, 9, 2, 2, 7, 7]
输出：2
```

**说明**：
- 第 1 条：Tag=1，Length=2，Value=[9,9]，占用 `2+2=4` 字节，4 对齐后仍 4，正好占用下标 0-3
- 第 2 条：Tag=2，Length=2，Value=[7,7]，占用 4 字节，下标 4-7
- 不同 Tag：{1, 2}，共 2 种 ✓

### 示例 2

```
输入：[1, 0, 5, 6]
输出：0
```

**说明**：第 1 条 Length=0，违反"Length 必须 > 0"，格式错误返回 0。

### 示例 3

```
输入：[1, 3, 9, 9, 9]
输出：0
```

**说明**：第 1 条 Tag=1，Length=3，Value=[9,9,9]，占用 `2+3=5`，对齐到 8 字节，但数组只有 5 字节，超出范围，返回 0。

## 提示

- **核心是模拟解析 + 边界校验**：按 stride 逐步推进指针
- 对齐公式：`stride = ((2 + length + 3) / 4) * 4`（即向上取整到 4 的倍数）
- 顺序很重要：先判"是否能读取 Tag+Length"，再判"Length 是否 > 0"，最后判"value+补齐是否越界"
- 用 `Set<Integer>` 统计不同的 Tag 值即可

---

## 思路

### 核心思想：指针扫描 + 步长对齐

用一个指针 `i` 从 0 开始扫描，每次处理一条 TLV：

1. 判 `i + 1 >= n` → 无法读取 Tag 和 Length，返回 0
2. 读 `tag = arr[i]`，`length = arr[i+1]`
3. 判 `length <= 0` → 返回 0
4. 计算实际占用字节数：`actual = 2 + length`
5. 按 4 对齐：`stride = ((actual + 3) / 4) * 4`
6. 判 `i + stride > n` → 越界，返回 0
7. 否则 `tags.add(tag)`，`i += stride`

**逐步演示**（示例 1，`[1, 2, 9, 9, 2, 2, 7, 7]`）：

```
i=0: tag=1, length=2, actual=4, stride=4
     i+stride=4 ≤ 8 ✓, tags={1}, i=4
i=4: tag=2, length=2, actual=4, stride=4
     i+stride=8 ≤ 8 ✓, tags={1,2}, i=8
i=8: i >= n, 结束
返回 tags.size() = 2  ✓
```

- 时间复杂度：\(O(n)\)，指针最多推进 n 次
- 空间复杂度：\(O(n)\)，最坏情况所有 Tag 都不同

## 代码

### 我的伪代码

```java
class Solution {
    public int countTagTypes(int[] arr) {
        int n = arr.length, i = 0;
        Set<Integer> tags = new HashSet<>();
        while (i < n) {
            if (i + 1 >= n) return 0;          // 无法读取 tag+length
            int tag = arr[i], length = arr[i + 1];
            if (length <= 0) return 0;          // length 必须 > 0
            int actual = 2 + length;
            int stride = ((actual + 3) / 4) * 4; // 向上取整到 4 的倍数
            if (i + stride > n) return 0;      // value+补齐超出数组
            tags.add(tag);
            i += stride;
        }
        return tags.size();
    }
}
```

### 解法（Java，指针扫描 + 步长对齐）

```java
class Solution {
    public int countTagTypes(int[] arr) {
        if (arr == null || arr.length == 0) return 0;
        int n = arr.length, i = 0;
        Set<Integer> tags = new HashSet<>();
        while (i < n) {
            // 1. 能否读取 Tag + Length
            if (i + 1 >= n) return 0;
            int tag = arr[i];
            int length = arr[i + 1];
            // 2. Length 必须 > 0
            if (length <= 0) return 0;
            // 3. 计算 4 字节对齐后的步长
            int actual = 2 + length;
            int stride = ((actual + 3) / 4) * 4;
            // 4. value + 补齐不能越界
            if (i + stride > n) return 0;
            tags.add(tag);
            i += stride;
        }
        return tags.size();
    }
}
```

### 复杂度分析

- **时间复杂度**：\(O(n)\)，指针 i 单调递增，最多扫 n 个字节
- **空间复杂度**：\(O(\min(n, 256))\)，Tag 只有 1 字节，不同 Tag 最多 256 种

> 💡 **记忆**：**「TLV 解析 = 步长公式 + 顺序校验」**。对齐公式 `((len + 3) / 4) * 4` 是经典 4 字节对齐写法，等价于 `(len + 3) & ~3`。
>
> ⚠️ **易错**：① 校验顺序不能乱——先判能否读 tag+length，再判 length>0，最后判越界；② 对齐是**整体**对齐（Tag+Length+Value 一起算），不是只对 Value；③ `length <= 0` 而非 `length == 0`，避免负数干扰。
