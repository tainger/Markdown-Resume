# 2026-08-09a. 查找最佳充电策略

> **难度**：🟢 简单 | **分值**：100 | **卷次**：新系统 2026-08-09 | **标签**：滑动窗口 | **考点**：固定长度滑动窗口求最小和

## 题目描述

给定一个一维数组 `priceArray`，表示未来 `priceRecords` 小时内每小时的电价（单位：分/kWh）。

找出充电成本最低的连续 `hours` 个小时时间段的开始时刻点。

若存在多种成本最低方案，优先返回最低成本方案的**最早的时刻点**。

## 输入描述

输入为三行：

```
priceRecords
hours
priceArray
```

- 参数 1：整数 `priceRecords`，表示电价记录数量
- 参数 2：整数 `hours`，表示连续小时数
- 参数 3：一维数组 `priceArray`，表示每小时的电价
- 约束：`1 <= priceRecords <= 24`，`1 <= hours <= priceRecords`，`1 <= price[i] <= 100`

`priceArray` 使用英文逗号分隔，允许逗号后有空格。

## 输出描述

返回一个整数，表示最优充电时段的起始索引（**从 0 开始**）。

## 示例

### 示例 1

```
输入：
12
3
25,15,20,18,12,25,30,28,22,16,14,35
输出：2
```

**说明**：连续 3 小时的最低电价时段是索引 2~4，价格分别为 20、18、12，总费用为 50 分。

```
12
4

```

**说明**：连续 4 小时的最低电价时段是索引 7~10，价格分别为 37、57、10、12，总费用为 116 分。

## 提示

- **固定长度滑动窗口**模板题：窗口大小恒为 `hours`，求所有窗口和的最小值
- 先算第一个窗口 `[0, hours)` 的和，之后每右移一格：`窗口和 += 新元素 - 移出窗口的旧元素`，无需重复累加
- 窗口起始索引范围为 `0 ~ priceRecords - hours`
- 多个窗口和同为最小值时取**最早索引**：更新最小值时用**严格小于** `<`，相等时不覆盖
- 索引从 **0** 开始计数，不要答成 1

---

## 思路

### 核心思想：固定窗口滑动求和

1. 计算初始窗口 `[0, hours)` 的电价和 `windowSum`，作为当前最小值，起始索引 `bestStart = 0`
2. 窗口右端点 `i` 从 `hours` 遍历到 `priceRecords - 1`：
   - 窗口右移：`windowSum += priceArray[i] - priceArray[i - hours]`
   - 新窗口起始索引为 `i - hours + 1`
   - 若 `windowSum < minSum`（严格小于），更新最小值和起始索引
3. 返回 `bestStart`

**逐步演示**（示例 1，hours=3）：

```
窗口[0,2]: 25+15+20 = 60 → minSum=60, bestStart=0
窗口[1,3]: 60 +18 -25 = 53 → 53<60，minSum=53, bestStart=1
窗口[2,4]: 53 +12 -15 = 50 → 50<53，minSum=50, bestStart=2
窗口[3,5]: 50 +25 -20 = 55 → 不更新
窗口[4,6]: 55 +30 -18 = 67 → 不更新
……后续均大于 50
返回 bestStart = 2 ✓
```

- 时间复杂度：\(O(n)\)，每个元素最多进、出窗口各一次
- 空间复杂度：\(O(1)\)

## 代码

### 解法（Java，固定长度滑动窗口）

```java
class Solution {
    /**
     * @param priceRecords 电价记录数量
     * @param hours        连续充电小时数（窗口大小）
     * @param priceArray   每小时电价
     * @return 成本最低时段的起始索引（从 0 开始）；并列取最早
     */
    public int findBestChargeStrategy(int priceRecords, int hours, int[] priceArray) {
        // 第一个窗口 [0, hours) 的电价和
        int windowSum = 0;
        for (int i = 0; i < hours; i++) {
            windowSum += priceArray[i];
        }

        int minSum = windowSum;
        int bestStart = 0;

        // 窗口右移：右端点 i 从 hours 开始
        for (int i = hours; i < priceRecords; i++) {
            // 加入新元素 priceArray[i]，移出旧元素 priceArray[i - hours]
            windowSum += priceArray[i] - priceArray[i - hours];
            int start = i - hours + 1;
            // 严格小于才更新，保证并列时保留最早的起始索引
            if (windowSum < minSum) {
                minSum = windowSum;
                bestStart = start;
            }
        }
        return bestStart;
    }
}
```

### 复杂度分析

- **时间复杂度**：\(O(n)\)，n = priceRecords，一次初始求和 + 一次滑动遍历
- **空间复杂度**：\(O(1)\)，仅用窗口和与几个指针变量

> 💡 **记忆**：**「固定窗口求最值 = 先建首窗，再滑一格加新减旧」**。滑动窗口把朴素 O(n·k) 的双重循环优化到 O(n)，是 100 分题最高频的考点之一。
>
> ⚠️ **易错**：① 求"最早索引"时更新条件必须是**严格小于** `<`，用 `<=` 会错误地保留并列的后者；② 移出窗口的元素下标是 `i - hours`，新窗口起点是 `i - hours + 1`，差一容易错；③ 返回索引从 **0** 开始；④ 本题数据量虽小（≤24），也要养成 O(n) 滑动窗口的习惯。
