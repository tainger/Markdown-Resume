# 2026-08-09b. 灯带颜色变换

> **难度**：🟢 简单 | **分值**：100 | **卷次**：新系统 2026-08-09 | **标签**：逻辑分析、位运算 | **考点**：规则模拟 + 状态压缩 + 循环节检测

## 题目描述

小明设计了一条灯带，该灯带中共有 `16` 盏灯（编号 `0` 到 `15`），每盏灯有两种颜色：红色（用字符 `R` 表示）和绿色（用字符 `G` 表示）。每过一秒，灯带中的灯都会按照以下规则进行一次颜色变换：

1. 如果上一秒灯 `lights[i]` 的两个相邻灯 `lights[i-1]` 和 `lights[i+1]` 颜色一致，则灯 `lights[i]` 在当前秒需要设置为**绿色**；
2. 其他场景（相邻灯颜色不一致、或灯只有单一邻居），则该灯在当前秒需要设置为**红色**。

注意：灯带中编号为 `0` 的灯和编号为 `15` 的灯是**不相邻**的（线性灯带，首尾不相连）。因此编号 `0` 的灯只有右邻居，编号 `15` 的灯只有左邻居。

给定一个灯带的初始状态，请你输出 `t` 秒后灯带中各灯的颜色。

## 输入描述

单行输入，格式为：

```
"lights",t
```

- `lights` 为用英文双引号包围的长度为 `16` 的字符串，每个字符为 `R` 或 `G`
- `t` 为整数，`1 <= t <= 10000000`（一千万）

两者用逗号分隔。

## 输出描述

输出一个用英文双引号包围的长度为 `16` 的字符串，表示 t 秒后灯带的状态。

---

## 示例

### 示例 1

```
输入："RRRRRRRRRRRRRRRR",1
输出："RGGGGGGGGGGGGGGR"
```

**说明**：中间 14 盏灯（编号 1~14）的左右邻居都是 R（颜色一致）→ 变绿；首尾两灯只有单一邻居 → 保持红色。

### 示例 2

```
输入："RRRRRRRRRRRRRRRR",2
输出："RRGGGGGGGGGGGGRR"
```

**说明**：第 1 秒后为 `RGGGG...GGGR`；第 2 秒时编号 1 的左邻 R、右邻 G（不一致）→ 变红，编号 14 同理变红；编号 2~13 的左右邻居都是 G → 保持绿色。

### 示例 3

```
输入："RGGGRGGGRGGGRGGG",1
输出："RRGRGRGRGRGRGRGR"
```

---

## 提示

- 每一秒的新状态**完全由上一秒的状态决定**，且必须基于"旧状态"统一计算，不能边算边覆盖
- 首尾两灯（0 和 15）只有一个邻居，**永远为红色**；中间灯 `i`（1~14）仅当 `old[i-1] == old[i+1]` 时变绿
- t 最大 10^7，直接模拟 16×10^7 次位运算虽可能卡线，但状态总数只有 **2^16 = 65536** 种，必然很快进入**循环**
- 用一个 16 位整数表示灯带状态（第 i 位为 1 表示 G），用数组记录每个状态第一次出现的秒数，再次遇到时即可**跳过整个循环节**
- 线性灯带首尾**不相连**，判断邻居时不要取模

---

## 思路

### 核心思想：状态压缩 + 循环节（有限状态自动机）

**状态编码**：16 盏灯每盏 2 种颜色，用一个 16 位整数 `state` 表示——第 i 位为 1 表示灯 i 为绿色 G，为 0 表示红色 R。

**状态转移** `nextState(state)`：

- 灯 0 和灯 15 只有单一邻居，下一秒必然是 R（对应位保持 0）
- 对中间灯 i（1 ≤ i ≤ 14）：若旧状态中第 i-1 位与第 i+1 位相同，则新状态第 i 位置 1（绿），否则为 0（红）

**循环节检测**：

- 状态空间有限（65536），变换又是确定性的，因此状态序列必然在 65536 步内重复
- 用 `seen[state]` 记录每个状态第一次出现的秒数
- 当算出的新状态 `next` 曾在第 `seen[next]` 秒出现时，说明找到了长度为 `cycleLen = step - seen[next]` 的循环节
- 剩余步数对循环节取模：`remain = (t - step) % cycleLen`，只需再模拟 `remain` 步即可

**逐步演示**（示例 1，初始全 R = 0，t=1）：

```
state = 0（全 R）
nextState: i=1..14 的左右邻居位都是 0（一致）→ 第 1~14 位置 1
step=1，到达 t，解码 → R G G ... G G R = "RGGGGGGGGGGGGGGR" ✓
```

若 t 很大（如 10^7），假设第 100 秒发现状态重复、循环节长度为 90，则直接跳过 90 的倍数步，最多再模拟 89 步。

- 时间复杂度：\(O(2^{16} \times 16)\)，最多约 65536 次状态转移即可定位循环节，之后常数步收尾
- 空间复杂度：\(O(2^{16})\)，`seen` 数组 65536 个 int

## 代码

### 解法（Java，位运算状态压缩 + 循环节）

```java
import java.util.Arrays;

class Solution {
    /**
     * @param lights 初始灯带状态（长度 16，字符为 R/G）
     * @param t      经过的秒数
     * @return t 秒后的灯带状态字符串
     */
    public String lightStripTransform(String lights, int t) {
        // 1. 状态压缩：第 i 位为 1 表示灯 i 为绿色 G
        int state = 0;
        for (int i = 0; i < 16; i++) {
            if (lights.charAt(i) == 'G') {
                state |= (1 << i);
            }
        }

        // 2. 记录每个状态第一次出现的秒数（-1 表示未出现过）
        int[] seen = new int[1 << 16];
        Arrays.fill(seen, -1);
        seen[state] = 0;

        int step = 0;
        while (step < t) {
            int next = nextState(state);
            step++;

            if (seen[next] != -1) {
                // 3. 发现循环节：next 曾在第 seen[next] 秒出现
                int cycleLen = step - seen[next];
                int remain = (t - step) % cycleLen;
                state = next;
                // 跳过整数个循环节，只模拟剩余步数
                for (int i = 0; i < remain; i++) {
                    state = nextState(state);
                }
                break;
            }

            state = next;
            seen[state] = step;
        }

        // 4. 解码为字符串
        StringBuilder sb = new StringBuilder();
        for (int i = 0; i < 16; i++) {
            sb.append(((state >> i) & 1) == 1 ? 'G' : 'R');
        }
        return sb.toString();
    }

    /**
     * 根据当前秒状态计算下一秒状态
     * 规则：中间灯 i 的左右邻居颜色一致 → 绿；否则红；首尾灯永远为红
     */
    private int nextState(int state) {
        int next = 0;
        // 首尾灯（0 和 15）只有单一邻居，对应位保持 0（红色）
        for (int i = 1; i <= 14; i++) {
            int left = (state >> (i - 1)) & 1;
            int right = (state >> (i + 1)) & 1;
            if (left == right) {
                next |= (1 << i);   // 邻居颜色一致 → 绿色
            }
        }
        return next;
    }
}
```

### 复杂度分析

- **时间复杂度**：\(O(2^{16} \times 16)\)，定位循环节最多 65536 次转移，每次检查 14 盏灯；与 t 的大小无关
- **空间复杂度**：\(O(2^{16})\)，约 256KB 的 `seen` 数组

> 💡 **记忆**：**「状态有限 + 转移确定 + 步数巨大 = 找循环节」**。把状态压成一个整数（位掩码），用数组/哈希表记录首次出现位置，重复出现时用 `剩余步数 % 循环节长度` 跳转。一维元胞自动机类题目（如本题灯带、开灯问题）都是这个套路。
>
> ⚠️ **易错**：① 每秒的新状态必须由**旧状态整体**计算，不能在原数组上原地修改（会污染后续灯的判断）；② 首尾灯只有一个邻居，**恒为红色**，且灯带首尾**不相连**，不要对下标取模；③ t 可达 10^7，不做循环节优化直接模拟可能超时；④ 循环节长度是 `step - seen[next]`，定位后剩余步数要对循环节**取模**而不是取整。
