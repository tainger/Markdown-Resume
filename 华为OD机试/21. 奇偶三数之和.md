# 21. 奇偶三数之和

> **难度**：🟡 中等 | **分值**：100 | **卷次**：新系统 2026-07-01 | **标签**：排序、双指针 | **考点**：三数之和变体（LeetCode 15）

## 题目描述

给定一个包含 n 个整数的数组 `nums` 和一个整数 `target`，请从数组中找出所有**不重复**的三元组 `[nums[i], nums[j], nums[k]]`，满足：

1. **和为目标**：`nums[i] + nums[j] + nums[k] = target`；
2. **奇偶性约束**：三个元素中**至少有两个是奇数**。

返回所有满足条件的不重复三元组。

**输出格式**：每个子数组内部元素按数值**升序**排列；所有子数组之间按**字典序升序**排列（先比较第一个元素，相同再比第二个，以此类推）。

**函数签名**：

```java
// 返回满足条件的所有不重复三元组（已按字典序排序）
public List<List<Integer>> threeSumOdd(int[] nums, int target)
```

## 示例

**示例 1**

```
输入：
nums = [-1, 0, 1, 2, -1, -4], target = 0
输出：
[[-1, -1, 2], [-1, 0, 1]]
```

**解释**：`-1 + -1 + 2 = 0`（奇数 2 个 ✓）；`-1 + 0 + 1 = 0`（奇数 2 个 ✓）；`-1 + 2 + -1` 与 `[-1,-1,2]` 重复去重。

**示例 2**

```
输入：
nums = [0, 0, 0], target = 0
输出：
[]
```

**解释**：`0+0+0=0` 但奇数个数为 0 < 2，不满足。

**示例 3**

```
输入：
nums = [1, 1, 2, 3, 5, 7], target = 8
输出：
[[1, 2, 5]]
```

**解释**：`1+2+5=8` 且奇数 1、5 共 2 个 ✓；其余组合如 `1+1+2=4`、`1+1+6`（无 6）、`3+5+7=15` 均不满足和为 8。

## 提示

- `3 ≤ nums.length ≤ 3000`，`-10⁵ ≤ nums[i] ≤ 10⁵`；
- 去重逻辑与 LeetCode 15 三数之和完全一致：**排序 + 跳过相邻重复**；
- 在满足 `sum == target` 的基础上，额外判断**奇数个数 ≥ 2** 才加入答案；
- 排序后 i < j < k，三元组天然内部升序，按 i 外层遍历天然字典序。

## 思路

### 核心思想

**排序 + 双指针 + 奇偶性过滤**（三数之和标准模板 + 一个条件）：

```
1. 排序 nums
2. 固定第一个数 i（0 ~ n-3），跳过重复的 nums[i]
3. 双指针 j = i+1, k = n-1：
   sum = nums[i] + nums[j] + nums[k]
   - sum < target → j++（需要更大）
   - sum > target → k--（需要更小）
   - sum == target：
     若奇数个数 >= 2 → 加入答案
     j++ 且跳过与 nums[j] 重复；k-- 且跳过与 nums[k] 重复
```

**为什么先排序**：排序让双指针能根据 sum 与 target 的大小关系单向移动（O(n²)），同时天然处理去重与输出排序。

**逐步演示**（示例 1，nums 排序后 `[-4,-1,-1,0,1,2]`，target=0）：

```
i=0 (nums=-4): j=1(-1), k=5(2): -4-1+2=-3 < 0 → j++
               j=2(-1), k=5(2): -4-1+2=-3 < 0 → j++
               j=3(0),  k=5(2): -4+0+2=-2 < 0 → j++ → j==k 结束
i=1 (nums=-1): j=2(-1), k=5(2): -1-1+2=0 ✓ 奇数2个(-1,-1) ✓ → 加入 [-1,-1,2]
               j 跳到3(0), k 跳到4(1)
               j=3(0), k=4(1): -1+0+1=0 ✓ 奇数2个(-1,1) ✓ → 加入 [-1,0,1]
i=2 (nums=-1): 与 i=1 重复 → 跳过
...
答案: [[-1,-1,2],[-1,0,1]] ✓
```

- 时间复杂度：\(O(n^2)\)（排序 O(n log n) + 双指针 O(n²)）
- 空间复杂度：\(O(1)\)（不计输出）

## 代码

### 我的伪代码

```java
 public static List<List<Integer>> threeSumOdd(int[] nums, int target) {
        Arrays.sort(nums);
        List<List<Integer>> res = new ArrayList<>();
        for (int i = 0; i < nums.length; i++) {

            int cur = nums[i];

            int theNextTarget = target - cur;
            int k = i + 1;

            int j = i - 1;

            if (j < 0 || k > nums.length) {
                continue;
            }

            while (0 <= j && k < nums.length) {

                int leftvalue = theNextTarget - nums[k];

                if (leftvalue > nums[j]) {
                    k++;
                } else if (leftvalue < nums[j]) {
                    j--;
                } else {

                    int count = 0;
                    if (Math.abs(nums[j]) % 2 != 0) {
                        count++;
                    }
                    if (Math.abs(nums[i]) % 2 != 0) {
                        count++;
                    }
                    if (Math.abs(nums[k]) % 2 != 0) {
                        count++;
                    }
                    if(count >= 2) {
                        List<Integer> resItem = new ArrayList<>();
                        resItem.add(nums[j]);
                        resItem.add(nums[i]);
                        resItem.add(nums[k]);
                        res.add(resItem);
                    }
                    k++;
                }
            }
        }
        return res;
    }

```

### 解法（Java，排序 + 双指针）

```java
import java.util.*;

class Solution {
    public List<List<Integer>> threeSumOdd(int[] nums, int target) {
        List<List<Integer>> ans = new ArrayList<>();
        Arrays.sort(nums);
        int n = nums.length;

        for (int i = 0; i < n - 2; i++) {
            if (i > 0 && nums[i] == nums[i - 1]) continue;  // 跳过重复 i

            int j = i + 1, k = n - 1;
            while (j < k) {
                int sum = nums[i] + nums[j] + nums[k];
                if (sum < target) {
                    j++;
                } else if (sum > target) {
                    k--;
                } else {
                    // 奇偶性过滤：至少 2 个奇数
                    int odd = (Math.abs(nums[i]) % 2) + (Math.abs(nums[j]) % 2) + (Math.abs(nums[k]) % 2);
                    if (odd >= 2) {
                        ans.add(Arrays.asList(nums[i], nums[j], nums[k]));
                    }
                    // 跳过重复
                    while (j < k && nums[j] == nums[j + 1]) j++;
                    while (j < k && nums[k] == nums[k - 1]) k--;
                    j++;
                    k--;
                }
            }
        }
        return ans;
    }
}
```

> 💡 记忆：**三数之和模板（排序 + 固定 i + 双指针 j/k + 双向去重）**是 OD/力扣双高频模板，本题只是加了一个「奇数 ≥ 2」的条件。
>
> ⚠️ 判奇数用 `x % 2` 时注意负数：Java 中 `-3 % 2 == -1`，取绝对值或 `x & 1` 与 0 比较都行（负数用 `(x & 1) != 0` 判断奇数最稳）。

## 个人总结

### 我的第一版思路：把 `i` 放在「中间」的双指针

标准模板是「固定最左的 `i`，`j`/`k` 都在 `i` 右边相向收缩」。我第一版换了一种摆法——**让 `i` 当中间那个数，`j` 从 `i-1` 往左走、`k` 从 `i+1` 往右走**：

```
我的摆法：      j ← i → k
              [.. j .. i .. k ..]
              j 从 i-1 往左        k 从 i+1 往右（背向移动）
```

这个思路**本身能成立**，但它把去重、边界、字典序都变难了，我在这几处连踩了 4 个坑。

### 踩坑记录

| # | 坑 | 我写的 | 问题 | 正确写法 |
|:---:|:---|:---|:---|:---|
| 1 | 边界 | `k > nums.length`；`while (0 < j ...)` | `k == nums.length` 时 `nums[k]` 已越界仍没拦住；`0 < j` 让下标 0 永远轮不到当左指针 | `k < nums.length`；`j >= 0` |
| 2 | 去重 | 一处都没写 | 题目要求**不重复**三元组，相邻重复值（如两个 `-1`）会重复命中 | i/j/k 跳重，或最后统一去重兜底 |
| 3 | 命中后指针 | 只 `k++`，`j` 没动 | 命中 `sum==target` 后只动一个指针，配合无去重极易产生重复答案 | 命中后 `j--` **且** `k++` |
| 4 | 字典序 | 按 `j,i,k` 加入后直接返回 | `i` 在中间 → 遍历时第一个元素 `nums[j]` 不单调，子数组间字典序不保证 | 最后额外排序，或改用标准摆法 |

> **易踩细节**：Bug 1 里 `0 < j` 这种写法最隐蔽——它不会报错，只是**悄悄漏掉下标 0 的元素**，测试数据不覆盖边界时很难发现。

### 唯一写对的地方 ✅

奇偶判断 `Math.abs(nums[j]) % 2 != 0` 是对的，绕开了负数 `-3 % 2 == -1` 的坑。文档推荐的 `(x & 1) != 0` 更简洁，但两者结果一致。

### 核心教训：为什么标准解法把 `i` 放最左更省心

| 维度 | 我的摆法（i 在中间） | 标准摆法（i 在最左） |
|:---|:---|:---|
| 指针方向 | j 往左、k 往右，**背向** | j、k 都在 i 右边，**相向收缩** |
| 去重 | i/j/k 三处都难对齐，还要跨 i 兜底 | i 跳重 + j/k 跳重，套路固定 |
| 字典序 | 第一个元素不单调，**要额外排序** | i 从小到大遍历，**天然字典序** |
| 边界 | `j>=0 && k<n` 两头都要防 | 一个 `while (j < k)` 搞定 |

> 💡 **一句话总结**：不是「i 在中间」的思路错，而是它把**去重、边界、字典序**这三件事的成本同时抬高了。三数之和这类题，**固定最小数 + 剩下两指针在其右侧相向逼近**，才能让一个 `while (j < k)` 把边界、去重、排序一次性兜住——这就是标准模板值得背下来的原因。

```java

public static List<List<Integer>> threeSumOdd(int[] nums, int target) {
    Arrays.sort(nums);
    List<List<Integer>> res = new ArrayList<>();

    for (int i = 0; i < nums.length; i++) {
        int cur = nums[i];
        int theNextTarget = target - cur;
        int j = i - 1;              // 左指针
        int k = i + 1;              // 右指针

        while (j >= 0 && k < nums.length) {   // Bug1: 边界修正
            int leftValue = theNextTarget - nums[k];
            if (leftValue > nums[j]) {
                k++;                // 注意:leftValue 偏大说明 nums[k] 太小,要 k++
            } else if (leftValue < nums[j]) {
                j--;
            } else {
                int count = ((nums[i] & 1) != 0 ? 1 : 0)
                          + ((nums[j] & 1) != 0 ? 1 : 0)
                          + ((nums[k] & 1) != 0 ? 1 : 0);
                if (count >= 2) {
                    res.add(Arrays.asList(nums[j], nums[i], nums[k]));
                }
                j--;                // Bug3: 命中后两个指针都要动
                k++;
                // Bug2: 跳过重复
                while (j >= 0 && nums[j] == nums[j + 1]) j--;
                while (k < nums.length && nums[k] == nums[k - 1]) k++;
            }
        }
    }
    // Bug2 补充:i 在中间导致跨 i 的重复,以及 Bug4 字典序,统一用去重+排序兜底
    return dedupAndSort(res);
}
```
