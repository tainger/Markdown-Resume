# 26. 项目模块依赖构建顺序规划

> **难度**：🔴 困难 | **分值**：200 | **卷次**：新系统 2026-04-26 | **标签**：拓扑排序、回溯 | **考点**：全部拓扑序列（字典序）

## 题目描述

某公司正在开发一个大型软件系统，系统包含 N 个模块，每个模块之间存在构建依赖关系。例如，模块 A 可能依赖于模块 B，这意味着**必须先构建模块 B，才能构建模块 A**。

请根据依赖关系，输出**所有可能的模块构建顺序**（按构建顺序排列模块名称），要求：

1. 每个合法的构建顺序作为一个结果；
2. 多个结果按**字典序**排序后输出；
3. 如果存在**循环依赖**（依赖成环），则没有合法构建顺序，返回**空数组**。

**函数签名**：

```java
// modules: 模块名称数组（互不相同，N ≤ 100）
// deps: [依赖模块, 被依赖模块]，表示前者依赖后者（被依赖者必须先构建）
// 返回所有合法构建顺序字符串列表（字典序）；有环返回空列表
public List<String> buildOrders(String[] modules, String[][] deps)
```

## 示例

**示例 1**

```
输入：
modules = ["user", "auth", "database", "api"]
deps = [["user","auth"], ["auth","database"], ["api","database"]]
输出：
["database api auth user", "database auth api user", "database auth user api"]
```

**解释**：`user → auth → database`、`api → database`，database 必须第一个构建；合法拓扑序共 3 种，按字典序输出 ✓

**示例 2**（循环依赖）

```
输入：
modules = ["A", "B", "C"]
deps = [["A","B"], ["B","C"], ["C","A"]]
输出：
[]
```

**解释**：形成环 A→B→C→A，无法完成构建 → 空数组 ✓

---

## 提示

- 依赖方向：`[A, B]` 表示 **A 依赖 B** → B 必须在 A **之前**构建；
- 建图方向：`被依赖 → 依赖`（即 B → A），B 的入度为 0 时先输出；
- 全部拓扑序 = DFS/回溯，每步从**当前入度为 0** 的模块中选一个；
- 为保证字典序，先把 modules **排序**，回溯时按序选入度 0 的模块；
- 结果数量 < 10!，回溯可行；若生成的序列长度 < N → 存在环。

---

## 思路

### 核心思想

**模块名排序 + 回溯选入度 0 节点（Kahn 思想的 DFS 版）**：

```
1. 建图（被依赖 → 依赖）并计算入度；modules 排序
2. dfs(已选序列, 剩余模块):
   - 已选 N 个 → 记录一个结果
   - 遍历排序后的模块：未选 且 入度==0 →
     选中它，把它指向的节点入度 -1，递归；回溯恢复
3. 结果数 == 0 或序列长度不足 → 有环 → []
```

**为什么先排序模块名**：DFS 时按升序遍历候选模块，生成的序列天然字典序，省去最后全量排序。

**逐步演示**（示例 1）：

```
图: database → auth → user；database → api
入度: database=0, auth=1, api=1, user=1
modules 排序: [api, auth, database, user]

第1步只能选 database（唯一入度 0）→ auth、api 入度变 0
第2步可选 auth 或 api:
  选 auth → user 入度变 0：
    第3步选 api → 第4步 user → "database auth api user"
    第3步选 user → 第4步 api → "database auth user api"
  选 api → 第3步只剩 auth（user 仍依赖 auth）：
    第3步选 auth → user 入度变 0 → 第4步 user → "database api auth user"
结果（字典序）: ["database api auth user", "database auth api user", "database auth user api"] ✓
```

> **与 [207 课程表](../leetcode-hot100/207.%20课程表.md) 的关系**：207 只问「能否完成」（有无环），是拓扑排序的**判定版**，跑一次 Kahn 看出队数是否等于 N 即可 \(O(V+E)\)；本题是拓扑排序的**枚举版**——不仅要判环，还要输出**所有**合法顺序。判环内核完全相同（Kahn 入度 / DFS 三色），差别在于 207 单跑一条，本题要在每个「入度 0 有多个候选」的岔口回溯展开全部分支。可以把本题理解为「207 判环 + 全排列式回溯」。

- 时间复杂度：\(O(V + E + K \cdot V)\)，K 为合法序列数（< 10!）
- 空间复杂度：\(O(V + E)\)

### 解法（Java，回溯 + 拓扑）

```java
import java.util.*;

class Solution {
    List<String> ans = new ArrayList<>();
    Map<String, List<String>> graph = new HashMap<>();
    Map<String, Integer> indegree = new HashMap<>();
    List<String> sorted;

    void dfs(List<String> chosen, int total) {
        if (chosen.size() == total) {
            ans.add(String.join(" ", chosen));
            return;
        }
        for (String m : sorted) {
            if (indegree.get(m) != 0) continue;      // 只选入度为 0
            if (chosen.contains(m)) continue;        // 未选过

            chosen.add(m);
            for (String next : graph.getOrDefault(m, List.of())) {
                indegree.put(next, indegree.get(next) - 1);
            }
            dfs(chosen, total);
            // 回溯恢复
            for (String next : graph.getOrDefault(m, List.of())) {
                indegree.put(next, indegree.get(next) + 1);
            }
            chosen.remove(chosen.size() - 1);
        }
    }

    public List<String> buildOrders(String[] modules, String[][] deps) {
        sorted = new ArrayList<>(Arrays.asList(modules));
        Collections.sort(sorted);                     // 先排序保证字典序
        for (String m : sorted) indegree.put(m, 0);

        for (String[] d : deps) {                     // d[0] 依赖 d[1] → d[1] 先
            graph.computeIfAbsent(d[1], k -> new ArrayList<>()).add(d[0]);
            indegree.put(d[0], indegree.getOrDefault(d[0], 0) + 1);
        }

        dfs(new ArrayList<>(), modules.length);
        return ans;                                   // 有环时 ans 为空 → []
    }
}
```

> 💡 记忆：**「输出所有合法拓扑序」= 排序 + 回溯选入度 0 节点**；选完更新入度、回溯恢复，是 LeetCode 课程表系列的进阶版。
>
> ⚠️ 依赖方向别建反：`[A, B]` = A 依赖 B，建图 B → A；若输出与答案相反，把 deps 的建边方向对调即可。

### 解法二：Kahn 回溯 + TreeSet 候选集（更贴本质、更快）

解法一每层都 `for (String m : sorted)` 扫全表再判 `indegree==0` + `chosen.contains(m)`（后者是 `O(N)` 线性查找）。改用一个**当前入度为 0 的候选集合** `ready`，回溯时增删，省掉重复扫描；`TreeSet` 自动维持字典序。

```java
import java.util.*;

class Solution {
    List<String> ans = new ArrayList<>();
    Map<String, List<String>> graph = new HashMap<>();
    Map<String, Integer> indeg = new HashMap<>();
    int total;

    public List<String> buildOrders(String[] modules, String[][] deps) {
        List<String> all = new ArrayList<>(Arrays.asList(modules));
        Collections.sort(all);                     // 字典序基础
        total = modules.length;
        for (String m : all) indeg.put(m, 0);
        for (String[] d : deps) {                  // [A,B]：A 依赖 B → 建 B→A
            graph.computeIfAbsent(d[1], k -> new ArrayList<>()).add(d[0]);
            indeg.merge(d[0], 1, Integer::sum);
        }
        // TreeSet 自动维持候选集的字典序
        TreeSet<String> ready = new TreeSet<>();
        for (String m : all) if (indeg.get(m) == 0) ready.add(m);
        dfs(new ArrayList<>(), ready);
        return ans;                                // 有环时永远凑不满 total → ans 为空
    }

    void dfs(List<String> path, TreeSet<String> ready) {
        if (path.size() == total) {
            ans.add(String.join(" ", path));
            return;
        }
        // 快照当前候选，避免遍历时修改 ready
        for (String m : new ArrayList<>(ready)) {
            ready.remove(m);
            List<String> unlocked = new ArrayList<>();       // 记录本步新解锁的节点，便于回溯
            for (String nx : graph.getOrDefault(m, List.of())) {
                indeg.put(nx, indeg.get(nx) - 1);
                if (indeg.get(nx) == 0) { ready.add(nx); unlocked.add(nx); }
            }
            path.add(m);
            dfs(path, ready);
            // 回溯恢复
            path.remove(path.size() - 1);
            for (String nx : unlocked) ready.remove(nx);
            for (String nx : graph.getOrDefault(m, List.of())) indeg.put(nx, indeg.get(nx) + 1);
            ready.add(m);
        }
    }
}
```

> 💡 候选集 `ready` 直接给出「当前能选谁」，不必每层扫全表 + `contains` 判重，逻辑更贴近 Kahn 本质；`TreeSet` 保证每步按字典序取候选。
>
> ⚠️ 遍历 `ready` 前要先**快照**（`new ArrayList<>(ready)`），否则递归中增删 `ready` 会触发 `ConcurrentModificationException`。

### 解法三：全排列暴力（N ≤ 9 骗分兜底）

生成 modules 的**所有 N! 排列**，逐个检查是否满足全部依赖（每条 `[A,B]` 中 B 必须排在 A 之前），合法的收集后排序。

```java
import java.util.*;

class Solution {
    public List<String> buildOrders(String[] modules, String[][] deps) {
        List<String> all = new ArrayList<>(Arrays.asList(modules));
        Collections.sort(all);                      // 先排序，permute 出的结果天然字典序
        List<String> ans = new ArrayList<>();
        permute(all, 0, deps, ans);
        return ans;
    }

    // 全排列：固定 start 之前的部分，交换枚举后续
    private void permute(List<String> arr, int start, String[][] deps, List<String> ans) {
        if (start == arr.size()) {
            if (valid(arr, deps)) ans.add(String.join(" ", arr));
            return;
        }
        for (int i = start; i < arr.size(); i++) {
            Collections.swap(arr, start, i);
            permute(arr, start + 1, deps, ans);
            Collections.swap(arr, start, i);        // 回溯
        }
    }

    // 校验：每条 [A,B] 要求 B 的下标 < A 的下标（B 先构建）
    private boolean valid(List<String> order, String[][] deps) {
        Map<String, Integer> pos = new HashMap<>();
        for (int i = 0; i < order.size(); i++) pos.put(order.get(i), i);
        for (String[] d : deps) {
            if (pos.get(d[1]) > pos.get(d[0])) return false;   // 被依赖者排在了后面 → 非法
        }
        return true;
    }
}
```

> ⚠️ 复杂度 \(O(N! \cdot E)\)，仅 `N ≤ 8~9`（`9! ≈ 36 万`）可行；`N=100` 直接爆炸。交换法枚举**不保证字典序**，若要严格字典序需最后对 `ans` 再 `Collections.sort`（或改用「按序选取 + used[]」的排列写法）。作为读不懂拓扑时抢小数据分的下策。

### 解法对比：判环方式与字典序保证

| 解法 | 判环方式 | 字典序保证 | 适用 | 推荐度 |
|:---|:---|:---|:---|:---|
| **排序 + 回溯扫全表**（解法一） | 隐式（序列长度不足） | 排序 modules | 通用、代码直观 | ✅ 够用 |
| **Kahn 回溯 + TreeSet 候选集**（解法二） | 隐式 | TreeSet | 候选多时更快、更贴本质 | ✅ 更优 |
| 先 Kahn 判环 + 再回溯 | 显式 Kahn | 排序 | 大概率有环时短路省时 | ✅ 稳健 |
| 三色 DFS 判环 + 回溯 | 三色标记 | 排序 | 练 DFS 拓扑范式 | 会即可 |
| 全排列暴力（解法三） | 逐条约束校验 | 需最后排序 | N≤9 / 骗分 | 兜底 |

> 一句话：「输出**全部**拓扑序」= **回溯逐层选入度 0 节点**（Kahn 的多分支展开）；字典序靠**候选集有序**（排序数组或 `TreeSet`）；判环可**隐式**（序列长度不足）或**显式**（先跑一次 Kahn / 三色 DFS）。要「唯一一条」序用 [207](../leetcode-hot100/207.%20课程表.md) 那样单跑 Kahn/DFS，要「全部」序就得回溯展开。
