# 29. 最小代价完成论文评审

> **难度**：🟡 中等 | **分值**：100 | **卷次**：新系统 2026-07-22 | **标签**：状态压缩、枚举 | **考点**：子集枚举（最小集合覆盖变体）

## 题目描述

某校有 n 篇论文需要分配给教师评审：

- 每篇论文 i 可由 `files[i]` 对应的教师列表中**任一**教师评审；
- 每篇论文**至少需要一名**教师评审；
- 每位教师 t，不论被分配多少篇论文，其评审费用**固定为** `cost[t]`。

请输出**参与评审教师数量最少**时的总费用；若存在多种方案满足教师数最少，则选择**总费用最小**的方案。

**函数签名**：

```java
// n: 论文篇数，m: 教师个数
// files: files[i] = 可评审论文 i 的教师列表
// cost: cost[t] = 教师 t 的评审费用
// 返回教师数最少时的最小总费用
public int minReviewCost(int n, int m, int[][] files, int[] cost)
```

## 示例

**示例 1**

```
输入：
n=3, m=3, files=[[0,1],[1,2],[0,2]], cost=[1,2,2]
输出：
3
```

**解释**：教师 {0,2} 可覆盖 3 篇论文（论文0→教师0，论文1→教师2，论文2→教师0/2），费用 1+2=3；教师 {1,2} 也可覆盖全部但费用 2+2=4 → 取 3 ✓

**示例 2**

```
输入：
n=3, m=3, files=[[0],[1],[2]], cost=[1,2,3]
输出：
6
```

**解释**：每篇论文只有唯一可选教师 → 必须 0、1、2 全部参与，费用 1+2+3=6 ✓

**示例 3**（教师数优先于费用）

```
输入：
n=4, m=5, files=[[0,3,4],[1,3],[2,4],[0,4]], cost=[1,1,1,3,3]
输出：
4
```

**解释**：

```
教师 0→论文[0,3] 费用1；教师 1→论文[1] 费用1；教师 2→论文[2] 费用1
教师 3→论文[0,1] 费用3；教师 4→论文[0,2,3] 费用3

3 名教师 [0,1,2] 可覆盖全部，费用 3 —— 但教师数 3 多于最少值 2，淘汰
2 名教师方案: [1,4] 费用 4；[3,4] 费用 6 → 取费用最小的 4 ✓
```

---

## 提示

- `1 ≤ n ≤ 20`，`1 ≤ m ≤ 12` → 教师集合总数 \(2^{12} = 4096\)，**子集枚举**可行；
- 优化目标有优先级：**先教师数最少，再总费用最小**（示例 3 的坑点）；
- 用**位掩码**表示每位教师能覆盖的论文集合；
- 枚举 mask：合并覆盖位、统计教师数与费用，能全覆盖时按双关键字更新。

---

## 思路

### 核心思想

**位运算子集枚举（集合覆盖）**：

```
1. 预处理 teacherCover[t]：教师 t 可评审论文的位掩码
   （对每篇论文 i，它的每个可选教师 t：teacherCover[t] |= 1<<i）
2. 枚举所有教师集合 mask (1 ~ 2^m - 1)：
   - 合并集合内所有教师的覆盖位 → cover
   - cover 覆盖全部论文 ((1<<n)-1)？
     统计教师数 cnt、总费用 sum
     按 (cnt, sum) 双关键字更新最优
3. 输出最优总费用
```

**为什么用枚举而不是贪心**：集合覆盖问题是 NP 难，贪心不保证最优；m ≤ 12 时 2^m 枚举是标准解法。

**逐步演示**（示例 1，n=3, m=3）：

```
files=[[0,1],[1,2],[0,2]] → teacherCover:
  教师0: 论文0、2 → 0b101；教师1: 论文0、1 → 0b011；教师2: 论文1、2 → 0b110

枚举 mask:
  mask={0,2} (0b101): cover=0b101|0b110=0b111 全覆盖 ✓ cnt=2 sum=1+2=3
  mask={1,2} (0b110): cover=0b011|0b110=0b111 全覆盖 ✓ cnt=2 sum=2+2=4
最优 = 3 ✓
```

- 时间复杂度：\(O(2^m \cdot m + n \cdot k)\)（k 为可选列表总长）
- 空间复杂度：\(O(m)\)

### 解法（Java，状态压缩枚举）

```java
import java.util.*;

class Solution {
    public int minReviewCost(int n, int m, int[][] files, int[] cost) {
        int[] teacherCover = new int[m];
        for (int i = 0; i < n; i++) {
            for (int t : files[i]) {
                teacherCover[t] |= (1 << i);       // 教师 t 可评审论文 i
            }
        }

        int allPapers = (1 << n) - 1;
        int bestCnt = Integer.MAX_VALUE;
        int bestCost = Integer.MAX_VALUE;

        for (int mask = 1; mask < (1 << m); mask++) {
            int cover = 0, cnt = 0, sum = 0;
            for (int t = 0; t < m; t++) {
                if ((mask & (1 << t)) != 0) {
                    cover |= teacherCover[t];
                    cnt++;
                    sum += cost[t];
                }
            }
            if (cover != allPapers) continue;      // 未覆盖全部论文

            // 双关键字：教师数优先，其次费用
            if (cnt < bestCnt || (cnt == bestCnt && sum < bestCost)) {
                bestCnt = cnt;
                bestCost = sum;
            }
        }
        return bestCost;
    }
}
```

> 💡 记忆：**「选最少的人覆盖所有需求」→ 子集枚举 + 位掩码**（m ≤ 12 是信号）；比较时先比人数再比费用。
>
> ⚠️ 枚举时别漏掉「人数更少但费用更高」的优先级：示例 3 中 3 名教师费用 3 < 2 名教师费用 4，但必须选 2 名教师的方案。

### 解法二：状压 DP（O(2ⁿ·m)，n 小 m 大时更优）

换个维度——**用「已覆盖论文集合」当状态**，避免枚举全部教师组合。当 `m` 很大而 `n` 较小时，比解法一的 \(O(2^m m)\) 更快。

- **状态**：`dp[S]` = 覆盖论文集合 `S`（n 位掩码）所需的最优 `(教师数, 费用)`。
- **转移**：从 `dp[S]` 再加一位教师 `t`，转移到 `dp[S | teacherCover[t]]`。
- **双关键字技巧**：把「教师数」放高位、「费用」放低位打进一个 `long`，直接数值比较就自动实现「先比人数、再比费用」。

```java
import java.util.*;

class Solution {
    public int minReviewCost(int n, int m, int[][] files, int[] cost) {
        int[] cover = new int[m];
        for (int i = 0; i < n; i++)
            for (int t : files[i]) cover[t] |= (1 << i);   // 教师 t 可评审论文 i

        int full = (1 << n) - 1;
        // 用 long 打包双关键字：高位=教师数，低位=费用，一次比较搞定优先级
        long[] dp = new long[1 << n];
        Arrays.fill(dp, Long.MAX_VALUE);
        dp[0] = 0;                                          // 覆盖空集：0 人 0 费用

        for (int S = 0; S <= full; S++) {
            if (dp[S] == Long.MAX_VALUE) continue;
            for (int t = 0; t < m; t++) {
                int ns = S | cover[t];                      // 加入教师 t 后新的覆盖集合
                long cand = dp[S] + (1L << 20) + cost[t];   // 教师数 +1（高位），费用 +cost（低位）
                if (cand < dp[ns]) dp[ns] = cand;
            }
        }
        return (int) (dp[full] & ((1 << 20) - 1));          // 取低位=费用
    }
}
```

> 💡 `1<<20` 只要远大于「最大可能总费用」即可（本题费用远小于 100 万），保证高位的教师数在比较中始终优先。
>
> ⚠️ 这是「n 与 m 谁小」的取舍：本题 `n≤20`、`m≤12`，解法一 \(O(2^{12}\cdot12)\) 反而更小 → **本题解法一更优**；只有 `m` 大而 `n` 小时，本解法才是正解。

### 解法三：回溯 + 剪枝（论文维度搜索，骗分 / 中等数据）

**逐篇论文**决定派哪位教师，用集合记录已选教师，全部论文覆盖时更新答案；配合「当前教师数已 ≥ 已知最优就剪枝」。

```java
import java.util.*;

class Solution {
    private int n, m, full;
    private int[] cost;
    private int[][] files;
    private int bestCnt = Integer.MAX_VALUE;
    private int bestCost = Integer.MAX_VALUE;

    public int minReviewCost(int n, int m, int[][] files, int[] cost) {
        this.n = n; this.m = m; this.files = files; this.cost = cost;
        this.full = (1 << n) - 1;
        dfs(0, new HashSet<>(), 0, 0);
        return bestCost;
    }

    // paper: 当前处理到第几篇；chosen: 已选教师集合；coveredMask: 已覆盖论文位掩码；curCost: 当前费用
    private void dfs(int paper, Set<Integer> chosen, int coveredMask, int curCost) {
        // 剪枝：人数已超最优，或人数持平但费用已超，直接回溯
        if (chosen.size() > bestCnt) return;
        if (chosen.size() == bestCnt && curCost >= bestCost) return;

        if (coveredMask == full) {                           // 全部论文已覆盖
            if (chosen.size() < bestCnt
                    || (chosen.size() == bestCnt && curCost < bestCost)) {
                bestCnt = chosen.size();
                bestCost = curCost;
            }
            return;
        }
        if (paper == n) return;                              // 论文分配完但没全覆盖（一般不会走到）

        for (int t : files[paper]) {                         // 给当前论文选一位可评审教师
            boolean added = chosen.add(t);                   // 新教师才增加人数与费用
            int nextCost = curCost + (added ? cost[t] : 0);
            dfs(paper + 1, chosen, coveredMask | (1 << paper), nextCost);
            if (added) chosen.remove(t);                     // 回溯撤销
        }
    }
}
```

> ⚠️ 最坏仍是指数级 \(O(\prod |files[i]|)\)，但双关键字剪枝后通常远快于全枚举；作为中等数据 / 骗分的备选，`n`、`m` 都爆时才轮到它。

### 解法对比：n 与 m 谁小选谁

| 解法 | 复杂度 | 最优？ | 适用 |
|:---|:---|:---|:---|
| **子集枚举 + 位掩码**（解法一，首选） | \(O(2^m m)\) | ✅ | `m` 小（本题 m≤12） |
| **状压 DP（按论文集合）** | \(O(2^n m)\) | ✅ | `n` 小而 `m` 大时更优 |
| 回溯 + 剪枝 | 指数级（剪枝快） | ✅ | 中等数据 / 骗分 |
| 贪心（选性价比最高教师） | \(O(nm)\) | ❌ 仅近似 | `2^n`、`2^m` 都爆时兜底拿部分分 |

**如何选**：

- **`m` 小（≤ ~20）** → 解法一枚举教师子集（本题最优，代码最短）。
- **`n` 小而 `m` 大** → 解法二状压 DP，状态维度换成论文集合。
- **两者都不算太大但组合爆炸** → 解法三回溯 + 剪枝。
- **`n`、`m` 都爆** → 贪心近似，只能拿部分分（集合覆盖是 NP 难，贪心不保证最优）。

> 一句话：本题是**加权集合覆盖**——`m` 小枚举教师子集、`n` 小状压论文集合，**看 `n` 与 `m` 谁小就把谁放进指数**；双关键字用「高位人数 + 低位费用」打包成一个数，一次比较即可。
