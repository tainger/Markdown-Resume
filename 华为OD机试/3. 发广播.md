# 3. 发广播

> **难度**：🟡 中等 | **分值**：200 | **标签**：并查集、图 | **考点**：连通分量

## 题目描述

某地有 N 个广播站，站点之间有些有连接，有些没有。**有连接的站点在接收到广播后会互相发送**（信号可沿连接接力传播）。

为了节省成本，现在只手动开启部分站点。给定表示广播站连接关系的 `grid`（长度为 N 的字符串数组，构成邻接矩阵），返回**最少需要手动开启多少个站点**，才能让所有站点都收到广播。

> 第 i 行第 j 个字符为 `'1'` 表示站点 i 与站点 j 直接相连。

### 函数签名

```java
class Solution {
    public int minBroadcast(String[] grid) {
        // ...
    }
}
```

---

## 示例

### 示例 1

```
输入：grid = ["110", "110", "001"]
输出：2
```

**解释**：站点 0 和 1 互相连通（一组），站点 2 孤立（一组）→ 共 2 个连通分量，各开 1 个即可让全部站点收到广播。

---

## 提示

- `1 <= grid.length == grid[i].length <= 1000`
- 邻接矩阵是对称的（`a[i][j] == a[j][i]`），对角线一般为 `'1'`（自己连自己）
- 信号可以**间接传递**：0 连 1、1 连 2，则 0 与 2 也能通信
- 答案 = **连通分量个数**

---

## 思路

### 核心思想

问题本质是：求无向图的**连通分量个数**。每个连通分量只需手动开启 1 个站点。

两种做法：

| 方法 | 思路 | 复杂度 |
|:---|:---|:---|
| **并查集（推荐）** | 遍历矩阵，`a[i][j]=='1'` 就 union(i, j)；最后统计根节点个数 | \(O(N^2 \alpha(N))\) |
| BFS/DFS | 每个未访问节点出发遍历整个连通块，计数 | \(O(N^2)\) |

**并查集三步**：

```
1. 初始化：parent[i] = i
2. 合并：a[i][j] == '1' → union(i, j)
3. 计数：统计不同的根节点数量（用 Set 或再次路径压缩后数 parent[i] == i）
```

**逐步演示**（示例输入）：

```
矩阵:  0 1 0
       1 1 0
       0 0 1

初始化: parent = [0, 1, 2]

(0,1) 相连 → union(0,1): parent[1] = 0
(1,0) 相连 → union(1,0): 已同一集合，跳过
(2,2) 自己 → 跳过

根节点: 0（含 0,1）、2 → 2 个连通分量 → 输出 2 ✓
```

class Solution {

        // 1. 并查集：i < j 且 grid[i].charAt(j)=='1' 时 union

        //    注意：用 find(i) 而不是 parent[i] 入 Set

### 解法（Java，并查集）

```java
import java.util.*;

class Solution {
    private int[] parent;

    private int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]); // 路径压缩
        return parent[x];
    }

    private void union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra != rb) parent[rb] = ra;
    }

    public int minBroadcast(String[] grid) {
        int n = grid.length;

        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;

        for (int i = 0; i < n; i++) {
            for (int j = i + 1; j < n; j++) { // 只处理上三角即可
                if (grid[i].charAt(j) == '1') {
                    union(i, j);
                }
            }
        }

        // 统计根节点个数
        Set<Integer> roots = new HashSet<>();
        for (int i = 0; i < n; i++) {
            //find(i);是找根，不是parent[i]，parent[i]是直接父节点，不是根
            roots.add(find(i));
        }
        return roots.size();
    }
}
```

### 复杂度分析

- **时间复杂度**：\(O(N^2 \cdot \alpha(N))\)，遍历上三角矩阵 \(O(N^2)\) 次 union，每次近似 \(O(\alpha(N))\)。
- **空间复杂度**：\(O(N)\)，并查集 `parent` 数组与根集合。

> 💡 记忆口诀：**「最少开启数 = 连通分量数」**，看到矩阵 + 可达性，先想并查集。

## 个人总结

### 统计根节点数：`parent[i]` vs `find(i)`

最初想直接遍历 `parent` 数组去重统计根节点数，这是并查集最常见的坑之一。

#### 错误做法

```java
Set<Integer> roots = new HashSet<>();
for (int i = 0; i < n; i++) roots.add(parent[i]);  // ❌
System.out.println(roots.size());
```

#### 为什么错

`parent[i]` 不一定是根节点，可能是**中间节点**——因为路径压缩只发生在 `find` 调用时，没被 `find` 过的节点 `parent[i]` 仍指向它的直接父节点，而非真正的根。

#### 反例追踪（5 个节点）

按特定顺序 union（用本文件 union 实现 `parent[rb] = ra`）：

```
节点: 0 1 2 3 4
初始: parent = [0,1,2,3,4]

union(0,1): find(0)=0, find(1)=1 → parent[1]=0
  parent = [0,0,2,3,4]

union(2,3): find(2)=2, find(3)=3 → parent[3]=2
  parent = [0,0,2,2,4]

union(1,3): find(1)=0, find(3)=find(parent[3])=find(2)=2 → parent[2]=0
  parent = [0,0,0,2,4]
  ⚠️ parent[3] 还是 2！find(3) 调用时路径压缩只更新了 3→2 这条边的中间节点 2，
     把 parent[2] 改成 0，但 parent[3] 仍指向 2，没有直接指向根 0
```

##### 用 `parent[i]` 直接统计（错误）

```
parent = [0,0,0,2,4]
Set = {0, 0, 0, 2, 4} → 去重 = {0, 2, 4} → size = 3 ❌
```

实际连通分量是 `{0,1,2,3}` 和 `{4}` 共 **2 个**，这里算出 3 个，多算了 1 个。

##### 用 `find(i)` 统计（正确）

```
find(0) = 0
find(1) = 0
find(2) = 0
find(3) = find(2) = 0  ← 路径压缩顺便把 parent[3] 改成 0
find(4) = 4
Set = {0, 0, 0, 0, 4} → 去重 = {0, 4} → size = 2 ✓
```

#### 关键原理

`find` 做了两件事：
1. **递归找到真正的根**
2. **路径压缩**：把沿途节点的 `parent` 都改成根

而 `parent[i]` 只是一个「指针」，可能是中间节点。所以统计根节点数**必须经过 `find`**，否则会遗漏路径压缩未覆盖到的节点。

#### 修正方案一：`Set<find(i)>`（推荐）

```java
Set<Integer> roots = new HashSet<>();
for (int i = 0; i < n; i++) roots.add(find(i));
System.out.println(roots.size());
```

#### 修正方案二：全量压缩后数 `parent[i] == i`

```java
for (int i = 0; i < n; i++) find(i);      // 先全量压缩
int count = 0;
for (int i = 0; i < n; i++) if (parent[i] == i) count++;
System.out.println(count);
```

此写法等价于方案一，但前提是**必须先调一遍 `find(i)` 把所有节点压到根**。跳过这一步直接数 `parent[i] == i`，会落入和错误做法一样的陷阱。

#### 一句话记忆

> **统计根节点数 = `add(find(i))`，不是 `add(parent[i])`**。
> `parent[i]` 只是「你爸是谁」，`find(i)` 才是「你祖先是谁」——数祖先才能数对家族数。

#### 反思

- **并查集中 `parent[i]` 永远不等于「根」**：它只是「直接父节点」，只有经过 `find` 才能保证指向根。
- **路径压缩是惰性的**：只有被 `find` 访问过的节点才会被压平，未被访问的中间节点仍保持旧指针。
- **统计连通分量前，要么 `find` 每个节点入 Set，要么先全量 `find` 再数 `parent[i] == i`**，二选一，不能省。
