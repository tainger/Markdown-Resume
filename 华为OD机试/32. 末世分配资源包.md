# 32. 末世分配资源包（2026 新系统）

> **难度**：🔴 困难 | **分值**：200 | **卷次**：新系统 2026-08-12 | **标签**：二分查找、贪心 | **考点**：二分答案 + 贪心可行性检查（等价 LeetCode 410 分割数组的最大值）

## 题目描述

末世时代，政府为各地分配资源。现有资源分配表 `nums[n]`，要求按如下规则分配给 `k` 个营地：

1. 每个营地只分配**一段连续**的分配表；
2. 每个营地**至少分到一份**资源；
3. 所有的资源**必须全部分出**；
4. 分配方式：**尽量平均分配**，即让「得利最大的营地」获得的资源值**尽量小**。

求这个「最大营地所得」的最小值。

> 新系统（力扣模式）：无需处理输入输出，直接实现函数，`return` 结果即可。

**函数签名**：

```java
// nums: 资源分配表（长度 1~n），nums[i] ≥ 0
// k:    营地数量，1 ≤ k ≤ n
// 返回：把 nums 切成 k 段连续子数组后，「各段和的最大值」能达到的最小值
public int splitResource(int[] nums, int k)
```

## 示例

**示例 1**

```
输入：nums = [7,2,5,10,8], k = 2
输出：18
```

**解释**：一共有 4 种把数组分成 2 段的方法：

```
[7]        | [2,5,10,8]  → max(7, 25)  = 25
[7,2]      | [5,10,8]    → max(9, 23)  = 23
[7,2,5]    | [10,8]      → max(14, 18) = 18  ✅ 最优
[7,2,5,10] | [8]         → max(24, 8)  = 24
```

其中 `[7,2,5] | [10,8]` 的最大子段和为 `18`，是所有分法里最小的。

**示例 2**

```
输入：nums = [1,2,3,4,5], k = 2
输出：9
```

**解释**：`[1,2,3] | [4,5]`，最大段和 `max(6, 9) = 9`，无法更小。

**示例 3**

```
输入：nums = [1,4,4], k = 3
输出：4
```

**解释**：每段一个元素 `[1] | [4] | [4]`，最大段和为 `4`。

## 思路

### 核心思想

「让最大段和尽量小」——**答案越大越容易满足、越小越难满足**，具有**单调性**，是「**二分答案 + 贪心验证**」的经典信号。

- **二分谁**：二分「最大段和」这个答案 `x`（不是二分数组下标）。
- **搜索区间**：
  - 下界 `low = max(nums)`：每段至少装一个元素，最大段和不可能小于数组里的最大单个值。
  - 上界 `high = sum(nums)`：极端情况全部分给一段（`k=1`），最大段和就是总和。
- **验证函数 `canSplit(x)`**：贪心地从左往右累加，只要「当前段和 + 下一个数」会超过 `x` 就**另起一段**。数完后统计所需段数 `cnt`：
  - `cnt <= k` → 说明限制 `x` 够宽松，能在 `k` 段内装下 → `x` 可行，往小的方向收（`high = mid`）；
  - `cnt > k` → `x` 太小，段切得太碎、超了 `k` 段 → 不可行，往大的方向收（`low = mid + 1`）。

> **为什么贪心是对的**：固定上限 `x` 时，每段都尽量塞满再切，用的段数一定最少。若「最省段数」都 > k，那更没法在 k 段内完成 → 不可行；反之则可行。所以贪心求出的 `cnt` 就是判定 `x` 是否可行的充要条件。

### 二分收敛演示（示例 1，`nums=[7,2,5,10,8]`, `k=2`）

```
low = max = 10, high = sum = 32
mid=21 → 段:[7,2,5]=14,[10,8]=18 → cnt=2 ≤2 可行 → high=21
mid=15 → 段:[7,2,5]=14,[10]=10(加8=18>15切),[8] → cnt=3 >2 不可行 → low=16
mid=18 → 段:[7,2,5]=14,[10,8]=18 → cnt=2 ≤2 可行 → high=18
mid=17 → 段:[7,2,5]=14,[10]=10(加8>17切),[8] → cnt=3 >2 不可行 → low=18
low==high=18 → 返回 18 ✅
```

- 时间复杂度：\(O(n \log S)\)，`S` 为数组总和（二分 `log S` 次，每次验证 `O(n)`）
- 空间复杂度：\(O(1)\)

### 解法：二分答案 + 贪心验证

```java
public class Main {
    public int splitResource(int[] nums, int k) {
        int low = 0;                 // 下界 = 单个最大值
        long high = 0;               // 上界 = 总和，用 long 防和过大
        for (int num : nums) {
            low = Math.max(low, num);
            high += num;
        }

        // 二分「最大段和」这个答案，找满足 canSplit 的最小值
        while (low < high) {
            int mid = (int) (low + (high - low) / 2);
            if (canSplit(nums, k, mid)) {
                high = mid;          // mid 可行，尝试更小
            } else {
                low = mid + 1;       // mid 太小，放大
            }
        }
        return low;
    }

    // 每段和都 ≤ maxSum 的前提下，贪心切分所需最少段数是否 ≤ k
    private boolean canSplit(int[] nums, int k, int maxSum) {
        int count = 1;               // 至少一段
        int cur = 0;
        for (int num : nums) {
            if (cur + num > maxSum) {
                count++;             // 放不下了，另起一段
                cur = num;
                if (count > k) return false;   // 已超 k 段，提前失败
            } else {
                cur += num;
            }
        }
        return true;
    }
}
```

> 💡 记忆：**「最大值最小化 / 最小值最大化」→ 二分答案**。区间 `[max, sum]`，`canSplit` 贪心数段数，`cnt<=k` 收左、`cnt>k` 收右。
>
> ⚠️ 两个易错点：① 下界必须是 `max(nums)` 而非 `0`——某个数本身就比 `x` 大时任何分法都装不下；② `canSplit` 里 `count` 从 `1` 起（第一段已开），别从 `0` 起。

### 解法二：区间 DP（O(n²k)，通用框架 / 可求具体分法）

LeetCode 410 的正统 DP 解法。二分答案只给「最优值」，DP 则是通用框架，还能扩展到「输出具体分法」「带额外约束」等场景。

- **状态**：`dp[i][j]` = 把**前 `i` 个数**分成 `j` 段时，「最大段和」的最小值。
- **转移**：枚举最后一段的起点 `ip`（前 `ip` 个数分成 `j-1` 段，第 `j` 段为 `nums[ip..i-1]`）：
  `dp[i][j] = min( max(dp[ip][j-1], sum(ip..i-1)) )`
- **答案**：`dp[n][k]`；用前缀和 `O(1)` 取区间和。

```java
import java.util.*;

public class Main {
    public int splitResource(int[] nums, int k) {
        int n = nums.length;
        long[] pre = new long[n + 1];                 // 前缀和，pre[i]=前 i 个数之和
        for (int i = 0; i < n; i++) pre[i + 1] = pre[i] + nums[i];

        // dp[i][j]：前 i 个数分成 j 段的「最大段和」最小值；初值 +∞ 表示不可行
        long[][] dp = new long[n + 1][k + 1];
        for (long[] row : dp) Arrays.fill(row, Long.MAX_VALUE);
        dp[0][0] = 0;                                  // 0 个数分 0 段，代价 0

        for (int i = 1; i <= n; i++) {
            for (int j = 1; j <= Math.min(i, k); j++) {
                // 枚举最后一段 [ip..i-1] 的起点 ip（前 ip 个数已分成 j-1 段）
                for (int ip = j - 1; ip < i; ip++) {
                    if (dp[ip][j - 1] == Long.MAX_VALUE) continue;   // 前半段不可行则跳过
                    long lastSeg = pre[i] - pre[ip];                 // 最后一段的和
                    long cost = Math.max(dp[ip][j - 1], lastSeg);    // 取两部分的较大者
                    dp[i][j] = Math.min(dp[i][j], cost);             // 在所有切法中取最小
                }
            }
        }
        return (int) dp[n][k];
    }
}
```

> ⚠️ 本题 `n ≤ 1000`，\(O(n^2k)\) 最坏约 `10^9`，**可能卡时间**——所以本题首选二分答案。DP 的价值在「通用、可扩展、能回溯出具体分法」。

### 解法三：暴力递归（指数级，骗分兜底）

枚举第一段取到哪里，递归把剩余部分分成 `seg-1` 段，取「最大段和」的最小值。加记忆化 `memo[start][seg]` 即退化为上面的区间 DP。

```java
public class Main {
    public int splitResource(int[] nums, int k) {
        return dfs(nums, 0, k);
    }

    // 从下标 start 开始，还要分成 seg 段，返回「最大段和」的最小值
    private int dfs(int[] nums, int start, int seg) {
        int n = nums.length;
        if (seg == 1) {                       // 只剩一段：剩下的全给它
            int sum = 0;
            for (int i = start; i < n; i++) sum += nums[i];
            return sum;
        }
        int best = Integer.MAX_VALUE, cur = 0;
        // 第一段取 [start..i]，至少要给后面 seg-1 段各留一个元素
        for (int i = start; i <= n - seg; i++) {
            cur += nums[i];                                   // 第一段累加到 i
            int rest = dfs(nums, i + 1, seg - 1);             // 剩余分 seg-1 段
            best = Math.min(best, Math.max(cur, rest));       // 取该切法的最大段和
        }
        return best;
    }
}
```

> ⚠️ 复杂度指数级 \(O(\binom{n-1}{k-1})\)，只在 `n` 很小时能过，机考里用来抢小数据部分分；加 `memo[start][seg]` 记忆化后即变成 \(O(n^2k)\) 的 DP。

### 解法对比：二分答案 vs DP

| 解法 | 时间 | 空间 | 适用 | 推荐度 |
|:---|:---|:---|:---|:---|
| **二分答案 + 贪心**（首选） | \(O(n\log S)\) | \(O(1)\) | 本题最优，`n` 大也稳 | ✅ 首选 |
| **区间 DP** | \(O(n^2 k)\) | \(O(nk)\) | 通用、需输出具体分法时 | ✅ 必会 |
| 记忆化搜索 | \(O(n^2 k)\) | \(O(nk)\) | DP 的递归写法 | 会即可 |
| 纯暴力递归 | 指数级 | \(O(n)\) | `n` 极小 / 骗分 | 兜底 |

**如何选**：

- **只求最优值、`n` 大** → 二分答案（本题 `n≤1000`，\(O(n\log S)\) 轻松过，代码也短）。
- **要输出具体怎么分、或带复杂约束**（如每段元素个数受限）→ 区间 DP（二分难表达约束，DP 可在转移里自然加限制，并回溯出分割点）。

> 一句话：**「最大值最小化」优先二分答案**（快、短）；**需要方案或带约束时退回区间 DP**（通用但 \(O(n^2k)\) 慢些）。二者是这类分段问题的「快慢双解」，本质都在最小化最大段和。
