# 33. LLM 推理批次最大化（2026 新系统）

> **难度**：🟡 中等 | **分值**：100 | **卷次**：新系统 2026-08-12 | **标签**：贪心、排序 | **考点**：区间调度贪心（最多不重叠区间，等价 LeetCode 435 / 452）

## 题目描述

大语言模型推理时，显存中有一个 **KV Cache**，用于存储各请求的键值对。现有 `N` 个推理请求排队，第 `i` 个请求需要占用 KV Cache 中一段**连续位置** `[L_i, R_i]`。每个位置同一时间只能分配给一个请求。

请选出**尽可能多**的请求，使它们的区间**互不重叠**，从而最大化批次的吞吐量。

**补充说明**：`[1, 3]` 和 `[3, 5]` 被认为是**重叠**（端点相接算重叠）。

> 新系统（力扣模式）：无需处理输入输出，直接实现函数，`return` 结果即可。

**函数签名**：

```java
// requests: N 个请求，requests[i] = [L_i, R_i]，0 ≤ L_i ≤ R_i ≤ 10^9
// 返回：最多可选出多少个互不重叠的区间
public int maxBatch(int[][] requests)
```

## 示例

**示例 1**

```
输入：requests = [[1,3],[2,5],[4,7],[6,9],[8,10],[11,12]]
输出：4
```

**解释**：选 `[1,3]`、`[4,7]`、`[8,10]`、`[11,12]`，共 `4` 个区间互不重叠，为最大可行数。

**示例 2**

```
输入：requests = [[1,3],[2,4],[3,3],[4,4]]
输出：2
```

**解释**：选 `[1,3]`、`[4,4]` 共 `2` 个不重叠的区间。（`[3,3]` 与 `[1,3]` 端点相接，算重叠）

**示例 3**

```
输入：requests = [[3,5]]
输出：1
```

**解释**：只有 1 个请求，直接选中，个数为 1。

## 提示

- `1 <= N <= 10^5`
- `0 <= L_i <= R_i <= 10^9`
- **端点相接算重叠**：下一个区间必须满足 `L > 上一个选中区间的 R`（严格大于）。

---

## 思路

### 核心思想

「选最多互不重叠区间」是**区间调度贪心**的模板题：**按右端点升序排序，从左到右贪心地选右端点最小且不冲突的区间**。

- **为什么按右端点排序**：右端点越小，留给后面区间的空间越大，越可能多塞几个。这是经典的**「结束越早越好」**贪心（活动选择问题）。
- **选择规则**：维护上一个选中区间的右端点 `lastEnd`（初始为极小值）。遍历排序后的区间，只要当前区间的左端点 `L > lastEnd`（本题端点相接算重叠，用**严格大于**），就选中它，`count++` 并更新 `lastEnd = R`。

> **贪心正确性（交换论证）**：假设最优解没选「结束最早的区间 A」，那把它选中的第一个区间换成 A，A 结束更早 → 不会减少后续可选区间数，替换后解不会更差。所以每一步选结束最早的区间总是安全的。

### 端点相接的处理

题目明确 `[1,3]` 和 `[3,5]` **重叠**，所以判断条件是 `L > lastEnd`（严格）。
若题目说端点相接**不算重叠**（如 LeetCode 435 的某些变体），则用 `L >= lastEnd`。**这一个符号是本题最大的坑**。

### 逐步演示（示例 1）

```
按右端点排序（本例已有序）：[1,3][2,5][4,7][6,9][8,10][11,12]
lastEnd = -∞
[1,3]  : 1 > -∞  选 → count=1, lastEnd=3
[2,5]  : 2 > 3?  否 → 跳过（与[1,3]重叠）
[4,7]  : 4 > 3   选 → count=2, lastEnd=7
[6,9]  : 6 > 7?  否 → 跳过
[8,10] : 8 > 7   选 → count=3, lastEnd=10
[11,12]:11 > 10  选 → count=4, lastEnd=12
结果 = 4 ✅
```

- 时间复杂度：\(O(N \log N)\)（排序主导，遍历 \(O(N)\)）
- 空间复杂度：\(O(1)\)（原地排序，忽略排序栈）

### 解法：区间调度贪心（按右端点排序）

```java
import java.util.*;

public class Main {
    public int maxBatch(int[][] requests) {
        // 按右端点升序：结束越早，越能给后面腾空间
        Arrays.sort(requests, (a, b) -> Integer.compare(a[1], b[1]));

        int count = 0;
        long lastEnd = Long.MIN_VALUE;   // 上一个选中区间的右端点
        for (int[] req : requests) {
            // 端点相接算重叠 → 必须严格大于
            if (req[0] > lastEnd) {
                count++;
                lastEnd = req[1];
            }
        }
        return count;
    }
}
```

> 💡 记忆：**「最多不重叠区间」→ 按右端点排序 + 贪心选结束最早的**。这是活动选择/会议室问题的核心套路。
>
> ⚠️ 两个易错点：① 必须按**右端点**排序，按左端点排是错的（反例：一个大区间左端点最小却挤占全部空间）；② 端点相接是否算重叠决定用 `>` 还是 `>=`——本题算重叠，用**严格大于 `>`**。
