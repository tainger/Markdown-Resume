# 9. 数组组成的最小数字

> **难度**：🟢 简单 | **分值**：100 | **标签**：排序、字符串 | **考点**：拼接比较排序

## 题目描述

给定一个整型数组，请从该数组中**选择 3 个元素**组成**最小数字**并输出（如果数组长度小于 3，则选择数组中所有元素来组成最小数字）。

**输入描述**：一行，逗号分隔的整数（如 `3,32,321`）。

**输出描述**：由 3 个（或全部）元素拼接而成的最小数字。

## 示例

```
输入：
3,32,321
输出：
321323
```

**解释**：选 3 个元素共有 6 种排列：`332321`、`332132`、`323321`、`321332`、`321323`、`323213`，最小的是 `321323`。

**示例 2**（不足 3 个）

```
输入：
1,12
输出：
112
```

**解释**：只有 2 个元素，全选拼接：`112` 和 `121`，最小为 `112`。

---

## 提示

- 拼接比较不是按数值大小，而是按**字符串拼接后的大小**（如 `3` 与 `32`：`332 > 323`，所以 `32` 应排在 `3` 前面）。
- 选哪 3 个元素也有讲究：**先对全部元素按拼接规则排序，取前 3 个**。
- 题目默认元素为无前导零的正整数。

---

## 思路

### 核心思想

自定义排序规则（贪心）：

```
比较 a、b 时：拼接 a+b 与 b+a，谁小谁在前（字符串比较）
对全部元素排序 → 取前 3 个（不足 3 个全取）→ 直接拼接
```

**为什么先整体排序再取前 3 个是对的**：拼接比较排序是「全序关系」，排序后数组从头开始拼接就是全局最小拼接（这就是 LeetCode 179「最大数」的镜像问题，思路同款）。

**逐步演示**（`3,32,321`）：

```
比较:
  3 vs 32:  "332" vs "323" → 323 小 → 32 在前
  32 vs 321: "32321" vs "32132" → 32132 小 → 321 在前
排序后: [321, 32, 3]
取前 3 拼接: "321" + "32" + "3" = "321323" ✓
```

- 时间复杂度：\(O(n \log n)\)
- 空间复杂度：\(O(n)\)

### 解法（Java）

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        String[] nums = sc.nextLine().trim().split(",");

        // 拼接比较排序：a+b 小则 a 在前
        Arrays.sort(nums, (a, b) -> (a + b).compareTo(b + a));

        // 取前 3 个（不足 3 个全取）
        StringBuilder sb = new StringBuilder();
        int take = Math.min(3, nums.length);
        for (int i = 0; i < take; i++) {
            sb.append(nums[i]);
        }
        System.out.println(sb);
    }
}
```

> 💡 记忆：**「拼接最小数字」= 数组全排序 + 取前 k 个拼接**；排序键是 `a+b vs b+a`，不是数值本身。
>
> ⚠️ 若输入含负数或带前导零，规则会变（题目一般不会出现），以实际题意为准。
