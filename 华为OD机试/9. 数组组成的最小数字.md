# 9. 数组组成的最小数字

> **难度**：🟢 简单 | **分值**：100 | **标签**：排序、字符串、枚举 | **考点**：三元组枚举 + 拼接比较排序

## 题目描述

给定一个整型数组 `nums`，请从该数组中**选择 3 个元素**组成**最小数字**并返回（如果数组长度小于 3，则选择数组中所有元素来组成最小数字）。

### 函数签名

```java
class Solution {
    public String minNumber(int[] nums) {
        // ...
    }
}
```

---

## 示例

### 示例 1

```
输入：nums = [3, 32, 321]
输出："321323"
```

**解释**：选 3 个元素共有 6 种排列：`332321`、`332132`、`323321`、`321332`、`321323`、`323213`，最小的是 `321323`。

### 示例 2

```
输入：nums = [1, 12]
输出："112"
```

**解释**：只有 2 个元素，全选拼接：`112` 和 `121`，最小为 `112`。

---

## 提示

- `1 <= nums.length <= 100`
- `0 <= nums[i] <= 10^9`
- 拼接比较不是按数值大小，而是按**字符串拼接后的大小**（如 `3` 与 `32`：`332 > 323`，所以 `32` 应排在 `3` 前面）。
- 选哪 3 个元素有讲究：**不能**简单「全局排序取前 3」——可能漏掉总位数更少的三元组（见下方常见坑反例）。n ≤ 100 直接枚举所有 C(n,3) 三元组即可。
- 题目默认元素为无前导零的正整数。

---

## 思路

### 核心思想

n ≤ 3 时全选拼接；n > 3 时**枚举所有 C(n,3) 三元组**，每组内部按拼接规则排序后拼接，取所有候选里的最小值。

```
对每个三元组 {a, b, c}：
  ① 按 (x+y) vs (y+x) 对组内三元素排序
  ② 排序后顺序拼接成候选串
取所有候选串中的最小值（按「位数少者小，位数同则字典序」比较）
```

**逐步演示**（`3,32,321`，n=3 全选）：

```
三元组只有 1 组 {3, 32, 321}
组内排序:
  3 vs 32:   "332" vs "323" → 323 小 → 32 在前
  32 vs 321: "32321" vs "32132" → 32132 小 → 321 在前
排序后: [321, 32, 3]
拼接: "321" + "32" + "3" = "321323" ✓
```

- 时间复杂度：\(O(n^3)\)（枚举 C(n,3) 组，每组排序 O(1)）— n ≤ 100 约 16 万组，毫秒级
- 空间复杂度：\(O(n)\)

### 解法一（暴力枚举，严格正确）

```java
import java.util.*;

class Solution {
    public String minNumber(int[] nums) {
        int n = nums.length;
        String[] arr = new String[n];
        for (int i = 0; i < n; i++) arr[i] = String.valueOf(nums[i]);

        // n ≤ 3：全选拼接
        if (n <= 3) {
            Arrays.sort(arr, (a, b) -> (a + b).compareTo(b + a));
            StringBuilder sb = new StringBuilder();
            for (String s : arr) sb.append(s);
            return sb.toString();
        }

        // n > 3：枚举所有 3 元组合
        String best = null;
        for (int i = 0; i < n; i++)
            for (int j = i + 1; j < n; j++)
                for (int k = j + 1; k < n; k++) {
                    String[] t = {arr[i], arr[j], arr[k]};
                    Arrays.sort(t, (a, b) -> (a + b).compareTo(b + a));
                    String cand = t[0] + t[1] + t[2];
                    if (smaller(cand, best)) best = cand;
                }
        return best;
    }

    // 数字串比较（无前导零 ≡ 数值比较）：位数少者小；位数同则字典序
    private boolean smaller(String a, String b) {
        if (b == null) return true;
        if (a.length() != b.length()) return a.length() < b.length();
        return a.compareTo(b) < 0;
    }
}
```

### 复杂度分析（解法一）

- **时间复杂度**：\(O(n^3)\)，枚举 C(n,3) 三元组；n ≤ 100 约 16 万组，毫秒级。
- **空间复杂度**：\(O(n)\)，字符串数组。

### 解法二（OD 流传·贪心，n > 3 有偏差）

```java
import java.util.*;

class Solution {
    public String minNumber(int[] nums) {
        // 1. 将整数转为字符串数组
        String[] strs = new String[nums.length];
        for (int i = 0; i < nums.length; i++) {
            strs[i] = String.valueOf(nums[i]);
        }

        // 2. 自定义排序：比较 a+b 和 b+a
        Arrays.sort(strs, (a, b) -> (a + b).compareTo(b + a));

        // 3. 选择元素：如果长度 >= 3 取前 3 个，否则取全部
        int count = Math.min(3, strs.length);
        StringBuilder result = new StringBuilder();
        for (int i = 0; i < count; i++) {
            result.append(strs[i]);
        }

        return result.toString();
    }
}
```

### 复杂度分析（解法二）

- **时间复杂度**：\(O(n \log n)\)，排序主导。
- **空间复杂度**：\(O(n)\)，字符串数组。

> ⚠️ 解法二对 `n ≤ 3` 正确（含两个示例）；`n > 3` 时输出可能**偏大**——反例 `[3,32,321,1]`：解法二输出 `"132132"`（6 位，选 1,321,32），而真最小为 `"1323"`（4 位，选 1,32,3）。**若 OD 官方用例按此贪心输出设，本版能过；否则用解法一。**

> 💡 记忆：**「选 3 拼」最小数字 = 枚举三元组 + 组内拼接排序 + 取最小**；组内排序键是 `a+b vs b+a`，不是数值本身。
>
> ⚠️ 常见坑：
> 1. **别和 LeetCode 179「最大数」混**——179 是「用**全部元素**拼接」，全局排序 + 全拼接才正确；本题是「**选 3 个子集**」，全局排序后取前 3 **不保证最优**。
> 2. **反例** `nums = [3, 32, 321, 1]`：
>    - 「全局排序取前 3」→ 选 `1, 321, 32` → `"132132"`（6 位）
>    - 正解 → 选 `1, 32, 3` → `"1323"`（4 位，更小）
>    - 根因：子集选取不能贪心，不同三元组拼接结果**位数可能不同**，必须枚举比较。
> 3. **比较候选串按 `(位数, 字典序)`**，不能纯字典序——否则会误判 `"13213" < "1323"`（因前者是后者前缀），导致位数多的反而胜出。
> 4. 若输入含负数或带前导零，规则会变（题目一般不会出现），以实际题意为准。
