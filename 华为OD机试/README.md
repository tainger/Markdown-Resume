# 华为 OD 机试

华为 OD（Outsourcing Developer，外包开发岗）面试第一关：在线机考编程题。本目录收录高频真题 + 题解，全部用 Markdown 管理，与 `leetcode-hot100/` 同一套笔记风格。

> ⚠️ 本目录题目根据流传真题整理，**题目描述/分值可能随卷次（A/B/C/D/E 卷）和年份变化**，以实际考试题目为准。重点是掌握每道题背后的**考点**。

## 考试规则（常见版本）

| 项目 | 说明 |
|:---|:---|
| 题量与时长 | 3 道编程题，共 150 分钟 |
| 分值分布 | 第 1 题 100 分（简单）、第 2 题 200 分（中等）、第 3 题 300 分（困难） |
| 总分 | 600 分 |
| 通过线 | 一般要求 **150 分**以上（部分部门/岗位要求 200+），两道题全过更稳 |
| 语言 | Java / Python / C / C++ / JS / Go 任选 |
| 环境 | 在线 OJ 提交；**新系统（力扣模式）不提供本地编译器/IDE**，只能在网页内编写、靠「提交」看用例通过率；老系统注意**输入输出格式**（多行、空格分隔、可能带逗号/引号） |
| 硬性要求 | 通过机试才进入后续技术面/综面/HR 面；机试不通过有冷冻期（一般 3 个月后可重考） |

> 📌 **2026 年 4 月 1 日起切换「新系统」（力扣模式）**：不需要自己写输入输出解析，直接实现函数（类似 LeetCode）；难度较老系统明显降低；题库 = **旧题复用 + 新题**组合。备考优先级：新系统真题 > 老系统高频题（本目录 #17-#31 为新系统真题，老题对算法考点依然通用）。

### 答题策略

1. **先读全部 3 题**，5 分钟内判断难度，规划时间。
2. **100 分题必须拿下**（保底分），优先做，别一上来死磕 300 分题。
3. 200 分题是拉开差距的关键，常见考点：图论（并查集/BFS/拓扑排序）、贪心、动态规划。
4. 300 分题难在**读题 + 边界条件**，暴力解（部分用例过）也值得写。
5. 提交前务必自测：空输入、单元素、最大值溢出（用 `long`）、重复元素。
6. 新系统（力扣模式）题：先看清**函数签名**（参数类型/返回值），别写 `Scanner` 解析。

## 新版机试经验与教训（2026 力扣模式）

> 面向 **2026-04-01 起的新系统（力扣模式）**。新系统只需实现函数，不再手写输入输出解析，但也带来一套新的坑，下面按「变化 → 经验 → 教训」总结。

### 一、新旧系统的关键变化

| 维度 | 老系统（ACM 模式） | 新系统（力扣模式，2026-04 起） |
|:---|:---|:---|
| 输入输出 | 自己用 `Scanner`/`BufferedReader` 读、`System.out` 打印 | **直接实现函数**，框架传参、收返回值 |
| 主要失分点 | 输入解析写错（多行、逗号、引号、行尾空格） | **函数签名理解错**、边界与数据类型 |
| 难度 | 偏高，读题+解析耗时 | **整体下调**，更接近 LeetCode 中等 |
| 题库 | 高频老题 | **旧题复用 + 新题**（本目录 #17-#35） |
| 调试 | 本地跑 `main` 拼输入 | **无本地编译器/IDE**，只能网页内写 + 靠提交看用例通过率，边界要靠脑内推演 |

### 二、经验（做对了什么）

1. **优先刷新系统真题**：新系统难度下调，题型集中在数组/字符串/图论(BFS·并查集·拓扑)/二分答案/贪心/树形 DP，把本目录 #17-#35 吃透，覆盖面已足够。
2. **先看函数签名再动手**：确认参数类型（`int[]` / `int[][]` / `List` / `String`）和返回值，能省掉一整类解析 bug；返回 `List` 还是数组、下标从 0 还是 1，都要先定死。
3. **100 分题必拿、200 分题决胜**：新系统 100 分题基本是模板题（层序遍历、排序、哈希计数），务必零失误；200 分题（二分答案、区间调度贪心、树形 DP）是拉分点。
4. **数学建模优先于暴力**：如 #32 用「二分答案 + 贪心可行性检查」把 \(O(2^n)\) 压到 \(O(n\log S)\)；#33 区间调度按右端点排序贪心一次扫描 \(O(n\log n)\)。识别出模型比硬写快得多。
5. **在脑子里造边界用例过一遍**：新系统**不提供本地编译器/IDE**，只能在网页 OJ 里写、靠「提交」看用例通过率。所以要**手动在纸上/注释里推演**空数组、单元素、全相同、最大规模这些边界，别指望本地跑函数——写完先自查这些情形再提交。

### 三、教训（踩过的坑）

1. **溢出**：累加/乘积/前缀和一律先想 `long`（如 #32 资源总量、#28 积分累计），`int` 溢出是新系统最隐蔽的失分。
2. **边界与空输入**：空数组、`k=0`、`n=1`、目标层不存在（#34）、树为空（#35）——这些用例框架经常拿来卡人，写完先补判空。
3. **返回格式对不上**：题目要求**去重 + 升序**（#34）却直接返回原始顺序；要求返回 `List` 却返回 `int[]`；要求返回下标却返回值——签名和题干的输出约定必须逐字核对。
4. **贪心排序键搞错**：区间调度（#33）要按**右端点**升序而非左端点；#11 按身高体重排队要「身高降序 + k 升序」。排序键选错直接全错。
5. **树形 DP 状态不全**：#35「点亮战争迷雾」需要三状态（未覆盖/已覆盖未监控/已监控），只用两状态会漏情况；后序遍历向上返回时要带足够信息。
6. **别再写 `Scanner`**：新系统里写输入解析纯属浪费时间，还可能因为多读一行报错；直接用函数入参。
7. **卷次/分值会变**：同一题在不同卷次（A/B/C/D/E）分值可能不同（本目录 #12、#13 标 `*`），以考场实际为准，别纠结分值。

## 文档模板规范

每道题统一按以下模板（与 leetcode-hot100 一致，增加「分值」字段）：

```
# 题目名称
> **难度**：🟢/🟡/🔴 | **分值**：100/200/300 | **标签**：xxx | **考点**：xxx

## 题目描述 → ## 示例 → ## 提示 → ## 思路 → ## 代码 → ## 个人总结
```

约定：

## 华为 OD 技术题可以暴力骗分吗

**结论：能，而且应该。** 华为 OD 机考**按测试用例通过率给部分分**——不是全对才得分。所以「暴力骗分」不是投机取巧，而是正规且被鼓励的应试策略：**先用暴力/朴素解拿下能过的那部分用例，再有余力才去优化**。

### 一、为什么暴力有效（机制层面）

1. **部分分机制**：过 20% 用例就得 20% 的分。一道 200 分题，暴力过一半用例 = 稳拿 100 分，远比空着强。
2. **小数据用例先过**：测试用例通常从小规模、边界情形排到大规模。暴力解对**小数据完全正确**，能吃下前面一批用例的分。
3. **超时只影响大用例**：暴力在大数据上会 TLE，但**已通过的小用例分数照拿**，不会倒扣。

### 二、三条红线（踩了适得其反）

| 风险 | 说明 | 规避 |
|:---|:---|:---|
| **异常中断后续用例** | 某个用例抛异常（越界/空指针/除零），**后面的用例直接不执行**，通过率被封顶 | 暴力也要做**健壮性处理**：判空、边界、`try` 兜底，宁可返回错误答案也别抛异常 |
| **代码重复率 ≥ 80% 判作弊** | 直接照搬网上答案、或大段复制粘贴 | 暴力要**自己写**，可拆子函数降重复率 |
| **溢出伪装成「错误」** | 暴力里累加/乘积用 `int` 溢出，小用例也会错 | 该用 `long` 就用 `long` |

### 三、实战节奏建议

1. **先读完 3 题**，判断哪些能直接暴力拿满、哪些只能暴力骗部分分。
2. **100 分题争取正解满分**（多是模板题），别在这浪费时间。
3. **200/300 分题：先写暴力保底**（过小用例），提交拿分后，再看时间是否够优化到正解。
4. **提交前脑内过一遍边界**（空输入、单元素、最大值）——新系统无本地编译器，只能靠推演 + 判空/兜底代码确保暴力不会因异常中断，这是暴力骗分能否拿满部分分的关键。

> 一句话：**暴力是保底不是终点**——先用暴力锁住部分分（尤其确保不抛异常），再在剩余时间冲正解。过合格线，暴力骗分往往就是那临门一脚。
