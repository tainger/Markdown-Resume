# B+ 树（B+ Tree）

B+ 树是 B 树的改良版，也是**多路平衡查找树**，但做了两处关键改动：**数据只存在叶子节点**、**所有叶子用链表串成有序序列**。内部节点只当「索引路标」不存数据，因此扇出更大、树更矮；叶子链表让**范围查询**极其高效。它是 MySQL InnoDB、大多数关系型数据库索引的实际选择。刷题不直接考，但「为什么数据库索引用 B+ 树」是高频面试题。

---

## 一、B+ 树 vs B 树：两大改动

| 维度 | B 树 | **B+ 树** |
|:---|:---|:---|
| **数据存放** | 内部节点 + 叶子都存 | **只有叶子存数据**，内部节点仅存索引键 |
| **叶子连接** | 叶子间无联系 | **叶子用双向链表按序串联** |
| **键的冗余** | 每键只出现一次 | 内部节点的键在叶子中**再出现一次**（作路标） |
| **查询稳定性** | 命中内部节点即可提前结束 | 每次查找**都要走到叶子**，路径长度稳定 |

```
内部节点只存「路标键」，不存数据：
              [ 17 | 35 ]
             /     |     \
        [5|11]  [20|29]  [41|53]        ← 内部层，仅索引
        叶子层（存全部数据，且横向链成表）：
  [1|5|11] ⇄ [17|20|29] ⇄ [35|41|53|66] → null
        ↑ 范围查询：定位起点后沿链表顺序扫，无需回溯
```

---

## 二、为什么这样改更适合数据库

### 1. 内部节点不存数据 → 扇出更大、树更矮

内部节点只放「键 + 孩子指针」，一个磁盘页能塞下更多键 → 扇出更大 → 相同数据量下**树更矮 → 磁盘 I/O 更少**。

### 2. 叶子链表 → 范围查询 / 排序极快

`WHERE age BETWEEN 20 AND 40`、`ORDER BY`、分页，只需**定位起点叶子，然后沿链表顺序扫**，不必像 B 树那样反复回到上层中序遍历。这是 B+ 树相对 B 树最大的实战优势。

### 3. 查询性能稳定

所有查找都到叶子才结束，路径长度一致（都等于树高），**性能可预测**，利于数据库优化器估算代价。

---

## 三、核心操作（与 B 树的差异）

| 操作 | 说明 |
|:---|:---|
| **查找** | 从根沿路标下降，**一直走到叶子**才拿到数据（B 树可能中途命中） |
| **范围查找** | 定位下界所在叶子，**沿叶子链表向后遍历**直到超过上界 |
| **插入** | 插到叶子；叶子溢出则分裂，**中键的副本上提**到父节点（叶子仍保留完整键） |
| **删除** | 删叶子中的键；下溢则向兄弟借或合并，内部路标相应调整 |

> 与 B 树的关键差别：分裂时中键**复制**一份上提（叶子不删该键），保证叶子始终含全部数据。

---

## 四、复杂度分析

| 操作 | 时间 / I/O |
|:---|:---:|
| 单点查找 / 插入 / 删除 | \(O(\log_m n)\) |
| **范围查询 `k` 条** | \(O(\log_m n + k)\)：定位 + 沿叶子链表扫 |

> 单点操作与 B 树同阶，但因**内部扇出更大**，实际树更矮、常数更优；**范围/顺序访问**因叶子链表远胜 B 树。

---

## 五、易错点与理解要点

### 1. 数据只在叶子，内部节点是「路标」

内部节点的键**不指向数据**，只用于导航；同一个键会在叶子里再出现一次（冗余但必要）。

### 2. 每次查询都到叶子

B+ 树查找**不会中途命中返回**，路径长度恒定——这是「稳定」而非「变慢」。

### 3. 叶子链表是范围查询的灵魂

面试问「B+ 树为何适合区间查询/排序」，答案就是**有序叶子链表可顺序扫描**。

### 4. 与聚簇索引的关系

MySQL InnoDB 中，**主键索引的叶子直接存整行数据**（聚簇索引），二级索引叶子存主键值再回表——这都建立在 B+ 树叶子存数据的特性上。索引面试题见 [mysql/索引.md](../mysql/索引.md)。

---

## 六、一句话总结

B+ 树是「**数据全在叶子 + 叶子链成有序表**」的多路平衡树——内部节点只当路标使扇出更大、树更矮、I/O 更少，叶子链表让**范围查询和排序**顺序扫描即可；单点操作 \(O(\log_m n)\)、范围查询 \(O(\log_m n + k)\)，稳定可预测。这正是 MySQL InnoDB 等数据库索引选它而非 B 树、红黑树的根本原因。

## 七、对比总览

| 结构 | 数据位置 | 范围查询 | 典型用途 |
|:---|:---|:---|:---|
| 红黑树 / [BST](二叉搜索树.md) | 各节点 | 中序遍历 | 内存有序表 |
| [B 树](B树.md) | 所有节点 | 需回溯中序 | 部分文件系统 |
| **B+ 树** | **仅叶子 + 链表** | **叶子顺序扫，最优** | **MySQL InnoDB、多数关系型 DB 索引** |
| [跳表](跳表.md) | 各节点 | 底层链顺序扫 | Redis ZSet、内存有序结构 |
