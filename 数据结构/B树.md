# B 树（B-Tree）

B 树是一种**多路平衡查找树**：每个节点可存**多个键**、拥有**多个孩子**，所有叶子在**同一层**（绝对平衡）。它专为**磁盘/外存**设计——通过增大节点「扇出」压低树高，把磁盘 I/O 次数降到 \(O(\log n)\)。是数据库索引、文件系统的经典结构。算法刷题里几乎不直接考，但作为「为什么数据库用它」的原理必备。

---

## 一、为什么需要 B 树

**痛点**：二叉搜索树 / 红黑树每个节点只有 1 个键、2 个孩子，`n` 大时树很高。数据存磁盘时，**每下降一层就是一次磁盘 I/O**（比内存慢约 10 万倍），树高就是 I/O 次数——必须把树压矮。

**思路**：让一个节点存很多键、指向很多孩子（扇出大到几百上千），一个节点正好对应**一个磁盘页**。这样树高 `≈ log_m(n)`（`m` 是阶数），几百万条数据也只要 3~4 层。

```
一次磁盘 I/O 读入一整个节点（一页，含很多键）
        [ 17 | 35 ]                    ← 根：2 个键，3 个孩子
       /     |     \
 [5|11]  [20|29]  [41|53|66]           ← 每个节点多键，叶子齐平
```

---

## 二、核心定义（m 阶 B 树）

一棵 `m` 阶 B 树满足：

| 规则 | 说明 |
|:---|:---|
| **每个节点最多 `m-1` 个键、`m` 个孩子** | 「阶」限制扇出上界 |
| **除根外，每个节点至少 `⌈m/2⌉-1` 个键** | 保证节点半满，不浪费 |
| **键在节点内有序** | 节点内可二分 |
| **孩子指针分隔键** | 第 `i` 个孩子的所有键落在第 `i-1` 与第 `i` 个键之间 |
| **所有叶子在同一层** | 绝对平衡，这是 B 树的关键性质 |
| **数据存在所有节点** | 键（及对应数据）分布在内部节点和叶子（与 B+ 树的核心区别） |

## 三、三大操作（思想）

### 1. 查找

从根开始：在**节点内**对有序键二分，命中则返回；否则根据键落在哪个区间，沿对应孩子指针下降一层（一次 I/O），直到命中或到叶子。

### 2. 插入

先查找到应插入的叶子，插入后若该节点键数**超过 `m-1`**（溢出），则**分裂**：取中间键上提到父节点，左右两半成为两个节点。上提可能引起父节点继续分裂，最坏一路裂到根（树增高一层）。

```
向 [20|29|41] 插入 35（m=4，最多 3 键）→ 溢出 [20|29|35|41]
分裂：中键 35 上提，左 [20|29] 右 [41]
```

### 3. 删除

删除后若节点键数**低于下限**（下溢），先尝试向**兄弟借键**（旋转），借不到就与兄弟**合并**（可能拉下父节点一个键），合并可能引起父节点继续下溢，最坏一路合并到根（树降低一层）。

> 分裂与合并保证「所有叶子始终同层」这一平衡性。

---

## 四、复杂度分析

| 操作 | 时间 / I/O |
|:---|:---:|
| 查找 / 插入 / 删除 | \(O(\log_m n)\)，即树高级别的磁盘 I/O |
| 节点内查键 | \(O(\log m)\)（二分）或 \(O(m)\)（顺序） |

> 关键收益：**扇出 `m` 越大，树越矮，磁盘 I/O 越少**。这是「压低树高换取更少 I/O」的经典权衡，也是它优于红黑树用于外存的根本原因。

---

## 五、易错点与理解要点

### 1. B 树 ≠ 二叉树

「B」不是 Binary！它是**多路**平衡树，一个节点多键多孩子。

### 2. 阶 `m` 与键数、孩子数的关系

`m` 阶 = 最多 `m` 个孩子 = 最多 `m-1` 个键。别把两者混淆。

### 3. 平衡靠分裂 / 合并维持

不像 AVL/红黑树靠旋转，B 树靠节点**分裂与合并**保持所有叶子同层。

### 4. 数据分布在所有节点

B 树的键值数据**内部节点也存**，这点与 B+ 树（只在叶子存数据）截然不同——见 [B+树.md](B+树.md)。

---

## 六、一句话总结

B 树是**多路平衡查找树**：节点多键多孩子、所有叶子同层，用**大扇出压低树高**把磁盘 I/O 降到 \(O(\log_m n)\)，靠**分裂 / 合并**维持平衡——它是「内存里用红黑树、磁盘里用 B 树」的分水岭，数据结构原理和数据库索引都绕不开它。

## 七、对比与延伸

| 结构 | 键/孩子 | 数据位置 | 典型用途 |
|:---|:---|:---|:---|
| 红黑树 | 2 路 | 各节点 | 内存有序表（`TreeMap`） |
| **B 树** | 多路 | **所有节点** | 部分数据库/文件系统索引 |
| **B+ 树** | 多路 | **仅叶子**，叶子成链 | MySQL InnoDB 索引（见 [B+树.md](B+树.md)） |

> 相关：内存中的平衡查找见 [二叉搜索树.md](二叉搜索树.md)；概率型平衡替代见 [跳表.md](跳表.md)（Redis ZSet 用它而非 B+ 树）。
