# 哈希表（Hash Table / HashMap / HashSet）

哈希表通过**哈希函数**把「键」映射到数组下标，实现**平均 \(O(1)\) 的插入、删除、查找**。它是「**用空间换时间**」的第一反应——把「遍历找」变成「直接查」。刷题里出现频率最高：两数之和、去重、计数、缓存、前缀和配对，几乎都靠它把 \(O(n^2)\) 降到 \(O(n)\)。

---

## 一、核心原理

```
key ──哈希函数 hash(key)──▶ 数组下标 index ──▶ 存到 bucket[index]

  "abc" → hash → 5 → table[5]
  "xyz" → hash → 2 → table[2]
```

| 概念 | 说明 |
|:---|:---|
| **哈希函数** | 把任意键映射为数组下标，要求**均匀、快速、确定** |
| **哈希冲突** | 不同键映射到同一下标（鸽巢原理，必然发生） |
| **负载因子** | `元素数 / 桶数`，超阈值（Java 默认 0.75）就**扩容 rehash** |
| **扩容** | 桶数翻倍并重新分布，摊还后单次操作仍 \(O(1)\) |

### 冲突处理两大流派

| 方式 | 做法 | 代表 |
|:---|:---|:---|
| **链地址法（拉链）** | 每个桶挂一条链表/红黑树，冲突就往后挂 | Java `HashMap`（链表长度 ≥ 8 转红黑树） |
| **开放寻址法** | 冲突就按规则探测下一个空位 | ThreadLocalMap、部分 C++ 实现 |

---

## 二、Java 用法（刷题直接用）

```java
// HashMap：键值对
Map<Integer, Integer> map = new HashMap<>();
map.put(key, val);                       // 增/改 O(1)
map.get(key);                            // 查，不存在返回 null
map.getOrDefault(key, 0);                // 常用：不存在给默认值
map.containsKey(key);
map.merge(key, 1, Integer::sum);         // 计数神器：有则+1，无则置1
map.remove(key);

// HashSet：只存元素，去重 / 判存在
Set<Integer> set = new HashSet<>();
set.add(x);
set.contains(x);                          // O(1) 判存在
```

> 计数场景 `map.merge(k, 1, Integer::sum)` 或 `map.put(k, map.getOrDefault(k,0)+1)`，比手写判空简洁。

## 三、经典应用套路（全是高频）

### 1. 查找配对：两数之和（[1](../leetcode-hot100/1.%20两数之和.md)）

边遍历边把「已见过的数 → 下标」存进哈希，查 `target - x` 是否出现，\(O(n)\)。

```java
int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int need = target - nums[i];
        if (seen.containsKey(need)) return new int[]{seen.get(need), i};
        seen.put(nums[i], i);              // 记录值 → 下标
    }
    return new int[0];
}
```

### 2. 前缀和 + 哈希：和为 K 的子数组（[560](../leetcode-hot100/560.%20和为%20K%20的子数组.md)）

用哈希记录「各前缀和出现次数」，查 `preSum - k` 是否出现过，把区间和问题降到 \(O(n)\)。详见 [前缀和与差分.md](前缀和与差分.md)。

### 3. 计数 / 频率统计

- **[347 前 K 个高频元素](../leetcode-hot100/347.%20前%20K%20个高频元素.md)**：哈希计数 + 堆/桶排序。
- **[438 找字母异位词](../leetcode-hot100/438.%20找到字符串中所有字母异位词.md)**：定长数组（26 字母）当哈希，滑窗比对频率。

### 4. 去重 / 判存在：最长连续序列（[128](../leetcode-hot100/128.%20最长连续序列.md)）

`HashSet` 存全部数，只从「序列起点」（`num-1` 不在集合）向右扩展，整体 \(O(n)\)。

### 5. 缓存 / 记忆化

DP 记忆化、LRU（哈希 + 双链表）都以哈希做 \(O(1)\) 命中。

## 四、复杂度分析

| 操作 | 平均 | 最坏（大量冲突） |
|:---|:---:|:---:|
| put / get / remove / contains | \(O(1)\) | \(O(n)\)（退化为链，Java 转红黑树后 \(O(\log n)\)） |
| 遍历全部 | \(O(n)\) | \(O(n)\) |
| 空间 | \(O(n)\) | \(O(n)\) |

> 平均 \(O(1)\) 的前提是**哈希函数均匀**且**负载因子受控**；最坏情况（恶意/劣质哈希）会退化，Java 8 用红黑树把最坏压到 \(O(\log n)\)。

## 五、易错点与技巧

### 1. 自定义对象做 key 必须重写 `hashCode` 和 `equals`

两者要**一致**：`equals` 相等的对象必须 `hashCode` 相等，否则查不到。

### 2. 值可能为 0 / null，别用 `get` 判存在

`map.get(k)` 返回 `null` 既可能是「不存在」也可能是「存了 null」，判存在用 `containsKey`。

### 3. 用定长数组代替哈希（小字符集）

只含小写字母时用 `int[26]` 比 `HashMap` 更快更省，`c - 'a'` 当下标。

### 4. 遍历时不要增删

对 `map`/`set` 遍历中直接 `put`/`remove` 会抛 `ConcurrentModificationException`，用迭代器的 `remove` 或先收集后处理。

### 5. 前缀和哈希记得初始化 `map.put(0, 1)`

表示「空前缀和为 0 出现一次」，否则会漏掉从下标 0 开始的整段。

---

## 六、一句话总结

哈希表用哈希函数把键映射到下标，实现**平均 \(O(1)\)** 的增删查——它是「**空间换时间**」的招牌工具：查找配对、计数统计、去重判存在、前缀和配对、记忆化缓存，都靠它把暴力的 \(O(n^2)\) 打到 \(O(n)\)；用时记住「判存在用 `containsKey`、小字符集改定长数组、自定义 key 重写 `hashCode/equals`」。
