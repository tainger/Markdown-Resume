# 图（Graph）

图是由**顶点（Vertex）**和**边（Edge）**组成的数据结构 `G = (V, E)`，用来刻画对象之间的**多对多关系**。树是「无环连通图」的特例，链表是「每个节点至多一条出边的图」的特例——**图是最通用的关系型数据结构**，社交网络、地图导航、依赖调度、状态机都能用图建模。

---

## 一、基本概念与分类

| 概念 | 说明 |
|:---|:---|
| **顶点 / 边** | `V` 是顶点集，`E` 是边集，边连接两个顶点 |
| **有向图 / 无向图** | 边是否有方向。`a→b` 有向；`a—b` 无向（等价于 `a→b` + `b→a`） |
| **带权图 / 无权图** | 边上是否带权值（距离、费用、比值等） |
| **度（Degree）** | 无向图：连接该点的边数；有向图分**入度**（指入）和**出度**（指出） |
| **路径 / 环** | 顶点序列首尾相连为路径；起点=终点的路径为环。无环图（有向）称 **DAG** |
| **连通 / 连通分量** | 无向图任意两点可达即连通；极大连通子图为连通分量。有向图讲**强连通** |
| **稀疏图 / 稠密图** | `E ≈ V` 为稀疏；`E ≈ V²` 为稠密。决定用邻接表还是邻接矩阵 |

```
无向图                有向图                带权有向图
  A —— B              A ——> B              A --3--> B
  |  / |              ^      |             |        |
  | /  |              |      v             5        2
  C —— D              D <——  C             v        v
                                           C --1--> D
```

> 记住三组「特例关系」：**树 = 无环连通无向图**（`n` 点 `n-1` 边）；**链表 = 每点至多一条出边的图**；很多树题（如给 `edges` 不给 `TreeNode`）本质是「用图的输入格式表达一棵树」。

## 二、两种存储方式

### 1. 邻接矩阵（Adjacency Matrix）

`matrix[i][j]` 表示 `i → j` 是否有边（无权用 0/1，带权存权值）。

```
    A  B  C  D
A [ 0  3  5  0 ]
B [ 0  0  0  2 ]      matrix[A][B] = 3 表示 A→B 权 3
C [ 0  0  0  1 ]
D [ 0  0  0  0 ]
```

- **优点**：查询 `i→j` 是否有边 \(O(1)\)；实现简单；适合稠密图、Floyd 这类需要随机访问点对的算法。
- **缺点**：空间恒为 \(O(V^2)\)，稀疏图极其浪费；遍历某点所有邻居要扫一整行 \(O(V)\)。

### 2. 邻接表（Adjacency List）★ 最常用

每个顶点维护一个「邻居列表」。

```
A: [(B,3), (C,5)]
B: [(D,2)]
C: [(D,1)]
D: []
```

- **优点**：空间 \(O(V+E)\)，稀疏图省内存；遍历邻居只需 \(O(\deg)\)。**刷题首选**。
- **缺点**：查询 `i→j` 是否存在需扫 `i` 的列表 \(O(\deg)\)。

### 存储方式选择

| | 邻接矩阵 | 邻接表 |
|:---|:---:|:---:|
| 空间 | \(O(V^2)\) | \(O(V+E)\) |
| 查边 `i→j` | \(O(1)\) | \(O(\deg i)\) |
| 遍历邻居 | \(O(V)\) | \(O(\deg i)\) |
| 适用 | 稠密图、Floyd | **稀疏图（绝大多数刷题场景）** |

### 建图代码模板（Java，邻接表）

```java
int n = ...;                                    // 顶点数，编号 0 ~ n-1
List<List<int[]>> graph = new ArrayList<>();    // int[]{邻居, 权值}；无权图可用 List<List<Integer>>
for (int i = 0; i < n; i++) graph.add(new ArrayList<>());

for (int[] e : edges) {                         // edges[i] = {u, v, w}
    graph.get(e[0]).add(new int[]{e[1], e[2]}); // u → v
    graph.get(e[1]).add(new int[]{e[0], e[2]}); // 无向图才加这条反向边；有向图删掉
}
```

> 建图三问：① **有向还是无向**（无向要加反向边）；② **带权否**（带权存 `int[]{to, w}`）；③ **编号从 0 还是从 1**（决定数组开多大、下标怎么映射）。字符串顶点先用 `Map<String,Integer>` 映射成下标，见 [399 除法求值](../leetcode-hot100/399.%20除法求值.md)。

## 三、两大基础遍历：DFS 与 BFS

### 1. 深度优先搜索（DFS）——一条路走到黑

用**递归 / 栈**，沿一条路径深入到底再回溯。`visited[]` 防止在环里死循环（树无环可省）。

```java
void dfs(int u, List<List<Integer>> graph, boolean[] visited) {
    visited[u] = true;                          // 进点即标记
    // ...对 u 的处理...
    for (int v : graph.get(u)) {
        if (!visited[v]) dfs(v, graph, visited);
    }
}
```

- **适用**：连通分量、找路径 / 环、拓扑排序、回溯、树形结构遍历。
- **注意**：图很大（深度上万）时递归会**爆栈**，改用显式栈或 BFS。

### 2. 广度优先搜索（BFS）——一层层扩散

用**队列**，按距离起点由近到远逐层访问。**无权图最短路**首选。

```java
void bfs(int start, List<List<Integer>> graph, int n) {
    boolean[] visited = new boolean[n];
    Queue<Integer> queue = new ArrayDeque<>();
    queue.offer(start);
    visited[start] = true;                      // 入队即标记（关键！否则同点多次入队）
    int level = 0;
    while (!queue.isEmpty()) {
        int size = queue.size();                // 锁定当前整层
        for (int i = 0; i < size; i++) {
            int u = queue.poll();
            for (int v : graph.get(u)) {
                if (!visited[v]) {
                    visited[v] = true;
                    queue.offer(v);
                }
            }
        }
        level++;                                // 每处理完一整层 +1
    }
}
```

- **适用**：无权图最短路 / 最少步数、按层处理（如二叉树第 k 层、[岛屿数量](../leetcode-hot100/200.%20岛屿数量.md) 淹没）、拓扑排序（Kahn）。
- **关键技巧**：① **入队即标记**（不是出队才标记），否则同一点被多次入队；② 需要「分层」时循环开头先固定 `size = queue.size()`。

### DFS vs BFS 对照

| 维度 | DFS | BFS |
|:---|:---|:---|
| 数据结构 | 栈 / 递归 | 队列 |
| 访问顺序 | 尽可能深 | 尽可能广（逐层） |
| 最短路（无权） | ❌ 不保证 | ✅ 天然最短 |
| 找是否连通 / 环 | ✅ | ✅ |
| 内存 | 深度成正比 | 最宽层成正比 |
| 爆栈风险 | 有（深图） | 无 |
| 典型题 | 连通分量、回溯、拓扑（三色） | 最少步数、层序、拓扑（入度） |

> 时间复杂度都是 \(O(V + E)\)（每点每边各访问一次），空间 \(O(V)\)。

## 四、拓扑排序（Topological Sort）

针对 **DAG（有向无环图）**，把顶点排成线性序列，使每条边 `u→v` 都满足 `u` 排在 `v` 前。用于**依赖调度**：编译顺序、课程先修、任务编排。

### 1. Kahn 算法（BFS 入度法）★ 推荐

```java
int[] indegree = new int[n];
for (each edge u→v) indegree[v]++;              // 统计入度

Queue<Integer> q = new ArrayDeque<>();
for (int i = 0; i < n; i++) if (indegree[i] == 0) q.offer(i);  // 入度 0 先入队

List<Integer> order = new ArrayList<>();
while (!q.isEmpty()) {
    int u = q.poll();
    order.add(u);
    for (int v : graph.get(u)) {
        if (--indegree[v] == 0) q.offer(v);     // 删边后入度归 0 才入队
    }
}
// order.size() == n → 无环，order 即拓扑序；否则有环
```

### 2. DFS 三色标记法

节点三态：`0` 未访问、`1` 访问中（在当前递归栈上）、`2` 已完成。DFS 时若遇到状态 `1` 的节点 → **成环**。完成的节点逆序即拓扑序。

- **判环本质**：Kahn 靠「最终出队数 `< n`」（环上节点入度永远减不到 0）；DFS 靠「遇到访问中的祖先」。
- **应用**：[207 课程表](../leetcode-hot100/207.%20课程表.md)、210 课程表 II、802 找到最终安全状态。

### 3. 实际应用场景

核心就一句：**给「有依赖关系的任务」排出一个合法执行顺序**（每件事都排在它依赖的事之后）。凡是能抽象成「A 必须先于 B」的场景，都是它的用武之地。

| 领域 | 点 | 边（依赖） | 说明 |
|:---|:---|:---|:---|
| **编译构建**（Make / Maven / Gradle / Bazel） | 源文件、模块、jar | A 依赖 B → B 先编 | 决定编译顺序；有环 = 循环依赖直接报错 |
| **包管理器**（npm / pip / apt / Maven） | 软件包 | 依赖某版本的包 | 先装被依赖的包；环 = 依赖死锁 |
| **CI/CD 流水线**（GitHub Actions、Airflow DAG） | Job / Stage / 计算任务 | `needs` / `depends_on` / 上游产出 | 编排串行与并行 |
| **Excel / 表格公式重算** | 单元格 | `C1 = A1 + B1` → A1、B1 先算 | 循环引用检测 |
| **前端打包**（Webpack 模块图） | 模块 | import 关系 | 决定打包与 tree-shaking 顺序 |
| **项目管理**（PERT / 甘特图） | 工序 | A 完成才能开始 B | 拓扑序 + DP 求关键路径 |
| **编译器 / 运行时** | 类型、静态变量 | 定义 / 初始化依赖 | 类型推导、静态初始化、类加载顺序 |
| **数据库建表 / 导数据** | 表 | 外键引用 | 被引用的表先建 |
| **游戏科技树 / 制造 BOM** | 科技 / 零件 | 前置解锁 / 装配 | 先造零件、先解锁前置 |

### 4. 面试重点

1. **拓扑序揭示可并行性**：Kahn 算法每一轮「入度同时归零」的那批节点之间没有依赖，**可以并发执行**——这是「拓扑排序不只给顺序，还给并行度」的高频追问点。
2. **环检测往往比排序更重要**：几乎所有场景里，拓扑排序同时承担**检测循环依赖**的职责——构建循环依赖 = 编译报错、包管理环 = 无法确定安装顺序、Excel 循环引用 = `#REF`、资源等待图成环 = **死锁**。判环方式即上面两种（Kahn 看「出队数 `< n`」、DFS 看「遇到访问中的祖先」）。
3. **两种实现怎么选**：面试首选 **Kahn 入度法**——无递归爆栈风险、天然产出拓扑序、还能顺带输出「并行分层」；需要「逆拓扑序 / 判环同时做其它 DFS 逻辑」时用**三色 DFS**。
4. **一句话记忆**：**「有先后依赖、要排执行顺序、顺带查有没有循环依赖」→ 拓扑排序**；分层结果直接告诉你哪些能并行。

## 五、最短路算法总览

| 算法 | 适用 | 时间 | 一句话 |
|:---|:---|:---:|:---|
| **BFS** | 无权图 | \(O(V+E)\) | 层数即最短距离 |
| **Dijkstra** | 非负权 | \(O((V+E)\log V)\)（堆优化） | 每次贪心取当前最近的未确定点 |
| **Bellman-Ford** | 可含负权（能判负环） | \(O(VE)\) | 对所有边松弛 `V-1` 轮 |
| **SPFA** | 含负权（队列优化 BF） | 平均 \(O(kE)\)，最坏 \(O(VE)\) | Bellman-Ford 的队列优化 |
| **Floyd** | 全源、可负权（无负环） | \(O(V^3)\) | 枚举中转点 `k` 更新所有点对 |

### Dijkstra 模板（堆优化，非负权单源最短路）

```java
int[] dist = new int[n];
Arrays.fill(dist, Integer.MAX_VALUE);
dist[start] = 0;
// 小顶堆按距离排序：int[]{到达距离, 节点}
PriorityQueue<int[]> pq = new PriorityQueue<>((a, b) -> a[0] - b[0]);
pq.offer(new int[]{0, start});
while (!pq.isEmpty()) {
    int[] top = pq.poll();
    int d = top[0], u = top[1];
    if (d > dist[u]) continue;                  // 过期的旧记录，跳过
    for (int[] e : graph.get(u)) {              // e = {邻居 v, 权 w}
        int v = e[0], w = e[1];
        if (dist[u] + w < dist[v]) {            // 松弛
            dist[v] = dist[u] + w;
            pq.offer(new int[]{dist[v], v});
        }
    }
}
```

### Floyd 模板（全源最短路 / 传递闭包）

```java
// d[i][j] 初始为边权，无边为 INF，d[i][i]=0
for (int k = 0; k < n; k++)                     // 中转点 k 必须在最外层！
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++)
            if (d[i][k] + d[k][j] < d[i][j])
                d[i][j] = d[i][k] + d[k][j];
```

> Floyd 的「乘积版」用于 [399 除法求值](../leetcode-hot100/399.%20除法求值.md)：把「加权值」换成「乘边权」求任意两变量比值。**`k` 必须是最外层循环**——它代表「允许经过前 k 个点中转」的阶段，写错顺序结果就错。

## 六、并查集（Union-Find）——连通性利器

处理**动态连通性**（不断合并、频繁查询「是否同组」）的高效结构，近似 \(O(1)\)。

```java
class UnionFind {
    int[] parent, rank;
    int count;                                  // 连通分量个数
    UnionFind(int n) {
        parent = new int[n]; rank = new int[n]; count = n;
        for (int i = 0; i < n; i++) parent[i] = i;
    }
    int find(int x) {                           // 路径压缩
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }
    void union(int a, int b) {                  // 按秩合并
        int ra = find(a), rb = find(b);
        if (ra == rb) return;
        if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) rank[ra]++;
        count--;                                // 每合并一次，分量少一个
    }
}
```

- **两大优化**：路径压缩（`find` 时把节点直接挂到根）+ 按秩 / 按大小合并，二者叠加后单次操作近 \(O(\alpha(n))\)（反阿克曼，几乎常数）。
- **应用**：连通分量计数（547 省份数量）、判环（684 冗余连接）、[岛屿数量](../leetcode-hot100/200.%20岛屿数量.md)、Kruskal 最小生成树；带权并查集见 [399 除法求值](../leetcode-hot100/399.%20除法求值.md)。
- **DFS/BFS vs 并查集**：静态一次性求连通用 DFS/BFS 更直观；**动态频繁合并查询**用并查集更优。

## 七、最小生成树（MST）

在带权无向连通图中，选 `V-1` 条边连通所有点且**总权最小**。

| 算法 | 思路 | 时间 | 适用 |
|:---|:---|:---:|:---|
| **Kruskal** | 边按权升序，用**并查集**依次加不成环的边 | \(O(E\log E)\) | 稀疏图 |
| **Prim** | 从一点出发，用**小顶堆**每次并入最近的点 | \(O((V+E)\log V)\) | 稠密图 |

> 记忆：Kruskal「**选边**」+ 并查集判环；Prim「**选点**」+ 堆取最近，和 Dijkstra 结构神似（区别：Prim 存「到树的距离」，Dijkstra 存「到源点的距离」）。

## 九、易错点与技巧

### 1. 建图先问三件事：有向？带权？编号起点？

无向图必须加**双向边**（漏了反向边是最常见 bug，如 [399 除法求值](../leetcode-hot100/399.%20除法求值.md) 反向查询失败）；编号从 1 开始要么数组多开一位、要么统一 `-1` 映射。

### 2. BFS「入队即标记」，不是「出队才标记」

出队才标记会让同一节点在出队前被多个前驱重复入队，既慢又可能错。**标记时机 = 入队时**。

### 3. DFS 判环必须三色，两色不够

只有「访问 / 未访问」无法区分「祖先（成环）」和「已走完的安全分支」。必须用三态，只有遇到**「访问中(1)」**才是环。

### 4. Floyd 的中转点 `k` 必须最外层

`k` 是 DP 的阶段维度（允许经过前 k 个点），写到内层就读到未更新的值，结果错误。

### 5. Dijkstra 不能处理负权

贪心「已确定的点不再更新」在负权下失效——负边可能让已确定的点变得更短。有负权用 Bellman-Ford / SPFA。

### 6. 无权图最短路用 BFS，别上 Dijkstra

无权即所有边权为 1，BFS 的层数就是最短距离，\(O(V+E)\) 比 Dijkstra 的 \(\log\) 更快、更简单。

### 7. 网格图（矩阵）是隐式图

上下左右四连通（或八连通）就是边，不必显式建图，用方向数组 `dirs = {{0,1},{0,-1},{1,0},{-1,0}}` 遍历即可，见 [岛屿数量](../leetcode-hot100/200.%20岛屿数量.md)。

## 十、一句话总结

图用**顶点 + 边**刻画多对多关系，稀疏用**邻接表**、稠密用**邻接矩阵**；**DFS / BFS** 是一切图算法的地基（无权最短路用 BFS）；有向无环靠**拓扑排序**调度；带权最短路按「非负→Dijkstra、含负→Bellman-Ford、全源→Floyd」选择；动态连通性用**并查集**，最小生成树用 **Kruskal / Prim**。
