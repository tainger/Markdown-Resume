# 并查集（Union-Find / Disjoint Set Union, DSU）

并查集是专门维护**「元素分组 / 连通性」**的数据结构，只做两件事：**合并（union）**两个集合、**查询（find）**某元素属于哪个集合（进而判断两元素是否同组）。配合**路径压缩**和**按秩合并**两大优化后，单次操作近乎 \(O(1)\)。它是处理「连通分量、等价类、动态连接」问题的利器，模板极短。

---

## 一、核心思想

每个集合用一棵树表示，树根作为该集合的「代表元」。判断两元素是否同组，就看它们的**根是否相同**。

```
初始：每个元素自成一组（自己是根）
  0   1   2   3   4        parent = [0,1,2,3,4]

union(0,1), union(2,3):
    0       2   4          parent = [0,0,2,2,4]
    |       |
    1       3

union(1,3)（合并两棵树）:
        0        4         parent = [0,0,0,2,4]
       / \
      1   2
          |
          3
```

| 操作 | 含义 |
|:---|:---|
| **find(x)** | 找 x 所在集合的根（代表元） |
| **union(x, y)** | 把 x、y 所在的两个集合合并成一个 |
| **connected(x, y)** | `find(x) == find(y)` 即同组 |

---

## 二、基础实现

```java
class UnionFind {
    int[] parent;
    UnionFind(int n) {
        parent = new int[n];
        for (int i = 0; i < n; i++) parent[i] = i;   // 初始各自为根
    }
    int find(int x) {
        while (parent[x] != x) x = parent[x];         // 一路向上找根
        return x;
    }
    void union(int x, int y) {
        parent[find(x)] = find(y);                    // 一个根挂到另一个根下
    }
}
```

> 朴素版最坏会退化成链（\(O(n)\) 查找），需要下面两个优化。

---

## 三、两大优化（必背）

### 1. 路径压缩（Path Compression）

`find` 时把路径上所有节点**直接挂到根下**，树被压扁，后续查询几乎 \(O(1)\)。

```java
int find(int x) {
    if (parent[x] != x) parent[x] = find(parent[x]);  // 递归压缩：直接指向根
    return parent[x];
}
```

### 2. 按秩 / 按大小合并（Union by Rank / Size）

合并时**把矮树挂到高树下**，避免树越长越高。

```java
int[] rank;                    // 记录每棵树的高度（秩）
void union(int x, int y) {
    int rx = find(x), ry = find(y);
    if (rx == ry) return;
    if (rank[rx] < rank[ry]) parent[rx] = ry;         // 矮的挂到高的
    else if (rank[rx] > rank[ry]) parent[ry] = rx;
    else { parent[ry] = rx; rank[rx]++; }             // 等高则任挂一个，秩+1
}
```

### 3. 图解推演

用两个具体 case 分别走一遍上面两段代码的执行过程。

#### case A：路径压缩「查一次，压一路」

前提：经过若干次朴素 `union` 后，树退化成一条链。

```
    0                       parent = [0, 0, 1, 2]
    |                              下标: 0  1  2  3
    1
    |
    2
    |
    3     ← 查 3 要走 3→2→1→0，深度 O(n)
```

执行 `find(3)`，递归**下探**到根，再在**回溯**时把每个节点直接挂到根：

| 阶段 | 调用 / 回填 | `parent` 变化 |
|:---|:---|:---|
| 下探 | `find(3)`→`find(2)`→`find(1)`→`find(0)` | `parent[0]=0` 触底，返回根 0 |
| 回溯 | `parent[1] = 0` | `[0,0,1,2]`（本就是 0，不变） |
| 回溯 | `parent[2] = 0` | `[0,0,`**`0`**`,2]` |
| 回溯 | `parent[3] = 0` | `[0,0,0,`**`0`**`]` |

```
压缩前：           压缩后：
    0                 0
    |               / | \
    1              1  2  3    ← 1、2、3 全部拍平挂到根 0
    |
    2
    |
    3
```

> 这次 `find(3)` 顺手把整条路径拍平，之后再 `find(2)`、`find(3)` 都一步到根 → 近乎 \(O(1)\)。

#### case B：按秩合并「矮挂高，树不长高」

前提：两棵高度不同的树，`union(3, 6)`。

```
树 A（根 0，rank=2）        树 B（根 5，rank=1）
        0                       5
       / \                      |
      1   2                     6
          |
          3
```

推演 `union(3, 6)`：

| 步骤 | 计算 | 结果 |
|:---|:---|:---|
| 求根 | `rx=find(3)=0`，`ry=find(6)=5` | 两根不同，继续 |
| 比秩 | `rank[0]=2 > rank[5]=1` | 命中 `rank[rx] > rank[ry]` 分支 |
| 挂接 | `parent[ry]=rx` 即 `parent[5]=0` | 矮树 B 挂到高树 A 根下 |
| rank | 不变，仍 `rank[0]=2` | 高度没增加 |

```
              0   (rank 仍 = 2，总高度还是 3)
            / | \
           1  2  5      ← 树 B 的根 5 挂到 0 下
              |  |
              3  6
```

**反例**：若「高挂矮」（`parent[0]=5`），树高会从 3 变成 4，`find` 多走一层——这正是按秩合并要避免的。

**等高分支**：若 `rank[rx]==rank[ry]`，走 `else`——任选一个当根、并 `rank[rx]++`（两棵等高树叠起来必然长高一层，秩要 +1）。

#### 两者配合

| 优化 | 时机 | 作用 |
|:---|:---|:---|
| 路径压缩（case A） | `find` 时 | 事后把路径**拍平** |
| 按秩合并（case B） | `union` 时 | 事前**矮挂高**控制树高 |

一个「事后拍平」、一个「事前控高」，叠加后单次操作摊还降到 \(O(\alpha(n)) \approx O(1)\)。

---

> **路径压缩 + 按秩合并**同时用，单次操作摊还复杂度为 **\(O(\alpha(n))\)**（阿克曼函数反函数，现实中 ≤ 4，视为常数）。刷题里通常「路径压缩」一项就够快。

## 四、经典应用套路

### 1. 连通分量计数（[200 岛屿数量](../leetcode-hot100/200.%20岛屿数量.md)）

把二维网格每个陆地格当节点，相邻陆地 `union`，最后统计**不同根的数量**即岛屿数。（也可用 DFS/BFS，见 [图.md](图.md)。）

### 2. 判断是否成环 / 冗余连接

无向图加边时，若两端点**已在同一集合**，这条边就构成环（如「冗余连接」题）。

### 3. 带权并查集（[399 除法求值](../leetcode-hot100/399.%20除法求值.md)）

在 `parent` 之外维护「到根的权值/比值」，`find` 时同步更新权值，可解「变量比值传递」类问题。

```
a/b=2, b/c=3  →  a、b、c 并入同一集合，记录各自到根的比值，查 a/c = 2*3 = 6
```

### 4. 等价类合并

账户合并、相似字符串分组等「传递性等价关系」都能建模成并查集。

---

## 五、复杂度分析

| 优化组合 | 单次 find/union 摊还 |
|:---|:---:|
| 朴素 | \(O(n)\)（可能退化成链） |
| 仅路径压缩 | 近似 \(O(\log n)\) |
| 仅按秩合并 | \(O(\log n)\) |
| **压缩 + 按秩** | **\(O(\alpha(n)) \approx O(1)\)** |

- 空间 \(O(n)\)（`parent`，可选 `rank`）。

---

## 六、易错点与技巧

### 1. 比较的是「根」不是元素本身

判同组、合并都要先 `find` 到根，不能直接比 `parent[x] == parent[y]`。

### 2. 二维网格要「降维」成一维下标

`(r, c) → r * cols + c`，把网格坐标映射到 `parent` 数组下标。

### 3. 路径压缩递归可能爆栈

`n` 极大时递归版 `find` 有栈风险，可改迭代（两趟：先找根，再回填）。

### 4. 带权并查集的权值要跟着压缩更新

路径压缩改指向根的同时，**必须把到根的累计权值一起更新**，否则查询出错。

### 5. 需要维护「集合数量」时，union 成功才减一

初始 `count = n`，每次 `union` 两个**不同**根成功合并才 `count--`。

---

## 七、一句话总结

并查集用「树根代表集合」维护动态连通性，只提供 **find / union** 两操作——判连通看**根是否相同**；靠**路径压缩 + 按秩合并**把单次操作压到近乎 \(O(1)\)；连通分量计数、判环、等价类合并、带权比值传递都是它的主场，模板短到能默写，是图连通类题的首选。
