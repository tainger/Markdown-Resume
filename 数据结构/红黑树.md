# 红黑树（Red-Black Tree, RBT）

红黑树是一种**自平衡的二叉搜索树**：在普通 [BST](二叉搜索树.md)「左小右大」的基础上，给每个节点染上**红或黑**，并用**五条颜色性质**约束「最长路径 ≤ 2×最短路径」，从而保证树高恒为 \(O(\log n)\)——彻底消除 BST「按序插入退化成链」的隐患。它是 Java `TreeMap`/`TreeSet`、C++ `map`/`set`、HashMap 桶内树化的底层结构，是「内存中的平衡有序表」首选。

---

## 一、为什么需要红黑树

**痛点**：普通 [BST](二叉搜索树.md) 的查找/插入/删除是 \(O(h)\)，`h` 为树高。随机插入时 `h ≈ log n`，但**按有序序列插入会退化成一条链**，`h = n`，操作退化到 \(O(n)\)。

```
按 1,2,3,4,5 顺序插入普通 BST：
1
 \
  2
   \
    3          ← 退化成链表，查找 O(n)
     \
      4
       \
        5
```

**思路**：插入/删除后通过**变色 + 旋转**把树「掰」回近似平衡。同类方案有 AVL 树（更严格平衡）和红黑树（近似平衡、旋转更少）——工程普遍选红黑树，因为**增删更快**。

| 方案 | 平衡程度 | 旋转次数 | 适用 |
|:---|:---|:---|:---|
| AVL 树 | 严格（左右高差 ≤ 1） | 增删旋转多 | 查多写少 |
| **红黑树** | 近似（最长 ≤ 2×最短） | **增删旋转少（O(1) 次）** | **增删频繁**（JDK 集合选它） |

---

## 二、五条核心性质

红黑树 = BST + 以下五条颜色约束：

1. **每个节点非红即黑**；
2. **根节点是黑色**；
3. **红节点的孩子必须是黑色**（即**不能有两个连续的红节点**）；
4. **从任一节点到其所有叶子（NIL 空节点）的路径，含相同数目的黑节点**（这个数目叫**黑高 black-height**）；
5. **叶子（NIL 空节点）视为黑色**。

```
              (13,B)                    B=黑  R=红
             /      \                   ← 根为黑（性质2）
         (8,R)      (17,R)              ← 红节点的孩子都是黑（性质3）
        /    \      /    \
    (1,B)  (11,B)(15,B) (25,B)          ← 每条到 NIL 的路径黑节点数相同（性质4）
     /  \    ...
   NIL  NIL                             ← NIL 视为黑（性质5）
```

> **为什么这五条能保证 \(O(\log n)\)**：性质 4 要求每条根→叶路径黑节点数相同（设为 `bh`）；性质 3 禁止连续红节点，所以红节点最多和黑节点一样多——**最长路径（红黑相间）≤ 2×最短路径（全黑）**。于是树高 `h ≤ 2·log(n+1)`，即 \(O(\log n)\)。

## 三、两大基本变换：变色与旋转

所有平衡修复都由这两个 \(O(1)\) 操作组合而成。

### 1. 变色（recolor）

直接翻转节点颜色（红↔黑）。变色不改变树的形状，只调整黑高分布，是最轻量的修复手段。

### 2. 旋转（rotation）——不破坏 BST 有序性

旋转只改动**局部指针**，且**保持中序遍历不变**（仍然左小右大），这是它能安全用于平衡的前提。

```
左旋 rotateLeft(x)：把 x 的右孩子 y 提上来当父，x 变成 y 的左孩子

      x                  y
     / \                / \
    a   y     ──►       x   c
       / \             / \
      b   c           a   b

      （b 从 y 的左子树，改挂到 x 的右子树；BST 有序性不变）
右旋 rotateRight 与之完全镜像。
```

```java
// 左旋：x 的右孩子 r 上位，x 降为 r 的左孩子
void rotateLeft(Node x) {
    Node r = x.right;
    x.right = r.left;                 // r 的左子树 b 改挂到 x 的右边
    if (r.left != null) r.left.parent = x;
    r.parent = x.parent;              // r 顶替 x 原来的位置
    if (x.parent == null)        root = r;
    else if (x == x.parent.left) x.parent.left = r;
    else                         x.parent.right = r;
    r.left = x;                       // x 成为 r 的左孩子
    x.parent = r;
}
```

## 四、插入：定位 + 染红 + 修复

**步骤**：① 像普通 BST 一样按大小找到空位挂上新节点；② **新节点一律染红**（红节点不增加黑高，破坏的性质最少）；③ 若父节点也是红（违反性质 3「连续红」），根据**叔叔节点的颜色**修复。

### 三种情况（以「父是祖父的左孩子」为例，右侧镜像）

| 情况 | 叔叔颜色 | 处理 | 效果 |
|:---:|:---:|:---|:---|
| **1** | **红** | 父、叔变黑，祖父变红 | 冲突「上移」到祖父，继续向上检查 |
| **2** | **黑**（当前是右孩子 LR） | 对父**左旋**，转成情况 3 | 降级为情况 3 |
| **3** | **黑**（当前是左孩子 LL） | 父变黑、祖父变红，对祖父**右旋** | 修复完成，退出 |

```
情况1（叔叔红）：只变色，问题上浮
        (G,B)                (G,R)←继续以G为新节点向上查
       /     \       ──►    /     \
    (P,R)   (U,R)        (P,B)   (U,B)
     /                    /
  (x,R)新               (x,R)

情况3（叔叔黑，LL）：变色 + 右旋，收工
        (G,B)                    (P,B)
       /     \       ──►        /     \
    (P,R)   (U,B)            (x,R)   (G,R)
     /                                  \
  (x,R)新                              (U,B)
```

> **口诀**：**叔红只变色（问题上浮），叔黑靠旋转（LL/RR 一次、LR/RL 两次，封顶 2 次旋转）**。最后别忘**根恒为黑**（性质 2）。

### 修复代码骨架

```java
void fixAfterInsertion(Node x) {
    x.color = RED;                                  // 新节点染红
    while (x != null && x != root && x.parent.color == RED) {
        if (parentOf(x) == leftOf(parentOf(parentOf(x)))) {   // 父是祖父的左孩子
            Node u = rightOf(parentOf(parentOf(x)));          // u = 叔叔
            if (colorOf(u) == RED) {                // 情况1：叔叔红 → 变色，问题上移
                setColor(parentOf(x), BLACK);
                setColor(u, BLACK);
                setColor(parentOf(parentOf(x)), RED);
                x = parentOf(parentOf(x));
            } else {
                if (x == rightOf(parentOf(x))) {    // 情况2：LR → 先左旋成情况3
                    x = parentOf(x);
                    rotateLeft(x);
                }
                setColor(parentOf(x), BLACK);       // 情况3：LL → 变色 + 右旋
                setColor(parentOf(parentOf(x)), RED);
                rotateRight(parentOf(parentOf(x)));
            }
        } else { /* 父是祖父的右孩子：完全镜像（叔叔在左、旋转方向相反） */ }
    }
    root.color = BLACK;                             // 性质2：根恒为黑
}
```

## 五、删除：后继替换 + 修复黑高

删除比插入更复杂，核心分两步：

**第一步（降级）**：若待删节点有**两个孩子**，先找**中序后继**（右子树最左节点，key 紧邻的下一个），把后继的 key/value 拷到当前节点，转为删除「至多一个孩子」的后继节点——问题降级。

**第二步（修复）**：
- 删的是**红节点** → 不影响任何路径的黑高，**无需修复**；
- 删的是**黑节点** → 该路径少一个黑节点（违反性质 4），产生一个「**双黑**」缺口，需通过「**向兄弟借黑**」的变色 + 旋转修复。

```
删除双黑修复的四种情况（简记）：
  兄弟红        → 旋转 + 变色，转为兄弟黑的情况
  兄弟黑+双侄黑 → 兄弟变红，缺口上移到父节点继续处理
  兄弟黑+近侄红 → 旋转 + 变色，转为远侄红情况
  兄弟黑+远侄红 → 旋转 + 变色，修复完成（封顶）
```

> 删除最多 **3 次旋转**（插入最多 2 次），都是 \(O(1)\) 次数，因此整体仍是 \(O(\log n)\)。删除是红黑树最烧脑的部分，面试能说清「后继替换降级 + 删黑才需修复 + 借兄弟的黑」即可，四种情况细节不必背死。

## 六、复杂度分析

| 操作 | 时间复杂度 | 说明 |
|:---|:---:|:---|
| 查找 | \(O(\log n)\) | 就是 BST 查找，树高有保证 |
| 插入 | \(O(\log n)\) | 查找定位 + 最多 2 次旋转 + \(O(\log n)\) 变色 |
| 删除 | \(O(\log n)\) | 查找 + 后继替换 + 最多 3 次旋转 |
| 中序遍历 | \(O(n)\) | 天然升序 |
| 空间 | \(O(n)\) | 每节点多存 1 bit 颜色 + parent 指针 |

> 与普通 [BST](二叉搜索树.md) 最坏 \(O(n)\) 相比，红黑树用「近似平衡」把**最坏情况也压到 \(O(\log n)\)**；旋转次数是 \(O(1)\) 常数，所以增删的额外开销很小。

## 七、红黑树的应用

| 场景 | 说明 |
|:---|:---|
| **Java `TreeMap` / `TreeSet`** | 有序 Map/Set 的底层，见 [TreeMap 源码分析](../java/TreeMap源码分析.md) |
| **Java `HashMap` 桶树化** | 链表长 ≥ 8 且容量 ≥ 64 时转红黑树，见 [HashMap 源码分析](../java/HashMap的应用场景和源码分析.md) |
| **C++ STL `map` / `set` / `multimap`** | 标准库有序关联容器 |
| **Linux 内核** | 进程调度（CFS 的 vruntime 红黑树）、虚拟内存区间管理 |
| **数据库 / 定时器** | 内存中的有序索引、事件按时间排序 |

> 一句话：**内存里要「有序 + 增删查都稳定 \(O(\log n)\)」，就用红黑树**；磁盘/外存则用扇出更大的 [B 树](B树.md) / [B+ 树](B+树.md)。

## 八、易错点与理解要点

### 1. 新节点为什么染红

红节点不增加所在路径的黑高，**破坏的性质最少**（只可能违反性质 3「连续红」，且局部可修）。若染黑则必然破坏性质 4（黑高不等），修复更麻烦。

### 2. 旋转不破坏 BST 有序性

旋转只是「换父子指针 + 挪一棵子树」，中序遍历结果不变——所以旋转后仍是合法 BST，只是形状变矮。

### 3. 别和 AVL 树混淆

AVL 靠「左右子树高差 ≤ 1」严格平衡、旋转更频繁；红黑树是「最长 ≤ 2×最短」的**近似平衡**，牺牲一点查询换取**更少旋转、更快增删**。JDK 集合选红黑树正是因为增删频繁。

### 4. 判重靠比较而非 equals

作为有序结构，红黑树用 `compareTo`/`Comparator` 的返回值定位与判重（返回 0 视为同一 key），**不看 `equals`/`hashCode`**——这是 `TreeMap` 与 `HashMap` 的本质区别。

### 5. 修复是「向上传播」的

插入情况 1、删除的「双黑上移」都可能把冲突一路带到根，最坏走 \(O(\log n)\) 层，但每层只做 \(O(1)\) 变色/旋转。

### 6. NIL 节点也算黑

性质 4/5 里的「叶子」指的是 NIL 空节点（哨兵），它们统一算黑色——计算黑高时别漏。

---

## 九、一句话总结

红黑树 = **BST + 五条颜色性质**：用「不能连续红 + 每条路径黑节点数相等」把树高钉死在 \(O(\log n)\)，插入靠「看叔叔颜色变色或旋转（封顶 2 次）」、删除靠「后继替换降级 + 删黑才修复黑高（封顶 3 次）」维持平衡——它以近似平衡换取比 AVL 更少的旋转，是内存中「有序 + 增删查稳定 \(O(\log n)\)」的黄金选择，也是 `TreeMap`/`TreeSet`、`HashMap` 树化、STL `map` 的共同底座。
