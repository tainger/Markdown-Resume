# 数据权限与多租户

> **P7 面试核心**：功能权限（RBAC）答完，面试官必追——「**用户只能看自己部门的数据怎么实现？多个公司共用一套系统数据怎么隔离？**」这是「行级数据权限」问题，也是水平越权的主战场。本文覆盖：数据范围五种模型 → 四种实现方案对比 → MyBatis 拦截器实战 → 多租户三层隔离 → 水平越权防护清单。

---

## 一、问题定位：数据权限 vs 功能权限

```
功能权限（能不能用这个功能）  → RBAC：order:delete 权限点 → 回答「能不能删订单」
数据权限（能用但能用多大范围）→ 行/列过滤：    → 回答「能删哪些订单」
```

| 类型 | 过滤对象 | 例子 | 实现层 |
|:---|:---|:---|:---|
| **行级** | 记录集合 | 只看本部门订单 | SQL WHERE / 拦截器 |
| **列级** | 字段 | 客服看不到手机号（脱敏）| DTO 裁剪 / 视图 |
| **字段级改写** | 值 | 工资脱敏显示 `12,***` | 序列化注解 |

## 二、数据范围模型（RBAC 扩展）

给角色加一个 `data_scope` 字段，五种档位（若依/RuoYi 等主流框架同款）：

| scope | 含义 | SQL 附加条件 |
|:---:|:---|:---|
| 1 | 全部数据 | 无 |
| 2 | 自定义部门集 | `dept_id IN (role 关联部门)` |
| 3 | 本部门 | `dept_id = user.deptId` |
| 4 | 本部门及以下 | `dept_id IN (deptId 及全部子部门)` |
| 5 | 仅本人 | `create_user = userId` |

```sql
-- 角色表扩展
ALTER TABLE sys_role ADD COLUMN data_scope TINYINT NOT NULL DEFAULT 1;
-- 自定义部门集：角色-部门关联表
CREATE TABLE sys_role_dept (role_id BIGINT, dept_id BIGINT, PRIMARY KEY(role_id, dept_id));
```

## 三、四种实现方案对比（核心考点）

| 方案 | 做法 | 优点 | 缺点 | 适用 |
|:---|:---|:---|:---:|:---|
| **① 手写 WHERE** | 业务代码每条 SQL 手动拼 `AND dept_id = ?` | 直观可控 | **每个 SQL 都要记得写，漏一处即越权**；代码侵入大 | 小项目 |
| **② MyBatis 拦截器（推荐）** | 拦截 SQL，用 JSqlParser 自动注入 WHERE | 业务零侵入、全局兜底 | 动态 SQL 复杂度（子查询/UNION）；调试难 | 中后台标配 |
| **③ 中间件/DB 层** | PostgreSQL RLS 行级安全、ShardingSphere 数据脱敏/SQL 改写 | 数据库级强制，绕不过 | 绑定特定 DB；策略配置成本 | 强合规、SaaS |
| **④ 应用层内存过滤** | 查全量后代码过滤 | 实现简单 | 性能灾难 + 分页失效 | ❌ 仅字典表级别小数据 |

### 方案② 拦截器原理（必能画）

```
Mapper SQL ──▶ MyBatis Interceptor(Executor/StatementHandler)
                    │
                    ├─ 1. 判定：方法/表是否在数据权限名单？线程上下文有无用户？
                    ├─ 2. 取当前用户数据范围（scope 3 → 本部门）
                    ├─ 3. JSqlParser 解析 SQL AST → SELECT 加 WHERE 条件
                    └─ 4. 替换 BoundSql，继续执行
```

```java
@Intercepts({@Signature(type = StatementHandler.class, method = "prepare",
              args = {Connection.class, Integer.class})})
public class DataScopeInterceptor implements Interceptor {

    @Override
    public Object intercept(Invocation invocation) throws Throwable {
        StatementHandler handler = (StatementHandler) invocation.getTarget();
        BoundSql boundSql = handler.getBoundSql();
        String sql = boundSql.getSql();

        DataScope ctx = DataScopeHolder.get();          // ThreadLocal 中的用户数据范围
        if (ctx != null && ctx.needFilter(sql)) {
            // 用 JSqlParser 给主表补 WHERE：dept_id IN (...) / create_by = userId
            Select select = (Select) CCJSqlParserUtil.parse(sql);
            PlainSelect ps = (PlainSelect) select.getSelectBody();
            ps.setWhere(and(ps.getWhere(), ctx.buildCondition()));
            ReflectUtil.setFieldValue(boundSql, "sql", select.toString());
        }
        return invocation.proceed();
    }
}
```

> 关键细节：**ThreadLocal 在请求结束必须 remove**（线程池复用导致串权限），放 Filter 的 finally 里清；子查询/JOIN 场景 JSqlParser 拼条件要做别名处理；报表类复杂 SQL 白名单绕过 + 单独审核。

## 四、列级权限与脱敏

```java
// 序列化时脱敏：Jackson 自定义序列化器
@Data
public class CustomerVO {
    @Sensitive(type = SensitiveType.PHONE)      // 138****5678
    private String phone;
    @Sensitive(type = SensitiveType.ID_CARD)    // 110***********1234
    private String idCard;
    @FieldAuth(perm = "salary:view")            // 无权限 → null
    private BigDecimal salary;
}
```

- 网关/日志层同理：**日志打印也要脱敏**（logback replace 正则 / MDC），否则日志库就是敏感数据泄露源。
- 面试延伸：加密存储（手机号 AES 加密 + 检索用 HMAC 哈希列）→ 见 [多租户设计](../mysql/多租户设计.md) 的敏感字段处理。

## 五、多租户（SaaS 一套系统服务 N 家公司）

### 5.1 三种隔离方案（必背对比）

| 方案 | 结构 | 隔离度 | 成本 | 适用 |
|:---|:---|:---:|:---:|:---|
| **共享库共享表**（tenant_id 字段） | 每张表加 `tenant_id` | ★ | 最低 | 中小 SaaS、租户量大数据少（千租户级）|
| **共享库独立 Schema** | 一个租户一个 schema | ★★ | 中 | 租户中等、合规要求中（百租户级）|
| **独立库/独立实例** | 租户独立数据库甚至独立集群 | ★★★ | 高 | 金融/大客户、强合规、数据不混存（十租户级）|

```
方案①（列隔离）              方案②（schema 隔离）         方案③（库隔离）
┌─────────────────┐      ┌──────┐ ┌──────┐          ┌──────┐   ┌──────┐
│ orders          │      │ db   │ │ db   │          │ db_A │   │ db_B │
│ id tenant_id .. │      │t_A.s │ │t_B.s │          │ orders│  │orders│
│  1    A         │      │orders│ │orders│          └──────┘   └──────┘
│  2    B         │      └──────┘ └──────┘          每租户独立实例
└─────────────────┘      同实例不同 schema
查询永远带 WHERE tenant_id=?   连接池按租户路由            按租户动态数据源
```

### 5.2 列隔离落地三件套

1. **每表必带 `tenant_id`**，且所有索引**最左前缀含 tenant_id**（`idx_tenant_status (tenant_id, status)`）。
2. **自动注入**：MyBatis-Plus `TenantLineInnerInterceptor` 自动拼 `tenant_id = ?`，业务无感知（同第二节的拦截器原理）。
3. **租户上下文**：登录时解析租户（域名/请求头 `X-Tenant-Id`）→ ThreadLocal 存 `TenantContext` → 拦截器读取。

```java
// MyBatis-Plus 列隔离：3 行配置全局生效
@Bean
public TenantLineInnerInterceptor tenantInterceptor() {
    return new TenantLineInnerInterceptor(new TenantLineHandler() {
        @Override public Expression getTenantId() {
            return new LongValue(TenantContext.getTenantId());   // 从 ThreadLocal 取
        }
        @Override public String getTenantIdColumn() { return "tenant_id"; }
        @Override public boolean ignoreTable(String table) {
            return Set.of("sys_config", "sys_dict").contains(table); // 全局表豁免
        }
    });
}
```

### 5.3 混合策略与难点

- **大客户独享 + 小客户共享**：按租户路由数据源（`AbstractRoutingDataSource` / 动态连接池），列隔离兜底小租户。
- **跨租户数据**（平台运营看全部）：豁免清单 + 超管上下文 + 审计日志。
- **租户级资源隔离延伸**：MQ tag/topic 隔离、Redis key 前缀 `tenant:{id}:...`、文件存储按租户分桶 → 单点故障不能互相拖垮（邻居效应）。

## 六、水平越权防护清单（安全面试必问）

| # | 防护 | 说明 |
|:---:|:---|:---|
| 1 | **资源归属校验** | `WHERE id = ? AND user_id = ?`（或 tenant_id/dept_id），先查再改不如带上条件直接改 |
| 2 | 禁止信任前端 id | 订单号用无规律 ID（雪花/UUID）防遍历；敏感资源不用自增 id 暴露 |
| 3 | 上下文取身份 | 服务端永远从登录态取 userId，**绝不信请求体里的 userId** |
| 4 | 拦截器兜底 | 数据权限在 SQL 层统一注入，不依赖每个业务自觉 |
| 5 | 越权测试用例 | 自动化：用 A 的 token 改 B 的资源 → 必须 403/404 |

---

## 七、易错点

1. **拦截器拼了 WHERE 却忘了分页 count**：MyBatis-Plus 分页 total 也走拦截器，注意 PageHelper 与自定义拦截器的执行顺序（数据权限拦截器优先级要更高）。
2. **ThreadLocal 泄漏**：线程池复用，租户/数据范围上下文不清理 = 下一个请求继承上个用户权限（严重事故）。
3. **UNION/子查询漏注入**：JSqlParser 只处理主查询，`UNION` 各分支都要拼；干脆复杂报表走白名单人工审。
4. **多租户索引没带 tenant_id**：百万租户数据下 `WHERE status = 1` 全表扫；列隔离的所有索引都要租户前缀。
5. **全局表误加租户条件**：字典/配置表被拦截器拼了 tenant_id 查出空数据 → 维护豁免清单。
6. **脱敏只做展示层**：日志、导出 Excel、RPC 返回都要过同一套脱敏规则，导出接口是最常见泄露口。

---

## 八、一句话总结

> **功能权限归 RBAC，数据权限归「范围模型 + SQL 自动注入」：角色 data_scope 定档位，MyBatis 拦截器 + JSqlParser 全局拼 WHERE（ThreadLocal 记得清理）；多租户首选列隔离（tenant_id + 索引前缀 + 自动注入），大客户升 Schema/独立库，越权防护靠「服务端身份 + 归属条件 + 拦截器兜底」三保险。**
