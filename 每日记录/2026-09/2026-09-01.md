## 复习要点

> 今天横跨算法 / Spring / MySQL 三条线，挑 7 条最有价值的收获。

1. **回文 DP 的两种等价表达**：合并式 `dp[i][j] = (s[i]=s[j]) ∧ (j-i<3 ∨ dp[i+1][j-1])`（短路 OR 折进方程）vs 分段式（base case 显式拆分 + 按长度填表）；len=3 依赖预填的 `dp[i][i]=true`——[5. 最长回文子串](../../leetcode-hot100/5.%20最长回文子串.md) 推导链 + 变体代码

2. **区间 DP 遍历顺序设计原理**：遍历顺序不是玄学，是被转移方程唯一确定的——每个格子的依赖箭头必须全部指向已算过的区域（拓扑序）；按长度枚举是「拓扑序显式」写法，零出错率——[5. 最长回文子串](../../leetcode-hot100/5.%20最长回文子串.md) 个人总结第 3 点

3. **LIS 贪心+二分的第一大坑**：严格递增用 lower_bound（≥，相等替换不追加），非递减用 upper_bound（>，相等追加），写反就错；tails 数组维护「长度 i 的 LIS 最小尾值」——[300. 最长递增子序列](../../leetcode-hot100/300.%20最长递增子序列.md)

4. **锁包事务而非事务包锁**：`@Transactional` 的 commit 在方法返回后（AOP 后置），`unlock` 在 finally 里（方法返回前）——事务包锁会产生「锁已释放但事务未提交」的窗口期导致超卖；解法是 Controller 外置锁或 `@DistributedLock` 切面 `@Order(0)` 放事务外层——[事务.md](../../Spring/事务.md) Q11

5. **explain 12 字段速背**：id 看执行顺序（同号上→下、不同号大值先）、type 看性能等级（至少 range）、key_len 算联合索引用了几列（变长+2、可空+1，突然变小=最左前缀断裂）、Extra 看 Using filesort/temporary 危险信号；深度排查 `format=json` 看成本、`optimizer_trace` 看索引决策——[explain详解.md](../../mysql/explain详解.md)

6. **InnoDB 加锁规则「两原则两优化」**：基本单位 Next-Key Lock（左开右闭）+ 访问到的对象才加锁；唯一索引等值命中退化为 Record Lock、非唯一索引向右遍历最后不满足值退化为 Gap Lock；RC 不加 Gap（除唯一约束/外键）——[锁机制深度.md](../../mysql/锁机制深度.md)

7. **数据类型选型六铁律**：主键一律 BIGINT、金额 DECIMAL 或 BIGINT 存分（禁 FLOAT 二进制误差）、能用 VARCHAR 不用 TEXT、时间默认 DATETIME（TIMESTAMP 2038 溢出）、字符集统一 utf8mb4、主键短而顺序（UUID 36 字节随机 → B+ 树频繁页分裂 + 二级索引撑大 4 倍）——[数据类型选型.md](../../mysql/数据类型选型.md)
