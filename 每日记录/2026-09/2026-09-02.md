## 复习要点

> 今天两大主题：**Redis 服务端 README 标准化 + Redisson Java 客户端全系列新建**，挑 7 条核心干货。

1. **Redisson = Netty NIO + 40+ 分布式对象，不是另一个 Jedis**：Jedis = BIO+无工具、Lettuce = 响应式但薄（无高级对象）、**Redisson = 企业级首选**（Starter + SpringCache 默认 + RLock/RLocalCachedMap/限流全开箱）——[核心架构与使用方式.md](../../redisson/核心架构与使用方式.md) 三选一对比表
2. **看门狗源码级三条铁律**：① 只有 leaseTime=-1 才开；② 每 `lockWatchdogTimeout/3 ≈ 10s` PEXPIRE 重设 30s；③ 续期任务跑在客户端 Netty HashedWheelTimer，实例挂了就不续 = 30s 后自然过期；**面试别只说「自动续期」要说源码入口 RedissonLock#scheduleExpirationRenewal**——[分布式锁全家桶原理.md](../../redisson/分布式锁全家桶原理.md)
3. **P7 红锁务实回答**：我知道 RedLock ≥N/2+1，但 Martin Kleppmann（时钟漂移/GC STW）质疑、性能折半 + 运维 N 套独立集群 → **工程上「单集群 RLock + 幂等 DB 唯一键兜底」性价比高得多**——这句话比「用红锁」像 P7 太多
4. **RLocalCachedMap 二级缓存是真金白银的优化**：本地 ConcurrentHashMap + Redis 远端；一致性靠 A 更新后 PUBLISH invalid 消息，其他实例删本地副本；项目里把商品详情 RMap 切到 RLocalCachedMap，**Redis QPS 8w→2w（-75%）、RT 1.8ms→0.1ms（-94%）**，面试讲数据 = P7 味道拉满——[分布式对象与集合API.md](../../redisson/分布式对象与集合API.md)
5. **🔴 事务包锁 = 空窗期并发脏写**（生产必翻车）：@Transactional AOP 在方法返回后才 commit，但 unlock 写在 finally（方法返回前）→ 锁放了、DB 还没提交 = 其他线程拿锁查到旧值超卖；**解法：切面 @Order(1) 事务外锁 或 Controller 层显式加锁**——[Spring集成与生产调优.md](../../redisson/Spring集成与生产调优.md) 有完整时序推演
6. **Spring Cache @Cacheable(sync=true) 背后就是 RLock**：同一个 key 并发过来，RedissonCacheManager 自动加分布式互斥锁，只让第一条线程查 DB+写缓存，其余 park 等 Pub/Sub → 防击穿零代码，不用手写 SETNX 重建逻辑——[Spring集成与生产调优.md](../../redisson/Spring集成与生产调优.md)
7. **redis/README 必背 28 条速记口诀**：快4原因（内存单线程IO多路复用高效结构）→ SDS4优势 → String三编码分界44 → listpack代ziplist → ZSet双结构缺一不可 → bgsave COW阻塞 → AOF写后日志 → 重写两缓冲区 → 混合持久化 → 过期三重兜底 → 8策略速记（-/allkeys × 4算法）→ 近似LRU采样 → LFU概率增+衰减 → 主从全量/增量三要素 → 最终一致 → 哨兵两阶段下线 + Raft选Leader + 选新主三依据 + ≥3奇数 → 16384槽（2KB心跳包）/ hash tag → 穿透=没数据 击穿=单热点过期 雪崩=集体失效 → 先更新库再删缓存 → 分布式锁五要素 + 看门狗续10s回30s → RedLock争议
