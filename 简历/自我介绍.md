## 常见追问预演

### Q：为什么从 Java 后端转向 AI 应用开发？

> AI 应用本质上还是工程问题——RAG 的召回优化、Agent 的工具编排、LLM 的流式交互，
> 都需要扎实的后端架构能力。我之前的 Java 后端经验不是被抛弃，而是 AI 应用落地的底座。
> 加上我自己对大模型方向有强烈兴趣，业余一直在做 LoRA 微调、RAG 实验，
> 所以 2024 年主动转型到 AI 应用开发方向。

### Q：你的 AI 项目和别人有什么不同？

> 区别在工程化深度。很多人做 RAG 就是调一下 LangChain，但我们是从 0 到 1 解决了
> 企业落地的真实问题：黑话同义词映射、切片不切断表格代码块、P0-P4 分级检索策略、
> LLM-as-Judge 回归测试守门、审计脱敏拦截 PII、pre/do/post 三态 Hook 防越权。
> 这些不是 demo 级别的实现，而是生产环境跑出来的。

### Q：Java 后端功底在 AI 项目中怎么体现？

> git worktree 并发隔离是典型例子——多任务同时编码操作同一仓库时，
> 共享工作树和 git index 会导致提交落错分支、文件互相覆盖。
> 我用 WorktreeManager 给每个任务分配独立 worktree，只对元数据操作加锁，
> 耗时的编码过程跑在锁外保留并行度，还提供异常降级回退。
> 这就是后端并发经验在 AI 工程中的直接应用。
