# 递归

**递归**：一个函数直接或间接调用自己，把一个问题转化为**规模更小的同类子问题**来求解。它是[分治](分治与递归.md)、[回溯](回溯.md)、树/图遍历、[动态规划](1.动态规划.md)（记忆化搜索）等一大批算法的**共同地基**。

> 本篇讲「递归本身怎么想、怎么写、怎么调试」；**分治、归并、快排、快速幂**等具体应用见 [分治与递归.md](分治与递归.md)，两篇互补。

---

## 一、递归三要素

一个正确的递归函数一定包含这三件事，缺一不可：

| 要素 | 作用 | 缺失后果 |
|:---|:---|:---|
| **终止条件（base case）** | 最小子问题不再递归，直接返回 | 缺失 / 写错 → 无限递归 → `StackOverflowError` |
| **递归关系** | 把问题**缩小一步**后调用自己 | 规模没变小 → 死循环 |
| **返回值处理** | 用子问题的解拼出当前问题的解 | 拼错 → 逻辑错误 |

```java
// 阶乘 n! —— 三要素齐全
long factorial(int n) {
    if (n <= 1) return 1;             // ① 终止条件：最小子问题
    return n * factorial(n - 1);      // ② 缩小规模 + ③ 用子解拼当前解
}
```

> **写递归的心法**：**相信递归会把子问题正确解决**（「递归假设」）。你只管写清楚「终止条件」和「如何用子问题的解拼出当前答案」，**不要试图在脑中展开整棵调用过程**——展开是给调试用的，不是给设计用的。

## 二、终止条件：代入边界值去测（你笔记的原点）

> **递归的终止条件可以代入边界去测试是否正确。**

终止条件是递归最容易写错的地方（漏写、边界差一、顺序放错）。最有效的检验方法：**把最小/临界输入直接代进去，看返回值对不对**。

### 检验清单

| 检验 | 问自己 | 例（阶乘 / 二叉树深度） |
|:---|:---|:---|
| **最小合法输入** | 代入后是否直接命中终止条件并返回正确值？ | `factorial(1)=1` ✅；`maxDepth(叶子)=1` ✅ |
| **空 / 越界输入** | `null`、`0`、`amount<0`、`lo>hi` 会不会漏判？ | `maxDepth(null)=0` 必须先判 ✅ |
| **终止条件的顺序** | 多个出口时，越界判断有没有排在访问之前？ | 先 `if(root==null)` 再访问 `root.val` |
| **会不会"过头"** | 缩小规模会不会跳过终止条件（如每次 -2 却只判 ==0）？ | 用 `<=` / `<` 兜底，别只写 `==` |

### 一个典型的终止条件 bug

```java
// ❌ 只判 == 0，当 amount 为负时永远命中不了，无限递归
if (amount == 0) return 0;

// ✅ 把"越界"也纳入终止条件（代入 amount<0 这个边界立刻发现问题）
if (amount == 0) return 0;
if (amount < 0)  return Integer.MAX_VALUE;   // 此路不通
```

> 这正是[完全背包/零钱兑换](例题/2.完全背包问题.md)里的经典处理：**代入 `amount<0` 这个边界**，就能测出「只写 `==0` 会漏掉越界分支」。**「代入边界值」= 用最小反例快速验证终止条件**，也是机考里查递归 bug 最快的手段。

## 三、递归树：看清「递归在算什么、慢在哪」

**递归树**把每一层递归调用画成树的节点，是分析递归**正确性、时间复杂度、重叠子问题**的核心工具。

### 画法

- **根**：最初的调用；
- **每个节点**：一次函数调用，其**孩子**就是它内部发起的子调用；
- **叶子**：命中终止条件的调用；
- **树高**＝递归深度＝调用栈最大高度（决定空间开销）。

### 例 1：斐波那契——递归树暴露「重叠子问题」

```java
int fib(int n) {
    if (n <= 1) return n;              // 终止
    return fib(n - 1) + fib(n - 2);   // 两个子调用 → 每个节点 2 个孩子
}
```

`fib(5)` 的递归树：

```
                fib(5)
              /        \
         fib(4)         fib(3)
        /     \        /     \
    fib(3)   fib(2)  fib(2)  fib(1)
    /   \     /  \    /  \
 fib2 fib1 fib1 f0 fib1 f0
```

一眼看出两个关键信息：

1. **`fib(3)` 被算了 2 次、`fib(2)` 被算了 3 次** → **子问题重叠** → 这是该上[动态规划/记忆化](1.动态规划.md)的信号；
2. 节点总数约 \(2^n\) → 时间复杂度 \(O(2^n)\)，指数级，会超时。

> **递归树是判断"分治 vs DP"的显微镜**：树里**没有重复节点** → 子问题独立 → [分治](分治与递归.md)；**出现重复节点** → 子问题重叠 → 加缓存变 DP，把 \(O(2^n)\) 降到 \(O(n)\)。

### 例 2：用递归树估时间复杂度

递归树的**节点总数 × 每个节点的工作量** = 总时间：

| 递归式 | 递归树形态 | 时间复杂度 | 例子 |
|:---|:---|:---|:---|
| \(T(n)=T(n-1)+O(1)\) | 一条链，n 层 | \(O(n)\) | 阶乘、链表递归 |
| \(T(n)=2T(n-1)+O(1)\) | 满二叉树，n 层 | \(O(2^n)\) | 裸斐波那契、子集枚举 |
| \(T(n)=2T(n/2)+O(n)\) | 二叉，\(\log n\) 层，每层总量 n | \(O(n\log n)\) | 归并排序 |
| \(T(n)=T(n/2)+O(1)\) | 一条链，\(\log n\) 层 | \(O(\log n)\) | 二分查找、快速幂 |

> 复杂度分析的通法（主定理）见 [分治与递归.md](分治与递归.md) 第四节。

## 四、递归的两种「时机」：先序 vs 后序

递归调用的前后各能插入逻辑，决定了「先处理当前、还是先处理子问题」：

```java
void recurse(Node node) {
    if (node == null) return;         // 终止条件
    // 【先序位置】：进入子问题之前处理当前 —— 自顶向下传递信息
    recurse(node.left);
    recurse(node.right);
    // 【后序位置】：子问题都解决后处理当前 —— 自底向上收集信息
}
```

| 位置 | 特点 | 典型用途 |
|:---|:---|:---|
| **先序**（递归前） | 当前节点信息还"新鲜"，向下传参 | 传路径、传深度、构造过程 |
| **后序**（递归后） | 已拿到左右子问题的解，向上合并 | 树的高度、路径和、[树形 DP](1.动态规划.md) |

> 很多树题的关键就是**想清楚逻辑该放先序还是后序**。求「子树聚合值」（高度/和/直径）几乎都在**后序**——因为要先有子问题的解才能算当前。

## 五、递归 vs 迭代（何时改写）

| 维度 | 递归 | 迭代（循环 / 显式栈） |
|:---|:---|:---|
| 可读性 | 树、分治、回溯问题更直观 | 线性问题更直观 |
| 空间 | 有调用栈开销 \(O(\text{递归深度})\) | \(O(1)\) 或自己控制的栈 |
| 风险 | 深度过大 → 栈溢出 | 无此风险 |
| 转换 | 可用**显式栈**模拟递归改成迭代 | — |

**什么时候必须改写成迭代？**

- 递归深度可能很大（如链表长 10⁵、退化成链的树）→ 栈溢出风险，改迭代或显式栈；
- 尾递归在 Java 里**不会**被自动优化（JVM 不做 TCO），线性深递归尤其危险。

> 例：链表反转、树的遍历都能在递归与「显式栈 / 迭代」之间互换。深度不可控时优先迭代。

## 六、写递归的通用模板

```java
返回类型 recurse(参数 表示"当前子问题") {
    // 1. 终止条件：最小子问题 / 非法输入，直接返回（记得代入边界验证！）
    if (到达边界) return 基准答案;

    // 2. （可选，先序）进入子问题前，处理/传递当前信息

    // 3. 递归解子问题（相信它会返回正确解）
    子解 = recurse(缩小后的参数);

    // 4. （后序）用子解拼出当前问题的解
    return 合并(当前, 子解);
}
```

**下笔前先回答四个问题**：

1. **子问题是什么**？参数怎么表示「更小的同类问题」？
2. **终止条件**是什么？代入最小/边界输入验证一遍。
3. 逻辑放**先序还是后序**？（向下传 or 向上收）
4. 子问题会不会**重叠**？会 → 加记忆化变 [DP](1.动态规划.md)；不会 → 纯[分治](分治与递归.md)。

## 七、常见坑点

| 坑 | 现象 | 对策 |
|:---|:---|:---|
| 终止条件漏 / 错 | `StackOverflowError` | 代入边界值测试（见第二节） |
| 规模没真正变小 | 死循环 / 栈溢出 | 确保每次递归参数**严格向边界靠近** |
| 越界判断放在访问之后 | `NullPointerException` | 先判 `null` / 越界，再访问 |
| 用返回值 `+1` 时溢出 | `MAX_VALUE + 1` 变负数 | 先判 `!= MAX_VALUE` 再运算（见[完全背包](例题/2.完全背包问题.md)哨兵复盘） |
| 该缓存没缓存 | 指数级超时 | 递归树出现重复节点 → 加 `memo` |
| 深度过大 | 栈溢出 | 改迭代 / 显式栈 |

## 九、一句话总结

> 递归 = **终止条件 + 缩小规模调用自己 + 用子解拼当前解**。写时相信「递归假设」，只管边界与合并；调试时**代入边界值验证终止条件**、**画递归树**看清复杂度与是否重叠——重叠就加缓存变 DP，不重叠就是分治。
