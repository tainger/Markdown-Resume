# 动态规划

动态规划（Dynamic Programming, DP）是一种通过**把原问题分解为重叠子问题**，并**保存子问题的解**来避免重复计算的算法思想。它的核心是「用空间换时间」：以斐波那契为例，暴力递归 `f(n)=f(n-1)+f(n-2)` 会把同一个子问题重复展开，时间是指数级的 \(O(2^n)\)、空间 \(O(n)\)（递归栈）；改成 DP 后每个子问题只算一次，时间降到 \(O(n)\)、空间 \(O(n)\)（记忆化数组），滚动优化后空间还能压到 \(O(1)\)。**代价是多用了一份 \(O(n)\) 的表来缓存中间结果**——这就是「用空间换时间」把 \(O(2^n)\) 优化成 \(O(n)\) 的由来。

---

## 一、什么问题能用 DP

一个问题能用动态规划求解，通常同时满足两个条件：

| 条件 | 含义 | 反例 |
|:---|:---|:---|
| **最优子结构** | 原问题的最优解可由子问题的最优解推出 | 有些贪心问题不满足 |
| **重叠子问题** | 子问题会被反复计算（否则直接分治即可） | 归并排序的子问题不重叠 |

> 判断口诀：**「能拆成子问题」+「子问题会重复」→ 考虑 DP**。如果子问题不重复，用分治；如果每步局部最优就能全局最优，用贪心。

## 二、DP 五步法

解 DP 题的标准流程，套用这五步能覆盖绝大多数题目：

| 步骤 | 关键问题 | 说明 |
|:---:|:---|:---|
| 1. 定义状态 | `dp[i]` 表示什么？ | 最难也最关键的一步，状态定义错则全错 |
| 2. 状态转移方程 | `dp[i]` 如何由更小的状态推出？ | DP 的核心递推关系 |
| 3. 初始化 | 边界状态的值是什么？ | 如 `dp[0]`、空串、第一行第一列 |
| 4. 遍历顺序 | 先算谁后算谁？ | 保证转移时依赖的状态已算出 |
| 5. 返回值 | 答案是 `dp[n]` 还是 `max(dp)`？ | 注意是「终点状态」还是「全局最优」 |

> 90% 的 DP bug 出在**状态定义**和**遍历顺序**上。写代码前先把这两步在纸上想清楚。

## 如何推演出状态转移方程

状态转移方程不是「背」出来的，而是**推**出来的。核心一句话：**盯住「最后一步」，讨论它的所有可能选择，把大问题拆成规模更小的同类子问题**。按下面五步走：

### 推演五步（可套用绝大多数题）

| 步骤 | 要做的事 | 打家劫舍（198）示范 |
|:---:|:---|:---|
| 1. 定义状态（先猜） | 用一句话说清 `dp[i]` 代表什么值，把「变量」放进下标 | `dp[i]` = 前 i 家能偷到的最大金额 |
| 2. 聚焦「最后一步」 | 只问：**最后一个元素/最后一个决策**有哪几种情况？ | 第 i 家：**偷** 或 **不偷** |
| 3. 对每种选择写出子问题 | 每个选择都会「剥掉一层」，落到更小的同类状态 | 偷 → `dp[i-2]+nums[i]`（隔一家）；不偷 → `dp[i-1]` |
| 4. 合并（取 max/min/求和） | 最优类取 max/min，计数类求和，判定类取 或/与 | `dp[i] = max(dp[i-1], dp[i-2]+nums[i])` |
| 5. 定边界与返回值 | 最小子问题的值 + 答案在哪个状态 | `dp[0]=0, dp[1]=nums[0]`；答案 `dp[n]` |

> **最关键的就是第 2、3 步——「最后一步分类讨论」**。想不出转移方程，99% 是因为没找对「最后一步该怎么分类」，或者状态定义没把变量都塞进去（状态漏维度）。

### 三个常用推演视角

- **「选或不选」视角**：每个元素只有取/不取两种 → 打家劫舍、0-1 背包、[416 分割等和子集](../leetcode-hot100/416.%20分割等和子集.md)。转移就是「不选（继承旧状态）」和「选（用更小容量/更前状态 + 当前收益）」取最优。
- **「以 i 结尾 / 枚举上一个」视角**：当前元素必须用上，往前枚举它能接在谁后面 → 最大子数组和、最长递增子序列（枚举 `j<i`）。
- **「枚举最后/中间的分割点」视角**：区间类，枚举「最后处理的元素」或「切成两半的位置 k」→ 戳气球、区间 DP。

### 推不出来时的自检清单

1. **状态定义漏了维度吗？** 如果转移时发现「还需要另一个信息才能算」，就把它加进状态（多开一维）。例：股票题要多记「是否持股」，打家劫舍 III 要返回「选/不选根」两个值。
2. **「最后一步」分类齐全吗？** 有没有漏掉某种选择？
3. **每个子问题都严格更小吗？** 否则会死循环 / 无法递推。
4. **先写暴力递归再抽象**：写不出方程时，先写朴素递归 `dfs(状态)`，跑通后把递归式原样搬成 `dp[...]`，再加边界——递归函数体本身就是转移方程。

## 如何在面试中和面试官沟通状态转移方程

面试考 DP，**讲清楚思路比直接写出代码更重要**。面试官想听的是你「怎么想到的」，按下面的顺序说，条理清晰又不容易卡壳：

### 推荐表达顺序（照着说）

1. **先判定为什么用 DP**：一句话点出「有最优子结构 + 重叠子问题」或「暴力递归会重复计算」，说明为什么不用贪心/分治。
2. **明确定义状态**：**先把 `dp[i]` 是什么用一句话说死**，特别强调是「前 i 个」还是「以 i 结尾」——这是面试官判断你有没有想清楚的关键。
3. **用「最后一步」推转移方程**：边说边分类——「考虑最后一个元素，它有 A、B 两种选择，A 对应……，B 对应……，取最优」，自然引出方程。
4. **交代边界和返回值**：`dp[0]` / 空串怎么初始化，答案是 `dp[n]` 还是 `max(dp)`。
5. **给复杂度**：状态数 × 单次转移，再提一句「能否用滚动数组把空间优化到 \(O(1)\)」——这是加分项。
6. **举个小例子手动走一遍**：用长度 3~4 的样例填一遍 dp 表验证方程，既自检又让面试官信服。

### 沟通话术模板

> 「我定义 `dp[i]` 表示**〈一句话状态〉**。考虑第 i 个元素的**最后一步**，它有〈几种〉选择：如果……那么由 `dp[…]` 转移；如果……那么由 `dp[…]` 转移。所以 `dp[i] = 〈max/min/求和〉(…)`。边界是 `dp[…] = …`，最终答案是 `dp[…]`。时间复杂度 \(O(…)\)，空间可以用滚动数组优化到 \(O(…)\)。」

### 沟通时的加分项与避坑

| 该做 ✅ | 该避 ❌ |
|:---|:---|
| 状态定义先说清「前 i 个 / 以 i 结尾」 | 上来就默写代码，不解释状态含义 |
| 先说暴力 → 再说 DP 优化，体现思考过程 | 卡在方程时沉默硬想（应边说边和面试官对齐） |
| 主动交代边界、遍历顺序、复杂度 | 忽略初始化和返回值，被追问才补 |
| 拿小例子手动验证 | 声称「肯定对」却不验证 |
| 卡住时先讲暴力递归/记忆化，保底拿分 | 一条路走到黑，不给退路 |

> 心态：**即使推不出最优方程，先把「暴力递归 + 记忆化」讲出来也是完整解法**（复杂度相同）。面试官更看重你能把问题结构讲清楚，而不是一步到位写出最优迭代版本。

## 三、DP 的两种实现方式

| 方式 | 别名 | 思路 | 优缺点 |
|:---|:---|:---|:---|
| **自顶向下** | 记忆化搜索 / 递归 + memo | 从原问题递归拆到子问题，用数组/哈希缓存已解子问题 | 好写、贴近思路；有递归栈开销 |
| **自底向上** | 递推 / 迭代填表 | 从最小子问题开始，用循环逐步填满 dp 表 | 无栈开销、可做空间优化；需想清遍历顺序 |

两者时间复杂度相同，面试中**自底向上**更常见，但**记忆化搜索更容易从暴力递归改写得到**（先写暴力递归，再加缓存）。

## 四、经典 DP 模型分类

DP 题万变不离其宗，主要分为以下几类：

### 1. 线性 DP

状态沿一个维度递推，`dp[i]` 只依赖 `dp[i-1]`、`dp[i-2]` 等。

| 题目 | 状态定义 | 转移方程 |
|:---|:---|:---|
| 爬楼梯（70） | `dp[i]` = 到第 i 阶的方法数 | `dp[i] = dp[i-1] + dp[i-2]` |
| 打家劫舍（198） | `dp[i]` = 前 i 家能偷的最大金额 | `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` |
| 最大子数组和（53） | `dp[i]` = 以 i 结尾的最大子数组和 | `dp[i] = max(dp[i-1] + nums[i], nums[i])` |

### 2. 背包 DP

在容量限制下选物品求最优。区分 0-1 背包（每物品选一次）和完全背包（可选多次）。

| 类型 | 内层循环方向 | 原因 |
|:---|:---|:---|
| 0-1 背包 | 容量 **从大到小** | 保证每个物品只被选一次 |
| 完全背包 | 容量 **从小到大** | 允许同一物品被重复选 |

- 转移方程（一维滚动数组）：`dp[j] = max(dp[j], dp[j - w[i]] + v[i])`

### 3. 区间 DP

`dp[i][j]` 表示区间 `[i, j]` 上的最优解，按**区间长度从小到大**枚举。

| 题目 | 状态定义 | 备注 |
|:---|:---|:---|
| [回文子串（647）](../leetcode-hot100/647.%20回文子串.md) | `dp[i][j]` = `s[i..j]` 是否回文 | `dp[i][j] = (s[i]==s[j]) && dp[i+1][j-1]` |
| 最长回文子串（5） | 同上 | 记录最长的 `j - i + 1` |
| 戳气球（312） | `dp[i][j]` = 戳破 `(i,j)` 开区间的最大硬币 | 枚举最后戳破的气球 |

### 4. 二维 / 网格 DP

在二维表格上递推，`dp[i][j]` 依赖上方、左方或左上方。

| 题目 | 状态定义 | 转移方程 |
|:---|:---|:---|
| 不同路径（62） | `dp[i][j]` = 到 `(i,j)` 的路径数 | `dp[i][j] = dp[i-1][j] + dp[i][j-1]` |
| 最小路径和（64） | `dp[i][j]` = 到 `(i,j)` 的最小和 | `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])` |
| 最长公共子序列（1143） | `dp[i][j]` = `s1[:i]` 与 `s2[:j]` 的 LCS 长度 | 见下方模板 |

### 5. 序列 DP（子序列问题）

| 题目 | 状态定义 | 转移方程 |
|:---|:---|:---|
| 最长递增子序列（300） | `dp[i]` = 以 i 结尾的 LIS 长度 | `dp[i] = max(dp[j]+1)`，`j<i && nums[j]<nums[i]` |
| 编辑距离（72） | `dp[i][j]` = `s1[:i]` 转 `s2[:j]` 的最少操作 | 增/删/改三者取 min |

### 6. 五类模型的本质区别

上面五类看着零散，但只要抓住三个维度——**状态维度、下标含义、枚举顺序**——就能看清它们的分界。核心差异在于**「`dp[i]` 从哪个方向、由哪些已算状态推来」**：

| 模型 | 状态维度 | `dp` 下标代表什么 | 转移依赖（来源方向） | 枚举顺序 | 本质特征 |
|:---|:---|:---|:---|:---|:---|
| 线性 DP | 一维 | **位置/阶段** i（前 i 个 或 以 i 结尾） | 相邻的 `dp[i-1]`、`dp[i-2]` | i 从小到大 | 沿单一时间轴推进，转移源**固定且相邻** |
| 背包 DP | 一维（压维后） | **剩余容量** j | `dp[j-w]`（同一维度更小容量） | 外层物品、内层容量（0-1 倒序 / 完全正序） | 下标是**资源约束**而非位置；靠循环方向控制「选一次/多次」 |
| 区间 DP | 二维 | **区间 `[i,j]`** | 更**短的子区间** `dp[i][k]`、`dp[k+1][j]` | 按**区间长度**从小到大 | 状态是一段区间，必须先算短区间；常枚举「分割点/最后操作的元素」 |
| 二维/网格 DP | 二维 | **两个独立位置** (i,j) | 上/左/左上 `dp[i-1][j]`、`dp[i][j-1]` | 逐行逐列 | 两个维度**各自独立推进**，转移源是网格邻居 |
| 序列 DP | 一维 或 二维 | 以 i 结尾 / 两串前缀 (i,j) | LIS 型看**所有更小的 j**；双序列型看 (i-1,j-1) 等 | i（或 i、j）从小到大 | 关注「子序列」关系，转移源**不一定相邻**（LIS 要回看全部前面） |

**一句话抓住每类的分界**：

- **线性 vs 序列**：都只有一个位置维度，但线性 DP 的 `dp[i]` **只看紧邻的前几个**（转移 \(O(1)\)）；序列 DP（如 LIS）的 `dp[i]` 要**回看前面所有的 j**（转移 \(O(n)\)），因为子序列可以跳着选。
- **一维背包 vs 线性 DP**：形式都像一维数组，但**下标含义不同**——线性 DP 下标是「位置」，背包下标是「容量/资源」；也正因如此，背包靠**内层循环方向**（倒序/正序）区分 0-1 与完全，这是线性 DP 没有的机关。
- **区间 DP vs 网格 DP**：都是二维 `dp[i][j]`，但**几何意义相反**——区间 DP 里 `i、j` 是**同一根轴上的两个端点**（i≤j，表示一段区间），依赖更短的区间，所以按**长度**枚举；网格 DP 里 `i、j` 是**两个正交维度的坐标**，依赖上/左邻居，所以按**行列**枚举。
- **区间 DP 的独特招式**：转移时通常**枚举「区间内最后处理/分割的那个点 k」**（如戳气球枚举最后戳破的气球、合并石头枚举分割点），这是其他模型没有的思维方式。

> 记忆锚点：**下标是「位置」→ 线性/网格；下标是「资源容量」→ 背包；下标是「区间端点」→ 区间；转移要「回看全部前缀」→ 序列（LIS 型）。** 判错模型 = 转移方程从一开始就写不出来。

## 五、代码模板（Java）

### 模板 1：线性 DP（打家劫舍 198）

```java
public int rob(int[] nums) {
    int n = nums.length;
    if (n == 0) return 0;
    int[] dp = new int[n + 1];
    dp[0] = 0;                          // 偷 0 家
    dp[1] = nums[0];                    // 只有 1 家
    for (int i = 2; i <= n; i++) {
        // 偷第 i 家（+dp[i-2]）或不偷（dp[i-1]），取最大
        dp[i] = Math.max(dp[i - 1], dp[i - 2] + nums[i - 1]);
    }
    return dp[n];
}
```

### 模板 2：0-1 背包（一维滚动数组）

```java
public int knapsack(int[] weight, int[] value, int capacity) {
    int[] dp = new int[capacity + 1];   // dp[j] = 容量 j 时的最大价值
    for (int i = 0; i < weight.length; i++) {
        // 0-1 背包：容量从大到小，保证每个物品只选一次
        for (int j = capacity; j >= weight[i]; j--) {
            dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }
    return dp[capacity];
}
```

### 模板 3：二维 DP（最长公共子序列 1143）

```java
public int longestCommonSubsequence(String s1, String s2) {
    int m = s1.length(), n = s2.length();
    int[][] dp = new int[m + 1][n + 1];  // dp[i][j] = s1[:i] 与 s2[:j] 的 LCS
    for (int i = 1; i <= m; i++) {
        for (int j = 1; j <= n; j++) {
            if (s1.charAt(i - 1) == s2.charAt(j - 1)) {
                dp[i][j] = dp[i - 1][j - 1] + 1;         // 字符相同，接在对角线后
            } else {
                dp[i][j] = Math.max(dp[i - 1][j], dp[i][j - 1]);  // 不同，取上/左较大
            }
        }
    }
    return dp[m][n];
}
```

### 模板 4：记忆化搜索（自顶向下）

```java
private int[] memo;

public int climbStairs(int n) {
    memo = new int[n + 1];
    Arrays.fill(memo, -1);              // -1 表示未计算
    return dfs(n);
}

private int dfs(int n) {
    if (n <= 2) return n;               // 边界
    if (memo[n] != -1) return memo[n];  // 命中缓存，避免重复计算
    memo[n] = dfs(n - 1) + dfs(n - 2);  // 递归 + 缓存
    return memo[n];
}
```

## 六、空间优化：滚动数组

当 `dp[i]` 只依赖前一两个状态时，可以把一维数组压成常数变量，或把二维压成一维。

**例：斐波那契 / 爬楼梯**

```java
// dp[i] = dp[i-1] + dp[i-2]，只需保留最近两个状态
public int climbStairs(int n) {
    if (n <= 2) return n;
    int prev2 = 1, prev1 = 2;           // dp[1], dp[2]
    for (int i = 3; i <= n; i++) {
        int cur = prev1 + prev2;
        prev2 = prev1;
        prev1 = cur;
    }
    return prev1;
}
```

> 空间从 \(O(n)\) 降到 \(O(1)\)。二维网格 DP 也常可从 \(O(mn)\) 压到 \(O(n)\)（只保留上一行）。

## 七、复杂度分析

| 维度 | 一般规律 |
|:---|:---|
| 时间复杂度 | ≈ **状态数 × 每个状态的转移代价** |
| 空间复杂度 | ≈ **状态数**，可用滚动数组优化 |

例如二维 DP 有 \(O(mn)\) 个状态，每个转移 \(O(1)\)，则时间 \(O(mn)\)、空间 \(O(mn)\)（可优化到 \(O(n)\)）。

## 八、易错点与技巧

| 易错点 | 说明 |
|:---|:---|
| **状态定义不清** | `dp[i]` 到底是「以 i 结尾」还是「前 i 个」？两者转移方程完全不同 |
| **边界初始化漏掉** | 空串、`dp[0]`、第一行第一列没初始化，导致越界或结果错 |
| **遍历顺序错** | 区间 DP 必须按长度递增；0-1 背包容量必须倒序 |
| **数组下标偏移** | `dp` 长度常取 `n+1`，注意 `nums[i-1]` 对应 `dp[i]` |
| **返回值取错** | 是 `dp[n]`（终点状态）还是 `max(dp)`（全局最优）要分清 |
| **滚动数组覆盖** | 压维后要注意更新顺序，别用到本轮已被覆盖的旧值 |

---

## 九、DP vs 其他算法

| 方法 | 适用信号 | 与 DP 的关系 |
|:---|:---|:---|
| **贪心** | 每步局部最优 → 全局最优 | DP 的特例，但**贪心无需保存所有子问题** |
| **分治** | 子问题**不重叠** | DP = 分治 + 记忆化 |
| **回溯** | 求**所有方案**而非最优值/计数 | 见 [回溯.md](回溯.md)；有时回溯 + 记忆化 = DP |

> 经验：看到「最优值 / 方案数 / 能否达到」且子问题重叠 → DP；看到「列出所有具体方案」→ 回溯。

---

## 十、一句话总结

动态规划的本质是**「记住走过的路」**——把重叠子问题的解存起来，用**状态定义 + 转移方程**把大问题拆成小问题递推求解。掌握「五步法」和「经典模型分类」，绝大多数 DP 题都能套路化解决。
