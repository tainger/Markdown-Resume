# 0-1 背包问题

> 动态规划最经典的入门模型。掌握它，就能理解一大批「选或不选」的 DP 题（如 [目标和 494](../leetcode-hot100/494.%20目标和.md)、分割等和子集 416）。

## 一、什么是 0-1 背包

有 `n` 件物品和一个容量为 `W` 的背包。第 `i` 件物品的**重量**是 `weight[i]`、**价值**是 `value[i]`。每件物品**只有一件**，要么放进背包（1），要么不放（0）——这就是「0-1」的含义。

**目标**：在不超过背包容量的前提下，装入物品的**总价值最大**。

> 关键限制：**每件物品最多用一次**。如果每件能用无限次，那是「完全背包」（另一种题型）。

### 举个例子

```
背包容量 W = 4
物品：  重量  价值
  0      1     15
  1      3     20
  2      4     30

问：怎么选，总价值最大且总重量 ≤ 4？
答：选物品 0 + 物品 1，重量 1+3=4，价值 15+20=35（最优）
```

---

## 二、为什么用动态规划

**暴力法**：每件物品选/不选，共 \(2^n\) 种组合，逐一检查——指数级，物品一多就爆炸。

**DP 的切入点**：0-1 背包满足动态规划的两个前提（详见 [动态规划.md](动态规划.md)）：

- **最优子结构**：「前 i 件物品、容量 j 的最优解」可由「前 i-1 件物品」的最优解推出
- **重叠子问题**：不同的选择路径会反复计算同一个「前 i 件 + 容量 j」子问题

于是用一张表把子问题的解存下来，避免重复计算，把 \(2^n\) 降到 \(O(n \times W)\)。

---

## 三、二维 DP：最容易理解的版本

### 1. 定义状态

$$
dp[i][j] = \text{从前 } i \text{ 件物品中选，放进容量为 } j \text{ 的背包，能得到的最大价值}
$$

### 2. 状态转移方程

对第 `i` 件物品（重量 `w = weight[i]`，价值 `v = value[i]`），只有两种选择：

- **不放第 i 件**：价值 = `dp[i-1][j]`（容量没变，还是前 i-1 件的最优解）
- **放第 i 件**（前提 `j >= w`）：价值 = `dp[i-1][j-w] + v`（腾出 w 的空间放它，加上它的价值）

取两者较大值：

$$
dp[i][j] = \max(dp[i-1][j],\ dp[i-1][j-w] + v)
$$

若 `j < w`（装不下第 i 件），只能不放：`dp[i][j] = dp[i-1][j]`。

### 3. 初始化

- `dp[0][j]`：只考虑第 0 件物品。`j >= weight[0]` 时能放，价值 `value[0]`；否则 0
- 也可加一行「0 件物品」的哨兵，全为 0，让转移方程统一

### 4. 填表演示（W=4，物品同上）

行 = 物品，列 = 容量 0~4：

```
        j=0   j=1   j=2   j=3   j=4
物品0    0    15    15    15    15      (重1价15：容量≥1都能放)
物品1    0    15    15    20    35      (重3价20：j=4 时 15+20=35)
物品2    0    15    15    20    35      (重4价30：j=4 放它=30 < 35，不划算)

答案 = dp[2][4] = 35
```

看 `dp[1][4] = 35` 怎么来的：
- 不放物品1：`dp[0][4] = 15`
- 放物品1：`dp[0][4-3] + 20 = dp[0][1] + 20 = 15 + 20 = 35`
- 取 max = 35 ✅

### 5. 二维代码

```java
public int knapsack(int[] weight, int[] value, int W) {
    int n = weight.length;
    int[][] dp = new int[n][W + 1];
    // 初始化第一行（只有物品 0）
    for (int j = weight[0]; j <= W; j++) {
        dp[0][j] = value[0];
    }
    for (int i = 1; i < n; i++) {
        for (int j = 0; j <= W; j++) {
            if (j < weight[i]) {
                dp[i][j] = dp[i - 1][j];                 // 装不下，只能不放
            } else {
                dp[i][j] = Math.max(
                    dp[i - 1][j],                        // 不放第 i 件
                    dp[i - 1][j - weight[i]] + value[i]  // 放第 i 件
                );
            }
        }
    }
    return dp[n - 1][W];
}
```

- 时间复杂度：\(O(n \times W)\)
- 空间复杂度：\(O(n \times W)\)

## 四、一维 DP：空间优化（重点）

观察二维转移方程：`dp[i][j]` 只依赖**上一行** `dp[i-1][...]`。既然只用到上一行，就可以用**一维滚动数组**覆盖更新，把空间从 \(O(n \times W)\) 降到 \(O(W)\)。

### 1. 一维状态

$$
dp[j] = \text{容量为 } j \text{ 的背包能装的最大价值}
$$

### 2. 一维转移方程

$$
dp[j] = \max(dp[j],\ dp[j - weight[i]] + value[i])
$$

- `dp[j]`（等号右边）：还没被本轮更新，相当于二维里的 `dp[i-1][j]`（不放）
- `dp[j - weight[i]]`：相当于 `dp[i-1][j-w]`（放）

### 3. 一维代码（注意内层倒序）

```java
public int knapsack(int[] weight, int[] value, int W) {
    int n = weight.length;
    int[] dp = new int[W + 1];                   // 初始全 0
    for (int i = 0; i < n; i++) {                // 外层遍历物品
        for (int j = W; j >= weight[i]; j--) {   // 内层容量【倒序】
            dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }
    return dp[W];
}
```

- 时间复杂度：\(O(n \times W)\)
- 空间复杂度：\(O(W)\)

## 五、最难理解的点：内层为什么必须倒序

这是 0-1 背包一维写法的**灵魂**，也是最容易出错的地方。

### 核心要求

`dp[j] = max(dp[j], dp[j-w] + v)` 里的 `dp[j-w]` 必须是**「上一轮（还没考虑第 i 件物品）」的值**，才能保证第 i 件物品**只被用一次**。

### 倒序（正确）

`j` 从大到小：算 `dp[j]` 时，`dp[j-w]`（下标更小）**本轮还没被更新**，还是旧值（上一行的）。✅

```
以物品重量 w=1 为例，W=4，倒序 j: 4→3→2→1
算 dp[4] 用 dp[3]（旧）
算 dp[3] 用 dp[2]（旧）
...每个 dp[j-1] 都还没动过，是上一轮的值
```

### 正序（错误 → 变成完全背包）

`j` 从小到大：算 `dp[j]` 时，`dp[j-w]`（下标更小）**本轮已经被更新过**了，是「已经放过第 i 件」的新值。于是第 i 件被**重复放入多次**——这就变成了「完全背包」（物品无限用）。❌

```
正序 j: 1→2→3→4，w=1
算 dp[1] = dp[0]+v      → 放了 1 次物品 i
算 dp[2] = dp[1]+v      → dp[1] 已含物品 i，又放一次 → 2 件！
算 dp[3] = dp[2]+v      → 3 件！  ← 物品被重复使用
```

> **一句话记忆：0-1 背包内层倒序（防重复），完全背包内层正序（允许重复）。**

## 六、0-1 背包的几种「问法」变体

背包模型不止「求最大价值」，同一套框架能解决多种问法，只需改**初始化**和**转移的运算**：

| 问法 | 状态含义 | 转移 | 初始化 |
|:---|:---|:---|:---|
| 最大价值 | `dp[j]`=容量 j 的最大价值 | `max(dp[j], dp[j-w]+v)` | `dp[*]=0` |
| **能否装满** | `dp[j]`=能否恰好装满 j | `dp[j] \|= dp[j-w]` | `dp[0]=true` |
| **装满的方案数** | `dp[j]`=装满 j 的方案数 | `dp[j] += dp[j-w]` | `dp[0]=1` |
| 装满的最少物品数 | `dp[j]`=装满 j 的最少件数 | `min(dp[j], dp[j-w]+1)` | `dp[0]=0`，其余 `∞` |

> [目标和 494](../leetcode-hot100/494.%20目标和.md) 用的就是「**装满的方案数**」变体：转移 `dp[j] += dp[j-num]`，初始化 `dp[0]=1`。

## 七、解题四步走（套路）

拿到一道疑似背包的题，按这个顺序想：

1. **识别背包**：是否「一组物品，每个选或不选，在某个容量限制下求最优/计数」？
2. **确定重量和价值**：谁是重量（受容量约束的量）？谁是价值（要优化的量）？
   - 有时「重量 = 价值」（如求子集和是否可达，见 416）
3. **选问法变体**：最大价值 / 能否装满 / 方案数 / 最少个数（见第六节表）
4. **写一维 DP**：外层物品、内层容量倒序，套对应转移方程

## 九、易错点清单

| 点 | 正确做法 | 反面 |
|:---|:---|:---|
| 内层遍历顺序 | 0-1 背包**倒序** | 正序 → 物品被重复用（变完全背包） |
| 遍历层次 | 外层物品、内层容量 | 求方案数时顺序还影响「排列 vs 组合」 |
| 内层下界 | `j >= weight[i]` 即可停 | 一直减到 0 会访问 `dp[负数]` |
| 初始化 | 按问法定（价值填 0、计数填 `dp[0]=1`） | 计数题忘了 `dp[0]=1` → 全 0 |
| 容量为负/非整 | 先剪枝（如 494 判奇偶、判越界） | 直接 `new int[负数]` 崩溃 |

## 十、一句话总结

> 0-1 背包 = **「每件物品选或不选，在容量约束下求最优」**。核心是状态 `dp[j]` + 转移 `dp[j]=max(dp[j], dp[j-w]+v)`，一维写法**内层容量必须倒序**以保证每件只用一次。学会它，再把「max」换成「+= / ||」，就能解决计数、可行性等一大批变体。
