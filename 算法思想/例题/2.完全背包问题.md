# 完全背包问题

> 背包模型的第二块基石。与 [0-1 背包](1.0-1背包问题.md) 只差**一处遍历顺序**，却能解决「零钱兑换」这类「物品可无限次选」的经典题。

## 一、什么是完全背包

有 `n` 种物品和一个容量为 `W` 的背包。第 `i` 种物品的**重量**是 `weight[i]`、**价值**是 `value[i]`。与 0-1 背包唯一的区别是：**每种物品有无限件，可以重复选取**。

**目标**：在不超过背包容量的前提下，装入物品的**总价值最大**（或按问法求方案数、最少个数等）。

> 关键区别：0-1 背包每件**最多用一次**；完全背包每种**可用无限次**。

### 贯穿本篇的例子（换零钱）

本篇用文件开头给出的「凑硬币」问题串起来讲：

> 给定 `n` 种面值的硬币 `c[0..n-1]`，以及总金额 `k`。每种硬币**无限供应**，求凑成 `k` 所需的**最少硬币数**；无法凑成返回 `-1`。

对照背包模型：**面值 = 重量**、**"1 枚硬币" = 单件代价**、**金额 k = 背包容量**。因为每种硬币能重复用，正是**完全背包**；又因为求「最少枚数」，属于背包的「**最少个数**」问法变体（见第六节）。

> 「**最少**」这个词是信号 → 最优化问题 → 天然适合动态规划。

---

## 二、为什么用动态规划

**暴力法**：每种硬币可以取 0、1、2… 枚，组合数随金额指数级膨胀。

**DP 的切入点**：和 0-1 背包一样满足两个前提（详见 [动态规划.md](../1.动态规划.md)）：

- **最优子结构**：「凑出金额 j 的最优解」可由「凑出更小金额」的最优解推出。
- **重叠子问题**：不同选法会反复计算同一个「凑出金额 j」子问题。

用一张表缓存子问题解，把指数级降到 \(O(n \times W)\)。

## 三、二维 DP：先理解，再优化

### 1. 定义状态

$$
dp[i][j] = \text{从前 } i \text{ 种物品中选（每种可重复），凑出容量 } j \text{ 的最优值}
$$

### 2. 状态转移方程

对第 `i` 种物品（重量 `w`、价值 `v`），关键差别来了——因为它能重复用：

- **不选第 i 种**：`dp[i-1][j]`
- **选第 i 种**（前提 `j >= w`）：`dp[i][j-w] + v`

注意选的那一项是 `dp[i]` 而**不是** `dp[i-1]`：因为选了一件之后，第 i 种物品**仍可继续选**，所以还停留在「前 i 种」这一层。

$$
dp[i][j] = \max(dp[i-1][j],\ dp[i][j-w] + v)
$$

> 对比记忆：0-1 背包选的是 `dp[i-1][j-w]+v`（用完就不能再用），完全背包选的是 `dp[i][j-w]+v`（用完还能接着用）。**差别就在下标 `i-1` 与 `i`。**

### 3. 二维代码

```java
public int knapsackComplete(int[] weight, int[] value, int W) {
    int n = weight.length;
    int[][] dp = new int[n][W + 1];
    // 初始化第一行（只有物品 0，可重复取）
    for (int j = weight[0]; j <= W; j++) {
        dp[0][j] = dp[0][j - weight[0]] + value[0];   // 注意用本行 dp[0][...]
    }
    for (int i = 1; i < n; i++) {
        for (int j = 0; j <= W; j++) {
            if (j < weight[i]) {
                dp[i][j] = dp[i - 1][j];                  // 装不下，只能不选
            } else {
                dp[i][j] = Math.max(
                    dp[i - 1][j],                         // 不选第 i 种
                    dp[i][j - weight[i]] + value[i]       // 选第 i 种（仍停留在第 i 层）
                );
            }
        }
    }
    return dp[n - 1][W];
}
```

- 时间复杂度：\(O(n \times W)\)
- 空间复杂度：\(O(n \times W)\)

## 四、一维 DP：空间优化（重点）

同样地，`dp[i][j]` 只依赖上一行 `dp[i-1][j]`（不选）和**本行** `dp[i][j-w]`（选）。滚动成一维后：

$$
dp[j] = \max(dp[j],\ dp[j - weight[i]] + value[i])
$$

方程和 0-1 背包**一模一样**，但**内层容量正序遍历**：

```java
public int knapsackComplete(int[] weight, int[] value, int W) {
    int n = weight.length;
    int[] dp = new int[W + 1];                   // 初始全 0
    for (int i = 0; i < n; i++) {                // 外层遍历物品
        for (int j = weight[i]; j <= W; j++) {   // 内层容量【正序】
            dp[j] = Math.max(dp[j], dp[j - weight[i]] + value[i]);
        }
    }
    return dp[W];
}
```

- 时间复杂度：\(O(n \times W)\)
- 空间复杂度：\(O(W)\)

## 五、灵魂所在：内层为什么正序

这是完全背包和 0-1 背包在一维写法上**唯一的代码差异**，务必理解透。

### 核心

`dp[j] = max(dp[j], dp[j-w] + v)` 里，我们**希望** `dp[j-w]` 是**「已经考虑过第 i 种物品」的新值**，这样第 i 种就能被反复叠加使用。

### 正序（完全背包，正确）

`j` 从小到大：算 `dp[j]` 时，`dp[j-w]`（下标更小）**本轮已经被更新过**，是「已含第 i 种」的值，于是第 i 种被允许**重复放入**。✅

```
以物品重量 w=1、价值 v 为例，W=4，正序 j: 1→2→3→4
dp[1] = dp[0] + v      → 放了 1 枚
dp[2] = dp[1] + v      → dp[1] 已含该物品，又放一枚 → 2 枚
dp[3] = dp[2] + v      → 3 枚   ← 同一物品被重复使用，正是我们想要的
```

### 倒序（那就退化成 0-1 背包）

`j` 从大到小时，`dp[j-w]` 还是上一轮旧值（不含第 i 种），每种只会被用一次——那就是 0-1 背包了。

> **一句话记忆：0-1 背包内层倒序（防重复），完全背包内层正序（允许重复）。**

## 六、完全背包的「问法」变体

同一套框架，改**初始化**和**转移运算**即可覆盖多种问法（内层始终**正序**）：

| 问法 | 状态含义 | 转移 | 初始化 |
|:---|:---|:---|:---|
| 最大价值 | `dp[j]`=容量 j 的最大价值 | `max(dp[j], dp[j-w]+v)` | `dp[*]=0` |
| **凑满的最少个数** | `dp[j]`=凑满 j 的最少件数 | `min(dp[j], dp[j-c]+1)` | `dp[0]=0`，其余 `∞` |
| **凑满的方案数（组合）** | `dp[j]`=凑满 j 的方案数 | `dp[j] += dp[j-c]` | `dp[0]=1` |
| 能否凑满 | `dp[j]`=能否恰好凑满 j | `dp[j] \|= dp[j-c]` | `dp[0]=true` |

### 用「最少个数」变体解开头的换零钱问题（[322. 零钱兑换](../../leetcode-hot100/322.%20零钱兑换.md)）

```java
public int coinChange(int[] coins, int k) {
    int[] dp = new int[k + 1];
    Arrays.fill(dp, k + 1);          // 用 k+1 当"无穷大"（凑 k 最多用 k 枚面值 1）
    dp[0] = 0;                       // 凑 0 元需要 0 枚
    for (int c : coins) {            // 外层遍历硬币（物品）
        for (int j = c; j <= k; j++) {   // 内层金额【正序】：硬币可无限用
            dp[j] = Math.min(dp[j], dp[j - c] + 1);
        }
    }
    return dp[k] > k ? -1 : dp[k];   // 仍是初始"无穷" → 凑不出，返回 -1
}
```

对照最初的问题描述：`coins = c[]`、`k` = 目标金额、返回值即「最少硬币数」，凑不出返回 `-1`——正好落到「凑满的最少个数」变体。

## 七、坑点：遍历顺序影响「组合 vs 排列」（求方案数时）

**只在「求方案数」时**需要额外注意外层内层的顺序：

| 遍历顺序 | 统计的是 | 例（凑 3，硬币 1、2） |
|:---|:---|:---|
| **外层物品、内层容量** | **组合数**（不计顺序） | `{1,2}` 算 1 种 |
| **外层容量、内层物品** | **排列数**（计顺序） | `1+2` 和 `2+1` 算 2 种 |

- 零钱兑换 II（求组合数）：外层硬币、内层金额。
- 爬楼梯 / 组合总和 Ⅳ（求排列数）：外层金额、内层步数。

> 求「最大价值 / 最少个数 / 能否凑满」时，两种顺序都对，不受影响；**只有求方案数才要区分**。

## 九、易错点清单

| 点 | 正确做法 | 反面 |
|:---|:---|:---|
| 内层遍历顺序 | 完全背包**正序** | 倒序 → 退化成 0-1（每种只用一次） |
| 二维转移下标 | 选的项用 `dp[i][j-w]` | 写成 `dp[i-1][j-w]` → 变 0-1 背包 |
| 求方案数的层次 | 组合外物品、排列外容量 | 搞反 → 组合排列数算错 |
| 最少个数初始化 | `dp[0]=0`，其余置「无穷」 | 全 0 → 会把「凑不出」误当 0 |
| 无解返回值 | 结果仍是「无穷」判为 `-1` | 直接返回大数 → 结果错误 |

## 十、换零钱问题的五种解法对比

同一道「凑金额求最少硬币数」，可以用五种思路解，理解它们的差异能帮你看清 DP「好在哪」。以最初的问题为例：硬币 `coins`（无限供应）、目标金额 `k`，求最少枚数，凑不出返回 `-1`。

| 方法 | 核心机制 | 时间复杂度 | 空间复杂度 | 优点 | 缺点 | 推荐度 |
|:---|:---|:---:|:---:|:---|:---|:---:|
| 动态规划（自底向上） | 记录子问题最优解，自底向上 | \(O(n \times k)\) | \(O(k)\) | 高效、标准、稳定 | 需要理解状态转移 | ⭐⭐⭐⭐⭐ |
| 记忆化搜索（自顶向下） | 递归 + 缓存子问题解 | \(O(n \times k)\) | \(O(k)\) | 从暴力递归自然演进，最好想 | 有递归栈开销、深度受限 | ⭐⭐⭐⭐ |
| BFS | 在状态空间图上做最短路径搜索 | \(O(n \times k)\) | \(O(k)\) | 思路直观（最短路径） | 稍复杂，有 visited 开销 | ⭐⭐⭐⭐ |
| 递归回溯 | 穷举所有组合，回溯剪枝 | 指数级 | \(O(k)\) | 逻辑最直接 | 极慢，无法用于大数据 | ⭐⭐ |
| 暴力迭代 | 多层循环穷举 | 指数级 | \(O(1)\) | 对固定少量硬币简单 | 硬币种类必须固定，不通用 | ⭐ |

> `n` = 硬币种类数，`k` = 目标金额。五种方法本质都在「凑金额」的解空间里搜索，区别是**有没有缓存/剪枝、以什么顺序搜**。其中「递归回溯 → 加缓存 → 记忆化搜索 → 换成迭代 → 自底向上 DP」是一条完整的优化链。

### 1. 动态规划（⭐⭐⭐⭐⭐ 首选）

完全背包「最少个数」变体，自底向上填表，每个金额只算一次（推导见第六节）：

```java
public int coinChange(int[] coins, int k) {
    int[] dp = new int[k + 1];
    Arrays.fill(dp, k + 1);              // k+1 当"无穷大"
    dp[0] = 0;
    for (int c : coins) {                // 外层硬币
        for (int j = c; j <= k; j++) {   // 内层金额【正序】
            dp[j] = Math.min(dp[j], dp[j - c] + 1);
        }
    }
    return dp[k] > k ? -1 : dp[k];
}
```

### 2. BFS（⭐⭐⭐⭐ 直观：最短路径视角）

把「金额」看成图的节点，从 `0` 出发，每加一枚硬币走一条边，**第一次到达 `k` 时的层数就是最少枚数**——这正是无权图最短路径（见 [图论专题.md](../图论专题.md)）。

```java
public int coinChange(int[] coins, int k) {
    if (k == 0) return 0;
    boolean[] visited = new boolean[k + 1];   // 金额去重，避免重复入队
    Queue<Integer> queue = new ArrayDeque<>();
    queue.offer(0);
    visited[0] = true;
    int step = 0;                             // 已用硬币数 = BFS 层数
    while (!queue.isEmpty()) {
        int size = queue.size();
        step++;                               // 进入下一层：多用一枚硬币
        for (int i = 0; i < size; i++) {
            int cur = queue.poll();
            for (int c : coins) {
                int next = cur + c;
                if (next == k) return step;    // 第一次到达 k，层数即答案
                if (next < k && !visited[next]) {
                    visited[next] = true;
                    queue.offer(next);
                }
            }
        }
    }
    return -1;                                // 队列空还没到 k，凑不出
}
```

> 为什么 BFS 一到 `k` 就是最优？因为 BFS 逐层扩展，**层数小的一定先被访问**，第一次到达即最少枚数。用 DFS 就没有这个性质。

### 3. 递归回溯（⭐⭐ 逻辑最直接，但极慢）

直接穷举「当前金额减去某枚硬币后的子问题」，取最小值。不加记忆化就是指数级——同一个子金额会被反复计算（这恰恰说明它该用 DP）：

```java
public int coinChange(int[] coins, int k) {
    int res = dfs(coins, k);
    return res == Integer.MAX_VALUE ? -1 : res;
}
// 返回凑出 amount 的最少硬币数，凑不出返回 MAX_VALUE
private int dfs(int[] coins, int amount) {
    if (amount == 0) return 0;                 // 恰好凑满
    if (amount < 0)  return Integer.MAX_VALUE; // 凑超了，此路不通（剪枝）
    int min = Integer.MAX_VALUE;
    for (int c : coins) {
        int sub = dfs(coins, amount - c);      // 用一枚 c，解子问题
        if (sub != Integer.MAX_VALUE) {
            min = Math.min(min, sub + 1);
        }
    }
    return min;
}
```

> 上面的裸递归慢在**重复计算**：`dfs(amount)` 会被不同路径反复调用。把结果缓存下来，就是下一节的「记忆化搜索」。

#### 复盘：我的第一版回溯（踩坑记录）

第一次尝试时用「已用枚数 `count` 往下传」的思路，写成了这样（**含 bug，仅作复盘**）：

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        return findCoinChange(coins, amount, 0);
    }
    private int findCoinChange(int[] coins, int amount, int count) {
        if (amount < 0)  return -1;
        if (amount = 0)  return count;               // ❌ 用了赋值 = 应为 ==
        for (int i = 0; i < coins.length; i++) {
            int cur = coins[i];
            int chooseAmount   = findCoinChange(coins, amount - cur, count + 1);
            int notchooseAmount = findCoinChange(coins, amount, count);  // ❌ 参数没变 → 死循环
        }
        // ❌ 循环里既没 return 也没取 min，函数无返回值
    }
}
```

三个致命问题：

| 问题 | 后果 | 修正 |
|:---|:---|:---|
| `if (amount = 0)` | 编译错误（`=` 是赋值） | 改成 `==` |
| `notchooseAmount = findCoinChange(coins, amount, count)` | `amount`、`count` 都没变 → **无限递归、栈溢出** | **删掉**：本模型枚举「这一步取哪枚」，"不取当前 cur" = 循环里选了别的 cur，无需单独递归 |
| 循环里没 `return`、没取 `min` | 编译不过，也拿不到答案 | 出口返回 `count`，循环内用 `min` 汇总，末尾 `return min` |

> 「不取」这一分支为什么不用写？因为状态只有 `amount`、**没有「到第几种硬币」的下标**，每一步都是从所有硬币里自由挑一枚——「不取 cur」自动被「取了别的 cur」覆盖了。这与二维背包 `dp[i][j]` 按「种类」决策、需要显式 `dp[i-1][j]` 表示「不取第 i 种」不同（详见第五、六节的对比）。

修正后（保留 `count` 下传的原思路）：

```java
class Solution {
    public int coinChange(int[] coins, int amount) {
        int res = findCoinChange(coins, amount, 0);
        return res == Integer.MAX_VALUE ? -1 : res;   // 无解统一返回 -1
    }
    // count = 已用掉的硬币数；返回凑满时的总枚数，凑不出返回 MAX_VALUE
    private int findCoinChange(int[] coins, int amount, int count) {
        if (amount < 0)  return Integer.MAX_VALUE;    // 凑超了，此路不通
        if (amount == 0) return count;                // 恰好凑满，返回已用枚数
        int min = Integer.MAX_VALUE;
        for (int cur : coins) {                       // 枚举「这一步取哪种硬币」
            min = Math.min(min, findCoinChange(coins, amount - cur, count + 1));
        }
        return min;
    }
}
```

> 这版仍是**指数级、会超时**，和上面的 `dfs` 等价，只是「枚数」用参数 `count` 下传、而非靠返回值 `+1` 累加。**注意：`count` 下传的写法不方便直接加记忆化**——同一个 `amount` 会带着不同的 `count` 到达，`memo[amount]` 存「累计总数」会串味。要加缓存，改用下一节「返回子问题最少枚数」的写法。

### 4. 记忆化搜索（⭐⭐⭐⭐ 自顶向下的 DP）

给递归回溯加一个 `memo` 数组缓存「凑出每个金额的最少枚数」，每个子金额**只算一次**，复杂度立刻从指数级降到 \(O(n \times k)\)。它就是**自顶向下形态的动态规划**，和第一节自底向上的 DP 等价。

```java
public int coinChange(int[] coins, int k) {
    int[] memo = new int[k + 1];
    Arrays.fill(memo, -2);          // -2 = 尚未计算；-1 = 已算出"凑不出"
    return dfs(coins, k, memo);
}
// 返回凑出 amount 的最少硬币数；凑不出返回 -1
private int dfs(int[] coins, int amount, int[] memo) {
    if (amount == 0) return 0;      // 恰好凑满
    if (amount < 0)  return -1;     // 凑超了，此路不通
    if (memo[amount] != -2) return memo[amount];   // 命中缓存，直接返回

    int min = Integer.MAX_VALUE;
    for (int c : coins) {
        int sub = dfs(coins, amount - c, memo);    // 用一枚 c，解子问题
        if (sub >= 0) {                            // 子问题有解
            min = Math.min(min, sub + 1);
        }
    }
    memo[amount] = (min == Integer.MAX_VALUE) ? -1 : min;   // 写入缓存
    return memo[amount];
}
```

> **记忆化搜索 vs 自底向上 DP**：两者复杂度、结果完全相同，只是「计算顺序」相反——记忆化按递归需要**懒计算**（只算用得到的子问题），迭代 DP **主动**从小到大全部填满。金额很大且很多子状态用不上时，记忆化能省掉无用计算；但它有**递归栈开销**，`k` 极大时可能栈溢出，此时改用自底向上dp更稳。

### 5. 暴力迭代（⭐ 仅演示，不通用）

硬币种类**固定**时，可以用多重循环枚举每种硬币的使用数量。下面以「硬币恰好 2 种」为例——种类一变就得改代码，毫无通用性，仅用于说明「暴力穷举」长什么样：

```java
// 仅演示：coins 恰好 2 种 {a, b}，枚举各用几枚
public int coinChangeBrute(int a, int b, int k) {
    int min = Integer.MAX_VALUE;
    for (int x = 0; x * a <= k; x++) {           // a 用 x 枚
        for (int y = 0; y * b <= k; y++) {       // b 用 y 枚
            if (x * a + y * b == k) {            // 恰好凑满
                min = Math.min(min, x + y);
            }
        }
    }
    return min == Integer.MAX_VALUE ? -1 : min;
}
```

> 硬币有 `n` 种就要 `n` 层循环，硬编码且指数级，**只在题目锁死硬币种类时才勉强能用**。实战中不要这样写，直接上 DP。

### 小结：为什么最终选 DP

- **暴力迭代 / 递归回溯**：能表达问题，但重复计算严重，指数级，数据一大就超时。
- **记忆化搜索（递归 + 缓存）**：给回溯加缓存，复杂度降到 \(O(n \times k)\)——已经是 DP 的「自顶向下」形态，最贴近人的思考过程，但有递归栈开销。
- **BFS**：把它当最短路径搜，复杂度也是 \(O(n \times k)\)，思路直观，但多了队列和 visited 的常数开销。
- **动态规划（自底向上）**：同样 \(O(n \times k)\)，无递归栈、无队列开销，代码最短最稳——**所以是首选**。

> 一条清晰的演进链：**暴力递归 →（加缓存）记忆化搜索 →（改成迭代）自底向上 DP**。记忆化搜索和自底向上 DP 只是同一套状态转移的两种写法，想不清遍历顺序时先写记忆化，往往更快落地。

## 十一、一句话总结

> 完全背包 = **「每种物品可无限次选，在容量约束下求最优/计数」**。它与 0-1 背包共用状态与转移方程，一维写法的**唯一差别是内层容量正序**（允许同一物品被反复叠加）。二维写法则记住选的那一项用 `dp[i][j-w]`（还停留在第 i 层）。求方案数时再按「组合 / 排列」决定外内层顺序即可。
