# 单调队列

单调队列是一种维护内部元素**单调性**的双端队列（Deque），能在**一次遍历**中高效求出「滑动窗口的最大/最小值」。它是滑动窗口最值问题的标准解法。

> 别和[单调栈](单调栈.md)混淆：**单调栈**解决「下一个更大/更小元素」；**单调队列**解决「滑动窗口最值」。

---

## 一、核心思想

维护一个双端队列，**队首始终是当前窗口的最值**。为此，当新元素入队时，把队尾所有「不可能再成为最值」的元素弹掉。

以求**窗口最大值**为例，维护一个**单调递减**队列（队首最大）：

- **入队（队尾）**：新元素比队尾大时，队尾元素永远不可能是后续窗口的最大值（它更小又更早过期），直接弹出，直到队尾比新元素大。
- **出队（队首）**：当队首元素滑出窗口范围时，从队首弹出。

> 记忆：**队列里存的是「有可能成为最值的候选」，一旦发现某个候选没戏了，立刻淘汰。**

---

## 二、为什么存下标而不是值

队列里存**数组下标**，因为要判断队首元素是否已经**滑出窗口**（比较下标和窗口左边界），值本身做不到这一点。

---

## 三、代码模板（Java）：滑动窗口最大值

以 [239. 滑动窗口最大值](https://leetcode.cn/problems/sliding-window-maximum/) 为例，窗口大小为 `k`：

```java
public int[] maxSlidingWindow(int[] nums, int k) {
    int n = nums.length;
    int[] result = new int[n - k + 1];
    Deque<Integer> deque = new ArrayDeque<>();   // 存下标，队首→队尾对应值单调递减
    for (int i = 0; i < n; i++) {
        // 1. 队尾淘汰：比新元素小的都不可能是最大值，弹掉
        while (!deque.isEmpty() && nums[deque.peekLast()] <= nums[i]) {
            deque.pollLast();
        }
        deque.offerLast(i);                       // 新下标入队尾

        // 2. 队首淘汰：队首下标已滑出窗口 [i-k+1, i]
        if (deque.peekFirst() <= i - k) {
            deque.pollFirst();
        }

        // 3. 结算：窗口形成后（i >= k-1），队首即当前窗口最大值
        if (i >= k - 1) {
            result[i - k + 1] = nums[deque.peekFirst()];
        }
    }
    return result;
}
```

> 求**窗口最小值**只需把队尾淘汰条件改成 `nums[deque.peekLast()] >= nums[i]`，维护单调递增队列。

## 四、执行过程图解

数组 `[1, 3, -1, -3, 5, 3]`，`k = 3`，维护单调递减队列（存下标）：

| i | nums[i] | 队尾淘汰后 | 队首淘汰 | 队列（下标） | 窗口最大值 |
|:---:|:---:|:---|:---|:---|:---:|
| 0 | 1 | — | — | `[0]` | 窗口未满 |
| 1 | 3 | 弹出 0（1≤3） | — | `[1]` | 窗口未满 |
| 2 | -1 | — | — | `[1,2]` | **3** |
| 3 | -3 | — | — | `[1,2,3]` | **3** |
| 4 | 5 | 弹出 3,2,1 | — | `[4]` | **5** |
| 5 | 3 | — | — | `[4,5]` | **5** |

## 五、复杂度分析

| 维度 | 复杂度 | 说明 |
|:---|:---|:---|
| 时间 | \(O(n)\) | 每个元素最多入队一次、出队一次 |
| 空间 | \(O(k)\) | 队列最多存一个窗口的候选 |

> 对比：暴力法每个窗口扫一遍是 \(O(nk)\)；用大根堆是 \(O(n\log k)\)（还要处理过期元素）；单调队列 \(O(n)\) 最优。

---

## 六、与其他方法对比

| 方法 | 时间 | 说明 |
|:---|:---|:---|
| 单调队列 | \(O(n)\) | 最优，标准解法 |
| 大根堆 | \(O(n\log k)\) | 需处理过期堆顶（懒删除） |
| 暴力扫窗口 | \(O(nk)\) | 仅数据量小时可用 |

---

## 七、易错点

1. **存下标不存值**：否则无法判断队首是否滑出窗口。
2. **队尾用 `<=` 还是 `<`**：用 `<=` 弹出相等元素，队列更短，结果不受影响（相等的取靠后的即可）。
3. **队首淘汰的边界**：窗口是 `[i-k+1, i]`，队首下标 `<= i-k` 时滑出。
4. **何时开始结算**：`i >= k-1`（窗口第一次填满）后才写结果。
5. **单调队列 vs 单调栈**：最值滑动窗口用队列；下一个更大/更小用栈。

---

## 八、一句话总结

单调队列通过**队尾淘汰无用候选、队首淘汰过期元素**，在一次 \(O(n)\) 遍历里维护出每个滑动窗口的最值，是「滑动窗口最大/最小值」问题的最优解法。滑动窗口本身的通用套路见 [双指针与滑动窗口.md](双指针与滑动窗口.md)。
