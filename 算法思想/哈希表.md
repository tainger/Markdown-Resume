# 哈希表的算法题套路

哈希表结构与底层原理（数组+链表/红黑树、扩容、扰动）见 [../数据结构/哈希表.md](../数据结构/哈希表.md)。本篇讲**刷题视角**：哈希表的三种用法（存在性、计数、映射）与两个高级组合（前缀和+哈希、设计题）。

## 一、三种基础用法

| 用法 | 容器选择 | 信号词 | 代表 |
|:---|:---|:---|:---|
| **存在性判断**（我见过它吗） | `HashSet` | 是否出现、去重、判重 | [1. 两数之和](../leetcode-hot100/1.%20两数之和.md)、[128. 最长连续序列](../leetcode-hot100/128.%20最长连续序列.md) |
| **计数**（它出现几次） | `HashMap<K,Integer>` / `int[128]` | 频次、出现次数 | [统计.md](统计.md) 全篇 |
| **映射**（A 对应 B） | `HashMap<K,V>` | 对应、配对关系 | 同构字符串、[399. 除法求值](../leetcode-hot100/399.%20除法求值.md)（→并查集） |

```java
// ① 存在性：两数之和 —— 一次遍历"边存边查"（查 complement 先于存自己，天然去重）
static int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> seen = new HashMap<>();   // 值 → 下标
    for (int i = 0; i < nums.length; i++) {
        Integer j = seen.get(target - nums[i]);     // 先查需要的另一半
        if (j != null) return new int[]{j, i};
        seen.put(nums[i], i);                       // 再存自己
    }
    return new int[0];
}

// ② 存在性进阶：最长连续序列 —— HashSet + 只从序列起点扩展，O(n)
static int longestConsecutive(int[] nums) {
    Set<Integer> set = new HashSet<>();
    for (int x : nums) set.add(x);
    int best = 0;
    for (int x : set) {
        if (set.contains(x - 1)) continue;          // ★ 只从"序列起点"（x-1 不存在）起跑
        int len = 1;
        while (set.contains(x + len)) len++;        // 顺着往后数
        best = Math.max(best, len);
    }
    return best;
}
```

## 二、进阶一：前缀和 + 哈希（空间换时间的典范）

「找和为 k 的子数组」暴力枚举区间 \(O(n^2)\)；**前缀和把区间和变成两数之差，哈希把"找差"变成 O(1)**：

```java
// 560 和为 K 的子数组：前缀和 pre(j) - pre(i) = k → 查 pre(j)-k 出现过几次
static int subarraySum(int[] nums, int k) {
    Map<Integer, Integer> cnt = new HashMap<>();
    cnt.put(0, 1);                          // ★ 空前缀：从下标 0 开始的区间也要算
    int pre = 0, ans = 0;
    for (int x : nums) {
        pre += x;
        ans += cnt.getOrDefault(pre - k, 0); // 有多少历史前缀 = pre - k
        cnt.merge(pre, 1, Integer::sum);     // 后记录（先查后存，防 x=0 时把自己算进去）
    }
    return ans;
}
```

- 同族题：[437. 路径总和 III](../leetcode-hot100/437.%20路径总和%20III.md)（搬到树上，详见 [树.md](树.md)）、[523. 连续的子数组和]（前缀和取模 + 下标距离）。
- 为什么不能用滑动窗口：**数组含负数**，窗口右扩和不一定增、左收不一定减——单调性被破坏。正数数组才能滑窗。这是两法分界的高频追问。

## 三、进阶二：设计题（哈希 + 其他结构复合）

| 设计题 | 组合 | 核心点 |
|:---|:---|:---|
| **LRU 缓存** | `HashMap` + 双向链表 | Map 定位节点 O(1)，链表维护访问序；头部最新/尾部淘汰；Java 可直接 `LinkedHashMap(accessOrder=true)` 重写 `removeEldestEntry` |
| LFU 缓存 | 双 HashMap + 频次桶 | 频次→双向链表，再加 minFreq 追踪 |
| O(1) 插入删除随机 | `HashMap` + 动态数组 | 数组存元素，Map 存「值→下标」；删除时**尾部元素补位** + pop |
| 两数之和进阶/字母异位词分组 | `HashMap<String, List>` | 排序后串作 key（或 26 位计数串作 key） |

> LRU 在工程里的对应物是 Redis 淘汰策略与 Caffeine，见 [../redis/缓存问题与实战.md](../redis/缓存问题与实战.md)。

## 四、易错点

| 易错点 | 澄清 |
|:---|:---|
| **两数之和先存后查** | 顺序颠倒 `[3,3] target=6` 会拿同一元素两次；先查 complement 再存 |
| **前缀和初始化漏 `put(0,1)`** | 「从头开始的子数组」会被漏计——空前缀必须预置 |
| **前缀和先存后查** | `k=0` 时会把自己算成区间；先查 `pre-k` 再 `merge(pre)` |
| **最长连续序列双层全扫** | 不判起点则每个元素都向后数一遍，退化 \(O(n^2)\)；必须 `contains(x-1) → skip` |
| **可变对象当 key** | key 参与哈希计算后如果被修改就找不到；key 用不可变类型 |
| **依赖遍历顺序** | HashMap 无序；需要按插入序用 `LinkedHashMap`，按 key 序用 `TreeMap` |
| **负数取模当"映射到桶"** | Java `%` 可为负；映射桶下标用 `((x % m) + m) % m` |

## 五、一句话总结

哈希刷题三板斧：**存在性用 HashSet（两数之和"先查后存"、最长连续序列"只从起点扩展"）、计数见统计篇、前缀和+哈希把区间问题降为两数之差（先查后存 + put(0,1) 两个铁律）**；设计题套路 = 哈希定位 + 链表/数组维护顺序——「用 O(1) 的查找换掉一层枚举」是它的一切。
