# 并查集

并查集（Union-Find / Disjoint Set Union, DSU）是一种维护**「不相交集合」**的数据结构，专门高效回答「**这两个元素是否属于同一组**」以及「**合并两组**」。近乎 \(O(1)\) 的均摊复杂度让它成为连通性、分组类问题的标配。

---

## 一、能解决什么

| 问题信号 | 用并查集做什么 |
|:---|:---|
| 判断两点是否连通 | `find(a) == find(b)` |
| 统计连通分量个数 | 合并后数不同的根 |
| 动态加边/合并分组 | `union(a, b)` |
| 带权约束（比值、距离） | 加权并查集，`find` 时同步维护到根的权值 |

> 对比：静态一次性求连通分量用 DFS/BFS 更直观；**边是动态加入的、要反复查连通性**时并查集更优。

---

## 二、核心三操作 + 两个优化

```java
class UnionFind {
    int[] parent, rank;   // rank 近似树高
    int count;            // 连通分量个数

    UnionFind(int n) {
        parent = new int[n];
        rank = new int[n];
        count = n;
        for (int i = 0; i < n; i++) parent[i] = i;  // 各自成组
    }

    // 路径压缩：查根时把沿途节点直接挂到根下
    int find(int x) {
        if (parent[x] != x) parent[x] = find(parent[x]);
        return parent[x];
    }

    // 按秩合并：矮树挂到高树下，避免树变高
    void union(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return;
        if (rank[ra] < rank[rb]) { int t = ra; ra = rb; rb = t; }
        parent[rb] = ra;
        if (rank[ra] == rank[rb]) rank[ra]++;
        count--;                 // 每成功合并一次，分量数 -1
    }

    boolean connected(int a, int b) { return find(a) == find(b); }
}
```

**两大优化**（同时用，均摊复杂度趋近 \(O(1)\)，准确说是反阿克曼 \(O(\alpha(n))\)）：

| 优化 | 做法 | 作用 |
|:---|:---|:---|
| 路径压缩 | `find` 时把节点直接指向根 | 压扁树，后续查询更快 |
| 按秩/按大小合并 | 小树挂到大树下 | 防止树退化成链 |

---

## 三、加权并查集（进阶）

当元素间有**相对关系**（如 `a/b = 3`、`a` 比 `b` 大 5），在 `parent` 之外再维护 `weight[x]`（x 到其父节点的权值），`find` 压缩路径时**累加权值**，`union` 时按约束推算两根之间的权值。

> 见 [399. 除法求值](../leetcode-hot100/399.%20除法求值.md)：把 `a/b=k` 建成加权并查集，同一组内任意两点的比值可由「各自到根的权值」相除得到。

---

## 四、易错点

1. **初始化 `parent[i]=i`**：每个元素一开始自成一组。
2. **`union` 前先 `find` 到根再合并**，不要直接改 `parent[a]=b`（会破坏树结构）。
3. **分量计数 `count` 只在真正合并（两根不同）时才 `--`**。
4. **加权并查集**：路径压缩时权值要跟着更新，容易漏。

---

## 五、复杂度

| 操作 | 复杂度（路径压缩 + 按秩合并） |
|:---|:---|
| find / union / connected | 均摊 \(O(\alpha(n)) \approx O(1)\) |
| 空间 | \(O(n)\) |
