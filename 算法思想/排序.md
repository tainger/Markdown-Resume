# 排序思想

排序不是背九个算法，而是**按数据特征选策略**：面试手撕高频是快排/归并/堆排三件套，工程高频是「该用哪个排序」的选型判断。另配合 [二分查找.md](二分查找.md)（有序是二分的前提）、[桶思想.md](桶思想.md)（线性排序）食用。

---

## 一、九大排序全景对比（必背表）

| 算法 | 平均 | 最坏 | 空间 | 稳定 | 一句话原理 |
|:---|:---:|:---:|:---:|:---:|:---|
| 冒泡 | \(O(n^2)\) | \(O(n^2)\) | \(O(1)\) | ✅ | 相邻逆序交换，大数右浮 |
| 选择 | \(O(n^2)\) | \(O(n^2)\) | \(O(1)\) | ❌ | 每轮选最小放前面 |
| 插入 | \(O(n^2)\) | \(O(n^2)\) | \(O(1)\) | ✅ | 像整理扑克，往前找位置插入 |
| 希尔 | \(O(n^{1.3})\) | \(O(n^2)\) | \(O(1)\) | ❌ | 分组插入，间隔递减 |
| **快排** | \(O(n\log n)\) | \(O(n^2)\) | \(O(\log n)\) | ❌ | 选基准分区，递归两侧 |
| **归并** | \(O(n\log n)\) | \(O(n\log n)\) | \(O(n)\) | ✅ | 二分递归 + 合并两个有序 |
| **堆排** | \(O(n\log n)\) | \(O(n\log n)\) | \(O(1)\) | ❌ | 建大顶堆，堆顶与末尾交换下沉 |
| 计数 | \(O(n+k)\) | \(O(n+k)\) | \(O(k)\) | ✅ | 值作下标计数，值域小 |
| 桶/基数 | \(O(n+k)\) | \(O(n^2)\)（桶内退化） | \(O(n+k)\) | ✅ | 分桶（桶内可再排序）/按位分配 |

> 稳定性 = 相等元素排序后**相对次序不变**。为什么工程要稳定：多关键字排序时先按次要键排再按主键排，稳定排序保证次序不丢。

## 二、手撕三件套（面试白板频率最高）

### 2.1 快速排序

```java
static void quickSort(int[] a, int left, int right) {
    if (left >= right) return;
    int pivot = a[left + (right - left) / 2]; // 随机/中间取基准防有序数组退化
    int i = left, j = right;
    while (i <= j) {                          // 双向扫描 partition
        while (a[i] < pivot) i++;             // 找到左边第一个 >= pivot
        while (a[j] > pivot) j--;             // 找到右边第一个 <= pivot
        if (i <= j) {                         // 交换后继续收缩
            int t = a[i]; a[i] = a[j]; a[j] = t;
            i++; j--;
        }
    }
    quickSort(a, left, j);                    // [left, j] 与 [i, right] 递归
    quickSort(a, i, right);
}
```

- 最坏 \(O(n^2)\) 的触发：**已有序 + 固定取端点基准** → 随机化基准或三数取中。
- 顺带掌握 **TopK 变体**：partition 后只递归 K 所在一侧，平均 \(O(n)\)——[215. 数组中的第K个最大元素](../leetcode-hot100/215.%20数组中的第K个最大元素.md)。

### 2.2 归并排序（逆序对/链表排序通用）

```java
static void mergeSort(int[] a, int left, int right, int[] tmp) {
    if (left >= right) return;
    int mid = left + (right - left) / 2;
    mergeSort(a, left, mid, tmp);             // 左半有序
    mergeSort(a, mid + 1, right, tmp);        // 右半有序
    // 合并两个有序区间到 tmp 再拷回
    int i = left, j = mid + 1, k = left;
    while (i <= mid && j <= right)
        tmp[k++] = a[i] <= a[j] ? a[i++] : a[j++]; // <= 保证稳定
    while (i <= mid) tmp[k++] = a[i++];
    while (j <= right) tmp[k++] = a[j++];
    System.arraycopy(tmp, left, a, left, right - left + 1);
}
```

- **稳定 + 最坏也 \(O(n\log n)\)**，代价 \(O(n)\) 辅助数组。
- 变体价值：**逆序对计数**（合并时统计右半跳到左半的数量）、[23. 合并 K 个升序链表](../leetcode-hot100/23.%20合并%20K%20个升序链表.md)（分治两两合并/堆）。

### 2.3 堆排序 / 堆思想

```java
static void heapSort(int[] a) {
    int n = a.length;
    for (int i = n / 2 - 1; i >= 0; i--) siftDown(a, i, n); // ① 自底向上建堆 O(n)
    for (int end = n - 1; end > 0; end--) {
        int t = a[0]; a[0] = a[end]; a[end] = t;            // ② 堆顶(最大)换到末尾
        siftDown(a, 0, end);                                // ③ 堆规模缩小后下沉
    }
}
static void siftDown(int[] a, int i, int size) {            // 大顶堆下沉
    while (2 * i + 1 < size) {
        int child = 2 * i + 1;
        if (child + 1 < size && a[child + 1] > a[child]) child++;
        if (a[i] >= a[child]) break;
        int t = a[i]; a[i] = a[child]; a[child] = t;
        i = child;
    }
}
```

- 建堆是 \(O(n)\) 不是 \(O(n\log n)\)（自底向上逐层下沉，多数节点下沉距离短）——高频追问点。
- 堆思想工程化就是 **TopK 场景**：维护 k 大小的小顶堆 \(O(n\log k)\)，见 [347. 前 K 个高频元素](../leetcode-hot100/347.%20前%20K%20个高频元素.md) 与数据结构 [优先队列.md](../数据结构/优先队列.md)。

## 三、按题目信号选排序（实战选型表）

| 题目信号 | 策略 | 复杂度 |
|:---|:---|:---|
| 求 **TopK / 第 K 大** | 小顶堆维护 k 个 / 快排 partition | \(O(n\log k)\) / 平均 \(O(n)\) |
| 值域小（年龄/分数/字母） | **计数排序** | \(O(n+k)\) |
| n 大且只要「前 K 高频」 | 桶排序（按频次分桶） | \(O(n)\)，见 [桶思想.md](桶思想.md) |
| 需要**稳定**（多关键字） | 归并 / 计数 | — |
| 链表排序 | 归并（链表合并无随机访问开销） | \(O(n\log n)\) |
| 几乎有序的流数据 | 插入 / TimSort 思想 | 接近 \(O(n)\) |
| 荷兰国旗（三值分类） | 三指针单遍 | \(O(n)\)，见 [75. 颜色分类](../leetcode-hot100/75.%20颜色分类.md) |
| 要求原地 O(1) 且最坏 O(nlogn) | 堆排 | — |

## 四、易错点 ⚠️

| 易错点 | 澄清 |
|:---|:---|
| **快排固定取端点基准** | 有序/全相等数据退化 \(O(n^2)\)；随机化 / 三数取中 / 三路分区 |
| **归并合并用 `<` 丢稳定性** | 相等时应取**左半**元素（`a[i] <= a[j]`） |
| **以为建堆是 \(O(n\log n)\)** | 自底向上建堆是 \(O(n)\)，逐个插入建堆才是 \(O(n\log n)\) |
| **递归终止条件漏 `left >= right`** | 死递归栈溢出；分区后边界 j/i 要保证区间缩小 |
| **堆排当稳定排序用** | 堆排不稳定；要稳定用归并 |
| **TopK 无脑全排序** | \(O(n\log n)\) 过不了大数据；堆 \(O(n\log k)\) 或 partition \(O(n)\) |
| **比较器返回值写反** | `(a,b) -> a - b` 升序；减法溢出风险 → `Integer.compare(a, b)` |

---

## 五、一句话总结

排序选型三板斧：**要稳定选归并、要 TopK 上堆或 partition、值域小用计数/桶**；手撕保命三件套 = 快排（随机化基准 + 双向分区）、归并（稳定合并 + 逆序对）、堆排（\(O(n)\) 建堆 + 下沉）——记「快排最坏为什么 \(O(n^2)\)、建堆为什么 \(O(n)\)、归并为什么稳定」三个为什么，面试就赢了。
