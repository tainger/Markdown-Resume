# 桶思想

桶思想（Bucketing）是一种**「按某种规则把数据分组装进若干个桶，再分桶处理」**的算法思想。它的核心是用**空间换时间**或**用分组化简问题**：当数据可以按值域、频率、区间等维度天然分组时，分桶往往能把复杂问题拆成一批简单子问题，甚至把排序做到线性时间。

---

## 一、桶思想的两条脉络

「桶」在算法里有两类常见用法，思路相通但场景不同：

| 脉络 | 分桶依据 | 典型用途 | 代表题目 |
|:---|:---|:---|:---|
| **值域 / 频率分桶** | 元素的值或出现次数 | 桶排序、计数排序、前 K 高频、找众数 | 桶排序、347、451 |
| **调度 / 结构分桶** | 时间片、位置、约束 | 把问题按固定周期切段处理 | [任务调度器（621）](../leetcode-hot100/621.%20任务调度器.md) |

> 记忆：**桶 = 分组**。看到「值域有限」「按频率归类」「按固定周期切分」，就可以想想分桶能不能化简问题。

---

## 二、为什么分桶能加速

桶思想突破「基于比较的排序 \(O(n\log n)\) 下界」的关键在于：**它不靠两两比较，而是靠「元素落到哪个桶」直接定位**。

| 方法 | 是否基于比较 | 时间下界 |
|:---|:---|:---|
| 快排 / 归并 / 堆排 | 是 | \(O(n\log n)\) |
| 桶排序 / 计数排序 | 否（按值映射到桶） | \(O(n + k)\)，k 为值域/桶数 |

- **代价**：需要额外 \(O(n + k)\) 空间，且要求数据**分布相对均匀**或**值域可控**
- **收益**：当 `k = O(n)` 时，整体退化为 \(O(n)\) 线性时间

## 三、桶排序（Bucket Sort）

### 核心步骤

1. **建桶**：根据数据范围划分若干个桶（区间）
2. **入桶**：遍历数据，按值映射到对应桶
3. **桶内排序**：对每个桶内部排序（数据均匀时每桶元素少，排序开销小）
4. **合并**：按桶顺序依次取出，得到有序序列

### 图解示例

数组 `[0.78, 0.17, 0.39, 0.72, 0.94, 0.21]`，分成 10 个桶（按小数第一位）：

```
桶0: []          桶1: [0.17]          桶2: [0.21]
桶3: [0.39]      桶4: []              桶5: []
桶6: []          桶7: [0.78, 0.72]    桶8: []
桶9: [0.94]

桶内排序后合并 → [0.17, 0.21, 0.39, 0.72, 0.78, 0.94]
```

### 复杂度

| 维度 | 值 | 说明 |
|:---|:---|:---|
| 时间（平均） | \(O(n + k)\) | 数据均匀分布时 |
| 时间（最坏） | \(O(n^2)\) | 所有元素挤进一个桶 |
| 空间 | \(O(n + k)\) | k 个桶 |

## 四、计数排序（Counting Sort）

桶思想的**极端特例**：每个「值」就是一个桶，桶里只存计数。适用于**值域小的整数**。

```java
public int[] countingSort(int[] arr, int maxVal) {
    int[] count = new int[maxVal + 1];   // 每个值一个桶，存出现次数
    for (int x : arr) {
        count[x]++;                       // 入桶：值 x 落到 count[x]
    }
    int[] res = new int[arr.length];
    int idx = 0;
    for (int v = 0; v <= maxVal; v++) {   // 按值从小到大取出
        while (count[v]-- > 0) {
            res[idx++] = v;
        }
    }
    return res;
}
```

- 时间复杂度：\(O(n + k)\)，k 为值域
- 空间复杂度：\(O(k)\)
- 适用：值域 `k` 不远大于元素个数 `n`（如年龄、成绩、字母频率）

## 五、频率分桶：前 K 高频问题

当需要「按出现次数排序 / 取前 K 个」时，**以「频率」为桶下标**，可把排序省掉，做到 \(O(n)\)。

### 例：前 K 个高频元素（LeetCode 347）

```java
public int[] topKFrequent(int[] nums, int k) {
    Map<Integer, Integer> freq = new HashMap<>();
    for (int x : nums) {
        freq.put(x, freq.getOrDefault(x, 0) + 1);
    }
    // 桶下标 = 出现频率，桶内放所有该频率的元素（频率最大为 n）
    List<Integer>[] bucket = new List[nums.length + 1];
    for (int key : freq.keySet()) {
        int f = freq.get(key);
        if (bucket[f] == null) bucket[f] = new ArrayList<>();
        bucket[f].add(key);
    }
    // 从高频桶往低频桶收集，直到凑够 k 个
    List<Integer> res = new ArrayList<>();
    for (int f = nums.length; f >= 1 && res.size() < k; f--) {
        if (bucket[f] != null) res.addAll(bucket[f]);
    }
    return res.stream().mapToInt(Integer::intValue).limit(k).toArray();
}
```

- 时间复杂度：\(O(n)\)，避免了堆的 \(O(n\log k)\)
- 关键洞察：**频率的取值范围是 `[1, n]`，天然适合做桶下标**

> 相关题：451. 根据字符出现频率排序，思路完全一致。

## 六、调度分桶：任务调度器模型

另一条脉络——把**时间轴按固定周期切成桶**。这是 [621. 任务调度器](../leetcode-hot100/621.%20任务调度器.md) 的核心。

设出现最多的任务次数为 `maxCount`，冷却时间 `n`：

```
以 A 出现 3 次、n = 2 为例，每桶 n+1 = 3 格：

桶1: [A ? ?]   桶2: [A ? ?]   桶3: [A]
     └─ 前 (maxCount-1) 桶填满 ─┘    └ 最后一桶放并列最多 ┘
```

公式：

$$
\text{结果} = \max\Big((maxCount - 1) \times (n + 1) + maxNum,\ \ \text{tasks.length}\Big)
$$

- **分桶依据**：以「出现最多的任务」为骨架，每 `n+1` 个时间片为一桶
- **与频率分桶的区别**：这里的桶是**时间片容器**，不是值域容器，但同样是「按固定规则分组化简」的桶思想

> 详细推导见 [621 题解](../leetcode-hot100/621.%20任务调度器.md)，那里有完整的桶模型图解和「为什么最后一段不冷却」的分析。

## 七、桶思想的适用信号

| 信号 | 可考虑的桶用法 |
|:---|:---|
| 数据是**值域有限的整数**（年龄、成绩、字母） | 计数排序 |
| 数据**分布均匀的浮点数 / 大范围数** | 桶排序 |
| 求**前 K 高频 / 按频率排序** | 频率分桶（频率当下标） |
| 求**最大间距**（如 LeetCode 164） | 桶 + 鸽巢原理（只比较相邻桶边界） |
| **固定周期调度 / 冷却约束** | 调度分桶（621） |

## 八、易错点与技巧

| 易错点 | 说明 |
|:---|:---|
| **桶数量选取** | 太少 → 退化为桶内排序 \(O(n^2)\)；太多 → 空间浪费。经验值取 `n` 个桶 |
| **值域过大** | 计数排序值域 `k` 远大于 `n` 时（如有单个极大值），空间爆炸，不适用 |
| **负数 / 浮点映射** | 需要先做偏移或归一化，把值映射到非负桶下标 |
| **稳定性** | 计数排序可做成稳定排序，但要从后往前填结果数组 |
| **频率分桶的桶大小** | 频率范围是 `[1, n]`，桶数组开 `n+1` 大小 |

## 九、桶思想 vs 其他方法

| 方法 | 适用信号 | 与桶思想的关系 |
|:---|:---|:---|
| **哈希表** | 需要按 key 快速查找 / 计数 | 频率分桶常先用哈希表统计频率，再分桶 |
| **堆 / 优先队列** | 求前 K / 动态最值 | 桶思想在值域可控时能把堆的 \(O(n\log k)\) 降到 \(O(n)\)；见 [贪心算法.md](贪心算法.md) 堆贪心 |
| **排序** | 通用比较排序 | 桶排序 / 计数排序是非比较排序，特定场景更快 |

---

## 十、一句话总结

桶思想的本质是**「按规则分组，分而治之」**——无论是按值域分桶做线性排序、按频率分桶取前 K，还是按时间片分桶做调度，核心都是**用分组把一个大问题拆成一批小问题，并借助「桶下标直接定位」省去比较**。
