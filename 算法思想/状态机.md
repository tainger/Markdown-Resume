# 状态机思想（状态定义型 DP）

很多 DP 难题卡住的根源不是转移方程，而是**一个维度装不下所有信息**——今天的决策受「昨天处于什么状态」约束。状态机思想：**给 DP 加一个「状态」维度，把约束显式建模，转移即状态间的有向边**。

---

## 一、什么时候想到状态机

信号词自查：

1. 「**不能连续**做某事」（不能连选两个、交易后要冷冻一天）；
2. 「**交替/往返**」（奇偶交替、买必须在卖后）；
3. 「有限个**身份/阶段**，每个阶段只能往特定阶段迁移」（排队、信号灯、股票持仓）。

普通 DP 一维装不下 → **加状态维**：`dp[i][state]` = 前 i 天（个元素）且第 i 个处于 state 时的最优值/方案数。状态之间画一张**有向图**，转移方程就是图的边——所以叫状态机 DP。

## 二、例题 1：打家劫舍（隐式状态机入门）

约束：不能偷相邻两家。把「选/不选」显式定义成两个状态：

```java
// dp[i][0] = 不偷第 i 家的最大金额；dp[i][1] = 偷第 i 家的最大金额
int rob(int[] nums) {
    int n = nums.length;
    int[][] dp = new int[n][2];
    dp[0][0] = 0;              // 第 0 家不偷
    dp[0][1] = nums[0];        // 第 0 家偷
    for (int i = 1; i < n; i++) {
        dp[i][0] = Math.max(dp[i-1][0], dp[i-1][1]); // 不偷：昨天随便
        dp[i][1] = dp[i-1][0] + nums[i];             // 偷：昨天必须没偷
    }
    return Math.max(dp[n-1][0], dp[n-1][1]);
}
```

> 滚动数组两变量即可 \(O(1)\) 空间；树形版本（相邻=父子）见 [打家劫舍 III 337](../leetcode-hot100/337.%20打家劫舍%20III.md)——状态机思想原样搬到树上。

## 三、例题 2：买卖股票系列（状态机标准应用，必背）

股票系列共用一个状态机骨架，只是状态数和转移边不同：

```
 状态机图（一次持仓状态 + 一次空仓状态，t=交易次数维度）

   持有(hold) ──rest──▶ 持有(hold)
      │ ▲
   买入│ │卖出
      ▼ │
   空仓(cash) ──rest──▶ 空仓(cash)
      ▲
      │(冷冻期：卖出后隔一天才能买 → 加 sold 状态)
```

| 题目 | 状态设计 | 转移要点 |
|:---|:---|:---|
| 121 只能交易一次 | `dp[i][0/1]` | hold = max(昨天 hold, -price) |
| 122 不限次数 | 两状态 | hold = max(hold, cash - price) |
| 309 **含冷冻期**（hot100） | 三状态：hold / sold(冷冻) / cash | cash 可从 sold 或 cash 来；hold→sold |
| 714 含手续费 | 两状态 | 卖出时减 fee |
| 123/188 限 k 次 | `dp[i][j][0/1]` j=已交易次数 | 买入时 j 不变，**卖出时 j+1**（约定好即可） |

```java
// 309. 含冷冻期：三状态机（hot100 原题）
int maxProfit(int[] prices) {
    int n = prices.length;
    int hold = -prices[0];   // 持有股票
    int sold = 0;            // 今天刚卖出 → 明天冷冻
    int cash = 0;            // 空仓且可买（冷冻期已过）
    for (int i = 1; i < n; i++) {
        int newHold  = Math.max(hold, cash - prices[i]); // 买：从可买空仓来
        int newSold  = hold + prices[i];                 // 卖：只能从持有来
        int newCash  = Math.max(cash, sold);             // 冷冻期过 → 可买
        hold = newHold; sold = newSold; cash = newCash;  // 同步更新（用旧值！）
    }
    return Math.max(sold, cash);
}
```

**同日更新 bug** 是本类题最高频错误：必须用**昨天**的状态推今天，先存临时变量（或用滚动数组时注意更新顺序）。

## 五、状态机 DP 的通用四步法

1. **枚举状态**：题目约束里出现几种「互斥处境」？（持有/空仓/冷冻）
2. **定义 `dp[i][state]`**：明确语义（最优值 or 方案数 or 可达性）。
3. **画状态转移图**：状态为点、动作为边，**每条边对应一行转移方程**；非法边（如冷冻期买入）不建边。
4. **初始化 + 遍历 + 取值**：初始状态合法值、其余非法值（-∞/false）；答案常是**多个终止状态的 max**（`max(sold, cash)`，漏一个是高频错）。

## 六、易错点 ⚠️

| 易错点 | 澄清 |
|:---|:---|
| **同一天状态互相引用** | 转移必须用「昨天」旧值：先存临时变量再整体覆盖，或注意更新顺序 |
| **答案只取最后一个状态** | 终止状态可能有多个合法（`max(sold, cash)`），只取一个会漏最优 |
| **非法初始值用 0** | 「持有股票」初始应是 `-prices[0]`（负债），用 0 会白送利润 |
| **状态数少了** | 冷冻期、手续费、限次数都会增加状态/维度；约束每多一条，先想是否要加状态 |
| **k 次交易的 j 何时 +1** | 买入加还是卖出加约定一致即可，混着用必错 |
| **把状态机 DP 写成贪心** | 股票含冷冻期/手续费时贪心不成立；有「不反悔」约束就老实上状态机 |

---

## 七、一句话总结

状态机 DP = **普通 DP + 状态维度**：把「不能连续」「交替」「冷冻」这类约束翻译成有限个互斥状态，转移方程就是状态图上的边；股票系列（121→309→188）是标准训练场——**先画状态图再写代码，答案取所有合法终止状态的 max**。
