# 统计思想（计数数组与摩尔投票）

「出现次数」类题目的共同骨架：**一次遍历建立计数结构，再一次遍历或 O(1) 查询消费计数**。统计思想是哈希表、桶排序、滑动窗口、前缀和的公共底座——先把「怎么数、数什么」想清楚，再谈数据结构选型。

---

## 一、三种计数容器怎么选

| 容器 | 适用 | 复杂度 | 注意 |
|:---|:---|:---:|:---|
| `int[26] / int[128]` | **字符集小且固定**（小写字母/ASCII） | \(O(1)\) | 零装箱开销，刷题首选；用 `c - 'a'` 做下标 |
| `HashMap<K, Integer>` | 键类型任意/稀疏 | \(O(1)\) 均摊 | `merge/getOrDefault` 原子化计数 |
| 计数数组 `int[count+1]` | 按**次数**再统计（次数作下标） | \(O(n)\) | 桶排序/前 K 高频的第二次统计 |

```java
// ============ 计数三板斧 ============
// ① 字符频次（int 数组版，避免装箱）
int[] freq = new int[128];
for (char c : s.toCharArray()) freq[c]++;

// ② Map 计数（键任意类型）
Map<Integer, Integer> cnt = new HashMap<>();
for (int x : nums) cnt.merge(x, 1, Integer::sum);   // 一行完成 get+put

// ③ 按次数倒排（次数 → 元素列表），桶排序核心
List<Integer>[] buckets = new List[nums.length + 1];
for (var e : cnt.entrySet()) {
    int c = e.getValue();
    if (buckets[c] == null) buckets[c] = new ArrayList<>();
    buckets[c].add(e.getKey());
}
```

> 完整的「计数 → 桶 → TopK」流水线见 [桶思想.md](桶思想.md) 与 [347. 前 K 个高频元素](../leetcode-hot100/347.%20前%20K%20个高频元素.md)。

## 二、摩尔投票：O(1) 空间找众数（必会技巧）

**问题**：找出现次数超过一半的元素（多数元素一定存在）。

```java
// 摩尔投票：不同的数两两抵消，剩到最后的必是多数元素
static int majority(int[] nums) {
    int candidate = 0, votes = 0;
    for (int x : nums) {
        if (votes == 0) candidate = x;   // 票数归零 → 换候选人
        votes += (x == candidate) ? 1 : -1; // 相同+1，不同-1
    }
    return candidate;
}
```

**直觉**：把「多数元素」与「其他所有元素」一一配对同归于尽，多数元素数量 > 一半，必然有存活。

- **一般化**（出现超过 n/3 的最多两个）：维护两个候选人 + 各自票数，最后**再扫一遍验证**（题目不保证存在时必须验证）——[169. 多数元素](../leetcode-hot100/169.%20多数元素.md) 及其 n/3 变体 229。
- 为什么不用排序/哈希：排序 \(O(n\log n)\)、哈希 \(O(n)\) 空间；摩尔投票 \(O(n)\) 时间 **\(O(1)\) 空间**，是本题的最优解。

## 四、易错点 ⚠️

| 易错点 | 澄清 |
|:---|:---|
| **字符集假设成 26** | 含大写/数字/符号时用 `int[128]`；宽字符用 HashMap——先看数据范围再定数组大小 |
| **摩尔投票不验证直接返回** | 只在「多数元素保证存在」时省验证；否则最后必须再扫一遍统计候选人真实票数 |
| **n/3 变体只维护一个候选人** | 超过 n/3 的元素最多 2 个，需要两个候选人 + 各自票数 |
| **按次数分桶时桶大小开错** | 次数范围是 `[1, n]`（一个元素最多出现 n 次），桶数组长度 `n + 1` |
| **`merge` 与 `getOrDefault` 混写漏更新** | 统一用 `cnt.merge(key, 1, Integer::sum)` 或 `putIfAbsent` 后 `get+put`，避免半路漏 put |
| **窗口统计全量重算** | 进出各 \(O(1)\) 增量更新频次，别每个窗口重建计数 |

## 五、一句话总结

统计思想 = **一次遍历建计数（int[128] / HashMap / 按次数分桶），一次消费出答案**：字符统计零装箱用数组、任意键用 `merge`、找众数背摩尔投票（\(O(n)\) 时间 \(O(1)\) 空间，存在性没保证就补一轮验证）——「数什么、用什么数、怎么消费」三问想清，统计题不丢分。
