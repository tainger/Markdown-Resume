# 贪心算法

贪心算法（Greedy Algorithm）是一种在每一步都做出**当前看起来最优**的选择，寄希望于通过局部最优达到全局最优的算法思想。它不回溯、不反悔，走一步算一步，因此实现简单、效率高，但**并非所有问题都适用**。

---

## 一、贪心的核心特征

一个问题能用贪心求解，通常需要满足两个性质：

| 性质 | 含义 | 说明 |
|:---|:---|:---|
| **贪心选择性质** | 全局最优解可以通过一系列局部最优选择得到 | 贪心与 DP 的分水岭：贪心当前选了就不反悔 |
| **最优子结构** | 原问题的最优解包含子问题的最优解 | 这一点和 DP 相同 |

> 关键区别：**DP 会考虑所有子问题的解再决策，贪心只凭当前状态直接决策**。所以贪心比 DP 快，但适用面窄。

---

## 二、贪心 vs 动态规划

| 维度 | 贪心 | 动态规划 |
|:---|:---|:---|
| 决策依据 | 当前局部最优，选了不反悔 | 综合所有子问题的解 |
| 是否回溯 | 否 | 否（但会保存并复用子问题解） |
| 时间复杂度 | 通常更低（常伴随排序 \(O(n\log n)\)） | 一般更高（状态数 × 转移） |
| 正确性 | **需要证明**贪心选择性质 | 只要状态转移对就正确 |
| 适用信号 | 每步局部最优 → 全局最优 | 子问题重叠且需权衡 |

> 经验：**先想能不能贪心（简单），不确定正确性就退回 DP（稳妥）**。贪心的最大陷阱是「看起来对，其实反例能推翻」。详见 [动态规划.md](动态规划.md)。

---

## 三、贪心解题四步法

| 步骤 | 关键问题 | 说明 |
|:---:|:---|:---|
| 1. 建立贪心策略 | 每一步选什么是「最优」？ | 如「选结束最早的」「选性价比最高的」 |
| 2. 证明策略正确 | 局部最优真能推出全局最优吗？ | 常用**反证法**或**交换论证法** |
| 3. 设计实现 | 是否需要先排序？用什么数据结构？ | 贪心常以排序 + 一次遍历实现 |
| 4. 处理边界 | 空输入、单元素、极值情况 | — |

> 最容易被跳过但最重要的是**第 2 步**。面试中如果不能说明贪心为什么对，很可能这题就不该用贪心。

## 四、经典贪心模型

### 1. 区间问题

排序后按规则选择，是贪心最典型的应用。

| 题目 | 贪心策略 | 排序依据 |
|:---|:---|:---|
| 无重叠区间（435） | 保留结束最早的区间 | 按**右端点**升序 |
| 用最少箭引爆气球（452） | 一箭射穿尽量多的重叠区间 | 按**右端点**升序 |
| 合并区间（56） | 能合并就合并 | 按**左端点**升序 |
| 会议室 II（253） | 用最小堆维护结束时间 | 按左端点升序 + 堆 |

> **区间调度口诀**：求「最多不重叠 / 最少覆盖」按**右端点**排序；求「合并 / 区间并集」按**左端点**排序。

### 2. 跳跃 / 覆盖问题

| 题目 | 贪心策略 |
|:---|:---|
| 跳跃游戏（55） | 维护当前能到达的最远位置 `maxReach` |
| 跳跃游戏 II（45） | 在当前跳跃范围内选下一跳能到最远的点 |
| 加油站（134） | 总油量够则解唯一，从累计亏空后的下一站出发 |

### 3. 排序 + 配对 / 分配

| 题目 | 贪心策略 |
|:---|:---|
| 分发饼干（455） | 小胃口配小饼干，两个指针从小到大配对 |
| 柠檬水找零（860） | 优先用大面额找零，保留小面额 |
| 根据身高重建队列（406） | 按身高降序、k 升序排，再按 k 插入 |

### 4. 哈夫曼 / 堆贪心

| 题目 | 贪心策略 |
|:---|:---|
| 哈夫曼编码 | 每次取频率最小的两个节点合并（最小堆） |
| 最后一块石头的重量（1046） | 每次取最重的两块相撞（最大堆） |

## 五、代码模板（Java）

### 模板 1：区间问题（无重叠区间 435）

```java
public int eraseOverlapIntervals(int[][] intervals) {
    if (intervals.length == 0) return 0;
    // 按右端点升序排序：结束越早，留给后面的空间越多
    Arrays.sort(intervals, (a, b) -> Integer.compare(a[1], b[1]));
    int count = 1;                       // 至少保留第一个区间
    int end = intervals[0][1];           // 已选区间的最右端点
    for (int i = 1; i < intervals.length; i++) {
        if (intervals[i][0] >= end) {    // 不重叠才保留
            count++;
            end = intervals[i][1];
        }
    }
    return intervals.length - count;     // 总数 - 保留数 = 要删除数
}
```

### 模板 2：跳跃 / 覆盖（跳跃游戏 55）

```java
public boolean canJump(int[] nums) {
    int maxReach = 0;                    // 当前能到达的最远下标
    for (int i = 0; i < nums.length; i++) {
        if (i > maxReach) return false;  // 当前位置都到不了，失败
        maxReach = Math.max(maxReach, i + nums[i]);
        if (maxReach >= nums.length - 1) return true;  // 能到终点，提前返回
    }
    return true;
}
```

### 模板 3：排序 + 双指针配对（分发饼干 455）

```java
public int findContentChildren(int[] g, int[] s) {
    Arrays.sort(g);                      // 孩子胃口升序
    Arrays.sort(s);                      // 饼干尺寸升序
    int child = 0, cookie = 0;
    while (child < g.length && cookie < s.length) {
        if (s[cookie] >= g[child]) {     // 当前饼干能满足当前孩子
            child++;                     // 满足一个孩子
        }
        cookie++;                        // 无论是否满足，饼干都用掉/跳过
    }
    return child;
}
```

### 模板 4：堆贪心（最后一块石头的重量 1046）

```java
public int lastStoneWeight(int[] stones) {
    // 大顶堆：每次取最重的两块
    PriorityQueue<Integer> heap = new PriorityQueue<>((a, b) -> b - a);
    for (int s : stones) heap.offer(s);
    while (heap.size() > 1) {
        int a = heap.poll();             // 最重
        int b = heap.poll();             // 次重
        if (a > b) heap.offer(a - b);    // 相撞后剩余重量入堆
    }
    return heap.isEmpty() ? 0 : heap.peek();
}
```

## 六、如何证明贪心的正确性

面试或竞赛中，证明贪心策略正确常用两种方法：

| 方法 | 思路 | 适用 |
|:---|:---|:---|
| **交换论证法** | 假设存在更优解，把它逐步「交换」成贪心解且不变差 | 区间调度、排序类 |
| **反证法** | 假设贪心不是最优，推出矛盾 | 覆盖、跳跃类 |
| **归纳法** | 证明前 k 步贪心最优可推出前 k+1 步最优 | 分步决策类 |

> 实战里更常用的是**举反例**：如果你能想到一个反例推翻贪心策略，说明这题不能贪心，该换 DP。想不出反例 + 能大致说通，再动手写。

## 七、复杂度分析

| 维度 | 一般规律 |
|:---|:---|
| 时间复杂度 | 多为 \(O(n\log n)\)（排序主导）或 \(O(n)\)（单次遍历） |
| 空间复杂度 | 通常 \(O(1)\) 或 \(O(n)\)（排序 / 堆） |

贪心的效率优势正是它相较 DP 的最大卖点——用排序 + 一次扫描代替了 DP 的多维状态表。

## 八、易错点与技巧

| 易错点 | 说明 |
|:---|:---|
| **误用贪心** | 最常见的坑：策略看起来对，实则有反例（如「找零」用面额贪心在某些币值下会错） |
| **排序依据选错** | 区间问题按左端点还是右端点排，直接决定成败 |
| **漏掉证明** | 没验证贪心选择性质就写代码，容易 WA |
| **边界条件** | 空数组、单元素、所有元素相同等极值 |
| **贪心 ≠ 排序后取前 k 个** | 有些问题需要动态维护（如堆），不是静态排序一次就够 |

## 九、贪心 vs 其他算法

| 方法 | 适用信号 | 与贪心的关系 |
|:---|:---|:---|
| **动态规划** | 子问题重叠、需权衡多种选择 | 贪心是 DP 的特例（每步只有一个最优选择）；见 [动态规划.md](动态规划.md) |
| **回溯** | 需要枚举所有方案 | 贪心不回溯、不枚举，只走一条路；见 [回溯.md](回溯.md) |
| **分治** | 子问题独立不重叠 | 贪心通常线性推进，分治二分递归 |

> 决策树：能证明局部最优 → 全局最优？→ 贪心；否则子问题重叠？→ DP；需要所有方案？→ 回溯。

---

## 十、一句话总结

贪心算法的本质是**「每一步都赌当前最优」**——不回头、不反悔，用排序 + 一次遍历高效求解。它的关键不在写代码，而在**证明「局部最优能导出全局最优」**；证不出来或存在反例时，就该退回动态规划。
