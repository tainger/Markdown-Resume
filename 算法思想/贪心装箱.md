# 贪心装箱

贪心装箱（Greedy Bin Packing）是**贪心思想在「把若干物品装入容量受限的箱子」这类问题上的专门套路**。它回答的是同一族问题：给定一批带「体积 / 重量 / 负载」的物品和固定容量的箱子，用**尽量少的箱子装完**，或在**箱子数固定时把负载摊得尽量均匀**。装箱问题（Bin Packing）本身是 **NP-Hard**，精确解要指数级搜索，因此工程与笔试里几乎都用**贪心近似**：排序 + 一次扫描，快且效果接近最优。

> 定位：本篇是 [贪心算法.md](贪心算法.md) 的一个**垂直子专题**。通用贪心讲「怎么判断能不能贪、怎么证明」，本篇聚焦「装箱 / 分组 / 负载均衡」这一类题的**固定策略与模板**。

---

## 一、什么是装箱问题

一句话：**把 `n` 个大小为 `w[i]` 的物品，放进容量都为 `C` 的箱子里。**

| 问法 | 目标 | 别名 |
|:---|:---|:---|
| **装箱（Bin Packing）** | 用**最少的箱子**装完所有物品 | 最少船只 / 最少卡车 / 最少机器 |
| **负载均衡（Load Balancing）** | 箱子数 `k` 固定，让**最重的箱子尽量轻** | 多机调度、任务分配、[分割数组最大值 410](../华为OD机试/32.%20末世分配资源包.md) |
| **可行性判定** | 给定箱数 / 容量，**能否装下** | 二分答案里的 `check` 函数 |

三者常常互相转化：「最少箱子」和「固定箱子求最小最大负载」互为对偶，后者又常与**二分答案**配合（二分「最大负载」，用贪心装箱验证可行）。

```
物品 w = [4, 8, 1, 4, 2, 1]，箱容 C = 10：

   ┌────────┐  ┌────────┐  ┌────────┐
   │ 8    2 │  │ 4  4  1│  │ 1      │      ← 一种装法用 3 箱
   │  (10)  │  │  (9)   │  │  (1)   │
   └────────┘  └────────┘  └────────┘
   目标：让箱子数最少（这里最优就是 2 箱：[8,2] 和 [4,4,1,1]）
```

---

## 二、为什么装箱要用贪心

装箱是 **NP-Hard**：想得到**绝对最少**的箱子，本质要枚举所有分组方式，复杂度指数级。所以：

| 思路 | 复杂度 | 用途 |
|:---|:---|:---|
| 暴力 / 回溯枚举分组 | 指数级 \(O(k^n)\) | 数据极小（`n ≤ 15` 左右）时求精确解 |
| 状压 DP | \(O(2^n \times n)\) | 中小规模求精确解 |
| **贪心近似（FF / BF / FFD）** | \(O(n\log n)\) | **笔试 / 工程首选**，答案接近最优 |

> 关键认知：**装箱贪心求的是「足够好」而非「一定最优」**。它有理论保证的近似比（见第五节），实践中通常和最优只差一两个箱子。笔试中若题目数据规模大（`n` 上万），基本就是在暗示用贪心。

## 三、四种经典装箱策略

设物品逐个到来，每来一个就要决定放进哪个已开的箱子（放不下就新开一个）。

| 策略 | 全称 | 决策规则 | 近似比 |
|:---|:---|:---|:---:|
| **FF** | First Fit（首次适应） | 从头扫箱子，放进**第一个装得下**的 | 1.7·OPT |
| **NF** | Next Fit（下次适应） | 只看**当前最后一个**箱子，装不下就直接新开 | 2·OPT |
| **BF** | Best Fit（最佳适应） | 放进「放进去后**剩余空间最小**」的箱子 | 1.7·OPT |
| **WF** | Worst Fit（最差适应） | 放进**剩余空间最大**的箱子（让负载均衡） | 2·OPT |

**加一步排序，效果显著提升**：

| 策略 | 说明 | 近似比 |
|:---|:---|:---:|
| **FFD** | First Fit **Decreasing**：先按体积**降序**排，再做 FF | ≈ 11/9·OPT + 1 |
| **BFD** | Best Fit Decreasing：降序排后做 BF | 与 FFD 相当 |

> **口诀**：**先大后小（降序）** 几乎总是更好——大物品先安排位置，小物品像「填缝」一样塞进剩余空隙，浪费更少。笔试写 **FFD** 基本够用。

### 图解：FF vs FFD

物品 `[4, 8, 1, 4, 2, 1]`，容量 `C = 10`：

```
FF（按原顺序）：
  4 → 箱1[4]
  8 → 箱1放不下(4+8>10) → 箱2[8]
  1 → 箱1[4,1]=5
  4 → 箱1[4,1,4]=9
  2 → 箱1放不下(9+2>10) → 箱2[8,2]=10
  1 → 箱1[4,1,4,1]=10
  结果：2 箱 ✓（本例 FF 就已最优）

FFD（先降序 [8,4,4,2,1,1]）：
  8 → 箱1[8]
  4 → 箱1[8]放不下 → 箱2[4]
  4 → 箱2[4,4]=8
  2 → 箱1[8,2]=10
  1 → 箱2[4,4,1]=9
  1 → 箱2[4,4,1,1]=10
  结果：2 箱 ✓，且装得更满更稳
```

## 四、代码模板（Java）

### 模板 1：FFD 求最少箱子数

```java
/**
 * 用 First Fit Decreasing 估计装完所有物品所需的最少箱子数
 * @param w 物品大小数组
 * @param C 每个箱子的容量
 */
public int minBinsFFD(int[] w, int C) {
    Integer[] arr = Arrays.stream(w).boxed().toArray(Integer[]::new);
    Arrays.sort(arr, (a, b) -> b - a);   // 关键：体积降序，先大后小
    List<Integer> bins = new ArrayList<>(); // bins.get(i) = 第 i 个箱子的剩余容量
    for (int item : arr) {
        int j = 0;
        // First Fit：找第一个装得下的箱子
        while (j < bins.size() && bins.get(j) < item) j++;
        if (j == bins.size()) {
            bins.add(C - item);          // 没有合适箱子 → 新开一个
        } else {
            bins.set(j, bins.get(j) - item); // 塞进去，扣减剩余容量
        }
    }
    return bins.size();
}
```

> 上面 `while` 线性找箱子是 \(O(n^2)\)。要 \(O(n\log n)\)，可用 **TreeMap / 有序多重集**维护「剩余容量」，`ceilingKey(item)` 直接定位（Best Fit Decreasing）。

### 模板 2：BFD —— 用 TreeMap 把找箱子降到 \(O(\log n)\)

```java
public int minBinsBFD(int[] w, int C) {
    Integer[] arr = Arrays.stream(w).boxed().toArray(Integer[]::new);
    Arrays.sort(arr, (a, b) -> b - a);        // 体积降序
    // key = 箱子剩余容量，value = 有多少个箱子恰好是这个剩余容量
    TreeMap<Integer, Integer> rooms = new TreeMap<>();
    int binCount = 0;
    for (int item : arr) {
        // Best Fit：找 >= item 的最小剩余容量（放进去后浪费最少）
        Map.Entry<Integer, Integer> e = rooms.ceilingEntry(item);
        if (e == null) {                      // 没有箱子装得下 → 新开
            binCount++;
            addRoom(rooms, C - item);
        } else {                              // 塞进该箱子并更新它的剩余容量
            int room = e.getKey();
            removeRoom(rooms, room);
            addRoom(rooms, room - item);
        }
    }
    return binCount;
}
private void addRoom(TreeMap<Integer, Integer> m, int room) {
    if (room >= 0) m.merge(room, 1, Integer::sum);
}
private void removeRoom(TreeMap<Integer, Integer> m, int room) {
    int c = m.get(room);
    if (c == 1) m.remove(room); else m.put(room, c - 1);
}
```

### 模板 3：二分答案 + 贪心 check（固定箱数，求最小「最大负载」）

当箱子数 `k` 固定、要求「最重的箱子尽量轻」时，**二分最大负载 `limit`**，用贪心 `check` 判断能否用 `k` 个箱子装下。见 [末世分配资源包（410 同型）](../华为OD机试/32.%20末世分配资源包.md)。

```java
public int minMaxLoad(int[] w, int k) {
    int lo = Arrays.stream(w).max().getAsInt(); // 下界：最大单件（谁都得装得下它）
    int hi = Arrays.stream(w).sum();            // 上界：全塞一个箱子
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (canPack(w, k, mid)) hi = mid;       // mid 可行 → 试更小
        else lo = mid + 1;                      // 不可行 → 放大
    }
    return lo;
}

/** 贪心：能否用 <= k 个箱子、每箱负载 <= limit 装完（物品需连续段时按顺序累加） */
private boolean canPack(int[] w, int k, int limit) {
    int bins = 1, cur = 0;
    for (int x : w) {
        if (cur + x <= limit) {
            cur += x;                            // 继续塞当前箱子
        } else {
            bins++;                              // 开新箱子
            cur = x;
            if (bins > k) return false;          // 箱子不够了
        }
    }
    return true;
}
```

> 若物品**可任意分配**（不要求连续），`canPack` 里的贪心改成「从大到小依次塞进当前剩余最多的箱子」，或直接沿用 FFD 思路。

## 五、近似比：贪心装箱到底差多少

装箱贪心不保证最优，但有**理论上界**（`OPT` 为最优箱数）：

| 策略 | 渐近近似比 | 直观含义 |
|:---|:---|:---|
| Next Fit | 用箱数 ≤ **2·OPT** | 最差用两倍箱子 |
| First Fit | ≤ **1.7·OPT** | 最差多七成 |
| **First Fit Decreasing** | ≤ **11/9·OPT + 1** ≈ 1.22·OPT | 最差多约两成，实践中常接近最优 |

> 结论：**排序（降序）是提升近似比的关键一步**，几乎零成本却把上界从 2 压到 1.22。工程与笔试默认写 **FFD / BFD**。

## 六、适用信号

| 看到这样的题目描述… | 套路 |
|:---|:---|
| 「用**最少的箱子 / 卡车 / 船 / 机器**装完 / 运完」 | 装箱，FFD / BFD |
| 「每个容器容量为 C，问最少需要几个」 | 装箱，FFD |
| 箱子数 **k 固定**，求「最重那个尽量轻 / 最大子段和最小」 | 二分答案 + 贪心 check |
| 「尽量平均分配 / 负载均衡 / 让最大值最小」 | 负载均衡，WF 或二分答案 |
| 物品**只能装一次**、有大小上限、求分组数 | 装箱（对比背包：背包求价值，装箱求分组数） |

## 七、复杂度分析

| 策略 | 时间复杂度 | 空间复杂度 |
|:---|:---|:---|
| FFD（线性找箱） | \(O(n^2)\) | \(O(n)\) |
| BFD（TreeMap 找箱） | \(O(n\log n)\) | \(O(n)\) |
| 二分答案 + 贪心 check | \(O(n\log(\sum w))\) | \(O(1)\) |

> 排序普遍是 \(O(n\log n)\)；瓶颈在「怎么找到合适的箱子」——线性扫是 \(O(n)\)，用有序结构是 \(O(\log n)\)。

## 八、易错点与技巧

| 易错点 | 说明 |
|:---|:---|
| **忘记降序排序** | 不排序的 FF 近似比 1.7，降序后降到 1.22，几乎白捡的优化，别漏 |
| **误把装箱当背包** | 背包在「一个容量」里求**最大价值 / 能否凑出**；装箱是「多个箱子」求**最少分组数**，别混 |
| **贪心当成精确解** | 装箱是 NP-Hard，FFD **不保证最优**；要精确解且 `n` 很小才用状压 DP / 回溯 |
| **二分下界取错** | 「最小最大负载」的二分下界必须是 `max(w[i])`，否则装不下最大单件 |
| **物品是否要求连续** | [410 类型](../华为OD机试/32.%20末世分配资源包.md)要求「连续段」，check 里只能顺序累加；可任意分配则用 FFD |
| **单件超容量** | 若存在 `w[i] > C`，无解，要提前判断 |
| **找箱子退化 \(O(n^2)\)** | 数据大时线性找箱会超时，改用 TreeMap / 优先队列 |

## 九、贪心装箱 vs 其他方法

| 方法 | 适用信号 | 与装箱的关系 |
|:---|:---|:---|
| **通用贪心** | 每步局部最优推全局最优 | 装箱是贪心的一个固定套路；策略正确性同样需理解，见 [贪心算法.md](贪心算法.md) |
| **0-1 背包 / DP** | 单容器求最大价值 / 能否凑出目标 | 背包关注「装什么最值钱」，装箱关注「分几组最省箱」；见 [0-1背包问题.md](0-1背包问题.md) |
| **二分答案** | 「最大值最小 / 最小值最大」 | 固定箱数的装箱常转成二分答案，贪心当 check；见 [二分查找.md](二分查找.md) |
| **回溯 / 状压 DP** | 数据极小、要**精确最少箱** | 装箱的精确解法，指数级；见 [回溯.md](回溯.md) |
| **桶思想** | 按值域 / 频率分组 | 都在「分组」，但桶按固定规则映射，装箱按容量约束择优放入；见 [桶思想.md](桶思想.md) |

## 十、一句话总结

贪心装箱的本质是**「先大后小，见缝插针」**——因为最优装箱是 NP-Hard，实践中用 **First Fit Decreasing** 这类贪心近似：把物品**降序排列**，每个物品塞进第一个（或最合适的）装得下的箱子，装不下就新开一个。它不保证最少箱数，但近似比约 1.22，快且够好；当箱数固定要「最大负载最小」时，则转成**二分答案 + 贪心校验**。
