## P7 必背清单（速查）

- **短链长度估算**：Base62（a-z A-Z 0-9 共 62 字符），6 位 = 62⁶ ≈ 568 亿，足够支撑大平台；7 位 = 3.5 万亿。短码 = 全局自增 ID 或 hash 截断后 Base62 编码。
- **短链 301 vs 302**：301 永久重定向（浏览器缓存，减轻服务端压力但**统计不到点击**）；302 临时重定向（每次都回服务端，**能统计点击 + 防预缓存长链失效**）。生产首选 302。
- **发号器三大派系**：UUID（无序、占 36 字符、不适合做主键和短码源）、Snowflake（有序、64bit、需解决时钟回拨）、号段模式（DB 高性能批分配、Leaf 最常用）。生产首选「**Snowflake 改造（Bits + 时钟回拨等待）+ 号段兜底**」双轨。
- **秒杀核心三段论**：①接入层限流 + 验证码拦截 80% 流量 → ②Redis 预减库存（DECR 原子防超卖）+ 异步 MQ 削峰落库 → ③DB 兜底（乐观锁 + 库存分段）。**绝不直接打 DB**。
- **秒杀防超卖三道闸**：Redis `DECR` 原子减库存（够减才放行）→ MQ 串行化下单（单消费者保顺序）→ DB `UPDATE stock = stock - 1 WHERE stock > 0`（兜底）。
- **秒杀热 key 三种打散**：本地缓存（Caffeine 1s 过期扛热点读）+ 多副本 key（stock_1/stock_2... 分桶减库存）+ 读主从分离。单 key 击穿 Redis = 全站雪崩。
- **Snowflake 时钟回拨**：当前时间 < 上次时间戳 → 等 `回拨毫秒数` 再发；超过阈值（如 5ms）则报错 / 走备用机房；或引入 NTP 单调时钟序列号兜底。
- **Feed 流推拉选型**：写扩散（推 fanout-on-write）适合**粉丝 < 10w 的中小 V**；读扩散（拉 fanout-on-read）适合**百万粉丝大 V**；**推拉结合**=大 V 读扩散 + 普通用户写扩散 + 活跃用户判定是核心优化。
- **Feed 流排序**：微博用「**关注时间倒序 + 个性化重排**」混排；朋友圈严格时间倒序（不做个性化）。Timeline = Redis ZSet（score=timestamp）+ DB 兜底，超 7 天读冷存。
- **系统设计七步法**：①澄清需求（功能性 + 非功能性）→ ②估算 QPS/存储/带宽 → ③API 设计 → ④数据模型与存储选型 → ⑤高层架构图 → ⑥深挖核心模块 → ⑦扩展性/容错/监控。**先骨架后血肉**，面试官更喜欢看到结构化思考。

## 学习建议

1. **按 1→4 顺序学**：短链是 SDD 入门（结构最简单，重在估算和编码）→ 秒杀是综合题（限流/缓存/MQ/锁全用上）→ ID 生成器是基础设施（面试最常被引申到「你们发号器怎么搞」）→ Feed 流是数据模型题（推拉模型 + 排序 + 大 V 难点）。
2. **每篇先盖住答案**，自己画一遍架构图再对照，找差距；能 30 分钟内口述完 = 过关。
3. **「选型对比表」+「易错点」是 P7 核心**——面试官不只问「你怎么设计」，更要问「**为什么这么选，不这么选会怎么样，踩过什么坑**」。
4. P7 系统设计题面试常**结合简历项目深挖**：准备 1~2 个真实案例（STAR 结构），比如你 AgentMate 里的发号器选型、秒杀式任务触发、Feed 流式消息推送，把笔记里的方案落到自己项目上。
5. **数字要熟记**：Base62 容量、Snowflake 单机 4M ID/s、读写扩散分界线（10w 粉丝）、典型 QPS 量级（电商 1w→10w→100w）——面试估算题张口就来。
