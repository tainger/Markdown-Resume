# AI 应用评测怎么做:别只靠「感觉不错」

> 探小虎 · 技术分享

AI 应用最大的坑,是「感觉不错就上线」。模型换了一版、prompt 调了一下,到底是变好还是变差?不跑评测,谁也说不清——上一版改对了 A 场景,可能把 B 场景改崩了,你根本不知道。

传统软件有单元测试兜底,AI 应用没有「确定性」可测,于是很多人就放弃了评测,靠「试两下感觉不错」过关。这是 AI 应用质量上不去的最大原因。本文聊一套可落地的 LLM 应用评测方法论。

![AI 应用评测示意](images/ai-eval.jpg)

---

## 一、为什么「感觉不错」靠不住

AI 应用的输出有三个传统软件没有的特性,**任何一个都让「感觉」失灵**:

| 特性 | 为什么让感觉失灵 |
|:---|:---|
| **非确定性** | 同一输入每次输出可能不同,试两次不能代表全部 |
| **长尾分布** | 90% 的 case 看着对,10% 的长尾 case 崩了,你试不到就漏 |
| **改一处波及全局** | 改 prompt 修 A 场景,可能暗伤 B 场景 |

> 一句话概括:**「试两下感觉不错」只覆盖了你恰好试到的那几个点,长尾和回归全靠运气。**

---

## 二、评测的三个层次

靠谱的 AI 应用评测,分三层,各管一件事:

```
离线 golden set  →  回归评测  →  线上监控
 (开发期)        (每次改动)    (上线后)
   ↓               ↓            ↓
 定基线          防退化        抓线上崩
```

| 层 | 时机 | 干嘛 |
|:---|:---|:---|
| **离线 golden set** | 开发期 | 建一批标注好的问答对,当「考试卷」 |
| **回归评测** | 每次改版 | 改完跑一遍 golden set,对比分数 |
| **线上监控** | 上线后 | 抽样人工复核 + 用户反馈追踪 |

三层缺一不可:只做离线,不知道线上崩;只做线上,改版时没兜底。

---

## 三、golden set 怎么建

golden set 是评测的地基,建得好坏决定评测有没有用。

三个要点:

1. **规模够。** 几十个不够,至少几百个,才能覆盖长尾。
2. **覆盖全。** 别只放「正常 case」,边界 case、对抗 case、长尾 case 都要有——**评测卷的难度,要高于线上真实分布**。
3. **有标注。** 每个 case 标好「期望输出」或「评判标准」,不能只标「对/错」——要可判。

> 设计哲学:**golden set 是你的考试卷,不是你的宣传册。放难题、放边界 case,才测得出真问题。**

---

## 四、LLM-as-judge:用模型评模型

人工评几百上千个 case 太贵,于是有了 **LLM-as-judge**:用一个更强的模型,当裁判评另一个模型的输出。

它的优势和坑:

| 优势 | 坑 |
|:---|:---|
| 大规模自动化评测 | 裁判模型自己有偏见 |
| 比人工便宜得多 | 对模糊边界判断不稳 |
| 可重复 | 评分标准要写清楚,否则漂移 |

**关键做法:给裁判明确的评分标准(rubric)。** 别问「这个回答好不好」,要问「这个回答是否覆盖了 X、Y、Z 三个要点,有无事实错误」——**评分标准越具体,裁判越稳**。

> LLM-as-judge 不是万能的,但对规模化回归评测,它远比「感觉」靠谱。

---

## 五、回归评测:防 prompt 漂移

AI 应用有个独特问题:**改一版,可能暗伤别的场景**。prompt 调了一下,主场景变好了,某个边界 case 突然崩了——你不知道,直到线上炸了。

回归评测就是防这个的:

```
改 prompt / 换模型
    ↓
跑一遍 golden set(几百 case)
    ↓
对比新旧分数:总分会变,各 case 分项也变
    ↓
某 case 分数掉了?→ 看是不是改崩的 → 决定回滚还是补
```

**没有回归评测,改 AI 应用就是蒙眼开车**——你只知道改了什么,不知道改坏了什么。

---

## 六、线上监控

上线后,离线评测管不到真实流量,要靠线上监控:

- **抽样人工复核。** 每天抽一定比例的线上输出,人工标对错,算线上准确率。
- **用户反馈追踪。** 点踩、投诉、修正率,都是信号。
- **异常报警。** 输出长度突涨、拒答率突升、某类 case 准确率掉,自动报警。

> 离线评测测的是「考试卷」,线上监控测的是「真实战场」。两者数据要对得上——离线好但线上差,说明 golden set 没覆盖线上真实分布。

---

## 七、常见踩坑

| 坑 | 后果 | 解法 |
|:---|:---|:---|
| **golden set 只放正常 case** | 长尾测不出 | 放边界、对抗、长尾 case |
| **没有回归评测** | 改版改崩了不知道 | 每次改动跑 golden set 对比 |
| **LLM-as-judge 标准模糊** | 裁判评分漂移 | 给具体 rubric,要可判 |
| **只看总分** | 某类 case 暗崩被总分掩盖 | 分项看分数 |
| **离线和线上对不上** | 离线好线上差 | golden set 覆盖线上真实分布 |

---

## 八、写在最后

1. **「感觉不错」靠不住。** 非确定 + 长尾 + 全局波及,任一个都让感觉失灵。
2. **三层评测缺一不可。** 离线 golden set 定基线,回归评测防退化,线上监控抓真实崩。
3. **LLM-as-judge 要给具体标准。** 评分 rubric 越具体,裁判越稳。

AI 应用与传统软件最大的差别,就是**没有「确定性」可测**。正因如此,评测不是可选项,是质量唯一的兜底——**没有评测的 AI 应用,质量永远停在「感觉不错」的水平**。
