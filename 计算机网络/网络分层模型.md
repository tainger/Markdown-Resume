# 网络分层模型（OSI 与 TCP/IP）

分层是整个计算机网络的设计哲学：把复杂的通信问题拆成若干层，**每层只对上层提供服务、只依赖下层的能力**，层与层之间通过接口解耦。面试的很多问题（「输入 URL 之后发生了什么」「数据包怎么到达对端」）都要靠分层视角来回答。

---

## 一、两种分层模型：OSI 七层 vs TCP/IP 四层

| 对比项 | OSI 七层 | TCP/IP 四层 |
|:---|:---|:---|
| 性质 | ISO 制定的**理论参考模型** | 互联网**实际使用**的模型 |
| 层数 | 物理→数据链路→网络→传输→会话→表示→应用 | 网络接口→网络→传输→应用 |
| 关系 | 教科书式的概念框架 | OSI 的工程简化落地版 |

两层的对应关系：

```
        OSI 七层                TCP/IP 四层            传数据单位
  ┌─────────────────┐
  │ 7 应用层  Application │─┐
  ├─────────────────┤ ├ 应用层           ← HTTP、DNS、SSH…    报文 message
  │ 6 表示层  Presentation│─┤
  ├─────────────────┤ │
  │ 5 会话层  Session     │─┘
  ├─────────────────┤
  │ 4 传输层  Transport   │──→ 传输层          ← TCP、UDP           段 segment
  ├─────────────────┤
  │ 3 网络层  Network     │──→ 网络层          ← IP、ICMP、ARP*      包 packet
  ├─────────────────┤
  │ 2 数据链路层 Data Link │─┐
  ├─────────────────┤ ├ 网络接口层        ← 以太网、Wi-Fi        帧 frame
  │ 1 物理层  Physical    │─┘                                          比特 bit
  └─────────────────┘
  * ARP 介于 2/3 层之间，面试说「网络层辅助协议」即可
```

> 面试话术：平时工作中用 TCP/IP 四层讲**工程**，用 OSI 七层讲**概念**。会话/表示层在现实中并入应用层（加密是 TLS、序列化是 JSON/Protobuf）。

## 二、每层职责与典型协议

| 层 | 职责（一句话） | 典型协议 | 寻址方式 | 典型设备 |
|:---|:---|:---|:---|:---|
| **应用层** | 为应用定义「说什么」（报文语义） | HTTP、DNS、SMTP、FTP、SSH | 域名/端口 | — |
| **传输层** | 进程到进程的「端到端」传输，靠**端口**区分进程 | TCP、UDP | 端口号 | — |
| **网络层** | 主机到主机的「跨越网络」路径选择（路由） | IP、ICMP、ARP | IP 地址 | 路由器 |
| **数据链路层** | 相邻节点（同一链路内）的帧传输、差错检测 | 以太网、PPP、Wi-Fi(802.11) | MAC 地址 | 交换机、网桥 |
| **物理层** | 比特流的电气/光信号传输 | RJ45、光纤规范 | — | 集线器、中继器 |

关键区分（高频追问）：

- **交换机 vs 路由器**：交换机工作在链路层，按 **MAC** 转发帧（局域网内）；路由器工作在网络层，按 **IP** 转发包（跨网络）。
- **IP 地址 vs MAC 地址**：IP 管「最终去哪」（全局路由，会变），MAC 管「下一跳给谁」（链路内不变）。类比：IP 是收货地址，MAC 是每一段快递车。
- **端口**：0~1023 知名端口（HTTP 80/HTTPS 443/SSH 22/DNS 53），传输层「IP+端口」唯一确定一条连接。

## 三、数据封装与解封装（发送方加头、接收方去头）

```
 发送方（自上而下逐层加头部）              接收方（自下而上逐层去头部）

 应用层:      [ HTTP 报文 ]                          ↑ 还原
 传输层:      [TCP头 | HTTP 报文]        = 段        ↑
 网络层:      [IP头 | TCP头 | HTTP]      = 包        ↑
 链路层:      [帧头|IP头|TCP头|HTTP|帧尾] = 帧       ↑
 物理层:      01010101...（比特流）      ────────→  ↑
```

每一层只「认识」自己的头部：链路层交换机读 MAC 帧，路由器剥到 IP 层查路由，最终接收方对端进程拿到原始 HTTP 报文。**对等层之间用「协议」通信，相邻层之间用「接口」服务**。

## 四、经典综合题：输入 URL 到页面展示，中间发生了什么

按分层顺序口述（每一层展开一点都是追问入口）：

1. **应用层**：URL 解析 → [DNS](DNS与CDN.md) 解析域名得到 IP（缓存→递归/迭代查询）。
2. **传输层**：建立 [TCP 连接](TCP.md)（三次握手）；若是 HTTPS 再完成 [TLS 握手](HTTPS.md)。
3. **应用层**：发送 [HTTP 请求](HTTP.md)，服务器处理后返回 HTML。
4. **网络层**：IP 协议逐跳路由；用 [ARP](IP与链路层.md) 找到网关 MAC，跨网段由路由器转发，可能经过 [NAT](IP与链路层.md)。
5. **链路层/物理层**：以太网帧在每段链路上传输（下一跳 MAC 每段都变，IP 不变）。
6. **浏览器渲染**：解析 HTML/CSS 构建渲染树、执行 JS、渲染页面；期间可能并发拉取静态资源（CDN、HTTP 缓存）。

> 追问预判：DNS 细节 → [DNS与CDN.md](DNS与CDN.md)；握手挥手 → [TCP.md](TCP.md)；加密 → [HTTPS.md](HTTPS.md)；状态码/缓存 → [HTTP.md](HTTP.md)。

## 五、易错点

| 易错点 | 澄清 |
|:---|:---|
| **OSI 是实际使用的模型** | 实际落地是 TCP/IP；OSI 是理论参考 |
| **会话层、表示层不存在** | 功能并入应用层：TLS 加密≈表示层，长连接管理≈会话层 |
| **ARP 严格属于网络层** | ARP 介于 2/3 层之间，说「辅助 IP 工作」最稳 |
| **MAC 地址全局唯一所以用来路由** | 路由用的是 **IP**；MAC 只在当前链路有效，跨路由会被替换 |
| **交换机工作在网络层** | 普通交换机是链路层设备；三层交换机才有路由能力 |
| **「IP+端口」标识一台主机** | 标识的是**一个进程（socket）**；主机靠 IP |

---

## 六、一句话总结

网络分层 = **每层干一件事**：链路层管相邻节点（MAC），网络层管全局寻址路由（IP），传输层管进程到进程（端口 + TCP/UDP），应用层管报文语义（HTTP/DNS）。发送方自上而下加头封装，接收方逆向解封装——「输入 URL 后发生了什么」就是这条链路的展开叙述。
