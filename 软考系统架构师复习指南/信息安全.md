# 信息安全

> 综合知识占比约 8%，选择题为主，论文偶尔涉及安全架构方向。

---

## 一、信息安全三要素（CIA）

| 要素 | 含义 | 攻击方式 | 防御 |
|:---|:---|:---|:---|
| **机密性（Confidentiality）** | 信息不被未授权访问 | 窃听、嗅探 | 加密、访问控制 |
| **完整性（Integrity）** | 信息不被篡改 | 篡改、中间人 | 哈希、数字签名、MAC |
| **可用性（Availability）** | 授权用户可正常使用 | DDoS、勒索 | 冗余、限流、备份 |

> 扩展：真实性（Authenticity）、不可否认性（Non-repudiation）

## 二、密码学基础

### 2.1 对称加密

- **特点**：加密和解密用同一密钥
- **算法**：DES（56 位，已不安全）、3DES（112 位）、AES（128/192/256 位）、SM4（国密）
- **优点**：速度快、适合大量数据
- **缺点**：密钥分发困难、密钥管理复杂

### 2.2 非对称加密

- **特点**：公钥加密、私钥解密（或反之）
- **算法**：RSA（大整数分解）、ECC（椭圆曲线）、SM2（国密）
- **优点**：无需预先共享密钥、支持数字签名
- **缺点**：速度慢（比对称慢 100~1000 倍）

### 2.3 哈希算法

- **特点**：单向、定长输出、不可逆、抗碰撞
- **算法**：MD5（128 位，已不安全）、SHA-1（160 位，已不安全）、SHA-256（256 位）、SM3（国密）
- **用途**：密码存储、文件完整性校验、数字签名摘要

### 2.4 混合加密（主流方案）

```
发送方：
1. 生成随机对称密钥 K
2. 用 K 加密大数据（AES）
3. 用接收方公钥加密 K（RSA）
4. 一起发送

接收方：
1. 用自己私钥解密得到 K
2. 用 K 解密大数据
```

## 三、数字签名与证书

### 3.1 数字签名原理

```
发送方：原文 → 哈希摘要 → 私钥签名 → 原文 + 签名 发送
接收方：原文 → 哈希摘要 → 公钥验签 → 对比摘要

作用：不可否认性 + 完整性验证 + 身份认证
```

### 3.2 PKI 与 CA

- **PKI（公钥基础设施）**：管理公钥的认证、分发、撤销
- **CA（证书颁发机构）**：签发数字证书的可信第三方
- **数字证书内容**：持有者信息 + 公钥 + CA 签名 + 有效期
- **证书链验证**：叶子证书 → 中间 CA → 根 CA（浏览器内置信任列表）

## 四、访问控制模型（必考）

| 模型 | 全称 | 核心 | 适用场景 |
|:---|:---|:---|:---|
| DAC | 自主访问控制 | 资源所有者自主决定 | 文件权限（chmod） |
| MAC | 强制访问控制 | 系统强制安全标签 | 军事、政府 |
| RBAC | 基于角色 | 用户 → 角色 → 权限 | 企业级系统（主流） |
| ABAC | 基于属性 | 动态属性策略 | 云原生、细粒度 |

## 五、网络安全协议

| 协议 | 层级 | 作用 |
|:---|:---|:---|
| HTTPS/TLS | 应用层之下 | Web 加密传输 |
| SSH | 应用层 | 远程登录加密 |
| IPSec | 网络层 | VPN 加密 |
| SSL/TLS 握手 | — | 协商加密套件 + 密钥交换 + 身份认证 |

### TLS 1.2 vs TLS 1.3

| 维度 | TLS 1.2 | TLS 1.3 |
|:---|:---|:---|
| 握手 | 2-RTT | 1-RTT |
| 密钥交换 | 支持静态 RSA | 只支持 ECDHE（前向安全） |
| 加密套件 | 大量套件 | 精简（TLS_AES_128_GCM_SHA256 等） |
| 安全性 | 可降级攻击 | 更安全 |

## 六、常见攻击与防御

| 攻击 | 原理 | 防御 |
|:---|:---|:---|
| SQL 注入 | 拼接 SQL 执行恶意语句 | 参数化查询、ORM |
| XSS | 注入恶意脚本执行 | 输出转义、CSP |
| CSRF | 冒用用户身份发请求 | CSRF Token、SameSite Cookie |
| DDoS | 大量请求打满资源 | 限流、WAF、CDN 清洗 |
| 中间人 | 劫持通信 | TLS、证书校验、防篡改 |
| 重放攻击 | 截获请求重发 | 时间戳 + Nonce + 签名 |
