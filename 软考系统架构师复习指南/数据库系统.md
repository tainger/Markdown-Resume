## 一、数据库设计基础

### 1.1 概念模型 → 逻辑模型 → 物理模型

```
需求分析 → ER 图（概念模型）→ 关系模式（逻辑模型）→ 物理存储（物理模型）
```

### 1.2 ER 图转关系模式规则

| ER 关系 | 转换规则 |
|:---|:---|
| 实体 | 转为一个关系模式 |
| 1:1 联系 | 联系合并到任意一端，加外键 |
| 1:N 联系 | 联系合并到 N 端，加外键 |
| M:N 联系 | 联系单独转为关系模式 |
| 弱实体 | 单独建表，加识别关系外键 |

## 二、范式与反范式

### 2.1 范式递进（必考）

| 范式 | 要求 | 解决问题 |
|:---|:---|:---|
| **1NF** | 字段原子性，不可再分 | 重复组 |
| **2NF** | 1NF + 消除部分依赖（非主键完全依赖主键） | 部分函数依赖 |
| **3NF** | 2NF + 消除传递依赖（非主键不依赖其他非主键） | 传递函数依赖 |
| **BCNF** | 3NF + 所有决定因素都是候选键 | 主属性对候选键的依赖 |

### 2.2 反范式化

- **目的**：用空间换时间，减少 JOIN，提升查询性能
- **手段**：增加冗余字段、合并表、预计算
- **风险**：数据一致性维护成本高

## 三、事务与并发控制

### 3.1 ACID 特性

| 特性 | 含义 | 实现手段 |
|:---|:---|:---|
| 原子性（Atomicity） | 要么全做，要么全不做 | undo log 回滚 |
| 一致性（Consistency） | 数据从一个合法状态到另一个 | 约束 + 事务 |
| 隔离性（Isolation） | 并发事务互不干扰 | 锁 + MVCC |
| 持久性（Durability） | 提交后永久保存 | redo log + 刷盘 |

### 3.2 隔离级别（必考）

| 级别 | 脏读 | 不可重复读 | 幻读 |
|:---|:---|:---|:---|
| 读未提交（Read Uncommitted） | ✅ | ✅ | ✅ |
| 读已提交（Read Committed） | ❌ | ✅ | ✅ |
| 可重复读（Repeatable Read） | ❌ | ❌ | ✅（MySQL InnoDB 通过 Next-Key Lock 基本解决） |
| 串行化（Serializable） | ❌ | ❌ | ❌ |

> 详细实现见 [`../mysql/5. 事务与锁.md`](../mysql/5.%20事务与锁.md)

### 3.3 锁机制

- **粒度**：行锁 > 页锁 > 表锁（粒度越小并发越高）
- **类型**：共享锁（S 锁，读锁）、排他锁（X 锁，写锁）
- **死锁**：互斥、请求保持、不剥夺、循环等待；解决：死锁检测 + 超时回滚

## 四、分布式数据库

### 4.1 CAP 定理（必考）

```
C（一致性）+ A（可用性）+ P（分区容错性）三选二

CP：ZooKeeper、HBase、MongoDB
AP：Cassandra、DynamoDB、Redis Cluster
```

### 4.2 BASE 理论（最终一致性）

- **BA**：基本可用（Basically Available）
- **S**：软状态（Soft State，允许中间状态）
- **E**：最终一致性（Eventual Consistency）

### 4.3 数据分片

| 方式 | 说明 | 优点 | 缺点 |
|:---|:---|:---|:---|
| 水平分片 | 按行拆分（如按用户 ID hash） | 扩展性好 | 跨片查询复杂 |
| 垂直分片 | 按列拆分（如冷热分离） | 降低单表宽度 | JOIN 开销 |
| 混合分片 | 两者结合 | 灵活 | 管理复杂 |

### 4.4 读写分离

- **主从架构**：主库写 + 从库读
- **延迟问题**：主从复制延迟导致读到旧数据
- **解决方案**：强制读主（写后立即读）、半同步复制、并行复制

## 六、数据库性能优化

1. **SQL 优化**：避免全表扫描、合理使用索引、EXPLAIN 分析执行计划
2. **索引优化**：B+ 树索引最左前缀原则、覆盖索引、避免索引失效
3. **表设计**：适当反范式化、冷热分离、字段类型最小化
4. **架构优化**：读写分离、分库分表、引入缓存、异步化
