## 一、软件开发模型

### 1.1 传统模型对比

| 模型 | 核心思想 | 优点 | 缺点 | 适用场景 |
|:---|:---|:---|:---|:---|
| **瀑布模型** | 顺序线性、阶段间文档驱动 | 简单、易管理 | 不适应需求变化、后期才能看到产品 | 需求明确、技术成熟 |
| **V 模型** | 开发与测试对等 | 测试早期介入 | 仍是顺序、文档重 | 需求明确、质量要求高 |
| **原型模型** | 快速构建原型、迭代确认 | 降低需求风险 | 原型可能被误用、成本高 | 需求不明确、探索性项目 |
| **增量模型** | 分批交付、逐步完善 | 早期可用、风险分散 | 增量集成困难、结构要求高 | 需求可分、核心功能明确 |
| **螺旋模型** | 迭代 + 风险驱动 | 风险控制好、灵活 | 管理复杂、成本高 | 大型高风险项目 |
| **喷泉模型** | 面向对象、无间隙迭代 | 开发无缝、可并行 | 管理复杂 | 面向对象系统 |

### 1.2 敏捷开发

- **敏捷宣言 4 价值观**：
  1. 个体和交互 > 流程和工具
  2. 可工作的软件 > 详尽的文档
  3. 客户合作 > 合同谈判
  4. 响应变化 > 遵循计划

- **Scrum 框架**：
  - **角色**：Product Owner（产品负责人）、Scrum Master（敏捷教练）、开发团队
  - **事件**：Sprint（迭代 2~4 周）、Sprint Planning、Daily Standup、Sprint Review、Sprint Retrospective
  - **工件**：Product Backlog（产品待办）、Sprint Backlog（迭代待办）、Increment（增量）

- **极限编程（XP）**：结对编程、测试驱动开发（TDD）、持续集成、重构

### 1.3 DevOps

- **核心**：开发（Dev）+ 运维（Ops）一体化，打通 CI/CD 流水线
- **CI（持续集成）**：代码提交 → 自动构建 → 自动测试 → 合并
- **CD（持续交付/部署）**：测试通过 → 自动发布到生产
- **关键实践**：基础设施即代码（IaC）、容器化（Docker）、编排（K8s）、可观测性

## 二、需求工程

### 2.1 需求分类

| 类型 | 描述 | 示例 |
|:---|:---|:---|
| 功能需求 | 系统必须做什么 | 用户登录、订单查询 |
| 非功能需求 | 系统质量属性 | 响应时间 < 200ms、支持 1000 QPS |
| 约束 | 限制条件 | 必须用 Java、数据库用 MySQL |

### 2.2 需求工程流程

```
需求获取 → 需求分析 → 需求规格说明 → 需求验证 → 需求管理
```

- **获取方法**：访谈、问卷调查、观察、原型、用例
- **分析技术**：用例建模、数据流图（DFD）、实体关系图（ER）
- **需求变更**：必须走变更控制流程（CCB 变更控制委员会）

## 三、UML 统一建模语言

### 3.1 UML 图分类

| 大类 | 图 | 用途 |
|:---|:---|:---|
| **结构图** | 类图 | 类、属性、方法、关系（必考） |
| | 对象图 | 系统某时刻的快照 |
| | 组件图 | 构件及依赖关系 |
| | 部署图 | 节点上的构件部署 |
| | 包图 | 包的组织与依赖 |
| **行为图** | 用例图 | 参与者与用例关系（需求建模） |
| | 顺序图 | 对象间消息的时间顺序 |
| | 通信图 | 对象间关系（强调结构） |
| | 状态图 | 对象状态变迁 |
| | 活动图 | 业务流程、并发活动 |

### 3.2 类图关系（必考）

| 关系 | 符号 | 强度 | 示例 |
|:---|:---|:---|:---|
| 依赖 | `┄┄▷` | 最弱 | A 临时使用 B |
| 关联 | `——` | 弱 | A 知道 B |
| 聚合 | `——◇` | 中 | 整体与部分（部分可独立） |
| 组合 | `——◆` | 强 | 整体与部分（部分不可独立） |
| 泛化/继承 | `——▷` | 强 | is-a 关系 |
| 实现 | `┄┄▷`（虚线） | 强 | 接口实现 |

### 3.3 用例图关系

- **包含（include）**：基础用例一定包含被包含用例
- **扩展（extend）**：基础用例在特定条件下扩展
- **泛化**：子用例继承父用例行为

## 四、设计模式（必考）

### 4.1 创建型模式（5 种）

| 模式 | 核心思想 | 经典应用 |
|:---|:---|:---|
| 单例 | 全局唯一实例 | Spring Bean 默认单例、Logger |
| 工厂方法 | 子类决定创建哪个对象 | `FactoryBean`、`@Bean` |
| 抽象工厂 | 创建一系列相关对象 | `ConnectionFactory` |
| 建造者 | 分步构建复杂对象 | `StringBuilder`、`Lombok @Builder` |
| 原型 | 克隆现有对象 | `Object.clone()` |

### 4.2 结构型模式（7 种）

| 模式 | 核心思想 | 经典应用 |
|:---|:---|:---|
| 适配器 | 接口转换 | Spring `HandlerAdapter` |
| 桥接 | 抽象与实现分离 | JDBC 驱动 |
| 组合 | 树形结构 | 菜单组织 |
| 装饰 | 动态增强 | Java IO 流、`HttpServletRequestWrapper` |
| 外观 | 简化子系统接口 | 服务门面 |
| 享元 | 共享细粒度对象 | Integer 缓存、String 池 |
| 代理 | 控制访问 | Spring AOP、RPC 代理 |

### 4.3 行为型模式（11 种）

| 模式 | 核心思想 | 经典应用 |
|:---|:---|:---|
| 策略 | 算法可互换 | 支付方式、折扣策略 |
| 模板方法 | 骨架固定，步骤可变 | Spring `JdbcTemplate` |
| 观察者 | 一对多通知 | `Observer`、Spring Event |
| 责任链 | 链式处理 | Servlet Filter、Interceptor |
| 命令 | 请求封装 | Runnable、MVC Command |
| 迭代器 | 顺序访问 | Iterator |
| 中介者 | 降低耦合 | MVC Controller |
| 备忘录 | 状态保存 | 事务回滚 |
| 状态 | 状态转换 | 订单状态机 |
| 访问者 | 遍历操作稳定 | AST 遍历 |
| 解释器 | 语法解释 | SpEL、正则 |

## 五、CMMI 能力成熟度模型

### 5 个等级

| 级别 | 名称 | 特征 |
|:---|:---|:---|
| 1 | 初始级 | 混乱、无序、靠个人英雄 |
| 2 | 已管理级 | 基本项目管理、可重复 |
| 3 | 已定义级 | 标准化、文档化的过程 |
| 4 | 量化管理级 | 统计过程控制、数据驱动 |
| 5 | 优化级 | 持续改进、缺陷预防 |

## 六、软件测试

### 6.1 测试分类

| 维度 | 类型 | 说明 |
|:---|:---|:---|
| 阶段 | 单元测试 | 函数/类级别 |
| | 集成测试 | 模块间接口 |
| | 系统测试 | 完整系统功能 |
| | 验收测试 | 用户视角 |
| 方法 | 黑盒测试 | 不看代码，只测功能 |
| | 白盒测试 | 基于代码结构 |
| | 灰盒测试 | 两者结合 |

### 6.2 白盒测试覆盖标准（由弱到强）

1. 语句覆盖（最弱）
2. 判定覆盖（分支覆盖）
3. 条件覆盖
4. 判定-条件覆盖
5. 条件组合覆盖
6. 路径覆盖（最强）
