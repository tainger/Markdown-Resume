# 算法面试实战指南

> "我刷了 500 道 LeetCode，为什么算法面还是挂了？"——80% 的情况不是你不会做，而是**面试场上的节奏、表达、临场策略**出了问题。本文从「面试官视角」讲算法面试的科学应对：从读题到通过，每一步怎么做、哪些坑绝不能踩；并整理各大厂算法面的难度分布、题型频率和备考清单。

## 一、算法面试 7 步答题法（任何题都套这个流程）

**⭐ 这是整本书最重要的部分，面试前默背一遍**。

```
第 1 步：澄清问题（1~2 分钟）
   │  复述题目 + 问清楚 5 件事：
   │   ① 输入范围：数组长度？整数范围？有没有负数/零？有没有重复？
   │   ② 输出要求：返回一个/多个？什么格式？顺序有没有要求？
   │   ③ 复杂度要求：有没有要求 O(N) / O(1) 空间？（如果没问也要自己评估）
   │   ④ 特殊情况：空输入 / 单元素 / 无解时返回什么？
   │   ⑤ 数据类型：整数会不会溢出？（大数相加/相乘要特别问）
   │
   ▼
第 2 步：举 2~3 个例子确认理解（1 分钟）
   │  口头给例子 + 问面试官："这样输入对吗？预期输出是 XXX 对吗？"
   │  例如：两数之和题，说"比如输入 nums = [2,7,11,15], target = 9，
   │        预期返回 [0,1] 对吗？那如果有重复答案，比如 [3,3] 找 6，
   │        是返回 [0,1] 吗？如果有多个解，返回哪一个？"
   │
   ▼
第 3 步：讲思路（2~3 分钟）—— ⭐ 这一步决定你 50% 的分数
   │  不要只讲最优解！按「暴力解 → 优化方向 → 最终最优解」的顺序说：
   │   ① 暴力解："最直接的方法是 XX，时间 O(N²) 空间 O(1)，但是这样有
   │             YYY 的问题，在数据量到 1e5 时会超时，所以我们要优化。"
   │   ② 优化方向："哪里可以剪？→ 重复计算可以 memoize / 用空间换时间
   │             用哈希 / 利用有序性双指针 / 状态转移 DP"
   │   ③ 最终最优："因此我想到的最优解法是 ZZZ，时间 O(N) 空间 O(1)。"
   │  ★★ 讲完问面试官："这个思路您觉得 OK 吗？有没有什么我没考虑到的点？"
   │     （面试官一般会点头，或者给你 hint，少走很多弯路！）
   │
   ▼
第 4 步：编码（15~25 分钟）—— 边写边讲，不要沉默
   │  · 先写函数签名（参数/返回值类型），再写注释说明每段做什么
   │  · 变量名要有意义（`windowMap` 不是 `map`，`slow/fast` 不是 `i/j`）
   │  · 写关键行时说一句"这里我要做的是……"
   │  · 复杂逻辑先写伪代码占位（TODO 注释），然后逐步填充
   │  · 代码风格：缩进一致、括号对齐、不要用太花哨的语法糖
   │
   ▼
第 5 步：自己先跑 2 组数据（2 分钟）—— ⭐ 别等面试官发现 bug
   │  ① 正常情况：比如"[2,7,11,15], 9 → [0,1]"，逐行跑一遍
   │  ② 边界情况：空数组、单元素、全 0、负数、正好在边界上
   │  ③ 自己发现 bug 立刻说："这里我发现了一个 bug，在 XX 行，原因是
   │     XX，我来修正一下——"（自己发现并修正，比面试官发现扣少很多分）
   │
   ▼
第 6 步：复杂度分析 + 讨论 trade-off（1 分钟）
   │  主动说："这个算法的时间复杂度是 O(N)，因为我们只遍历了一次；
   │         空间复杂度是 O(1)，没有用额外的数据结构。"
   │  加分："如果数据量更大，比如 1e7 数组，我们的方案有没有瓶颈？
   │        这里可以考虑用 XX 进一步优化，或者 YY 的 trade-off 牺牲空间。"
   │
   ▼
第 7 步：扩展讨论（可选）
   │  如果还有时间，面试官可能问：
   │  · 「有没有其他解法？」→ 讲另一种（比如"也可以用排序 + 双指针，
   │    空间 O(1) 但要改原数组，如果允许修改原数组的话可以选这种"）
   │  · 「如果输入是数据流怎么办？」→ 讲在线算法
   │  · 「如果要找前 K 个解呢？」→ 堆维护 TopK
```

### 一个 7 步法的实战示例（「和为 K 的子数组」）

> 这段对话模板，面试时念出来都比沉默 10 分钟强：

```
你：好的，我先确认一下题意。题目是给一个整数数组 nums 和一个整数 k，
     要求找出数组中「和等于 k 的连续子数组」的个数，对吗？
面试官：对。

你：好，我再确认几个边界。数组长度有上限吗？元素值可以是负数/零吗？
     比如 nums = [1], k = 0 应该返回 0，对吗？如果 nums = [0,0], k = 0
     的话，应该返回 3 对吧？（[0] 第一、[0] 第二、[0,0] 一共 3 个）
面试官：对，考虑得很仔细。

你：好的，那我先讲一下思路。
     最暴力的方法是两重循环，枚举起点 i 和终点 j，累加 nums[i..j]，
     和等于 k 就计数，这样时间是 O(N²)，N=1e5 时就会超时。
     优化思路是：这是「连续区间和」问题，一般用前缀和。
     设前缀和 pre(j) = nums[0] + … + nums[j]，那区间 nums[i..j]
     的和 = pre(j) - pre(i-1) = k → pre(j) - k = pre(i-1)。
     所以我们用 HashMap 记录「每个前缀和出现过几次」，遍历到 pre(j)
     时，查 map 里 pre(j)-k 的次数，加到答案上；然后把 pre(j) 存进去。
     这样只需要 O(N) 时间，空间 O(N)。这个思路您觉得可以吗？
面试官：嗯，没问题。注意下初始条件。
你：对！还需要把 map.put(0, 1)，代表"前缀和等于 0"的情况出现过一次
     （就是一个元素都不选的空前缀），这样从下标 0 开始的子数组能被算到。
     我现在开始写代码。

你：（边写边说）首先创建一个 HashMap 存计数，初始化空前缀……
     然后遍历数组，累加 pre，然后查 pre - k 的次数加到 ans 里……
     这里注意要「先查后存」，如果先存再查的话，当 k = 0 时，
     自己和自己相减也会 = 0，会把单个元素 0 的情况多算一次。
     （写完代码）

你：我跑一下刚才的两个测试用例：
     ① nums = [1,1,1], k = 2 → 预期 2：
       pre=1 → 查 1-2=-1 → 0；存 1:1
       pre=2 → 查 0 → 1；ans=1；存 2:1
       pre=3 → 查 1 → 1；ans=2；存 3:1
       返回 2，正确。
     ② nums = [0,0], k = 0 → 预期 3：
       pre=0 → 查 0 → 1（空前缀）；ans=1；存 0:2
       pre=0 → 查 0 → 2；ans=1+2=3；存 0:3
       返回 3，正确。
     我再跑一个含负数的测试：nums = [3,4,7,2,-3,1,4,2], k=7 → 应该有 4 个。
     跑下来的话 pre = 3,7,14,16,13,14,18,20，分别查 -4,0,7,9,6,7,11,13
     计数到 7 时各命中 1 次，一共 4 次，正确。
面试官：嗯，很好。

你：时间复杂度 O(N) 一次遍历，空间 O(N) HashMap 最坏情况 N 个不同前缀和。
面试官：有没有空间更优的？
你：如果数组全是正数，可以用滑动窗口，空间 O(1)。但因为有负数，
     窗口右移时 sum 不一定增大，单调性不成立，滑窗就失效了——所以
     含负数时 HashMap 方案是最优的。
```

## 三、算法面试「十大最常见翻车现场」+ 抢救方法

| # | 翻车场景 | 为什么会翻车 | 抢救方法 |
|:---|:---|:---|:---|
| 1 | **拿到题 5 分钟沉默不开口** | 还在想最优解，怕说出来暴力解被鄙视 | 立刻说暴力解！"最直接的方法是 XX，复杂度 O(N²)，显然有优化空间，我想下能不能降到 O(N)…" 开口=50 分，沉默=0 分 |
| 2 | **一上来直接写最优解，写错方向** | 想当然觉得题目是某种套路，没问清楚边界 | 严格按 7 步法，第 1 步澄清完再想解法；**先问清楚是不是允许修改原数组 / 有没有重复元素**这些决定了方向 |
| 3 | **思路正确，但代码边界全是 bug** | 平时刷题直接跑测试用例，习惯了 IDE 自动帮你找错 | 写完代码**自己先跑一遍**（第 5 步），不要等面试官提示你"这里好像越界了" |
| 4 | **变量名 l/i/j/n/m 一堆分不清** | 平时刷题图快，面试时也一样 | 面试代码变量名要有语义：`slow`/`fast` 而不是 `i`/`j`；`preSum` 不是 `s`；`mapCount` 不是 `m` |
| 5 | **死磕一道题 30 分钟没动静** | 担心写不出来扣分，越想越慌越想不出来 | 20 分钟没思路，主动问："这块我暂时还没想出最优解，我先把能想到的 XX 解法写出来可以吗？" 写暴力解能拿一半分，死磕 0 分 |
| 6 | **被面试官 hint 到了还嘴硬** | 觉得自己思路没错，纠结"您说的这个我考虑过了" | hint = 面试官给你送分！立刻接："对！您说的这个是我之前没考虑到的关键点，这样能把复杂度降一级，谢谢您的提醒！" 然后改 |
| 7 | **链表/二叉树指针操作总丢链** | 改指针顺序错了，画图能救 80% 的丢链 | 面试桌上有纸就画！没纸就在脑子里模拟：先存 next 再改 prev/next。模板详见 [算法思想 / 链表](../算法思想/链表.md) |
| 8 | **DP 题状态定义总错** | 一上来想 dp[n] 就开始写转移，没想清楚状态代表什么 | DP 五步法：① 状态定义（写注释！）② 转移方程 ③ 初始化 ④ 遍历顺序 ⑤ 返回值。先写注释再写代码。详见 [1.动态规划](../算法思想/1.动态规划.md) |
| 9 | **并查集 / Trie / KMP 等模板代码记错** | 平时只看理解，不默背模板 | 面试前一天晚上默背一遍：并查集 10 行模板 + Trie 插入查询 + 单调栈模板 + LRU 模板。模板题直接拿满分不香吗？ |
| 10 | **一道题写完，面试官再问"还有没有其他解法？"答不上** | 刷题只背最优解，不横向联系 | 每道题至少知道 2 种解法：比如 TopK 至少会「最小堆」和「快排 partition」两种；TopK 频率题至少会「桶思想」和「堆」两种。不会就笑着说："这个我暂时只想到这种解法，面试后我再学习一下其他思路"，**不要瞎说** |

## 四、备战节奏规划（3 种时间窗口）

### 情况 A：2 周内突击（临时抱佛脚型）

```
目标：Hot100 至少过一遍（有印象），Medium 能写出 70%
 第 1~4 天：数组/字符串/哈希 + 双指针滑窗
             → 刷：1/3/15/18/49/56/76/128/209/238/283/347/438/560 等
 第 5~6 天：链表 + 栈与队列 + 单调栈
             → 刷：2/19/21/23/141/142/146(LRU)/155/206/234/394/739 等
 第 7~8 天：二叉树（树题占面试 1/4，必练熟）
             → 刷：94/101/104/105/114/124/226/236/297/437/538/543/617 等
 第 9~10 天：回溯 + DFS/BFS + 图
             → 刷：39/46/78/79/131/200/207/22括号 等
 第 11~12 天：动态规划（挑高频）+ 二分
             → 刷：53/62/64/70/121~123/152/198/213/279/300/309/322/416/72
 第 13 天：TopK / 排序 / 位运算 / 设计题
 第 14 天：模拟面试 3 场，复盘错题
```

### 情况 B：4~6 周（稳健型）
- 第 1~2 周：按标签分类刷 **Hot100 + Hot150**，重点看算法思想每篇笔记最后推荐的题
- 第 3 周：按题型归纳模板（滑动窗口模板、DP 模板、并查集模板……），**自己写下来不要看答案**
- 第 4~5 周：LeetCode Mock 随机抽题限时 + 找朋友两两对练，面完互相复盘
- 第 6 周：刷牛客/CodeTop 对应公司最近的真题（按公司标签+时间筛选）

### 情况 C：长期备战（3 个月以上，跳槽准备）
- 遵循「五毒神掌」：第 1 天做题 → 第 3 天重做 → 第 7 天 → 第 15 天 → 第 30 天。同一题刷 5 遍比做 5 道新题有效
- 每周做一次「模式总结」：比如这周刷了 20 道 DP，抽出 5 道最典型的，把状态转移方程和状态定义整理成笔记
- 每道题至少掌握 2 种解法：最优解 + 暴力/次优解，并能说清 trade-off
- **手写代码 > 光看题解**：面试现场是共享屏幕/白板，没有 IDE 自动补全，要锻炼"肌肉记忆"

## 五、现场硬件 / 环境 Checklist（视频面试前 10 分钟检查）

```
□ 1. 网络：最好插网线，WiFi 放近一点；4G/5G 热点备用
□ 2. 视频：摄像头角度和视线齐平，不要俯拍/仰拍；灯光从正面打（不要背光脸全黑）
□ 3. 声音：戴耳机，不要外放（外放会回声，面试官非常难受）；测试语音设备
□ 4. IDE：开一个空 Java / Python 文件，测试能不能正常跑
□ 5. 辅助：
     - 旁边放一张 A4 白纸 + 笔（画图、链表操作、dp 状态表）
     - 水杯（面试 1 小时，嗓子会干）
     - 手机静音（不是振动，振动声音麦能收到）
     - 门窗关好，避免有人闯入
□ 6. 心理：深呼吸 3 次。记住：
     - 你面挂了天塌不下来，只是又多了一次免费复盘机会
     - 面试官也希望你通过（招到人是他的KPI），放轻松，正常发挥就好
```

## 一句话总结

**算法面 ≠ 纯做题**：面试官给你 30 分钟，看的不只是代码对不对——**更看你解决问题的方式（澄清→思路→编码→调试→分析），以及在压力下能否清晰沟通**。把 7 步法刻在脑子里，面试时按步骤走，正常发挥就超过 80% 的候选人了。
